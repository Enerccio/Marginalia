# 画像生成

ストーリーのパートひとつ分の画像を作成します。モデルがパートの内容から画像プロンプトを書き、あなたがそれを編集します。画像バックエンドが絵を描くので、気に入るまで reroll を繰り返し、Accept すると、その画像はパートの画像になります。パートのメニューの*画像*から手動で追加した画像と同じ扱いで、ストーリー内に表示され、エクスポートにも含まれます。

この拡張機能自体は画像を生成しません。**ComfyUI** サーバー、または **OpenAI images API** を話すサーバー（stable-diffusion.cpp、LiteLLM、多くのホスト型サービスも対応しています）と通信します。

<a id="adding-a-backend"></a>

## バックエンドの追加

*設定 → Extension Settings → Image Generator Settings* にバックエンドの一覧があります。(+) で追加し、項目を入力して*設定*ページを保存してください。

| 設定項目 | 役割 |
|---|---|
| Name, Type | ウィンドウに表示される名前。**ComfyUI** か **OpenAI images API** を選びます。 |
| Address | サーバーのベースアドレス。ComfyUI の場合は例えば `http://localhost:8188`。 |
| Api key | Bearer トークンとして送信されます。暗号化して保存され、再表示はされません。新しいキーを入力して置き換えるか、**Remove the key** を使ってください。 |
| Model | OpenAI images API のみ：リクエストの `model`。 |
| Workflow | ComfyUI のみ：ComfyUI で **Save (API Format)** を使って保存したワークフロー。`{{prompt}}`、`{{negative}}`、`{{seed}}`、`{{width}}`、`{{height}}` を、それぞれ入れたい場所に書いてください。 |
| The server is on this machine or on my network | ローカルネットワークのアドレスを許可します。クラウド上のサーバーではオフのままにしてください。そうしないと、あなたのマシンを呼び出させられてしまいます。 |
| Width, Height, Negative prompt | ウィンドウを開いたときの初期値です（その1枚だけ、ウィンドウで変更できます）。 |
| Timeout | 1枚の画像を待つ時間。 |
| Release after idle | [One GPU](#one-gpu-for-the-model-and-the-images) を参照。 |

![設定でのバックエンド](../../images/plugin-imagegenerator-settings.png)

**Test connection** でアドレスとキーを確認できます。

パネルには、すべてのプロンプトの前に付ける**文体**（作品の雰囲気。例：*watercolor, soft light*）と、パートからプロンプトを書くモデルに与える指示文**Instruction for the prompt writer** もあります。空のまま、または変更しなければ、組み込みの指示文が使われます。

<a id="making-an-image"></a>

## 画像の作成

![パートのメニューの Generate image](../../images/plugin-imagegenerator-menu.png)

1. パートのメニューから **Generate image** を選びます。ウィンドウのモデル（初期値は作品のモデルで、最後に選んだものが記憶されます）が、そのパートのプロンプトを書き始めます。**Abort** で止めたり、プロンプトを書き換えたり、**Write the prompt with the model** を押して書き直させたりできます。書き直す前に、次の項目を入力できます：
   - **Send lorebook entries** - 作品のロアブック（およびそのサブロアブック）のエントリが、生成時と同じようにモデルに送られます。そのため、モデルは登場人物や場所の見た目を把握できます。エントリは、フィルターに一致する語がパートに見つかったときに送られます。対象になるのは、本文、指示、シーン設定、視点、登場人物、そして *Details* です。常に有効なエントリも送られます。送れるのはモデルのコンテキストに収まる分だけです（入りきらなかった数は通知されます）。この選択は記憶されます。
   - **Details** - 画像に何を写すか、どのように見せるか（*夜、顔のアップ、赤いドレス*など）を書きます。プロンプトを書くモデルはこれに従います。この内容はこのウィンドウだけで使われます。
2. バックエンドを選び、**生成** を押します。*Size and negative prompt* の下では、このウィンドウに限り、サイズとネガティブプロンプトを変更できます。
3. 画像が表示されます。**Reroll** で新しいシードの画像を作り直し、**Discard** で破棄し、**Accept** でパートに追加してウィンドウを閉じます。**Abort** は作成中の画像を止めます（ComfyUI にはジョブの中断が伝えられます）。

![モデルが書いたプロンプトのあるウィンドウ](../../images/plugin-imagegenerator-prompt.png)

![画像と、Accept・Discard・Reroll のボタン](../../images/plugin-imagegenerator.png)

開いているパートでは、新しい画像がすぐに本文の下に表示されます。

<a id="one-gpu-for-the-model-and-the-images"></a>

## 1枚のGPUをモデルと画像で共有する

小さなGPUが1枚だけの場合、言語モデルと画像モデルを同時に読み込むことはできません。拡張機能はメモリを管理しません。その代わり、各バックエンドには次の2つのリクエストリストを設定できます：

- **Before the first image** - ウィンドウがそのバックエンドを使い始めるときに、一度だけ実行されます。たとえば、言語モデルをアンロードして画像モデルをロードする、プロキシへのリクエストです。
- **After the last image** - 画像を Accept、Discard、またはウィンドウを閉じたときに実行されます。または、最後の画像から **Release after idle** で設定した秒数が経過したときにも実行されます（忘れられたウィンドウがGPUを占有し続けないようにするためです。0 にすると無効になります）。ComfyUI の場合は、本文が `{"unload_models": true, "free_memory": true}` の `POST <address>/free` にできます。プロキシの場合は、言語モデルを再び読み込むリクエストにします。

`llama-server` をルーターモードで LiteLLM の後ろで動かしている場合、*Before* のリクエストでプロキシを通じて言語モデルをアンロードできます。詳しくは [別のモデルのためにGPUを解放する](../prompt-cache.md#freeing-the-gpu-for-another-model) を参照してください。

どちらのタイミングも**リクエストのリスト**を受け取り、順番に実行されます（**Add a request** で追加し、ゴミ箱のアイコンで削除します）。モデルの切り替えには、複数のリクエストが必要なことがよくあります。たとえば、言語モデルをアンロードしてから画像サーバーを起動し、画像が終わったら停止する、という流れです。各リクエストには、アドレス、メソッド（初期値は `POST`）、ヘッダー（`Name: value` を1行に1つ）、本文、**timeout**（空欄なら60秒、最大600秒。大きなモデルを読み込むサーバーには長めに設定してください）、そして **Wait afterwards**（応答後に待つ秒数。「はい」と答えた後もまだ忙しいサーバー向けです）を設定します。ヘッダーは API キーと同じように暗号化して保存されます（リクエストには `Authorization: Bearer ...` を含めることがよくあります）。Reroll の間もバックエンドは保持されるので、切り替えの費用を払うのは最初の1枚だけです。モデルの前にあるプロキシがモデル名で切り替えを行う場合は、両方のリストを空のままにしてください。

*Before* のリストのリクエストが失敗すると、残りは実行されず、画像の作成は止まります（メッセージには失敗したリクエストが示されます：*Request 2 of 3: ...*）。これは、まだ満杯のGPUに何かを読み込んでしまわないためです。*After* のリストは、どのリクエストが失敗しても**すべて**実行されます（どのサーバーも停止させる必要があるからです）。最初の失敗は警告として表示されます。以前のバージョンで保存された単一のリクエストのバックエンドは、リストの最初のリクエストとして表示されます。

**1枚のGPUを複数人で使う場合。** 同じサーバーアドレス（`http://host:port`）のバックエンドを持つ全員は、ひとつのゲートを通ります。*Before* のリクエストは最初に開始されたウィンドウのために実行され、*After* のリクエストは最後のウィンドウが終わったときに実行されます。そのため、ひとつのウィンドウを閉じても、別の人の画像の下でモデルがアンロードされることはありません。また、画像は一度に1枚ずつ作られます（2つ目のウィンドウは順番を待ちます）。リクエストは、先に来たユーザーと最後に残ったユーザーのものになります。

バックエンドには、それが動いているGPUの名前（**GPU (name)**）を指定することもできます。同じGPUの名前を指定したバックエンドは、アドレスが違っていても互いに待ち合わせます。これには、[オーディオブック](audiobook.md)のバックエンド（1枚のカードで動く音声サーバーと画像サーバー）も含まれます。別のモデルを必要とするユーザーは、他の処理が終わるまで待ってから自分のリクエストを実行します。同じGPUに読み込まれる他の処理に割り込むことはありません。名前を空欄にすると、同じアドレスへのリクエスト同士だけが待ち合わせます。

<a id="what-is-not-done"></a>

## 対象外の事項

- バックエンドは作品ごとではなく、ユーザーごとに管理されます。
