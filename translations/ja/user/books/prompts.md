# 書籍のプロンプト

書籍の**プロンプト**タブには、Marginalia がプロンプトを組み立てる元になる文章が入ります。内容は、2 つのテンプレート、物語の設定、要約と書き直しのプロンプトです。モデルの設定よりも、書籍の声を大きく左右します。

![プロンプトタブ](../../images/book-prompts.png)

<a id="defaults-and-book-values"></a>

## 既定値と書籍の値

すべての欄は省略できます。空の欄は継承されます。その欄を設定している、書籍の上にある最も近い[フォルダ](folders.md)の値が使われます。フォルダにもなければ、**設定 → Templates**（[アカウントと設定](../account.md)を参照）の既定値が使われます。それも空であれば、設定の[プロンプトの言語](../account.md#prompt-language)にもとづく組み込みのデフォルトが使われます。継承される値は、空の欄の中にグレーで表示されます。

そのため、すべての書籍に共通する内容は*設定*で、シリーズに共通する内容はそのフォルダで設定し、その書籍だけに特有の内容だけを書籍の*プロンプト*タブで設定してください。変更は入力すると自動的に保存されます。

<a id="inherited-settings"></a>

### 継承された設定

空の欄の下の行に、その値の出どころが表示されます。書籍の文章がなぜそのように書かれるのかを確認できます。

- *Inherited from the folder "Sci-fi"*：[フォルダ](folders.md#where-the-settings-of-a-book-come-from)がその値を設定しています（書籍の上にある最も近いフォルダの名前が表示されます）。
- *ユーザー設定から継承*：*設定 → Templates* の値です。
- *組み込みのデフォルト*：どこも値を設定していません。

![フォルダ内の書籍のプロンプトタブ](../../images/book-prompts-inherited.png)

フォルダの設定にも同じ欄があり、同じ行が表示されます。空白のテキストは未設定として扱われます。継承の参照はプロンプトを組み立てるときに行われるため、書籍を別のフォルダに移動したり、フォルダを変更したりすると、次に生成する部分に反映されます。

<a id="settings-of-extensions"></a>

### 拡張機能の設定

[拡張機能](../extensions/index.md)は、書籍やフォルダが同じように継承する設定を追加できます（例：書籍についてのチャットでそれをどの媒体として扱うか）。これらの設定は、プロンプトの下の**拡張機能の設定**セクションにあります。書籍の*プロンプト*タブとフォルダの設定にあり、拡張機能ごとに 1 つの折りたたみパネルがあります（値が設定されている最初の拡張機能以外はすべて閉じています。そのため、入力した値が隠れることはありません）。動作は上の欄と同じです。空の欄は、書籍の上にあるフォルダの値から継承されます。次に、*設定 → 拡張機能の設定* にある拡張機能自身の設定から継承されます。最後に、その既定値が使われます。欄の下の行には、どこから継承されたかが表示されます。[エクスポート形式](export.md#title-page-template)のテンプレート（表題ページ、前付け、著作者表示）も同じセクションにあり、形式ごとにパネルがあります。拡張機能に設定した値は、その拡張機能が読み込まれていなくても、書籍またはフォルダに残ります。

各欄には、ヒントのポップオーバーがあり、**既定のテンプレートを挿入**を選ぶと既定の内容を欄にコピーできます。自分用のバージョンを作るときの出発点になります。テンプレートの欄には、**利用可能なテンプレート変数**と**利用可能なマクロ**も表示されます。

![テンプレート欄のヒントのポップオーバー](../../images/template-hints.png)

<a id="the-fields"></a>

## 欄

| 欄 | 使用箇所 | |
|---|---|---|
| **マスターテンプレート** | システムメッセージ | プロンプトの枠組みです。モデルの役割と、設定、物語の設定、要約を入れる位置を定めます。テンプレートです。 |
| **視点（POV）** | マスターテンプレート | 語りの声です（例：*First person*、*Third-Person Limited*）。プレーンテキストです。 |
| **時制** | マスターテンプレート | 例：*Past Tense*、*Present Tense*。プレーンテキストです。 |
| **文体** | マスターテンプレート | 文章の文体とトーンの指針です。プレーンテキストです。 |
| **既定のユーザープロンプト** | 最後のメッセージ | 次の部分の依頼です。[ターンの指示](story-editor.md#writing-the-next-part)から組み立てられます。テンプレートです。 |
| **既定の要約プロンプト** | 要約 | [要約](summaries.md)の依頼です。テンプレートです。 |
| **既定のメタ要約プロンプト** | メタ要約 | [メタ要約](summaries.md#meta-summaries)の依頼です。要約を統合します。テンプレートです。 |
| **書き直しシステムプロンプト** | 書き直し | [書き直し](story-editor.md#redrafting-a-part)のシステムメッセージです。指示、語り、要約を含みます。テンプレートです。 |
| **書き直しプロンプト** | 書き直し | 書き直しの最後のメッセージで、依頼そのものです。ロアブックがその部分に対して今与えるロア（ロアのエントリーを編集すると書き直しに反映されます。その部分を書いたときのロアは、書籍にロアブックがない場合にのみ使われます）、その部分の後の物語、その部分、そして指示を含みます。テンプレートです。 |
| **短縮して書き直すプロンプト**、**長くして書き直すプロンプト** | 書き直し | [書き直し](story-editor.md#redrafting-a-part)のウィンドウで**短く**または**長く**を選んだときに、あなたの指示の後に加えられる文です。プレーンテキストで、テンプレートではありません。空の場合は組み込みの文が使われます。 |
| **注釈システムプロンプト** | 注釈 | 部分に[注釈を付ける](annotations.md#letting-a-model-annotate)ようモデルに依頼するときのシステムメッセージです。テンプレートです。 |
| **注釈プロンプト** | 注釈 | 注釈の依頼の最後のメッセージです。テンプレートです。 |
| **Annotate Instructions**（*確認してほしい点*） | 注釈 | モデルが注釈を付けるときに探すもの（*連続性の誤りを指摘*、*弱い会話*）です。注釈プロンプトの `{%{{{annotateInstructions}}}%}` の中身になります。プレーンテキストです。ここ、フォルダ、または*設定 → Templates* で設定すると、*AI で注釈を付ける*ウィンドウはこの内容から始まります。 |
| **代筆プロンプト** | 指示の下書き | あなたの代わりに次のターンの[指示を下書き](story-editor.md#drafting-the-instructions)するようモデルに依頼します。テンプレートです。 |

*視点*、*時制*、*文体*は、そのままマスターテンプレートに挿入されます。これらの欄ではマクロは機能しません。

構文エラーのあるテンプレートは保存されません。エラーの内容を示す警告が表示されます。

<a id="templates"></a>

## テンプレート

テンプレートは、二重の波括弧で囲んだプレースホルダーを含むテキストです。各テンプレートには、それぞれ固有の変数があります。

| テンプレート | 変数 |
|---|---|
| マスターテンプレート | `{%{{{backgroundLore}}}%}`（有効化されたロアブックのエントリー）、`{%{{{narrativePov}}}%}`、`{%{{{narrativeTense}}}%}`、`{%{{{style}}}%}`、`{%{{{summaries}}}%}`、`{%{{{annotations}}}%}`（モデルに伝えたメモ） |
| ユーザープロンプト | `{%{{{sceneSetting}}}%}`、`{%{{{povCharacter}}}%}`、`{%{{{presentCharacters}}}%}`、`{%{{{instructions}}}%}` |
| 要約プロンプト | `{%{{{backgroundLore}}}%}`（ロアブックがその部分に対して今与えるロア）、`{%{{{text}}}%}`（要約する部分） |
| メタ要約プロンプト | `{%{{{backgroundLore}}}%}`（上と同じ）、`{%{{{summaryBlocks}}}%}`（統合する要約） |
| 書き直しシステムプロンプト、書き直しプロンプト | `{%{{{text}}}%}`（その部分）、`{%{{{redraftInstructions}}}%}`（変更したい内容）、`{%{{{previousStory}}}%}`、`{%{{{summaries}}}%}`、`{%{{{followingStory}}}%}`、`{%{{{backgroundLore}}}%}`、`{%{{{narrativePov}}}%}`、`{%{{{narrativeTense}}}%}`、`{%{{{style}}}%}`、そしてその部分を書いたときのターン：`{%{{{sceneSetting}}}%}`、`{%{{{povCharacter}}}%}`、`{%{{{presentCharacters}}}%}`、`{%{{{instructions}}}%}`、さらに `{%{{{annotations}}}%}`（その部分に対するあなたの未解決のメモ。書き直しウィンドウで求めた場合にのみ入り、それ以外は空です）。また、[選択範囲の書き直し](story-editor.md#redrafting-only-a-passage)では `{%{{{selection}}}%}`（選択したテキスト。部分全体を書き直す場合は空）、`{%{{{selectionBefore}}}%}`、`{%{{{selectionAfter}}}%}`（その周囲の部分のテキスト） |
| 代筆プロンプト | `{%{{{impersonateInstructions}}}%}`（あなたの指針）、`{%{{{outline}}}%}`（呼び出し元が渡す物語の計画。例：アークアウトラインの現在の章）、`{%{{{previousStory}}}%}`、`{%{{{summaries}}}%}`、`{%{{{backgroundLore}}}%}`（最後の部分のロア）、`{%{{{instructionExamples}}}%}`（直近 3 つの部分の指示。古いものから順に）、`{%{{{narrativePov}}}%}`、`{%{{{narrativeTense}}}%}`、`{%{{{style}}}%}`、そして指示の対象となるターン：`{%{{{sceneSetting}}}%}`、`{%{{{povCharacter}}}%}`、`{%{{{presentCharacters}}}%}` |
| 注釈システムプロンプト、注釈プロンプト | 書き直しプロンプトの変数に加えて、`{%{{{redraftInstructions}}}%}` の代わりに `{%{{{annotateInstructions}}}%}`（見てほしい内容）、`{%{{{annotations}}}%}`（その部分にすでにあるメモ）、`{%{{{facts}}}%}`（拡張機能が、その部分の時点の物語について知っていること。たとえば登場人物が知っていることです。そのような拡張機能がない場合は空）、`{%{{{outputFormat}}}%}`（モデルに回答の形式を伝える内容） |

セクションは、変数が空でない場合にのみ内容を出力します。そのため、プロンプトに空の見出しは出てきません。

{%{
```handlebars
{{#sceneSetting}}Current Location & Time: {{.}}{{/sceneSetting}}
```
}%}

セクション内の `{%{{{.}}}%}` は、その変数の値を指します。*場面設定* が空であれば、その行全体は省略されます。

すべてのテンプレートは、SillyTavern 互換の**マクロ**も使えます。例として、`{%{{{user}}}%}`（視点人物）、`{%{{{description}}}%}`（書籍の説明）、`{%{{{random::a::b}}}%}`、`{%{{{getvar::name}}}%}`、`{%{{{setvar::name::value}}}%}` があります。構文の全体と、マクロの一覧は[テンプレートとマクロ](../templates/index.md)を参照してください。

<a id="master-template"></a>

## マスターテンプレート

マスターテンプレートは、**システムメッセージ**、つまりプロンプトの最初のメッセージになります。組み込みのデフォルトには、次のブロックがあります。

1. **システムの役割**：モデルは物語を続ける作者です。
2. **世界とロアの文脈**：有効化された[ロアブック](../lorebooks/index.md)のエントリー（`backgroundLore`）。
3. **文体と書き方の規則**：視点、時制、文体、および一般的な文章の規則。
4. **これまでの物語の要約**：[要約](summaries.md)。
5. **物語についての作者のメモ**：[モデルへのメモ](annotations.md#giving-a-note-to-the-model)を与えた場合にのみ表示されます。

[推論プロバイダー](../inference-providers.md#general-settings)でジェイルブレイクプロンプトが有効になっている場合、それはマスターテンプレートの前に置かれます。

<a id="user-prompt"></a>

## ユーザープロンプト

ユーザープロンプトは、プロンプトの**最後のメッセージ**です。書く部分への依頼です。*新しいターンの指示*（再生成とスワイプの場合は*ターンの詳細*）から組み立てられます。組み込みのデフォルトは、視点人物、場所、登場人物、そして筋の指示を含めて、次のセクションを依頼します。その後に、次の規則が続きます。依頼がない限り新しい登場人物を出さないこと、指示に従うこと、連続性を保つこと、そして物語の本文だけを出力することです。

挿入モードが*ユーザープロンプトの前*のロアブックのエントリーは、このすぐ前に置かれます。[エントリーと有効化](../lorebooks/entries.md)を参照してください。
<a id="redraft-prompt"></a>

## リダイレクトプロンプト

パートの[書き直し](story-editor.md#redrafting-a-part)は、二つのプロンプトからなる一つのリクエストです。**Redraft System Prompt**（書き直しシステムプロンプト）がシステムメッセージになり、そのパートより前の物語は会話の前の方のメッセージとして（生成時と同じように、パートはモデルの応答として）続き、**Redraft Prompt**（書き直しプロンプト）がユーザーからの最後のメッセージになります。組み込みの既定値は、モデルに対して、あなたの指示を適用すること、頼まれていない部分は残すこと、パートの前後の物語と整合性を保つこと、語り口を保つこと、そして書き直したパートだけを返答することを指示します。両方のプロンプトは同じ変数を持っています。`{%{{{previousStory}}}%}` は、物語がメッセージとして続くことを示す注記にすぎません。システムプロンプトには、書き直しのたびに変わらない内容を入れ、最後のプロンプトには変わる内容を入れてください（パートごとに異なる設定、パートの後に続く物語、パート自体、指示）。読み込んだプロンプトを記憶しているサーバーであれば、その大部分を再利用できます。自作の最後のプロンプトには、必要な変数を残しておいてください。`{%{{{text}}}%}` がないと、モデルはパートを見られません。どちらのプロンプトも、すべてのプロンプトに共通のルールに従います。すなわち、本の設定項目があればそれを使い、なければ *Settings → Templates*（設定 → テンプレート）のものを使い、それもなければ組み込みのものを使います。

[選択した一部分だけを書き直す](story-editor.md#redrafting-only-a-passage)場合も、同じプロンプトが `{%{{{selection}}}%}` を埋めた状態で使われます。組み込みの既定値では、パートが `[[PASSAGE TO REDRAFT]]` と `[[/PASSAGE TO REDRAFT]]` で囲まれた部分を含んだ形で示され、モデルには、その一部分を置き換える文章だけを返答するよう指示されます。自作のプロンプトが `{%{{{selection}}}%}` を知らない場合、モデルはパート全体を返答し、その全体が選択範囲を置き換えてしまいます。これを扱うには、`{%{{#selection}}%}...{%{{/selection}}%}` のブロック（そして、そうでない場合のために `{%{{^selection}}%}`）を追加してください。

<a id="redraft-shorter-and-longer"></a>

## 短く・長く書き直す

[書き直し](story-editor.md#redrafting-a-part)ウィンドウの **Length**（長さ）の選択肢（**Same length**（同じ長さ）、**Shorter**（短く）、**Longer**（長く））は、書き直しプロンプトには手を加えません。**Shorter** の場合は **Redraft Shorter Prompt**（短縮して書き直すプロンプト）の文章を、**Longer** の場合は **Redraft Longer Prompt**（長く書き直すプロンプト）の文章を、*Instructions for the redraft*（書き直しの指示）に書いた内容のあとに追加します。追加される位置は `{%{{{redraftInstructions}}}%}` の場所です。そのため、自作の書き直しプロンプトでも機能します。指示が空の場合は、この文章だけが指示になります。この二つの文章も、すべてのプロンプトに共通のルールに従います。すなわち、本の設定項目があればそれを使い、なければその上にある最も近いフォルダで設定されたものを使い、それもなければ *Settings → Templates*（設定 → テンプレート）のものを使い、それもなければ組み込みの文章を使います。組み込みの文章は、内容を変えずに、おおよそ三分の一から半分ほど短く（長く書く場合は、さらに半分から二倍ほど長く）するよう求めます。

<a id="annotate-prompt"></a>

## 注釈プロンプト

モデルが[パートに注釈を付ける](annotations.md#letting-a-model-annotate)とき、書き直しと同じ種類のリクエストを受け取ります。**Annotate System Prompt**（注釈システムプロンプト）がシステムメッセージになり、そのパートより前の物語が前の方のメッセージとして続き、**Annotate Prompt**（注釈プロンプト）が最後のメッセージになります。組み込みの既定値では、モデルは編集者の役割を担います。あなたの指示の意味で問題のある箇所を見つけ、それぞれの箇所を一字一句そのまま引用し、短いメモを書きます。賞賛や無駄な言葉はなく、パートにすでにあるメモを繰り返すこともありません。拡張機能が[物語に関する事実](annotations.md#letting-a-model-annotate)（ナレッジトラッカー：登場人物が何を知っているか）を提供する場合、既定のプロンプトはそれを *Established facts*（確立された事実）として示し、編集者はそれと矛盾する箇所を指摘します。このプロンプトには、回答の方法を記述する場所に変数 `{%{{{outputFormat}}}%}` があります（JSON、テキストブロック、自由記述のレビューのいずれかで、選んだ回答形式によって決まります）。自作のプロンプトでもこれを残してください。残さないと、モデルに回答の方法が伝わりません。どちらの注釈プロンプトも、すべてのプロンプトに共通のルールに従います。すなわち、本の設定項目があればそれを使い、なければ *Settings → Templates*（設定 → テンプレート）のものを使い、それもなければ組み込みのものを使います。

**What to look for**（確認してほしい点、*Annotate Instructions*）も同じルールに従うため、一度設定すれば済みます。すべての本に対しては *Settings → Templates*（設定 → テンプレート）で、そのフォルダ内の本に対してはフォルダで、一冊の本に対しては *Prompts*（プロンプト）タブで設定できます。*Annotate with AI*（AI で注釈を付ける）ウィンドウには、適用されている内容が欄の灰色の文字で表示され、その出所も示されます。欄を空のままにすると適用されている内容がそのまま使われます。何か入力すると、その回の実行に限ってその内容に置き換わります。欄の情報アイコンをクリックして **Fill default**（既定値を入力）を選ぶと、適用されている内容が欄にコピーされ、その回の実行のために編集できます。どこにも設定がなければ、プロンプトの既定の作業内容が使われます。自動注釈と `/generate-annotation` コマンドも同じです。

<a id="impersonate-prompt"></a>

## 代筆プロンプト

モデルが次のターンの[指示を下書きする](story-editor.md#drafting-the-instructions)とき、書き直しと同様に、ただ一つのメッセージとして送られる一回のリクエストを受け取ります。組み込みの既定値は、あなたが *Instructions*（指示）に入力するであろう内容を書くようモデルに求めます。すなわち、次のパートの筋書き（何が起こり、誰が何をし、パートがどこで止まるか）です。それはあなたの指導を発展させ、計画に従い、物語が終わったところから続け、あなた自身の以前の指示と同じように書かれ、本文そのものではないものです。指導がなければ、物語が向かうところへ続けます。あなたの指導は、プロンプトの `{%{{{impersonateInstructions}}}%}` の位置に入ります。自作のプロンプトにもこれを残してください。代筆プロンプトは、すべてのプロンプトに共通のルールに従います。すなわち、本の設定項目があればそれを使い、なければ *Settings → Templates*（設定 → テンプレート）の *Impersonate Prompt*（代筆プロンプト）を使い、それもなければ組み込みのものを使います。

<a id="how-the-prompt-is-put-together"></a>

## プロンプトの組み立て

```
system     jailbreak (有効な場合) + マスターテンプレート
user       [ Generate story. ]
assistant  part #1
user       [ Generate more story. ]
assistant  part #2
...        (収まる限りの前のパート)
user       lore "Before User Prompt" + ユーザープロンプト
```

前のパートは、モデル自身の応答として送られるため、モデルは同じ語り口で続けます。物語が[コンテキストの上限](../protocols.md#limits)より長くなると、古いパートから順に除外されます。[要約](summaries.md)は、それらを圧縮された形で物語に残します。

どのパートのメニューにある **Show Prompt**（プロンプトを表示）は、そのパートが書かれたもとの正確なプロンプトを表示します。**Compare Prompt**（プロンプトを比較）は、それを前のパートのプロンプトと並べて表示し、両者が最初に異なる箇所を示します。その箇所が、サーバーの[プロンプトキャッシュ](../prompt-cache.md#compare-prompt)の有効範囲の終わりになります。

<a id="tips"></a>

## ヒント

- どのパートにも当てはまるルール（新しい登場人物を出さない、長さ、書式など）は、ユーザープロンプトに入れてください。最後のメッセージなので、最も強く効きます。
- 世界や登場人物について長く続く事実は、*Style*（文体）ではなく[ロアブック](../lorebooks/index.md)に入れてください。
- 長さは、応答の上限に頼るのではなく指示で求めてください（「約800語」など）。応答の上限では、文章が途中で切れてしまいます。
- テンプレートを変更したら、パートを一つ生成し、**Show Prompt**（プロンプトを表示）で確認してください。
