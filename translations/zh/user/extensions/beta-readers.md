# 测试读者

你虚构的读者，以及与他们就你的书进行的聊天。你为一个**角色设定**（名字、图标，以及几行关于此人如何阅读、在意什么的描述）编写内容，模型会扮演这位读者：它会以该读者的视角回应你故事的各个部分，可以是单独一位，也可以是一组相互争论的读者。读者说的任何内容都不属于书的一部分。

![与两个角色设定的群聊](../../images/plugin-betareaders-chat.png)

<a id="the-beta-readers-tab"></a>

## 测试读者标签页

[故事编辑器](../books/story-editor.md)的左侧边栏会出现一个**测试读者**标签页，位于*大纲*旁边。每个打开的书籍聊天都有一个对应的标签。**+** 用于开始新聊天，它旁边的菜单（⋮）包含：

| 项目 | |
|---|---|
| 新建聊天 | 与 **+** 相同。 |
| 重命名聊天 | 更改聊天的标题。 |
| 关闭聊天 | 关闭标签页；聊天会被保留，并出现在*已关闭的聊天*中。 |
| 聊天设置 | 更改[聊天的选项](#the-options-of-a-chat)。 |
| 删除聊天 | 在确认后删除该聊天及其历史记录。 |
| 本书的角色设定 | 仅属于本书的角色设定，见[下文](#personas)。 |
| 已关闭的聊天 | 重新打开已关闭的聊天。 |

聊天与书籍一同保存，因此会包含在其备份中。

![第一次聊天之前的标签页](../../images/plugin-betareaders-tab.png)

![聊天菜单](../../images/plugin-betareaders-menu.png)

<a id="personas"></a>

## 角色设定

一个角色设定包含一个**名称**、一段**描述**（模型所扮演的内容：此人如何阅读、喜欢什么、讨厌什么）以及可选的**图标**，即缩小到很小尺寸的图片。若没有图标，角色设定会显示为一个圆圈，里面是名字的首字母。

你账户中的角色设定位于*设置 → 扩展设置 → 测试读者*中的**角色设定库**，初始包含六位读者：Athena、Vesper、Ember、Quill、Nox 和 Sable。**编辑角色设定**会在窗口中打开角色设定库，你可以在其中添加、编辑、复制、删除和重新排序角色设定，上传它们的图标，并**添加初始角色设定**（补充库中缺少的初始角色设定）。更改通过**保存**生效，**取消**则会放弃这些更改。

![角色设定库](../../images/plugin-betareaders-library.png)

一本书可以拥有自己的角色设定：聊天菜单中的*本书的角色设定*会打开同一窗口，显示仅属于本书的角色设定。在为聊天选择它们时，会标注*（本书）*。

![一本书的角色设定](../../images/plugin-betareaders-book-personas.png)

角色设定窗口中的**用模型编写**会替你完成编写工作：用几句话描述该角色设定（*一位只关心谁做了这件事以及为什么的读者*），按下按钮，模型就会按照库中的风格填写**名称**和**描述**。这些只是字段：你可以修改它们，或重新生成，正确后再点击**保存**。负责编写的模型与聊天所用的模型相同（本书的角色设定使用本书的模型，库中的角色设定使用插件设置中的模型，否则使用你的默认模型）；列表中已有的名称会告知模型，以免它重复使用。

![由模型编写的角色设定](../../images/plugin-betareaders-write-persona.png)

聊天会保存其角色设定的**副本**，因此在库中所做的更改不会影响已经开始的聊天；只有在你要求时副本才会更改（见[群组](#a-group)）。

<a id="starting-a-chat"></a>

## 开始聊天

**+** 会打开新聊天的窗口。

![新聊天窗口](../../images/plugin-betareaders-new-chat.png)

| 字段 | |
|---|---|
| 类型 | **一个角色设定**或**一个群组**。之后无法更改。 |
| 标题 | 留空时：角色设定的名称。 |
| 角色设定 | 单人聊天只需一个角色设定；群组则至少需要一个（群组可以先从一个角色设定开始，其他角色设定稍后加入）。 |

折叠的部分**故事、媒介、模型和格式**包含[聊天的选项](#the-options-of-a-chat)。其中每一项都可以留空，留空时则继承默认值。

包含**一个角色设定**的聊天是你与该角色设定之间的对话。**群组**则是所有在场的角色设定与你以及彼此之间的对话：一次回复中可以有多位角色依次发言，他们可能会意见不一、互相调侃，并在彼此的观点上继续发展。回复中的一条消息也可以是旁白（*叙述者*）：对该角色设定所做之事的简短描述。
<a id="talking"></a>

## 对话

在底部的输入框中写下内容，然后按 **发送**；回复会边生成边显示，生成过程中按钮变为 *停止*，点击 **停止** 即可中途截断。一次回复就是模型的一轮输出：包括模型的思考过程（如果它发出了思考内容，会显示为一个可折叠的 **推理** 部分；不进行思考的模型则不显示）以及各个角色的消息，每条消息都附带其动作和台词。

<a id="sending-a-scene"></a>

### 发送场景

**以场景发送**（位于 *发送* 旁边）会把输入的文字作为场景而不是你的发言发送出去：可以是场景的转换（*灯光熄灭，酒吧里一片寂静。*），也可以是对你所做之事的描述（*我把手稿放在桌上，然后等待。*）。它在历史记录中显示为一张 **场景** 卡片，角色会像对待消息一样即时对它做出反应。关于场景从哪里开始，请参见[下文](#the-scene)中的聊天场景；而这个按钮则用于之后发生的事情。场景消息可以像你的消息一样编辑和删除；它不会发送故事的部分内容（*包含最新章节* 复选框属于 *发送*）。

![聊天历史中的一个场景，以及对它的回复](../../images/plugin-betareaders-scene.png)

群组中的角色只会被告知你上一条消息结束时在场的人员（这一信息不会被保存），因此添加或移除某个角色，永远不会改变之前的历史记录。

<a id="sending-the-story"></a>

### 发送故事

聊天本身不保存故事的副本。它会记住你已经**交给**角色的是哪些部分，并且每次请求时，角色所读取的故事都会根据故事当前的内容重新构建：即他们已获得的各个部分，其中最早的部分会用摘要代替，并以能放入模型上下文为限。各个部分位于给出它们的那条消息之前，因此某个部分只会出现在请求中一次，当你交出更多部分时，请求的开头保持不变：只保留提示词开头的模型服务器只需读取新增的内容。被编辑过的部分会以编辑后的内容被读取，被删除的部分则不再被读取，这会从给出该部分的那条消息开始改变请求。之后生成的摘要会在下一条消息起替换它所描述的各个部分。

**包含最新章节** 是让角色读到更多故事内容的方式：它会加入他们尚未获得的部分（参见[下文](#how-much-of-the-story-the-personas-read)）。不勾选它，则只是聊天，之后再把故事交给他们。复选框的标签会显示它将添加多少个部分（*包含故事（5 个章节）*、*包含最新章节（2 个新章节）*、*没有新内容*）。它会自动跟随故事变化：当你添加、编辑或删除某个部分，或切换分支时，数字会随之更新，并且只有在有新内容时复选框才会被勾选。你发出的消息会说明它交出了哪些部分（*已发送第 1–5 章*）。

输入框旁边的 **最后一章** 和 **第一章**，是[角色所读取的故事范围](#how-much-of-the-story-the-personas-read)；你读到哪里时，就在那里调整它们。

输入框下方显示的是角色已读取的内容（*角色已读：第 1–5 章*）以及上下文的大小（*上下文：2,266 / 30,720 个词元*）：即下一条消息将发送的内容，包括历史记录、你输入的文字，以及在勾选 **包含最新章节** 时将添加的各个部分。当你勾选该复选框或在输入时暂停，这些数字都会更新。各个部分至少占用上下文的一半；如果历史记录无法与之并存，则最早的消息（连同它们所给出的部分）会从请求中略去，但不会被删除，并会出现提示说明略去了多少条。

<a id="changing-the-conversation"></a>

### 更改对话

| 按钮 | |
|---|---|
| 笔（你的消息） | 编辑你的消息；它所交出的各个部分保持已交出状态。 |
| 垃圾桶 | 删除你的消息，或回复中的某一条消息（该轮的其余内容保留，模型看到的是删去这一条之后的轮次）。 |
| 重新生成 | 丢弃最后一条回复并重新请求。 |

当回复失败或没有回复时，面板会予以说明，并提供 **重新询问** 按钮。

![消息的操作按钮](../../images/plugin-betareaders-actions.png)

<a id="a-group"></a>

### 群组

对话上方的 *角色（n）* 列出了当前在场的人员。在群组中你可以：

- **引入角色**：从资料库或书籍中引入，并可附加一条说明，告诉群组他们为何到来（"Mara 读完了整本书"）。历史记录中会添加一行（*Mara 加入了对话。*），让模型知道这件事发生的时间。
- **送走角色**：点击其所在行的箭头按钮，同样可附带说明。被送走的角色仍保留在列表中，显示为灰色并标注 *（已离开）*。最后一位角色不能离开。
- **从资料库更新**：将资料库（或书籍）中该角色当前的描述和图标同步到聊天中。

![加入群组的角色](../../images/plugin-betareaders-joined.png)

![引入角色](../../images/plugin-betareaders-bring-in.png)
<a id="the-options-of-a-chat"></a>

## 聊天的选项

新聊天的窗口和 **Chat settings** 中的选项相同;每一项都可以留空,留空时聊天沿用对应的设置。

| 选项 | |
|---|---|
| Your name | 角色们如何称呼你;你的消息会显示这个名字,而不是 *You*。留空:不称呼。 |
| Scene | 对话发生的地点和方式,几句话即可:*打烊后一家下雨的酒吧*,*读书会结束后的视频通话*。没有场景时,聊天就是线上聊天,见[下文](#the-scene)。在进行中的聊天里修改场景,会从下一次请求起改变系统提示词,且不会在历史记录中留下任何一行;若要让从现在起发生的事情生效,请使用[场景消息](#sending-a-scene)。 |
| Medium | 文本所代表的媒介:书籍、电影、电视剧、漫画或连环画、广播剧、舞台剧、游戏或视觉小说。角色们会以该媒介受众的方式做出反应。在进行中的聊天里修改媒介,会在历史记录中留下一行(*From now on the text is read as: ...*)。 |
| Model | 作出回应的 AI。 |
| Protocol | 与之配合使用的[协议](../protocols.md)。 |
| Reply format | 要求模型以何种方式写作:**Automatic**(模型能遵循架构时使用架构中的 JSON,否则使用自由文本)、**JSON**(始终使用架构)、**JSON without a schema** 或 **Free text**。参见[推理](#the-reasoning)。 |
| Personas read up to part | [剧透上限](#how-much-of-the-story-the-personas-read)。仅在新聊天的窗口中设置;已存在的聊天则在文本框下方设置。 |
| Start from part | 角色们所读故事的起始部分。同上。 |
| Use the summaries of the story | 见下文。 |
| Most messages in a turn | 角色们针对你的一条消息所写的最多消息数(1 至 50)。留空:使用你在 *Settings → Extension Settings → Beta Readers* 中的设置。超出的回复会被截断,并告知模型该上限。 |

![聊天的设置](../../images/plugin-betareaders-chat-settings.png)

<a id="the-reasoning"></a>

### 推理

回复上方的 **Reasoning** 是模型的思考过程,由服务器原样发送(与 Marginalia 中其他生成器相同);不进行思考的模型没有推理内容,也不会显示任何内容。本插件不会要求模型另行生成推理:在架构之下写下的几句话更像是计划而非思考,而且会妨碍本身就会思考的模型。写在 `<think>` 标签之间的思考内容同样会作为推理显示。

**JSON without a schema**(位于 *Chat settings* 中)只在提示词中要求相同的 JSON,不附带响应格式;在服务器无法同时接受架构和模型思考的情况下使用它。

<a id="the-text-as-it-is-written"></a>

### 逐字呈现的文本

回复会在模型书写时逐条消息、逐字显示:一旦确定发言者是谁,正在书写的消息就会出现,并随之增长。属于动作的部分在其类型被写出时即出现,因此手势不会一开始就被误认为是对话。

对话会随回复的增长而向下跟随。向上滚动以阅读较早的内容时,页面会停留在原处;滚回到底部后,它会重新跟随。发送消息总会滚动到末尾。

<a id="the-scene"></a>

### 场景

场景是一段文字,位于每个聊天系统提示词的末尾(在提示词之后),使角色们知道自己身处何地以及彼此如何交谈。它是一项[继承的设置](../books/prompts.md#inherited-settings):依次取聊天自身的设置,若无则取书籍的,若无则取最近的文件夹的,若无则取 *Settings → Extension Settings → Beta Readers* 中的设置,若仍无则取内置的:**线上聊天**,即每个人都从所在之处发送简短消息。若你自己的提示词中包含 `{{scene}}`,则由它决定场景的位置;否则场景会被添加在提示词之后。

<a id="how-much-of-the-story-the-personas-read"></a>

### 角色们读到故事的哪一部分

各部分从 1 开始编号,与故事的 *Outline* 标签页一致。

- **Personas read up to part**(文本框下方的字段 **Last part**)是剧透上限:角色们永远不会获得该部分之后的内容,摘要也只从截至该部分的故事中收集。故事继续推进时提高它,下一条消息便会将先前被扣留的部分作为新内容提供。降低它,角色们会立即停止阅读之后的部分。
- **Start from part**(**First part**)会略去较早的部分,连摘要也不保留。用它可以让角色们只阅读某一章。
- **Use the summaries of the story**(默认开启)允许故事以摘要开始,然后接上最新摘要之后的部分,从而让长篇故事保持精简。摘要仅在故事从开头开始时适用。

起始部分若位于结束部分之后,将被拒绝。

在文本框下方修改这些设置(停止输入或点击步进按钮后即会保存)会从下一条消息起改变角色们所读的故事;不会重新发送任何内容,因为每条消息都会重新构建故事。

![一个只读取第 2 至 3 部分的聊天](../../images/plugin-betareaders-spoiler.png)

词条书不会发送给角色们:他们只知道故事告诉他们的内容。

<a id="settings"></a>

## 设置

*Settings → Extension Settings → Beta Readers* 是你默认设置的位置:

![插件的设置](../../images/plugin-betareaders-settings.png)

| 设置 | |
|---|---|
| Medium | 聊天的媒介。 |
| Model of the chats | 所用的 AI。留空:使用书籍的模型。 |
| Protocol of the chats | 留空:使用书籍的协议。 |
| Prompt of a chat with one persona | 一对一聊天的系统提示词。留空:内置提示词。 |
| Prompt of a group chat | 群组聊天的系统提示词。留空:内置提示词。 |
| Scene | 见[上文](#the-scene)。留空:线上聊天。 |
| Most messages in a turn | 角色们针对你的一条消息所写的最多消息数,适用于所有未设定自身上限的聊天(1 至 50)。留空:自动,一对一聊天为 3,群组中每位角色约为 2(最多 8)。较短的上限会让回复更简短;当角色们在对话中途被截断时,请调高该值。 |
| Persona library | **Edit personas**,见[上文](#personas)。 |
| Mediums | **Edit mediums**:每种媒介都有一个名称,以及告诉角色们如何对其作出反应的提示词。**Restore the built-in mediums** 会添加缺少的内置媒介。 |

提示词中的 `{{medium}}` 会被替换为媒介的文本,`{{scene}}` 会被替换为场景。设置需通过 *Settings* 页面的 **Save** 按钮保存。

场景、媒介、模型、协议以及两个提示词也都是[继承的设置](../books/prompts.md#inherited-settings):书籍的 *Prompts* 标签页和[文件夹](../books/folders.md)的设置在 **Extension Settings** 部分中提供这些选项。书籍使用其自身的值,否则取最近文件夹的值,否则取 *Settings* 中的值,否则取内置值;书籍的模型和协议则是最后的备选。聊天可以在其[选项](#the-options-of-a-chat)中为自身覆盖媒介、模型和协议。

<a id="on-a-phone"></a>

## 在手机上

可以使用。**Beta Readers** 标签页位于故事的大纲抽屉中,聊天与桌面端相同;对话的空间较小,因此横屏更便于使用。参见[在手机上使用 Marginalia](../phone.md#extensions)。

<a id="storage"></a>

## 存储

一本书的角色和聊天保存在该书的属性中(因此随其备份一同保存),你账户的角色保存在你的账户中,设置则保存在你的用户设置中。模型按 AI 的常规限制进行调用,所用的令牌计入该书的用量。
