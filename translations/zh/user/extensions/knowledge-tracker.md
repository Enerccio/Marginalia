# 知识追踪器

记录故事中角色知道什么、不知道什么，并把这些信息放入提示词。模型往往会让角色知道他们从未见过的人的事（名字、职业、长相），除非指令明确防范这一点。使用知识追踪器后，提示词会针对场景中每个被追踪的角色说明：该角色知道什么，以及它除此之外一无所知。

!!!
由你决定追踪谁。只有你添加到标签页中的角色会被描述给模型，并且只在它们属于正在撰写的章节的*当前角色*时才会如此。不会从故事正文中猜测任何内容。
!!!

<a id="the-knowledge-tab"></a>

## 知识标签页

[故事编辑器](../books/story-editor.md)左侧边栏在*大纲*旁边会出现一个**知识**标签页。你做的每一处修改都会即时保存到书籍中。

![知识标签页](../../images/plugin-knowledgetracker.png)

**追踪角色**会要求填写一个**名称**，以及可选的**别名**：角色在章节的*当前角色*字段中可能被写成的其他名字，用逗号分隔。一个名称或别名只能属于一个被追踪的角色。

点击角色卡片上的箭头即可展开，查看它知道什么：

| | |
|---|---|
| **已知**（绿色）/ **未知**（红色） | 关于任何事物的一句简短陈述：一个人、一个地点、一个秘密、一件事件（*Peter 知道针对公爵的阴谋*，*Fiora 不知道 Thomas 是她的父亲*）。请明确写出角色**不知道**什么，因为模型正是据此行事的。 |
| 排序与 **#12** | 最新的知识排在最上面（旧知识也一样）。模型习得的条目末尾会带有它所在章节的小编号（**#12**）：点击后故事会滚动到该章节并闪烁提示（在手机上会先关闭抽屉）。你自己写的条目没有编号，所在章节不在当前分支上（属于另一分支，或章节已被删除）的条目也没有编号。 |
| **添加知识** | 添加一个条目，立即生效。请保持**一个想法**：如果一个条目包含两件事（*不知道 Thomas 是谁，从未见过他*），那么其中一件事一旦不再成立，整个条目就会被撤回。**编辑**按钮可修改文本和类型。 |
| **撤回**（带斜线的圆圈） | 该条目不再成立（例如两人相遇后，*未见过 Thomas*）。它不会被删除，而是变为*旧知识*，不再发送给模型。 |
| **锁定**（挂锁，用于模型习得的条目） | [整理过程](#tidying-the-knowledge)永远不会处理已锁定的条目：请将其用于必须保留的内容，比如背叛、秘密。故事仍可能与已锁定的条目相矛盾（例如角色失去记忆）：对故事的重新阅读会照常撤回该条目。 |
| **删除** | 在确认后永久删除一个条目。撤回会保留条目，因此如有疑虑，请使用撤回。 |
| **选择条目**（位于**添加知识**旁边） | 快速批量删除条目：角色的每个条目（包括旧条目）都会出现一个复选框。**全选** / **取消全选**用于勾选或清除，**删除所选（n）**会在一次确认后永久删除已勾选的条目，**取消**则退出选择。 |
| **已见过** | 角色见过的人，由[处理](#processing)记录。处理过程可能会记下一个并非人物的名字（当前角色字段中的一条备注）：打开**编辑**，然后修改**已见过**列表，用逗号分隔逐个填写名字。你写入的名字在故事被重新阅读时会保留；你删除的名字只有在它所在的章节被重新阅读后才会再次出现。 |
| **旧知识（n）** | 默认折叠。每个旧条目都可以被**复制**、**编辑**、**恢复**（从此重新生效）或删除。 |

<a id="mass-changes"></a>

### 批量修改

**批量修改**按钮（位于**追踪角色**旁边的列表图标）会打开一个窗口，其中以网格形式列出所有被追踪的角色及其全部条目（包括旧条目），每行带有复选框，显示条目的类型、文本、状态（*生效*，或旧条目：*已撤回*、*在审阅中被否决*、*已整理*）、来源（*初始状态*、*手动填写*、*从故事中习得*）以及习得所在的章节。你可以在多个网格中勾选条目（每个网格标题栏中的复选框会勾选该网格的全部条目；底部栏中的**全选** / **取消全选**则会作用于所有角色的全部条目），然后：

| | |
|---|---|
| **撤回所选（n）** | 已勾选的生效条目变为旧知识，效果与单独点击**撤回**相同。 |
| **恢复所选（n）** | 已勾选的旧条目从此重新生效。 |
| **删除所选（n）** | 在确认后永久删除已勾选的条目。 |

按钮上的数字表示每个按钮将改动多少个已勾选的条目。修改之后勾选状态会保留，因此已撤回的条目可以接着被删除。

窗口顶部的**导出为 JSON**会将本书中被追踪的角色（名称、别名、条目及其类型、状态、来源和锁定情况，以及角色已见过的人）下载为一个文件；处理过程的数据不会包含在内，因此该文件适用于任何书籍。**从 JSON 导入**会读取此类文件并将其写入本书，且只做添加：名称已被本书追踪（作为名称或别名）的角色，会获得其尚未拥有的别名、条目和已见过的人（类型和文本相同的条目会被跳过）；其他角色则成为新的被追踪角色。被导入的条目在本书中没有对应的章节来源，因此重新处理永远不会删除它：模型习得的条目会被视为手动填写，旧条目则保持为旧状态。导入后的消息会说明新增或更新了多少个角色，以及新增了多少个条目、有多少个条目原本就已存在。

<a id="what-goes-into-the-prompt"></a>

## 提示词中包含什么

对于每个属于当前角色的被追踪角色，提示词会加入一个如下所示的块：

```
What the characters of this scene know. A character acts only on the knowledge listed for it:

Fiora knows: Mara, a courier of the Guild of Lamps and the sister of her friend Nell; she owes the Guild of Lamps forty crowns.
Fiora does not know: that her father is alive, or that Thomas is her father.
Fiora has met: Mara.
Fiora is currently with: Mara, Thomas.
Fiora has never met or heard of anyone else in this story and knows nothing else of its secrets, plans or events.
```

只会发送生效的条目。最后一行（**封闭世界**行）用于阻止模型赋予角色它不可能拥有的知识。它涵盖故事所讲述的内容（人物、地点、秘密、计划、事件），而不涵盖一个生活在该世界中的人本来就知道的常识，因此角色仍然知道自己的城镇。你可以在设置中关闭这一行。一个被追踪但不在场的角色则完全不会获得任何内容，连一行说明它不知道什么的文字也没有。

<a id="who-is-present"></a>

### 谁在场

该块由章节的**当前角色**字段生成。该字段是自由文本，因此读取时较为宽松：

- 方括号中的文字会被忽略：`Tomáš (tired), Mizuki` 即 Tomáš 和 Mizuki；
- 名字会按**分隔符**切分（默认值：`,` `;` 换行、`/`、`|`、`、` `，` `；`）；
- ` - ` 或 `:` 之后的内容是备注，会被丢弃（`Mara - wounded`）；
- 大小写、重音符号以及开头的 *the* 都不影响匹配；
- 名字必须**整体**匹配：*Mara's brother* 不等于 *Mara*。当一个角色有多种写法时，请使用别名。关键在于：漏掉一次匹配只会少一个块，而错误的匹配则会把一个不在场景中的角色描写进去。

*视角人物*字段不会被单独读取，因此也请把视角人物写在当前角色之中。
<a id="processing"></a>

## 处理

此插件会跟随故事进展。**处理**功能按顺序读取当前分支中从**起始点**开始的各个部分，并记录一个**游标**（它最近读取的部分）。在不使用模型的情况下，它会记录谁与谁见过面：被追踪的角色与当前角色字段中同时出现的每个名字都算见过面，处理结果块会列出这些名字。使用模型时，它还能找出角色**了解到**的内容（参见[了解角色所获知的信息](#reading-what-the-characters-learn)）。

![处理面板](../../images/plugin-knowledgetracker-processing.png)

标签页顶部的面板显示当前进度。当新的部分定稿时（如果书籍启用了自动注释和重写，则在这些步骤之后），面板会自动重新加载；如果你以其他方式添加、编辑或删除了部分，请按下**刷新**按钮（齿轮旁边的箭头）以重新读取故事。面板包含以下内容：

- **立即处理**：读取尚未处理的部分。
- **处理下一部分**：每次只读取第一个尚未处理的部分，逐步进行（使用模型时，无论*每次运行的部分数*如何设置，都只对该部分发送一次请求）。用于试用设置，或查看模型对单个部分的结果。命令 `knowledge-process` 在 `parts` 设为 1 时效果相同。
- **起始点**：处理开始的部分（默认为*全书开头*）。起始点之前的部分永远不会被读取。将其前移会从新的起点重新读取各部分，将其后移则保留已读取的内容。
- **已处理的部分**：最近读取过的部分。如果某部分的文本在**处理后有所更改**（你编辑或重写过它），该部分会被标记；插件不会因此自动重新处理。每行的按钮**从此处重新处理**会撤销该部分及之后部分所产生的内容（你手动编写的条目和撤回记录会保留），然后重新读取这些部分。

当启用**自动处理新部分**（默认关闭）时，插件会自动执行以下操作：

- 在生成开始之前，处理自上次以来新写的部分，使提示词了解谁与谁见过面。通过*重新生成*或切换候选版本而被替换的部分会被忽略。使用模型时，只有在**应用前询问**关闭时（见下文）才会借助模型读取；否则仅记录谁与谁见过面，模型的结果需从标签页手动启动，因为不会在生成过程中强制你进行审阅。
- 当某个部分被**重新生成**并收到新文本时，从旧文本中获知的内容会被撤销。
- 当你**切换候选版本**或切换到另一分支时，游标会回退到两个分支共有的最后一个部分。
<a id="reading-what-the-characters-learn"></a>

## 阅读角色所知的内容

在设置中勾选 **用模型阅读角色所知的内容**。然后点击 **立即处理**，模型会针对故事中接下来的各个部分，判断每个被追踪的角色在其中**了解到**了什么：看到、听到、读到或被告知的内容。它还会指出哪些条目被故事**推翻**了（例如角色在相遇之后仍然“从未见过托马斯”）。请求中包含各个部分（及其视角和在场角色）、每个被追踪角色当前所知的内容，并可按您的选择包含世界书。模型会被告知：不要记录该世界中的人本来就知道的常识（例如谁是国王），也不要记录从角色自身设定中自然推出的内容（例如女魅魔知道自己有尾巴），并且对于不确定的内容一律不予报告。没有出现在任何部分中的被追踪角色，不会被询问。

每次运行只向模型发送一个请求。当 **立即处理** 需要超过三个请求时（例如一段尚未处理的长篇故事，或 **每次运行的部分数** 设得很低），它会先告诉您需要处理多少个部分和请求，以及大约有多少文本会经过模型，并在您确认后才开始。每个请求还会附带指令、世界书和角色所知的内容，因此实际费用高于仅计算文本的费用。

当 **提问后再应用** 关闭时，变更会立即应用，并且每项变更都会写入标签页“处理”部分中的 **自动应用** 日志：哪个角色获得了什么或失去了什么，来自哪个部分。日志中的内容不可编辑，但每一行都有一个 **撤销** 按钮：新增的条目会被拒绝（它会保留在 *旧知识* 中，与审阅中被拒绝的新增条目一样），被撤回的条目会重新变为有效。如果您此后手动编辑、删除或撤回了某行对应的条目，该行将保持不变。日志保留最近 200 条变更。

当 **提问后再应用** 关闭时，新部分一旦定稿就会被读取：即生成结束时，或者，如果书籍开启了自动注释（及重写）或翻译，则在其完成时读取，这样模型就能在您阅读的同时，读取您保留的文本并进行工作。这是[部分之后的步骤](../books/story-editor.md#what-follows-a-generated-part)之一。之后的生成会发现角色知识已是最新的，无需等待。尚未完成的内容（您中止的运行、关闭的窗口）会像以前一样，在下次生成之前读取。

模型工作时，页面上会悬浮一个小型 **进度面板**。它是**非模态**的：您可以继续阅读和编辑故事，并且可以通过标题栏**拖动**它。关闭它只会隐藏面板，工作仍会继续（**取消** 会停止工作）。

![进度面板](../../images/plugin-knowledgetracker-progress.png)

模型回答时，面板会实时显示 **模型正在写的内容**：先是它的推理过程，然后是答案，因此在慢速模型上长时间等待时，不会只看到一个空白进度条。请求结束后，同样的文本会保留在 **模型的思考** 下（运行中每个请求各占一个区块，包含它的回答）；即使模型没有提出任何变更、也没有打开审阅，这些内容也会保留。标签页中会保留一个 **上次运行：模型的思考** 按钮，点击即可再次打开面板，以便您了解为什么没有添加任何内容。

模型回答后，面板会提示并显示 **审阅变更**；标签页处理面板中（*3 项待审阅变更*）也有同样的按钮。**审阅界面不会自动打开。** 它是一个按角色分组的变更表格：

![审阅变更](../../images/plugin-knowledgetracker-review.png)

表格下方的 **模型的思考**（默认折叠）保存了模型在给出答案之前的推理过程（如果模型发送了该内容）。它会说明为什么提出某项变更，或者为什么您预期的某项变更缺失，以便您在应用前判断变更是否合理。不进行推理的模型不会在此显示任何内容。

| | |
|---|---|
| 复选框 | 该变更是否被应用。默认全部勾选；每个角色都有 **全选** / **全不选** 按钮。 |
| **撤回** / **新增** | 撤回会使条目变为旧知识（条目会被保留，参见[标签页](#the-knowledge-tab)）。新增则是一个新条目，类型为 *知道* 或 *不知道*。新增条目的文本和类型可以在应用前**编辑**。 |
| 引文 | 部分中显示该变更的原文，以及它所在的部分。若在该部分中找不到此引文，则会被标记：模型可能编造了它，请在接受前检查。 |

**应用** 会应用已勾选的变更并继续下一步。**取消** 会停止整个系列，且不做任何变更：下次会再次提出相同的部分。您取消勾选的新增条目会被**保留为旧知识**及其引文（您可以恢复）；未勾选的撤回则保持条目原状。模型提出但无法使用的内容（它未被询问的角色、不存在的条目、没有引文的变更、角色已经知道的内容）会列在 *已略过* 下。已应用的变更会记录其所属部分，因此 **从此处重新处理** 可以再次撤销它们。如果您在审阅期间故事发生了变化（例如切换了分支、删除了某个部分），变更将不会被应用，您需要重新处理。

部分会以**每次运行的部分数**（默认为 1）为单位分批读取；若某一批超出模型的上下文长度，则会被截断到能容纳的范围。系列会逐批持续进行，直到最后一个已定稿的部分；在需要您确认的系列中，模型未发现任何内容的运行会被跳过，不再询问。**提问后再应用** 关闭时，变更会立即应用，面板会保留一份日志，每次运行一行。

!!!
该提示词仅在少量场景上针对某个模型进行了测试，并未广泛验证：它能防止角色了解到其未曾感知的内容，但请检查所提出的变更，尤其是出现在长场景中的角色。请求会发送到您在下方选择的模型，并承担该服务通常的费用与隐私条款。
!!!

<a id="tidying-the-knowledge"></a>

## 整理知识

模型会记录每个角色所了解的内容，而在长篇故事中，这份列表会不断增长，其中有许多琐碎条目，不必每次请求都发送给模型。**整理知识**（位于 **立即处理** 旁边，需要开启模型设置）会请求模型重新阅读某个角色所知的内容，并以故事最近处理过的部分作为上下文，然后进行以下操作：

- **删除**不值得保留的条目：琐事、场景中所有人都看到过的细节（故事本身已经记录了这些内容）、已被后续事件超越的内容，或与其他条目内容重复的内容；
- **合并**关于同一件事的多个条目，合并为一个并保留所有事实。

被删除或合并的条目不会真正删除：它们会变为*旧知识*，并且可以恢复。这些变更会像阅读结果一样接受审阅（由 **提问后再应用** 决定），或立即应用并写入日志，附带 **撤销** 按钮。

整理过程只能改动模型学到的内容中、您未**锁定**的部分。初始条目、您手动添加或编辑过的条目、已锁定的条目以及旧知识永远不会被改动（前两类和锁定的条目会展示给模型，以便它看到某个条目会与哪些内容重复）。一个很久没有在任何部分中出现的秘密，本身并不是删除它的理由，提示词中也明确说明了这一点；模型存疑时会保留该条目。模型学到的条目少于 **整理：条目数不少于** （8）时，该角色不会被整理；**整理：部分上下文数** （10）表示它会读取最近处理过的多少个部分。

**自动整理**（一项设置，默认关闭）会在一次运行结束时自动执行整理，前提是该次运行的变更无需询问即可应用（即 **提问后再应用** 关闭，因此新部分也会被自动阅读），并且自上次整理以来，模型已读取了 **整理前的部分数** （10）个部分。它所做的变更会被应用，并写入日志，附带 **撤销** 按钮，该次运行的日志中也会注明。您需要审阅的运行绝不会自动开始整理；条目过少的角色会被跳过，不会询问模型。

在命令栏中也可以执行相同的操作：`knowledge-tidy`（`ask true` 以列表形式获取变更；此时打开的标签页会显示审阅按钮），以及 `lock-knowledge` / `unlock-knowledge`，分别指定角色和条目编号。
<a id="settings"></a>

## 设置

*追踪角色*旁边的齿轮：

| 设置 | |
|---|---|
| **在提示中** | 将该块插入每次生成的提示中。开启时按钮变为绿色。 |
| **深度** | 插入位置，从提示末尾按消息数计算：`0` 表示放在本轮指令之后，`1` 表示放在指令之前。它永远不会排在系统提示之前。 |
| **角色** | 以 *System*、*Assistant* 还是 *User* 消息发送。 |
| **声明没有其他已知信息** | 封闭世界声明。 |
| **将角色所知内容提供给标注** | 开启（默认）时，[用 AI 标注](#annotating-with-what-the-characters-know) 会获得本部分开始时被追踪角色所知的内容。 |
| **自动处理新部分** | 参见[处理](#processing)。 |
| **借助模型读取角色的新获知内容** | 处理时会让模型判断每个被追踪角色学到了什么，并提出建议。关闭（默认）时，处理只记录谁见过谁，不产生额外开销。 |
| **应用前询问** | 开启（默认）时，每项建议都会先供你审阅。关闭时，建议会立即应用并记入日志。 |
| **让模型阅读早先的部分** | 模型读取新部分时，可以阅读某条条目所获知的那一部分（条目会注明“在第 12 部分中获知”），以判断它读到的内容是否证实、重复或与之矛盾：例如，之前听来的传言现在亲眼所见。每次请求最多读取 5 个部分，每个部分只读一次；过长的部分文本会被截断以适应上下文，审阅界面会显示模型读取了哪些部分。每次读取都会增加一轮与模型的交互，因此默认关闭。无法调用函数的模型仍按原方式读取请求。 |
| **每次运行的部分数** | 一次请求读取的部分数量。数量越大越省钱，但答复会更长，审阅也更困难。 |
| **自动整理**，**每处理这么多部分后整理** | 当一次运行在不询问的情况下应用其更改时，每隔这么多部分（10）自动执行一次整理。默认关闭。 |
| **整理：上下文部分数** | 整理过程读取最近处理过的部分的数量（10）。 |
| **整理：至少这么多条目** | 模型已学到的（且未锁定的）条目数少于此值的角色不会被整理（8）。 |
| **供模型使用的设定集** | *部分激活的条目*（默认：生成这些部分时会用到的条目）、*整本设定集*（所有条目；若放不进上下文，则只发送已激活的条目，并在备注中说明）或*不使用设定集*。 |
| **提取所用的模型／协议** | 留空：使用本书的模型。这项任务用较便宜的模型即可；在只保存一个提示缓存的服务器上，单独使用一个模型可避免它被替换。 |
| **本书的分隔符** | 在“在场角色”字段中，用于将名字拆分开的分隔符，每行一个名字（换行符为 `\n`）。像 `and` 这样的词会按空格拆分，因此 *Jack and Jill* 在你添加之前会保持为一个名字。 |
| **我的分隔符（所有书籍）** | 对你所有书籍生效的同类设置。本书自己的分隔符优先；两者都未设置时，使用内置分隔符。 |

<a id="prompts"></a>

## 提示

阅读时的系统消息（**知识提取提示**）和整理过程的消息（**知识整理提示**）是[继承设置](../books/prompts.md#inherited-settings)：一本书优先使用自己的设置；若没有，则使用上层最近一个设置了该项的文件夹的设置；再没有，则使用你的全局设置；最后才使用经过真实模型测试的内置文本。

你可以在书籍的*提示*选项卡中、*扩展设置*下设置它们，也可以在文件夹的对话框中设置，或在*设置 → 扩展设置 → 知识追踪器*中为你所有的书籍统一设置（留空时，灰色字体会显示内置文本）。请保留内置文本中的 JSON 答复格式：插件通过它读取答复。当模型可以阅读早先的部分时，插件会自动添加针对 `read_part` 的指令，因此你的提示中无需包含这些内容。

<a id="annotating-with-what-the-characters-know"></a>

## 用角色所知内容进行标注

上面的块可以防止模型在*写作时*让角色变得无所不知。同样的记录也有助于找出仍然混入的错误。当模型[标注某个部分](../books/annotations.md#letting-a-model-annotate)时（**用 AI 标注**、一段范围内的部分、自动标注，`/generate-annotation`），追踪器会告诉它该部分*开始时*被追踪角色所知的内容，编辑器会标记那些说出、想到或做出他们不可能知道之事的角色。例如：*Fiora 叫出了 Thomas 的名字；记录显示她从未见过他。* 备注会指出具体的事实。

- **事实以该部分为准，而非全书结尾。** 角色在后面的部分中才学到的内容，此时尚未为人所知；后面的部分才撤销的条目，在此之前仍然成立。该部分自身带来的内容（学到了什么、遇见了谁、在其中什么不再成立）会单独列出，因此不会把该部分的前半段与后半段混在一起检查。
- **哪些角色。** 包括：在该部分的*在场角色*中、是其视角人物，或在其文本中被提及的被追踪角色（全词匹配，不分大小写，也包括别名）。
- **在任何时候都不是事实的条目会被排除。** 包括：你手动撤销的条目、整理过程删除的条目，以及你在审阅中拒绝的条目。
- **只使用已记录的内容。** 模型会被告知，记录中没有写明的内容不是事实，因此不会因为追踪器从未得知的事情而标记某个角色。*声明没有其他已知信息*还会在角色见过的人后面加上“（没有其他人）”。
- 如果被审阅部分之前有某个部分未被追踪器读取，事实中会注明这一点：那里角色所学到的内容缺失，此时先执行**立即处理**会得到更好的审阅结果。
- 这些事实会增加标注请求的 token 消耗，且仅针对包含被追踪角色的部分。若要关闭，请使用**将角色所知内容提供给标注**。

<a id="the-block-as-a-macro"></a>

## 作为宏使用的块

除了（或同时取代）自动插入，你还可以通过 [{%{`{{command::knowledge-tracker-block::<characters>}}`}%} 宏](../templates/macros.md#commands)自行放置该块。其参数是场景中角色的列表，因此模板可以传入该部分的在场角色字段：

```
{%{{{command::knowledge-tracker-block::{{presentCharacters}}}}}%}
```

无论**在提示中**是否开启，该宏都会输出该块，因此使用宏时请关闭该选项，否则模型会收到两次。深度和角色对宏不起作用（该块属于包含该宏的消息的一部分）。如果列出的角色都未被追踪，它不输出任何内容。命令宏的答复会与新部分所接续的那个部分一起保存，因此从同一部分进行的第二次生成不会看到你在中间所做的更改；而重新生成和换一版则会重新询问。

<a id="commands"></a>

## 命令

适用于[命令行](../commands/index.md)和代理：

| 命令 | |
|---|---|
| `knowledge-status` | 设置以及处理进度。 |
| `list-tracked-characters`、`add-tracked-character`、`update-tracked-character`、`delete-tracked-character` | 被追踪的角色，可通过名字、别名或编号指定。 |
| `list-knowledge`、`add-knowledge`、`retract-knowledge`、`restore-knowledge`、`delete-knowledge` | 某个角色的条目，通过其在 `list-knowledge` 中的编号指定。 |
| `knowledge-process` | 立即处理（`parts`：最多处理该数量）。开启模型时，`ask true` 会以编号列表的形式返回模型找到的更改并予以保留：此时尚未更改任何内容。打开的“知识”选项卡会显示一个**由命令找到的更改**按钮，点击后打开常规审阅界面（应用／取消）；代理则使用 `apply-knowledge-changes` 来应用。 |
| `apply-knowledge-changes` | 应用保留的更改，可以是全部，也可以是指定的编号（与选项卡审阅中的**应用**相同）。 |
| `knowledge-tidy` | 整理过程。加上 `ask true` 时，会以编号列表返回更改并予以保留（选项卡会显示一个按钮用于审阅；`apply-knowledge-changes` 应用它们）。 |
| `lock-knowledge`、`unlock-knowledge` | 锁定某个条目（角色、条目编号），使整理过程不再改动它；或解除锁定。 |
| `knowledge-reprocess` | 从某个部分（其句柄或位置）重新处理；会先询问。开启模型时，它只会回退状态，`knowledge-process` 则会重新读取各部分。 |
| `knowledge-set-start` | 设置起点；不指定部分时，设为全书的开头。 |
| `knowledge-tracker-block` | 以文本形式输出该块，供宏使用。 |

命令行会按空格拆分参数：角色列表请用引号括起来（`/knowledge-tracker-block "Fiora, Mara"`）。

## 存储

所有内容都随书籍一起保存（保存在其属性中），因此它也包含在[书籍备份](../books/backups.md)和副本中。
