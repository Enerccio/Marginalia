# 도움말 어시스턴트

도움말 어시스턴트는 Marginalia 매뉴얼을 바탕으로 Marginalia에 관한 질문에 답하는 채팅입니다. 관리자는 이 어시스턴트가 사용할 모델을 고르고, 질문할 수 있는 사용자에게 [권한](permissions.md)에서 **도움말 어시스턴트** 권한을 줍니다(관리자는 항상 사용할 수 있습니다). 사용자는 자신의 모델이 없어도 됩니다. 권한 기능이 도입되기 전부터 있던 사용자는 그때 어시스턴트가 켜져 있었다면 이 권한을 받고, 새 사용자는 권한이 없습니다.

사용자가 어시스턴트를 쓸 수 있게 되면, 창 오른쪽 아래에 둥근 로봇 버튼이 보입니다. 이 버튼을 누르면 채팅이 열립니다. 패널에는 어떤 모델이 답하는지가 표시되고, 사용자의 제한이 적용될 때는 경고가 나타납니다(see [Who pays](#who-pays)). 모델은 매뉴얼에서 답을 찾고(매뉴얼을 검색하고 그 페이지를 읽을 수 있습니다), 사용한 페이지를 [공개된 매뉴얼](https://enerccio.github.io/Marginalia/)로 연결되는 링크로 알려 주며(새 탭에서 열립니다), 설명합니다. 어시스턴트는 아무것도 바꾸지 않으며, 사용자가 허용하지 않는 한 사용자의 책을 볼 수 없습니다(see [Your books](#your-books)). 무엇인가 실패했을 때는 무슨 일이 있었는지 살펴볼 수 있고(see [When something goes wrong](#when-something-goes-wrong)), 관리자가 허용하면 사용자를 원하는 곳으로 안내할 수도 있습니다(see [Showing the way](#showing-the-way)). 대화는 사용자가 로그아웃할 때까지 유지되며(패널을 닫거나 페이지를 새로 고쳐도 유지됩니다), 빗자루 버튼을 누르면 대화가 지워집니다. 매뉴얼이 사용자의 인터페이스 언어로 번역되어 있으면 그 언어의 매뉴얼을 읽고, 링크도 그 언어의 매뉴얼로 연결됩니다. 번역되지 않은 페이지는 영어로 읽습니다.

![도움말 어시스턴트가 질문에 답하는 모습](../../images/help-assistant.png)

버튼은 사용자가 Marginalia를 열 때 나타나고, 모델과 제한 경고는 패널을 열 때마다 다시 읽힙니다. 권한을 회수하거나 모델을 삭제하면, 이미 페이지를 열어 둔 사용자는 페이지를 새로 고칠 때(또는 패널을 열 때) 버튼이 사라집니다.

<a id="settings"></a>

## 설정

**Admin → 도움말 어시스턴트**를 엽니다:

![도움말 어시스턴트 탭](../../images/admin-help-assistant.png)

| 설정 | |
|---|---|
| **모델** | *본인의* [모델](../inference-providers.md) 중 하나이며, 사용자와 공유할 수도 있고 공유하지 않을 수도 있습니다. 다른 관리자가 공유한 모델은 목록에 나타나지 않습니다. |
| **관리 데이터 읽기 허용** | 어시스턴트가 *관리자가 요청할 때* 확장 기능의 상태와 로그, 데이터베이스 백업, 관리 페이지의 기타 데이터를 읽을 수 있게 합니다(see [Administration data](#administration-data)). 기본값은 꺼짐입니다. |
| **관리자용 프롬프트**, **다른 사용자용 프롬프트** | 질문마다 모델이 받는 지시문입니다. [프롬프트](#prompts)를 참고하세요. |

다음 두 설정은 사용자에 따라 달라지며, 사용자의 **도움말 어시스턴트** [권한](permissions.md#settings-of-a-permission)에 들어 있습니다(**Admin → Users**에서 열쇠 버튼을 눌러 엽니다. 두 설정 모두 기본값은 꺼짐입니다):

| 권한의 설정 | |
|---|---|
| **제한 적용** | 공유 모델에만 해당합니다. [사용 비용 부담](#who-pays)을 참고하세요. |
| **인터페이스 탐색 허용** | 사용자가 무엇인가를 어디서 찾는지 보여 달라고 요청하면, 어시스턴트가 섹션을 열고, 탭을 선택하고, 무엇인가를 추가하는 대화상자를 열 수 있게 합니다(see [Showing the way](#showing-the-way)). |

이런 권한이 없는 관리자는 두 설정이 모두 꺼진 상태로 답변을 받습니다.

설정은 **저장**으로 저장됩니다. 어시스턴트는 [프로토콜](../protocols.md) 없이 모델에 요청하므로, 모델 자체의 설정이 그대로 적용됩니다. 모델을 삭제하거나 모델의 소유자가 더 이상 관리자가 아니면 어시스턴트는 스스로 작동을 멈춥니다. 그래서 일반 사용자 소유의 모델이 모든 사람에게 넘어가는 일은 없습니다.

<a id="what-the-assistant-sees-of-the-screen"></a>

## 어시스턴트가 화면에서 보는 것

모델은 사용자가 지금 무엇을 하고 있는지 볼 수 있습니다(질문이 "여기" 또는 "이것"에 관한 것이면 모델은 그렇게 하라는 지시를 받습니다). 열려 있는 섹션, 탭, 대화상자가 무엇인지, 화면의 각 부분에 대한 짧은 설명을 받습니다. 예를 들어 열린 책의 제목과 열린 탭, 또는 열린 대화상자의 제목이 여기에 포함됩니다. 열려 있지 않은 탭은 목록으로만 알려지며, 질문에 필요할 때만 읽습니다. 열려 있는 양식에 대해서는 현재 무엇이 잘못되었는지도 받습니다. 즉 양식이 유효하지 않다고 표시한 필드와 그 필드가 보여 주는 메시지, 비어 있는 필수 필드, 그리고 양식이 여러 필드에 걸쳐 검사하는 내용을 받습니다(모델의 경우, 응답은 컨텍스트보다 작아야 합니다). 받는 것은 필드의 *이름*뿐이며, 그 안에 입력된 내용은 받지 않습니다. 이야기 본문, 로어북 항목, API 키, 비밀번호는 절대로 받지 않습니다.

![새 모델의 양식을 아직 저장할 수 없는 이유를 설명하는 어시스턴트](../../images/help-assistant-form.png)

<a id="your-books"></a>

## 내 책

어시스턴트 패널에는 **어시스턴트가 내 책을 볼 수 있게 허용** 체크 상자가 있습니다. 기본값은 꺼짐이며, 각 사용자가 직접 설정합니다(사용자 설정에 저장됩니다). 그 아래의 안내문은 이것이 무엇을 뜻하는지 설명합니다. 어시스턴트는 책의 폴더 이름, 제목, 설명, 작성 설정을 읽고 본문에서 검색할 수 있지만, 이야기 본문은 결코 읽지 않습니다. 읽은 내용은 답변하는 AI에게 전송되는데, 그 AI는 위에서 선택한 모델입니다. 따라서 그것이 관리자의 통제 밖에 있는 외부 서비스라면 사용자에게 그 사실을 알려 주세요.

![책에 대한 체크 상자가 있는 어시스턴트 패널](../../images/help-assistant-books.png)

이 기능이 켜져 있으면 모델은 세 가지 함수를 받습니다. 모두 읽기 전용이며, 질문한 사용자의 책에만 적용됩니다:

| 함수 | |
|---|---|
| `list_folder` | 한 폴더의 하위 폴더와, 각 하위 폴더 아래에 있는 책의 수, 그리고 그 폴더의 책을 제목과 설명과 함께 보여 줍니다. `Sci-fi/Expanse` 같은 경로는 폴더를 가리키며, 경로가 없으면 최상위 수준을 뜻합니다. |
| `search_books` | 제목이나 설명의 단어, 또는 이야기 본문으로 책을 찾으며, 필요하면 특정 폴더 안에서만 찾습니다("진정한 연인에 관한 내 책은 어디 있지?"). 일치하는 항목이 어디에서 어떤 폴더에 있는지 알려 주지만, 찾은 본문은 반환하지 않습니다. |
| `get_book_settings` | 책의 언어, 시점, 시제, 문체와, 각각이 어디에서 왔는지(책 자체, 폴더, 사용자 설정, 또는 기본 제공 기본값)를 보여 줍니다. 프롬프트는 *사용자 지정 텍스트* 또는 *기본 제공 텍스트*로만 알려 주며, 그 출처도 함께 알려 줍니다. |

어시스턴트는 아무것도 바꾸거나, 옮기거나, 만들 수 없습니다. 목록은 잘라 내고(항목 백 개, 일치 항목 스무 개까지) 설명도 줄입니다.

<a id="when-something-goes-wrong"></a>

## 문제가 생겼을 때

사용자가 무엇인가 실패했다고 말하면("오류가 나요", "저장되지 않아요", "모델이 응답하지 않아요"), 어시스턴트는 Marginalia가 사용자에게 보여 준 내용을 읽을 수 있습니다. 여기에는 최근 오류, 모델 제공자에 대한 실패한 요청(잘못된 키, 존재하지 않는 모델, 한도 초과, 시간 초과 등), 경고, 저장되지 못한 양식의 메시지가 포함되며, 최신순으로 정렬되고 각 항목이 몇 분 전에 일어났는지도 함께 표시됩니다. 어시스턴트는 그 메시지가 무엇을 뜻하는지, 무엇을 고쳐야 하는지 설명하며, 열려 있는 양식이라면 어떤 필드를 바꿔야 하는지도 알려 줍니다.

무엇이 기록되고 어디에 기록되는지는 다음과 같습니다:

* 사용자에게 알림으로 오류나 경고로 표시된 모든 내용과, 실패한 검증의 메시지는 세션 동안 보관됩니다(최근 20개).
* 예상하지 못한 실패(스택 트레이스 대화상자가 나타나는 실패)와 제공자에 대한 실패한 요청은 브라우저 탭이 따로 보관합니다(최근 3개, 탭의 세션 저장소에 저장됩니다). 그래서 페이지를 새로 고치거나 세션이 만료된 뒤에도 남아 있습니다.

어시스턴트는 사용자가 본 텍스트와, 실패의 경우 예외의 이름과 메시지를 받습니다. 스택 트레이스는 받지 않습니다. 각 텍스트는 400자에서 잘리며, 키, 토큰, 비밀번호처럼 보이는 것은 제거됩니다. 하지만 메시지 텍스트에는 제공자나 시스템이 한 말의 일부, 예를 들어 요청에 대한 제공자의 응답이 여전히 들어 있을 수 있습니다. 답변하는 모델은 여러분이 고른 모델이며, 외부 제공자일 수도 있습니다. [선택할 때](#settings) 이 점을 염두에 두세요.
<a id="showing-the-way"></a>

## 인터페이스 안내

사용자의 권한에서 **인터페이스 탐색 허용**을 켜 두면, 사용자가 요청할 때(“로어북은 어디 있어?”, “백업 화면으로 데려다줘”, “모델은 어떻게 추가해?”) 어시스턴트가 화면에서 몇 가지 작업을 할 수 있습니다. 섹션(Books, Lorebooks, Settings 등)을 열고, 관리자 페이지(관리자만 볼 수 있음)를 열고, 설정·관리자 페이지·스토리 편집기의 탭을 선택하고, 책·모델·프로토콜을 추가하는 대화상자를 여는 버튼을 누를 수 있습니다. 대화상자는 열기만 하며, 사용자가 내용을 입력하고 확인하기 전까지는 아무것도 만들어지지 않습니다. 다른 대화상자가 열려 있는 동안에는 이 기능을 제공하지 않습니다. 어시스턴트는 무엇을 했는지 사용자에게 알려 줍니다.

그 밖의 일은 할 수 없습니다. 다른 버튼을 누르거나, 입력하거나, 저장하거나, 삭제하거나, 생성하거나, 대화상자를 닫거나, 로그아웃하지 않습니다. 사용자가 직접 열 수 없는 화면은 어시스턴트도 대신 열어 줄 수 없습니다. 또한 어시스턴트는 스스로 판단해 움직이지 않고, 요청을 받았을 때만 움직입니다. 탐색이 잠겨 있는 경우(열린 섹션에 저장되지 않은 변경 사항이 있거나, 책을 생성하는 중인 경우)에는 이동할 수 없습니다.

![어시스턴트가 요청에 따라 데이터베이스 백업 탭을 연 모습](../../images/help-assistant-navigate.png)

이 기능을 허용하면 모델에도 화면에 있는 요소들의 이름과 각 요소가 제공하는 기능이 전달됩니다. 이는 [어시스턴트가 화면에서 보는 것](#what-the-assistant-sees-of-the-screen)에서 설명하는 정보와 같은 종류입니다.

<a id="administration-data"></a>

## 관리 데이터

사용자의 권한에서 **관리 데이터 읽기 허용**을 켜 두면, 관리자가 요청할 때 어시스턴트가 관리자 페이지의 데이터를 읽을 수 있습니다(“왜 Side Query가 동작하지 않아?”, “마지막 백업은 언제 만들어졌어?”). 관리자가 아닌 사용자에게는 설정과 상관없이 이 데이터가 제공되지 않으며, 데이터를 읽을 때마다 이 조건을 다시 확인합니다.

| 주제 | 읽는 내용 |
|---|---|
| 확장 기능 | 설치된 모든 [확장 기능](../extensions/index.md)의 버전, 활성 여부, 사용자가 중지했는지 또는 시작에 실패했는지, 검증 결과 |
| 확장 기능의 로그 | 마지막 로그 줄(기본 40줄, 최대 200줄). **관리자 → 확장 기능 → 로그**에서 보는 내용과 같음 |
| 사용자 | 사용자 수, 관리자 수, 잠긴 계정 수. 이름은 포함하지 않음 |
| 데이터베이스 백업 | 데이터베이스 크기, 백업 개수, 가장 최근 백업 시각, 일정, 복원 대기 여부 |
| 정리 | [정리](cleanup.md)를 실행하면 무엇이 제거될지(실제로는 아무것도 제거되지 않음)와 정리를 막는 요인 |
| 애플리케이션 | Java 버전, 사용 중인 메모리, 애플리케이션이 실행된 시간 |

이 데이터는 읽기 전용입니다. 어시스턴트는 여기서 무엇도 시작하거나 중지하거나 제거할 수 없습니다. 이 데이터는 모두 응답하는 모델로 전송된다는 점을 기억하세요. 그 모델은 외부 제공자의 것일 수 있습니다. 또한 확장 기능의 로그에는 확장 기능이 작성한 텍스트가 들어 있을 수 있습니다. 로그 한 줄은 400자에서 잘리고 키, 토큰, 비밀번호는 제거되지만, 그 밖의 처리는 하지 않습니다. 그래서 이 설정은 사용자가 직접 켜기 전까지 꺼져 있습니다.

<a id="prompts"></a>

## 프롬프트

프롬프트는 두 가지입니다. 하나는 관리자용(관리자 페이지에 대해 물어볼 수 있는 사용자용)이고, 다른 하나는 그 밖의 모든 사용자용(관리 기능은 관리자만 사용할 수 있다고 안내받는 사용자용)입니다. 둘 다 기본값으로 채워져 있습니다. 텍스트를 바꾸고 저장할 수 있으며, **기본값으로 재설정**을 누르면 기본값으로 돌아갑니다. 비어 있거나 기본값과 같은 프롬프트는 "기본값"으로 저장되므로, Marginalia의 새 버전이 나오면 함께 개선됩니다. 직접 바꾼 프롬프트는 사용자가 관리하며, 최신 상태로 유지할지는 사용자가 정합니다.

프롬프트의 `{{manualIndex}}`는 매뉴얼 페이지 목록(경로, 제목, 페이지 내용 요약)으로 바뀝니다. 모델이 어떤 페이지를 읽을 수 있는지 이 목록으로 알게 됩니다. 이 부분을 빼면 모델은 검색으로만 페이지를 찾습니다. 매뉴얼에서 정보를 찾아보라는 지시와, 매뉴얼에 없는 질문에는 그렇다고 말하라는 지시는 유지하세요. 그렇지 않으면 답변의 신뢰도가 떨어집니다. 오류를 읽고, 인터페이스를 이동하고, 관리 데이터를 읽는 도구의 규칙은 Marginalia가 프롬프트에 추가하므로(직접 넣을 필요는 없습니다), 허용된 도구에 대해서만 추가됩니다.

<a id="who-pays"></a>

## 비용 부담

사용자는 모델이나 그 API 키를 볼 수 없습니다. 사용자의 질문은 애플리케이션을 거쳐 전달됩니다.

| 모델 | 사용자의 **제한 적용** 권한 | 일어나는 일 |
|---|---|---|
| 공유 | 켜짐 | 질문은 공유 모델에 대한 다른 요청과 똑같이 처리됩니다. 사용자에게 설정한 [제한](../inference-providers.md#limits-of-shared-providers)을 확인하고, 사용한 토큰을 사용자의 사용량에 더합니다. 사용자의 제한에 도달했거나 모델을 사용할 수 없는 사용자는 답변을 받지 못합니다. |
| 공유 | 꺼짐 | 모델의 소유자가 비용을 부담합니다. 사용자의 제한은 무시되며, 사용자에 대해서는 아무것도 집계되지 않습니다. |
| 공유 아님 | (해당 없음) | 모델의 소유자가 비용을 부담합니다. 제한이 없고, 사용자에 대해서는 아무것도 집계되지 않습니다. 이 모델은 어시스턴트만 사용합니다. |

본인의 질문도 같은 방식으로 집계됩니다. 본인에게는 이 모델이 다른 모델과 다르지 않습니다.
