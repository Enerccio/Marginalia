# 图像生成器

为故事的某一部分生成一张图像。模型根据该部分内容撰写图像提示词，你可以对其进行编辑，图像后端绘制出图片，你可以反复重新生成，直到满意后接受它。接受后，它会成为该部分的一张图像，与你通过部分菜单中的*图像*手动添加的图像相同（它会显示在故事中，并包含在导出内容里）。

本扩展本身不生成图像：它与 **ComfyUI** 服务器或支持 **OpenAI 图像 API** 的服务器通信（stable-diffusion.cpp、LiteLLM 以及许多托管服务也支持该接口）。

<a id="adding-a-backend"></a>

## 添加后端

*设置 → 扩展设置 → 图像生成器设置* 列出了各个后端。点击（+）添加一个，填写内容后保存*设置*页面。

| 设置 | 作用 |
|---|---|
| 名称、类型 | 窗口中显示的名称。**ComfyUI** 或 **OpenAI 图像 API**。 |
| 地址 | 服务器的基础地址，例如 ComfyUI 的 `http://localhost:8188`。 |
| Api 密钥 | 以 Bearer 令牌的形式发送。密钥会加密存储，且不再显示；输入新密钥即可替换，或使用**移除密钥**。 |
| 模型 | 仅限 OpenAI 图像 API：请求中的 `model`。 |
| 工作流 | 仅限 ComfyUI：在 ComfyUI 中通过 **Save (API Format)** 保存的工作流。在需要的位置写入 `{{prompt}}`、`{{negative}}`、`{{seed}}`、`{{width}}` 和 `{{height}}`。 |
| 服务器位于本机或我的局域网中 | 允许访问本地网络地址。对于云端服务器请保持关闭：这样它就无法被诱导去调用你自己的机器。 |
| 宽度、高度、负面提示词 | 窗口打开时的初始值（你可以在窗口中为单张图像更改它们）。 |
| 超时 | 等待一张图像生成的最长时间。 |
| 空闲后释放 | 参见[单块 GPU](#one-gpu-for-the-model-and-the-images)。 |

![设置中的一个后端](../../images/plugin-imagegenerator-settings.png)

**测试连接**用于检查地址和密钥。

该面板还包含放在每条提示词前面的**风格**（例如本书的画风，如 *watercolor, soft light*），以及**给提示词撰写者的指令**，即模型根据某一部分撰写提示词时所依据的文本。留空或保持未修改则使用内置指令。

<a id="making-an-image"></a>

## 生成图像

![部分菜单中的生成图像](../../images/plugin-imagegenerator-menu.png)

1. 在某一部分的菜单中选择**生成图像**。窗口中的模型（默认为本书所用模型，上次的选择会被记住）开始为该部分撰写提示词；你可以用**中止**停止，修改提示词，或点击**用模型撰写提示词**重新撰写。重新撰写之前，你可以填写以下内容：
   - **发送世界书条目**——本书世界书（及其子世界书）中的条目会像在正常生成时一样发送给模型，使其了解角色和场所的外观。当某条目的过滤器在该部分中被找到时，该条目会被发送：过滤器可匹配其正文、指令、场景设定、视角、在场角色，或你在*细节*中的内容。始终启用的条目也会发送。发送的条目数量受模型上下文长度限制（通知会告知有多少条目被省略）。此选择会被记住。
   - **细节**——画面必须呈现的内容或其呈现方式（*夜晚、她面部的特写、红色的裙子*）；提示词撰写者会遵循这些内容。它仅用于本窗口。
2. 选择后端并点击**生成**。在*尺寸与负面提示词*下，你可以为本窗口更改尺寸和负面提示词。
3. 图像出现后，**重新生成**会以新的种子再生成一张，**丢弃**会将其舍弃，**接受**会将其添加到该部分并关闭窗口。**中止**用于停止正在生成的图像（ComfyUI 会收到中断作业的指令）。

![模型撰写提示词后的窗口](../../images/plugin-imagegenerator-prompt.png)

![图像，以及接受、丢弃和重新生成按钮](../../images/plugin-imagegenerator.png)

打开的部分会立即在其正文下方显示新图像。

<a id="one-gpu-for-the-model-and-the-images"></a>

## 单块 GPU 同时供模型和图像使用

在一块较小的 GPU 上，语言模型和图像模型无法同时加载。扩展本身不管理显存；每个后端可以设置两组请求列表：

- **首张图像之前**——在窗口开始使用该后端时执行一次。例如，向你的代理发送一个请求，卸载语言模型并加载图像模型。
- **最后一张图像之后**——在你接受、丢弃或关闭窗口时执行，或距离上一张图像过去了**空闲后释放**设定的秒数时执行（这样一个被遗忘的窗口就不会一直占用 GPU；设为 0 则关闭此功能）。对于 ComfyUI，可以使用 `POST <address>/free`，请求体为 `{"unload_models": true, "free_memory": true}`；对于代理，则可以发送一个重新加载语言模型的请求。

如果 `llama-server` 以路由模式运行于 LiteLLM 之后，*之前*请求可以通过代理卸载语言模型：参见[为其他模型释放 GPU](../prompt-cache.md#freeing-the-gpu-for-another-model)。

这两个时机都接受一个**请求列表**，各请求依次执行（**添加请求**添加一项，垃圾桶图标则删除一项）。切换模型通常需要多个请求：先卸载语言模型，再启动图像服务器，图像生成完毕后再将其停止。每个请求包含：地址、方法（默认为 `POST`）、请求头（`名称: 值`，每行一个）、请求体、**超时**（留空为 60 秒，最多 600 秒；为加载大模型的服务器可设置更长时间）以及**之后等待**（在收到响应后暂停的秒数，适用于回复“好”之后仍在忙碌的服务器）。请求头与 API 密钥一样加密存储（请求通常会携带 `Authorization: Bearer ...`）。在你重新生成时后端会保持占用，因此只有第一张图像需要承担切换的开销。如果模型前面的代理按模型名称进行切换，则将两个列表都留空。

当*之前*列表中的某个请求失败时，其余请求不再执行，图像生成随之停止（提示信息会说明是哪个请求失败，例如 *Request 2 of 3: ...*），以免在仍然占满的 GPU 上加载其他内容。*之后*列表会**全部**执行，无论其中某个请求发生什么（每个服务器都必须被停止），并且第一个失败会以警告的形式显示。使用旧版本单个请求保存的后端，会将其显示为列表中的第一个请求。

**多人共用一块 GPU。** 所有服务器地址相同（`http://host:port`）的后端用户共享同一个闸门：*之前*请求在第一个启动的窗口时执行，*之后*请求在最后一个窗口结束时执行，因此关闭一个窗口不会在另一个窗口的图像生成过程中卸载模型；图像也会逐一生成（第二个窗口需等待轮到自己）。这些请求以最先和最后使用的用户的设置为准。

后端还可以指定其所运行的 GPU（**GPU（名称）**）。指定同一 GPU 的后端即使地址不同也会相互等待，这包括[有声书](audiobook.md)的后端（同一张卡上的语音服务器和图像服务器）：如果某用户的后端需要加载另一个模型，它会等待其他任务完成后再执行自己的请求，而不是加入一个并非它所需的加载过程。留空时，则只有发往相同地址的请求会相互等待。
