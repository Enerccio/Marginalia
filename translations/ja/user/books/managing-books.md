# 書籍の管理
<a id="the-book-list"></a>

## 本一覧

**本**タブには、あなたの本が一覧表示されます。他のユーザーの本は表示されません。一覧には一度に1つの[フォルダ](folders.md)が表示され、現在のフォルダ内のフォルダは、その本の上に表示されます。トップレベルでフォルダをまだ作っていない場合は、単にすべての本が表示されます。

![本タブ](../../images/books.png)

| 列 | |
|---|---|
| **名前** | 本の名前。 |
| **タグ** | 本のタグ。 |
| **作成日時** | 本が作成された日時。 |
| **最終更新** | 本が最後に変更された日時。 |

一覧は*最終更新*順に並び、新しいものが先頭に来ます。列の見出しをクリックすると、その列で並べ替えられます。複数の列で並べ替えている場合は、指定した順に従ってすべての列で並べ替えられます。

見出しの下の行で一覧を絞り込めます。

- **名前** - 名前が入力したテキストで*始まる*本。`*` をワイルドカードとして使えます。例えば `*dragon` は、名前のどこかに「dragon」を含むすべての本を見つけます。
- **タグ** - 選択したタグを*すべて*持つ本。

フィルタ行の末尾にある更新ボタンで一覧を再読み込みします。

各行にはボタンがあります。星印は本を[お気に入り](folders.md#favorites)にし、ペン印は本を開きます。**フォルダに移動**は本を[フォルダ](folders.md)に入れ、コピーボタンは本の複製を作り、ゴミ箱ボタンは本を削除します。見出しには**新しいフォルダ**、**管理**メニュー（**整理**：本やフォルダを[移動・コピー](folders.md#organise)するためのウィンドウ、**タグを付ける**、**統計**、そして**一括変更**のサブメニュー）、および**インポート**があります。インポートは、お手元のファイルから新しい本を作ります（[本のインポート](#importing-a-book)を参照）。

<a id="a-book-is-open-in-one-window"></a>

### 本は1つのウィンドウでだけ開ける

本は、ブラウザのタブをまたいでも、他のブラウザやスマートフォンでも、同時に1つのウィンドウでしか開けません。他の場所で開いている本を開こうとすると、Marginalia はそれが開かれている時刻を示し、**ここで開く**を実行するかを尋ねます。**ここで開く**を選ぶと、本はここで開かれ、他の場所のウィンドウは理由を示したうえで閉じられます（他の場所で部分の生成中であれば、質問にその旨が表示され、**ここで開く**を選ぶと生成が停止します。それまでに書かれた内容は残ります）。**キャンセル**を選ぶと、本は元の場所に残ります。ログインして Marginalia が前回開いていた本を開く場合は、他のウィンドウの本を奪うことはなく、本を閉じたままにして、その本がどこで開かれているかを知らせます。閉じられたタブや、電源が切れたデバイスのウィンドウは本を保持しません。その場合は**ここで開く**で即座に本を開けます。

<a id="advanced-search"></a>

### 詳細検索

ヘッダーの**管理**の隣にある**検索**（スマートフォンではヘッダーの虫眼鏡）を開くと、フィルタ行よりも多くの条件で本を探せるウィンドウが開きます。確認したい項目を入力し、残りは空のままにして、**検索**を押します（テキスト欄でEnterを押しても同じです）。

| 項目 | 次のような本を探す... |
| ----- | -------------- |
| **名前** | 名前にテキストを含む本（`*` はワイルドカード）。 |
| **含めるタグ** | タグを持つ本。欄の横で選んだ*すべてのタグ*または*いずれかのタグ*で絞り込みます。 |
| **除外するタグ** | タグを持たない本。*いずれかのタグ*を選ぶと、そのうち1つでも持つ本は除外されます。*すべてのタグ*を選ぶと、すべてを持つ本だけが除外されます。 |
| **作成日（開始 / 終了）**、**更新日（開始 / 終了）** | 指定した期間に作成された、または最後に変更された本。*終了*の日付の日も含まれます。 |
| **部分数（開始 / 終了）** | すべての分岐で、その数の部分を持つ本（ゴミ箱の部分は数えません）。 |
| **テキスト** | テキストのすべての単語を含む部分を持つ本。単語、`"フレーズ"`、`*` は[物語の検索](story-editor.md#searching-the-story)と同様に動作します。 |
| **バージョンを含める** | オフ（既定）：部分の現在のテキストだけを検索します。オン：部分の以前のバージョンに単語がある場合も本が見つかります。詳しくは[バージョン履歴](version-history.md#searching-the-old-text)を参照してください。 |
| **すべてのブランチを検索** | オフ（既定）：本が今いる分岐（本を開いたときに見える物語）でだけテキストを検索します。オン：すべての分岐の部分を検索します。 |

本は、入力したすべての条件を満たす必要があります。見つかった本は、そのタグとともに下に一覧表示され、最後に変更されたものが先頭に来ます。列の見出しをクリックすると並べ替えられます。フォルダのボタンは本を開きます（検索結果の上に表示されるウィンドウで開くため、本を閉じると検索結果に戻ります）。**クリア**は入力欄を空にします。

![本の詳細検索](../../images/book-search-advanced.png)

<a id="cloning-a-book"></a>

### 本の複製

複製ボタンは、新しい本の**名前**を尋ねます（既定では元の名前に *(Copy)* を付けたもの）。また、既定でオンになっているチェックボックス**現在の分岐のみ**があります。新しい本は独立した本で、次のものを受け取ります。

![本の複製](../../images/book-clone.png)

- 本の設定（説明、言語、プロンプト、視点、時制、文体、バックアップ設定）、拡張機能が本に保存しているデータ、およびタグ。
- 同じ**モデル**、**プロトコル**、**ロアブック**。ロアブックは*コピーされず、リンクされます*。そのため、一方を変更するともう一方にも反映されます。
- 物語。部分、その要約、画像は、それぞれ独自のコピーになります。**現在の分岐のみ**をオンにすると、[現在の分岐](branches-and-story-tree.md)の先頭から末尾までの部分だけがコピーされます。オフにすると、すべての分岐がコピーされます。

複製には、独自の[バージョン履歴](version-history.md#backups-copies-and-the-trash)が作られます（部分ごとに1バージョン）。元の本の履歴はコピーされません。

元の本が公開されていても、複製は公開されません。元の本は変更されません。複製は元の本と同じ[フォルダ](folders.md)に入れられます。

<a id="tagging-many-books-at-once"></a>

### 多数の本に一度にタグを付ける

ヘッダーの**管理**メニューにある**本にタグを付ける**は、多数の本にタグを付けたり、そこから外したりするウィンドウを開きます。個々の本を開く必要はありません。**タグ**を選ぶか（新しいタグを入力してEnterを押すこともできます）、一覧にはすべての本とそのタグが表示されます。選んだタグを持つ本が先頭に来て、そのタグが強調表示されます。各行には、その本にタグを付ける**+**ボタンと、タグを外す**-**ボタンがあります。複数の本に同じ操作をするには、それらのチェックボックスをオンにし（見出しのボックスをオンにすると全部選べます）、下部の**チェックした項目にタグを付ける**または**チェックした項目からタグを外す**を使います。エージェントが作業中の本はグレーで表示されます。これはロックされているため、実行が一時停止または停止されるまで、チェックも変更もできません。同じウィンドウで、[ロアブックとそのエントリ](../lorebooks/lorebooks.md#tagging-many-at-once)にもタグを付けられます。

![本へのタグ付け](../../images/multi-tag-books.png)

<a id="changing-the-model-and-protocol-of-many-books"></a>

### 多数の本のモデルとプロトコルを変更する

**管理**メニューの**一括変更**サブメニューには、**モデル/プロトコルの一括変更**という項目があります。これは、多数の本に1つの**モデル**と/または1つの**プロトコル**を、本を1つずつ開かずに設定するウィンドウを開きます。ボックスを空のままにすると（*置き換えない*と表示されます）、その部分は変わりません。モデルだけを選べば、モデルは変わり、プロトコルはそのままです。表には、現在の[フォルダ](folders.md)の本が、名前と現在のモデル・プロトコルとともに一覧表示されます。**サブフォルダを含める**をオンにすると、その下の本も加わります。**名前**の下のフィルタに入力して一覧を絞り込み、変更する本にチェックを付けます（見出しのボックスは、表示されているすべての本にチェックを付けます）。そして**置き換えて閉じる**を押します。フィルタで隠れている本のチェックは外れるため、表示されているものだけが変更されます。エージェントが作業中の本はグレーで表示されます。これはロックされているため、実行が一時停止または停止されるまで、チェックも変更もできません。

![多数の本のモデルとプロトコルの変更](../../images/mass-change-model-protocol.png)

同じメニューの**言語の一括変更**も、本の**言語**について同じように動作します。言語を選び、本を絞り込んでチェックを付け、**置き換えて閉じる**を押します。表には、各本の現在の言語と、フォルダから受け継ぐ言語が表示されます（[言語](folders.md#language)を参照）。

![多数の本の言語の変更](../../images/mass-change-language.png)

<a id="renaming-many-books"></a>

### 多数の本の名前を変更する

**名前の一括変更**は、チェックした本の名前を一度に変更します。方法を選びます。

| 方法 | 動作 |
|---|---|
| **先頭に追加** | 名前の前に**追加するテキスト**を付けます。 |
| **末尾に追加** | 名前の後に**追加するテキスト**を付けます。 |
| **検索して置換** | 名前内の**検索**のすべての出現を**置換後の文字列**に置き換えます（空の場合は削除します）。テキストはパターンではなくそのまま扱われます。**大文字と小文字を区別**は既定でオフです。 |
| **本に番号を付ける** | 本に番号を付けます。**名前のパターン**が新しい名前になり、`{name}` は現在の名前、`{n}` は番号を表します。例えば `{name} {n}`、`{n}. {name}`、`Chapter {n}` のように書きます。チェックした最初の本には**開始番号**が、次の本からは**増分**ずつ増えた番号が付けられます。**桁数**を指定すると、番号は0で埋められます（`007`）。 |

![すべてのフォルダの本に番号を付ける](../../images/mass-rename.png)

**新しい名前**の列には、入力中にチェックした各本が受け取る名前が表示されます。**名前を変更**を押す前に確認してください。番号付けは、一覧の順序（名前順）でチェックした本を数えます。新しい名前の先頭と末尾の空白は取り除かれます。テキストがない場合、パターンに `{n}` がない場合、名前が変わらない場合、または名前が空になってしまう場合は、何も名前が変更されず、ウィンドウは開いたままになります。フィルタ、**サブフォルダを含める**、ロックされた本の扱いは、他の一括変更と同じです。

**タグを付ける**と**フォルダにタグを付ける**は、現在のフォルダにある本、またはフォルダに対して、同じ方法で動作します。
<a id="creating-a-book"></a>

## 新しい本を作成する

1. **本を追加** をクリックします。
2. 名前を入力して確定します。

新しい本は、一覧に表示されている[フォルダ](folders.md)に入ります。インポートした本も同様です。作成するとすぐに開きます。[設定](../account.md)のタブで **既定のモデル** と **既定のプロトコル** を設定済みであれば、それらが最初から使われます。設定していない場合は、生成の前に *概要* タブで選択してください。

<a id="importing-a-book"></a>

### 本のインポート

一覧のヘッダにある **インポート**（スマートフォンではファイルのボタン）を押すと、新しい本の元になるものをすべて扱える 1 つのウィンドウが開きます。
**作成元** を選ぶと、名前の下に表示されるテキスト、受け付けるファイル、オプションが変わります。

| 作成元 | アップロード | オプション |
|---|---|---|
| **アーカイブからインポート** | `.md` ファイルをまとめた `.zip`。ファイルごとにパートになります。[本へのインポート](story-editor.md#importing-into-the-book)を参照 | なし |
| **SillyTavern からインポート** | 1 つ以上の `.jsonl` チャット。[下記](#importing-from-sillytavern)を参照 | ユーザーとアシスタントのメッセージを 1 つのパートにまとめる |
| **LM Studio からインポート** | 1 つ以上の会話。[下記](#importing-from-lm-studio)を参照 | ユーザーとアシスタントのメッセージを 1 つのパートにまとめる |
| **ドキュメントからインポート** | 原稿を 1 つのファイルで（Word、LibreOffice、RTF、Markdown、プレーンテキスト、EPUB）。[下記](#importing-a-finished-manuscript)を参照 | パートあたりの語数、章の見出しレベル |
| **Obsidian ボールトからインポート** | ボールトの `.zip`。[下記](#from-an-obsidian-vault-or-a-scrivener-project)を参照 | 同じ |
| **Scrivener プロジェクトからインポート** | `.scriv` プロジェクトの `.zip`。[下記](#from-an-obsidian-vault-or-a-scrivener-project)を参照 | 同じ |

ファイルをアップロードし、本の名前を付けて（ファイルから、ドキュメントのタイトルから、またはチャットのキャラクター名から自動入力されます。空のままにすると本は *New book* という名前になります）、**インポート** をクリックします。**停止** のある進行状況ウィンドウに、保存されているパートが表示されます。停止しても、それまでに保存された分は残ります。作成元が読めないファイルは警告とともに拒否され、ほかのアップロードはそのまま残ります。

本の設定メニュー（⚙）から開く同じウィンドウでは、その本の好きな位置にパートを追加できます。[本へのインポート](story-editor.md#importing-into-the-book)を参照してください。

![インポートウィンドウの作成元](../../images/import-source.png)

![テキストファイルの zip を新しい本としてインポートする](../../images/archive-upload.png)

<a id="importing-a-finished-manuscript"></a>

### 完成した原稿のインポート

すでにある原稿の場合は、**ドキュメントからインポート** を選んでファイルをアップロードします。対応形式は `.docx`（Word）、`.odt`（LibreOffice、OpenOffice）、`.rtf`（リッチテキスト。WordPad、TextEdit などの任意のプログラムから）、`.md`（1 つの Markdown ファイル）、`.txt`（プレーンテキスト）、`.epub`（電子書籍）です。テキストは新しい本のパートになり、すべてあなたが書いたものとして扱われます（インポートは[統計](statistics.md)では執筆として数えられず、パートの履歴には *ドキュメントからインポート* と表示されます）。

- **章。** *見出し* のスタイルの段落（Markdown ファイルでは `#` の見出し）が章を始めます。各章はその見出しで始まります（パートの最初の見出しがその章のタイトルになります。[エクスポート](export.md)と同じです）。**章を始める見出しレベル** で、どの見出しが章の見出しになるかを選びます。選んだレベルとそれより上のレベルが対象です（最初は、文書にあるもっとも浅いレベルが選ばれます）。それより深い見出しは、小さな見出しとして本文に残ります。見出しのない文書は 1 つの章になります。文書の *タイトル* は本文としてはインポートされず、本の名前になります（Markdown ファイルでは先頭のヘッダの `title:`、または `##` の章の前にある 1 つの `#` 見出しです）。プレーンテキストファイルには見出しがないため、`Chapter 12`、`Part IV: The Return`、`Book two`、`Prologue`（ほかに `Epilogue`、`Interlude`、`Preface`、`Foreword`、`Afterword`）のように単独の行に書かれたものが章の始まりになります。この場合、見出しレベルの選択は必要ありません。
- **パートあたりの語数。** テキストは段落の間で、おおよそこの語数（最初は 1000）ごとのパートに分けられます。切れ目は、数に最も近い段落の境目です。パートが 1 つの章の終わりと次の章の始まりを含むことはありません。また、章を無意味に切ることもしません。章の末尾に残る部分が語数の半分未満であれば、その前のパートに含められます。そのため、語数の 1.5 倍までの章は 1 つのパートになります。語数より長い段落は切られません。
- 名前の下の行に、インポートで作られる章、語数、パートの数が表示されます。オプションを変えると、この表示も変わります。
- **テキストファイルの段落。** 空行が段落を区切り、段落の行はつなげられます（ある桁で折り返されたテキストは 1 つの段落になります）。空行のないファイルでは、1 行ごとに段落になります。Markdown ファイルは書かれたとおりに保たれ、空行、見出し、コードブロックで区切られます。UTF-8 ではなく Windows-1252 のテキストも読み込めます。
- **書式。** 斜体と太字は保たれます（Markdown の `*斜体*`、`**太字**` として）。それ以外の書式（フォント、サイズ、配置）、画像、ヘッダとフッタ、脚注、コメント、変更履歴の削除されたテキストはインポートされません。表はセルごとに読み込まれます。

![Word 文書のインポート。約 500 語のパートに分けられる](../../images/document-import.png)

古い `.doc` ファイルは、先に `.docx`、`.odt`、`.rtf` として保存し直す必要があります。

**EPUB** は、読書順にページごとに読み込まれます。ページの見出し（`h1` から `h6`）が章になります。見出しのないページでも、電子書籍の目次にその名前があれば、その名前が見出しになります。表紙、目次、脚注、ルビの読みは除外されます。電子書籍のタイトルが本の名前になります。DRM で保護された本は読み込めません。

<a id="from-an-obsidian-vault-or-a-scrivener-project"></a>

#### Obsidian ボールトまたは Scrivener プロジェクトから

どちらもフォルダなので、先にフォルダを zip で圧縮し（Mac では Finder で **圧縮**。Scrivener の `.scriv` もフォルダです）、`.zip` をアップロードします。オプションはドキュメントの場合と同じです。

- **Obsidian ボールト。** すべてのノート（`.md`）が、ノートの名前（またはヘッダの `title:`）の付いた章になります。順序はパスの順で、番号は数として数えられます（`Chapter 2` は `Chapter 10` の前）。フォルダは、その中のノートより上のパートになり、ノート内の見出しはそのノート自身の見出しより下になります。`[[Note|text]]` のリンクはその文字列になります。埋め込み（前に `!` が付いた `[[file]]`）、コメント `%%...%%`、ブロック ID、コールアウトのマーカーは削除されます。ハイライト `==text==` はプレーンテキストになります。隠しフォルダ（`.obsidian`、`.trash`）、添付ファイル、本文のないノートは飛ばされます。ボールトに物語の一部ではないノートがある場合は、zip にする前に削除してください。
- **Scrivener プロジェクト。** インポートされるのは原稿（バインダーの *Draft* フォルダ。Scrivener 2 と 3 の両方）です。リサーチ、ゴミ箱、*コンパイルに含める* になっていない文書はインポートされません。フォルダ、またはその下に文書を持つ文書は見出しになります（バインダー内の深さがそのレベル、タイトルが本文になります）。フォルダが持つ文書のみで構成されるものはそのシーンになり、シーン区切りを挟んで順に並びます（そのタイトルは使われません）。原稿の直下、またはほかのフォルダだけを含むフォルダにある文書は、そのタイトル付きの章になります。プロジェクトの名前が本の名前になります。

作成元にかかわらず、インポートが終わると新しい本が開きます（中止した場合も同じです）。また、[**インポート完了**](story-editor.md#after-an-import)のウィンドウから、パートの要約の作成や、エージェントによる設定メモの作成を選べます。

<a id="importing-from-sillytavern"></a>

### SillyTavern からインポート

[SillyTavern](https://github.com/SillyTavern/SillyTavern) で始めたロールプレイや物語を続けるには、**インポート → SillyTavern からインポート** を使います。SillyTavern でチャットをエクスポートします（*チャットファイルの管理*、または `data/<user>/chats/<character>/` にある `.jsonl` ファイルを使います）。その後、次の手順を行います。

1. **1 つ以上** の `.jsonl` チャットをアップロードします。SillyTavern のチャットではないファイルは拒否され、ほかのファイルはそのまま残ります。
2. 本の名前を付けます（最初のチャットのキャラクター名から自動入力されます）。
3. ターンごとに 1 パートにしたい場合は、**ユーザーとアシスタントのメッセージを 1 つのパートにまとめる** にチェックを入れます。ユーザーのメッセージ（連続した複数のメッセージは空行でつなげられます）がパートの *指示* になり、その後の回答がパートの本文になります。チェックを入れないと、それぞれのメッセージが独立したパートになり、そのテキストがパートの本文になるため、本はチャットと同じ流れで読めます。
4. **インポート** をクリックします。**停止** のある進行状況ウィンドウに、保存されているパートが表示されます。停止しても、それまでに保存された分は残ります。

![SillyTavern チャットのインポート](../../images/sillytavern-import.png)

SillyTavern は、*ブランチ* や *チェックポイント* を作成するときにチャットをコピーするため、同じ物語のチャットは最初の部分を共有します。まとめてアップロードすると、Marginalia は共通のメッセージを見つけて 1 回だけ保存します。チャットは 1 つのツリーのブランチになり、それを[ツリー表示](story-editor.md)でたどれます。メッセージの *スワイプ*（代替の回答）は兄弟のパートになり、本は最後に書かれたチャットの末尾（最後のメッセージの日付順）で開きます。最初のメッセージが一致しないチャットは、別々の最初のパートになります。非表示（システム）のメッセージは飛ばされ、空のスワイプも飛ばされます。回答の推論とモデル名は、パートとともに保持されます。

<a id="importing-from-lm-studio"></a>

### LM Studio からインポート

[LM Studio](https://lmstudio.ai) で行った会話を続けるには、**インポート → LM Studio からインポート** を使います。LM Studio は各会話を、ホームフォルダの `.lmstudio/conversations` フォルダ内のファイル `<番号>.conversation.json` に保存します（Windows では `%USERPROFILE%\.lmstudio\conversations`）。操作は [SillyTavern からインポート](#importing-from-sillytavern)と同じです。

1. **1 つ以上** の会話をアップロードします。LM Studio の会話ではないファイルは拒否され、ほかのファイルはそのまま残ります。
2. 本の名前を付けます（会話の名前、名前がない場合はファイル名から自動入力されます）。
3. ターンごとに 1 パートにしたい場合は **ユーザーとアシスタントのメッセージを 1 つのパートにまとめる** にチェックを入れます（あなたのメッセージがパートの *指示* になります）。チェックを入れないと、それぞれのメッセージが独立したパートになります。
4. **インポート** をクリックします。

![1 つの会話をアップロードした LM Studio からのインポートウィンドウ](../../images/lmstudio-import.png)

LM Studio が保持するメッセージのバージョン（再生成した回答、編集したテキスト）は兄弟のパートになり、表示されていたバージョンで本が開きます。同じ始まりを持つ会話は、1 つのツリーにまとめられます。推論モデルの思考過程は、モデル名とともにパートの推論として保持されます。会話のシステムプロンプト、ツールの呼び出し、添付ファイルはインポートされません。

バックアップファイルから本を始めるには、*設定* タブの **バックアップを新しい本としてインポート** を使います。[本のバックアップ](backups.md#importing-a-backup-as-a-new-book)を参照してください。

| **読者に画像を表示** | 初期値はチェックありです。公開された本の読者には、各パートの画像が表示されます。チェックを外すと、読者には本文のみが表示されます。ご自身の画像は常に表示されます。 |

変更は入力と同時に保存されます。

以下は読み取り専用の集計です。

| | |
|---|---|
| **総単語数**、**総トークン数** | すべてのブランチを含む、本の全パートの数です。 |
| **現在のブランチの単語数**、**現在のブランチのトークン数** | [現在のブランチ](branches-and-story-tree.md)のパートのみの数です。 |

<a id="deleting-a-book"></a>

## 本の削除

本の一覧にあるゴミ箱ボタンをクリックし、確認してください。本は一覧から消えます。

本に対して何かが処理中の場合、本は削除されません。たとえば、パートの生成中、要約の一括処理中、翻訳中、書き直しや注釈のウィンドウが開いている場合、または本が別のウィンドウで開かれている場合です。その際Marginaliaは、何が妨げになっているかを表示します(*This is in use: ...*)。処理が終わるまで待つか、停止してから、もう一度削除してください。別のウィンドウや実行処理が本に対して作業中に、本へ[バックアップ](backups.md)を復元する場合も同様です。

削除された本は、データベースからすぐには消去されません。管理者が[クリーンアップ](../administration/cleanup.md)を使ってパートを含めて完全に消去するまでは、[ゴミ箱](../trash.md)タブから本を復元できます。それまでは、データは[データベースのバックアップ](../administration/database-backups.md)に残っています。本自身の[バックアップ](backups.md)はファイルであるため、そのままの場所に残ります。
