# 书籍简介生成器

让模型根据故事写出书的**名称**和**简介**。你可以选择它读取故事的哪一部分，并把它写好的内容复制到书中。

<a id="opening-it"></a>

## 打开

安装扩展后，书籍窗口的**关于**标签页末尾有一个**生成名称和简介**按钮。它在[手机布局](../phone.md#extensions)中同样可用。对话框左侧是选项，右侧是结果。

![生成名称和简介的窗口](../../images/plugin-book-description.png)

| 选项 | |
|---|---|
| **模型**、**协议** | 生成所使用的模型和协议。默认与书籍的模型和协议相同，否则使用*设置*中的默认值（见[账户与设置](../account.md)）；此选择仅对本次生成有效。若没有模型，只会显示一条警告。 |
| **从消息**、**到消息** | 故事的范围，以当前分支中带有文本的消息编号表示。消息开头的内容显示在输入框下方，便于你确认对应的是哪一条。默认为整个故事。 |
| **使用摘要** | 当范围内包含[摘要](../books/summaries.md)所覆盖的全部消息时，摘要将代替这些消息使用；这能大幅降低长篇范围的成本。超出范围的摘要不会被使用，与故事内容已不相符的摘要也不会被使用（改用消息）。该设置会被记住，供下次使用。 |
| **回答格式** | *自动*：当模型的服务支持结构化模式时要求 JSON 格式（附带模式），否则要求 Markdown。*JSON*：强制要求带模式的 JSON。*无模式的 JSON*：在提示词中描述 JSON 格式，适用于无法同时接受模式和模型思考过程的服务器。*Markdown*：要求以一级标题给出名称，简介写在标题之下。无论模型写的是 JSON 还是 Markdown，都会被正确读取，因此即使模型没有遵守指令，结果依然能被理解。该设置会被记住，供下次使用。 |

选项下方的计数器会显示该范围连同提示词一共有多少个词元、模型会接收多少，以及故事是按原样发送，还是需要先整理成笔记。

点击**生成**启动模型，同一按钮也可用于停止。名称和简介会显示在右侧，各自带有一个**复制到书籍**按钮：点击后会把文本填入关于标签页的对应字段，并立即保存书籍（书籍窗口的标题也会随之更新）。如果回答无法被解析为名称和简介，对话框会显示模型写出的原始文本。

<a id="a-story-that-is-too-long"></a>

## 故事过长的情况

当范围超出模型所能接受的长度时，故事会按顺序被分成若干能容纳的部分，模型会为每一部分写出**笔记**（笔记会随生成陆续显示在*笔记*下方）。之后简介将基于笔记而非原始故事来撰写。仍然过长的笔记会被再次分割并整理成笔记，最多进行四轮。单条超过分段长度的消息会在段落、换行或句子处被切开。

!!!
如果模型和协议都没有设置上下文大小，插件无法判断内容是否过长，将始终按原样发送故事。
!!!

<a id="prompts"></a>

## 提示词

共有两个提示词：一个用于撰写名称和简介，另一个用于为长篇故事的某一部分撰写笔记。它们都是[继承的设置](../books/prompts.md#inherited-settings)：书籍使用自己的提示词；若没有，则使用上方最近的、设置了该提示词的文件夹中的提示词；再没有，则使用你的全局设置；最后才使用内置文本。

| 提示词 | 变量 |
|---|---|
| **简介提示词** | `{{story}}`（故事，或由其整理出的笔记）、`{{fromNotes}}`、`{{bookName}}`、`{{bookDescription}}` |
| **笔记提示词** | `{{story}}`（该部分内容）、`{{part}}`、`{{parts}}`、`{{bookName}}`、`{{bookDescription}}` |

你可以在书籍的*提示词*标签页中、在*扩展设置*下设置它们，也可以在文件夹的对话框中设置，或在*设置 → 扩展设置 → 书籍简介生成器*中为所有书籍统一设置。告诉模型如何组织回答（JSON 或 Markdown）的说明，会由扩展添加在简介提示词之后，因此你的提示词只需说明要写什么。
