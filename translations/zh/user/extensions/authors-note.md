# 作者注释

随书稿每次生成一同发送给模型的注释：你此刻希望的语气、当前章节的内容，或是模型总会忘记的提醒。与某一轮的指令不同，注释会一直保留，直到你改动它。

<a id="the-authors-note-tab"></a>

## “作者注释”标签页

[故事编辑器](../books/story-editor.md)左侧边栏在 *Outline* 旁边多了一个 **Author's Note** 标签页。修改会在你输入时自动保存到书稿中，并用于下一次生成。

![“作者注释”标签页](../../images/plugin-authorsnote.png)

| 字段 | |
|---|---|
| **Insert into prompt** | 开启或关闭注释，但不删除它。 |
| **Insertion depth** | 注释插入的位置，从提示词末尾开始按消息数计算：`0` - 放在本轮指令之后（即最后一条消息），`1` - 放在指令之前，`2` - 放在最后一段故事之前，依此类推。深度较大时，注释会紧跟在系统提示词之后。 |
| **Role** | 注释以 *System*、*User* 还是 *Assistant* 消息的形式发送。 |
| **Author's Note** | 发送给模型的文本。空注释不会被发送。其下方显示其大小的估算词元数。 |
| **Author's Note (private)** | 留给自己看的笔记，例如计划、提醒。从不发送给模型。 |

!!!
注释离提示词末尾越近，效果越强。角色设为 *System*、深度设为 `1` 是一个很好的起点。
注释不会被当作[模板](../templates/macros.md)处理：宏会按原样发送。
!!!

<a id="how-the-prompt-looks"></a>

## 提示词的结构

一次生成会先发送系统提示词，然后把故事作为对话依次发送（每一段故事都是模型对 *Generate story* 的一次回答），最后是本轮指令。深度为 `1` 时，注释会插入到指令之前：

1. 系统提示词（模板、设定、摘要）
2. 故事片段……
3. **作者注释**
4. 本轮指令

注释的词元会占用故事可用的空间：注释越长，提示词中能放入的故事片段就越少。如果注释连提示词的其余部分都放不下，生成会被中止，并显示 *Contextual limit not sufficient*。

<a id="the-note-as-a-macro"></a>

## 将注释作为宏使用

除了（或代替）自动插入，你还可以用 [{%{`{{command::authors-note}}`}%} 宏](../templates/macros.md#commands)自行放置注释：把它写进主模板、用户提示词或某个设定条目中，它就会在你希望的位置输出注释文本。无论 **Insert into prompt** 是否开启，宏都会输出注释的当前内容，因此用宏放置注释时请关闭该选项，否则模型会收到两次。深度和角色对宏不起作用（注释成为包含该宏的那条消息的一部分），空注释则不输出任何内容。

<a id="storage"></a>

## 存储

注释随书稿一起保存，因此它也包含在[书稿备份](../books/backups.md)和副本之中。
