# クリーンアップ

Marginalia で本、ストーリーパート、ロアブック、推論プロバイダーなどを削除すると、それらは一覧から消えますが、データベースには残ります。そのため削除は安全に行え, 参照も壊れません（本は、そのパートを書いたプロバイダーをまだ把握しています）。削除したオブジェクトは、それまで[ゴミ箱](../trash.md)タブから復元できます。**Cleanup** は、そのように削除されたデータを完全に取り除き、データベースを小さく保ちます。

![Cleanup タブ](../../images/admin-cleanup.png)

<a id="running-a-cleanup"></a>

## クリーンアップの実行

!!!warning
クリーンアップは元に戻せません。削除されたデータは[ゴミ箱](../trash.md)からも消えます。先に[データベースのバックアップを作成](database-backups.md)してください。
!!!

1. 管理ページの **Cleanup** タブを開き、**Analyze** をクリックします。この時点ではまだ何も変更されません。
2. 結果を確認します（下記参照）。
3. **Run Cleanup** をクリックし、*n objects will be permanently removed* の確認に応じます。

クリーンアップは全ユーザーのデータを対象とします。

クリーンアップはデータベースのエントリーを削除しますが、ファイルは[エージェント](../agents.md)のものだけを削除します。具体的には、削除されたエージェントのワークスペースと、削除された実行のフォルダーです。削除済みで未使用の[リソース](../resources.md)（パーツの画像、音声）のファイルは、[リソースファイル](resource-files.md)タブで削除するまで、所有者のデータフォルダーに残ります。

<a id="seeing-what-is-deleted"></a>

## 削除されたものの確認

テーブルの下にある **Trash** には、全ユーザーの削除済みオブジェクトが1オブジェクトにつき1行で一覧表示されます（テーブルを読み込むには開いてください）。これにより、クリーンアップで何が消えるかを確認でき、誰かが復元を求めたものを戻すこともできます。[ゴミ箱](../trash.md)タブと同じテーブルで、ユーザーと種類によるフィルターや *Extended Content* リンクも同じです。

![クリーンアップタブのゴミ箱セクション](../../images/admin-trash.png)

<a id="reading-the-analysis"></a>

## 分析結果の読み方

最初の表には、データの種類ごとに1行あります。

| 列 | |
|---|---|
| **Entity** | データの種類: `Manuscript`（本）、`ChatMessage`（ストーリーパート）、`Lorebook`、`LorebookEntry`、`AI`（推論プロバイダー）、`Protocol`、`Summary`、`Tag`、`TagRelation`、`User`... |
| **Deleted** | 削除されている数です。 |
| **To purge** | *Run Cleanup* によって削除される数です。削除済みオブジェクトに属するデータも含みます。 |
| **Blocked** | 削除済みですが、まだ使用中のため保持されます。 |

**Deleted objects still in use** には、ブロックされたオブジェクトが名前と **Referenced by**（それを何がまだ使っているか）とともに一覧表示されます。

<a id="what-is-removed"></a>

## 削除される内容

クリーンアップは、もう生きているものが使用していない削除済みオブジェクトを、それだけに属するデータとともに削除します。

| 削除済み | 一緒に削除されるもの |
|---|---|
| 本 | そのすべてのストーリーパート、要約、タグのリンク |
| ロアブック | そのエントリーとタグのリンク。他のロアブックは、それをサブロアブックとして含まなくなります |
| ストーリーパート | そのパート（子パートは既に親に移動されています）と、その要約 |
| 推論プロバイダーまたはプロトコル | *Settings* にあるユーザーのデフォルトから消去されます |
| タグ | 本とエントリーへのリンク |
| ユーザー | 所有していたすべてのもの: 本（そのストーリーパートと要約を含む）、ロアブック、推論プロバイダー、プロトコル、タグ、設定 |

クリーンアップは、誰も削除していなくても、もう使われていない[リソース](../resources.md)も削除します。対象は、オブジェクトに追加されたファイル（[オーディオブック](../extensions/audiobook.md)の音声、パートの画像）で、そのオブジェクトがデータベースから消えている場合、またはこのクリーンアップで削除される場合であり、かつ他のどのオブジェクトもそのファイルを指定していない場合です。パートから作られた分岐は同じ画像やクリップを持つので、分岐が存在する間は残ります。ゴミ箱にある削除済みオブジェクトが指定しているファイルも残ります。これらは `Resource` の **To purge** に数えられ、*Deleted* には数えられません。どのオブジェクトにも使われていないファイル（リソースタブで *nothing*）は残ります。

<a id="what-is-kept"></a>

## 保持される内容

削除済みのオブジェクトは、生きているものがまだ使用している間は **blocked**（保持）されます。

| ブロック | 理由 | ブロックを解除するには |
|---|---|---|
| 削除された推論プロバイダーまたはプロトコル | 本がまだそれをモデルまたはプロトコルとして使用している | 本の *About* タブで別のものを選ぶか、本を削除する |
| 削除されたロアブック（エントリーを含む） | 本がまだ使用している | 本で別のロアブックを選ぶか、それをクリアする |
| 削除されたストーリーパート | 本のアクティブな分岐の最後のパートである | 本を別の分岐に切り替えるか、本を削除する |
| 削除されたユーザー | 別のユーザーのものが、そのユーザーのデータをまだ使用している（その推論プロバイダーやロアブックを使う本） | 別のユーザーの本を変更するか削除する |

ブロックを解除したら、*Analyze* をもう一度実行してください。

<a id="reference-model"></a>

## 参照モデル

下部にある **Reference Model** は、データの種類同士のすべての参照と、そのポリシーを一覧にします。なぜ何かがブロックされているのかを理解したいときに役立ちます。

| ポリシー | 意味 |
|---|---|
| **Blocks purge** | 削除されたターゲットは、生きているオブジェクトがそれを参照している間は保持されます。 |
| **Purged with target** | 参照しているオブジェクトはターゲットに属しており、ターゲットとともに削除されます（エントリーはそれらのロアブックとともに）。 |
| **Owns target** | ターゲットは参照しているオブジェクトに属します（要約はそのパートに）。 |
| **Cleared on purge** | ターゲットが削除されるときに参照は消去されます（サブロアブック、デフォルトモデル）。 |

拡張機能は、独自のルールでクリーンアップに参加できます。
