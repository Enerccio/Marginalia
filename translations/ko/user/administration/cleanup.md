# 정리

Marginalia에서 사용자가 책, 스토리 파트, 로어북, 추론 제공자 같은 항목을 삭제하면 그 항목은 목록에서 사라지지만 데이터베이스에는 그대로 남습니다. 그래서 삭제는 안전하고 참조도 계속 작동합니다(책은 자신의 파트를 쓴 제공자를 여전히 알고 있습니다). 그전까지 사용자는 [Trash](../trash.md) 탭에서 삭제한 객체를 복원할 수 있습니다. **Cleanup**은 이렇게 삭제된 데이터를 영구히 제거해 데이터베이스를 작게 유지합니다.

![The Cleanup tab](../../images/admin-cleanup.png)

<a id="running-a-cleanup"></a>

## 정리 실행하기

!!!warning
정리는 되돌릴 수 없으며, 정리로 제거된 항목은 [Trash](../trash.md)에서도 사라집니다. 먼저 [데이터베이스 백업 만들기](database-backups.md).
!!!

1. 관리자 페이지의 **Cleanup** 탭을 열고 **Analyze**를 클릭합니다. 아직 아무것도 변경되지 않습니다.
2. 결과를 확인합니다(아래 설명 참고).
3. **Run Cleanup**을 클릭하고 *n objects will be permanently removed*라는 메시지를 확인합니다.

정리는 모든 사용자의 데이터를 대상으로 합니다.

정리는 데이터베이스의 항목을 삭제하고, [에이전트](../agents.md)의 파일만 삭제합니다. 즉 제거된 에이전트의 작업 공간과 제거된 실행의 폴더를 지웁니다. 삭제되었거나 사용되지 않는 [리소스](../resources.md)(파트의 그림, 오디오 등)의 파일은 소유자의 데이터 폴더에 남아 있으며, [Resource Files](resource-files.md) 탭에서 직접 제거해야 합니다.

<a id="seeing-what-is-deleted"></a>

## 삭제된 항목 살펴보기

탭 아래쪽의 **Trash** 섹션에는 모든 사용자의 삭제된 객체가 한 행에 하나씩 나열됩니다(표를 불러오려면 펼치세요). 정리로 무엇이 제거될지 확인하고, 누군가 복원을 요청한 항목을 되돌릴 수도 있습니다. 이 표는 [Trash](../trash.md) 탭과 같으며, 사용자 및 유형별 필터와 *Extended Content* 링크도 동일하게 제공합니다.

![The Trash section of the Cleanup tab](../../images/admin-trash.png)

<a id="reading-the-analysis"></a>

## 분석 결과 읽기

첫 번째 표에는 데이터 종류마다 한 행씩 있습니다:

| 열 | |
|---|---|
| **Entity** | 데이터 종류: `Manuscript`(책), `ChatMessage`(스토리 파트), `Lorebook`, `LorebookEntry`, `AI`(추론 제공자), `Protocol`, `Summary`, `Tag`, `TagRelation`, `User`... |
| **Deleted** | 삭제된 개수입니다. |
| **To purge** | *Run Cleanup*으로 제거될 개수이며, 삭제된 객체에 속한 데이터도 포함합니다. |
| **Blocked** | 삭제되었지만 아직 사용 중이어서 남겨 두는 개수입니다. |

**Deleted objects still in use**에는 차단된 객체가 이름과 **Referenced by**(아직 이 객체를 사용하는 대상)와 함께 나열됩니다.

<a id="what-is-removed"></a>

## 제거되는 항목

정리는 삭제되었고 살아 있는 어떤 것도 더 이상 사용하지 않는 객체를, 그 객체에만 속한 데이터와 함께 제거합니다:

| 삭제된 항목 | 함께 제거되는 데이터 |
|---|---|
| 책 | 모든 스토리 파트, 요약, 태그 연결 |
| 로어북 | 항목과 태그 연결. 다른 로어북은 이 로어북을 하위 로어북으로 더 이상 포함하지 않습니다 |
| 스토리 파트 | 파트 자체(자식 파트는 이미 부모로 옮겨졌습니다)와 요약 |
| 추론 제공자 또는 프로토콜 | 사용자 기본값(*Settings*)에서 지워집니다 |
| 태그 | 책과 항목에 대한 연결 |
| 사용자 | 소유한 모든 것: 책(스토리 파트와 요약 포함), 로어북, 추론 제공자, 프로토콜, 태그, 설정 |

정리는 또한, 아무도 삭제하지 않았더라도 더 이상 쓰이지 않는 [리소스](../resources.md)를 제거합니다. 예를 들어 [오디오북](../extensions/audiobook.md)의 오디오나 파트의 그림처럼 항목에 추가된 파일은, 그 항목이 데이터베이스에서 사라졌거나 이번 정리로 제거되고, 다른 어떤 객체도 그 파일을 참조하지 않으면 함께 제거됩니다. 파트에서 만든 분기는 같은 그림과 클립을 가지므로, 분기가 존재하는 동안에는 파일이 남습니다. 휴지통에 있는 삭제된 객체가 참조하는 파일도 마찬가지로 남습니다. 이런 파일은 `Resource`의 **To purge**에 포함되며 *Deleted*에는 포함되지 않습니다. 어떤 객체도 사용하지 않는 파일(Resources 탭에서 *nothing*으로 표시되는 파일)은 남겨 둡니다.

<a id="what-is-kept"></a>

## 남겨지는 항목

삭제된 객체는 살아 있는 무언가가 여전히 사용하는 동안 **blocked**(차단됨) 상태가 되어 남겨집니다:

| 차단됨 | 이유 | 차단 해제 방법 |
|---|---|---|
| 삭제된 추론 제공자 또는 프로토콜 | 책이 모델이나 프로토콜로 여전히 사용합니다 | 책의 *About* 탭에서 다른 것을 선택하거나 책을 삭제합니다 |
| 삭제된 로어북(항목 포함) | 책이 여전히 사용합니다 | 책에서 다른 로어북을 선택하거나 비웁니다 |
| 삭제된 스토리 파트 | 책 활성 분기의 마지막 파트입니다 | 책을 다른 분기로 전환하거나 책을 삭제합니다 |
| 삭제된 사용자 | 다른 사용자의 무언가가 이 사용자의 데이터를 사용합니다(그 사용자의 추론 제공자나 로어북을 쓰는 책) | 다른 사용자의 책을 변경하거나 삭제합니다 |

차단을 해제한 뒤에는 *Analyze*를 다시 실행하세요.

<a id="reference-model"></a>

## 참조 모델

화면 아래쪽의 **Reference Model**에는 데이터 종류 사이의 모든 참조와 그 정책이 나열됩니다. 어떤 항목이 왜 차단되었는지 이해하고 싶을 때 유용합니다:

| 정책 | 의미 |
|---|---|
| **Blocks purge** | 살아 있는 객체가 참조하는 동안 삭제된 대상은 남겨집니다. |
| **Purged with target** | 참조하는 객체는 대상에 속하며 대상과 함께 제거됩니다(항목은 로어북과 함께 제거됩니다). |
| **Owns target** | 대상은 참조하는 객체에 속합니다(요약은 파트에 속합니다). |
| **Cleared on purge** | 대상이 제거될 때 참조가 지워집니다(하위 로어북, 기본 모델). |

확장 기능도 자체 규칙으로 정리에 참여할 수 있습니다.
