# 확장 기능 관리

관리자 페이지의 **확장 기능** 탭에서는 설치 전체에 적용되는 [확장 기능](../extensions/index.md)을 설치하고 제거합니다.

![확장 기능 탭](../../images/admin-extensions.png)

<a id="installing"></a>

## 설치

**확장 기능 불러오기 (.jar)**를 클릭하거나(파일을 이 버튼 위에 끌어다 놓아도 됩니다) 확장 기능의 JAR 파일을 선택합니다. 파일은 [데이터 폴더](index.md#the-data-folder)의 `extensions` 폴더로 복사되고 바로 시작됩니다. *Extension loaded successfully.* 메시지가 나타나면 설치가 완료된 것입니다. 확장 기능은 목록에 나타납니다:

| 열 | |
|---|---|
| **ID** | 이번 실행에서 부여된 확장 기능의 내부 번호입니다. |
| **확장 기능 이름** | 확장 기능의 이름입니다. |
| **버전** | 확장 기능의 버전입니다. 옆의 **#** 버튼에 마우스를 올리면 확장 기능 JAR의 SHA-256 해시가 표시되며, 클릭하면 해시가 복사됩니다. 예를 들어 작성자가 공개한 해시와 비교할 때 사용할 수 있습니다. |
| **상태** | 실행 중이면 *활성*, 직접 중지했다면 *중지됨*(see [Stopping and starting](#stopping-and-starting)), 시작에 실패했다면 *설치됨* 또는 *해결됨*(see [When an extension fails](#when-an-extension-fails))으로 표시됩니다. |
| **검증** | *유효* 또는 *유효하지 않음*으로 표시됩니다. 클릭하면 Marginalia가 확장 기능을 시작하기 전에 수행한 검사의 보고서를 읽을 수 있습니다. |
| **작업** | **중지** / **시작**, **로그**, **언로드** 버튼이 있습니다. |

이후에 여는 창에서부터 사용자에게 확장 기능이 보입니다. 이미 열려 있던 책은 닫았다가 다시 열거나 페이지를 새로 고쳐야 합니다.

JAR 파일을 `extensions` 폴더에 직접 복사할 수도 있습니다. 예를 들어 UI에 접근할 수 없는 서버에서 이 방법을 쓸 수 있으며, 이 경우 다음 시작 때 불러옵니다. Docker 설정도 이 방식으로 준비할 수 있습니다. JAR 파일을 `./data/extensions`에 넣으면 됩니다. JAR 파일은 Docker 안에서 빌드할 수도 있습니다. 자세한 내용은 서버 가이드의 [플러그인](../getting-started/docker-server.md#plugins)을 참고하세요.

!!!warning 이 버전용으로 빌드된 확장 기능을 사용하세요
확장 기능은 특정 Marginalia 버전의 사용자 인터페이스 일부를 바꿉니다. Marginalia 애플리케이션과 같은 소스에서 빌드된 확장 기능을 사용하세요([플러그인 README](https://github.com/Enerccio/Marginalia/blob/master/marginalia/plugins/README.md) 참고). 호환되지 않는 확장 기능은 불러오지 못하거나 애플리케이션의 일부를 망가뜨릴 수 있습니다. 1.0에서 확장 기능 API는 아직 고정되지 않았으므로, 확장 기능도 Marginalia와 함께 업데이트할 준비를 해 두세요.
!!!

<a id="stopping-and-starting"></a>

## 중지와 시작

**중지**를 누르면 확장 기능이 즉시 언로드되지만 목록에서 제거되지는 않습니다. 확장 기능이 추가했던 화면에서는 사라지지만 JAR 파일과 데이터는 그대로 남으며, 목록에는 *중지됨* 상태로 표시됩니다. 그러면 버튼이 **시작**으로 바뀌고, 이를 누르면 다시 불러옵니다(애플리케이션을 시작할 때와 같이 먼저 검사합니다. 검사에 실패하면 중지된 상태로 남고 보고서가 표시됩니다). 중지된 확장 기능은 Marginalia를 다시 시작해도 계속 중지된 상태로 남습니다. 중지된 확장 기능의 새 버전을 업로드하면 그 확장 기능이 시작됩니다.

중지 상태는 `extensions` 폴더에 JAR과 같은 이름에 `.STOPPED`를 덧붙인 빈 파일(예: `sidequery.jar.STOPPED`)로 기억됩니다. UI에 접근할 수 없는 서버에서는 이 파일을 만들면 확장 기능이 시작되지 않고, 파일을 삭제하면 다음 시작 때 확장 기능이 시작됩니다.

<a id="the-extension-log"></a>

## 확장 기능 로그

**로그**를 열면 확장 기능의 로그가 표시됩니다. 여기에는 Marginalia가 확장 기능에 제공하는 로거([로깅](../../developer/plugins/overview.md#logging))로 확장 기능 자체가 기록한 내용이 나옵니다. 파일의 마지막 부분이 보이며, **새로 고침**을 누르면 파일을 다시 읽고, **지우기**를 누르면 파일을 삭제합니다. 파일은 `extensions/<name>.jar.log`(예: `sidequery.jar.log`)이며, 2MB를 넘으면 `.log.old`로 옮겨지고 새 파일이 시작됩니다. 확장 기능을 언로드하면 파일도 삭제됩니다. 아무것도 기록하지 않는 확장 기능의 로그는 비어 있습니다. 확장 기능이 기록한 내용은 애플리케이션 로그(이름은 `extension.<name>`이며, 각 줄의 수준으로 기록됨)에도 전달되므로 서버 로그에서도 볼 수 있습니다. Marginalia 자체의 문제는 애플리케이션 로그에만 나타납니다.

![확장 기능의 로그](../../images/extension-log.png)

<a id="removing"></a>

## 제거

**언로드**를 누르면 확인을 요청한 뒤, 확장 기능을 즉시 중지하고 `extensions` 폴더에서 JAR 파일(및 로그)을 삭제합니다. 데이터는 남으며([확장 기능 데이터가 보관되는 위치](../extensions/index.md#where-extension-data-is-kept) 참고), 다시 불러오면 데이터도 돌아옵니다.

<a id="updating"></a>

## 업데이트

확장 기능의 새 버전을 설치하려면 새 파일로 **확장 기능 불러오기 (.jar)**를 사용하세요. 파일 이름은 상관없습니다. 설치되어 있던 버전은 언로드되고 JAR 파일이 삭제되며, 새 버전이 그 자리에서 시작됩니다. 새 버전을 불러오지 못하면 업로드 화면에 오류가 표시되고, 기존 버전은 계속 실행됩니다.

<a id="when-an-extension-fails"></a>

## 확장 기능이 실패할 때

업로드한 확장 기능을 불러올 수 없으면 *Failed to load extension: ...* 메시지가 표시되며, 해당 JAR 파일은 보관되지 않습니다.

Marginalia는 확장 기능을 시작하기 전에 실행 중인 버전과 맞는지 검사합니다. 맞지 않는 확장 기능(대개 다른 버전의 Marginalia용으로 빌드된 것)은 불러오지 않습니다. 업로드했을 때는 검사 보고서가 표시되고 파일은 보관되지 않습니다. `extensions` 폴더에 있는 확장 기능은 목록에 남지만 시작되지 않으며, *검증* 열에 **유효하지 않음**이 표시되고 보고서는 로그에 남습니다. Marginalia를 업데이트한 뒤에도 검사가 다시 수행되므로, 전에는 작동하던 확장 기능이 이후 거부될 수 있습니다. 이 경우 새 버전의 Marginalia용으로 빌드된 확장 기능 버전을 받아 불러오세요. 유효하지 않은 확장 기능이 있으면 작업 공간 위쪽에 **빨간 막대**가 표시되어 모든 사용자에게 알립니다. 관리자는 마우스를 올려 어떤 확장 기능인지 확인하고, 막대를 클릭하면 이 페이지가 열립니다. 다른 사용자에게는 관리자에게 알리라는 안내가 나타납니다(직접 중지한 확장 기능은 집계에 포함되지 않습니다). 각 확장 기능의 JAR 옆에는 보고서가 담긴 작은 `.valid` 또는 `.invalid` 파일이 있습니다. 이 파일은 확장 기능과 함께 제거되며, 그대로 두어도 됩니다.

![유효하지 않은 확장 기능이 있을 때 작업 공간 위에 표시되는 빨간 막대](../../images/invalid-extensions-warning.png)

![맞지 않는 확장 기능의 검증 보고서와 중지된 확장 기능(시작 버튼)](../../images/extension-verification.png)

`extensions` 폴더에 있는 확장 기능 중 시작에 실패한 것(예: 다른 버전용으로 빌드된 것)이 있어도 다른 확장 기능의 불러오기를 막지는 않습니다. 이런 확장 기능은 *활성* 대신 *설치됨* 또는 *해결됨* 상태로 목록에 표시되며, **언로드**로 제거할 수 있습니다. 확장 기능이 아닌 파일은 건너뛰고 목록에 표시하지 않습니다. 이런 파일은 `extensions` 폴더에서 직접 삭제하세요. 오류의 자세한 내용은 로그(`docker compose logs`, 또는 데스크톱 앱의 경우 `desktop/logs/marginalia.log`)에 있습니다.
