# エントリと有効化

<a id="the-entry-list"></a>

## エントリ一覧

ロアブックエディターの各行が1つのエントリです。

| 列 | |
|---|---|
| チェックボックス | **有効**。無効のエントリは決して使われません。 |
| **エントリ名** | エントリにつける名前です。モデルには送られません。 |
| **順序** | プロンプト内でのエントリの位置です。[順序と挿入](#order-and-insertion)を参照してください。新しいエントリには `100` が設定されます。 |
| **タグ** | エントリを有効化するタグです。[タグ](#tags)を参照してください。 |
| ⌄ | エントリの詳細を表示します。 |
| 展開 | エントリを[全画面エディター](lorebooks.md#editing-in-full-screen)で開きます（デスクトップのみ）。 |
| ゴミ箱 | エントリを削除します（確認後）。 |

ツールバーの**エントリを追加**で、順序 `100` のエントリが追加されます。変更は入力と同時に保存されます。

<a id="searching-and-deleting-many-entries"></a>

### 多数のエントリの検索と削除

ボタンの横にある虫眼鏡付きの入力欄では、名前、内容、メモ、フィルターに入力したテキストを含むエントリだけが表示されます（大文字と小文字は区別しません）。入力欄を空にすると、すべてのエントリが再び表示されます。検索対象は選択中のロアブックのエントリだけで、サブロアブックは含みません。スマートフォンのレイアウトでは、入力欄が一覧の上にあります。

入力欄の隣には、一覧を絞り込むための入力欄がさらに2つあります。**タグ**では、そのタグを持つエントリを表示します（ロアブック内のいずれかのエントリが持つタグが一覧に出ます。*除外タグ*は対象外です）。**ステータス**では、**すべて**、**有効**、**無効**、**常時（キーなし）**から選べます。最後のものは、有効でフィルターを持たないエントリ、つまりすべてのパートで使われるエントリを表示します。検索、タグ、ステータスは組み合わされ、エントリはそのすべてに合う必要があります。スマートフォンのレイアウトでは、この2つの入力欄が検索欄の下にあります。

左端のチェックボックスの列でエントリを選択します（ヘッダーのチェックボックスは表示中のすべてを選択するので、検索してからヘッダーのチェックボックスを使うと、一致したものだけを選択できます）。何かを選択すると、ツールバーに**選択したものを削除**がエントリ数とともに表示されます。確認は一度だけ行われ、その後エントリは[ゴミ箱](../trash.md)に移動します。[一括編集](lorebooks.md#mass-edit)にも**チェックしたものを削除**ボタンがあります。スマートフォンでは、エントリの**⋮**メニューに**Select entries**があります。これを選ぶとエントリの前にチェックボックスが表示され、チェックしたエントリの数とともに**選択したものを削除**が現れます（そこには各エントリ用の**Delete entry**ボタンもあります）。


<a id="search-and-replace"></a>

## 検索と置換

**検索と置換**（**エントリを追加**の右側）は、ロアブックのすべてのエントリの名前、テキスト、メモにある単語、名前、語句を一度に置き換えます。[ストーリーの検索と置換](../books/story-editor.md#search-and-replace)と同様に動作しますが、要約と分岐に関するオプションはありません。**検索**では、一致するエントリを一覧表示します（表にはエントリ名が出ます）。また、その中の一致箇所を、現状と置換後の両方の形で表示します。**置換**はエントリを変更します。オプションとして**正規表現で検索**（[正規表現](../regular-expressions.md)を参照）と**大文字と小文字を区別**があります。後者は初期設定でオンです。正規表現が有効な間はロックされ、代わりに `(?i)` を使うと大文字と小文字を無視できます。無効のエントリも検索対象になります。スマートフォンでは、*有効*のチェックボックスの横にあるアイコンのボタンから、同じウィンドウをスマートフォン用のレイアウトで開けます。

![ロアブックの検索と置換ウィンドウ。1つのエントリの一致箇所を開いた状態](../../images/lorebook-search-replace.png)

ストーリーエディターのコマンドラインには、開いている本のロアブック用の `/search-replace-lore-entries` があります。[コマンド](../commands/index.md#commands-that-come-with-marginalia)を参照してください。

<a id="entry-details"></a>

## エントリの詳細

⌄ ボタンで詳細を開きます。

![詳細を表示したエントリ](../../images/lorebook-entry.png)

| 項目 | |
|---|---|
| **内容** | プロンプトに入るテキストです。[テンプレート](#templates-in-entries)で、変数やマクロを使えます。 |
| **フィルターモード** | **キーワード（いずれか）**、**キーワード（すべて）**、**テキスト**、**正規表現**のいずれかで、*フィルターテキスト／パターン*の照合方法を決めます。 |
| **フィルターテキスト／パターン** | フィルターです。[フィルター](#filters)を参照してください。空の場合はフィルターなしです。 |
| **挿入モード** | **ロアブック内**または**ユーザープロンプトの前**。[順序と挿入](#order-and-insertion)を参照してください。 |
| **Activation Context** | フィルターを探す場所です。**指示**（パートへのリクエスト、初期設定）または**指示とストーリーのパート**のどちらかです。[ストーリーの中を探す](#looking-into-the-story)を参照してください。 |
| **パート** | *指示とストーリーのパート*を選んだ場合に、リクエストと一緒に検索する、ストーリーの最新のパートの数です（1以上）。 |
| **開始メッセージ** | このパート番号以降でのみエントリを使います。[エントリを一部のパートに限定する](#limiting-an-entry-to-some-parts)を参照してください。空欄の場合は最初から使います。 |
| **To message** | このパート番号までのみエントリを使います。空欄の場合は最後まで使います。 |
| **条件** | エントリを使うために真の値を返す必要があるテンプレートです。[エントリの条件](#a-condition-for-an-entry)を参照してください。空欄の場合は条件なしです。 |
| **除外タグ（除外条件）** | エントリを無効にするタグです。[タグ](#tags)を参照してください。 |
| **要約も検索する** | チェックすると、フィルターは、次のリクエストで送られる、これまでのストーリーの[要約](../books/summaries.md)からも探されます（ストーリーと合わなくなった要約は除外されます）。フィルターが必要です。 |
| **内容を他のエントリーのフィルターの検索対象にしない** | チェックすると、このエントリの内容の語によって他のエントリが呼び出されることはありません。[他のエントリによって呼び出されるエントリ](#entries-brought-in-by-other-entries)を参照してください。 |
| **他のエントリ経由のみ** | チェックすると、このエントリはリクエストやストーリー自体によっては決して使われず、使われた別のエントリの内容の中で、このエントリのフィルターが見つかった場合にだけ使われます。[他のエントリによって呼び出されるエントリ](#entries-brought-in-by-other-entries)を参照してください。 |
| **メモ** | 自由なメモです。モデルには送られません。SillyTavernからインポートしたエントリでは、ここにインポートできなかった設定が一覧されます。 |

内容は、モデルに読んでほしいとおりに書いてください。短く事実を述べた説明が最も効果的です。

> **キャプテン・ヴァロ** - オストラ港の見張り隊の指揮官。五十代、左手に傷がある。
> 公爵に忠実で、魔術師ギルドを信用していない。短く切れのよい文で話す。
<a id="activation"></a>

## アクティベーション

生成される各パートの前に、Marginaliaはその本のロアブックおよび[サブロアブック](lorebooks.md#sub-lorebooks)のエントリーを順に確認します。エントリーが**アクティブ化**されるのは、次のすべてを満たすときです。

1. エントリーが有効で、そのロアブックも有効である。
2. 書いているパートが、エントリーにパートの範囲（**開始メッセージ**、**終了メッセージ**）が設定されている場合にその範囲内にある。
3. **除外タグ**のいずれも、本のタグに含まれていない。
4. タグがないか、そのうち少なくとも1つが本のタグに含まれている。
5. **条件**が設定されている場合、その条件が真である（[エントリーの条件](#a-condition-for-an-entry)を参照）。
6. フィルターがないか、フィルターがパートの指示に一致する（または、**アクティベーションのコンテキスト**が*指示とストーリーのパート*の場合は、指示と、ストーリーの最新のパートに一致する）。

すべての条件が成り立つ必要があります。タグもフィルターもないエントリーは、常にアクティブです。

<a id="tags"></a>

### タグ

タグは、エントリーと**本のタグ**（本の[概要](../books/managing-books.md#the-about-tab)タブで設定）を結び付けます。異なる部分を必要とする本の間で、1つのロアブックを共有するために使えます。

| エントリーのタグ | 除外タグ | 次のタグを持つ本でアクティブ |
|---|---|---|
| - | - | 常に |
| `winter` | - | `winter` |
| `winter`, `book-2` | - | `winter` **または** `book-2` |
| - | `book-1` | `book-1` 以外のすべて |
| `winter` | `book-1` | `winter`。ただし `book-1` も持つ場合は除く |

タグは完全一致で照合されます。除外タグは、タグより常に優先されます。

タグは、ロアブック全体にも付けられます（[ロアブック](lorebooks.md)の**タグ**フィールド。ファイルから読み込まれたロアブックはタグを持つ場合があります）。その場合、それらのタグは各エントリーのタグとして扱われます。

<a id="filters"></a>

### フィルター

フィルターは、パートのリクエストがそのエントリーに言及している場合にのみエントリーをアクティブにします。フィルターは、パートの[ユーザープロンプト](../books/prompts.md#user-prompt)、つまり送信される形のリクエストと照合されます。ここには、入力した*場面設定*、*視点人物*、*登場人物*、*指示*が、ユーザープロンプトテンプレートの文言の中に含まれています。

| モード | 一致する条件 |
|---|---|
| **キーワード（いずれか）** | フィルターがカンマで区切られたキーワードの一覧である（`Varro, Ostra`）。リクエストにそのうち少なくとも1つが含まれる（大文字と小文字は区別しない）。キーワードの前後の空白は無視される。 |
| **キーワード（すべて）** | 同じ一覧だが、リクエストにすべてのキーワードが含まれている必要がある。 |
| **テキスト** | そのテキストがリクエストのどこかに現れる（大文字と小文字は区別しない）。`varro` は *Captain Varro* に一致する。 |
| **正規表現** | [正規表現](../regular-expressions.md#in-a-lorebook-entry-filter)がリクエストのどこかに一致する（大文字と小文字は区別せず、改行をまたぐ）。 |

例えば、正規表現 `\b(varro|captain)\b` は単語としての *Varro* または *Captain* に一致します。`varro.*(harbor|docks)` は、Varroと港または埠頭の両方がその順序で言及されている場合にのみ一致します。

!!!warning フィルターが見るのはストーリーではなくリクエストです
エントリーがストーリーを参照する設定（[ストーリーを参照する](#looking-into-the-story)を参照）になっていない限り、フィルターは新しいパートの指示だけを確認し、それ以前のパートの本文は確認しません。Varroについてのエントリーは、書いているパートの場面、登場人物、指示にVarroが言及されたときにアクティブになります。Varroが場面に登場するなら、*登場人物*に彼を入れてください。
   
リクエストには、ユーザープロンプトテンプレート自体の文言も含まれます。テンプレートが使う単語（標準のものは *characters*、*plot*、*tone* などに言及します）に対するフィルターは、常にアクティブになります。
!!!

正しくない正規表現は決して一致しないため、そのエントリーはアクティブになりません。

タグとフィルターを組み合わせるのは、エントリーを一部の本でだけ、しかも関係するときにだけ使わせたい場合です。

<a id="looking-into-the-story"></a>

### ストーリーを参照する

既定では、フィルターはパートのリクエストだけから探されます。そのため、ドラゴンについてのエントリーは、*あなたが*ドラゴンに言及したときに使われます。ストーリーの中でそのエントリーを有効に保ちたい場合、たとえばドラゴンが前のパートに登場していて、新しい指示が「彼は飛び去る」だけの場合は、エントリーの**アクティベーションのコンテキスト**を**指示とストーリーのパート**に設定し、**パート**に、リクエストと一緒に検索する最新パートの数を入力します（`1` は書いているパートの前のパート、`2` はその前の2つのパート...を指します）。

- フィルターは、それらのパートの本文とリクエストをまとめて探されます。そのため、**キーワード（すべて）**のキーワードは、それらの間で分かれていてもかまいません。リクエストは常に対象になります。
- 検索されるのはパートの本文だけで、要約は対象になりません。また、書いている枝のパートだけが対象です（スワイプや再生成では、置き換えられるパートは検索されません）。
- ストーリーが**パート**より短い場合は、全体が検索されます。Marginaliaは、有効になっているエントリーが必要とする分だけパートを読むため、そのようなエントリーがないロアブックはストーリーに一切触れません。
- [他のエントリーが呼び込むエントリー](#entries-brought-in-by-other-entries)は、ストーリーからは探されず、使われたエントリーの内容の中でだけ探されます。

<a id="limiting-an-entry-to-some-parts"></a>

### パートの一部に限定する

ある設定が真になるのは、ストーリーの一部だけという場合があります。たとえば、第5章で見破られる登場人物の変装や、戦争が始まる前の噂などです。**開始メッセージ**と/または**終了メッセージ**に、パートの番号を入力してください。番号は、ストーリーのアウトラインでの付け方に従います（最初のパートは `1`。どちらの番号も範囲に含まれます）。エントリーは、書いているパートの番号がその範囲内にあるときにだけ使われます。フィルターの内容は関係ありません。フィルターのないエントリーは、範囲内でのみ常に有効になるエントリーです。

- 空欄は制限なしを意味します。**開始メッセージ**に `10` だけを入れると「パート10以降」、**終了メッセージ**に `4` だけを入れると「パート4まで」になります。
- 書いているパートは、枝の最後のパートの次のパートです（9パートのストーリーでは、パート `10` を書きます）。スワイプや再生成では、置き換えるパートを書きます。
- テキストのないパートも、アウトラインと同じく数えられます。パートを削除したり挿入したりすると、番号が変わります。
- **開始メッセージ**が**終了メッセージ**より大きい場合、そのエントリーは決して使われません。
- 範囲外のエントリーは、[他のエントリーが呼び込む](#entries-brought-in-by-other-entries)場合でも呼び込まれません。
- [Lorebook VCS](../extensions/index.md)拡張機能は、エントリーの各バージョンに範囲を保持します。ロアブックのインポート、エクスポート、複製でも範囲は保たれます。

<a id="a-condition-for-an-entry"></a>

### エントリーの条件

**条件**は、[エントリーの内容](#templates-in-entries)と同じように書くテンプレートで、Marginaliaが各パートの前に展開します。結果が**真**の場合にのみ、エントリーが使われます。真とは、空の結果、`0`、`false`、`no`、`off`（大文字と小文字は区別しない）以外のすべてを指します。条件は内容と同じものを見ます。すなわち、視点人物、登場人物、場面、そのターンの指示、これまでのストーリー、変数です。

![条件が設定されたエントリー：Tomášが視点人物で、Mizukiが登場しているときにだけ、このエントリーが使われる](../../images/lorebook-condition.png)

| 条件 | エントリーが使われるとき |
|---|---|
| `{%{{{#if presentCharacters}}yes{{/if}}}%}` | そのターンに登場人物がいる |
| `{%{{{eval::povCharacter == "Fiora"}}}%}` | 視点人物がFioraである（[式](../templates/macros.md#expressions)を参照） |
| `{%{{{eval::povCharacter == "Fiora" and presentCharacters has "Mara"}}}%}` | 視点人物がFioraで、Maraが登場している |
| `{%{{{getvar::revealed}}}%}` | 変数 `revealed` に値がある（前のパートで設定される。[マクロリファレンス](../templates/macros.md#variables)を参照） |
| `{%{{{command::authors-note}}}%}` | [コマンド](../commands/index.md)が何かを返す（マクロ用に作られたコマンドのみ使用可能） |

動作の仕組みは次のとおりです。

- 有効のスイッチ、パートの範囲、タグの後、**フィルターの前**に確認されます。そのため、条件が偽のエントリーは、フィルターに一致する場合でも使われず、[他のエントリーが呼び込む](#entries-brought-in-by-other-entries)場合にも呼び込まれません。
- **判定できない**条件は偽として扱われ、[プレビュー](#preview-activation)にその理由が表示されます。理由は、有効なテンプレートではない、存在しない名前（タイプミス）を使っている、存在しないコマンドまたはマクロ用ではないコマンドを使っている、時間切れ、のいずれかです。最初の2つの場合は、入力中にフィールドが赤くなります。
- 読み取りのみを行います。条件内の `{%{{{setvar}}}%}` は何も変更しません。プロンプトにも他のエントリーにも影響しません。使えるコマンドも読み取り専用のものだけです。
- 条件は、エントリーとパートごとに1回だけ展開されます。そのため、`{%{{{random::yes::no}}}%}` は最初の走査とスキャン深度の走査の間で結果が変わりません。
- [プレビュー](#preview-activation)には、条件が偽のエントリーが表示されます（*未使用: 条件が偽*）。

  ![アクティベーションのプレビュー：Mizukiのエントリーは、条件が偽のため使われない](../../images/lorebook-condition-preview.png)
- 1つのパートのすべての条件は、**60秒**を共有します。時間を使い切ると、残っている条件は偽として扱われます（*条件が失敗*、タイムアウト）。実行中の条件は停止されず、時間は次の条件の前に確認されます。
- ロアブックのインポートとエクスポート、複製、Lorebook VCS拡張機能は、条件を保持します。

<a id="entries-brought-in-by-other-entries"></a>

### 他のエントリーが呼び込むエントリー

通常、アクティブになるのはパートのリクエストだけです。ロアブックの**スキャン深度**（[ロアブック](lorebooks.md#the-lorebook-editor)のフィールド。既定の `0` は、この機能をオフにします）を設定すると、アクティブになったエントリーの内容が、アクティブになっていないエントリーのフィルターについて検索されます。リクエストの一部であるかのように扱われます。フィルターが見つかったエントリーもアクティブになります。これが**パス1**です。パス1でアクティブになったエントリーの内容は、パス2で検索され、以下同様に、スキャン深度で指定された回数（最大5回）繰り返されます。

例えば、スキャン深度が `1` の場合、リクエストによってエントリー *Captain Varro*（フィルター `varro`）がアクティブになり、その内容に「...オストラ公に仕えている」と書かれているとします。すると、エントリー *Ostra*（フィルター `ostra`）もアクティブになります。リクエストが都市に一切言及していなくてもです。スキャン深度が `2` であれば、エントリー *Ostra* は、それが言及している港についてのエントリーをさらに呼び込みます。

- 数えられるのは**フィルター**だけです。フィルターがないためにすでに使われているエントリーには、何も必要ありません。また、無効にされているエントリーや、タグで除外されたエントリーは呼び込まれません。
- 検索されるのは、記述どおりのエントリーの本文です。その中のテンプレートは実行されません。
- 本が**使用するロアブック**の**スキャン深度**は、そのロアブック自身のエントリーと、そのサブロアブックのエントリーに対して有効です。サブロアブックは独自の深度を持つことができます（その設定の**サブロアブックとしてのスキャン深度**。空欄の場合は、本が使うロアブックの深度）。その場合、サブロアブックのエントリーは、他のエントリーの内容によって、その深度までのパスでのみ見つかります。`0` の場合は見つかりません。実行されるパスの数は、最大の深度によって決まります。サブロアブックの欄は、サブロアブックとして使われている間だけ有効です。本が直接使う場合は、通常の**スキャン深度**が有効です。
- **このエントリーの内容を他のエントリーの検索対象にしない**にチェックが入っているエントリーは、アクティブになることはできますが、他のエントリーを呼び込むことはありません。
- **他のエントリー経由のみ**にチェックが入っているエントリーは、リクエストによって見つかることは決してありません。使われたエントリーの内容が、そのフィルターに一致した場合にのみ使われます。スキャン深度がないか、フィルターがない場合は、まったく使われません。[プレビュー](#preview-activation)には *未使用: 他のエントリの内容経由でのみ使用* と表示されます。
- プロンプト内の順序は、エントリーがどのように見つかったかに依存しません（[順序と挿入](#order-and-insertion)を参照）。
- エントリーが使われるかどうかを変える拡張機能（[拡張機能](../extensions/index.md)を参照）は、呼び込まれたエントリーについても確認されます。
<a id="preview-activation"></a>

## プレビューの発動

**発動をプレビュー**（ロアブックエディタのツールバーにある目のアイコンのボタン。スマートフォンでは検索と置換のボタンの隣にあります）は、何も生成せずに「このテキストでどのエントリが使われるか」を教えてくれます。**ターンのテキスト**に依頼の本文（シーン、登場人物、指示など、実際に入力するとおりの内容）を入力すると、ロアブックとそのサブロアブックのすべてのエントリが、使われる順に一覧表示されます。

- 使われるエントリには緑のチェックマーク、それ以外には灰色のマークが付きます。
- エントリのロアブック、その**順序**、そして**パス**（テキストで発動したエントリは空欄、[他のエントリによって呼び込まれたエントリ](#entries-brought-in-by-other-entries)は `1`、`2`……と表示されます）。
- **理由**：フィルターなし、テキスト内でフィルターを発見、別のエントリの内容内でフィルターを発見（フィルターとそのエントリを表示）、または使われない理由として、オフになっている、その部分が範囲外、ブックの否定タグ、ブックにエントリのタグがない、条件が偽または判定できない、フィルターが見つからなかった、のいずれかが表示されます。

タグも判定に使われるため、**ブックのタグを使用**でブックを選ぶと、そのブックのタグが使われます（選ばない場合、タグは一切考慮されません）。そのブックは、[ストリーム内を参照する](#looking-into-the-story)エントリのために物語の部分も提供します（選ばない場合は、テキストだけを検索します）。また、[一部のパートに限定したエントリ](#limiting-an-entry-to-some-parts)のために次のパートの番号も提供します（選ばない場合は、その範囲は確認されません）。入力したテキストは、ターンの指示として[条件](#a-condition-for-an-entry)に使われます。ブックを選んでいれば、そのブックの変数と視点、現在の登場人物、最後のパートのシーンも使われます（条件のコマンドはプレビューでは実行されません）。テキストの下の行には、使われるエントリの数と、おおよそのロアのトークン数が表示されます。ロアブックのスキャン深度も適用されます。

[全画面エディタ](lorebooks.md#editing-in-full-screen)では、各エントリのタブの名前の行にも目のアイコンがあります。これを押すと、そのエントリのプレビューが開き、その行が選択された状態になります。表の上の行には、そのエントリが使われるかどうかと、その理由が表示されます。この行は入力に応じて変わります。タブでフィルターを変更したあと、プレビューの**更新**を押すと効果を確認できます。

![ロアブックの発動のプレビュー](../../images/lorebook-preview-activation.png)

プレビューに適用されるのはMarginaliaのルールだけです。テキストは入力したもの（その周りにあるユーザープロンプトのテンプレートではありません）であり、パートの生成中に[拡張機能](../extensions/index.md)が変更する内容も含まれません。

<a id="order-and-insertion"></a>

## 順序と挿入

発動したエントリは、**順序**の小さい順（低いものが先）にソートされてプロンプトに入れられます。同じ順序のエントリは、作成された順のままになります。含まれるすべてのロアブックのエントリは、まとめてソートされます。

**挿入モード**によって、エントリの配置先が決まります。

| モード | 配置先 |
|---|---|
| **ロアブロック内** | [マスターテンプレート](../books/prompts.md#master-template)の `{%{{{backgroundLore}}}%}` ブロック（デフォルトのテンプレートでは*World & lore context*）に、システムメッセージの中で入ります。背景知識に使います。 |
| **ユーザープロンプトの前** | パートの依頼の直前、プロンプトの末尾に入ります。モデルが最も注意を払う位置です。このパートそのものに影響させたい内容（登場人物の現在の状態、シーンのルールなど）に限って、控えめに使ってください。 |

エントリどうしは空行で区切られます。ロアは[コンテキストの上限](../protocols.md#limits)に含まれます。長いエントリが多いと、プロンプトに入る物語の量が少なくなります。

<a id="templates-in-entries"></a>

## エントリ内のテンプレート

エントリの内容は、[ブックのプロンプト](../books/prompts.md#templates)と同じテンプレートです。次のものを使えます。

| 変数 | |
|---|---|
| `{%{{{sceneSetting}}}%}`、`{%{{{povCharacter}}}%}`、`{%{{{presentCharacters}}}%}`、`{%{{{instructions}}}%}` | パートの指示。 |
| `{%{{{narrativePov}}}%}`、`{%{{{narrativeTense}}}%}`、`{%{{{style}}}%}` | ブックの語りの設定。 |

そして、すべての[マクロ](../templates/macros.md)も使えます。例えば、視点人物に合わせて変わるエントリは次のようになります。

{%{
```handlebars
Varro {{#povCharacter}}is seen through the eyes of {{.}}: {{/povCharacter}}a stern, scarred officer.
```
}%}

同じパートで発動したすべてのエントリは、発動の順に変数を共有します。あるエントリが`setvar`で値を設定すると、順序で後ろにあるエントリ（およびマスターテンプレート）は、その値を`getvar`で読み取れます。

内容に構文エラーがあると、フィールドの下に表示されます。エントリは保存されますが、修正するまでは、テンプレートを処理せずに内容がプレーンテキストとして使われます。

<a id="tips"></a>

## ヒント

- エントリは短く、事実に基づいて書いてください。モデルに必要なのは文章ではなく事実です。
- 登場人物、場所、概念ごとに1エントリにすると、それぞれを単独で発動できます。
- 世界の中核には常時発動のエントリを使い、登場人物や場所にはフィルターを使い、ブックどうしでロアブックを共有するにはタグを使ってください。
- 生成されたパートで**Show Prompt**を使うと、何が発動したかを確認できます。また、書く前に[発動のプレビュー](#preview-activation)でテキストを試すこともできます。
- スキャン深度は控えめに使ってください。ほとんどのブックでは1パスで十分です。パスを増やすたびに、望んでいた以上のロアが入り込むおそれがあります。
