# ジョブ

アプリケーションが**外部のAI**に依頼するものはすべて*ジョブ*です。生成、要約、注釈、エージェントの実行、音声に変換された章、画像などが該当します。各ジョブには、それを実行したユーザー、開始と終了の時刻、終わり方、そして言語モデルや音声・画像のバックエンドに対して行った*呼び出し*のすべてが記録されます。呼び出しにもそれぞれ開始と終了があります。管理ページの**Jobs**タブにログが表示されます。現在実行中のものは、ページ`/jobs`で確認できます。

ここに保存されるのはメタデータだけです。誰が、いつ、どれくらいの時間、どのAIまたはサーバー（AIの名前、または音声・画像サーバーのホスト。アドレスのパスやクエリは決して含まない）、どのモデル、どのように終わったか、失敗した場合は短いエラーメッセージです。**プロンプト、回答、本文はいっさい**保存されません。

<a id="what-is-one-job"></a>

## 1つのジョブとは何か

- **まとめられていないリクエスト**（生成、注釈、再下書き、成り代わり生成、一部分の要約、ヘルプアシスタントへの質問、一部分の翻訳やロア項目の翻訳などのプラグインのリクエスト）は、1回の呼び出しを持つ独立したジョブになります。ジョブの種類は作業の種類です（`generation`、`annotate`、`summary`...）。
- **要約の書き直し**は1つのジョブ（`summary`）で、書き直された要約ごとに1回の呼び出しがあります。
- **エージェント実行の作業セッション**は1つのジョブ（`agent`）で、エージェントのラウンドごとに1回の呼び出しがあります。一時停止して再開された実行は、セッションごとにジョブが作られます。サブエージェントのリクエストはそれぞれ独立したジョブです。
- **音声への変換**は、パートのまとまり（バッチ）ごとに1つのジョブ（`audiobook`）になります。ラベル付けを行うモデルへのリクエストと、読み上げた各断片が呼び出しとなります。
- **Image Generator**で作られた画像は、それ自体が1つのジョブ（`image-generator`）で、画像の呼び出しが1回あります。

<a id="what-runs-now-jobs"></a>

## 今実行中のもの：`/jobs`

![生成が進行中のページ /jobs](../../images/jobs-live.png)

Marginaliaのアドレスで`/jobs`を開いてください（例：`http://localhost:8080/jobs`。タブの**Open the live view**リンクからも開けます）。他のページと同じくログインが求められ、管理者以外のユーザーには何も表示されません。一覧は2秒ごとに更新され、実行中のジョブごとに、ユーザー、種類、実行時間、完了した呼び出しの数、いま進行中のもの（AIまたはサーバー、および呼び出しが待っている時間）、そのジョブが対象とする実行の本、そして**Stop**ボタンが表示されます。サーバーが忙しそうなときにざっと確認するのに便利です。1つのモデルの前で多くの呼び出しが待っていれば、すべてが遅い理由がわかります。

ジョブの下には、**Runs on the books**が、いま本に対して作業している実行と、その本が実行中に削除されたり変更されたりしないよう保護しているものを一覧にします（同じ内容が各ユーザーに自分の本について表示される[実行のパネル](../books/story-editor.md#the-panel-of-the-runs)も参照してください）。表示されるのは、ユーザー、本、何をしているか、いまどの段階か、いつから、そしてそれがいくつのオブジェクト（本、パート）を保持しているか、です。「いまどの段階か」はパネルの表示をそのまま使います：*Waiting for the model*、*The model is thinking/writing...*、*Working*、*Waits for you*、生成の場合はその段階（例：パートを書いている間の*INFERENCE*）。開いている本のウィンドウでは、この欄に何も表示されません。開いている本のウィンドウも1つの実行です。**Stop**は、その実行をユーザー自身が行うのと同じように止めます。**End**は、質問の後に、作業を止めずに実行を終わらせます。保持しているものは直ちに解放されます。終わらない実行にだけ使ってください。その作業は、目を覚ましたときにまだ書き込みを行うかもしれません。たいていの実行は自然に終わります。1時間のあいだ何も作業せず、あなたやモデルを待っていない実行は、サーバーによって終了されます。ページを閉じたウィンドウも同様です。

<a id="the-log-the-jobs-tab"></a>

## ログ：Jobsタブ

![管理ページのJobsタブ](../../images/admin-jobs.png)

| | |
|---|---|
| **User, Kind, Status** | 絞り込み条件。*kind*はジョブの種類です（`generation`、`summary`、`annotate`、`agent`、`audiobook`、`image-generator`...）。作業の名前を指定しないコードが行ったリクエストは`untagged`になります。 |
| **Older than (days)** | 指定した日数以上前に開始されたジョブだけ。 |
| **Refresh** | ログを読み直します。 |
| **Delete these jobs** | 絞り込みで表示されているジョブとその呼び出しを、件数を尋ねる確認の後に完全に削除します。絞り込みを設定しない場合は、ログ全体を削除します。 |
| **Open the live view** | `/jobs`を新しいタブで開きます。 |

行をクリックすると、そのジョブの呼び出しが表示されます。種類（言語モデル、音声、画像）、AIまたはサーバー、モデル、開始、終了、所要時間、状態、そして失敗した呼び出しのエラーが表示されます。失敗と表示されるジョブは、失敗した呼び出しがあったか、それを実行したコードによって失敗として終了させられたものです。キャンセルされた呼び出しとは、あなたが停止したもの（またはジョブの終了時にまだ実行中だったもの）です。

![オーディオブック変換の呼び出し](../../images/admin-jobs-calls.png)

失敗したジョブでは、どの呼び出しが失敗し、なぜかが示されます：

![音声呼び出しのエラーで失敗した変換](../../images/admin-jobs-failed.png)

**自動では何も削除されません。** ログはリクエストごとに増えていくので、ときどき整理してください。*Older than (days)*を設定し（例：30）、一覧に出たものを確認して削除します。[クリーンアップ](cleanup.md)は、ユーザーを削除するときにそのユーザーのジョブも一緒に削除します。

![30日より古いジョブと、削除の前の確認](../../images/admin-jobs-old.png)

![ジョブを削除する前の確認](../../images/admin-jobs-delete.png)

ジョブはその終了時にログに書き込まれます。まだ実行中のジョブは`/jobs`にのみ表示されます。アプリケーションが停止した場合、実行中だったジョブは失われます（完了していなかったため）。誰も終了させず、30分間呼び出しも行わないジョブは、完了として終了されます。
