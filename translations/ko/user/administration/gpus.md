# GPU

그래픽 카드는 한 번에 모델 하나만 올려 두는 경우가 많습니다. 언어 모델, 이미지 모델, 음성 모델 중 하나만 올라가는 식입니다. 관리(Admin) 페이지의 **GPU** 탭에서는 한 카드에 있는 모델과 서버가 차례대로 카드를 쓰도록 설정할 수 있습니다. 이렇게 하면 언어 모델이 카드를 채우고 있는 동안 이미지나 오디오북이 시작되지 않고, 필요할 때 언어 모델이 다시 올라옵니다.

관리자가 한 번만 설정하면 됩니다. 이후 모든 사용자는 자신의 AI나 백엔드에 사용할 잠금을 고르기만 하면 됩니다.

<a id="what-it-is-made-of"></a>

## 구성 요소

| | |
|---|---|
| **GPU** | 카드 하나(또는 모델을 한 번에 하나만 올릴 수 있는 모든 기기). 이름만 입력합니다. |
| **GPU 잠금** | GPU를 사용하는 한 가지 방법으로, 그 GPU에 무엇이 올라가 있는지를 뜻합니다. 예를 들어 같은 GPU에 *언어 모델*, *ComfyUI*, *Speech*를 각각 잠금으로 둘 수 있습니다. 잠금에는 순서가 있는 두 개의 단계 목록이 있습니다. 획득 단계는 잠금을 올립니다(컨테이너 시작, 모델 로드, 먼저 내려야 할 것 해제). 해제 단계는 잠금을 올린 것을 카드에서 내립니다(컨테이너 중지, 모델 언로드). **동시 작업 수**는 같은 잠금의 작업을 동시에 몇 개까지 실행할지 제한합니다(한 번에 이미지 하나만 만드는 이미지 서버: 1; 제한 없음: 0). |
| **GPU step** | HTTP 요청 하나입니다. 주소, 메서드, 헤더(`Name: value`, 한 줄에 하나씩, 암호화되어 저장되므로 베어러 키를 여기에 적을 수 있음), 본문, 제한 시간(비워 두면 60초), 응답 후 대기 시간으로 이루어집니다. 하나의 단계를 여러 잠금이 함께 쓸 수 있습니다. 예를 들어 이미지 잠금과 음성 잠금이 모두 먼저 실행하는 *unload the language model* 단계 하나를 둘 수 있습니다. **테스트**를 누르면 요청을 즉시 보냅니다. |

잠금은 다음 위치에서 고릅니다:

- 언어 모델을 위한 [AI의 설정](../inference-providers.md)(일반 설정의 **GPU 잠금**);
- [이미지 생성기](../extensions/image-generator.md#one-gpu-for-the-model-and-the-images)의 백엔드;
- [오디오북](../extensions/audiobook-server.md#one-gpu-for-the-model-and-the-speech)의 백엔드.

**GPU 잠금** 상자는 잠금이 하나 이상 있을 때만 표시됩니다.

<a id="how-the-turns-work"></a>

## 차례가 돌아가는 방식

- 모델에 대한 모든 요청, 모든 이미지, 그리고 오디오북의 모든 배치나 샘플은 자신이 속한 AI나 백엔드의 잠금을 **그 작업이 끝날 때까지** 점유합니다.
- GPU에 그 잠금이 이미 올라가 있으면, 작업은 즉시 시작되고 어떤 단계도 실행되지 않습니다.
- 다른 잠금이 올라가 있으면, 작업은 그 잠금의 작업들이 끝날 때까지 기다립니다. 그런 다음 그 잠금의 **해제 단계**가 모두 실행되고(한 단계가 실패해도 전부), 이어서 새 잠금의 획득 단계가 순서대로 실행됩니다(처음 실패한 단계에서 중단되고, 작업은 그 단계의 메시지와 함께 실패합니다).
- 해제 단계가 실패하면 새 잠금은 전혀 올라가지 않습니다(카드가 여전히 가득 차 있을 수 있기 때문입니다). 작업은 오류와 함께 실패하고, GPU는 원래 가지고 있던 잠금을 그대로 유지합니다. 다른 잠금의 다음 작업이 다시 해제를 시도합니다.
- 작업이 끝난 뒤에도 GPU는 자신의 잠금을 올린 채 **그대로 유지됩니다**. 시간이 지나도 자동으로 해제되지 않습니다. 이미지 창을 열어 두든, 접든, 닫든 GPU를 붙잡고 있지 않으며, 이미지 모델은 언어 모델(또는 다른 잠금)이 카드를 필요로 할 때까지 올라가 있습니다.
- 작업은 들어온 순서대로 기다립니다. 어떤 작업이 다른 잠금을 기다리기 시작하면, 올라가 있는 잠금의 새 작업들은 그 뒤에서 기다립니다. 그래서 바쁜 언어 모델이 이미지를 영원히 기다리게 만들 수는 없습니다.
- 잠금이 없거나, 삭제된 잠금을 가진 AI나 백엔드는 아무것도 기다리지 않습니다.

GPU에 무엇이 올라가 있는지는 애플리케이션이 실행되는 동안에만 알려집니다. 재시작 후에는 아무것도 올라가 있다고 알려지지 않으며, 첫 작업은 획득 단계만 실행합니다.

<a id="the-tab"></a>

## 탭

이 탭에는 GPU 목록이 나오며, 각 GPU에 지금 올라가 있는 잠금(아직 아무것도 실행되지 않았거나 해제된 경우 *Unknown*)과 그 GPU에서 실행 중이거나 기다리는 작업 수가 표시됩니다. 이어서 잠금과 단계 목록이 나오며, 각각 추가, 편집, 삭제 버튼이 있습니다. **새로 고침**을 누르면 GPU가 무엇을 가지고 있는지 다시 읽어 옵니다.

**지금 해제**는 GPU를 수동으로 비웁니다. 예를 들어 Marginalia 밖의 용도로 카드를 쓰고 싶을 때 사용합니다. 실행 중인 작업이 끝나기를 기다리고, 올라가 있는 잠금의 해제 단계를 실행한 뒤 GPU를 알 수 없는 상태로 둡니다(단계가 실패한 경우에도 마찬가지이며, 메시지에 어느 단계인지 나옵니다). 다음 작업이 그 잠금을 다시 올립니다.

GPU를 삭제하면 그 GPU의 잠금도 삭제됩니다. 단계를 삭제하면 그 단계를 실행하던 잠금에서 빠집니다. 삭제된 잠금을 지정했던 AI와 백엔드는 잠금 없이 실행됩니다.

<a id="an-example-one-card-three-models"></a>

## 예: 카드 하나, 모델 세 개

LiteLLM 뒤에 `llama-server`을 두고, 컨테이너를 시작하고 중지하는 [`tools/gpu-control`](../extensions/audiobook-server.md#what-answers-those-addresses) 방식의 프록시를 사용한다고 하면:

| 단계 | 요청 |
|---|---|
| Unload the language model | 헤더 `X-Llama-Unload: all`를 붙인 `POST http://litellm:4000/v1/chat/completions` ([다른 모델을 위해 GPU 비우기](../prompt-cache.md#freeing-the-gpu-for-another-model) 참고) |
| Start ComfyUI / Stop ComfyUI | `POST http://litellm:4000/gpu/comfy/start` / `.../stop` |
| Start speech / Stop speech | `POST http://litellm:4000/gpu/tts/start` / `.../stop` |

| 잠금 | 획득 단계 | 해제 단계 | 동시 작업 수 |
|---|---|---|---|
| 언어 모델 | (없음: 라우터가 다음 요청과 함께 올립니다) | (없음) | 0 |
| ComfyUI | Unload the language model, Start ComfyUI | Stop ComfyUI | 1 |
| Speech | Unload the language model, Start speech | Stop speech | 1 |
| Clip cleanup | Unload the language model, Start ComfyUI | Stop ComfyUI | 1 |

언어 모델의 AI는 *언어 모델*을, 이미지 백엔드는 *ComfyUI*를, 음성 백엔드는 *Speech*를 고릅니다. 오디오북의 [클립 정리](../extensions/audiobook.md#cleanup-of-clips)는 *Clip cleanup*을 고릅니다. 이 잠금은 이미지와 같은 ComfyUI에서 실행되지만, 자체 잠금이 둘 사이에 ComfyUI를 다시 시작하므로 이미지 모델과 정리 모델이 메모리에 함께 올라가는 일은 없습니다. 채팅 뒤의 음성 배치는 *Unload the language model*과 *Start speech*를 실행하며, 다음 채팅 메시지는 먼저 *Stop speech*를 실행합니다.
