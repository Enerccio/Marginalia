# 知识追踪器

记录故事中角色知道什么、以及**不**知道什么，并将其写入提示词。模型往往会让角色知道他们从未见过的人的事情（他们的名字、职业、长相），除非指令加以约束；使用知识追踪器后，提示词会针对场景中每个被追踪的角色，说明该角色知道什么，以及它除此之外一无所知。

!!!
由你决定追踪哪些角色。只有你添加到标签页中的角色会被描述给模型，并且只在它们是正在撰写的部分的*在场角色*时才会如此。不会从故事文本中进行任何猜测。
!!!

<a id="the-knowledge-tab"></a>

## 知识标签页

[故事编辑器](../books/story-editor.md)左侧边栏在*大纲*旁边会出现一个**知识**标签页。你的每一次更改都会即时保存到书籍中。

![知识标签页](../../images/plugin-knowledgetracker.png)

**追踪一个角色**会要求填写一个**名称**，以及可选的**别名**：即该角色在某个部分的*在场角色*字段中可能被写成的其他名字，用逗号分隔。一个名称或别名只能属于一个被追踪的角色。

点击角色卡片上的箭头即可打开该角色，查看它知道什么：

| | |
|---|---|
| **知道**（绿色）/ **不知道**（红色） | 关于任何事物的一句简短陈述：一个人、一个地方、一个秘密、一件事件（*Peter 知道公爵遭遇的阴谋*，*Fiora 不知道 Thomas 是她的父亲*）。请明确写出角色**不**知道的内容，因为模型会遵守这些内容。 |
| 顺序与 **#12** | 最新的知识排在最上面（旧知识也一样）。模型所习得的条目末尾会带有它习得时所在部分的小编号（**#12**）：点击即可将故事滚动到该部分并使其闪烁（在手机上会先关闭抽屉）。你自己写的条目没有编号，所在部分不在当前分支上（另一分支，或该部分已被删除）的条目也没有编号。 |
| **添加知识** | 添加一个条目，立即生效。请保持**一个想法**：一个同时包含两层意思的条目（*不认识 Thomas，从未见过他*）会在其中任一内容不再成立时被撤回。**编辑**按钮可更改文本与类别。 |
| **撤回**（带斜线的圆圈） | 该条目不再成立（例如两人相遇后的*未见过 Thomas*）。它不会被删除，而是变为*旧知识*，并且不再发送给模型。 |
| **锁定**（挂锁，用于模型习得的条目） | [整理过程](#tidying-the-knowledge)永远不会处理被锁定的条目：用它来保留必须留存的内容，例如背叛、秘密。故事仍可能与被锁定的条目相矛盾（例如角色失去记忆）：对故事的重新阅读会照常撤回它。 |
| **删除** | 在确认后永久移除一个条目。撤回会保留该条目，因此拿不准时请使用撤回。 |
| **选择条目**（位于**添加知识**旁边） | 快速删除多个条目：该角色的每个条目（包括旧条目）都会出现一个复选框。**全选** / **取消全选**用于勾选或清除，**删除所选 (n)** 会在确认一次后永久移除已勾选的条目，**取消**则退出选择。 |
| **已见过** | 角色见过的人，由[处理](#processing)记录。处理过程可能会记下并非人物的名字（在在场角色字段中的备注）：打开**编辑**，逐个修改**已见过**列表，名字之间用逗号分隔。你写下的名字在故事被重新阅读后会保留；你删除的名字只有在它所在的部分被重新阅读时才会再次出现。 |
| **旧知识 (n)** | 默认折叠。每个旧条目都可以**复制**、**编辑**、**恢复**（从此刻起重新生效）或删除。 |

<a id="mass-changes"></a>

### 批量更改

**批量更改**按钮（位于**追踪一个角色**旁边的列表图标）会打开一个窗口，其中以带复选框的网格列出所有被追踪的角色及其全部条目（包括旧条目）：类别、文本、状态（*生效*，或旧条目：*已撤回*、*在审阅中被拒绝*、*已整理*）、来源（*初始状态*、*手动编写*、*从故事中习得*），以及习得时所在的部分。你可以在任意多个网格中勾选条目（网格标题处的复选框会勾选该网格的全部条目；底部栏中的**全选** / **取消全选**则作用于所有角色的全部条目），然后：

| | |
|---|---|
| **撤回所选 (n)** | 已勾选的生效条目变为旧知识，与单独点击**撤回**的效果一致。 |
| **恢复所选 (n)** | 已勾选的旧条目重新生效，从此刻起有效。 |
| **删除所选 (n)** | 在确认一次后，永久移除已勾选的条目。 |

按钮上的数字表示每个按钮会更改多少个已勾选的条目。更改之后勾选状态会保留，因此之后可以直接删除已撤回的条目。

窗口顶部的**导出为 JSON** 会将书籍中被追踪角色的数据（名称、别名、条目及其类别、状态、来源与锁定情况，以及他们见过的人）下载为一个文件；不包含任何处理结果，因此适用于任何书籍。**从 JSON 导入**会将此类文件读入书籍，且只会添加：若书籍中已追踪某角色的名称（作为名称或别名），则该角色会获得它尚未拥有的别名、条目和已见过的人（类别和文本都相同的条目会被跳过）；其他角色则成为新的被追踪角色；若某别名已被另一角色占用，则会被略去。导入的条目在本书中没有对应的部分，因此重新处理永远不会将其删除：模型习得的条目被视为手动编写，旧条目仍保持为旧知识。导入后的消息会说明新增或更新了多少个角色，以及新增或已存在的条目各有多少。

<a id="what-goes-into-the-prompt"></a>

## 写入提示词的内容

对于每个属于在场角色的被追踪角色，提示词中会加入如下形式的一段：

```
本场景中角色所知道的内容。角色只根据为其列出的知识行事：

Fiora knows: Mara, a courier of the Guild of Lamps and the sister of her friend Nell; she owes the Guild of Lamps forty crowns.
Fiora does not know: that her father is alive, or that Thomas is her father.
Fiora has met: Mara.
Fiora is currently with: Mara, Thomas.
Fiora has never met or heard of anyone else in this story and knows nothing else of its secrets, plans or events.
```

只发送生效的条目。最后一行（**封闭世界**行）用于阻止模型赋予角色它不可能拥有的知识；它涵盖故事所陈述的内容（人物、地点、秘密、计划、事件），而不包括一个人在那个世界里本来就知道的常识，因此角色仍然了解自己的城镇。你可以在设置中关闭这一行。一个未在场的被追踪角色则完全不会获得任何内容，连一行表明其不知情的文字也没有。

<a id="who-is-present"></a>

### 谁在场

这段内容由部分的**在场角色**字段生成。该字段是自由文本，因此会被宽松地读取：

- 括号中的文字会被忽略：`Tomáš (tired), Mizuki` 指的是 Tomáš 和 Mizuki；
- 名字会在**分隔符**处被切分（默认：`,` `;` 换行、`/`、`|`、`、` `，` `；`）；
- ` - ` 或 `:` 之后的内容是备注，会被丢弃（`Mara - wounded`）；
- 大小写、重音符号以及开头的 *the* 都不影响匹配；
- 名称必须**完整**匹配：*Mara's brother* 不是 *Mara*。当一个角色有多种写法时，请使用别名。关键在于，漏匹配只会少一段内容，而误匹配则会描述一个并不在场景中的角色。

*视点*字段不会被单独读取，因此也请把视点角色写进在场角色中。
<a id="processing"></a>

## 处理

该插件跟随故事进展。**处理**会按顺序读取当前分支中、从**起点**开始的各个部分，并保存一个**游标**（它最后读取的部分）。不使用模型时，它只记录谁与谁见过面：一个被跟踪的角色与“当前角色”字段中与其同时出现的每个名字都算见过面，本区块会列出这些名字。使用模型时，它还会找出角色**得知**的内容（参见[读取角色所得知的内容](#reading-what-the-characters-learn)）。

![处理面板](../../images/plugin-knowledgetracker-processing.png)

标签页顶部的面板显示当前进度。当新的部分定稿后（如果本书启用了自动注释和重写，则在其之后），面板会自动重新加载；如果你以其他方式添加、编辑或删除了部分，请按下**刷新**按钮（齿轮旁边的箭头）以重新读取故事。面板包含：

- **立即处理**：读取尚未处理的部分。
- **处理下一部分**：只读取第一个尚未处理的部分，每次一步（使用模型时，无论*每次运行的部分数*设为多少，都只为该部分发出一次请求）。用它来测试设置，或查看模型对单个部分的发现。命令 `knowledge-process` 将 `parts` 设为 1 时效果相同。
- **起点**：处理开始的部分（默认为*全书开头*）。起点之前的部分永远不会被读取。将起点往前移会从新起点重新读取各部分；往后移则保留已读取的内容。
- **已处理的部分**：最近读取过的各个部分。如果某部分的文本在**处理后发生了变化**（你编辑或重写了它），该部分会被标记；插件不会因此自动重新处理。每行的按钮**从此处重新处理**会撤销来自该部分及之后各部分的内容（你手动编写的条目和撤销记录会保留），然后重新读取这些部分。

当启用**自动处理新部分**时（默认关闭），插件会自动执行以下操作：

- 在生成开始之前，处理自上次以来新写的部分，以便提示词知道谁与谁见过面。被**重新生成**或切换版本（swipe）替换的部分会被忽略。使用模型时，只有在关闭**应用前询问**（见下文）时才会用模型读取；否则只记录谁与谁见过面，模型的发现需要从标签页手动启动，因为不会在生成过程中强制你进行审核。
- 当某部分被**重新生成**并且新文本到达时，之前从旧文本中得知的内容会被撤回。
- 当你**切换版本**或切换到另一条分支时，游标会回退到两条分支共有的最后一个部分。
<a id="reading-what-the-characters-learn"></a>

## 阅读角色所知

在设置中勾选 **Read what the characters learn with the model**。之后，**Process now** 会针对故事的后续部分，请模型判断每个被追踪的角色在其中*学到*了什么：它看见、听到、读到或被告知的内容。它还会指出故事与哪些条目*相矛盾*（例如，角色在相遇之后仍然*从未见过 Thomas*）。请求中包含各部分（以及它们的视角和在场角色）、每个被追踪角色当前所知的内容，并且可根据你的选择包含 lorebook。模型被告知要排除该世界中的人本就知道的事（例如谁是国王），以及由角色自身设定可推出的事（例如魅魔知道自己有尾巴），并且对于不确定的内容不作报告。若某个被追踪角色不在任何一个部分中出现，则不会就其询问模型。

每次运行都是对模型的一次请求。当 **Process now** 需要超过三次请求时（例如一段尚未处理的长篇故事，或 **Parts per run** 被设得很低），它会先告诉你需要处理多少个部分和多少次请求，以及大致有多少文本会经过模型，并在你确认后才开始。每个请求还会携带指令、lorebook 和角色所知的内容，因此实际费用高于仅计算文本的费用。

当 **Ask before applying** 关闭时，改动会立即应用，每一项都会记录到标签页中 Processing 部分的 **Applied automatically** 日志里：哪个角色获得了什么、失去了什么，来自哪个部分。日志中的内容不可编辑，但每一行都有一个 **Revert** 按钮：新增的条目会被否决（它会保留在 *Old knowledge* 下，与审阅中被否决的新增条目一致），被撤回的条目会重新变为有效。如果此后你手动编辑、删除或撤回了该条目，则对应的那一行不会被处理。日志保留最近 200 条改动。

在 **Ask before applying** 关闭时，新的部分一旦定稿即被读取：生成结束后，或者如果本书开启了自动注释（并重新起草）或翻译，则在它们完成后读取，因此模型读取的是你保留的文本，并且在你阅读时同步工作。这是 [部分生成之后的步骤](../books/story-editor.md#what-follows-a-generated-part) 之一。之后的生成会发现角色所知的内容已是最新，不必等待。剩下未完成的部分（你中止的运行、你关闭的窗口）会在下一次生成之前照常读取。

模型工作时，页面上会浮现一个小的**进度面板**。它**不是模态的**：你可以继续阅读和编辑故事，并且可以通过标题栏**拖动**它。关闭它只会隐藏面板，工作仍会继续（**Cancel** 可以停止它）。

![进度面板](../../images/plugin-knowledgetracker-progress.png)

模型作答期间，面板会实时显示 **What the model is writing**：先是它的推理，然后是答案，因此在慢速模型上长时间等待时，不会只看到一个空白的进度条。请求结束后，同样的文本会保留在 **What the model thought** 下（运行中每个请求各占一个区块，并附上它的回答）。即使模型没有提出任何改动、也不会打开审阅，这些内容依然保留。标签页还会保留一个按钮 **Last run: what the model thought**，点击即可重新打开该面板，让你看到为什么什么都没有添加。

模型作答完毕后，面板会告知你，并显示 **Review changes**；标签页的处理面板中也有同样的按钮（*3 changes to review*）。**审阅绝不会自动打开。** 审阅界面是按角色分组的改动表格：

![审阅改动](../../images/plugin-knowledgetracker-review.png)

表格下方的 **What the model thought**（默认折叠）保存了模型在给出答案之前的推理（若模型会发送这些内容）。它说明了为什么提出某项改动，或者为什么你预期的某项改动没有出现，以便你在应用之前判断该改动是否合理。不进行推理的模型在此处不显示任何内容。

| | |
|---|---|
| 复选框 | 是否应用该改动。默认全部勾选；每个角色都有 **Check all** / **Uncheck all**。 |
| **Retract** / **Add** | 撤回会使条目变为旧条目（它被保留，参见[该标签页](#the-knowledge-tab)）。新增是一个新条目，类型为 *Knows* 或 *Does not know*。新增条目的文本和类型可以在应用前**编辑**。 |
| 引文 | 部分中体现该内容的原文，以及它所在的部分。若引文在该部分中找不到，则会被标记：模型可能编造了它，接受前请核实。 |

**Apply** 应用已勾选的改动并继续。**Cancel** 停止整个系列，且不做任何改动：下次会再次提出相同的部分。你取消勾选的新增条目会**作为旧知识保留**，并附带其引文（你可以恢复）；未勾选的撤回则保持该条目不变。模型提出但无法使用的内容（它未被询问的角色、不存在的条目、没有引文的改动，或角色已经知道的内容）会列在 *Left out* 下。已应用的改动会记录其所属部分，因此 **Reprocess from here** 可以将其再次撤销。如果你在审阅期间故事发生了变化（例如切换了分支、删除了某个部分），改动将不会被应用，你需要重新处理。

部分按 **Parts per run**（默认 1）的**批次**读取；超出模型上下文容量的批次会被裁剪到能容纳的范围。系列会逐批继续，直到最后一个已定稿的部分；在需要你确认的系列中，模型未发现任何内容的批次会被跳过，不再询问。若 **Ask before applying** 关闭，改动会立即应用，面板会保留一份日志，每个批次一行。

!!!
该提示词仅在少数场景上对某个模型进行了测试，并未广泛验证：它能防止角色学到自己并未感知到的内容，但请检查所提出的改动，尤其是长场景中的角色。请求会发送到你在下方选择的模型，并承担该服务通常的费用和隐私条款。
!!!

<a id="tidying-the-knowledge"></a>

## 整理知识

模型会记录每个角色学到的内容，而在一个很长的故事中，这份列表会越来越长，其中有很多零碎的条目，你并不希望每次请求都把它们发送给模型。**Tidy knowledge**（位于 **Process now** 旁边，需要开启模型设置）会请模型重新阅读某个角色所知的内容，并结合故事最近处理过的部分作为上下文，然后：

- **删除**不值得保留的条目：琐碎细节、所有在场者都看见过的场景细节（故事本身已经保存了这些内容）、已被后来事件超越的内容，或与另一条目含义重复的内容；
- **合并**关于同一件事的多个条目，合并为一个并保留其中所有事实。

被删除或被合并的条目并不会真正删掉：它们会变为 *Old knowledge*，并且可以恢复。这些改动会像阅读结果一样进行审阅（由 **Ask before applying** 决定），或者立即应用，并以带有 **Revert** 按钮的形式写入日志。

整理只能改动模型学到的、且你没有 **lock**（锁定）的内容。初始条目、你手动添加或编辑的条目、已锁定的条目以及旧条目都不会被改动（前两类和已锁定的条目会展示给模型，以便它看到某个条目会与哪些内容重复）。长时间没有在任何部分中出现的秘密不是删除它的理由，提示词中也明确说明了这一点；模型有疑虑时会保留该条目。模型学到的条目数少于 **Tidy: from this many items**（8）的角色不会被整理；**Tidy: parts of context**（10）则是它读取的最近已处理部分的数量。

**Tidy automatically**（一项设置，默认关闭）会在一次无需询问即可应用改动的运行结束时自动执行整理（即 **Ask before applying** 关闭，因此新部分也是自动读取的），前提是模型自上次整理以来已读取了 **Tidy after this many parts**（10）个部分。它所做的改动会被应用，并以带有 **Revert** 按钮的形式写入日志，该运行的日志也会注明这一点。你需要审阅的运行不会自行启动整理，而条目过少的角色会被跳过，不会询问模型。

在命令栏中也可以执行相同的操作：`knowledge-tidy`（使用 `ask true` 可将改动以列表形式获取；此时打开的标签页会显示审阅按钮），以及 `lock-knowledge` / `unlock-knowledge`，后两者需要指定角色和条目编号。
<a id="settings"></a>

## 设置

*追踪角色*旁边的齿轮：

| 设置 | |
|---|---|
| **加入提示词** | 将该区块插入每次生成的提示词中。开启时按钮变为绿色。 |
| **深度** | 位置，以提示词末尾起算的消息数计：`0` 表示位于本轮指令之后，`1` 表示紧挨在指令之前。它永远不会排到系统提示词之前。 |
| **角色** | 以 *System*、*Assistant* 还是 *User* 消息发送。 |
| **声明没有其他已知信息** | 封闭世界的说明句。 |
| **将角色所知的内容交给标注** | 开启（默认）时，[用 AI 标注](#annotating-with-what-the-characters-know)会获得该部分开始时被追踪角色所知的内容。 |
| **自动处理新部分** | 参见[处理](#processing)。 |
| **让模型读取角色学到的内容** | 处理时会请模型判断每个被追踪角色学到了什么，并提出建议。关闭（默认）时，处理只记录谁见过谁，不产生任何费用。 |
| **应用前询问** | 开启（默认）时，每条建议都会先供审阅。关闭时，建议立即应用并记入日志。 |
| **让模型读取更早的部分** | 模型在阅读新部分时，可以读取某条条目所习得的那一部分（条目会写明“于第 12 部分习得”），以确认所读内容是证实、重复还是与之相矛盾：例如，原本是传闻、现在亲眼所见的内容。每次请求最多读取 5 次，每次读取一个部分；长部分的文本会被截断至能放入上下文的长度；审阅时会显示模型读取了哪些部分。每次读取都是对模型的一轮额外请求，因此默认关闭。无法调用函数的模型会像以前一样只读取请求内容。 |
| **每次运行的部分数** | 一次请求读取多少个部分。数值越大越省钱，但回答会更长，审阅也更困难。 |
| **自动整理**、**每处理这么多部分后整理** | 在一次不经询问直接应用更改的运行结束时，每隔这么多部分（默认 10）自动执行一次整理。默认关闭。 |
| **整理：上下文部分数** | 整理时读取最近处理的多少个部分（默认 10）。 |
| **整理：从这么多条目起** | 模型已习得（且未锁定）的条目少于此数的角色不会被整理（默认 8）。 |
| **供模型使用的 Lorebook** | *部分所激活的条目*（默认：生成这些部分时会使用的条目）、*整个 Lorebook*（所有条目；若放不进上下文，则只发送已激活的条目，并在说明中注明）或*不使用 Lorebook*。 |
| **提取所用的模型 / 协议** | 留空：使用本书的模型。这项工作用较便宜的模型即可；若服务器只保留一份提示词缓存，单独指定模型可避免其被替换。 |
| **本书的分隔符** | 在“当前在场角色”字段中如何将名字拆分开，每行一个名字（换行写作 `\n`）。像 `and` 这样的词会按空格拆分，因此 *Jack and Jill* 在你添加规则之前仍会被视为一个名字。 |
| **我的分隔符（所有书籍）** | 对你所有书籍通用的设置。本书自己的分隔符优先；两者都未设置时，使用内置分隔符。 |

<a id="prompts"></a>

## 提示词

阅读时的系统消息（**知识提取提示词**）和整理时的系统消息（**知识整理提示词**）都是[继承设置](../books/prompts.md#inherited-settings)：一本书使用自己的设置；若没有，则使用上方最近的、设置了该项的文件夹；若仍没有，则使用你的全局设置；若还没有，则使用经过真实模型测试的内置文本。

请在书籍的*提示词*标签页中、*扩展设置*下设置，也可以在文件夹的对话框中设置，或在*设置 → 扩展设置 → Knowledge Tracker* 中为你所有的书籍统一设置（留空时会以灰色显示内置文本）。请保留内置文本中的 JSON 回答格式，插件是依据它来读取回答的。当模型可以读取更早的部分时，插件会添加 `read_part` 的使用说明，因此你的提示词无需包含这些内容。

<a id="annotating-with-what-the-characters-know"></a>

## 用 AI 标注时的角色所知内容

上述区块可以防止模型在*写作时*让角色变得无所不知。同一批记录也有助于找出仍然漏进来的纰漏。当模型[标注某个部分](../books/annotations.md#letting-a-model-annotate)时（**用 AI 标注**、某个范围的部分、自动标注、`/generate-annotation`），追踪器会告诉它，被追踪的角色在**该部分开始时**知道什么；编辑器则会标记那些说出、想到或做出了自己不可能知道之事的角色。例如：*Fiora 叫出了 Thomas 的名字；记录显示她从未见过他。* 提示会指明相关事实。

- **所依据的事实是该部分当时的事实，而不是全书结束时的事实。** 角色在后面某个部分才学到的东西，在此时尚不为人所知；后面某个部分才撤销的条目，在此时仍然为真。该部分自身带来的内容（所习得的、所遇见的、在其中不再成立的）单独列出，因此不会用后半部分去检查前半部分。
- **涉及哪些角色。** 指那些位于该部分的*当前在场角色*中、是该部分的视角人物，或在其正文中被提及的被追踪角色（按整词匹配，不分大小写，也包括别名）。
- **在任何时点都不构成事实的条目会被排除**：即你手动撤销的条目、整理通道已删除的条目，以及你在审阅中拒绝的条目。
- **只依据已记录的内容。** 模型会被告知，记录中没有写到的内容不算事实，因此不会因为追踪器从未得知的事情而标记某个角色。*声明没有其他已知信息*还会在角色遇见过的人物后加上“（没有其他人）”。
- 如果被审阅部分之前有某个部分未被追踪器读取，事实中会注明这一点：那里角色所习得的内容缺失，此时先执行**立即处理**会得到更好的审阅结果。
- 这些事实会计入标注请求的 token 消耗，且仅针对包含被追踪角色的部分。若要关闭，请使用**将角色所知的内容交给标注**。

<a id="the-block-as-a-macro"></a>

## 作为宏使用的区块

除了（或在）自动插入之外，你还可以使用 [{%{`{{command::knowledge-tracker-block::<characters>}}`}%} 宏](../templates/macros.md#commands)自行放置该区块。参数是场景中角色的列表，因此模板可以传入部分的字段内容：

```
{%{{{command::knowledge-tracker-block::{{presentCharacters}}}}}%}
```

无论**加入提示词**是否开启，该宏都会输出区块，因此使用宏时请将其关闭，否则模型会收到两次。深度和角色对宏不适用（区块属于包含该宏的那条消息的一部分）。若所列角色中没有一个是被追踪的，它不输出任何内容。命令宏的回答会与新部分所接续的那一部分一同保存，因此，若你在两次生成之间做了修改，从同一部分进行的第二次生成不会看到该修改；而重新生成和切换候选则会重新请求。

<a id="commands"></a>

## 命令

关于[命令行](../commands/index.md)以及面向代理的说明：

| 命令 | |
|---|---|
| `knowledge-status` | 设置以及处理的进度。 |
| `list-tracked-characters`、`add-tracked-character`、`update-tracked-character`、`delete-tracked-character` | 被追踪的角色，可通过名字、别名或编号指定。 |
| `list-knowledge`、`add-knowledge`、`retract-knowledge`、`restore-knowledge`、`delete-knowledge` | 某个角色的条目，通过 `list-knowledge` 中的编号指定。 |
| `knowledge-process` | 立即处理（`parts`：最多处理这么多个部分）。开启模型时，`ask true` 会以编号列表的形式返回模型发现的更改，并将其保留：此时尚未改动任何内容。打开的知识标签页会显示一个**命令找到的更改**按钮，点击后打开常规审阅（应用 / 取消）；代理则通过 `apply-knowledge-changes` 应用这些更改。 |
| `apply-knowledge-changes` | 应用保留的更改，可全部应用，也可只应用所给编号的更改（与标签页审阅中的**应用**相同）。 |
| `knowledge-tidy` | 整理通道。使用 `ask true` 时，它会以编号列表返回更改并将其保留（标签页会显示一个用于审阅的按钮；`apply-knowledge-changes` 可应用这些更改）。 |
| `lock-knowledge`、`unlock-knowledge` | 锁定某条条目（角色、条目编号），使整理通道不再处理它；或解锁。 |
| `knowledge-reprocess` | 从某个部分（其句柄或位置）开始重新处理；执行前会先询问。开启模型时，它只回退状态，实际重新读取部分需要运行 `knowledge-process`。 |
| `knowledge-set-start` | 设置起始点；不指定部分时，则为全书的开头。 |
| `knowledge-tracker-block` | 以文本形式输出该区块，供宏使用。 |

命令行会按空格拆分参数：角色列表请用引号括起（`/knowledge-tracker-block "Fiora, Mara"`）。

<a id="storage"></a>

## 存储

所有内容都与书籍一同保存（保存在书籍的属性中），因此它也属于[书籍备份](../books/backups.md)和副本的一部分。
