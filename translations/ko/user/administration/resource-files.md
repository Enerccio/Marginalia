# 리소스 파일

[리소스](../resources.md)의 파일(사용자가 스토리 파트에 첨부한 그림, 업로드한 파일)은 각 사용자의 데이터 폴더 안, `data/<login>/images` 및 `data/<login>/resources`에 저장됩니다. 리소스를 삭제하거나 그 내용을 바꾸면 데이터베이스만 바뀝니다. 파일은 디스크에 그대로 남으며, [정리](cleanup.md)를 포함해 그 어떤 것도 파일을 지우지 않습니다. **리소스 파일** 기능은 더 이상 아무것도 사용하지 않는 파일을 찾아 내려받을 수 있게 하고, 디스크 공간을 되찾기 위해 디스크에서 삭제할 수 있게 합니다.

<a id="cleaning-up-the-files"></a>

## 파일 정리하기

1. 관리자 페이지에서 **리소스 파일** 탭을 열고 **파일 스캔**을 클릭합니다. 진행 막대에 읽히고 있는 폴더가 표시됩니다. 아무것도 바뀌지 않습니다.
2. 표에는 **어떤 리소스도 가리키지 않는** 파일이 나열됩니다. 경로(`<user folder>/images/<file>`), 크기, 마지막으로 수정된 날짜가 표시됩니다. 모든 파일이 체크되어 있습니다. 유지하고 싶은 파일의 체크를 해제하십시오. **모두 선택**과 **선택 해제**는 모든 파일에 적용되며, 첫 번째 열 머리글의 화살표도 같은 일을 합니다. 표 위의 줄에는 사용되지 않는 파일이 몇 개인지, 그 총 크기, 체크된 파일이 몇 개인지가 표시됩니다.
3. 선택 사항으로 **ZIP으로 다운로드**를 클릭하면 체크된 파일을 하나의 압축 파일로 받을 수 있습니다(항목 이름은 경로로 지어집니다). 행의 화살표를 눌러 파일 하나만 받을 수도 있습니다. 삭제하기 전에 보관해 둘 백업입니다.
4. **선택 항목 삭제**를 누르면 확인 후 체크된 파일이 디스크에서 제거됩니다. **닫기**는 아무것도 삭제하지 않고 표만 비웁니다.

![파일 스캔 후의 리소스 파일 탭](../../images/admin-resource-files.png)

!!!warning
삭제된 파일은 복구할 수 없습니다. 확실하지 않다면 먼저 ZIP으로 다운로드하십시오.
!!!

<a id="what-counts-as-used"></a>

## 사용 중으로 간주되는 기준

파일은 **삭제된 리소스를 포함해, 어떤 사용자의 리소스든 그 파일을 가리키고 있으면** 사용 중입니다. [휴지통](../trash.md)에 있는 리소스도 복원할 수 있으므로, 그 그림은 다시 제대로 작동해야 합니다. 따라서 삭제된 리소스의 파일은 [정리](cleanup.md)가 데이터베이스에서 리소스를 제거한 뒤에야 목록에 나타납니다. 교체된 내용의 파일(이전 파일이 남아 있는 경우)과 업로드 실패로 남은 파일도 마찬가지입니다.

파일은 이름(무작위 식별자)으로 비교되며, 모든 사용자의 폴더를 대상으로 합니다. 삭제된 사용자의 `<login>-deleted` 폴더도 포함됩니다. 이들 파일은 정리가 그 사용자와 리소스를 완전히 지우기 전까지 *사용 중*으로 남습니다.

데이터 폴더의 폴더 중 `images` 및 `resources` 폴더만 읽으며, 그 밖은 읽지 않습니다(데이터베이스 백업, 에이전트 작업 공간 등은 건드리지 않습니다).

스캔 후에 사용자가 업로드한 파일은 삭제되지 않습니다. **선택 항목 삭제**는 데이터베이스를 다시 읽어, 그 시점에 리소스가 가리키고 있는 파일을 남겨 둡니다(메시지에 남겨 둔 파일 수가 표시됩니다).

스캔은 데이터 폴더를 읽기 때문에 파일이 많으면 시간이 걸릴 수 있습니다. 진행 막대의 **중지**로 스캔을 취소할 수 있습니다.
