# 데이터베이스 백업

데이터베이스 백업은 Marginalia 데이터베이스의 완전한 사본입니다. 모든 사용자와 그들의 책, 로어북, 설정, 확장 데이터가 모두 포함됩니다. 설치본을 실수나 장애로부터 보호하고 다른 컴퓨터로 옮기는 데 사용하세요. 책 하나만 백업하려면 사용자는 [책 백업](../books/backups.md)을 이용할 수 있습니다.

![데이터베이스 백업 탭](../../images/admin-database-backups.png)

<a id="creating-a-backup"></a>

## 백업 만들기

**데이터베이스 백업** 탭에서 **백업 생성**을 클릭하세요. 사본은 Marginalia가 실행 중일 때 만들어지며, 사람들이 글을 쓰고 있는 동안에도 일관성이 유지됩니다. 백업은 **이름**, **생성됨** 날짜, **유형**(*수동* 또는 *예약*), **크기**와 함께 목록에 나타납니다. 도구 모음에는 데이터베이스의 현재 크기가 표시됩니다.

각 백업에는 다음 버튼이 있습니다:

| 버튼 | |
|---|---|
| **다운로드** | 백업 파일(`.sqlite`)을 다운로드합니다. 사본을 서버 바깥에 보관하세요. |
| **재시작 시 복원** | 백업을 복원합니다. [아래](#restoring)를 참고하세요. |
| 휴지통 | 백업을 삭제합니다. |

**백업 업로드**는 백업 파일(`.sqlite` 또는 `.db`)을 목록에 추가합니다. 예를 들어 다른 설치본에서 내려받은 파일을 추가할 수 있습니다. 파일은 먼저 검사되며, SQLite 데이터베이스가 아니거나, 손상되었거나, Marginalia 데이터베이스가 아니거나(다른 애플리케이션의 데이터베이스), 실행 중인 버전보다 새로운 Marginalia 버전에서 만들어진 경우 *The database can't be restored: ...* 메시지와 함께 그 이유를 표시하고 거부합니다.

!!!warning 백업에는 비밀 정보가 들어 있습니다
데이터베이스 백업에는 모든 사용자의 비밀번호 해시와 API 키를 포함한 모든 것이 들어 있습니다. API 키는 [데이터 폴더](index.md#the-data-folder)의 `secret.key` 파일로 암호화되어 있지만, 이 파일은 백업에 포함되지 않습니다. 그래도 백업과 `secret.key` 파일을 모두 가진 사람은 API 키를 읽을 수 있습니다. 내려받은 백업은 서버 자체만큼 안전하게 보관하세요.
!!!

파일은 [데이터 폴더](index.md#the-data-folder)의 `db-backups` 폴더에 저장됩니다. Marginalia가 스스로 만드는 사본 - [복원](#restoring) 전의 `pre-restore-...`와 [업그레이드](#copy-before-an-upgrade) 전의 `pre-migration-...` - 도 목록에 포함되며 *수동*으로 표시됩니다. 따라서 예약 백업의 순환 삭제로 지워지지 않습니다. 책 백업과 확장 JAR 파일은 별도의 파일이며 데이터베이스 백업에 포함되지 않습니다.

**업로드된 파일([파트 그림](../books/story-editor.md#images))도 데이터베이스 백업에 포함되지 않습니다**. 데이터베이스는 이 파일을 [리소스](../resources.md) 탭의 항목으로만 알고 있으며, 파일 자체는 데이터 폴더의 `data/<login>/images` 폴더에 있습니다. 이것은 문제가 없습니다. 복원 후에도 항목은 백업 당시의 것이며, 그 항목이 사용하는 그림은 여전히 폴더에 있습니다. 백업 이후에 추가된 그림의 파일은 아무것도 참조하지 않는 채로 남아 디스크 공간을 차지합니다. 그림을 안전하게 보관하려면 데이터 폴더 전체를 직접 만든 백업에 포함하거나, [책 백업](../books/backups.md#pictures-in-a-backup)에 묶어 넣으세요.

백업을 **다른 설치본**에서 복원할 때는 Marginalia를 멈춘 상태에서 원래 설치본의 `secret.key`도 함께 복사하세요. 그렇지 않으면 저장된 API 키를 복호화할 수 없어 모든 사용자가 다시 입력해야 합니다.

<a id="scheduled-backups"></a>

## 예약 백업

**예약 백업** 섹션은 백업을 자동으로 만듭니다:

| 필드 | |
|---|---|
| **백업 자동 생성** | 예약 백업을 켭니다. |
| **일정 (cron)** | 백업을 만들 시점입니다. [아래](#schedule-syntax)를 참고하세요. 다음 세 번의 실행 시각이 필드 아래에 표시됩니다. |
| **예약 백업 보관 수** | 보관할 예약 백업의 개수입니다. 더 오래된 백업은 삭제됩니다. `0`은 모두 보관합니다. 수동 백업과 업로드된 백업은 절대 삭제되지 않습니다. |

**일정 저장**을 클릭하여 적용하세요. 상태 줄에는 마지막 예약 백업이 만들어진 시각과 다음 백업 예정 시각이 표시됩니다.

예약된 시각에 Marginalia가 실행 중이 아니었다면 - 글을 쓰는 동안에만 실행되는 데스크톱 앱에서 흔한 경우입니다 - 다음 시작 후 약 30초 뒤에 놓친 백업을 만듭니다.

<a id="schedule-syntax"></a>

### 일정 문법

일정은 다섯 개의 필드로 이루어진 cron 표현식이며, 형식은 `minute hour day-of-month month day-of-week`입니다:

| 표현식 | 실행 시점 |
|---|---|
| `0 3 * * *` | 매일 3:00 |
| `0 */6 * * *` | 6시간마다 |
| `30 2 * * 1` | 월요일 2:30 (요일: `0` 또는 `7`은 일요일, `1`은 월요일...) |
| `0 12 1 * *` | 매월 1일 정오 |
| `@daily`, `@weekly`, `@monthly` | 매일 / 매주 / 매월 자정에 한 번 (`@hourly`, `@yearly`도 작동합니다) |

시각은 서버의 시간대 기준입니다(Docker에서는 `TZ` 환경 변수로 설정합니다).

!!!
예약 백업을 끄려면 *백업 자동 생성*의 체크를 해제하고 *일정 저장*을 클릭하세요. 표현식은 그대로 보관되므로 나중에 다시 켤 수 있습니다. 표현식은 여전히 검사되며, 잘못된 표현식은 저장되지 않습니다. 다만 백업이 꺼져 있는 동안에는 필드가 비어 있을 수도 있습니다.
!!!

<a id="restoring"></a>

## 복원

Marginalia가 사용 중인 동안에는 데이터베이스를 교체할 수 없으므로, 복원은 **다음 시작** 때 이루어집니다:

1. 백업 옆의 **재시작 시 복원**을 클릭하고 확인하세요.
   탭에 *Database restore is scheduled. Restart the application to apply it.* 메시지가 표시됩니다. **복원 취소**를 누르면 이 예약을 되돌릴 수 있습니다.
2. Marginalia를 재시작하세요. [데스크톱 앱](../getting-started/desktop-app.md)을 종료한 뒤 다시 실행하거나, [서버](../getting-started/docker-server.md)에서 `docker compose restart`를 실행하세요.

시작할 때 현재 데이터베이스는 `db-backups/pre-restore-<time>-marginalia.sqlite`으로 옮겨집니다. 이 파일은 목록에 나타나므로, 그 파일을 복원하여 복원을 되돌릴 수 있습니다. 그 자리를 백업이 대신합니다. 이전 Marginalia 버전의 백업은 자동으로 업그레이드됩니다.

백업은 교체되기 전에 다시 검사됩니다(*백업 업로드*와 같은 검사이며, *재시작 시 복원*도 이 검사를 통과하지 못한 백업은 거부합니다). 검사에 실패하거나 업그레이드에 실패하면 Marginalia는 현재 데이터베이스를 유지하거나(또는 되돌려 놓고) 정상적으로 시작합니다. 거부된 파일은 `db-backups/rejected-restore-<time>-marginalia.sqlite`로 옮겨지고, 이유는 로그에 기록됩니다.

백업 이후에 만들어진 모든 것(책, 파트, 설정)은 사라집니다. 로그인되어 있던 사용자는 계정이 바뀌었다면 다시 로그인해야 합니다.

<a id="copy-before-an-upgrade"></a>

## 업그레이드 전 사본

새 버전의 Marginalia가 기존 데이터베이스의 구조를 바꾸려 할 때는 먼저 `db-backups/pre-migration-<time>-V<version>-marginalia.sqlite`이라는 이름으로 사본을 저장합니다. 여기서 버전은 데이터베이스가 있던 버전입니다. 이 사본은 백업 목록에 들어가므로, 이전 버전의 Marginalia를 설치하고 그 사본을 [복원](#restoring)하면 업그레이드를 되돌릴 수 있습니다. 마지막 세 개의 사본이 보관됩니다. 새 설치에는 복사할 것이 없으며, 사본을 만들 수 없는 경우(예: 디스크가 가득 찬 경우) 로그에 그 사실이 기록되고 업그레이드는 계속 진행됩니다.

절반쯤 실패한 마이그레이션은 스스로 되돌려지며 Marginalia는 시작하지 않습니다. 이 사본은 업그레이드가 완료되었지만 원하지 않는 결과를 낸 경우를 위한 것입니다.

<a id="moving-to-another-computer"></a>

## 다른 컴퓨터로 옮기기

1. 백업을 생성하고 **다운로드**하세요.
2. 새 컴퓨터에 Marginalia를 설치하고, 처음 시작할 때 임시 관리자를 만드세요.
3. **백업 업로드**, **재시작 시 복원**, 재시작.
4. 백업에 있던 계정으로 로그인하세요.

예전 [데이터 폴더](index.md#the-data-folder)에서 `data` 폴더(책 백업과 파트 그림)와 `extensions` 폴더도 함께 복사하세요. 또는 Marginalia를 멈추고 `.marginalia` 폴더 전체를 복사하세요.
