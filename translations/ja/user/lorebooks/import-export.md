# インポートとエクスポート

<a id="exporting"></a>

## エクスポート

エディターでロアブックを選択し、**エクスポート**ボタン（ファイルのアイコン、*ロアブックをエクスポート*）をクリックします。ブラウザーは次の内容を含む `<lorebook name>.json` をダウンロードします：

- ロアブック本体と**そのすべてのサブロアブック**（すべての階層）。名前、説明、有効状態、タグを含みます。
- すべてのエントリ。内容、メモ、順序、フィルター、挿入モード、タグ、ネガティブタグを含みます。

バックアップとして保存したり、世界観を他のユーザーと共有したり、別のインストール環境へ移したりするのに使います。[拡張機能](../extensions/index.md)がロアブックやエントリに保存しているデータもファイルに含まれ、インポート時に復元されます。[Lorebook VCS](../extensions/lorebook-vcs.md)拡張機能のエントリのリビジョンは元のエントリに属しており、インポートで作られるエントリには表示されません。リビジョンについては、この拡張機能が独自のエクスポートを持っています。

<a id="exporting-for-sillytavern"></a>

### SillyTavern 向けのエクスポート

**エクスポート**ボタンを押すと、2つの項目があるメニューが開きます：**ロアブックをエクスポート**（上で説明したファイル）と**SillyTavern へエクスポート**です。後者はロアブックを、SillyTavern が読み込める SillyTavern のワールドインフォファイルとしてダウンロードします。これは[インポート](#importing-sillytavern-world-info)の逆の操作です：

| Marginalia | SillyTavern |
|---|---|
| *エントリ名* | タイトル / メモ（`comment`） |
| *内容*、*順序*、*有効* | 内容、順序、disabled |
| フィルターなし | 常時有効のエントリ（🔵） |
| *テキスト* フィルター | プライマリキーが1つ |
| *キーワード（いずれか）* | キーワードごとに1つのプライマリキー |
| *キーワード（すべて）* | 最初のキーワードがプライマリキーで、残りはロジック *AND ALL* のセカンダリキー |
| *正規表現* | `/pattern/flags` の形式で書かれた1つのキー |
| *ロアブロック内* | 位置：*before character definitions* |
| *ユーザープロンプトの前* | 位置：*at depth* 1 |
| タグ | キャラクターフィルター（名前で指定）。ネガティブタグは、エントリにタグがない場合のみ（*exclude*） |

**サブロアブックは統合されます**。ファイルには、まずロアブック本体のエントリが、その後にサブロアブックのエントリが並びます。SillyTavern にはロアブックの中にロアブックを置く仕組みがないためです。SillyTavern に対応する項目がないものは省かれます：エントリの*メモ*、タグと同時に設定されたネガティブタグ、拡張機能のデータです。SillyTavern は直近のチャットでキーを照合します。逆方向については[動作の違い](#what-works-differently)を参照してください。

!!! warning
正規表現は Java の構文で書かれます。SillyTavern は JavaScript を使うため、単純な表現は動作しますが、Java 独自の機能（所有量指定子、`\p{...}` クラスなど）はそこでは一致しません。
!!!

<a id="importing-a-marginalia-lorebook"></a>

## Marginalia ロアブックのインポート

1. **インポート**ボタン（ファイルのアイコン）をクリックし、**Marginalia ロアブックをインポート**を選びます。
2. Marginalia からエクスポートしたファイルをアップロードします。

インポートでは、同じ名前のロアブックが既にあっても、常に**新しい**ロアブックが作成されます。作成されるのは、ロアブック本体とそのサブロアブックで、構造も同じです。インポートされたロアブックはエディターで選択された状態になります。タグは名前で既存のタグと照合され、一致しなければ新しく作成されます。

古いバージョンの Marginalia のファイル（サブロアブックのない単一のロアブック）もインポートできます。

!!!
ロアブックは[ブックのバックアップ](../books/backups.md)の中にも含まれます。バックアップを復元またはクローンすると、コピーを作成する代わりに、既に持っているロアブックにリンクすることがあります。[バックアップの復元](../books/backups.md#restoring-a-backup)を参照してください。
!!!

<a id="importing-a-lorebook-another-user-shares"></a>

## 他のユーザーが共有したロアブックのインポート

インポートメニューの**他のユーザーからインポート**には、他のユーザーが[共有](lorebooks.md#sharing-a-lorebook)しているロアブックが、名前、作者、説明とともに一覧表示されます。行を開くとエントリを読めます。**インポート**をクリックすると、自分専用のコピーを取得できます。含まれるのは、作者が共有しているサブロアブックだけです。ファイルのインポートと違い、エクスポートして送る必要はありません。作者は**他のユーザーと共有**にチェックを入れるだけです。

<a id="importing-an-archive-of-text-files"></a>

## テキストファイルのアーカイブのインポート

1. **インポート**ボタンをクリックし、**アーカイブからインポート**を選びます。
2. `.md`（Markdown）ファイルを含む `.zip` ファイルをアップロードします。
3. 表の**エントリ名**を確認し、必要であれば変更してから、**インポート**をクリックします。

![アーカイブをアップロードするウィンドウ](../../images/archive-lorebook-upload.png)

![インポート前のエントリ名](../../images/archive-entry-names.png)

Marginalia は、ファイル名（`.zip` を除く）と同じ名前の新しいロアブックを作成し、**`.md` ファイルごとに1つのエントリ**を作ります。ファイルは名前の順に取り込まれます。名前に含まれる数字は数値として比較されるため（`2.md` は `10.md` より前になります）、アーカイブのフォルダ内のファイルも同じ扱いです。エントリには、この順序で *順序* 1、2、3…が割り当てられます。ファイル全体が *内容* になります。それ以外のファイル、フォルダー、隠しファイル（`.name`）、Mac で作られたアーカイブの `__MACOSX` フォルダーは除外されます。

**エントリ名**は、次の順序で入力されます：

1. アーカイブのルートにあるファイル `names.txt`。1行に1つの名前を書き、1行目が上記の順序で最初の `.md` ファイルの名前になります。以降も同様です（空行の場合、そのファイルは次の規則に委ねられます。余分な行は無視されます）。スクリプトなどで多数のファイルに一度に名前を付けたいときに使います；
2. ファイルの最初の見出し（`# Chapter 1` の場合は *Chapter 1*）；
3. `.md` を除いたファイル名。

ダイアログの表に結果が表示されます。名前はどれでも上書き入力できます。

その後、インポートの進行状況が表示されます。**停止**を押すと、保存中のエントリの処理が終わった時点でインポートが終了します。ロアブックには、それまでにインポートされたエントリが残ります（インポートは取り消されません）。また、何個のファイルがインポートされたかがメッセージで表示されます。

エントリは**無効**の状態でインポートされます。フィルターがないため、有効にすると、すべてのリクエストに送られてしまいます。章が何十と並ぶ一冊分の本ではこれは望ましくないでしょう。必要なものだけ、フィルターか[タグ](entries.md#tags)を設定したうえで有効にしてください。多数のエントリを一度に処理するなら、**一括編集**が手早い方法です。

同じファイルをストーリーにパートとして取り込みたい場合は、[ブックへのインポート](../books/story-editor.md#importing-into-the-book)を参照してください。

<a id="importing-sillytavern-world-info"></a>

## SillyTavern のワールドインフォのインポート

1. **インポート**ボタンをクリックし、**SillyTavern からインポート**を選びます。
2. SillyTavern からエクスポートしたワールドインフォファイル（`.json`）をアップロードします。

Marginalia は、ワールドインフォの名前（またはファイル名）と同じ名前の新しいロアブックを作成し、各エントリを変換します：

| SillyTavern | Marginalia |
|---|---|
| タイトル / メモ（`comment`） | *エントリ名*（タイトルがない場合は最初のキー） |
| 内容 | *内容*。`{%{{{user}}}%}` や `{%{{{char}}}%}` などのマクロはそのまま機能します。[マクロ](../templates/macros.md)を参照 |
| 順序 | *順序* |
| Disabled | *有効* のチェックを外す |
| Constant（🔵）、またはキーなし | 常に有効（フィルターなし） |
| プライマリキー、ロジック付きのオプションのセカンダリキー | フィルター。下記を参照 |
| Case-sensitive、Match whole words | フィルターに組み込まれます |
| 位置：*before / after character definitions*、*example messages* | *ロアブロック内* |
| 位置：*author's note*（上 / 下）、*at depth* | *ユーザープロンプトの前* |
| キャラクターフィルター | タグ（または *exclude* の場合はネガティブタグ）。キャラクター名とタグで照合 |

**キーはフィルターになります。** 単一の平易なキーは *テキスト* フィルター（`dragon`）になります。それ以外のもの（複数のキー、セカンダリキー（*AND ANY*、*AND ALL*、*NOT ANY*、*NOT ALL*）、`/regex/` の形式で書かれたキー、大文字小文字の区別や単語単位の一致）は、同じ働きをする1つの *正規表現* フィルターになります。例えば、キー `dragon`、`wyrm` とセカンダリキー `fire`（*AND ANY*）は次のようになります：

```
(?s)^(?=.*(?:\Qdragon\E|\Qwyrm\E))(?=.*(?:\Qfire\E))
```

この式を読む必要はありません。正規表現がわかる場合にのみ編集してください。

<a id="what-works-differently"></a>

### 動作の違い

Marginalia に対応する項目がない SillyTavern の設定は、エントリの**メモ**に記載されます。例えば *Imported from SillyTavern, not supported: probability 50%, inclusion group "weather".* のようになります。対象は次のとおりです：

- 確率（probability）、包含グループ（inclusion groups）、持続（sticky）、クールダウン（cooldown）、遅延（delay）：エントリは一致するたびに単純に有効になります；
- *at depth* での挿入：代わりにエントリはユーザープロンプトの前に入ります。

最も大きな違いは、**キーを何と照合するか**です。SillyTavern は直近のチャットを検索します。Marginalia は、[書いているパートのリクエスト](entries.md#filters)（そのシーン、キャラクター、指示）と照合し、インポートされたエントリは最初からそれだけを対象にします（その **Activation Context** は *指示* になります）。そのため、SillyTavern では直近のメッセージに名前が出てきたために有効になったエントリも、Marginalia ではターン中にその名前に言及したときにしか有効になりません。SillyTavern と同じ動作にしたい場合は、エントリの **Activation Context** を *指示とストーリーのパート* に設定し、**パート** に、確認する最新のパートの数を指定してください。詳しくは[ストーリーを参照する](entries.md#looking-into-the-story)を参照してください。再帰的な有効化（エントリが他のエントリを有効にすること）もインポートでは設定されません。ロアブックの **scan depth** を設定すると有効になります。詳しくは[他のエントリによって取り込まれるエントリ](entries.md#entries-brought-in-by-other-entries)を参照してください。

インポート後は、エントリを確認し、どれを常に有効にするか、どれをフィルターのままにするか、どれを[タグ](entries.md#tags)で管理するのが良いかを決めてください。
