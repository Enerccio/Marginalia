# 항목과 활성화

<a id="the-entry-list"></a>

## 항목 목록

로어북 편집기의 각 행이 항목 하나입니다.

| 열 | |
|---|---|
| 체크박스 | **사용**. 비활성화된 항목은 절대 사용되지 않습니다. |
| **항목 이름** | 항목에 붙인 이름입니다. 모델에는 전송되지 않습니다. |
| **순서** | 프롬프트에서 항목의 위치입니다. [순서와 삽입](#order-and-insertion)을 참고하세요. 새 항목은 `100`을 받습니다. |
| **태그** | 항목을 활성화하는 태그입니다. [태그](#tags)를 참고하세요. |
| ⌄ | 항목의 세부 정보를 보여 줍니다. |
| 펼치기 | 항목을 [전체 화면 편집기](lorebooks.md#editing-in-full-screen)에서 엽니다(데스크톱). |
| 휴지통 | 항목을 삭제합니다(확인 후). |

도구 모음의 **항목 추가**는 순서가 `100`인 항목을 추가합니다. 변경 내용은 입력하는 대로 저장됩니다.

<a id="searching-and-deleting-many-entries"></a>

### 여러 항목 검색 및 삭제

버튼 옆의 돋보기 상자는 이름, 내용, 메모 또는 필터에 입력한 텍스트가 있는 항목만 보여 줍니다(대소문자는 구분하지 않습니다). 모든 항목을 다시 보려면 상자를 비우세요. 선택한 로어북의 항목만 검색하며, 하위 로어북은 검색하지 않습니다. 휴대폰 레이아웃에서는 이 상자가 목록 위에 있습니다.

상자 옆에는 목록을 좁히는 상자가 두 개 더 있습니다. **태그**는 태그가 붙은 항목을 보여 줍니다(로어북의 항목 중 하나 이상이 가진 태그만 나열하며, *제외* 태그는 보지 않습니다). **상태**는 **전체**, **사용**, **비활성화됨**, **상시 (키 없음)** 중 하나를 보여 줍니다. 상시는 사용 상태이면서 필터가 없어서 모든 파트에 사용되는 항목입니다. 검색, 태그, 상태는 함께 적용되므로 항목은 세 조건을 모두 만족해야 합니다. 휴대폰 레이아웃에서는 두 상자가 검색 상자 아래에 있습니다.

왼쪽의 체크박스 열에서 항목을 선택합니다. 머리글의 체크박스는 보이는 항목을 모두 선택하므로, 검색한 뒤 머리글 상자를 누르면 검색 결과가 선택됩니다. 항목이 선택되면 도구 모음에 **선택 항목 삭제**가 항목 수와 함께 나타나며, 한 번 확인한 뒤 항목을 [휴지통](../trash.md)으로 옮깁니다. [일괄 편집](lorebooks.md#mass-edit)에도 **선택 항목 삭제** 버튼이 있습니다. 휴대폰에서는 항목의 **⋮** 메뉴에 **Select entries**가 있습니다. 이를 누르면 항목 앞에 체크박스가 나타나고, 체크한 항목 수와 함께 **선택 항목 삭제**가 나타납니다(항목마다 **Delete entry** 버튼도 따로 있습니다).


<a id="search-and-replace"></a>

## 찾기 및 바꾸기

**찾기 및 바꾸기**(**항목 추가** 오른쪽)는 로어북의 모든 항목에 있는 이름, 텍스트, 주석에서 단어, 이름 또는 구절을 한꺼번에 바꿉니다. 요약과 분기에 대한 옵션을 제외하면 [이야기의 찾기 및 바꾸기](../books/story-editor.md#search-and-replace)와 같은 방식으로 작동합니다. **검색**은 일치 항목이 있는 항목을 나열하고(표에 항목 이름이 표시됨), 각 항목의 일치 부분을 현재 상태와 바뀐 뒤의 상태로 보여 줍니다. **바꾸기**는 항목을 실제로 변경합니다. **정규식으로 검색**([정규 표현식](../regular-expressions.md) 참고)과 **대소문자 구분** 옵션이 있습니다. 대소문자 구분은 기본으로 켜져 있으며, 정규식이 켜져 있는 동안에는 잠깁니다. 정규식에서는 `(?i)`를 사용해 대소문자를 무시할 수 있습니다. 비활성화된 항목도 검색합니다. 휴대폰에서는 *사용* 체크박스 옆의 아이콘 버튼을 누르면 휴대폰 레이아웃의 같은 창이 열립니다.

![로어북의 찾기 및 바꾸기 창, 한 항목의 일치 항목이 펼쳐진 모습](../../images/lorebook-search-replace.png)

이야기 편집기의 명령줄에서는 열린 책의 로어북에 대해 `/search-replace-lore-entries`를 사용할 수 있습니다. [명령어](../commands/index.md#commands-that-come-with-marginalia)를 참고하세요.

## 항목 세부 정보

⌄ 버튼을 누르면 세부 정보가 열립니다.

![세부 정보가 펼쳐진 항목](../../images/lorebook-entry.png)

| 필드 | |
|---|---|
| **내용** | 프롬프트에 들어가는 텍스트입니다. 변수와 매크로를 사용할 수 있는 [템플릿](#templates-in-entries)입니다. |
| **필터 모드** | **키워드 (하나라도)**, **키워드 (모두)**, **텍스트** 또는 **정규식** 중 하나로, *필터 텍스트/패턴*을 어떻게 일치시킬지 정합니다. |
| **필터 텍스트/패턴** | 필터입니다. [필터](#filters)를 참고하세요. 비어 있으면 필터가 없습니다. |
| **삽입 모드** | **로어 블록 안** 또는 **사용자 프롬프트 앞**입니다. [순서와 삽입](#order-and-insertion)을 참고하세요. |
| **Activation Context** | 필터를 어디에서 찾을지 정합니다. **지시문**(파트에 대한 요청, 기본값) 또는 **지시문과 이야기의 파트**입니다. [이야기 안을 살펴보기](#looking-into-the-story)를 참고하세요. |
| **파트** | *지시문과 이야기의 파트*를 선택했을 때, 요청과 함께 검색할 가장 최근 이야기 파트의 개수를 정합니다. 최소 1입니다. |
| **시작 메시지** | 이 번호 이상의 파트에서만 항목을 사용합니다. [항목을 일부 파트로 제한하기](#limiting-an-entry-to-some-parts)를 참고하세요. 비어 있으면 처음부터입니다. |
| **To message** | 이 번호 이하의 파트에서만 항목을 사용합니다. 비어 있으면 끝까지입니다. |
| **조건** | 항목을 사용하려면 참 값을 내야 하는 템플릿입니다. [항목의 조건](#a-condition-for-an-entry)을 참고하세요. 비어 있으면 조건이 없습니다. |
| **제외 태그** | 항목을 끄는 태그입니다. [태그](#tags)를 참고하세요. |
| **요약에서도 검색** | 선택하면, 필터를 이야기의 지금까지의 [요약](../books/summaries.md) 중 다음 요청에 전송될 요약에서도 찾습니다(이야기와 더 이상 맞지 않는 요약은 제외됩니다). 필터가 있어야 합니다. |
| **이 항목의 내용에서 다른 항목을 검색하지 않음** | 선택하면, 이 항목의 내용에 있는 단어가 다른 항목을 불러오지 않습니다. [다른 항목이 불러오는 항목](#entries-brought-in-by-other-entries)을 참고하세요. |
| **다른 항목을 통해서만** | 선택하면, 요청이나 이야기 자체 때문에는 항목을 절대 사용하지 않습니다. 사용된 다른 항목의 내용에서 이 항목의 필터가 발견될 때만 사용합니다. [다른 항목이 불러오는 항목](#entries-brought-in-by-other-entries)을 참고하세요. |
| **메모** | 메모입니다. 모델에는 전송되지 않습니다. SillyTavern에서 가져온 항목은 여기서 가져올 수 없었던 설정을 나열합니다. |

내용은 모델이 읽기를 바라는 대로 작성하세요. 짧고 사실에 기반한 설명이 가장 잘 작동합니다.

> **Captain Varro** - 오스트라 항구 경비대의 지휘관, 50대, 왼손에 흉터가 있음. 공작에게 충성하며 마법사 길드를 불신함. 짧고 끊어지는 문장으로 말함.
<a id="activation"></a>

## 활성화

Marginalia는 생성되는 파트마다 전에 책의 로어북과 그 [하위 로어북](lorebooks.md#sub-lorebooks)의 항목들을 살펴봅니다. 항목은 다음의 경우에 **활성화**됩니다:

1. 항목이 켜져 있고, 그 로어북도 켜져 있다;
2. 지금 쓰이는 파트가 항목의 파트 범위 안에 있다 (범위가 있는 경우, **시작 메시지**, **끝 메시지**);
3. **제외 태그** 중 어느 것도 책의 태그가 아니다;
4. 항목에 태그가 없거나, 태그 중 적어도 하나가 책의 태그이다;
5. **조건**이 있다면 그 조건이 참이다. 자세한 내용은 [항목의 조건](#a-condition-for-an-entry)을 보십시오;
6. 필터가 없거나, 필터가 해당 파트의 지시문과 일치한다 (또는 **활성화 맥락**이 *지시문과 이야기의 파트*이면 지시문과 이야기의 최신 파트들과 일치한다).

모든 조건이 성립해야 합니다. 태그와 필터가 없는 항목은 언제나 활성화됩니다.

<a id="tags"></a>

### 태그

태그는 항목을 **책 태그**(책의 [정보](../books/managing-books.md#the-about-tab) 탭에서 설정)와 연결합니다. 서로 다른 부분이 필요한 책들이 하나의 로어북을 공유하고 싶을 때 사용하십시오:

| 항목 태그 | 제외 태그 | 다음 태그가 달린 책에서 활성화됨 |
|---|---|---|
| - | - | 항상 |
| `winter` | - | `winter` |
| `winter`, `book-2` | - | `winter` **또는** `book-2` |
| - | `book-1` | `book-1`이 아닌 모든 책 |
| `winter` | `book-1` | `winter`이면서, `book-1`도 아닌 경우 |

태그는 정확히 일치해야 합니다. 제외 태그는 항상 태그보다 우선합니다.

태그는 로어북 전체에도 줄 수 있습니다([로어북](lorebooks.md)의 **태그** 필드; 파일에서 가져온 로어북에는 태그가 있을 수 있습니다). 이 경우 태그는 로어북의 모든 항목에 붙은 것으로 간주됩니다.

<a id="filters"></a>

### 필터

필터는 **파트를 위한 요청**에 항목이 언급될 때만 항목을 활성화합니다. 필터는 파트가 전송될 때의 [사용자 프롬프트](../books/prompts.md#user-prompt)와 맞춰 확인합니다. 즉 사용자 프롬프트 템플릿의 문구 안에 들어간 *장면 배경*, *시점 인물*, *등장인물*, *지시문*을 기준으로 합니다.

| 모드 | 일치하는 경우 |
|---|---|
| **키워드 (하나라도)** | 필터가 쉼표로 구분된 키워드 목록입니다(`Varro, Ostra`). 요청에 그중 하나라도 들어 있으면 일치합니다. 대소문자는 무시하며, 키워드 앞뒤의 공백도 무시합니다. |
| **키워드 (모두)** | 같은 목록이지만, 요청에 모든 키워드가 들어 있어야 합니다. |
| **텍스트** | 요청의 어디에든 해당 텍스트가 나타나면 일치합니다. 대소문자는 무시합니다. `varro`는 *Captain Varro*와 일치합니다. |
| **정규식** | [정규 표현식](../regular-expressions.md#in-a-lorebook-entry-filter)이 요청의 어디에서든 일치하면 됩니다. 대소문자를 무시하며, 줄을 넘어서도 일치합니다. |

예를 들어, 정규식 `\b(varro|captain)\b`는 단어 *Varro* 또는 *Captain*과 일치하고, `varro.*(harbor|docks)`는 Varro와 항구(harbor 또는 docks)가 이 순서대로 모두 언급될 때만 일치합니다.

!!!warning 기본적으로 필터는 이야기가 아니라 요청을 봅니다
항목이 이야기 내용을 살펴보도록 설정되어 있지 않다면([이야기 살펴보기](#looking-into-the-story) 참고), 필터는 새 파트의 지시문만 확인하고 이전 파트의 본문은 확인하지 않습니다. Varro에 관한 항목은 여러분이 작성하는 파트의 장면, 등장인물 또는 지시문에서 Varro가 언급될 때 활성화됩니다. 그가 장면에 나온다면 *등장인물*에 넣으십시오.

요청에는 사용자 프롬프트 템플릿의 문구도 포함됩니다. 템플릿이 사용하는 단어(기본 템플릿에는 *characters*, *plot*, *tone* 등이 있습니다)에 대한 필터는 항상 활성화됩니다.
!!!

잘못된 정규 표현식은 결코 일치하지 않으며, 그 항목은 비활성 상태로 남습니다.

태그와 필터를 함께 사용하면, 일부 책에서만, 그리고 관련이 있을 때만 항목을 쓰도록 할 수 있습니다.

<a id="looking-into-the-story"></a>

### 이야기 살펴보기

기본적으로 필터는 파트를 위한 요청에서만 찾으므로, 용에 관한 항목은 *여러분이* 용을 언급할 때 사용됩니다. 이야기가 항목을 계속 활성 상태로 유지하기를 원할 때 - 용이 지난 파트에 있었고, 새 지시문은 "그는 날아간다"라고만 말하는 경우 - 항목의 **활성화 맥락**을 **지시문과 이야기의 파트**로 설정하고, **파트**에 요청과 함께 검색할 최신 파트의 개수를 입력하십시오(`1`은 쓰이는 파트 바로 앞의 파트, `2`는 그 앞의 두 파트...).

- 필터는 해당 파트들의 본문과 요청을 함께 검색합니다. 그러므로 **키워드 (모두)**의 키워드들은 그 사이에 나뉘어 있을 수 있습니다. 요청은 언제나 포함됩니다.
- 파트의 본문만 검색하며, 요약은 검색하지 않습니다. 또한 여러분이 쓰고 있는 가지의 파트만 검색합니다(스와이프나 재생성은 자신이 대체하는 파트를 검색하지 않습니다).
- 이야기가 **파트**보다 짧으면 전체를 검색합니다. Marginalia는 켜져 있는 항목에 필요한 만큼만 파트를 읽으므로, 그런 항목이 없는 로어북은 이야기에 전혀 접근하지 않습니다.
- [다른 항목이 가져온 항목](#entries-brought-in-by-other-entries)은 이야기에서 찾지 않고, 사용된 항목들의 내용에서만 찾습니다.

<a id="limiting-an-entry-to-some-parts"></a>

### 항목을 일부 파트로 제한하기

어떤 설정은 이야기의 일부 파트에서만 참입니다. 예를 들어 5장에서 드러나는 인물의 변장이나, 전쟁이 시작되기 전의 소문 같은 것입니다. 이야기의 개요가 매긴 번호대로 파트 번호를 **시작 메시지**와/또는 **끝 메시지**에 입력하십시오(첫 파트는 `1`; 두 번호 모두 포함됩니다). 그러면 항목은 쓰이는 파트의 번호가 범위 안에 있을 때만 사용되며, 필터가 무엇이라고 하든 상관없습니다. 필터가 없는 항목은 범위 안에서만 항상 활성화됩니다.

- 빈 칸은 제한이 없다는 뜻입니다. **시작 메시지**에만 `10`을 넣으면 "10번 파트부터"이고, **끝 메시지**에만 `4`를 넣으면 "4번 파트까지"입니다.
- 쓰이는 파트는 가지의 마지막 파트 다음입니다(파트가 9개인 이야기는 `10`번 파트를 씁니다). 스와이프나 재생성은 자신이 대체하는 파트를 씁니다.
- 텍스트가 없는 파트도 개요에서와 마찬가지로 번호에 포함됩니다. 파트를 삭제하거나 삽입하면 번호가 바뀝니다.
- **시작 메시지**가 **끝 메시지**보다 크면 항목은 결코 사용되지 않습니다.
- 범위 밖에 있는 항목은 [다른 항목이 가져오는 경우](#entries-brought-in-by-other-entries)에도 가져와지지 않습니다.
- [로어북 VCS](../extensions/index.md) 확장 기능은 항목의 버전에 범위를 보존하며, 로어북의 가져오기, 내보내기, 복제도 범위를 유지합니다.

<a id="a-condition-for-an-entry"></a>

### 항목의 조건

**조건**은 [항목의 내용](#templates-in-entries)과 같은 방식으로 작성되는 템플릿이며, Marginalia는 파트마다 이를 렌더링합니다. 결과가 **참**일 때만 항목이 사용됩니다. 빈 결과, `0`, `false`, `no`, `off`(대소문자 무관)를 제외한 모든 값이 참입니다. 조건은 내용과 같은 것들을 봅니다: 시점 인물, 등장인물, 장면, 해당 차례의 지시문, 지금까지의 이야기, 그리고 변수.

![조건이 있는 항목: Tomáš가 시점 인물이고 Mizuki가 등장할 때만 항목이 사용됨](../../images/lorebook-condition.png)

| 조건 | 항목이 사용되는 경우 |
|---|---|
| `{%{{{#if presentCharacters}}yes{{/if}}}%}` | 해당 차례에 등장인물이 있는 경우 |
| `{%{{{eval::povCharacter == "Fiora"}}}%}` | 시점 인물이 Fiora인 경우 (see [식](../templates/macros.md#expressions)) |
| `{%{{{eval::povCharacter == "Fiora" and presentCharacters has "Mara"}}}%}` | Fiora가 시점 인물이고 Mara가 등장하는 경우 |
| `{%{{{getvar::revealed}}}%}` | 변수 `revealed`에 값이 있는 경우 (앞선 파트에서 설정됨, see [매크로 참조](../templates/macros.md#variables)) |
| `{%{{{command::authors-note}}}%}` | [명령](../commands/index.md)이 무언가를 답하는 경우 (매크로용으로 만들어진 명령만 사용할 수 있습니다) |

작동 방식:

- 조건은 켜짐 스위치, 파트 범위, 태그를 확인한 뒤, **필터보다 먼저** 확인됩니다. 따라서 조건이 거짓인 항목은 필터가 일치하더라도 사용되지 않으며, [다른 항목이 가져오는 경우](#entries-brought-in-by-other-entries)에도 가져와지지 않습니다.
- **판단할 수 없는** 조건은 거짓으로 취급되며, [미리보기](#preview-activation)에 그 이유가 표시됩니다. 유효하지 않은 템플릿이거나, 존재하지 않는 이름(오타)을 사용하거나, 존재하지 않거나 매크로용이 아닌 명령을 사용하거나, 시간이 초과된 경우입니다. 앞의 두 경우에는 입력하는 동안 필드가 빨갛게 표시됩니다.
- 조건은 읽기만 합니다. 조건 안의 `{%{{{setvar}}}%}`은 프롬프트에도 다른 항목에도 아무 변화를 주지 않으며, 사용되는 명령도 읽기 전용 명령뿐입니다.
- 조건은 항목과 파트마다 한 번씩만 렌더링되므로, `{%{{{random::yes::no}}}%}`는 첫 번째 패스와 스캔 깊이의 패스들 사이에서 결과를 바꾸지 않습니다.
- [미리보기](#preview-activation)는 조건이 거짓인 항목을 *사용 안 됨: 조건이 거짓임*으로 표시합니다.

  ![활성화 미리보기: Mizuki의 항목은 조건이 거짓이므로 사용되지 않음](../../images/lorebook-condition-preview.png)
- 한 파트의 모든 조건은 **60초**를 함께 씁니다. 시간이 다 되면 남은 조건들은 거짓으로 간주됩니다(*condition failed*, 시간 초과). 실행 중인 조건은 중단되지 않으며, 시간은 다음 조건을 시작하기 전에 확인됩니다.
- 로어북의 가져오기와 내보내기, 복제, 그리고 로어북 VCS 확장 기능은 조건을 유지합니다.

<a id="entries-brought-in-by-other-entries"></a>

### 다른 항목이 가져온 항목

보통은 파트를 위한 요청만이 항목을 활성화합니다. [로어북](lorebooks.md#the-lorebook-editor)의 **스캔 깊이** 필드에 값을 주면(`0`은 기본값이며 이 기능을 끕니다) 활성화되지 않은 항목의 필터를 찾기 위해, 활성화된 항목들의 내용을 요청의 일부인 것처럼 검색합니다. 필터가 거기서 발견되는 항목도 활성화됩니다. 이것이 **패스 1**입니다. 그다음 패스 1에서 활성화된 항목들의 내용을 패스 2에서 검색하며, 스캔 깊이가 말하는 만큼(최대 5회) 계속합니다.

예를 들어 스캔 깊이가 `1`이면, 요청으로 항목 *Captain Varro*(필터 `varro`)가 활성화되고, 그 내용에 "...Ostra 공작을 섬긴다"라고 적혀 있을 때, 요청은 도시를 전혀 언급하지 않았는데도 항목 *Ostra*(필터 `ostra`)가 활성화됩니다. 스캔 깊이가 `2`이면, 항목 *Ostra*가 다시 그 안에서 언급되는 항구에 관한 항목을 가져옵니다.

- **필터**만 셉니다. 필터가 없어서 이미 사용 중인 항목은 아무것도 필요하지 않으며, 꺼져 있거나 태그 때문에 제외된 항목은 가져와지지 않습니다.
- 검색되는 내용은 작성된 그대로의 항목 본문이며, 그 안의 템플릿은 실행되지 않습니다.
- 로어북의 **스캔 깊이**는 **책이 사용하는** 로어북의 것으로, 그 로어북 자신의 항목과 하위 로어북의 항목에 적용됩니다. 하위 로어북은 자신만의 깊이를 가질 수 있습니다(설정의 **하위 로어북으로서의 스캔 깊이**; 비워 두면 책이 사용하는 로어북의 깊이를 따릅니다). 그 항목들은 다른 항목의 내용으로 그 깊이까지의 패스에서만 찾아지며, `0`이면 결코 찾아지지 않습니다. 만들어지는 패스 수는 가장 큰 깊이만큼입니다. 하위 로어북의 필드는 그것이 하위 로어북인 동안에만 적용되며, 책이 그것을 직접 사용할 때는 일반 **스캔 깊이**가 적용됩니다.
- **다른 항목을 통해서만 검색하지 않음**이 체크된 항목은 활성화될 수 있지만, 다른 항목을 가져오지는 않습니다.
- **다른 항목을 통해서만** 체크된 항목은 요청으로는 결코 찾아지지 않으며, 사용된 항목의 내용이 그 필터를 포함할 때만 사용됩니다. 스캔 깊이가 없거나 필터가 없으면 결코 사용되지 않으며, [미리보기](#preview-activation)에는 *사용 안 됨: 다른 항목의 내용을 통해서만 사용됨*이라고 표시됩니다.
- 프롬프트에서의 순서는 항목이 어떻게 찾아졌는지에 따라 달라지지 않습니다. [순서와 삽입](#order-and-insertion)을 보십시오.
- 사용되는 항목을 바꾸는 확장 기능([확장 기능](../extensions/index.md) 참고)은 가져와진 항목에 대해서도 질문을 받습니다.
<a id="preview-activation"></a>

## 미리 보기 활성화

**활성화 미리 보기**(로어북 편집기 도구 모음의 눈 모양 버튼, 휴대폰에서는 검색 및 바꾸기 버튼 옆)는 아무것도 생성하지 않고 "이 텍스트에 어떤 항목이 사용될까?"라는 질문에 답합니다. **턴의 텍스트**에 요청 텍스트(장면, 등장인물, 지시 사항 등 실제로 입력할 내용)를 입력하면, 표에 로어북과 하위 로어북의 모든 항목이 사용되는 순서대로 나타납니다.

- 사용될 항목에는 초록색 체크 표시, 나머지에는 회색 표시가 붙습니다.
- 항목이 속한 로어북, 해당 **순서**, **통과**(텍스트가 활성화한 항목은 비어 있고, [다른 항목이 끌어들인 항목](#entries-brought-in-by-other-entries)은 `1`, `2`... 로 표시됩니다)가 나옵니다.
- **사유**: 필터 없음, 텍스트에서 필터를 찾음, 다른 항목의 내용에서 필터를 찾음(필터와 해당 항목 표시), 또는 사용되지 않는 이유가 표시됩니다. 사용되지 않는 이유는 꺼져 있음, 부분이 허용 범위 밖임, 책의 부정 태그, 책에 항목의 태그가 없음, 조건이 거짓이거나 판단할 수 없음, 필터를 찾지 못함 중 하나입니다.

태그도 결정에 영향을 줍니다. 책의 태그를 사용하려면 **책의 태그**에서 책을 선택하세요(선택하지 않으면 태그는 전혀 고려되지 않습니다). 이 책은 [story를 살펴보는](#looking-into-the-story) 항목이 참조할 이야기 부분도 제공하고(선택하지 않으면 텍스트만 검색합니다), [특정 부분으로 제한된 항목](#limiting-an-entry-to-some-parts)을 위해 다음 부분의 번호도 제공합니다(선택하지 않으면 범위를 확인하지 않습니다). 입력한 텍스트는 [조건](#a-condition-for-an-entry)에 쓰이는 턴의 지시 사항이 되며, 책을 선택한 경우에는 그 책의 변수, 시점, 현재 등장인물, 마지막 부분의 장면도 함께 사용됩니다(미리 보기에서는 조건의 명령을 실행하지 않습니다). 텍스트 아래 줄에는 몇 개의 항목이 사용될지와 로어의 대략적인 토큰 수가 표시됩니다. 로어북의 스캔 깊이도 적용됩니다.

[전체 화면 편집기](lorebooks.md#editing-in-full-screen)에서는 모든 항목 탭의 이름 줄에도 눈 모양 버튼이 있습니다. 이 버튼을 누르면 해당 항목에 대한 미리 보기가 열리고 그 항목의 행이 선택되며, 표 위의 한 줄에 그 항목이 사용될지와 그 이유가 표시됩니다. 입력하는 동안 이 줄도 바뀝니다. 탭에서 필터를 바꾼 뒤 미리 보기에서 **새로 고침**을 누르면 결과를 확인할 수 있습니다.

![로어북의 활성화 미리 보기](../../images/lorebook-preview-activation.png)

미리 보기는 Marginalia의 규칙만 적용합니다. 텍스트는 사용자 프롬프트 템플릿이 아니라 직접 입력한 내용이며, 부분이 생성되는 동안 [확장 기능](../extensions/index.md)이 바꾸는 내용은 포함되지 않습니다.

<a id="order-and-insertion"></a>

## 순서와 삽입

활성화된 항목은 **순서**가 낮은 것부터 정렬되어 프롬프트에 들어갑니다. 순서가 같은 항목은 생성된 순서를 유지합니다. 포함된 모든 로어북의 항목이 함께 정렬됩니다.

**삽입 모드**는 항목이 들어갈 위치를 정합니다.

| 모드 | 위치 |
|---|---|
| **로어 블록 안** | [마스터 템플릿](../books/prompts.md#master-template)의 `{%{{{backgroundLore}}}%}` 블록에 들어갑니다. 기본 템플릿에서는 시스템 메시지의 *World & lore context*입니다. 배경 지식에 사용하세요. |
| **사용자 프롬프트 앞** | 부분을 요청하는 문장 바로 앞, 프롬프트 끝에 들어갑니다. 모델이 가장 주의를 기울이는 위치입니다. 이번 부분에 반드시 영향을 주어야 하는 내용(등장인물의 현재 상태, 장면의 규칙 등)에만 아껴서 사용하세요. |

항목들은 빈 줄로 구분됩니다. 로어도 [컨텍스트 한도](../protocols.md#limits)에 포함되므로, 길이가 긴 항목이 많으면 프롬프트에 들어가는 이야기의 양이 줄어듭니다.

<a id="templates-in-entries"></a>

## 항목의 템플릿

항목의 내용은 [책 프롬프트](../books/prompts.md#templates)와 같은 템플릿입니다. 다음을 사용할 수 있습니다.

| 변수 | |
|---|---|
| `{%{{{sceneSetting}}}%}`, `{%{{{povCharacter}}}%}`, `{%{{{presentCharacters}}}%}`, `{%{{{instructions}}}%}` | 부분의 지시 사항입니다. |
| `{%{{{narrativePov}}}%}`, `{%{{{narrativeTense}}}%}`, `{%{{{style}}}%}` | 책의 서술 설정입니다. |

그리고 모든 [매크로](../templates/macros.md)를 사용할 수 있습니다. 예를 들어, 시점 인물에 맞춰 달라지는 항목은 다음과 같습니다.

{%{
```handlebars
Varro {{#povCharacter}}is seen through the eyes of {{.}}: {{/povCharacter}}a stern, scarred officer.
```
}%}

한 부분에서 활성화된 모든 항목은 활성화 순서대로 변수를 공유합니다. 어떤 항목이 `setvar`로 값을 설정하면, 순서상 뒤에 오는 항목과 마스터 템플릿이 `getvar`로 그 값을 읽을 수 있습니다.

내용에 문법 오류가 있으면 필드 아래에 표시됩니다. 항목은 그대로 저장되지만, 고칠 때까지는 템플릿 처리 없이 내용이 일반 텍스트로 사용됩니다.

<a id="tips"></a>

## 팁

- 항목은 짧고 사실 위주로 쓰세요. 모델에게 필요한 것은 산문이 아니라 사실입니다.
- 인물, 장소, 개념마다 항목 하나를 두면 각각 단독으로 활성화할 수 있습니다.
- 세계의 핵심에는 항상 활성화되는 항목을, 등장인물과 장소에는 필터를, 로어북을 책끼리 공유하려면 태그를 사용하세요.
- 생성된 부분에서 **프롬프트 보기**를 눌러 무엇이 활성화되었는지 확인하거나, 글을 쓰기 전에 [활성화 미리 보기](#preview-activation)로 텍스트를 시험해 보세요.
- 스캔 깊이는 아껴서 사용하세요. 대부분의 책에는 한 번의 스캔으로 충분하며, 스캔을 한 번 더 할 때마다 원하지 않던 로어가 더 많이 들어올 수 있습니다.
