# ロア生成

モデルに[ロアブックのエントリ](../lorebooks/entries.md)の内容を書いてもらいます。既存のロアを読み取るので、新しいエントリは世界観に合った内容になります。また、結果はロアエントリに最も適した、短く濃密な形にまとめられます。

!!!
ロア生成は[電話用レイアウト](../phone.md#extensions)でも使えます。エントリの行に魔法の杖ボタンがあり、ウィンドウでは上にプロンプト、下に結果が表示されます。
!!!

<a id="opening-the-generator"></a>

## 生成ツールを開く

拡張機能をインストールすると、ロアブックエディタの各行に魔法の杖ボタン (**Generate lore entry**) が表示されます。これを押すと、そのエントリ用の生成ツールが開きます。エントリにすでに内容がある場合、ダイアログの上部にその旨が表示されます。結果をエントリにコピーすると、内容は置き換えられます。

[全画面エディタ](../lorebooks/lorebooks.md#editing-in-full-screen)にも魔法の杖があります。エントリ一覧の各行と、エントリタブの名前の行にある **Generate lore entry** です。エントリに書き込んだ内容は、すぐにそのタブに表示されます。ブック(その *Lorebook* タブ、またはストーリーのロアブックタブ)から開いた場合、エディタはそのブックを認識しているので、ロアブックのページと同じくブックがモデルの費用を負担します。

生成ツールは、*設定*の **既定のモデル** と **既定のプロトコル** から始まります。詳細は[アカウントと設定](../account.md)を参照してください。ダイアログのヘッダー下にある **モデル** と **プロトコル** のリストで、この生成だけ別のモデルやプロトコルを使えます(選択内容は保存されません)。プロトコルは任意です。モデルが選ばれていないと警告が表示されるだけです。

![ロア生成ツール](../../images/plugin-loregenerator.png)

<a id="what-the-model-sees"></a>

## モデルに渡される内容

ダイアログ上部の2つの選択肢で、リクエストに含めるロアが決まります。

| 選択肢 | |
|---|---|
| **Current Lorebook** (既定) / **All Lore** | エントリが属するロアブックのエントリだけを渡します([サブロアブック](../lorebooks/lorebooks.md)は除外)。または、そのロアブックのエントリに加えて、すべてのサブロアブックのエントリを渡します。 |
| **Only up to position (n)** (既定) / **All entries** | *n* はエントリの順序です。そのエントリより前にあるエントリだけを表示します(順序が小さいもの、または順序が同じで先に作成されたもの)。これにより、モデルは既存の内容を土台に書き、エントリより後に書かれたロアは渡されません。*All entries* はすべてのエントリを表示します。 |

生成対象のエントリは、内容があってもなくても含まれません。他のエントリやロアブックが有効かどうか、そのタグやフィルタ、挿入モードは無視されます。ここで選んだものがそのまま送られ、エントリがプロンプトに挿入される順序で並びます。エントリのテンプレートは通常どおり処理されます。

<a id="prompts"></a>

## プロンプト

生成プロンプトは、モデルに書いてほしい内容を指示する文章です。プロンプトは、選択肢の隣にある同じ上段の箱に一覧表示されます。選択中のプロンプトの本文は左側のテキストエリアにあり、保存せずにその回の生成だけ変更できます。ダイアログの左右の区切りはドラッグで動かせます。

| ボタン | |
|---|---|
| **Save** | 選択中のプロンプトを、その名前で保存します。 |
| **Save as** | 名前を入力すると、本文を新しいプロンプトとして保存します(同名のものがあれば、確認のうえ置き換えます)。 |
| **Delete** | 選択中のプロンプトを削除します。最後の1つを削除すると、組み込みの `DEFAULT` プロンプトが戻ります。 |

組み込みのプロンプトには、角括弧で囲まれたプレースホルダー(題材、含める詳細、長さ、構成)があります。実行する前にそれらを埋めてください。プロンプトはアカウントに属し、最後に使ったものは次回ダイアログを開いたときに再び選ばれています。

<a id="generation-and-compaction"></a>

## 生成と圧縮

右側には2つのタブがあります。

**Generation** - **Run Generation** を押すと、ロアに続けて生成プロンプトが送られます。回答は書かれながら順に表示され、モデルが推論を示す場合はその内容が上の *Thinking Process* セクションに表示されます。**Stop** (*Run Generation* の代わりに表示) を押すと途中で終了します。それまでに書かれた内容は残ります。

**Compaction** - 生成結果ができると使えます。**Run Compaction** を押すと、同じロアに続けて、生成されたテキストを含む圧縮プロンプトが送られ、モデルがそれを簡潔なエントリにまとめます。圧縮プロンプトは *設定 → 拡張機能の設定 → Lore Generator* で指定します。空の場合は組み込みのものが使われます(地の文を取り除き、事実を残すものです)。生成をもう一度実行すると、圧縮結果は破棄されます。

![生成したエントリの圧縮](../../images/plugin-loregenerator-compaction.png)

モデルが作業している間は、**Stop** 以外のすべての操作が無効になります。ダイアログを閉じることもできません。

<a id="remembered-per-entry"></a>

### エントリごとに記憶される設定

**Copy to Lore Entry** を押すと、その生成のオプションがエントリとともに保存されます。保存されるのは、プロンプトの本文、どの保存済みプロンプトから来たか、ロアとエントリの選択、チェックされた名前のカテゴリです。そのエントリの生成ツールを再び開くと、これらが復元されます。直前に使ったプロンプトや保存済みの名前カテゴリより優先されます。一度も生成結果を書き込んでいないエントリは、通常の既定値で開きます。オプションはエントリに属するので、ロアブックのバックアップやエクスポートにも一緒に含まれます。

<a id="tools"></a>

### ツール

[モデル用のツール](tools.md)のスイート([名前ジェネレーター](name-generator.md)または[名前プロバイダー](name-provider.md)の名前、[場所プロバイダー](place-provider.md)の場所)がインストールされていると、上段に **Tools** ボタンが表示されます。これを押すと、モデルが使ってよいスイートと、カテゴリを持つスイートではそのカテゴリを選ぶウィンドウが開きます。動作の仕組みは[モデル用のツール](tools.md)を参照してください。何かがチェックされている間、モデルは生成中(圧縮中は除く)にツールを呼び出せます。各スイートについてモデルが受け取るヒントは、生成プロンプトの末尾に追加されます。この選択はアカウントとエントリの両方に保存されます。

<a id="attachments"></a>

### 添付ファイル

プロンプトの下には、モデルに見せるファイルを追加できます。参考画像、地図、キャラクターシートなどです。アップロード領域にドロップする、選んで追加する、またはプロンプトに Ctrl+V で貼り付けることができます(スクリーンショットやコピーしたファイルは添付になり、貼り付けたテキストは通常どおり挿入されます)。1つあたり20 MBまでです。名前、種類、サイズとともに一覧表示され、ゴミ箱ボタンで1つずつ削除できます。添付は生成時に送られ、圧縮時には送られません。追加と削除は、生成が動いていないときだけできます。

モデルがそれらを利用できるかどうかは、モデルと[推論プロバイダー](../inference-providers.md)によって決まります。画像は画像として送られ、音声はWAVまたはMP3のみ、その他のファイルはファイルとして送られます。プロバイダーが添付を拒否した場合はメッセージが表示され、何も生成されません。

<a id="copying-the-result"></a>

## 結果のコピー

**Copy to Lore Entry** は、圧縮に結果があるときに使えます。圧縮されたテキストがエントリの **content** (内容)になり、圧縮前の生成テキストがその **note** (メモ)に入ります。どちらも置き換えられます。圧縮結果が1つのコードブロックだけの場合(組み込みプロンプトは、コピーしやすくするためにそう指定しています)、その周りのコードブロックは取り除かれます。ロアブックは更新され、ダイアログは開いたままになります。閉じるには **終了** を押してください。
<a id="commands"></a>

## コマンド

ジェネレーターはダイアログを使わなくても動作し、コマンドラインと[エージェント](../commands/index.md)向けに3つの[コマンド](../agents.md)として提供されています。ダイアログと同じ2つの手順を実行しますが、ダイアログと同様に何も保存しません。テキストを返すだけで、それをエントリに入れる作業（**Copy to Lore Entry** が行うこと）は呼び出し元に任されるため、3つのコマンドはいずれも読み取りのみです。ロアブックとエントリは、`/list-lorebooks` や `/list-lore-entries` と同じように番号で指定します。モデルはデフォルトのモデルとプロトコルが使われます。

| コマンド | 機能 |
|---|---|
| `/list-lore-templates [template]` | 保存済みの生成プロンプトの一覧（名前、長さ、テキストの冒頭）と、最後に使われたものを表示します。名前を指定すると、そのプロンプトのテキスト全体を返します。 |
| `/generate-lore-entry [prompt [template [lorebook [entry [order [scope [limit [images [compact]]]]]]]]]` | ロアブックのロアからテキストを生成し、それを圧縮し（`/compact-lore-entry` と同様）、圧縮後のテキストを返します。`compact` を `false` にすると、生成されたテキストをそのまま返します。送信されるテキストは、テンプレートの後に呼び出し元のプロンプトが続く形です（後述）。`images` を指定すると、ダイアログの添付画像と同様に、モデルが画像も参照します。 |
| `/compact-lore-entry text [lorebook [entry [order [scope [limit]]]]]` | 同じロアを使ってテキストを圧縮し、結果を返します。その際、周囲のコードブロックは付けません。 |

テキストの対象となるエントリによって、モデルが参照するロアが決まります。`entry` にエントリのハンドルまたは番号を指定してください（番号で指定する場合は、そのエントリが属する `lorebook` もハンドルまたは番号で指定します）。ロアはダイアログの場合と同じになります。`limit` が `UP_TO_POSITION`（デフォルト）の場合は、そのエントリより前のエントリが対象となり、エントリ自体は含まれません。まだ存在しないエントリには番号がないため、代わりに付与される `order`（`/list-lore-entries` の `order`。小さい値ほど先頭になります）を指定してください。その場合、モデルはその `order` より前のエントリを参照します。どちらも指定しない場合は、そのテキストは他のすべてのエントリの後に続く新規エントリ向けに書かれます。`scope` は `CURRENT_LOREBOOK`（デフォルト）または `ALL_LORE`、`limit` は `UP_TO_POSITION` または `ALL_ENTRIES` で、ダイアログと同じです。

生成結果はプロンプトの質に左右されるため、このコマンドは常に保存済みの生成プロンプト（[プロンプト](#prompts)を参照）のいずれかから始まります。`template` で指定したもの、または名前を指定しない場合は最後に使われたものです。呼び出し元の `prompt` は、その後に *Task for this entry* という見出しの下に続きます。ここには、テンプレートが求める題材、事実、長さ、セクションなどを書きます。`template` に `none` を指定すると、プロンプトだけを送信します。これは、呼び出し元がプロンプト全体を自分で書いた場合に使います（例えば、`/list-lore-templates` でテンプレートのテキストを取得し、それを編集した場合など）。テンプレートを指定してプロンプトを指定しなかった場合は、テンプレートだけが送信されます。

`/generate-lore-entry` の `images` は、ダイアログが生成に添付する画像と同じものです。[エージェント](../agents.md)は、そのワークスペースにある画像ファイルのパスのリストを渡します（`/refs/map.png` のように、最大8件、PNG、JPEG、GIF、WebP。大きい場合は縮小されます）。これらの画像は、Workspace タブの **Upload file** でアップロードしておきます。コマンドバーには画像を名前で指定する方法がないため、`images` はエージェント向けです。画像を参照するのはデフォルトのモデルです。画像に対応していない場合、コマンドは失敗してその旨を伝えます。ダイアログと同様に、画像を扱うのは生成のみです。圧縮はテキストだけを対象に行われます。

`/generate-lore-entry` の `compact` パラメーターは、デフォルトで `true` です。コマンドは生成と圧縮を1回の呼び出しで行うため、[エージェント](../agents.md)は1つのコマンドで済み、2つ目の手順を忘れることがありません。長い生成テキストを受け取りたい場合（例えば、確認や編集をするため）は、`compact` を `false` に指定し、後から `/compact-lore-entry` を実行してください。

ここではモデルにツールは与えられません。名前が必要な場合は、呼び出し元が先に [名前ジェネレーター](name-generator.md) の `/generate-names` または [名前プロバイダー](name-provider.md) の `/pick-real-names` で名前を取得し、気に入ったものをプロンプトに書き込んでください。エージェントは、`/list-lore-templates` でテンプレートのテキストを取得し、それを変更して、結果をプロンプトとして渡すこともできます。

<a id="storage"></a>

## ストレージ

プロンプトと圧縮用プロンプトは、設定とともに保存されます。そのため、[データベースのバックアップ](../administration/database-backups.md)にも含まれます。ロアブックと一緒に保存されるものはありません。生成されたテキストは、コピーするまでダイアログ内にのみ存在します。
