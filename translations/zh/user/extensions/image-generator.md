# 图像生成器

为故事的某个部分生成一张图像。模型根据该部分写出图像提示词，你进行编辑，图像后端绘制图片，你可以反复重新生成，直到满意后接受它。接受后，它就成为该部分的一张图像，与你用部分菜单中的 *图像* 手动添加的图像相同（它会显示在故事中，并包含在导出内容里）。

本扩展本身不生成图像：它与 **ComfyUI** 服务器或提供 **OpenAI images API** 的服务器通信（stable-diffusion.cpp、LiteLLM 以及许多托管服务也支持该接口）。

<a id="adding-a-backend"></a>

## 添加后端

*设置 → 扩展设置 → 图像生成器设置* 列出了各个后端。点击（+）添加一个，填写内容后保存 *设置* 页面。

| 设置项 | 作用 |
|---|---|
| 名称、类型 | 窗口中显示的名称。**ComfyUI** 或 **OpenAI images API**。 |
| 地址 | 服务器的基础地址，例如 `http://localhost:8188`（ComfyUI 的地址）。 |
| API 密钥 | 以 Bearer 令牌的形式发送给图像服务器。它会加密存储，且不会再次显示；输入新的密钥即可替换，或使用 **删除密钥**。 |
| 图像周围请求的密钥 | 与每个在[图像前后](#one-gpu-for-the-model-and-the-images)发出的请求一起以 `Authorization: Bearer` 头发送，前提是该请求没有自己的 `Authorization` 头，例如 LiteLLM 代理的密钥。加密存储。留空时使用 API 密钥。 |
| 模型 | 仅限 OpenAI images API：请求中的 `model`。 |
| 工作流 | 仅限 ComfyUI：在 ComfyUI 中使用 **保存（API 格式）** 保存的工作流。将 `{{prompt}}`、`{{negative}}`、`{{seed}}`、`{{width}}` 和 `{{height}}` 写在它们应当出现的位置，并在 LoRA 加载器中写入 `{{lora}}` / `{{lora_strength}}`，以便[在窗口中选择 LoRA](#choosing-a-lora)。 |
| 服务器位于本机或我的网络中 | 允许访问本地网络的地址。对于云端服务器请保持关闭：这样它就无法被诱导去调用你自己的机器。 |
| 宽度、高度 | 窗口打开时的初始值（你可以在窗口中为单张图像更改）。 |
| 提示词格式 | 语言模型为该后端编写提示词的方式，以适应其图像模型：**标签**（简短的逗号分隔短语，适用于 SDXL、Pony、Illustrious）、**描述性句子**（一段完整文字，适用于 Flux、Krea、Qwen-Image、Z-Image）或 **自由文本**，即你自己为提示词编写者提供的指令（它以所选格式的指令为起点）。在该设置出现之前创建的后端会编写标签，或者将当时设置的指令用作自由文本。内置指令使用你的[提示词语言](../account.md#prompt-language)编写，并要求以英文输出图像提示词，因为图像模型对英文的理解最好。 |
| 超时 | 等待一张图像生成的最长时间。 |
| GPU 锁 | 服务器所运行 GPU 的[GPU 锁](../administration/gpus.md)，适用于它与语言模型或其他服务器共享该 GPU 的情况；参见[单 GPU](#one-gpu-for-the-model-and-the-images)。仅当管理员设置了 GPU 锁时才会显示。 |

![设置中的一个后端](../../images/plugin-imagegenerator-settings.png)

**测试连接** 用于检查地址和密钥。

该面板还有两段可由书籍修改的文本：

- **风格** - 放在每个提示词之前：图片的外观，例如 *watercolor, soft light*（水彩，柔和光线）。提示词编写者也会获知这一设置，因此提示词不会描述另一种风格。
- **负面提示词** - 图片中不应出现的内容。以无引导（CFG 1）运行的 turbo 模型会忽略它。后端之前使用的负面提示词会在你第一次打开该面板时被沿用到这里。

你在面板中的设置即为默认值。书籍（其 *提示词* 选项卡）或[文件夹](../books/folders.md)可以在 *扩展设置 → 图像生成器* 下设置自己的值；书籍使用自己的设置，否则使用最近的文件夹的设置，再否则使用你的默认设置。

<a id="making-an-image"></a>

## 生成图像

![部分菜单中的生成图像](../../images/plugin-imagegenerator-menu.png)

1. 在某个部分的菜单中选择 **生成图像**。此时尚未向模型发送任何内容：先填写提示词编写者应遵循的内容，然后点击 **用模型编写提示词**（或在 *详情* 中按 <kbd>Ctrl+Enter</kbd>）。窗口中的模型（默认为书籍所用的模型，并记住你上次的选择）会为该部分编写提示词；你可以用 **中止** 停止它，修改提示词，自己编写，或重新编写。这些设置仅作用于编写提示词，不作用于图像本身：
   - **发送世界书条目** - 书籍世界书（及其子世界书）中的条目会像生成时一样发送给模型，使其了解人物和地点的外观。当某条目的过滤条件在该部分中出现时，该条目才会被发送：包括其文本、指令、场景设定、视角、在场人物，或你的*详情*中出现的内容。始终启用的条目也会被发送。只会发送模型上下文能容纳的数量（会有提示说明有多少条被省略）。该选择会被记住。
   - **详情** - 图像必须展示的内容或应有的样子（*夜晚、她的脸部特写、红色的裙子*）；提示词编写者会遵循它。它仅用于本窗口。
2. 选择后端，然后点击 **生成**。图像根据 **提示词** 生成，前面加上 **风格**，并使用 **负面提示词**；两者最初都取自书籍（或你的默认设置），对它们的更改仅用于本窗口（风格也会告知提示词编写者）。尺寸最初取自后端，可以为本窗口更改。
3. 图像随即出现。**重新生成** 会以新的种子再生成一张，**丢弃** 会将其删除，**接受** 会将其添加到该部分并关闭窗口。**中止** 会停止正在生成的图像（ComfyUI 会被告知中断该任务）。

![窗口中由模型编写的提示词](../../images/plugin-imagegenerator-prompt.png)

![图像，附带接受、丢弃和重新生成按钮](../../images/plugin-imagegenerator.png)

打开的部分会立即在其文本下方显示新图像。

窗口会记住你为每个部分所用的设置：详情、风格、负面提示词、提示词和尺寸会在提示词编写完成时以及生成时与该部分一同保存；下次在该部分上打开窗口时，会以这些设置开始。从未为某部分生成过图像的情况下，它将以书籍的风格和负面提示词开始。

<a id="choosing-a-lora"></a>

## 选择 LoRA

LoRA 是图像模型的一个小型附加组件，通常用于风格。使用 ComfyUI 时，你可以在窗口中选择它，而无需为每个 LoRA 重新保存工作流：

1. 在导出的工作流中，将 `{{lora}}` 写为 LoRA 加载器的 `lora_name`（*Load LoRA*、`LoraLoaderModelOnly` 或 `LoraLoader`），并将 `{{lora_strength}}` 写为其强度（`strength_model`；对于 `LoraLoader` 也同样写 `strength_clip`）。
2. 窗口随后会显示 **LoRA**，列出服务器上的 LoRA 文件（位于其 `models/loras` 文件夹中），以及 **LoRA 强度**。如果列表中没有你需要的文件，你也可以直接输入其文件名。
3. **无**（空的 LoRA）会从工作流中移除 LoRA 加载器，因此图像将在不使用它们的情况下生成。

你生成时使用的 LoRA 及其强度会针对该后端被记住，并在下次保留。文件列表同样如此：与 GPU 共享的服务器在窗口打开时往往尚未运行（第一张图像之前的请求会将其启动），因此窗口会提供服务器上次列出的 LoRA，并在第一张图像生成后重新请求。只有在从未能成功获取列表时，才会出现提示说明无法读取 LoRA；此时你仍可以输入文件名。
<a id="one-gpu-for-the-model-and-the-images"></a>

## 一块 GPU 同时承载语言模型和图像

显存较小的 GPU 无法同时加载语言模型和图像模型。管理员只需在 [Admin → GPUs](../administration/gpus.md) 中设置一次，即可覆盖该 GPU 上的所有模型和服务器：为语言模型和图像服务器各建立一个 **GPU lock**，并分别指定加载它的请求以及释放 GPU 的请求。在后端的 **GPU lock** 中选择图像服务器的锁（语言模型的锁则在其 [AI settings](../inference-providers.md) 中选择）。

每张图像都会依次轮流使用 GPU：

- 如果 GPU 已经加载了图像服务器，图像会立即开始生成；重新生成之间不会卸载任何内容。
- 如果 GPU 当前加载的是语言模型（或其他服务器），图像会等待模型回复完成，模型的锁释放 GPU，然后由图像服务器的锁将其加载。
- 图像之间不会保留 GPU：关闭或折叠窗口，或者让窗口保持打开，都不会占用 GPU。下一次对语言模型的请求会自动释放图像服务器占用的 GPU，在此之前图像服务器会一直保持加载状态。

窗口在轮到之前等待时会显示 *Generating the image*。

**每张图像前后的请求。** 后端还可以有两个请求列表，它们位于锁内，在每张图像前后执行：**Before each image** 和 **After each image**。释放 GPU 属于 GPU lock 的职责；这两个列表用于服务器在图像前后需要的其他操作。每个列表中的请求按顺序依次执行（**Add a request** 添加一个请求，垃圾桶图标删除一个请求）。每个请求包括：地址、方法（默认为 `POST`）、请求头（`Name: value`，每行一个）、请求体、**timeout**（留空为 60 秒，最多 600 秒）以及 **Wait afterwards**（收到回复后暂停的秒数）。请求头与 API 密钥一样加密存储。

当 *before* 列表中的某个请求失败时，后续请求不再发出，图像生成也随之停止（消息会说明是哪个请求失败，例如 *Request 2 of 3: ...*）。*after* 列表则会**完整**执行，无论其中某个请求是否失败；失败信息会写入扩展的日志，图像仍会保留。早期版本保存的单个请求的后端，会将该请求显示为列表中的第一个请求。

在 GPU 锁出现之前保存的后端，会失去 **GPU (name)** 和 **Release after idle** 设置：请改为选择一个 GPU lock，并将释放 GPU 的请求（例如卸载语言模型的 ComfyUI `POST <address>/free` 请求）移入各个锁的步骤中。
