# 故事编辑器

书的 **Story** 标签页是你写作的地方。它显示[当前分支](branches-and-story-tree.md)中从开头到结尾的各个片段。

![故事编辑器](../../images/hero-story-editor.png)

本页描述桌面端的布局。在手机上，故事是单栏显示的，大纲放在抽屉里，参见[在手机上使用 Marginalia](../phone.md#the-story)。

| 区域 | |
|---|---|
| **Outline**（左侧） | 每个片段对应一个条目，`#1`、`#2`……并附有该片段的数据库 ID。点击条目可滚动到该片段；如果它尚未加载，会先加载它之前的片段。标题显示该分支共有多少个片段。有[摘要](summaries.md)的片段，其条目后面会有一个小文档图标。[Chapter Marker](../extensions/chapter-marker.md) 扩展会在这里显示章节标题。 |
| **Lorebook**（左侧，紧挨 Outline） | 查看本书的设定，带搜索框，并可快速编辑某个条目的文本，参见 [Lorebook 标签页](#the-lorebook-tab)。 |
| **Annotations**（左侧，紧挨 Outline） | 整本书故事段落上的[注释](annotations.md)。 |
| **Planner**（左侧，紧挨 Outline） | 你计划要写的场景，是一个由你手动填写的列表，参见 [Planner 标签页](#the-planner-tab)。 |
| **Story**（中间） | 每个片段的文本，其右侧有菜单（☰）和元数据，下方是底部栏。 |
| **底部栏** | 左侧是 **Summaries** 按钮（列表图标）和设置菜单（⚙），中间是命令行，右侧是 **+** 按钮。 |

这是一本新书的样子。以上所有内容都是可以随意排列的标签页，故事本身也是，参见[调整标签页布局](#arranging-the-tabs)。侧边栏与故事之间的分隔条可以拖动，Marginalia 会记住你停放它的位置（随书保存），并在你下次打开这本书时恢复。

故事总是从底部开始显示，也就是最新的片段。长篇作品不会一次全部绘制：只加载最后的几个片段，你向上滚动时，更早的片段会加在上方，而你正在阅读的内容不会移动。另一端的片段会被移除，因此加载的片段数不会超过你[账户](../account.md)中 **Parts loaded at once in the story** 设置的值（留空则全部加载）。如果你滚动得比片段加载得快，边缘会出现一个 *Loading earlier parts*（或 *later parts*）标记，提示还有更多内容。点击大纲中的片段，或通过搜索找到某个片段，都会加载它周围的片段；开始一个新片段则会把你带回故事的结尾。

<a id="searching-the-story"></a>

### 搜索故事

大纲上方有一个搜索框，用来搜索**你所在分支**的文本（故事树的搜索会搜索所有分支）。由于长篇作品不会一次全部加载，浏览器自带的搜索（Ctrl+F）无法找到尚未加载的片段中的文本；这里的搜索可以。

- 输入要查找的内容，停止输入后搜索会自动开始。多个词必须同时出现在同一个片段中；短语请用双引号括起（`"old key"`），`*` 代表任意字符（`light*house`）。大小写不敏感。
- 每个词出现的位置都是一个匹配项，它们在整个分支中统一编号。搜索框下方会显示 *Match 3 of 27, in part #5*，以及表示当前进度的进度条。故事会滚动到该匹配项，如果它尚未加载，还会加载它周围的片段。
- **up** 和 **down** 按钮分别跳到上一个和下一个匹配项（到达最后一个后会循环回到第一个）。在搜索框中按 **Enter** 与 **down** 按钮作用相同，按 **Shift+Enter** 与 **up** 按钮作用相同。
- 已加载片段中的所有匹配项都会在文本中高亮显示，你当前所在的匹配项颜色更深。清空搜索框即可取消高亮。

在手机上，搜索位于大纲抽屉中；抽屉在显示匹配结果时会自动关闭，要查看下一个匹配项，请再次打开它。

<a id="the-lorebook-tab"></a>

### Lorebook 标签页

侧边栏的 **Lorebook** 标签页无需离开故事即可显示本书 Lorebook 中的设定，因此你不必切换标签页就能查看某个条目的内容，或修正其中的一个词。每次回到 *Story* 标签页时都会重新读取，因此你在本书的 *Lorebook* 标签页中所做的更改会立即显示。

- 顶部的**搜索框**只显示名称、内容、备注或过滤条件中包含该文本的条目（大小写不敏感）。
- 条目的**铅笔**图标会打开一个小窗口，里面有其名称、是否启用、过滤条件及其查找方式、内容和备注；点击 **Save** 即可保存。标签、顺序和激活设置需要在本书的 *Lorebook* 标签页中修改。当有代理正在处理 Lorebook 时，无法做任何更改。
- **展开按钮**（⤢）会打开[全屏 Lorebook 编辑器](../lorebooks/lorebooks.md#editing-in-full-screen)（仅限桌面端）：Lorebook 旁搜索框旁边的按钮会打开整个 Lorebook，某个条目上的按钮会打开该条目，某个子 Lorebook（启用 *Include sub lorebooks* 时）上的按钮会打开该子 Lorebook。关闭编辑器后，本标签页会重新加载。

- 每个条目是一行，显示其名称和铅笔图标。点击箭头可展开，显示其**内容**（以 Markdown 渲染）以及**激活它的文本**（即 *Filtering Text/Pattern*；如果是正则表达式，会附有说明）。
- **Include sub lorebooks** 会将 Lorebook 及其每一个子 Lorebook（及其更深层的子 Lorebook）分别显示为独立的行，各自的条目列在其下。点击某个 Lorebook 的箭头可隐藏其条目。未启用此项时，只列出本书 Lorebook 的条目。
- 已关闭（即不用于故事）的条目和 Lorebook 会显示为暗淡状态。
- 没有 Lorebook 的书会显示一条说明。

![打开了两个条目的 Lorebook 标签页](../../images/story-lorebook-tab.png)

和编辑器中的其他标签页一样，它可以被拖出，放入自己的独立面板中，参见下文。
<a id="the-planner-tab"></a>

### Planner 标签页

**Planner** 标签页是你希望故事按顺序经过的场景列表。每个场景都是写下它的那一轮的详细信息：列表中显示的**标题**、**场景设定**、**视角角色**、**在场角色**和**指令**，与新轮次表单中的四个字段相同。

![Planner 标签页，四个场景，第一个已写完](../../images/planner-tab.png)

- **Add scene** 打开一个新场景的表单，新场景会加到列表末尾。铅笔图标用于编辑场景，箭头用于上下移动场景，垃圾桶用于删除场景。
- 场景行中的 **+** 会**在该场景下方插入一个新场景**，位于该场景和下一个场景之间。
- 场景的合并按钮会**将该场景与下一个场景合并**：打开的表单中已填入两个场景的详细信息（两个标题、两个场景设定和指令上下相接、两者的在场角色，以及第一个场景的视角角色；如果第二个场景有另一个视角角色，表单会说明这一点）。修改不合适的地方，然后按 **Merge**（或 <kbd>Ctrl/Cmd+Enter</kbd>）：两个场景合并为一个，位于第一个场景的位置。只有当两个场景都已完成时，合并后的场景才算完成。
- **Import from the branch** 会为书所在分支中（从第一部分到最新部分）每个带有轮次详细信息的部分各添加一个场景，包括其场景设定、视角角色、在场角色和指令，并以指令的第一行作为标题。没有轮次详细信息的部分会被忽略，新场景排在你已有场景之后，且均未完成。用它来规划重写你已写好的故事：先导入，再合并属于一起的轮次，插入缺少的内容，然后在新分支上或书的副本中编写这些场景。
- 场景前面的方框表示该场景已**完成**（已写完）：标题加删除线，场景变暗。系统不会替你检查，写完场景后请手动勾选。列表上方的一行会统计已完成的数量。
- **点击场景**会将其详细信息填入**新轮次表单**（表单会打开，其中包含该场景的场景设定、视角角色、在场角色和指令，原有内容会被替换），你满意后按 **Generate**。在手机上，抽屉会先关闭。

场景与书一起保存，因此也包含在其备份和副本中。模型同样可以添加场景：Arc Outline 扩展的[情节向导](../extensions/arc-outline.md#developing-the-plot-in-a-conversation)以及[代理](../agents.md)可以通过[命令](../commands/index.md#the-planner)读取和修改规划器，列表会立即显示它们新增的内容。

![新场景的表单](../../images/planner-scene-dialog.png)

![点击场景会用其详细信息填充新轮次表单](../../images/planner-new-turn.png)

与编辑器的每个标签页一样，它可以被拖出，成为独立的面板，见下文。

<a id="arranging-the-tabs"></a>

### 排列标签页

编辑器由一组标签页组成：**Story** 本身（各部分以及其下方的底部栏）、**Outline**、**Lorebook**，以及[扩展](../extensions/index.md)添加的标签页（Characters、Arcs、Side Query 等）。通过标签页的标题栏拖动，可以重新排列它们（仅限桌面端，手机端保持单列，大纲位于抽屉中）。新书的 **Outline** 和 **Lorebook** 位于左侧的一个面板中，**Story** 位于右侧自己的一列中。你可以把 **Story** 放在任何位置，例如放在中间，大纲在一侧，lore 在另一侧，或放在大纲上方：

- 将其拖放到一列中面板上方、之间或下方出现的虚线条上，即可将其**分离**为该列中独立的面板。同一列中的面板会上下堆叠。
- 将其拖放到编辑器左侧、右侧或列与列之间出现的高条上，即可将其**侧向分离**：它会获得自己的一列，与其他列并排。拖动分隔条可以加宽编辑器，以便容纳更多列。

面板和列之间由分隔条隔开：拖动它们，为每个面板提供所需的空间。尺寸会随布局一起保存。

![侧边栏中 Characters 位于自己的一列，Side Query 位于其下方](../../images/story-editor-tabs.png)

- 将其拖放到另一个面板的标签标题或正文上，即可**合并**到该面板（放在标签上会插入到该标签之前，放在正文上则会放在最后）。失去最后一个标签的面板会消失，没有面板的列也会消失。

布局和尺寸随书一起保存，因此下次打开时以及在任何浏览器中都保持一致；每个面板显示的标签也会与工作区的其他设置一起被记住。未加载的扩展的标签会保留其位置，待扩展恢复后再显示。

故事始终存在于某处：它的标签页无法关闭，而与其他标签共处同一面板的标签页，在选中另一个标签时会被隐藏。任何显示某一部分的操作都会将故事带回：点击大纲中的条目、搜索结果、在[故事树](branches-and-story-tree.md)中选择分支，以及开始生成，都会先选中 **Story** 标签页。生成准备提示词（通常需要几秒）期间，其他标签页会被禁用；模型开始写作后，它们会恢复可用，参见[下文](#while-a-part-is-generated)。
<a id="minimizing-tabs"></a>

### 最小化标签页

除故事以外，每个标签页的名称旁边都有一个小的 **⌄**（下拉箭头）按钮。点击它可以**最小化**该标签页：标签页会离开所在面板（所有标签页都被最小化的面板会暂时消失），同时在编辑器边缘的一个小栏中会出现它的圆形图标，即一个带有图案的彩色圆圈（大纲是列表，设定集是书本，批注是对话气泡，Side Query 是放大镜，依此类推；没有图案的扩展标签页则显示一两个字母）。将鼠标悬停在图标上即可看到它是哪个标签页。没有任何东西被关闭，标签页仍保留它原先显示的内容。点击图标，标签页就会回到面板中原来的位置，并重新显示出来。

只要有标签页处于最小化状态，这个小栏就会保留。它顶部的按钮（环绕的箭头）会把小栏顺时针移到编辑器的下一侧：左、上、右、下。故事标签页无法被最小化，因此屏幕上始终至少有一个内容。

![编辑器边缘小栏中的最小化标签页](../../images/story-minimized-tabs.png)

在你更改之前，图标按标签页名称的字母顺序排列。将一个图标拖到另一个图标上，它就会占据后者的位置。哪些标签页被最小化、小栏位于哪一侧，以及图标的排列顺序，都会与书籍一起保存，同时保存的还有布局和尺寸。

<a id="the-default-arrangement"></a>

### 默认布局

新建的书籍会以标准布局打开（大纲、设定集和批注位于左侧，故事位于右侧）。若想把你自己的布局设为标准布局，请调整标签页（面板、尺寸、最小化的标签页、小栏所在的一侧），然后在故事的设置菜单（⚙）中选择**将当前布局保存为我的默认布局**。之后，所有没有自己布局的书籍（即你没有重新排列过的书籍）都会以此布局打开；已经重新排列过的书籍则保留自己的布局。该默认布局保存在你的用户设置中。

若要恢复默认布局，请在故事的设置菜单（⚙）中选择**恢复默认布局**并确认。恢复的是你保存过的布局；如果你从未保存过，则恢复标准布局。此操作只会把标签页移回原位（并清除尺寸和最小化状态）：你的文本、每个面板所显示的标签页以及扩展标签页都会保留，其中扩展标签页会放在第一个面板中。
<a id="writing-the-next-part"></a>

## 编写下一部分

1. 点击右下角的 **+**。*New Turn Instructions* 面板随即打开。
2. 填写各个字段。所有字段都是可选的，但模型至少需要一些指引：

   | 字段 | |
   |---|---|
   | **Scene Setting** | 这一部分发生的地点和时间，例如 *The lighthouse, a stormy night in late autumn*。 |
   | **POV Character** | 这一部分以谁的视角书写。 |
   | **Present Characters** | 场景中有谁，以及他们的状态。 |
   | **Instructions** | 这一部分应当发生什么。 |

   *Scene Setting*、*POV Character* 和 *Present Characters* 会从上一部分自动填入，因此你只需修改不同的内容。*Instructions* 每次都从空白开始。
3. 点击 **Generate**。

![New Turn Instructions 面板](../../images/new-turn-instructions.png)

新的部分会出现在末尾，并随着模型的书写逐步填充。对于[推理模型](../inference-providers.md#reasoning-models)，推理过程会先显示在 **View Reasoning** 下。

部分生成期间，**+** 按钮会变成红色的 **Stop** 按钮。停止后，已写出的文本会保留为该部分的内容。

<a id="while-a-part-is-generated"></a>

### 部分生成期间

在最初的几秒钟内，系统会根据全书内容组装提示词，此时整个书籍窗口都会等待。模型一开始书写，只有新部分及其之前的部分会被锁定：

- **新部分**在完成之前不能被触碰：不能编辑，也不能打开菜单。
- **之前的部分**保持原位：你可以编辑、添加注释和重写它们，但不能删除、合并或分支，故事也会留在当前分支上（不能滑动切换，也不能切换分支）。对较早部分或设定的修改不会影响正在书写的部分，因为它的提示词已经组装完毕；这些修改只对之后的内容生效。
- **其他内容均可自由操作**：设定、书籍的设置与提示词、左侧栏的各个标签页（侧边查询、情节大纲、笔记等），以及命令栏。如果生成占用了模型的唯一连接，对模型的其他请求会等待一个空闲连接。
- **等待中**：第二个回合、搜索替换、导入到书籍中，以及批量删除。树状视图和备份标签页也会等待。

窗口中被置灰的操作，在命令、代理或扩展请求时同样会被拒绝，此时 Marginalia 会说明是什么在阻止（*This is in use: …*）。

**离开书籍会停止生成。** 退出按钮会先询问；选择 *Yes* 与 **Stop** 相同：已接收的内容会被保留。关闭浏览器标签页也会如此；在部分生成期间关闭或刷新标签页时，浏览器会先询问。网络短暂中断，或笔记本合上一分钟，都不算离开：页面会恢复，并显示这期间已接收的内容。

如果模型返回错误（服务器无法连接、API 密钥错误、上下文过长等），系统会显示该错误。若尚未收到任何文本，故事会保持原样：新部分或滑动版本会被移除，重新生成的部分会恢复其之前的文本。错误出现之前已接收的文本会被保留，与 **Stop** 的情况相同。请先解决问题，然后再次生成。

字段如何进入提示词，由书籍的 [User Prompt](prompts.md#user-prompt) 决定。使用默认的用户提示词时，模型会以 *Current Location & Time*、*Point of View Character*、*Characters Currently Present / State* 和 *Plot Specifications for the Next Part* 的形式接收这些字段。

!!!
文本以 Markdown 格式书写：`*斜体*`、`**粗体**`、`# 标题`等会以格式化形式显示。带有 `#` 标题的部分会被 [Chapter Marker](../extensions/chapter-marker.md) 扩展视为一个章节。
!!!

<a id="drafting-the-instructions"></a>

### 起草指令

不知道接下来该写什么？面板中 *Instructions* 字段下方的 **Draft Instructions** 可以让模型代你撰写指令，就像你自己会写的那样。点击后会打开一个窗口，包含：

| | |
|---|---|
| **Guidance** | 这一部分应当关于什么：一个粗略的想法、一个方向（"她就那封信质问他"），或者什么都不填，模型会顺着故事自然发展。它初始内容为你已在 *Instructions* 中输入的文字。 |
| **Plan of the Story** | 仅当有来源提供时才会出现。[Arc Outline](../extensions/arc-outline.md#drafting-the-instructions-for-the-current-chapter) 会提供，内容来自当前章节的数据。只读；模型会遵循它。 |

点击 **Draft Instructions** 会启动模型，并将回答逐步输出到 **Drafted Instructions** 中。你可以在继续之前修改或清空它；**Draft Again** 会再尝试一次，**Stop** 则保留已收到的内容。在你点击 **Use as Instructions** 之前，不会有任何改动：该文本会替换面板中的 *Instructions*（其他字段不受影响），面板随后重新打开，准备好进行 **Generate**。

模型会获取到目前为止的故事（较早的故事以[摘要](summaries.md)形式提供，与生成时相同）、面板中的场景设定、视角和在场角色、上一部分的设定、你最近的指令（作为你写作风格的示例）、你的指导以及情节计划。它不会看到新回合会激活的设定集条目。该请求使用[仿写提示词（impersonate prompt）](prompts.md#impersonate-prompt)。所用模型为书籍所设定的模型；起草与其他请求一样消耗 token。

![起草下一回合的指令](../../images/impersonate-dialog.png)

命令 [`/impersonate`](../commands/index.md) 的功能相同，它会直接返回文本。[代理](../agents.md)不会获得此功能，它们使用自己的指令来撰写故事。

## 编辑文本

生成的文本可以由你修改。在部分菜单中选择**编辑**，修改文本，然后选择**保存**。编辑过的部分会按你编辑后的样子发送给模型。

如果编辑的部分被某个[摘要](summaries.md)涵盖，该摘要就会过时；Marginalia 会在下次生成时发现这一点，并删除该摘要。为免出乎意料，**保存**时会先检查新文本：如果会导致摘要过时，会弹出一个窗口，说明数量，并提供三个选项：**返回编辑**（不保存，编辑器保持打开，保留你的文本）、**仍然保存**（摘要将变为过时）以及**保存并重新验证摘要**（保存文本，摘要保持有效，适用于不改变摘要内容的修改，例如修正错别字）。该检查针对**保存**（菜单、快捷键和编辑器按钮）；自动保存（例如编辑器打开时开始生成）不会询问。

| 按键 | |
|---|---|
| `+` | 打开*新回合指令*面板，光标位于*指令*中。 |

<a id="deleting-a-part"></a>

## 删除部分

**删除**会将该部分从故事中移除。其后的部分保留下来，并从它之前的部分继续，因此删除故事中间的某个部分只是把它拿掉。删除最后一个部分会使它之前的部分成为该分支的新结尾。

<a id="deleting-many-parts-at-once"></a>

### 一次删除多个部分

设置菜单（⚙）中有**批量删除**。开启后，每个部分的左侧会出现一个复选框，故事下方会出现一个栏，显示已勾选的部分数量以及一个**删除**按钮。勾选你想删除的部分（滚动时勾选状态会保留，故事只加载一部分内容）；在复选框上**按住 Shift 并点击**，会勾选（或取消勾选）它与你之前点击的那个之间的所有部分；被勾选的部分会以红色标示。然后按下**删除**：经过确认后，各部分会在一个无法中止的进度条后逐一删除。删除方式与删除单个部分相同：被删除部分之后的部分从其前面的部分继续，被删除的部分进入回收站。之后故事会重新显示，批量删除随即关闭。栏中的**取消**，或再次选择**批量删除**，会关闭该功能且不删除任何内容。开始生成也会关闭批量删除。若某个被勾选的部分正被某个窗口或翻译处理，它会保留在故事中，Marginalia 会说明是哪个功能占用了它。

![勾选了部分内容的批量删除](../../images/story-mass-delete.png)
<a id="redrafting-a-part"></a>

## 重写某一部分

**重新生成**和**换一版**只针对最后一部分，并从头写出该部分。**重写**可用于任何部分，包括故事中间的旧部分，并保留你未要求修改的内容。请在该部分的菜单中选择**重写**：

1. 在**重写指令**中写下需要修改的内容，例如：*在两人之间增加更多对话*、*让打斗更长*、*去掉对地图的解释*、*保持结局不变*。若指令为空，则按相同情节重新写出该部分。
2. 如果该部分需要变得**更短**或**更长**，请在**长度**中选择（默认为**长度不变**）：系统会在你的指令之后附加一句相应要求（参见[重写更短与更长提示](prompts.md#redraft-shorter-and-longer)）。然后选择**重写**。文本会流式输出到**重写文本**中；点击**停止**可提前结束。选择**再次重写**可再试一次，也可以换用其他指令。**差异**会逐词显示与该部分相比的改动。若该部分有尚未处理的[批注](annotations.md)，则默认勾选的**处理该部分未完成的批注**会把这些批注一并交给模型；点击**应用**则会将它们标记为已解决。
3. 重写文本是可以继续编辑的文本框（其角落的图标可将其展开到整个文本的高度），**差异**会跟随你的编辑而更新。点击**应用**，用它替换该部分的文本；点击**关闭**，则放弃它。在点击**应用**之前，书中的任何内容都不会改变。

![重写窗口：指令、新文本和差异](../../images/redraft-dialog.png)

模型会收到[重写提示](prompts.md#redraft-prompt)：该部分的内容、你的指令、该部分之前的故事（较早的故事在有效时以[摘要](summaries.md)形式提供，其余以原文形式提供；若放不下，则从最新的部分开始）、该部分之后的故事（在空间允许的范围内，最多占可用空间的四分之一）、此刻该部分适用的设定集（针对该部分所在的轮次重新计算，因此对条目的编辑会影响重写；只有当书中没有设定集时，才会使用该部分写作时所用的设定）、全书的视角、时态和风格，以及该部分所来自的那一轮的场景设定、视角人物、在场角色和指令。之后的故事会一并提供，以便新文本仍能顺利衔接到后文：后续部分所依赖的事件应当保留。

该部分保留其位置、摘要、配图以及生成方式；文本、字数和词元会被替换，该部分被视为已编辑。应用重写与编辑器中的**保存**一样属于编辑，因此描述旧文本的[摘要](summaries.md)将变得过时，Marginalia 会告诉你有多少个。该部分自身的摘要也包括在内。

当某个摘要描述的是该部分（该部分有摘要，或该分支中有更新的部分有摘要）时，窗口中会出现复选框**重新验证此次重写使之过时的摘要**，默认未勾选。当摘要仍然正确（重写只改变了措辞，而没有改变发生的事件）时，请勾选它：点击**应用**后，系统会重新计算它们的哈希值，摘要保持有效。若事件已经改变，请不要勾选，而应重新生成摘要。

该窗口不会阻塞故事，参见[与重写和批注窗口并行工作](#working-beside-the-redraft-and-annotation-windows)。

<a id="working-beside-the-redraft-and-annotation-windows"></a>

### 与重写和批注窗口并行工作

在电脑上，**重写**和**用 AI 批注**窗口会停靠在故事的右侧，故事仍可使用：在模型写作的同时，你可以阅读、滚动和编辑故事。拖动标题可以移动窗口，拖动边缘可以调整大小。标题中的箭头（⌄）会将窗口收起到页面左下角的[运行面板](#the-panel-of-the-runs)中：模型继续工作，点击**打开**（或点击该条目）可将窗口调出，点击**停止**则会停止模型（模型完成后，**关闭**会关闭窗口）。在手机上，窗口仍会覆盖故事，但收起方式相同。

![窗口停靠在故事旁，模型写作时，左下角面板中显示运行状态](../../images/redraft-beside-story.png)

**关闭与停止是两回事。** 窗口自身的**停止**会停止模型，窗口保留已经收到的内容。模型工作时点击**关闭**并不会停止它：窗口收起到面板中，模型继续在其队列中运行；下次打开窗口时，答复会显示在其中。模型已完成的窗口，或在面板中点击**关闭**的窗口，会被直接移除。关闭书籍或浏览器标签页时，被收起的窗口也会随之停止。对于其他等待模型的窗口，情况相同，包括：**摘要**（以及*创建摘要*、*重写所有摘要*）、[审阅者](../extensions/reviewer.md)、书籍简介、设定集和大纲生成器、图像和漫画生成器，以及 Beta 读者的人物写作器。有声书的*工作室*和*转换*窗口也不会阻塞页面；关闭它们从来不会停止转换。

当某一部分上有窗口打开（或已收起）时，该部分旁边的菜单会显示其正在进行的操作（*正在重写 · 本书*），并且该部分的**重新生成**、**换一版**、**重写**、**用 AI 批注**、**合并到上一部分**和**删除**将被禁用，以免窗口失去其所属的部分。编辑该部分仍然可以进行。关闭书籍会同时关闭其窗口并停止相应的模型。[翻译器](../extensions/real-language-translator.md)正在处理的部分会以同样的方式显示*正在翻译该部分的语音...*；两个翻译器不会同时处理同一部分，第二个翻译器会提示该部分正在使用中。

- 当你对整个部分**应用**重写，而该部分在窗口打开之后已被修改（即你在此期间进行了编辑）时，Marginalia 会先询问：**差异**会将部分的当前内容与重写稿进行比较，让你看到应用后将被替换的内容；然后选择**仍然应用**或**取消**。若重写[自动应用](annotations.md#annotating-every-new-part-automatically)，且该部分已被修改，则不会直接应用：窗口会等待你的处理。
- 若在你**应用**重写或添加批注之前，该部分已被删除，窗口会告知你，不会写入任何内容，并自动关闭。
<a id="the-panel-of-the-runs"></a>

### 运行面板

你的书目前用模型处理的一切都列在每个页面的左下角：生成、重写或批注；[Real Language](../extensions/real-language-translator.md) 或
[Conlang](../extensions/conlang-translator.md) 翻译器的翻译；摘要的改写；Knowledge Tracker 阅读故事；[Audiobook](../extensions/audiobook.md) 的转换；命令栏中耗时较长的命令（*Draft instructions*、摘要……：其窗口位于一侧，并像其他窗口一样收起）。在模型回答期间，你正在等待回答的窗口也会列出：**Impersonate**、帮助助手、快速翻译、Conlang 设计器、Side Query 的聊天、Beta Readers 或情节向导。它列出的是你**所有已打开页面**中的运行（另一个标签页、手机上的），而不只是在本页启动的。没有任何运行时，则不显示。

![已打开的运行面板：重写窗口已收起到其中，显示模型文本的结尾，以及 Open 和 Stop](../../images/runs-panel.png)

- **收起时**，它是一个小栏：第一个运行、还有多少个（*Translating the speech of the part... · 2 more*），以及模型工作时的移动进度条。点击即可打开列表；当你把窗口收起到其中时，它会自动打开。
- **展开时**，每个运行会显示它做什么、属于哪本书、运行了多久、在等待什么，以及模型写出内容的结尾：
  - 当模型忙于其他请求时，显示 *Waiting for the model: 2 requests before this one*（参见 [推理提供方](../inference-providers.md) 中的 *Connections*）；
  - *The model is thinking...* 或 *The model is writing...*，下方是其思考或回答的结尾；
  - 当运行等待你的决定时显示 *Waits for you*（例如需要应用的重写、需要你审阅的 Knowledge Tracker 提议、生成前 Prompt Inspector 的询问，或情节向导需要你允许的命令）。
- **Stop** 会停止该运行，无论它在哪里启动。**Open**，或点击该条目，会重新显示一个收起的窗口（仅限于打开它的那个页面），或显示运行本身；当运行在等待你时，按钮为 **Review**。Knowledge Tracker 的运行会在本页打开其书（若本页未打开其他书；否则会要求你先关闭那本书），切换到 Knowledge 标签页并显示审阅内容。**Close** 会永久关闭一个窗口（并停止其模型）。
- 在电脑上，你可以通过左侧的把手（⋮）移动面板；它会保留在你在此浏览器中放置的位置。当页面处于下半部分时，展开后它向上生长，位于角落处，并且始终保持在页面之内。当它与[帮助助手](../administration/help-assistant.md)的圆形按钮位置重叠时（在书本页面上两者都在左下角），该按钮会让开，待位置空出后再回来。

如果你启动的运行在其页面关闭后结束，你打开的另一个页面会发送其[通知](../account.md#notifications)（对于有通知的运行，例如摘要的重写）。

<a id="redrafting-only-a-passage"></a>

### 只重写一段文字

要重写几句话而保留该部分的其余内容，请在部分的正文中选中它们，然后**右键单击**（在手机上为长按）：菜单中有 **Redraft selection**。（部分的菜单 ☰ 不提供此功能，在某些浏览器中打开它可能会丢失选区。）该窗口的工作方式与上述相同，但有两点不同：它显示 **Selected text**，而重写的结果只是用来替换它的文字。模型会获得整个部分（选区已标记）以及周围的故事和设定，因此新段落能与前后句子衔接。**Differences** 比较选区与重写文字；**Apply** 将重写文字放到选区的位置，并保留其余部分，包括选区两端的空格或换行。若开启了[批注](annotations.md)，复选框只提供与选区段落有重叠的批注。如果在你选中文字之后该部分被改动了（在另一个窗口中），**Apply** 会拒绝执行，你需要重新选择。在该部分正在编辑时，使用编辑器中的选区，并先保存编辑内容。


<a id="what-follows-a-generated-part"></a>

### 生成的部分之后会发生什么

当你生成的一个部分（从页面或命令栏）完成后，书可能会自行对它做更多处理，顺序如下：

1. **Annotate**：[自动批注](annotations.md#annotating-every-new-part-automatically)审阅该部分。
2. **Redraft**：该部分被重新写出，以回应批注中的意见。
3. **Translate**：[Real language](../extensions/real-language-translator.md) 与 [Conlang](../extensions/conlang-translator.md) 翻译器翻译其中的对话。
4. **Knowledge**：[Knowledge Tracker](../extensions/knowledge-tracker.md) 阅读它。
5. **Audio**：[Audiobook](../extensions/audiobook.md) 将它制作成音频。

只有书中开启的步骤才会运行。它们在服务器上运行，因此页面可以关闭；它们在[运行面板](#the-panel-of-the-runs)中合并为一个条目：*After part 14: Annotate ✓ · Redraft … · Translate*，附带模型的文本和一个 **Stop**。改变文本的步骤优先，因此跟踪器和音频获得的是最终文本。等待你的步骤（批注或要选择的重写）会打开其窗口，该条目会有 **Review** 按钮，用于在另一个页面中打开它。

- **Stop**、关闭一个等待你的窗口，或某个步骤失败，都会在此处结束整个流程：已完成的工作保留，其余步骤不再运行，并会有一条消息说明还剩下什么需要手动完成（每个步骤在该部分上都有自己的操作）。
- 在**重写**运行期间，下一个部分无法生成（系统会告诉你是哪个运行造成的）；而在其他步骤运行期间，则可以生成。
- 在文本定稿之前，该部分无法删除；再次生成它会结束其早先版本之后所执行的步骤。
- [代理](../agents.md)通过自己的命令执行这些步骤：代理生成的部分之后不会执行任何后续步骤。
<a id="merging-a-part-into-the-previous-one"></a>

## 合并到上一部分

当模型在句子中间停止（达到回复长度上限、连接中断）时，无法可靠地让它"继续"同一段文本。此时应改为编写下一部分（*从上一部分停止的地方继续*），然后在第二部分的菜单中选择 **合并到上一部分** 将两者连接起来。随即会打开一个审阅窗口：

- **文本连接方式**：空行、换行、空格或不加任何分隔。默认值根据上一段文本的结尾自动选定：如果上一段以句子结束，则使用段落；如果在中途被截断，则使用空格。
- **场景设定**、**视角人物**、**在场人物**和**指令**（两个回合的内容），可在可编辑的字段中合并显示。两个回合开头相同的部分只保留一次（例如"写决斗场面。写得简短"和"写决斗场面。加入雨景"会合并为第一行"写决斗场面"，第二行"加入雨景"）。
- **数据**：两个部分各自保存的内容，逐项列出（例如故事的[变量](../templates/macros.md)以及扩展的数据），并标明每一项在两个部分中是相同、不同，还是仅存在于其中一个部分。合并后的部分默认保留**较晚部分**的值（因为它代表故事当前的状态），除非你为该项选择上一部分的值，或将其删除。相同的值默认隐藏，需要时可以手动显示。

![将一个部分合并到上一部分之前的审阅窗口](../../images/part-merge-dialog.png)

上一部分保持其位置、摘要以及生成方式（提示词、模型、时间）不变；它会获得合并后的文本、合并后的推理过程和图片，其字数和词元数也会重新计算。被合并的部分会被删除（可在[回收站](../trash.md)中找到），其后的内容将接续在上一部分之后。涵盖这两个部分的摘要会变为过时，与编辑后的情况相同。被合并部分的[历史记录](version-history.md#backups-copies-and-the-trash)会被移除，保留下来的部分会以合并后的文本作为一个 **已合并** 版本。如果该部分是书中的第一部分，或者它之前的部分还有其他续写分支（该部分的备选版本），则无法合并。此时请先删除这些续写，或将其转为分支。
<a id="images"></a>

## 图片

一个部分可以有图片：地图、角色肖像、插图。在部分菜单中选择**图片**，即可打开该部分的图片列表。

![部分的图片对话框](../../images/images-dialog.png)

- **添加图片**（或将文件拖放到其上）可上传 PNG、JPEG、GIF 或 WebP 图片，大小不超过 10 MB。WebP 图片在上传时会转换为 PNG，因为 Word 和 PDF 文件不能包含 WebP。
- **说明文字**显示在图片下方，可以为空。
- **在部分中的位置**是一个 3x3 的网格。列表示文本的一侧（左、中、右），行表示其中的位置：顶部位于文本之前，中部位于文本中间，底部位于文本之后。点击方格即可选择。
- **文字环绕图片**可让文本环绕图片排布，而不是位于图片的上方和下方。位于左侧或右侧时，文本与图片并排排列。位于中间一列时，文本在图片两侧排列：该行位置的若干文本块（约 400 个字符，至少两个文本块）会变为两栏，第一部分位于图片左侧，其余部分位于右侧，因此文本先顺着左栏向下读，然后继续进入右栏。同一位置的两张图片会在两栏之间上下排列。当文本没有足够的空间分为两栏时（只有一个段落，或文本块已被上方的横带占用），图片将作为独立的块居中显示。
- **宽度**是图片宽度占文本宽度的百分比。**自动**会保持图片的原始尺寸（不会比文本更宽；两侧都有文本的图片为 30%）。文字环绕在旁的图片最大为 60%，两侧都有文字的图片最大为 40%，以便文本保留一定的空间。高度按图片的比例跟随变化。
- 垃圾桶按钮可将图片从部分中移除。

![图片的位置：位于中间，文字环绕排布](../../images/images-position.png)

**按查看器效果预览**（对话框中的按钮；当部分有图片时，部分菜单中也有同样的入口）会以[查看器](publishing.md)的方式显示该部分，并采用本书的文字样式：图片位于你设定的位置，并提供宽屏与窄屏（手机）切换开关。预览使用编辑器中的当前文本，无论是否已保存。

![预览：文本分为两栏，图片位于两栏之间](../../images/images-preview.png)

故事编辑器本身不使用位置设置：它会将图片以列表形式显示在部分文本的下方。位置设置由查看器以及[导出](export.md#images)使用。

图片在文本中的位置并不取决于与之一同保存的数字：文本会在其块与块之间被切分（段落、列表、引文和代码块永远不会被切断），因此编辑文本时，图片仍会留在应在的位置。"中部"是块与块之间最接近文本中线的位置；底部的文字环绕图片会被放在最后一个块之前，以便至少该块与图片并排。同一位置的图片保持列表中的顺序；位于同一位置且彼此相邻（且不允许文本环绕）的图片，在空间允许时会并排排列。PDF 和 Word 对带有宽度设置的图片会这样处理。

图片**不属于文本的一部分**。模型看不到它们，它们不会出现在提示词中，不计入令牌，也不会改变[摘要](summaries.md)。它们也不是 Markdown：文本中写入的 `![](...)` 链接不是部分的图片，请改用**图片**功能。

需要了解的要点：

- **重新生成**会保留部分的图片，即使生成失败也是如此。**滑动**会写入一个新的部分（与旧版本并列的新版本），该部分一开始没有图片。**分支故事**会将图片复制到新部分。
- 图片属于你的账户。在[查看器](publishing.md)中，已发布书籍的读者同样可以看到图片，除非你取消勾选书籍"关于"标签页中的**向读者显示图片**。
- [备份](backups.md)会记录部分拥有哪些图片，但不包含图片文件本身。将备份恢复到另一个账户或另一个安装实例后，部分将不再有其图片。
- 从部分中移除图片只是将其从该部分取下。文件仍然保留，并会继续列在[资源](../resources.md)中，你可以在那里下载、替换或删除它。在那里删除它会将其从所有使用它的部分中移除。文件本身保留在数据文件夹中。

## 摘要

底部栏中的**摘要**按钮（位于设置菜单 ⚙ 的左侧）会打开当前分支的摘要概览，可在其中编辑、删除摘要，或将其合并为元摘要。该按钮的提示会显示正在使用的摘要在提示词中占用的令牌数。参见[摘要](summaries.md#the-summaries-overview)。

<a id="how-much-of-the-context-the-story-takes"></a>

## 故事占用了多少上下文

设置菜单（⚙）中有**分支令牌**。在生成任何内容之前，它会显示当前分支的故事在提示词中占用了多少：一个条形图分别显示**不含摘要**（所有部分）和**含摘要**（摘要以及最新部分之后的部分）的占用情况，另有一个表格列出各部分、令牌数，以及占**提示词预算**（书籍模型的上下文减去为回复保留的空间）的比例。只有仍然符合故事内容的摘要才会被计算；已不再匹配的摘要会被指明，并在生成某个部分时被丢弃。世界设定、系统模板和本轮指令同样占用同一预算。若没有带上下文大小的模型，表格中将不显示比例。

<a id="which-lore-entries-were-used"></a>

## 哪些 lore 条目被用过

设置菜单（⚙）中的 **Analysis**（分析）里的 **Lore Usage**（Lore 使用情况）显示生成内容用到了本书 lorebook 中的哪些条目，哪些从未被用到。
这样你就可以根据实际使用情况来精简 lorebook，而不必凭感觉猜测。每次生成都会记录其提示词中用到了哪些条目（以及每个条目的 token 数）；窗口会把这些记录汇总到各个部分：

- **Parts**（部分）用于选择统计范围：**Active branch**（当前分支），或 **All branches**（所有分支），即本书的每个分支和每个 swipe。
- **From part**（起始部分）和 **To part**（结束部分）用于限定范围，编号与大纲中的一致（分支的第一个部分为 1，在所有分支中，编号表示该部分在树中的深度）；留空则表示从头或到末尾。
- **Show**（显示）用于筛选统计范围内 **Never used**（从未使用）、**Sometimes used**（有时使用）或 **Always used**（总是使用）的条目。

![Lore Usage 窗口](../../images/lore-usage.png)

表格为本书 lorebook 中的每个条目各占一行，按使用次数从多到少排列，包括：所属 lorebook、是从未使用、有时使用还是总是使用、在多少个部分中使用（仅计有记录的部分，并附百分比）、在这些部分中的总 token 消耗以及每次使用的平均 token 消耗，还有首次和最后一次使用它的部分。点击表头可排序。如果某个条目过去被用过，但现在已不在本书的 lorebook 中（已删除、已移动，或其 lorebook 已关闭或不再属于本书），它仍会留在列表中，并标注为 *not in the lorebook now*（当前不在 lorebook 中）；已删除的条目没有名称。

只有有记录的部分才会被统计：手动输入的部分、在 Marginalia 开始保存此记录之前写的部分，或在本书没有 lorebook 时写的部分都没有记录，窗口会显示这些部分的数量。*Always used*（总是使用）的条目可能是常驻条目；*Never used*（从未使用）的条目则是删除或改用更好过滤条件的候选。lorebook 编辑器中的 [**Preview activation**（预览激活）](../lorebooks/entries.md#preview-activation) 可以显示某个条目现在为何不被触发。

<a id="text-styles"></a>

## 文字样式

底部工具栏中的设置菜单（⚙）有 **Appearance → Change Styles For Text**（外观 → 更改文字样式），这是一个菜单，每种样式各占一项，按名称排序。
关于如何制作样式，请参阅[样式指南](styling-guide.md)。
样式决定部分文字的外观：字体、字号、颜色、对齐方式、标题等。应用自带两种不可更改的样式：**Normal**（应用本身的外观）和 **Book**（类似书籍的阅读样式，即[查看器](publishing.md)所使用的样式）；你也可以在 [Settings → Styles](../account.md#styles) 中创建自己的样式。

- 第一项 **Default (...)**（默认）跟随你的*默认样式*（在 *Settings → Styles* 中标记的那一个；若你未选择，则为 Normal）。新建的书没有自己的样式，因此会显示默认样式。
- 选择其他项会把该样式**保存在书中**，仅对这本书覆盖默认样式；被勾选的项即为本书当前使用的样式。选择 **Default** 则取消这一选择。
- 删除某个样式后，使用过它的书会回退为你的默认样式。

![外观 → 更改文字样式：可选的样式](../../images/story-style-menu.png)

在 **Book** 样式中，段落两端对齐，过长的单词会自动断行，断行所依据的词典取自本书的 **Language**（语言，在[About 标签页](managing-books.md#the-about-tab)中设置）。断行由浏览器完成；对于少数冷门语言，浏览器没有相应词典，文字就不会断行。

之前开启过旧版 *Change Styles For Text* 开关的书，在你选择其他项之前，仍会显示 Book 样式。

<a id="highlighting-generated-text"></a>

## 高亮生成的文字

设置菜单（⚙）中还有一个可勾选的 **Highlight Generated Text**（高亮生成的文字）。开启后，模型写下的词句会在每个部分中被高亮显示，使你新增或改写的内容更加醒目。Marginalia 会沿着[部分的版本](version-history.md)追踪文字：每个版本都会叠放在前一个版本之上，它们共有的词语仍归原作者所有，因此你在生成文本中写入的句子，无论模型改写其余部分多少次，仍然属于你。你从未编辑过的部分会整体高亮；你自己写的部分则没有任何高亮。智能体写下的内容计为模型生成的内容。此开关不会被保存：重新打开页面时它会恢复为关闭。

[历史记录已关闭](version-history.md)的部分没有可供追踪的版本，因此会与模型最初生成的文本进行比较。该高亮功能在[手机](../phone.md)上同样可用。

同样的统计也可以算出比例：书的 **Info** 标签页中有 **Authorship of the branch**（分支的作者构成）及 **Calculate**（计算）按钮，可显示当前分支的词语中有多少百分比是你写的、多少是模型生成的；[导出](export.md)时也可以在文件末尾附上这一统计。

![高亮的生成文字与设置菜单](../../images/highlight-generated.png)

## 命令

故事下方菜单旁边有一个**命令行**：输入 `/` 可查看命令，选择一个后按 **Enter**（或点击播放按钮）即可运行。命令的返回结果会显示在命令行上方的一个小窗口中。关于如何编写参数、帮助信息的内容以及如何中止耗时较长的命令，请参阅[命令](../commands/index.md)。目前命令行仅在桌面布局的故事标签页中可用。
<a id="search-and-replace"></a>

## 搜索和替换

设置菜单（⚙）中还有 **Clear history of the book** 和 **Empty trash of the history**，参见[版本历史](version-history.md#deleting-versions)。

设置菜单（⚙）中还有 **Search and replace**，可以一次性在整个故事中更改某个词、名字或短语。该窗口有 **Search for** 和 **Replace with** 两个字段，以及以下选项：

![带有 Search and replace 的设置菜单](../../images/story-settings-menu.png)

![已输入搜索内容的 Search and replace 窗口](../../images/search-replace-dialog.png)

| 选项 | 默认值 | 含义 |
|---|---|---|
| **Search by regex** | 关 | 搜索文本是一个[正则表达式](../regular-expressions.md)，替换文本可以使用其分组（`$1`）。否则按输入的原文搜索。 |
| **Case sensitive** | 开 | 只查找与输入大小写完全一致的文本（*John* 不会找到 *john*）。关闭后不区分大小写。开启 **Search by regex** 时此选项锁定。 |
| **Search in summaries** | 开 | 同时搜索并更改[摘要](summaries.md)。 |
| **Search in all branches** | 关 | 搜索所有[分支](branches-and-story-tree.md)，否则只搜索当前活动分支。 |
| **Revalidate all summaries** | 开 | 替换完成后，本书的每个[摘要](summaries.md)都会重新变为有效，见下文。 |

使用正则表达式时，大小写始终按输入处理；如需忽略大小写，请在开头加上 `(?i)`。点击 **Search**（位于字段右侧的按钮；在手机上位于字段下方）。进度条显示搜索进度，其旁边的 **Stop** 可以中断搜索。搜索本身不会更改任何内容。

表格列出故事中每一个有匹配项的部分以及每一个有匹配项的摘要，并显示其类型和 id。打开某一行可查看其中的匹配项：匹配文本前后的内容，既显示原文，也显示替换后的效果。过长而无法完整显示的匹配文本或替换文本会以 *[searched text]* 或 *[replace text]* 表示。

![搜索结果的匹配项，第一个部分已展开](../../images/search-replace-found.png)

在 **Search for** 或 **Replace with** 字段中按下 **Enter**，效果与点击 **Search** 相同。

搜索完成后，字段和选项将被锁定，**Replace** 按钮变为可用。**Search again** 会清除已找到的结果并解锁窗口，以便你修改搜索内容。**Replace** 会真正更改故事：在完成之前整个窗口完全冻结（即使 **Stop** 也无效），完成后窗口会再次清空。被替换的部分会标记为已编辑，就像你亲自编辑过一样。

如果替换的是某个[摘要](summaries.md#when-summaries-become-outdated)所描述的文本，该摘要就会变为过时。开启 **Revalidate all summaries** 后，Marginalia 会为本书的每个摘要重新计算校验值（包括所有分支的摘要，也包括未被替换影响的摘要，以及之前已经过时的摘要），因此替换后所有摘要都将重新变为有效。这样做也会在不检查摘要文本的情况下使过时的摘要恢复有效，因此只有在你确定摘要的内容仍然正确时才应使用此选项。

关闭此选项时，只有搜索范围内的摘要会被更新。搜索范围之外的摘要（未被搜索的分支的摘要，它们与当前活动分支共享前面的部分；或者当摘要不被搜索时的全部摘要）会变为过时。如果存在此类摘要，Marginalia 会告知数量，并询问是否继续。之前已经过时的摘要仍然保持过时。

![关于将变为过时的摘要的警告](../../images/search-replace-warning.png)

在[手机布局](../phone.md)中，同一窗口的字段和按钮上下排列；表格只有一列，显示类型和 id，其下方是匹配文本和替换文本。

[摘要概览](summaries.md#search-and-replace-in-the-summaries)中有一个仅针对摘要的同款窗口。

同样的搜索和替换也可以通过[命令行](../commands/index.md#commands-that-come-with-marginalia)使用 `/search-replace-parts` 执行；它会在替换前进行询问。

## 导入到书中

设置菜单（⚙）中有 **Import**（位于 **Import & export** 之下）。它是书籍标签页中的窗口，用于把文件新建为一本书（参见[管理书籍](managing-books.md#creating-a-book)）；而在这里，导入的内容则是为你当前所在的这本书**添加到故事中**，即各部分被加入故事。**Source**（来源）可以是 `.md` 文件的 zip 压缩包、文档（Word、LibreOffice、RTF、Markdown、纯文本、EPUB）、Obsidian 库的 zip 压缩包或 Scrivener 项目的 zip 压缩包；每种来源的文本和选项与上面相同（每个部分的字数以及章节的标题级别），并且一行文字会说明本次导入将会产生什么。SillyTavern 和 LM Studio 的聊天记录不在可选范围内：它们是一棵分支树，在故事中间没有位置。

**Put the parts**（放置部分）用于指定这些部分放在哪里：

- **At the end of the story**（放在故事末尾）：放在当前分支的最后一个部分之后（空书的话则成为第一个部分）。
- **Before a part**（放在某部分之前）或 **After a part**（放在某部分之后）：从列表中选择一个部分（编号即当前分支中的位置，附带文本开头）。新部分被插入到两个部分之间：原先位于该位置之后的所有内容，包括它们的所有分支，都会排在新部分之后，且没有任何部分被修改或重新生成。故事的末尾位置保持不变（故事因此多出了相应数量的部分）。覆盖该位置的摘要已经过时，因为它们描述的是没有新部分的故事；[摘要](summaries.md)窗口会显示这些摘要，并可以重新生成它们。

![书籍的导入窗口](../images/book-import-into.png)

压缩包中的各部分是按文件名顺序排列的文件，文件名中的数字按数值比较（`2.md` 排在 `10.md` 之前），文件夹中的文件同样适用。文件夹、隐藏文件（`.name`）、`__MACOSX` 文件夹以及非 `.md` 的文件都会被跳过。文件内容即为部分的原文，不会发送给模型，也不会被修改；所有部分都视为由你撰写。

导入时会显示一个进度条，并标明已完成的部分数。**Stop**（停止）会在当前正在保存的部分完成后结束导入：已经添加的部分保留在故事中（导入不会被撤销），并会显示一条消息说明导入了多少个部分。

<a id="after-an-import"></a>

### 导入之后

当各部分已进入书中后，会出现一个 **Import finished**（导入完成）窗口，提供两项有助于更轻松地续写长篇故事的功能（如果刚刚导入的是一本新书，则会先打开该书，且该窗口会显示在它前面）。这两项功能也可以在设置菜单（⚙，**Analysis**）中找到，因此可以稍后再做或重复执行：

- **Create summaries...**（生成摘要……）为导入的内容编写摘要，参见[生成摘要](summaries.md#create-summaries)。请先执行此操作：智能体在工作时会锁定书籍。
- **Take lore notes with an agent...**（用智能体记录设定……）启动一个[智能体](../agents.md)，它会阅读故事，并将其中发现的人物、地点、事物和术语写成该书设定集的条目，参见[设定笔记](../agents.md#lore-notes-of-an-imported-book)。

**Not now**（暂不）会关闭窗口，两项都不执行。

![导入之后的窗口](../../images/import-finished.png)

将同样的内容导入到设定集中的方法，参见[导入与导出](../lorebooks/import-export.md#importing-an-archive-of-text-files)。

<a id="exporting-the-story"></a>

## 导出故事

设置菜单（⚙）中还有 **Export story**（导出故事），可将当前分支保存为文本、Markdown、HTML、Word、PDF 或 EPUB 文件。参见[导出书籍](export.md)。

<a id="what-the-model-gets"></a>

## 模型会收到什么

对于每个新部分，Marginalia 会发送以下内容：

1. **主模板**作为系统消息：角色、[设定集](../lorebooks/index.md)条目、叙述视角、时态、风格和[摘要](summaries.md)。如果已启用，[推理提供方](../inference-providers.md#general-settings)的越狱提示词会排在最前面。
2. 当前分支中之前的各部分，作为模型自己先前的回答发送——数量以能放入[上下文限制](../protocols.md#limits)为准，且从最新的开始。装不下的更早部分会被省略（若某个[摘要](summaries.md)涵盖了它们则除外）。
3. 包含生成新部分指令的**用户提示词**。

在任一部分上使用 *Show Prompt*（显示提示词）可以看到实际发送的全部内容。模板参见[书籍提示词](prompts.md)。
