# 清理

在 Marginalia 中删除书籍、故事片段、设定集或推理提供方等对象后，它们会从列表中消失，但仍保留在数据库里。这样删除是安全的，引用也能继续工作（例如，一本书仍然知道写下其片段的提供方）。在此之前，用户可以从 [Trash](../trash.md) 标签页恢复已删除的对象。**Cleanup** 会永久删除这些已删除的数据，以减小数据库的体积。

![Cleanup 标签页](../../images/admin-cleanup.png)

<a id="running-a-cleanup"></a>

## 运行清理

!!!warning
清理无法撤销，被清理的内容也会从 [Trash](../trash.md) 中消失。请先[创建数据库备份](database-backups.md)。
!!!

1. 打开管理页面的 **Cleanup** 标签页，点击 **Analyze**。此时尚未更改任何内容。
2. 检查结果（见下文）。
3. 点击 **Run Cleanup**，并确认 *n objects will be permanently removed*。

清理会涵盖所有用户的数据。

清理只会从数据库中删除条目。对于 [智能体](../agents.md)，它只删除文件：被清除的智能体的工作区，以及被清除的运行记录的文件夹。已删除和未使用的[资源](../resources.md)（片段的图片、音频）的文件会保留在其所有者的数据文件夹中，直到你在 [Resource Files](resource-files.md) 标签页中将其删除。

<a id="seeing-what-is-deleted"></a>

## 查看已删除的内容

表格下方的 **Trash** 列出了所有用户已删除的对象，每个对象占一行（打开它即可加载表格）。这样你可以看到清理会删除哪些内容，也可以恢复别人请你找回的对象。它与 [Trash](../trash.md) 标签页使用同一张表，包括按用户和类型筛选的功能以及 *Extended Content* 链接。

![Cleanup 标签页中的 Trash 部分](../../images/admin-trash.png)

<a id="reading-the-analysis"></a>

## 阅读分析结果

第一张表每种数据类型占一行：

| 列 | |
|---|---|
| **Entity** | 数据类型：`Manuscript`（书籍）、`ChatMessage`（故事片段）、`Lorebook`、`LorebookEntry`、`AI`（推理提供方）、`Protocol`、`Summary`、`Tag`、`TagRelation`、`User`…… |
| **Deleted** | 已删除的数量。 |
| **To purge** | 将由 *Run Cleanup* 删除的数量，包括属于已删除对象的数据。 |
| **Blocked** | 已删除但仍在使用中，因此被保留。 |

**Deleted objects still in use** 列出被阻止的对象，包括名称以及 **Referenced by**（仍在使用它们的对象）。

<a id="what-is-removed"></a>

## 会被删除的内容

清理会删除不再被任何现存对象使用的已删除对象，以及只属于它们的数据：

| 已删除 | 一并删除的内容 |
|---|---|
| 一本书 | 其所有故事片段、摘要和标签关联 |
| 一个设定集 | 其条目和标签关联；其他设定集不再将其作为子设定集包含 |
| 一个故事片段 | 该片段（其子片段此前已移至父片段）及其摘要 |
| 一个推理提供方或协议 | 从用户在 *Settings* 中的默认设置里清除 |
| 一个标签 | 其与书籍和条目的关联 |
| 一个用户 | 其拥有的一切：书籍（及其故事片段和摘要）、设定集、推理提供方、协议、标签和设置 |

清理还会删除那些不再被任何对象使用的[资源](../resources.md)，即使没有人删除过它们：添加到某个对象上的文件（[有声书](../extensions/audiobook.md)的音频、片段的图片），当其所属对象已不在数据库中，或被本次清理删除，并且也没有其他对象引用它们时，就会被删除。从某个片段创建的分支拥有相同的图片和剪辑，因此只要分支存在，这些文件就会保留；仍在回收站中的已删除对象所引用的文件也会保留。这些文件计入 `Resource` 的 **To purge**，而不计入 *Deleted*。未被任何对象使用的文件（在 Resources 标签页中显示为 *nothing*）会被保留。

<a id="what-is-kept"></a>

## 会被保留的内容

只要仍有现存对象在使用某个已删除对象，它就会被 **blocked**（阻止删除），即被保留：

| Blocked | 原因 | 解除阻止的方法 |
|---|---|---|
| 已删除的推理提供方或协议 | 一本书仍将其用作模型或协议 | 在该书的 *About* 标签页中选择另一个，或删除该书 |
| 已删除的设定集（及其条目） | 一本书仍在使用它 | 在该书中选择另一个设定集，或将其清除 |
| 已删除的故事片段 | 它是某本书当前活动分支的最后一个片段 | 将该书切换到另一个分支，或删除该书 |
| 已删除的用户 | 另一用户的某些内容仍在使用其数据（另一本书使用了他们的推理提供方或设定集） | 修改或删除另一用户的那本书 |

解除阻止后，请再次运行 *Analyze*。

<a id="reference-model"></a>

## 引用模型

底部的 **Reference Model** 列出了各类数据之间的每一种引用及其策略。当你想了解某项内容为何被阻止时，它会很有用：

| 策略 | 含义 |
|---|---|
| **Blocks purge** | 当存在现存对象引用某个已删除目标时，该目标会被保留。 |
| **Purged with target** | 引用方对象属于该目标，并会随之一起删除（条目随其设定集一起删除）。 |
| **Owns target** | 该目标属于引用方对象（摘要属于其片段）。 |
| **Cleared on purge** | 当目标被清除时，该引用会被移除（子设定集、默认模型）。 |

扩展可以通过其自身的规则参与清理。
