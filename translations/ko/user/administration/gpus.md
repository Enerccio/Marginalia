# GPU

그래픽 카드 한 장은 대개 한 번에 모델 하나만 올려 둘 수 있습니다. 언어 모델, 이미지 모델, 음성 모델 중 하나입니다. 관리자 페이지의 **GPU** 탭에서는 같은 카드에 있는 모델과 서버가 카드를 차례로 쓰도록 설정할 수 있습니다. 그래서 언어 모델이 카드를 채우고 있는 동안 이미지나 오디오북이 시작되지 않고, 언어 모델이 필요할 때 다시 돌아옵니다.

관리자가 한 번 설정하면, 이후 각 사용자는 자신의 AI나 백엔드에 잠금을 선택합니다.

<a id="what-it-is-made-of"></a>

## 구성 요소

| | |
|---|---|
| **GPU** | 카드 한 장(또는 모델을 한 번에 하나만 올릴 수 있는 기기). 이름만 있습니다. |
| **GPU 잠금** | GPU를 쓰는 한 가지 방식으로, 그 GPU에 무엇이 올라가 있는지를 뜻합니다. 예를 들어 같은 GPU에 *언어 모델*, *ComfyUI*, *Speech*가 있을 수 있습니다. 잠금에는 순서가 있는 두 목록의 단계가 있습니다. **획득 단계**는 잠금을 적재합니다(컨테이너 시작, 모델 적재, 먼저 내려야 할 것 해제). **해제 단계**는 카드에서 잠금을 비웁니다(컨테이너 중지, 모델 언로드). **동시 작업 수**는 이 잠금의 작업이 동시에 몇 개 실행될 수 있는지 제한합니다(이미지를 한 번에 한 장만 만드는 이미지 서버: 1, 제한 없음: 0). |
| **GPU 단계** | HTTP 요청 하나입니다. 주소, 메서드, 헤더(`Name: value`, 줄마다 하나씩, 암호화되어 저장되므로 베어러 키를 여기에 적을 수 있음), 본문, 제한 시간(비우면 60초), 응답 후 대기 시간으로 이루어집니다. 한 단계를 여러 잠금이 함께 쓸 수 있습니다. 예를 들어 이미지 잠금과 음성 잠금이 모두 먼저 실행하는 *언어 모델 해제* 단계 하나가 그렇습니다. **테스트**를 누르면 요청을 즉시 보냅니다. |

잠금은 다음 위치에서 고릅니다:

- [AI의 설정](../inference-providers.md)(일반 설정의 **GPU 잠금**), 언어 모델용;
- [Image Generator](../extensions/image-generator.md#one-gpu-for-the-model-and-the-images)의 백엔드;
- [Audiobook](../extensions/audiobook-server.md#one-gpu-for-the-model-and-the-speech)의 백엔드.

**GPU 잠금** 입력란은 잠금이 하나 이상 있을 때만 표시됩니다.

<a id="how-the-turns-work"></a>

## 차례 진행 방식

- 모델에 대한 모든 요청, 모든 이미지, 그리고 오디오북의 모든 배치나 샘플은 자신의 AI 또는 백엔드의 잠금을 **그 작업이 끝날 때까지** 점유합니다.
- GPU가 이미 그 잠금으로 적재되어 있으면, 작업은 즉시 시작되고 아무 단계도 실행되지 않습니다.
- GPU가 다른 잠금으로 적재되어 있으면, 작업은 그 잠금의 작업들이 끝날 때까지 기다립니다. 그다음 그 잠금의 **해제 단계**를 모두 실행하고(하나가 실패해도 전부 실행합니다), 새 잠금의 **획득 단계**를 순서대로 실행합니다. 첫 실패에서 중단되며, 작업은 해당 단계의 메시지와 함께 실패합니다.
- 해제 단계가 실패하면 새 잠금은 전혀 적재되지 않습니다(카드가 여전히 가득 차 있을 수 있으므로). 작업은 오류와 함께 실패하고, GPU는 기존 잠금을 유지합니다. 다른 잠금의 다음 작업이 다시 비우기를 시도합니다.
- 작업이 끝난 뒤에도 GPU는 자기 잠금을 **그대로 유지한 채 적재되어 있습니다**. 타이머로 해제되는 것은 없습니다. 열어 둔 채로, 접혀 있거나 닫힌 이미지 창은 GPU를 점유하지 않지만, 이미지 모델은 언어 모델(또는 다른 잠금)이 카드를 필요로 할 때까지 적재된 상태로 남습니다.
- 작업은 들어온 순서대로 기다립니다. 작업 하나가 다른 잠금을 기다리기 시작하면, 적재된 잠금의 새 작업들은 그 뒤에서 기다립니다. 그래서 바쁜 언어 모델이 이미지를 무한정 기다리게 만들지는 못합니다.
- 잠금이 없거나 삭제된 잠금을 가리키는 AI 또는 백엔드는 아무것도 기다리지 않습니다.

GPU에 무엇이 올라가 있는지는 애플리케이션이 실행되는 동안에만 알려집니다. 재시작 후에는 아무것도 적재된 것으로 알려지지 않으므로, 첫 작업은 획득 단계만 실행합니다.

<a id="the-tab"></a>

## 탭

이 탭에는 GPU 목록이 나오며, 각 GPU에 지금 적재된 잠금(아무것도 실행되지 않았거나 해제된 경우 *Unknown*)과 그 GPU에서 실행 중이거나 대기 중인 작업 수가 표시됩니다. 이어서 잠금과 단계가 나오며, 각각 추가, 편집, 삭제 버튼이 있습니다. **새로 고침**은 GPU가 무엇을 가지고 있는지 다시 읽습니다.

**지금 해제**는 GPU를 직접 비웁니다. 예를 들어 Marginalia 밖의 용도로 카드를 쓰고 싶을 때 사용합니다. 실행 중인 작업을 기다리고, 적재된 잠금의 해제 단계를 실행한 뒤, GPU를 알 수 없는 상태로 둡니다. 단계가 실패해도 마찬가지이며, 메시지에 어느 단계에서 실패했는지 나옵니다. 다음 작업이 자신의 잠금을 다시 적재합니다.

GPU를 삭제하면 그 잠금들도 삭제됩니다. 단계를 삭제하면 그 단계를 실행하던 잠금에서 빠집니다. 삭제된 잠금을 지정했던 AI와 백엔드는 잠금 없이 실행됩니다.

<a id="an-example-one-card-three-models"></a>

## 예: 카드 하나, 모델 세 개

LiteLLM 뒤에 `llama-server`가 있고, 컨테이너를 시작하고 중지하는 [`tools/gpu-control`](../extensions/audiobook-server.md#what-answers-those-addresses) 방식의 프록시가 있는 경우:

| 단계 | 요청 |
|---|---|
| 언어 모델 해제 | 헤더 `X-Llama-Unload: all`를 포함한 `POST http://litellm:4000/v1/chat/completions` 요청([다른 모델을 위해 GPU 비우기](../prompt-cache.md#freeing-the-gpu-for-another-model) 참고) |
| ComfyUI 시작 / ComfyUI 중지 | `POST http://litellm:4000/gpu/comfy/start` / `.../stop` |
| 음성 시작 / 음성 중지 | `POST http://litellm:4000/gpu/tts/start` / `.../stop` |

| 잠금 | 획득 단계 | 해제 단계 | 동시 작업 수 |
|---|---|---|---|
| 언어 모델 | (없음: 라우터가 다음 요청 때 적재합니다) | (없음) | 0 |
| ComfyUI | 언어 모델 해제, ComfyUI 시작 | ComfyUI 중지 | 1 |
| Speech | 언어 모델 해제, 음성 시작 | 음성 중지 | 1 |

언어 모델의 AI는 *언어 모델* 잠금을, 이미지 백엔드는 *ComfyUI* 잠금을, 음성 백엔드는 *Speech* 잠금을 고릅니다. 채팅 뒤의 음성 배치는 *언어 모델 해제*와 *음성 시작*을 실행하고, 다음 채팅 메시지는 먼저 *음성 중지*를 실행합니다.
