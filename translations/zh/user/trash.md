# 回收站

在 Marginalia 中删除内容并不会立即销毁任何东西：被删除的书籍、设定集、故事段落或推理提供方只是被标记为已删除，并从你的列表中隐藏。**回收站**标签页列出这些已删除的对象，并可将它们恢复回来。

已删除的对象会留在回收站中，直到管理员运行[清理](administration/cleanup.md)，清理会将它们从数据库中永久移除。清理删除的内容无法再恢复（只有之前制作的[数据库备份](administration/database-backups.md)仍保存着它们）。

![回收站标签页](../images/trash-tab.png)

表格会随着你滚动而加载。最近删除的对象排在最前面。

| 列 | |
|---|---|
| （复选框） | 选择要恢复的对象。表头中的复选框会选择所有对象。 |
| **类型** | 对象的种类：书籍、设定集、设定集条目、消息（故事段落）、段落的版本（[版本历史](books/version-history.md#deleting-versions)中已删除的条目，恢复它会将其移出历史回收站）、摘要、模型（推理提供方）、协议、标签、代理、代理运行、资源……|
| **名称** | 对象的名称。故事段落和标签链接没有名称，会显示其 id；要阅读故事段落，请使用*扩展内容*。 |
| **用户** | 对象的所有者。只有管理员能看到这一列。 |
| **删除时间** | 对象被删除的时间。 |
| **扩展内容** | 打开对象的已保存数据，参见[下文](#extended-content)。 |

在表格上方，**类型**只显示一种对象，**刷新**会重新加载表格。

<a id="restoring"></a>

## 恢复

勾选你想要找回的对象，然后点击**恢复所选**。Marginalia 在恢复前会先询问你。对象会回到它们所在的列表中，与删除时完全一致，其他标签页也会随之刷新。

<a id="objects-that-belong-to-other-objects"></a>

### 属于其他对象的对象

删除一个对象会同时删除属于它的内容，恢复它时也会把这些内容一并带回：书籍会连同它的故事段落、这些段落的摘要和它的标签一起恢复；设定集会恢复它的条目；故事段落会恢复它的摘要以及其下方的段落；推理提供方会恢复它的用量统计。你无需勾选这些内容：恢复书籍，它的故事就会随之回来。这些内容会在表格中以单独的行出现（一本篇幅很长的书会让表格中充满它的段落）；如果只恢复其中一个，只有在它所属的对象未被删除时才能成功。你之前单独删除过的内容（例如某个条目、某个故事段落）也会随设定集或书籍一起恢复，因为 Marginalia 无法将它们与同时删除的内容区分开来。

有些对象离不开其他对象：

- 条目需要它的设定集；
- 故事段落和摘要需要它们的书籍；
- 书籍需要它的模型（推理提供方）、它的协议以及它的设定集，只要它在使用这些内容；
- 标签链接需要它的标签。

如果一个对象所属的设定集、书籍等已被删除，它**只能与之一同恢复**：两者都要勾选。如果你只勾选了条目，Marginalia **不会恢复任何内容**，并会告诉你缺少什么：

> 未恢复任何内容。这些对象需要一个未被选中的已删除对象。请也选中它，或让它们保持删除状态。
> 设定集条目 "mosh" 需要已删除的设定集 "Phrasebook"（设定集）

![因条目所属的设定集也已删除而被拒绝的恢复操作](../images/trash-restore-blocked.png)

勾选它所指明的对象，然后再次恢复。已经不再被删除的对象（期间已被恢复，或你并未删除过的对象）不会造成问题。

!!!info 恢复故事段落
从故事中间删除的故事段落，其后续段落会被移动到它的父段落下。恢复它时，段落会作为一个新分支重新出现在其父段落之下，但**不包括**它之后的段落：那些段落仍停留在被移动到的位置。如果你希望恢复故事原来的样子，请恢复整本书，而不是单个段落。
!!!

<a id="deleting-for-good"></a>

## 永久删除

有时你不想等待清理：你确定不再需要的故事段落或设定集条目，可以立即移除。勾选它并点击**永久删除**；Marginalia 会先询问你，而且**此操作无法撤销**。

![永久删除一个故事段落](../images/trash-delete-permanently.png)

- 只有**故事段落**和**设定集条目**可以被永久删除（连同它们的摘要和标签）。当勾选了其他任何类型的对象时，该按钮会被禁用：书籍、设定集以及其余对象都要等待管理员的[清理](administration/cleanup.md)，这样你就不会意外删除整本书。
- 位于被移除段落之下的故事段落不会随之移除，无论它们是否已被删除：它们会移动到该段落的父段落下，与你在编辑器中删除段落时的做法一致。如果该段落正是某本书打开时所在的位置，这本书会改为在父段落处打开。
- 当某个对象无法被移除时（例如某个扩展仍需要该对象），Marginalia 不会删除任何内容，并会告诉你是哪一个对象。

<a id="extended-content"></a>

### 扩展内容

Marginalia 会将对象的大部分数据（故事段落的文本、设定集条目的设置、[扩展](extensions/index.md)保存的笔记）以 JSON 的形式保存在对象旁边。行中的**扩展内容**会显示这些数据，以便你在恢复对象之前检查它包含什么，例如用来找到正确的故事段落。没有此类数据的对象（资源）没有链接；没有扩展内容的对象会显示*此对象没有扩展内容。*

<a id="administrators"></a>

## 管理员

管理员可以看到**所有用户**的已删除对象，并可以恢复其中任何一个。表格上方的**用户**筛选器可显示某一位用户的对象；**用户**列会显示对象属于谁。恢复的对象会回到其所有者名下。

同一张表格也位于*管理 → 清理*（**回收站**）中，因此你可以看到下一次清理会移除哪些内容。已删除用户的对象无法恢复：它们依赖于该用户。
