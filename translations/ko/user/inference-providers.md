# 추론 제공자

추론 제공자(inference provider)는 모델에 연결하는 설정입니다. API 주소, API 키, 모델과 그 제한값을 담고 있습니다. 모든 책은 제공자 하나를 사용합니다. 제공자는 원하는 만큼 만들 수 있습니다. 예를 들어 이야기에는 큰 클라우드 모델을, 실험에는 작은 로컬 모델을 쓸 수 있으며, 책마다 언제든지 바꿔 쓸 수 있습니다.

제공자는 사용자 계정에 속합니다. 다른 사용자는 제공자와 API 키를 볼 수 없습니다. API 키는 암호화되어 저장됩니다(see [The data folder](administration/index.md#the-data-folder)).

제공자를 추가하려면 **자체 모델 만들기** 권한이 필요하며, 이 권한은 관리자가 부여합니다(관리자는 항상 이 권한을 가집니다. [Permissions](administration/permissions.md) 참고). 이 권한이 없으면 관리자가 [공유](#shared-providers)한 제공자만 사용할 수 있고, **추론 제공자 추가** 버튼은 보이지 않습니다.

## 지원하는 API

Marginalia는 **OpenAI Chat Completions** 인터페이스(`/v1/chat/completions`, 스트리밍 포함)를 구현한 모든 API와 함께 작동합니다. 대부분의 서비스와 로컬 서버가 이를 지원합니다:

| 서비스 | OpenAI URL |
|---|---|
| OpenAI | `https://api.openai.com/v1` |
| OpenRouter | `https://openrouter.ai/api/v1` |
| LiteLLM proxy | `http://localhost:4000/v1` |
| llama.cpp (`llama-server`) | `http://localhost:8080/v1` |
| LM Studio | `http://localhost:1234/v1` |
| Ollama | `http://localhost:11434/v1` |
| vLLM | `http://localhost:8000/v1` |

포트는 각 서버의 기본값입니다. 실제로 서버가 사용하는 포트를 사용하세요.

!!!warning 포트 8080
Docker 버전의 Marginalia도 포트 8080을 사용합니다. 같은 컴퓨터에서 llama.cpp를 실행한다면 다른 포트에서 시작하세요(`llama-server --port 8081`).
!!!

!!!
[Docker 버전](getting-started/docker-server.md)에서 `localhost`은 Marginalia 컨테이너를 가리킵니다. 같은 컴퓨터에 있는 모델 서버에는 `http://host.docker.internal:<port>/v1`을 사용하세요. [같은 컴퓨터의 모델](getting-started/docker-server.md#models-on-the-same-machine)을 참고하세요.
!!!

## 제공자 추가

**추론 제공자** 탭을 열고 **추론 제공자 추가**를 누릅니다. 기존 제공자는 연필 버튼으로 편집하고 휴지통 버튼으로 삭제합니다. 복제 버튼(종이 두 장 모양)은 제공자를 복사합니다. 확인하는 이름으로 저장되며, 원본 이름에 *(Copy)*가 붙습니다. 복사본은 주소, 모델, **API 키**(또는 확장 기능의 설정), 추론 설정, 토큰 제한과 매개변수를 원본과 똑같이 가지므로, 같은 서비스의 두 번째 모델은 이름만 정하고 클릭 한 번이면 됩니다. 복사본은 공유되지 않으며 고유한 한도나 사용량을 갖지 않습니다. 복제할 수 있는 것은 본인의 제공자뿐입니다(키를 볼 수 없는 관리자의 공유 제공자는 제외). 또한 제공자를 만들 권한이 있을 때만 복제할 수 있습니다.

대화상자 상단에는 다음 항목이 있습니다:

| 항목 | |
|---|---|
| **이름** | 제공자의 이름입니다. 책에 사용할 모델을 고를 때 표시됩니다. 모델명을 포함하세요. 예: `OpenRouter - Claude Sonnet`. |
| **유형** | API의 종류입니다: **OpenAI 호환**, 또는 [확장 기능](extensions/index.md)이 제공하는 제공자를 위한 **확장 기능**(해당 확장 기능이 로드된 동안에만 제공됩니다. 예: [Google Gemini](extensions/google-genai.md) 또는 [Anthropic Claude](extensions/anthropic.md)). 제공자를 만든 뒤에는 유형을 바꿀 수 없습니다. |
| **제공자** | 유형이 **확장 기능**일 때만 쓰입니다: 이 제공자가 어떤 확장 기능의 제공자인지 정합니다. 그 확장 기능의 고유 설정은 *유형별 설정* 탭에 채워집니다. |

### 유형별 설정

![유형별 설정, 모델 목록이 불러와진 상태](../images/inference-provider.png)

이 탭은 대화상자보다 길어서 스크롤됩니다. 아래쪽 항목은 다음과 같습니다:

![제한 시간, 재시도 횟수, 추가 매개변수, 연결 테스트](../images/inference-provider-2.png)

| 항목 | |
|---|---|
| **OpenAI URL (/v1로 끝남)** | API의 기본 주소입니다. [위의 표](#supported-apis)를 참고하세요. `/chat/completions`은 빼고 입력합니다. |
| **API 키** | 서비스의 키입니다. 로컬 서버는 보통 키를 확인하지 않습니다. 이 항목을 비워 두면 Marginalia는 자리 표시자 `none`를 보냅니다. |
| **모델** | 사용할 모델입니다. **새로 고침**을 눌러 API에서 모델 목록을 불러오거나, 모델 ID를 직접 입력하세요(예: OpenRouter의 `anthropic/claude-sonnet-4.5`). |
| **제한 시간 (초)** | API가 응답할 때까지, 그리고 글을 쓰기 시작한 뒤 다음 텍스트가 올 때까지 기다리는 시간입니다. 기본값은 300입니다. 추론 모델은 첫 텍스트가 나오기까지 몇 분이 걸릴 수 있습니다. 이 시간 동안 아무 응답도 없는 요청은 제한 시간 초과 메시지와 함께 실패합니다(모델의 추론 과정도 텍스트로 칩니다. 따라서 계속 생각하는 모델은 중단되지 않습니다). 변경한 값은 다음 요청에 적용되며, 작업 중인 에이전트의 요청도 마찬가지입니다. |
| **재시도 횟수** | API가 요청 한도 초과(429)나 서버 오류(5xx)로 응답하거나 연결할 수 없을 때 요청을 몇 번 반복할지 정합니다. 시도 사이의 대기 시간은 점점 길어지며, API의 `Retry-After` 헤더를 따릅니다. 기본값은 2이며, 0으로 두면 재시도를 끕니다. 재시도되는 것은 요청의 시작 부분뿐이며, 이미 도착한 텍스트가 두 번 쓰이는 일은 없습니다. |
| **토크나이저** | Marginalia가 이 제공자에 대해 텍스트의 토큰을 세는 방법입니다. **자동**(기본값)은 서버의 토크나이저 엔드포인트(OpenAI, llama.cpp, LiteLLM)를 차례로 시도해 처음으로 응답하는 것을 사용하고, 어느 것도 응답하지 않으면 로컬 추정치를 사용합니다. 하나를 고르면 그것만 사용합니다. **LOCAL_TOKKIT**은 서버를 호출하지 않는 로컬 추정치입니다(토큰을 세는 과정에서 서버가 다른 모델을 불러와야 할 때 유용합니다). 플러그인이 제공하는 토크나이저도 여기에 나열되며, 주소, 모델, 텍스트를 받지만 API 키는 받지 않고, 직접 선택했을 때에만 사용됩니다. **토크나이저 테스트**는 제공자가 시도할 방법들로 샘플 텍스트의 토큰을 세고, 각각이 어떻게 응답했는지 보여 줍니다. 제공자를 새로 만들면, 직접 선택하기 전까지 주소에 맞는 플러그인 토크나이저가 미리 선택됩니다. |
| **추론 과정을 다시 보내기** | 다음 요청에서 모델이 자신의 추론 과정을 다시 받을지 여부입니다. [추론 과정을 다시 보내기](#send-the-thinking-back)를 참고하세요. OpenAI 호환 제공자에만 해당합니다. Anthropic과 Google 제공자는 각자의 API가 필요로 하는 것을 스스로 보냅니다. |
| **추가 매개변수** | 이 제공자에 대한 모든 요청에 추가할 필드들을 담은 JSON 객체입니다. 예: 로컬 서버용 `{"top_k": 40, "min_p": 0.05}`, 또는 OpenRouter용 `{"provider": {"order": ["anthropic"]}}`. 여기서 설정한 필드는 [프로토콜](protocols.md)(예: `temperature`)이나 응답 한도(`max_completion_tokens`)의 같은 설정보다 우선합니다. 올바른 JSON 객체이거나 비어 있어야 합니다. |

기존 제공자를 편집할 때 API 키는 다시 표시되지 않습니다. **API 키 초기화**를 누르고 새 키를 입력하지 않는 한 현재 값이 그대로 유지됩니다.

**새로 고침**은 양식에 입력된 URL과 키로 API에 모델 목록(`/v1/models`)을 요청합니다. *Failed to download model list*라는 메시지와 함께 실패하면 URL(`/v1`로 끝나야 합니다), 키, 서버가 실행 중인지 확인하세요. 일부 서비스는 모델 목록을 제공하지 않으므로, 대신 모델 ID를 입력하세요.

**연결 테스트**는 저장하지 않고 양식의 값을 확인합니다. API에 모델 목록을 요청한 다음, 선택한 **모델**로 한 토큰짜리 응답을 요청합니다. 재시도는 하지 않습니다. 성공 메시지는 URL, 키, 모델이 함께 작동한다는 뜻입니다. 실패하면 원인이 표시됩니다([오류 메시지](#error-messages) 참고). 모델 목록이 없는 서비스도 있으며, 이 경우 테스트는 한 토큰짜리 응답만 확인합니다.

### 일반 설정

![추론 제공자의 일반 설정](../images/inference-provider-general.png)

| 항목 | |
|---|---|
| **최대 컨텍스트 크기** | 필수 항목입니다. 프롬프트와 응답을 합쳐 모델이 받아들이는 토큰의 총량입니다. |
| **최대 응답 토큰** | 필수 항목입니다. 모델이 쓸 수 있는 가장 긴 응답입니다. API에는 `max_completion_tokens`로 전달되며, 이만큼의 컨텍스트가 응답을 위해 비워 둡니다. *최대 컨텍스트 크기*보다 작아야 합니다. |
| **연결** | 이 모델로 동시에 진행 중일 수 있는 요청 수입니다. 모든 사용자와 모든 종류(사용자의 생성, 부가 질의, 번역, 주석, [에이전트](agents.md#one-model-several-agents), 플러그인)의 요청이 모두 포함됩니다. 나머지 요청은 들어온 순서대로 차례를 기다립니다. 대기 중인 생성은 *Waiting for the model: N requests before this one*라고 표시되며, **중지**를 누르면 대기열에서 빠집니다. 기본값은 **1**입니다. 한 번에 하나의 슬롯만 있는 로컬 서버(GPU 하나)에 적합합니다. 여러 요청에 동시에 답하는 클라우드 모델은 더 많이 설정해서, 생성과 함께 부가 질의를 동시에 실행할 수 있습니다. |
| **로어 이미지 전송** | 한 턴이 사용하는 [로어북 항목의 이미지](lorebooks/lorebooks.md#editing-in-full-screen)를 텍스트와 함께 보냅니다. 기본적으로 꺼져 있습니다. 이미지를 받을 수 있는 모델에서만 켜세요. 비전을 지원하지 않는 모델은 요청을 거부하고 턴이 실패합니다. 로어 블록에 있는 항목의 이미지는 시스템 프롬프트 바로 뒤에 별도의 메시지로 들어가며(모델의 짧은 답변과 함께), 나머지는 사용자의 프롬프트와 함께 들어갑니다. |
| **시스템 메시지의 이미지** | (OpenAI 호환, *로어 이미지 전송*을 켠 경우) 로어 블록의 이미지를 로어 텍스트 옆에 있는 시스템 메시지 자체에 넣습니다. 이미지를 그곳에서 받는 서버와 채팅 템플릿에서만 사용하세요. 대부분은 지원하지 않으며, 그럴 경우 요청이 실패합니다. |
| **탈옥 필요**, **탈옥 프롬프트** | 일부 내용의 작성을 거부하는 모델을 위한 추가 프롬프트입니다. 체크하면 탈옥 프롬프트가 프롬프트의 가장 앞에 놓입니다. |
| **추론(Reasoning) 사용**, **추론 강도** | 추론("생각") 모델용입니다. [추론 모델](#reasoning-models)을 참고하세요. |

Marginalia는 컨텍스트 중 **최대 응답 토큰**만큼을 응답을 위해 비워 두고, 나머지를 프롬프트로 채웁니다. 템플릿, [로어북](lorebooks/index.md) 항목, [요약](books/summaries.md)이 여기에 포함되며, 들어가지 못하는 이야기의 가장 오래된 부분은 제외됩니다. 컨텍스트가 32 000 토큰이고 응답이 최대 2 000 토큰이면, 프롬프트는 30 000 토큰을 사용합니다.

**최대 컨텍스트 크기**는 서비스의 문서에서 가져오되, 조금 낮게 설정하세요. 토큰 수는 항상 정확하지 않으며, 실제 한도를 넘는 요청은 실패합니다. [프로토콜](protocols.md)은 일부 책에 대해 두 한도를 모두 낮출 수 있지만, 높일 수는 없습니다.
<a id="error-messages"></a>

## 오류 메시지

API가 요청을 거부하면, Marginalia는 내부 오류를 보여 주는 대신 무엇을 고쳐야 하는지 알려 주고, 이어서 API 자체가 한 말을 보여 줍니다:

![사용자에게 표시되는 제공자의 오류](../images/error-dialog.png)

| 메시지 | 원인 |
|---|---|
| *제공자가 API 키를 거부했습니다.* | **API 키**가 잘못되었거나, 만료되었거나, 비어 있습니다. |
| *이 API 키로는 이 모델이나 엔드포인트를 사용할 수 없습니다.* | 키는 유효하지만 해당 모델에 접근 권한이 없습니다. |
| *제공자가 설정된 모델을 알지 못합니다.* | **모델**이 잘못되었습니다. **새로 고침**을 사용하면 API가 알고 있는 이름을 볼 수 있습니다. |
| *설정된 URL에서 아무것도 찾을 수 없습니다.* | **OpenAI URL**이 잘못되었습니다. 보통 `/v1`로 끝납니다. |
| *프롬프트가 모델의 컨텍스트에 들어가지 않습니다.* | **최대 컨텍스트 크기**가 모델이 실제로 받아들이는 값보다 큽니다. 값을 낮추십시오. |
| *제공자가 요청을 제한하고 있습니다.* | 재시도 후에도 속도 제한에 걸렸거나 할당량을 모두 썼습니다. |
| *제공자가 요청을 처리하지 못했습니다.* | 재시도 후에도 서비스에 문제가 있습니다(5xx). |
| *제공자가 제시간에 응답하지 않았습니다.* | **제한 시간 (초)** 값을 올리거나 서버를 확인하십시오. |
| *제공자에 연결할 수 없습니다.* | 서버가 실행 중이 아니거나 Marginalia에서 접근할 수 없거나, URL에 오타가 있습니다. |
| *제공자가 요청을 거부했습니다.* | 그 밖의 거부 사유로, 대개 **추가 매개변수**에 지원되지 않는 필드가 있거나 모델이 지원하지 않는 추론을 요청한 경우입니다. |

<a id="warning-before-sending"></a>

## 전송 전 경고

Marginalia는 컨텍스트를 **최대 컨텍스트 크기**에서 **최대 응답 토큰**을 뺀 만큼까지만 채웁니다. 완성된 프롬프트가 그보다 여전히 크면(예를 들어 확장 기능이 텍스트를 덧붙였거나 토큰 수 계산이 틀렸을 때), 요청을 보내기 전에 추정 크기를 보여 주는 경고가 나타납니다. 요청은 그래도 전송됩니다. API가 거부하거나 프롬프트를 잘라낼 수 있습니다.

![들어가지 않을 수 있는 프롬프트에 대한 경고](../images/context-warning.png)

<a id="reasoning-models"></a>

## 추론 모델

추론 모델은 답하기 전에 생각합니다. **추론(Reasoning) 사용**을 체크하면, Marginalia는 선택한 **추론 강도**(*없음*, *낮음*, *중간* 또는 *높음*)를 `reasoning_effort`로 API에 보냅니다. 강도를 높이면 대개 더 잘 계획된 텍스트가 나오지만, 응답은 느려지고 비용도 더 듭니다. 모든 API가 이 매개변수를 지원하지는 않습니다. 추론을 켠 상태에서 요청이 실패하면 끄십시오.

모델이 추론 과정을 돌려주면(서버에 따라 `reasoning_content` 또는 `reasoning`로), 생성된 부분 위에 **추론 과정 보기** 아래에 표시됩니다. 추론 과정은 이야기의 일부가 아니며, 아래의 **추론 과정을 다시 보내기**를 설정하지 않는 한 모델에 다시 보내지지 않습니다.

<a id="send-the-thinking-back"></a>

### 추론 과정을 다시 보내기

**추론 과정을 다시 보내기**(OpenAI 호환 제공자의 *유형별 설정*에 있음)는 모델의 추론 과정을 다음 요청에서 모델에게 되돌려 보낼지 정합니다. 이는 이전 메시지의 `reasoning_content`로 전달됩니다:

| 값 | |
|---|---|
| **없음** (기본값) | 절대 보내지 않습니다. 대부분의 모델과 서버에 알맞고, 알 수 없는 필드를 거부하는 API에도 알맞습니다. |
| **도구 호출 사이** | 한 답변의 도구 호출이 계속되는 동안에만 보냅니다. 도구를 호출한 모델은 결과와 함께 자신의 추론 과정을 돌려받습니다. 사용자의 새 메시지는 이전 추론 과정 없이 시작합니다. Google이 Gemma 4에 요구하는 방식입니다(*함수 호출 사이에서는 추론을 제거하면 안 되지만, 턴 사이에서는 제거합니다*). |
| **항상** | 채팅이 보관하고 있는 이전 답변의 추론 과정도 함께 보냅니다(Arc Outline의 플롯 마법사가 이렇게 합니다). 오래된 추론을 스스로 버리는 템플릿을 가진 서버(예: Gemma 4의 서버)는 이 설정을 무시합니다. |

이 설정은 도구 루프(플롯 마법사, 도구를 사용하는 생성기)와 에이전트에 적용됩니다. 에이전트는 한 턴의 도구 호출이 계속되는 동안 이전 라운드의 추론 과정을 돌려받습니다(추론 과정은 저장된 메시지가 아니라 콘솔의 메시지와 함께 보관됩니다). 서버가 이 필드를 받아들여야 합니다. llama.cpp는 받아들입니다(`reasoning`가 아니라 `reasoning_content`를 읽습니다). LiteLLM을 거치는 경우에도 마찬가지입니다. 알 수 없는 메시지 필드를 거부하는 제공자에서는 실패하므로, 그때는 *없음*으로 두십시오.

![생성된 부분의 추론 과정](../images/reasoning-view.png)

추론도 응답 길이에 포함됩니다. 추론 모델에는 **최대 응답 토큰**을 더 크게 주십시오. 그렇지 않으면 긴 추론 뒤에 텍스트가 잘릴 수 있습니다.

<a id="token-counting"></a>

## 토큰 계산

Marginalia는 프롬프트에 얼마나 많은 이야기가 들어갈지 정하기 위해 토큰을 셉니다. 가능하면 제공자에게 묻고, 다음 방법을 순서대로 시도합니다:

1. OpenAI 토큰 계산 엔드포인트(`/v1/responses/input_tokens`),
2. llama.cpp의 `/tokenize` 엔드포인트,
3. LiteLLM의 `/tokenize` 엔드포인트,
4. LiteLLM의 `/v1/messages/count_tokens` 엔드포인트(Anthropic 모델용),
5. OpenAI 토크나이저를 이용한 로컬 추정.

처음으로 작동한 방법이 그 뒤로 계속 사용됩니다. 로컬 추정은 대부분의 모델에서 꽤 가깝지만 정확하지는 않습니다. 이것이 **최대 컨텍스트 크기**를 실제 한도보다 조금 낮게 두어야 하는 또 하나의 이유입니다. *Extension* 유형의 제공자는 각 확장 기능이 말하는 방식대로 계산하며, [Google Gemini](extensions/google-genai.md)와 [Anthropic Claude](extensions/anthropic.md) 제공자는 계산을 제공자에게 맡깁니다.

<a id="prompt-cache"></a>

## 프롬프트 캐시

Marginalia가 한 종류의 작업(새 부분, 주석, 다시 쓰기, 요약 등)을 위해 보내는 모든 요청에는 헤더 `X-Session-ID`가 붙습니다. 이는 같은 사용자와 같은 종류의 작업에 대해 항상 같은 해시 값입니다. 프롬프트 캐시를 유지하는 서버나 프록시는 이를 이용해 같은 종류의 이전 요청의 캐시를 찾을 수 있습니다. 이를 모르는 서버는 무시합니다. 디스크에 저장된 llama.cpp 슬롯 하나를 쓰는 예시는 [프롬프트 캐시와 세션 ID](prompt-cache.md)를 보십시오.

<a id="shared-providers"></a>

## 공유 제공자

여러 사용자가 있는 설치에서 관리자는 제공자를 **공유**할 수 있습니다. 제공자의 대화상자에서 **모든 사용자와 공유됨**을 체크하십시오(이 체크박스는 관리자에게만 보입니다). 그러면 모든 사용자는 자신의 책의 **모델** 목록과 **추론 제공자** 탭에서 이를 찾게 되며, *공유됨* **예**로 표시됩니다. 사용자는 이를 사용할 수는 있지만, 열어 보거나, 주소나 API 키를 보거나, 바꾸거나, 삭제할 수는 없습니다. 이는 소유자만 할 수 있습니다. 공유 제공자를 참조하는 책, 백업, 복원은 그것을 볼 수 있는 모든 사용자에게 계속 작동합니다.

![일반 사용자의 추론 제공자 탭에 있는 공유 제공자](../images/provider-shared-user.png)

제공자를 공유하면 다른 사용자가 소유자의 서비스 할당량을 쓸 수 있습니다. 사용자가 자신의 제공자를 추가하지 못하게 하고 공유된 제공자만 쓰게 하려면, [사용자와 제공자](administration/users.md#users-and-providers)를 보십시오.
<a id="limits-of-shared-providers"></a>

## 공유 제공자의 제한

관리자는 공유 제공자마다 사용자가 그 제공자로 할 수 있는 일을 제한할 수 있습니다. **추론 제공자** 탭에서 공유 제공자를 소유한 관리자에게는 해당 행에 **제한** 버튼(자물쇠 모양 사용자 아이콘)이 있습니다. 이 버튼을 누르면 설정된 제한이 표 형태로 열립니다. **제한 추가**를 누르면 새 제한을 만들 수 있으며, 이때 사용자와 제한 유형을 고릅니다.

![공유 제공자의 제한](../images/provider-limits.png)

| 제한 유형 | 의미 |
|---|---|
| 무제한 | 제한 없음(제한이 없는 것과 같습니다). |
| 토큰 제한 | 사용자는 기간마다 지정한 수만큼의 토큰을 사용할 수 있습니다. |
| 사용 불가 | 사용자는 제공자를 쓸 수 없으며, 이 제공자로 요청을 보내려는 모든 작업이 실패합니다. |

**토큰 제한**에는 **초기화** 주기(매일, 월요일부터 시작하는 매주, 또는 매월; 달력 기간은 서버의 시간대 기준)가 있고, 전송된 토큰(**전송**), 생성된 토큰(**생성**), 그리고 둘의 합(**총합**) 세 가지 한도를 각각 비워 두어 제한 없음으로 둘 수 있습니다. 먼저 도달한 한도가 다음 초기화 때까지 사용자를 막습니다. 세 가지를 모두 설정하면 전송 한도와 생성 한도의 합이 총합 한도보다 작아서는 안 됩니다(그렇지 않으면 총합에 결코 도달할 수 없습니다). 그렇지 않으면 대화상자가 저장을 거부합니다. 예를 들어 총합 100,000에 전송 100,000, 생성 20,000은 괜찮지만, 총합 100,000에 전송 20,000, 생성 10,000은 안 됩니다.

![제한 추가하기](../images/provider-limit-edit.png)

어떤 것도 타이머로 초기화되지 않습니다. 사용된 토큰은 사용자가 새 기간에 제공자를 처음 사용하거나(또는 자신의 제한을 처음 확인할 때) 0부터 시작합니다. 요청의 크기는 전송 전에 알 수 있으므로, 프롬프트가 사용자를 **전송** 또는 **총합** 한도 너머로 밀어낼 요청은 거부됩니다(프롬프트는 Marginalia 자체의 추정치로 측정되며, 서비스의 계산과 약간 다를 수 있습니다). **생성된** 토큰은 미리 알 수 없습니다. 요청이 끝날 때 집계되므로, 사용자는 한도에 도달한 뒤에야 막히며 마지막 응답이 한도를 넘을 수 있습니다. 표에 제한이 없는 사용자는 제한을 받지 않습니다.

생성된 토큰이 한도를 넘지 않게 하려면 **하드 제한**을 선택하십시오(생성 토큰 제한이 있을 때만 사용할 수 있습니다). 요청은 허용되는 가장 큰 응답 분량을 미리 예약합니다(제공자의 **최대 응답 크기**, 또는 프로토콜의 값 중 더 작은 값). 하드 제한이 걸려 있으면, 이 예약분이 남은 생성 한도에 들어가지 않을 때 요청이 거부됩니다. 따라서 제공자의 응답 크기보다 낮은 하드 제한은 모든 요청을 거부합니다. 표와 사용자의 정보 화면에는 이러한 제한 옆에 *hard*가 표시됩니다. 하드 제한은 생성된 토큰에만 적용되며, **총합** 제한은 마지막 응답 때문에 여전히 넘어설 수 있습니다.

모든 사용자는 자신의 탭에서 공유 제공자를 읽기 전용 행으로 봅니다. 공유 제공자의 **정보** 버튼(i가 들어간 원형 아이콘)을 누르면 자신의 제한이 표시됩니다. 이번 기간에 사용한 양, 제한 값, 그리고 초기화되는 시점입니다. 제한에 도달하면 스토리 편집기, 요약, 확장 기능은 요청을 보내는 대신 오류를 표시합니다.

![이번 기간에 사용한 양과 함께 사용자가 보는 제한](../images/provider-limit-info.png)

<a id="usage"></a>

## 사용량

**추론 제공자** 탭에는 제공자별로 **전송된 토큰**(프롬프트, "프리필")과 **생성된 토큰**(응답, 추론 포함)이 표시됩니다. 이는 모든 책, 요약, 확장 기능에서 합산한 값입니다. 공유 제공자는 사용자마다 별도의 집계가 있으므로, 자신의 몫만 보입니다.

관리자에게는 탭에 **사용자별 사용량** 버튼도 제공됩니다. 이 버튼을 누르면 모든 사용자가 모든 제공자에서 사용한 양(전송된 토큰, 생성된 토큰, 요청 수, 마지막 요청 시각)을 담은 표가 열립니다.

![사용자별 사용량](../images/provider-usage.png)

표시되는 수치는 서비스가 보고한 값입니다. 서비스가 수치를 보고하지 않거나(또는 중간에 멈춘 요청) 경우에는 [토큰 계산](#token-counting)에서 설명한 로컬 추정치로 집계되므로, 이 수치는 대략적인 값입니다. 텍스트가 전혀 도착하기 전에 실패한 요청은 집계되지 않습니다. 관리자가 공유 제공자에 대해 [제한](#limits-of-shared-providers)을 설정하지 않았다면, 이 집계값은 참고용입니다.

!!!
Marginalia는 서비스에 토큰 수를 보고해 달라고 요청합니다(`stream_options` 와 `include_usage`). 제공자에 대해 이를 바꾸려면, **추가 매개변수**에 직접 `stream_options` 항목을 넣으십시오. 예를 들면 `{"stream_options": {"include_usage": false}}` 같은 식입니다. 이 값은 Marginalia가 보내는 내용을 대체하며, 이때는 로컬 추정치가 사용됩니다.
!!!

<a id="using-a-provider-in-a-book"></a>

## 책에서 제공자 사용하기

각 책의 모델은 **정보** 탭의 **모델** 필드에서 정합니다. 새로 만드는 모든 책에 제공자를 적용하려면 **설정** 탭에서 해당 제공자를 **기본 모델**로 고르십시오. 책의 제공자를 바꾸면 다음에 생성되는 부분부터 적용되며, 그 전에 쓰인 부분은 그대로 남습니다.

<a id="troubleshooting"></a>

## 문제 해결

| 문제 | 확인할 사항 |
|---|---|
| *모델 목록을 내려받지 못했습니다* | URL이 `/v1`로 끝나는지, API 키, 서버가 실행 중이며 Marginalia에서 접근 가능한지 확인하십시오. 서비스에 모델 목록이 없다면 모델 ID를 직접 입력하십시오. |
| *제공자가 제시간에 응답하지 않았습니다.* | 제공자의 **제한 시간 (초)** 값을 올리십시오. 추론 모델은 몇 분이 걸리기도 합니다. |
| *제공자가 요청을 제한하고 있습니다.* | 기다리거나 **재시도 횟수**를 올리십시오. |
| *책에 모델이 없습니다.* | 책에 제공자가 없습니다. **정보 → 모델**에서 하나를 선택하십시오. |
| *컨텍스트 제한이 충분하지 않습니다.* | 이야기 없이 프롬프트만으로도 컨텍스트에서 응답 토큰을 뺀 크기에 들어가지 않습니다. **최대 컨텍스트 크기**(또는 프로토콜의 **최대 컨텍스트 토큰**)를 올리거나, **최대 응답 토큰**을 낮추거나, 템플릿과 로어북 항목을 줄이십시오. |
| 텍스트가 도중에 끊김 | **최대 응답 토큰**(또는 프로토콜의 **최대 응답 토큰**)이 너무 낮습니다. 특히 추론 모델에서 그렇습니다. |
