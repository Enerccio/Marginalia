# 导出书籍

导出会把故事变成一个可以阅读、打印、发送或在其他地方发布的文件。与[备份](backups.md)不同，它只包含文本，并且是一本成书的形式。

只导出[当前分支](branches-and-story-tree.md)，也就是故事编辑器所显示的那些部分。要导出故事的另一个版本，请先切换到该分支。

<a id="exporting"></a>

## 导出

1. 打开书籍，进入 **Story** 标签页。
2. 在底部栏点击设置菜单（⚙），选择 **Export story**。
3. 填写对话框，然后点击 **Export**。
4. Marginalia 会收集该分支的各个部分并写入文件，篇幅较长的书需要一点时间。进度条会显示完成的进度。
5. 文件准备好后，会弹出一个对话框提供下载。点击 **Download** 按钮即可保存。

![导出故事对话框](../../images/export-dialog.png)

| Field | |
|---|---|
| **Format** | 文件类型，见下文。 |
| **Print style** | 仅适用于具有字体和颜色的格式（HTML、Word、PDF、EPUB）。文本的外观，从*用于导出*的样式中选择：应用为这些格式各提供了一种样式，即 **HTML page**、**E-book (EPUB)**、**PDF book** 和 **Word document**。这些正是导出过去一直使用的外观，选择格式时会自动选用。你也可以制作自己的样式，见[打印样式](#print-styles)。你在[设置 → Exports](../account.md#exports)中为该格式选择的样式会被预先选中。 |
| **File name** | 下载文件的名称，不含 Marginalia 添加的扩展名。默认为书籍的名称。 |
| **Book title** | 文件中的标题（标题页和文件属性）。默认为书籍的名称；修改它不会重命名书籍。 |
| **Author** | 默认为你在[账户](../account.md)中填写的全名。留空则表示没有作者。 |
| **From message**, **To message** | 要导出的部分。部分按故事顺序从 1 开始计数，没有文本的部分不计入。将 **To message** 留空则导出至结尾。 |
| **Include title page** | 在文件开头加入一页，包含标题和作者。 |
| **Include authorship statement** | 在文件末尾加入一段简短声明，说明文字由谁写成：你写了多少字、模型生成了多少字，以字数和百分比表示，并注明模型。有些出版社和比赛会要求提供。它根据所导出部分的[版本历史](version-history.md)计算（见[标示生成文本](story-editor.md#highlighting-generated-text)）。SillyTavern 聊天格式不提供此项。措辞是[设置 → Exports](../account.md#exports)中的一个模板。 |

![已完成的导出文件，可供下载](../../images/export-download.png)

<a id="formats"></a>

## 格式

| Format | |
|---|---|
| **Plain text** (`.txt`) | 仅为 UTF-8 编码的文本。去掉*斜体*等格式，段落之间用空行分隔。 |
| **Markdown** (`.md`) | 文本保持故事中的书写形式，适用于 Obsidian、Typora 等编辑器、静态网站或代码仓库。强调、标题、引语、列表、代码块和场景分隔符都保留为 Markdown。文本中的原始 HTML 按原样保留，由 Markdown 阅读器决定是否显示。 |
| **HTML** (`.html`) | 一个包含书籍式样式的页面，因此在任何浏览器中外观都一致。可以打印，且没有外部文件。 |
| **Word document** (`.docx`) | 可在 Word、LibreOffice 及类似程序中打开。两端对齐的文本，标题和作者写入文件属性。 |
| **PDF** (`.pdf`) | A5 页面，嵌入的字体覆盖拉丁文、希腊文和西里尔文，并附带一款日文字体（Noto Sans JP），用于假名、汉字和日文标点。其他文字（仅限中文的字符、韩文、阿拉伯文）不会被绘制：PDF 中没有相应的字体。 |
| **EPUB** (`.epub`) | 适用于电子阅读器和阅读应用的电子书。篇幅较长的书会被拆分为 EPUB 内的多个文件，以保证阅读器运行流畅。 |
| **HTML for Archive of Our Own** (`.html`) | 用于发布到 AO3，见[下文](#for-other-tools)。 |
| **Markdown with front matter** (`.md`) | 用于静态网站生成器，见[下文](#for-other-tools)。 |
| **SillyTavern chat** (`.jsonl`) | 将故事作为聊天记录导出，见[下文](#for-other-tools)。 |
| **Obsidian vault** (`.zip`) | 将章节和 lorebook 作为相互链接的笔记导出，见[下文](#for-other-tools)。 |
| **LaTeX** (`.zip`) | 书籍的 LaTeX 项目（`main.tex` 和图片），见[下文](#for-other-tools)。 |

各部分的文本为 Markdown。强调、标题、引语、列表、代码块和场景分隔符（`---`）在每种能够显示它们的格式中都会保留。文本中的原始 HTML 会以文字形式显示，从不执行。

<a id="footnotes"></a>

## 脚注

脚注写在部分文本中：标记所在位置写作 `[^1]`，单独一行写作 `[^1]: 注释内容`（标签可以是任意词）。所有格式都支持脚注：**Markdown** 保留语法；**HTML**、**EPUB** 和 **HTML for Archive of Our Own** 会放置一个小号上标数字，链接到部分文本下方的注释（AO3 则保留其编辑器所用的普通标记）；**纯文本**将标记写作 `[1]`，并在部分文本之后以以 `[1]` 开头的行列出注释，这也是尾注的常见样式。**Word** 和 **PDF** 使用真正的脚注：标记是小号上标数字，注释位于同一页的底部，字号较小（PDF 中注释上方有一条短横线，页面会排版到每页都有足够空间容纳其注释为止；Word 自行编号并排放注释，因此编辑文档时它们会随之调整）。扩展也可以使用脚注：Conlang Translator 扩展会将每段发言的英文译文写成脚注。

<a id="images"></a>

## 图片

各部分的[图片](story-editor.md#images)会放在其位置所指定的地方（除非你选择了其他位置，否则位于文本之后），并附带说明文字，宽度为你设定的宽度（相对于文本宽度的百分比；未设定宽度时，图片保持其尺寸，并缩放以适应页面）。并非每种格式都能让文字环绕图片：

| Format | |
|---|---|
| **HTML**, **EPUB** | 嵌入（在页面中，或作为书籍的文件）。文字在图片左侧或右侧环绕；位于中间的图片会将文字分为两栏。在窄屏上，图片会置于文字上方；不支持分栏的阅读器（部分电子阅读器）会依次显示开头的文字、图片和其余文字。同一位置相邻的图片会排成一行。 |
| **Word document** | 文字环绕的图片放在一个小表格中，Word 会将其置于一侧或中间，并让文字环绕它（中间的图片两侧都环绕，逐行排列）；说明文字位于图片下方。宽度足以并排的图片构成表格的一行。 |
| **PDF** | 文字在图片的一侧环绕，说明文字绘制在图片下方。位于中间的图片会将文字分为两栏左对齐的文字（无法放入页末的区块会移至下一页）。宽度合适、可并排放置的图片构成一行。对于超出页面剩余空间的高图片，会移至下一页。 |
| **Markdown** | 以 `![caption](data:...)` 的形式嵌入文件，说明文字以斜体置于其下，因此仍然是一个文件。图片在文本中的位置会保留；宽度和文字环绕则不保留。并非所有阅读器都会显示嵌入的图片（GitHub 不显示），而且图片较多的书会产生很长的行，因此只有在需要 Markdown 导出中包含图片时，才将图片附加到各部分。 |
| **Plain text** | 在文本中的对应位置标记为 `[Image]` 或 `[Image: caption]`。 |
| **HTML for Archive of Our Own** | 标记为 `[Image: caption]`：AO3 只接受来自链接的图片。 |
| **Obsidian vault** | 保存在 vault 的 `Attachments` 文件夹中，并以斜体说明文字嵌入其所在章节的笔记中的对应位置。 |
| **LaTeX** | 保存在项目的 `images` 文件夹中，并在文本的对应位置引入（图形宽度与图片相同，且不超过文本宽度），说明文字位于其下方。文字不会环绕图片。 |
| **SillyTavern chat** | 省略，聊天记录只包含文本。 |
<a id="for-other-tools"></a>

## 其他工具

这些格式供读取它们的工具使用，而不是供阅读。它们没有*打印样式*选项。

**Archive of Our Own 用的 HTML。** AO3 要求在其自己的字段中填写标题、作者和章节标题，并会丢弃它不认识的内容（样式块、包裹文本的页面、非链接的图片），因此该文件没有标题页。在浏览器中打开即可看到粘贴到 AO3 后的效果。每一章（以标题开头的部分及其后直到下一个标题之前的部分）的标题位于两条注释 `BEGIN chapter N` 和 `END chapter N` 的上方：将两者之间的内容复制到 AO3 上该章的 HTML 编辑器中，并将标题填入其标题字段。文本是干净的 HTML，标签之间没有换行，因为 AO3 会把每个换行转换为 `<br>`。

**带前置元数据的 Markdown。** 与 *Markdown* 格式相同的 Markdown，但文件开头是一个 YAML 块（`title`、`author`、`lang`、导出的 `date`），供 Jekyll、Hugo、Eleventy 等生成器读取，而不是标题页；**包含标题页**对它无效。该块是一个模板，可在[设置 → 导出](../account.md#exports)中修改（`{{title}}`、`{{author}}`、`{{language}}`、`{{exportDate}}`；标题和作者已为用于双引号内部做好转义）。

**SillyTavern 聊天。** 一个 JSON Lines 文件，供 SillyTavern 的聊天导入功能读取：角色以书名命名，而你是作者。故事的每一部分都是角色的一条消息（正文）；如果该部分是带指令编写的，指令会作为你的消息放在其前面。如果该部分有模型的推理内容，则保留为该消息的推理内容。标题页不适用。

**Obsidian 仓库。** 一个以书名命名的文件夹的 ZIP 包；解压后将该文件夹作为仓库打开。它包含：一个以书名命名的笔记（前置元数据、标题页，以及章节和设定列表）；`Chapters` 中每章一个笔记（带有指向上一章和下一章的链接）；书的[设定集](../lorebooks/index.md)及其子设定集中每个已启用条目一个笔记，位于 `Lore/<lorebook>` 中（条目的标签即笔记的标签，其注释为提示框）；以及 `Attachments` 中的图片。在每个笔记中，条目名称的首次出现（至少三个字符的名称，整词匹配，按原样拼写）都会链接到该条目的笔记，因此关系图视图可以显示哪个条目出现在哪一章。带有标题的部分开始一章；第一个标题之前的部分为笔记 *Beginning*（若书中没有标题，则为 *Story*）。前置元数据和标题页是可在[设置 → 导出](../account.md#exports)中修改的模板。

**LaTeX。** 一个以书名命名的文件夹的 ZIP 包。`main.tex` 是一个 `book` 文档，可用 `pdflatex`、`xelatex` 或 `lualatex` 编译，各部分的图片位于 `images` 中。标题页是一个 `titlepage`，由[标题页模板](../account.md#exports)生成。故事中层级最浅的标题为章（chapter），下一层级为节（section），依此类推；它们不编号（故事会自行命名各章），但会列入目录。强调、引用、列表、代码块和场景分隔符会转换为 LaTeX 中对应的形式；脚注为真正的 LaTeX 脚注；对 LaTeX 有特殊含义的字符会按文本书写；当书籍语言为常见语言之一时，语言设置会选择连字规则（`babel`）。包含日文、中文或韩文文本的书需要 `xelatex` 或 `lualatex`（`pdflatex` 会停止并给出提示）：文件会为此加载 `xeCJK` 或 `luatexja`；使用 `xelatex` 时，你需要设置一个包含所需字符的字体（需修改的那一行位于其上方的注释中，例如 `\setCJKmainfont{Noto Serif CJK JP}`），否则只会使用 `xeCJK` 自带的中文字体。将 ZIP 上传到 [Overleaf](https://www.overleaf.com)，或解压后运行 `pdflatex main.tex`（运行两次以生成目录）。打印样式不适用：外观由文档类决定，请在 `main.tex` 的导言区中修改。

<a id="print-styles"></a>

## 打印样式

导出使用[设置 → 样式](../account.md#styles)中标记为**用于导出**的文本样式。样式分为两类：用于书籍的（故事和阅读器）以及用于导出的：*更改文本样式*菜单和阅读器只显示第一类，导出对话框只显示第二类。四种内置样式是各格式的外观；**复制**一个样式（或一个书籍样式，并勾选**用于导出**）即可创建你自己的样式，例如纸质书的书籍样式。样式按纸张来设计：依赖应用程序主题的颜色（深色主题的浅色文字）会变为白色页面上的深色。

| 格式 | 样式的作用 |
|---|---|
| **HTML** | 样式的整个样式表，包括**自定义 CSS**、**首字下沉**、文本宽度和背景；标题页和目录保持该格式的外观。 |
| **EPUB** | 样式表，不含自定义 CSS（并非所有电子阅读器都支持它；某些阅读器还会设置自己的字体和字号）。 |
| **PDF** | 字体系列（来自字体栈的已嵌入字体中的衬线、无衬线或等宽字体）、字号、行高、对齐方式、段落间距、首行缩进、页面的**背景颜色**（整个页面，包括标题页）、文本、斜体、粗体、引用、标题和场景分隔符的颜色、标题的对齐方式和字号，以及场景分隔符的符号。 |
| **Word 文档** | 与 PDF 相同，但使用样式中指定的字体名（若电脑上没有该字体，Word 会显示它自己的字体），而不是嵌入字体。背景为页面颜色：Word 会在屏幕上显示，但除非在其打印选项中启用*打印背景颜色和图像*，否则不会打印。 |

首字下沉、自定义 CSS（PDF、Word、EPUB）、标题的小型大写字母以及文本宽度不会在 PDF 和 Word 文件中生成。

<a id="title-page-template"></a>

## 标题页模板

标题页由模板生成，每种格式各一个。在[设置 → 导出](../account.md#exports)中修改：模板为 Markdown，使用 `{{title}}`（对话框中的书名）和 `{{author}}`，例如 `## {{title}}` 以及一行 `written by {{author}}`。默认为以标题作为标题、作者用斜体显示。

同样的模板（标题页、前置元数据、著作权声明）可以**针对单本书或某个文件夹**进行修改：在书籍的*提示词*选项卡中，以及在文件夹窗口中，**扩展设置**包含每种导出格式的一个面板，每个模板对应一个字段。依次使用书籍自身的版本、其上方最近文件夹的版本、你在*设置 → 导出*中的版本，最后是默认值，因此一个系列可以拥有自己的标题页。空字段会被继承，并会说明来源。
<a id="table-of-contents"></a>

## 目录

当文本包含章节时，文件会在标题页之后放置一个目录。章节是故事中包含 Markdown 标题（以 `#` 开头的行，例如 `# Chapter 3: The Harbour`）的部分，这与故事侧边栏中 [Chapter Marker](../extensions/chapter-marker.md) 插件采用的规则相同。某部分的第一个标题即为其标题，没有标题的部分归属于其前面的章节。没有任何标题的故事不会生成目录。

![导出的 PDF 的标题页和目录](../../images/export-result.png)

在 PDF、Word 和 EPUB 中，每个章节都从新的一页开始。标题页和目录也各自独占一页。

目录条目是通向各章节的链接：

| 格式 | |
|---|---|
| **HTML** | 链接到页面中的各章节。 |
| **PDF** | 可点击的条目，附带章节所在页码；章节也会出现在 PDF 阅读器显示在页面旁边的大纲（书签）中。 |
| **EPUB** | 阅读器的目录，同时也是标题页之后的一页图书内容。 |
| **Word 文档**（`.docx`） | 可点击的条目，附带章节所在页码。Word 打开文件时会询问是否更新域，选择 **是** 即可填入页码（LibreOffice 会自行填入）。它是链接列表，而不是 Word 的目录域。 |
| **Markdown** | 没有目录。章节标题保留在正文中，大多数 Markdown 编辑器会根据这些标题生成大纲。 |
| **纯文本** | 没有目录。 |

<a id="page-numbers"></a>

## 页码

PDF 和 Word 文件在除标题页之外的每一页页脚都有页码。页码是该页在文件中的位置，因此标题页为第 1 页，其后的第一页为第 2 页。其他格式没有自己的页码。

<a id="the-title-page"></a>

## 标题页

勾选 **Include title page**（包含标题页）后，文件会以独立的一页开始，页面上显示书名和作者。该页由内置模板（`DEFAULT_EXPORT_HEADER_TEMPLATE`）生成，目前尚不能在应用中编辑。

<a id="good-to-know"></a>

## 注意事项

- 导出内容是你点击 **Export**（导出）时分支的快照。之后生成或编辑的部分不会包含在文件中。
- 导出的文件仅保留到你关闭下载对话框为止。如果以后还需要，请重新导出。
- 摘要、Lorebook、指令和模型的推理过程不会被导出，只导出各部分的文本和图片。若要保存全部内容，请创建[备份](backups.md)。
