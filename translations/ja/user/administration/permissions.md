# 権限

権限は、すべての人に開放されているわけではない操作を、特定のユーザーに許可する仕組みです。管理者はユーザーに一人ずつ権限を付与します。権限を持たないユーザーも、Marginalia のそれ以外の機能は通常どおり使えます（本を書く、ロアブックを作る、管理者が[共有](../inference-providers.md#shared-providers)しているモデルを使う、など）。

| 権限 | 許可される内容 | 設定 |
|---|---|---|
| **独自のモデルの作成** | [推論プロバイダー](../inference-providers.md)の追加。この権限がないユーザーは、管理者が共有しているプロバイダーのみを使えます。すでに持っているプロバイダーは引き続き動作し、編集もできます。 | |
| **ヘルプアシスタント** | マニュアルに基づいて答えるチャットである[ヘルプアシスタント](help-assistant.md)への質問。 | **制限を適用する**と**インターフェースの操作を許可する**。詳しくは[権限の設定](#settings-of-a-permission)を参照。 |
| **エージェント** | （試験的機能。[エージェント](../agents.md)を参照）[エージェント](../agents.md)タブ：エージェントの作成、複製、本での実行。 | **エージェントの最大数**、**同時実行数**、**モデルへの同時リクエスト数 (実行ごと)**、**実行あたりのトークン予算**、およびコピーとファイルの上限。詳しくは[権限の設定](#settings-of-a-permission)を参照。 |
| **バージョン履歴** | ユーザーの本の履歴が保持する[パートのバージョン](../books/version-history.md#how-many-versions-are-kept)の最大数。すべてのユーザーは50を持ちます（この行がないユーザーも同様）。付与されていない権限は、そのユーザーに履歴がないことを意味します。 | **パートごとに保持するバージョン数**。フォルダー、本、ユーザーがこれを超えて増やすことのできない上限です。ここで数値を空にしても、この設定では上限を設けません。追加した権限は50から始まります。 |
| **通知** | エージェントがユーザーを必要としていて画面が開いていないときに、サーバーが URL へ送る[メッセージ](../agents.md#when-you-are-not-there)。サーバーはユーザーが入力したアドレスを呼び出すため、独立した権限になっています。この権限がないと、ユーザーの設定に入力欄が表示されず、何も送信されません。 | **このマシンとプライベートネットワークのアドレスを許可**。詳しくは[権限の設定](#settings-of-a-permission)を参照。 |

管理者はすべての権限を常に持っているため、権限は必要なく、付与する必要もありません（管理者のボタンやセクションは、権限に左右されることはありません）。新しいユーザーは権限を持っていないので、[ユーザーを追加した](users.md#adding-a-user)直後に、必要な権限を与えてください。

<a id="giving-and-taking-permissions"></a>

## 権限の付与と取り消し

**Admin → Users** のユーザーの行にある鍵のボタンを押すと、そのユーザーの権限が開きます：

![ユーザーの権限](../../images/permissions-dialog.png)

このウィンドウは、ユーザーが持つ権限の表で、列は3つあります：

| 列 | |
|---|---|
| **名前** | 権限です。設定を持つ権限は、名前の前に矢印があります。[権限の設定](#settings-of-a-permission)を参照。 |
| **付与** | 権限が有効かどうか。付与されていない権限は、権限がないのと同じですが、設定は保持されるため、しばらく無効にして、あとで再び有効にできます。 |
| ゴミ箱のボタン | 権限（とその設定）を完全に削除します。 |

権限を付与するには、表の上にある**権限を追加**をクリックし、ユーザーがまだ持っていない権限を一つ選びます。権限は付与された状態で表に追加されます。**保存**をクリックするまで何も保存されません：

![追加する権限を選ぶ](../../images/permissions-add.png)

- 保存するものがない間は、**保存**は無効です。
- **終了**はウィンドウを閉じます。未保存の変更がある場合は、先に確認が表示されるため、変更を誤って破棄することはありません。
- 削除した権限は、保存するまで表に残り、保存したときに完全に削除されます。それまでは、保存せずに**終了**でウィンドウを閉じれば元に戻せます。

保存後、ユーザーがログイン中であればそのユーザーのページが再読み込みされるため、権限に依存するボタンやセクションがすぐに表示されたり消えたりします。自分自身の権限を変更した場合でも、自分のページは再読み込みされません。

<a id="settings-of-a-permission"></a>

## 権限の設定

権限の中には、インストール全体ではなくユーザーごとに属する設定を持つものがあります。そのような権限の行は矢印で始まります。クリックすると設定が展開され（ウィンドウを開いたときは折りたたまれており、追加したばかりの権限は展開されています）、もう一度クリックすると折りたたまれます。折りたたみは長いリストを短く保つためだけのもので、何も変更せず、未保存の変更とはみなされません。

![ヘルプアシスタント権限の設定](../../images/permissions-settings.png)

**ヘルプアシスタント**、**エージェント**、**通知**には設定があります。ヘルプアシスタントの設定は次のとおりです：

| 設定 | |
|---|---|
| **制限を適用する** | 共有モデルの場合、ユーザーの質問が他のリクエストと同様に上限と使用量に計上されるかどうか。詳しくは[費用の負担](help-assistant.md#who-pays)を参照。初期値は無効です。 |
| **インターフェースの操作を許可する** | ユーザーが案内を求めたときに、アシスタントがセクションを開いたり、タブを選択したり、何かを追加するダイアログを開いたりできるようにします。詳しくは[案内の表示](help-assistant.md#showing-the-way)を参照。初期値は無効です。 |

エージェントの設定は次のとおりです。空欄の場合は初期値になります：

| 設定 | |
|---|---|
| **エージェントの最大数** | ユーザーが持てるエージェントの数。複製されたエージェントも含みます。空欄の場合は5です。0にすると、ユーザーは既存のエージェントを保持して実行できますが、新たに作成や複製はできません。削除したエージェントは、その枠を空けます。 |
| **同時実行数** | ユーザーの実行が同時に動作できる数。空欄の場合は1です。 |
| **モデルへの同時リクエスト数 (実行ごと)** | 1回の実行で、エージェントと[サブエージェント](../agents.md#sub-agents)を合わせて、同時にモデルへ送信中にできるリクエストの数。空欄の場合は1です。その場合、サブエージェントがモデルに問い合わせている間、エージェントは待機し、逆も同様です。より大きい値にすると、サブエージェントがエージェントと並行して作業できます（エージェントのモデルには独自の[リクエスト数の上限](../inference-providers.md#general-settings)もあり、そちらも適用されます）。 |
| **実行あたりのトークン予算** | ユーザーの1回の実行が使えるトークンの最大数（送信分と生成分）。空欄または0は無制限です。 |
| **作業用コピー数** | ユーザーの実行が同時に保持する本の作業用コピーの数。完了していない実行はコピーを保持し、一時停止中の実行も同様です。実行が完了、停止、または削除されると、コピーを返却します。空欄または0の場合、エージェントの数以外に上限はありません。 |
| **最大ファイルサイズ (KB)** | ユーザーのエージェントがワークスペースに書き込める最大のファイル。空欄の場合は1024 (1 MB) です。 |
| **ワークスペースの容量 (MB)** | ユーザーのエージェント1つのワークスペース内のすべてのファイルが占有できる容量。空欄の場合は20です。 |
| **ワークスペース内のファイル数** | ユーザーのエージェント1つのワークスペースが保持できるファイルの数。フォルダーは数に含みません。空欄の場合は500です。 |
| **実行のチェックポイントの容量 (MB)** | 1回の実行のすべての[チェックポイント](../agents.md#checkpoints)（作業用コピーとそのワークスペースの復元ポイント）が占有できる容量。その一部は自動のチェックポイント用に確保されます。空欄の場合は100です。 |

![エージェント権限の設定](../../images/permissions-settings-agents.png)

通知の設定は次のとおりです：

| 設定 | |
|---|---|
| **このマシンとプライベートネットワークのアドレスを許可** | 下位の権限です。チェックボックスは**通知**が付与されているときだけ選択できます（それ以外はグレーアウトし、権限を取り消すと選択も外れます）。これを許可しない場合、インターネット上のアドレスのみに接続します。つまり `localhost`、プライベートネットワーク（`10.x.x.x`、`172.16-31.x.x`、`192.168.x.x`）、リンクローカルまたは共有アドレス（`169.254.x.x`。クラウドホストがメタデータサービスを置いている場所です。`100.64-127.x.x`）、IPv6 のユニークローカルアドレスには接続しません。ntfy や Gotify が同じマシンや自分のネットワーク上で動いているユーザーには、これを選択してください。初期値は無効です。名前は、解決されたアドレスで確認されるため、プライベートアドレスを指す名前は拒否され、見つからない名前も同様に拒否されます。 |

管理者は権限も下位の権限も必要ありません。管理者はメッセージを受け取れ、ローカルアドレスも使えます。完全には信頼していない人々と共有しているサーバーでは、下位の権限をオフのままにしてください。オフにしないと、サーバーがユーザーの入力した先へ、あなたのネットワーク内からリクエストを送ってしまいます。

<a id="when-permissions-were-introduced"></a>

## 権限が導入された経緯

権限が導入される前は、**ユーザーが独自のモデルを作成できる**と、ヘルプアシスタントの**有効**スイッチ（**制限を適用する**と**インターフェースの操作を許可する**も含む）は、インストール全体の設定でした。Marginalia は更新の際に、これらを権限へ移しました。当時存在していたユーザーは、全員がモデルを作成できた場合（これが初期値でした）は**独自のモデルの作成**を、アシスタントが有効だった場合は同じ二つの設定を持つ**ヘルプアシスタント**を受け取りました。あなたがそれを変更するまで、これらのユーザーに変化はありません。これ以降に追加するユーザーは、権限を持たない状態で始まります。
