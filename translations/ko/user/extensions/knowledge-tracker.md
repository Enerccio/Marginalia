# 지식 추적기

이야기의 등장인물이 **무엇을** 알고 있고 **무엇을 모르는지** 기록하여 프롬프트에 넣습니다. 모델은 지시문이 막지 않으면 캐릭터가 한 번도 만난 적 없는 사람에 대해서도 (이름, 직업, 얼굴 등) 알고 있는 것처럼 행동하는 경향이 있습니다. 지식 추적기를 사용하면 프롬프트에 장면의 추적 대상 캐릭터마다 그 캐릭터가 아는 것과, 그 밖의 것은 전혀 모른다는 사실이 명시됩니다.

!!!
추적할 인물은 직접 고릅니다. 탭에 추가한 캐릭터만 모델에게 설명되며, 그것도 작성 중인 부분의 *등장인물*에 포함되어 있을 때만 적용됩니다. 이야기 본문에서 무언가를 추측하지 않습니다.
!!!

<a id="the-knowledge-tab"></a>

## 지식 탭

[스토리 편집기](../books/story-editor.md)의 왼쪽 사이드바에 *개요* 옆으로 **지식** 탭이 생깁니다. 변경할 때마다 모든 내용이 책에 자동으로 저장됩니다.

![지식 탭](../../images/plugin-knowledgetracker.png)

**캐릭터 추적**을 누르면 **이름**과, 선택 사항으로 **別名**(별칭)을 입력하라고 합니다. 별칭은 부의 *등장인물* 필드에 적히는 다른 이름들로, 쉼표로 구분합니다. 하나의 이름이나 별칭은 한 명의 추적 캐릭터에만 속할 수 있습니다.

캐릭터 카드의 화살표를 눌러 그 캐릭터가 아는 것을 봅니다.

| | |
|---|---|
| **알고 있음** (초록) / **모름** (빨강) | 사람, 장소, 비밀, 사건 등 무엇에 관해서든 짧은 문장 하나로 씁니다 (*피터는 공작을 상대로 한 음모를 알고 있다*, *피오라는 토마스가 자기 아버지라는 것을 모른다*). 캐릭터가 **모르는** 것도 분명하게 적으세요. 모델이 지키는 것이 바로 그것입니다. |
| 순서와 **#12** | 가장 최근의 지식이 맨 위에 옵니다 (오래된 지식도 포함). 모델이 배운 항목에는 그것을 배운 부의 작은 번호가 붙습니다 (**#12**). 클릭하면 이야기가 그 부분으로 스크롤되어 잠시 깜박입니다 (휴대폰에서는 먼저 서랍이 닫힙니다). 직접 작성한 항목에는 번호가 없으며, 현재 가지에 없는 부분 (다른 가지이거나 삭제된 부분)에서 온 항목에도 번호가 없습니다. |
| **지식 추가** | 항목을 추가하며 바로 활성화됩니다. **한 가지 생각**만 담으세요. 두 가지를 말하는 항목 (*토마스가 누구인지 모르고, 그를 만난 적도 없다*)은 둘 중 하나라도 사실이 아니게 되는 순간 철회됩니다. **편집** 버튼으로 내용과 종류를 바꿀 수 있습니다. |
| **철회** (빗금 친 원) | 항목이 더 이상 사실이 아닙니다 (두 사람이 만난 뒤의 *토마스를 만난 적 없다*). 삭제되지는 않고 *오래된 지식*이 되며 더 이상 모델에 전달되지 않습니다. |
| **잠금** (자물쇠, 모델이 배운 항목에 있음) | [정리 작업](#tidying-the-knowledge)은 잠긴 항목을 보지 않습니다. 남아 있어야 하는 것, 배신, 비밀 등에 사용하세요. 그래도 이야기가 잠긴 항목과 모순될 수는 있습니다 (기억을 잃은 캐릭터 등). 이 경우 이야기를 다시 읽을 때 평소처럼 철회됩니다. |
| **삭제** | 확인 후 항목을 영구적으로 제거합니다. 철회는 항목을 남겨 두므로, 확신이 서지 않으면 철회를 쓰세요. |
| **항목 선택** (**지식 추가** 옆) | 여러 항목을 빠르게 삭제합니다. 오래된 항목을 포함한 캐릭터의 모든 항목에 체크박스가 생깁니다. **모두 선택** / **선택 해제**로 전체를 체크하거나 해제할 수 있고, **선택 삭제 (n)**은 확인 한 번을 거쳐 체크한 항목을 영구적으로 제거하며, **취소**는 선택을 종료합니다. |
| **만난 사람** | [처리](#processing)를 통해 기록된, 캐릭터가 만난 사람들입니다. 처리 과정은 사람이 아닌 이름 (등장인물 필드의 메모)을 기록할 수도 있습니다. 이때는 **편집**을 열어 **만난 사람** 목록을 바꾸세요. 쉼표로 구분된 이름을 하나씩 적으면 됩니다. 직접 쓴 이름은 이야기를 다시 읽어도 남으며, 삭제한 이름은 그것이 확인된 부분을 다시 읽을 때만 돌아옵니다. |
| **오래된 지식 (n)** | 기본적으로 접혀 있습니다. 각 오래된 항목을 **복사**, **편집**, **복원** (다시 활성화되어 지금부터 적용됨) 하거나 삭제할 수 있습니다. |

<a id="mass-changes"></a>

### 일괄 변경

**일괄 변경** 버튼 (**캐릭터 추적** 옆의 목록 아이콘)을 누르면 추적 중인 모든 캐릭터와 오래된 항목을 포함한 모든 항목이 체크박스가 있는 표로 나타나는 창이 열립니다. 표에는 종류, 내용, 상태 (*활성*, 또는 오래된 상태: *철회됨*, *검토에서 거부됨*, *정리됨*), 출처 (*초기 상태*, *직접 작성*, *이야기에서 학습*), 그리고 배운 부가 표시됩니다. 원하는 만큼 여러 표에서 항목을 체크하세요 (표 머리글의 상자는 그 표의 모든 항목을 체크하고, 하단 바의 **모두 선택** / **선택 해제**는 모든 캐릭터의 모든 항목을 체크합니다). 그런 다음:

| | |
|---|---|
| **선택 철회 (n)** | 체크한 활성 항목을 오래된 지식으로 바꿉니다. 한 항목에 대해 **철회**를 누르는 것과 같습니다. |
| **선택 복원 (n)** | 체크한 오래된 항목을 다시 활성화하며, 지금부터 적용됩니다. |
| **선택 삭제 (n)** | 확인 한 번을 거쳐 체크한 항목을 영구적으로 제거합니다. |

각 버튼에 표시된 숫자는 그 버튼이 체크된 항목 중 몇 개를 바꾸는지를 나타냅니다. 변경 후에도 체크 상태는 유지되므로, 철회된 항목을 이어서 삭제할 수 있습니다.

창 상단의 **JSON으로 내보내기**는 책의 추적 캐릭터 (이름, 별칭, 종류·상태·출처·잠금 상태를 포함한 항목, 만난 사람)를 파일로 내려받습니다. 처리 과정의 데이터는 포함되지 않으므로 어떤 책에도 맞습니다. **JSON에서 가져오기**는 이런 파일을 책에 읽어 들이며 추가만 합니다. 책이 이미 추적하는 이름 (이름 또는 별칭)을 가진 캐릭터는 아직 없는 별칭, 항목, 만난 사람을 얻고, 나머지는 새 추적 캐릭터가 됩니다. 다른 캐릭터가 이미 가진 별칭은 제외됩니다. 가져온 항목은 이 책의 어떤 부와도 연결되어 있지 않으므로, 다시 처리해도 사라지지 않습니다. 모델이 배운 항목은 직접 작성한 것으로 취급되고, 오래된 항목은 오래된 상태로 남습니다. 가져오기 후 메시지에는 몇 명의 캐릭터가 추가 또는 갱신되었는지, 그리고 몇 개의 항목이 추가되었거나 이미 있었는지가 표시됩니다.

<a id="what-goes-into-the-prompt"></a>

## 프롬프트에 들어가는 내용

등장인물에 포함된 추적 캐릭터마다 프롬프트에 다음과 같은 블록이 들어갑니다.

```
이 장면의 등장인물이 아는 것. 캐릭터는 자신에게 나열된 지식에 따라서만 행동합니다:

피오라는 알고 있다: 마라, 등불 길드의 전령이자 친구 넬의 자매; 그녀는 등불 길드에 40크라운의 빚이 있다.
피오라는 모른다: 자기 아버지가 살아 있다는 것, 토마스가 자기 아버지라는 것.
피오라가 만난 사람: 마라.
피오라는 지금 다음 사람들과 함께 있다: 마라, 토마스.
피오라는 이 이야기에 등장하는 그 밖의 누구도 만난 적이나 들은 적이 없으며, 이 이야기의 비밀, 계획, 사건에 대해 그 밖의 어떤 것도 알지 못한다.
```

활성 항목만 전송됩니다. 마지막 줄 (**닫힌 세계** 줄)은 모델이 캐릭터에게 그럴 수 없는 지식을 주지 않도록 막는 역할을 합니다. 이 줄은 이야기가 알려 주는 것 (사람, 장소, 비밀, 계획, 사건)을 다루며, 그 세계의 사람이라면 누구나 아는 것은 다루지 않으므로 캐릭터는 여전히 자기 마을은 알고 있습니다. 설정에서 이 줄을 끌 수 있습니다. 등장하지 않는 추적 캐릭터에게는 아무것도 전달되지 않으며, "모른다"는 줄조차 들어가지 않습니다.

<a id="who-is-present"></a>

### 누가 등장하는가

블록은 부의 **등장인물** 필드를 바탕으로 만들어집니다. 이 필드는 자유 텍스트이므로 관대하게 읽힙니다.

- 괄호 안의 글은 무시됩니다: `토마시 (지쳐 있음), 미즈키`는 토마시와 미즈키입니다.
- 이름은 **구분자**(기본값: `,` `;` 줄바꿈, `/`, `|`, `、` `，` `；`)에서 나뉩니다.
- ` - ` 또는 `:` 뒤의 글은 메모이므로 버려집니다 (`마라 - 부상당함`).
- 대소문자, 악센트, 앞에 붙은 *the*는 상관없습니다.
- 이름은 **전체가** 일치해야 합니다. *마라의 동생*은 *마라*가 아닙니다. 캐릭터가 여러 방식으로 적혀 있다면 별칭을 사용하세요. 일치하지 않는 경우에는 블록 하나를 잃을 뿐이지만, 잘못 일치하면 장면에 없는 캐릭터를 묘사하게 되므로, 놓치는 쪽이 낫습니다.

*시점* 필드는 단독으로 읽히지 않으므로, 시점 캐릭터도 등장인물에 함께 적어 주세요.
<a id="processing"></a>

## 처리

플러그인은 이야기의 흐름을 따라갑니다. **처리**는 활성 분기의 파트를 순서대로 **시작 지점**부터 읽고, 마지막으로 읽은 파트를 가리키는 **커서**를 유지합니다. 모델을 쓰지 않을 때는 누가 누구를 만났는지만 기록합니다. 추적 대상 캐릭터는 현재 등장인물 필드에 함께 적힌 모든 이름과 만난 것으로 기록되며, 블록에 그 목록이 표시됩니다. 모델을 쓰면 캐릭터들이 **알게 된 것**도 찾아냅니다(see [Reading what the characters learn](#reading-what-the-characters-learn)).

![처리 패널](../../images/plugin-knowledgetracker-processing.png)

탭 상단의 패널에서 현재 상태를 볼 수 있습니다. 새 파트가 확정되면 자동으로 다시 불러옵니다(책에 자동 주석 달기와 재작성이 설정되어 있다면 그 이후에). 파트를 추가, 편집, 삭제하면서 다른 방식으로 바꾼 경우에는 **새로 고침** 버튼(톱니바퀴 옆의 화살표)을 눌러 이야기를 다시 읽으세요. 패널에는 다음이 있습니다.

- **Process now**: 아직 처리되지 않은 파트를 읽습니다.
- **Process next part**: 아직 처리되지 않은 첫 번째 파트만 한 단계씩 읽습니다(모델 사용 시에는 *Parts per run* 값과 상관없이 그 파트에 대한 요청 한 번). 설정을 시험해 보거나 모델이 한 파트에서 무엇을 찾는지 살펴볼 때 사용하세요. `parts`를 1로 설정한 `knowledge-process` 명령도 같은 일을 합니다.
- **Start point**: 처리가 시작되는 파트입니다(기본값은 *Start of the book*). 이보다 앞의 파트는 전혀 읽지 않습니다. 시작 지점을 앞으로 되돌리면 새 시작점부터 파트를 다시 읽고, 뒤로 옮기면 이미 읽은 내용은 그대로 남습니다.
- **Processed parts**: 최근에 읽은 파트 목록입니다. 처리된 뒤에 **텍스트가 바뀐** 파트(편집하거나 재작성한 파트)에는 표시가 붙습니다. 이 때문에 자동으로 다시 처리되지는 않습니다. 각 행의 버튼 **Reprocess from here**는 그 파트와 그 이후 파트에서 나온 항목과 철회 내용을 되돌리고 다시 읽습니다(직접 작성한 항목과 철회는 남습니다).

**Process new parts automatically**가 켜져 있으면(기본값은 꺼짐) 플러그인은 다음을 자동으로 수행합니다.

- 생성이 시작되기 전에, 마지막 처리 이후에 작성된 파트를 처리해서 프롬프트가 누가 누구를 만났는지 알 수 있게 합니다. *Regenerate*나 스와이프로 교체되고 있는 파트는 건드리지 않습니다. 모델을 사용할 때는 **Ask before applying**이 꺼져 있을 때만 모델로 읽습니다. 그렇지 않으면 누가 누구를 만났는지만 기록하고, 모델이 찾은 내용은 생성 도중에 검토를 강요하지 않도록 탭에서 직접 시작해야 합니다.
- 파트를 **다시 생성**하여 새 텍스트가 도착하면, 예전 텍스트에서 알게 된 내용은 되돌립니다.
- **스와이프**하거나 다른 분기로 전환하면, 커서는 두 분기가 공유하는 마지막 파트로 돌아갑니다.

## characters 학습 내용 읽기

설정에서 **Read what the characters learn with the model**을 선택하세요. 그러면 **Process now**가 다음 부분들에 대해, 등장하는 추적 대상 캐릭터가 **무엇을 알게 되었는지** 모델에 묻습니다. 여기에는 보고, 듣고, 읽고, 전해 들은 것이 포함됩니다. 또한 이야기가 **모순되는** 항목도 알려 줍니다(예: 두 사람이 만난 뒤인데 *Thomas를 만난 적 없다*로 되어 있는 경우). 요청에는 부분들(시점과 등장 캐릭터 포함), 각 추적 캐릭터가 현재 알고 있는 내용, 그리고 원하면 로어북이 담깁니다. 모델에게는 그 세계의 인물이라면 당연히 아는 것(예: 왕이 누구인지)과 캐릭터 자체에서 따라 나오는 것(예: 서큐버스는 꼬리가 있다는 것을 안다)은 제외하고, 확실하지 않은 것은 보고하지 말라고 지시합니다. 어떤 부분에도 등장하지 않는 추적 캐릭터에 대해서는 아예 묻지 않습니다.

실행 한 번은 모델에 대한 요청 한 번입니다. **Process now**에 요청이 세 번을 넘어야 할 경우(아직 처리되지 않은 긴 이야기 구간이 있거나 **Parts per run**을 낮게 설정한 경우), 먼저 부분이 몇 개이고 요청이 몇 번인지, 모델에 대략 얼마나 많은 텍스트가 전달되는지 알려 주며, 확인하기 전에는 시작하지 않습니다. 각 요청에는 지시문, 로어북, 캐릭터들의 지식도 함께 들어가므로, 실제 비용은 텍스트만으로 계산한 것보다 높습니다.

**Ask before applying**이 꺼져 있으면 변경 사항은 즉시 적용되고, 각각 탭의 Processing 섹션에 있는 **Applied automatically** 로그에 기록됩니다. 누가 무엇을 얻었는지 또는 잃었는지, 어느 부분에서 왔는지가 나옵니다. 로그의 내용은 편집할 수 없지만, 각 행에는 **Revert** 버튼이 있습니다. 추가된 항목은 거부되며(검토 화면에서 거부된 추가 항목과 마찬가지로 *Old knowledge* 아래에 남습니다), 제외된 항목은 다시 활성화됩니다. 그 후 직접 항목을 편집, 삭제하거나 제외한 행은 건드리지 않습니다. 로그에는 최근 200개의 변경만 남습니다.

**Ask before applying**이 꺼져 있으면 새 부분은 확정되는 즉시 읽힙니다. 생성이 끝났을 때, 또는 책에 자동 주석(및 재작성)이나 번역 기능이 켜져 있다면 그 작업이 끝났을 때입니다. 따라서 모델은 여러분이 보관한 텍스트를 읽으면서 동시에 작업합니다. 이것은 [생성된 부분 다음에 오는 단계](../books/story-editor.md#what-follows-a-generated-part)의 한 단계입니다. 그러면 다음 생성은 지식이 최신 상태인 것을 확인하고 기다리지 않습니다. 남아 있는 작업(중지한 실행, 닫은 창)은 이전과 같이 다음 생성 전에 읽힙니다.

모델이 작업하는 동안 페이지 위에 작은 **진행 패널**이 떠 있습니다. 이 패널은 **모달이 아니므로**, 계속 읽고 이야기를 편집할 수 있습니다. 제목을 잡고 **드래그**하여 옮길 수 있습니다. 닫으면 숨겨지고 작업은 계속됩니다(**Cancel**로 중지할 수 있습니다).

![진행 패널](../../images/plugin-knowledgetracker-progress.png)

모델이 응답하는 동안 패널에는 **What the model is writing**이 실시간으로 표시됩니다. 먼저 모델의 추론이, 그다음 답변이 나옵니다. 그래서 느린 모델을 기다릴 때도 빈 막대만 보이지 않습니다. 요청이 끝나면 같은 내용이 **What the model thought** 아래에 남습니다(실행의 요청마다 블록이 하나씩 있고, 모델이 답한 내용이 함께 표시됩니다). 모델이 아무것도 제안하지 않아 검토 창이 열리지 않은 경우에도 마찬가지입니다. 이때 탭에는 **Last run: what the model thought** 버튼이 남아, 패널을 다시 열고 왜 아무것도 추가되지 않았는지 확인할 수 있습니다.

모델이 답을 마치면 패널에 그 사실이 표시되고 **Review changes**가 나타납니다. 같은 버튼이 탭의 처리 패널에도 있습니다(*3 changes to review*). **검토 창은 저절로 열리지 않습니다.** 변경 사항을 캐릭터별로 묶은 표가 나옵니다.

![변경 사항 검토](../../images/plugin-knowledgetracker-review.png)

표 아래의 **What the model thought**(처음에는 닫혀 있음)에는, 모델이 답하기 전에 보낸 추론이 담겨 있습니다(모델이 이를 보낼 때에 한함). 어떤 변경이 제안된 이유, 또는 여러분이 기대했지만 빠진 변경의 이유를 보여 주므로, 적용하기 전에 변경을 판단할 수 있습니다. 추론을 하지 않는 모델의 경우 이 부분은 비어 있습니다.

| | |
|---|---|
| 체크 박스 | 변경을 적용할지 여부. 처음에는 모두 체크되어 있으며, 각 캐릭터마다 **Check all** / **Uncheck all**이 있습니다. |
| **Retract** / **Add** | 제외는 항목을 오래된 것으로 만듭니다(항목은 남으며, [탭](#the-knowledge-tab) 참고). 추가는 새 항목이며, *Knows* 또는 *Does not know*입니다. 추가 항목의 텍스트와 종류는 적용하기 전에 **편집**할 수 있습니다. |
| 인용 | 그것을 보여 주는 부분의 문장과, 그 문장이 들어 있는 부분. 해당 부분에서 찾을 수 없는 인용은 표시되며, 모델이 지어냈을 수 있으니 수락하기 전에 확인하세요. |

**Apply**는 체크된 변경을 적용하고 다음으로 넘어갑니다. **Cancel**은 전체 과정을 중단하며 아무것도 바꾸지 않습니다. 다음번에 같은 부분들이 다시 제안됩니다. 체크를 해제한 추가 항목은 인용과 함께 **오래된 지식으로 보관**됩니다(복원할 수 있습니다). 체크를 해제한 제외 항목은 그 항목을 그대로 둡니다. 모델이 말했지만 사용할 수 없었던 내용(묻지 않은 캐릭터, 존재하지 않는 항목, 인용이 없는 변경, 캐릭터가 이미 알고 있는 내용)은 *Left out* 아래에 나열됩니다. 적용된 변경에는 그것이 나온 부분이 함께 기록되므로, **Reprocess from here**를 쓰면 그 변경을 다시 되돌릴 수 있습니다. 검토하는 동안 이야기가 바뀌었다면(다른 분기, 삭제된 부분 등) 변경은 적용되지 않으며, 다시 처리해야 합니다.

부분들은 **Parts per run**(기본값 1) 단위의 **실행**으로 읽힙니다. 모델의 컨텍스트에 들어가지 않는 부분은 들어갈 만큼으로 잘립니다. 마지막으로 확정된 부분까지 실행이 연달아 이어지며, 확인을 요청하는 방식일 때 모델이 아무것도 찾지 못한 실행은 묻지 않고 건너뜁니다. **Ask before applying**이 꺼져 있으면 변경은 즉시 적용되고, 패널에는 실행당 한 줄씩 기록된 로그가 남습니다.

!!!
이 프롬프트는 몇몇 장면으로 한 모델에 대해서만 시험되었고, 널리 검증되지는 않았습니다. 캐릭터가 자신이 지각하지 않은 것을 알게 되는 일은 막아 주지만, 특히 긴 장면에 등장하는 캐릭터에 대해서는 제안된 내용을 확인하세요. 요청은 아래에서 선택한 모델로 전송되며, 그 서비스의 일반적인 비용과 개인정보 처리 방식이 적용됩니다.
!!!

## 지식 정리하기

모델은 각 캐릭터가 알게 된 것을 기록하며, 긴 이야기에서는 목록이 점점 길어져서 매 요청마다 모델에 보내기에는 자잘한 항목이 너무 많아집니다. **Tidy knowledge**(**Process now** 옆에 있으며, 모델 설정이 필요합니다)는 모델이 최근 처리된 이야기 부분을 맥락으로 삼아 캐릭터가 아는 내용을 다시 읽고, 다음을 하도록 요청합니다.

- 보관할 가치가 없는 항목을 **삭제**합니다. 사소한 내용, 그 장면에 있던 모든 사람이 본 장면의 세부(이야기에 이미 남아 있음), 이후의 사건에 의해 이미 뒤처진 내용, 다른 항목과 같은 말을 하는 항목 등이 해당합니다.
- 같은 대상에 관한 여러 항목을 **병합**하여, 모든 사실을 담은 하나의 항목으로 만듭니다.

삭제되거나 병합된 항목은 지워지지 않고 *Old knowledge*가 되며, 복원할 수 있습니다. 변경은 읽기 과정의 변경처럼 검토할 수 있고(**Ask before applying**이 이를 결정합니다), 또는 즉시 적용되어 **Revert** 버튼이 있는 로그에 기록됩니다.

정리 작업이 건드릴 수 있는 것은 모델이 알게 된 항목 중에서, 여러분이 **잠그지** 않은 것뿐입니다. 초기 항목, 여러분이 직접 추가하거나 편집한 항목, 잠긴 항목, 오래된 항목은 절대 바뀌지 않습니다(처음 두 종류와 잠긴 항목은 모델이 중복을 알아볼 수 있도록 모델에게 보여 줍니다). 오랫동안 어떤 부분에서도 언급되지 않은 비밀이라고 해서 삭제할 이유가 되지는 않으며, 프롬프트도 이를 명시합니다. 모델이 확신하지 못하면 항목을 남겨 둡니다. 모델이 알게 된 항목이 **Tidy: from this many items**(8개)보다 적은 캐릭터는 정리되지 않으며, **Tidy: parts of context**(10)는 모델이 읽는 최근 처리된 부분의 수입니다.

**Tidy automatically**(설정 항목, 기본값은 꺼짐)는 묻지 않고 적용되는 실행(**Ask before applying**이 꺼져 있어 새 부분도 자동으로 읽히는 경우)이 끝날 때 정리를 자동으로 실행합니다. 이는 마지막 정리 이후 모델이 **Tidy after this many parts**(10) 부분을 읽었을 때 이루어집니다. 정리로 바뀐 내용은 적용되어 **Revert** 버튼과 함께 로그에 기록되며, 해당 실행의 로그에도 그렇게 표시됩니다. 검토 중인 실행은 스스로 정리를 시작하지 않으며, 항목이 너무 적은 캐릭터는 묻지 않고 건너뛰며 모델에 요청하지 않습니다.

명령 막대에서도 같은 작업을 할 수 있습니다. `knowledge-tidy`(`ask true`를 주면 변경 사항을 목록으로 받을 수 있으며, 열려 있는 탭에 검토 버튼이 나타납니다)와, 캐릭터 이름과 항목 번호를 넣는 `lock-knowledge` / `unlock-knowledge`가 있습니다.

## 설정

*추적할 인물* 옆의 톱니바퀴 아이콘입니다.

| 설정 | |
|---|---|
| **프롬프트에 포함** | 블록을 모든 생성의 프롬프트에 넣습니다. 켜져 있는 동안 버튼이 초록색으로 바뀝니다. |
| **깊이** | 블록이 놓일 위치로, 프롬프트 끝에서부터 메시지 개수로 셉니다. `0`은 그 턴의 지시문 뒤, `1`은 그 바로 앞입니다. 시스템 프롬프트보다 앞에 놓이지는 않습니다. |
| **역할** | *시스템*, *어시스턴트*, *사용자* 중 어떤 메시지로 보낼지 정합니다. |
| **다른 것은 알려진 바 없다고 말하기** | 닫힌 세계를 알리는 문장입니다. |
| **등장인물이 아는 것을 주석에 전달** | 켜짐(기본값)이면 [AI로 주석 달기](#annotating-with-what-the-characters-know)가 파트가 시작될 때 그 파트의 추적 대상 인물들이 알고 있던 것을 받습니다. |
| **새 파트를 자동으로 처리** | [처리](#processing)를 참고하세요. |
| **모델로 등장인물이 새로 알게 된 것 읽기** | 처리 과정에서 모델에게 추적 대상 인물마다 무엇을 새로 알게 되었는지 묻고, 그 결과를 제안합니다. 꺼짐(기본값)이면 처리는 누가 누구를 만났는지만 기록하며, 이 경우 비용이 들지 않습니다. |
| **적용 전에 확인** | 켜짐(기본값)이면 모든 제안을 검토용으로 보여 줍니다. 꺼짐이면 즉시 적용하고 기록을 남깁니다. |
| **모델이 이전 파트를 읽도록 허용** | 모델이 새 파트를 읽는 동안, 항목이 알게 된 파트(항목에는 "12번 파트에서 알게 됨"이라고 표시됩니다)를 읽어 볼 수 있습니다. 그래서 읽은 내용이 그 항목을 확인하는지, 되풀이하는지, 모순되는지 살펴봅니다. 예를 들어 전해 들은 이야기를 이제 직접 눈으로 확인하게 되는 경우입니다. 요청 한 번에 파트별로 최대 5번까지 읽을 수 있고, 긴 파트의 본문은 컨텍스트에 들어갈 만큼으로 잘립니다. 검토 화면에는 모델이 읽은 파트가 표시됩니다. 읽기 한 번마다 모델에 한 번씩 더 요청이 가므로 기본값은 꺼짐입니다. 함수 호출을 지원하지 않는 모델은 이전과 같이 요청을 읽습니다. |
| **실행당 파트 수** | 요청 한 번에 읽는 파트 수입니다. 많을수록 비용이 줄지만 답변이 길어지고 검토도 어려워집니다. |
| **자동으로 정리**, **이 개수의 파트 후 정리** | 확인 없이 변경을 적용하는 실행이 끝날 때, 이 개수의 파트(10)마다 정리 작업이 자동으로 실행됩니다. 기본값은 꺼짐입니다. |
| **정리: 컨텍스트 파트 수** | 정리 작업이 읽는, 마지막으로 처리된 파트의 개수입니다(10). |
| **정리: 이 개수 이상의 항목부터** | 모델이 알게 된 항목(잠기지 않은 항목)이 이 개수보다 적은 인물은 정리하지 않습니다(8). |
| **모델용 로어북** | *파트가 활성화한 항목*(기본값: 이 파트들에 대해 생성이 사용했을 항목), *로어북 전체*(모든 항목을 보냅니다. 컨텍스트에 맞지 않으면 활성화된 항목만 보내고 그 사실을 알립니다), *로어북 없음* 중에서 고릅니다. |
| **추출용 모델 / 프로토콜** | 비워 두면 이 책의 모델을 사용합니다. 이 작업에는 더 저렴한 모델이면 충분하며, 프롬프트 캐시를 하나만 보관하는 서버라면 별도의 모델을 쓰는 것이 이 작업 때문에 기존 캐시가 밀려나는 것을 막아 줍니다. |
| **이 책의 구분자** | 등장인물 필드를 이름별로 나누는 구분자로, 한 줄에 하나씩 나뉩니다(줄바꿈은 `\n`). `and` 같은 단어는 띄어쓰기 기준으로 나뉘므로, 직접 추가하지 않는 한 *Jack and Jill*은 하나의 이름으로 남습니다. |
| **내 구분자(모든 책)** | 모든 책에 공통으로 적용되는 구분자입니다. 책 자체의 구분자가 우선하며, 둘 다 없으면 내장 구분자를 사용합니다. |

<a id="prompts"></a>

## 프롬프트

읽기 작업의 시스템 메시지(**지식 추출 프롬프트**)와 정리 작업의 시스템 메시지(**지식 정리 프롬프트**)는 [상속되는 설정](../books/prompts.md#inherited-settings)입니다. 책이 자체 프롬프트를 쓰면 그것을 사용하고, 없으면 위쪽에서 가장 가까운 폴더가 설정한 프롬프트를, 그것도 없으면 여러분의 프롬프트를, 그것도 없으면 실제 모델로 시험한 내장 텍스트를 사용합니다.

프롬프트는 책의 *프롬프트* 탭에서 *확장 기능 설정* 아래에 설정하거나, 폴더의 대화상자에서 설정하거나, *설정 → 확장 기능 설정 → Knowledge Tracker*에서 모든 책에 대해 설정할 수 있습니다(비워 두면 내장 텍스트가 회색으로 표시됩니다). 플러그인이 답변을 읽을 때 쓰므로 내장 텍스트의 JSON 답변 형식은 그대로 유지하세요. 모델이 이전 파트를 읽을 수 있을 때는 `read_part`에 대한 지시문을 플러그인이 추가하므로, 여러분의 프롬프트에 그 내용을 넣을 필요는 없습니다.

<a id="annotating-with-what-the-characters-know"></a>

## 등장인물이 아는 것으로 주석 달기

위의 블록은 모델이 *글을 쓰는 동안* 인물을 전지적 존재로 만드는 것을 막습니다. 같은 기록은 그래도 새어 들어간 오류를 찾는 데에도 도움이 됩니다. 모델이 [파트에 주석을 달 때](../books/annotations.md#letting-a-model-annotate)(**AI로 주석 달기**, 파트 범위 지정, 자동 주석, `/generate-annotation`), 추적기는 그 파트의 추적 대상 인물들이 **파트가 시작될 때** 알고 있던 것을 모델에게 알려 줍니다. 편집기는 알 수 없는 것을 말하거나, 생각하거나, 행동하는 인물을 표시합니다. 예를 들어 *피오라가 토마스의 이름을 부른다. 기록에 따르면 그녀는 그를 만난 적이 없다.* 이런 식입니다. 메모에는 그 사실이 적힙니다.

- **사실은 책의 끝이 아니라 파트 시점의 것입니다.** 인물이 나중 파트에서 알게 된 것은 아직 알려지지 않은 것으로 봅니다. 나중 파트에서 철회되는 항목도 그 시점에는 여전히 참이었습니다. 파트 자체가 가져오는 것(새로 알게 되는 것, 만나는 사람, 그 파트에서 더 이상 참이 아니게 되는 것)은 따로 나열되므로, 파트의 전반부가 후반부와 뒤섞여 검사되지 않습니다.
- **어떤 인물인가.** 추적 대상 인물 중 해당 파트의 *등장인물*에 있거나, 파트의 시점 인물이거나, 본문에서 이름이 언급된 인물입니다(단어 단위로, 대소문자를 구분하지 않으며, 별칭도 포함).
- **어느 시점에서도 사실이 아닌 항목**은 제외합니다. 직접 철회한 항목, 정리 작업이 제거한 항목, 검토에서 거절한 항목이 여기에 해당합니다.
- **기록된 것만.** 기록에 없는 것은 사실이 아니라고 모델에게 알려 주므로, 추적기가 전혀 듣지 못한 일로 인물을 표시하지 않습니다. *다른 것은 알려진 바 없다고 말하기*를 켜면, 인물이 만난 사람 목록에 "(그 밖의 누구도 아님)"도 덧붙습니다.
- 검토 대상 파트보다 앞선 파트 중에 추적기가 읽지 않은 파트가 있으면, 사실 목록이 이를 표시합니다. 그 파트에서 인물들이 알게 된 내용이 빠져 있다는 뜻이므로, 더 나은 검토를 위해서는 먼저 **지금 처리**를 누르세요.
- 사실 정보는 요청 토큰을 사용하며, 추적 대상 인물이 있는 파트에 대해서만 주석 요청에 포함됩니다. **등장인물이 아는 것을 주석에 전달** 설정을 끄면 이 정보를 보내지 않습니다.

<a id="the-block-as-a-macro"></a>

## 매크로로서의 블록

자동 삽입 대신(또는 자동 삽입과 함께) [{%{`{{command::knowledge-tracker-block::<characters>}}`}%} 매크로](../templates/macros.md#commands)로 블록을 직접 배치할 수 있습니다. 인수는 장면의 등장인물 목록이므로, 템플릿은 파트의 필드를 그대로 넘길 수 있습니다.

```
{%{{{command::knowledge-tracker-block::{{presentCharacters}}}}}%}
```

매크로는 **프롬프트에 포함**이 켜져 있든 말든 블록을 출력하므로, 매크로를 쓸 때는 그 설정을 끄세요. 그렇지 않으면 모델이 블록을 두 번 받게 됩니다. 깊이와 역할은 매크로에 적용되지 않습니다(블록은 매크로가 들어 있는 메시지의 일부가 됩니다). 나열된 인물 중 추적 대상이 하나도 없으면 아무것도 출력하지 않습니다. 명령 매크로의 답변은 새 파트가 이어 붙는 파트와 함께 저장되므로, 같은 파트에서 두 번째로 생성해도 그 사이에 여러분이 바꾼 내용을 보지 않습니다. 재생성과 스와이프는 다시 묻습니다.

<a id="commands"></a>

## 명령

[명령줄](../commands/index.md)과 에이전트용입니다.

| 명령 | |
|---|---|
| `knowledge-status` | 설정과 처리 진행 상황입니다. |
| `list-tracked-characters`, `add-tracked-character`, `update-tracked-character`, `delete-tracked-character` | 추적 대상 인물입니다. 이름, 별칭 또는 번호로 지정합니다. |
| `list-knowledge`, `add-knowledge`, `retract-knowledge`, `restore-knowledge`, `delete-knowledge` | 인물의 항목입니다. `list-knowledge`에 표시되는 번호로 지정합니다. |
| `knowledge-process` | 지금 처리합니다(`parts`: 최대 그 개수만큼). 모델을 켠 상태에서 `ask true`를 주면 모델이 찾은 것을 번호가 매겨진 변경 사항으로 돌려주고 보류합니다. 아직 아무것도 바뀌지 않습니다. 열려 있는 지식 탭에는 **명령으로 찾은 변경 사항** 버튼이 표시되며, 이를 누르면 일반적인 검토 화면(적용 / 취소)이 열립니다. 에이전트는 `apply-knowledge-changes`로 적용합니다. |
| `apply-knowledge-changes` | 보류 중인 변경 사항을 모두, 또는 지정한 번호만 적용합니다(탭 검토 화면의 **적용**과 같습니다). |
| `knowledge-tidy` | 정리 작업입니다. `ask true`를 주면 변경 사항을 번호 목록으로 돌려주고 보류합니다(탭에 검토용 버튼이 표시되며, `apply-knowledge-changes`로 적용합니다). |
| `lock-knowledge`, `unlock-knowledge` | 항목(인물, 항목 번호)을 잠가 정리 작업이 건드리지 않게 하거나, 잠금을 풉니다. |
| `knowledge-reprocess` | 파트(핸들 또는 위치)부터 다시 처리합니다. 먼저 확인을 묻습니다. 모델을 켠 상태에서는 상태만 되돌리며, 파트를 다시 읽는 것은 `knowledge-process`가 합니다. |
| `knowledge-set-start` | 시작 지점을 설정합니다. 파트를 지정하지 않으면 책의 시작입니다. |
| `knowledge-tracker-block` | 매크로에 쓸 블록을 텍스트로 돌려줍니다. |

명령줄은 인수를 공백으로 나눕니다. 인물 목록은 따옴표로 묶으세요(`/knowledge-tracker-block "Fiora, Mara"`).

<a id="storage"></a>

## 저장

모든 데이터는 책과 함께 저장됩니다(책의 속성에 저장됩니다). 따라서 [책 백업](../books/backups.md)과 복사본에도 포함됩니다.
