# 상태 추적기

등장인물의 현재 **상태**를 추적합니다. 무엇을 입고 있는지, 무엇을 지니고 있는지, 손에 든 무기, 부상, 기분, 또는 직접 정의한 다른 무엇이든 해당합니다. 장면에 등장하는 인물들의 상태를 프롬프트에 넣어 줍니다. 모델은 두 장 전에 칼을 잃어버렸다는 사실이나 망토가 흠뻑 젖어 있다는 사실을 쉽게 잊어버립니다. 상태 추적기를 사용하면 프롬프트에 장면의 추적 대상 인물 각각에 대해 지금 무엇이 사실인지가 적힙니다.

!!!
추적할 인물과 그 인물에 대해 추적할 내용은 여러분이 정합니다. 탭에 추가한 인물만 모델에게 설명되며, 그것도 작성 중인 부분의 *Present Characters* 필드에 있는 동안에만 그렇습니다. 상태는 직접 관리하거나, 모델이 이야기를 읽고 변경 사항을 제안하게 할 수 있습니다([이야기 따라가기](#following-the-story) 참조).
!!!

<a id="categories"></a>

## 카테고리

**카테고리**는 인물에 대해 추적할 수 있는 항목 하나입니다. 각 카테고리는 다음을 가집니다:

- **이름**: 프롬프트에서도 이 이름으로 불립니다 (*Wearing*, *Weapon at hand*, *Carrying*);
- **종류**:
  - **Single value**: 짧은 값 하나이며, 새 값이 들어오면 기존 값을 대체합니다 (손에 든 무기, 위치).
  - **List**: 항목을 하나씩 추가하고 제거하는 목록입니다 (소지품, 부상).
  - **Description**: 전체가 통째로 다시 쓰이는 텍스트 하나입니다 (옷, 기분).
- **모델을 위한 지침**: 카테고리에 무엇이 들어가고 무엇이 들어가지 않는지를 적습니다. 모델은 이야기를 따라갈 때 이 지침을 읽습니다.
- **텍스트에 적힌 것만**: 켜져 있으면 값은 텍스트가 그렇게 말할 때만 바뀝니다. 꺼져 있으면 명백한 결과(수영 후 젖음)에도 바뀝니다.
- **비어 있으면 "none"이라고 쓰기**: 인물에게 값이 없을 때(잃어버린 무기) 카테고리를 빼는 대신 프롬프트에 *none*이라고 씁니다.

<a id="my-categories"></a>

### 내 카테고리

여러분의 카테고리는 **Settings → Extension Settings → State Tracker**에 있습니다. 책은 이곳에서 카테고리를 복사해 옵니다. 바꾸기 전까지는 기본 제공되는 다섯 가지 카테고리가 있습니다: *Wearing*, *Weapon at hand*, *Carrying*, *Injuries*, *Mood*. 이 설정 화면에서 카테고리를 추가, 편집, 삭제할 수 있으며, 변경한 뒤에는 **Save**를 누르십시오. **Reset to the built-in categories**를 누르면 기본 제공 다섯 가지가 돌아옵니다.

<a id="the-categories-of-a-book"></a>

### 책의 카테고리

책은 사용하는 모든 카테고리의 **자체 복사본**을 보관합니다. 그래서 백업이나 내보내기에 모든 내용이 포함되며, 여러분의 카테고리를 삭제해도 책이 깨지지 않습니다. State 탭의 **Categories of this book** 버튼은 책의 카테고리를 나열합니다:

- **Add from my categories**는 여러분의 카테고리 하나를 책에 복사합니다.
- **New category for this book**은 이 책에만 있는 카테고리를 만듭니다 (배의 화물, 마법 친화도 등). 이런 카테고리에는 *Only in this book*이라고 표시됩니다. **Save to my categories**를 누르면 여러분의 카테고리에 추가되어 다른 책에서도 쓸 수 있습니다.
- 여러분의 카테고리와 더 이상 같지 않은 복사본에는 *Differs from your category*라고 표시됩니다. **Update from my categories**를 누르면 여러분의 버전을 가져옵니다. 여러분이 직접 하기 전에는 아무것도 갱신되지 않습니다. 지침이 바뀌면 모델의 동작이 바뀌기 때문입니다.
- 카테고리를 편집하면 이 책에서만 바뀝니다. 인물들이 그 카테고리의 값을 가지고 있는 동안에는 종류를 바꿀 수 없습니다.
- 책에서 카테고리를 삭제하면 모든 인물의 그 카테고리 값이 함께 삭제됩니다.

## State 탭

[story editor](../books/story-editor.md)의 왼쪽 사이드바에 **State** 탭이 생깁니다. 바꿀 때마다 모든 내용이 책에 저장됩니다.

![추적 중인 인물이 있는 State 탭](../../images/plugin-statetracker.png)

![값의 기록](../../images/plugin-statetracker-history.png)

**Track a character**를 누르면 **name**(이름)을 묻고, 선택적으로 **aliases**(별칭, 부분의 *Present Characters* 필드에 쓰이는 다른 이름들이며 쉼표로 구분합니다)와 **tracked categories**(추적 카테고리)를 묻습니다. 목록에는 책의 카테고리와 여러분의 카테고리가 나옵니다. 여러분의 카테고리를 고르면 책에 복사됩니다. 말은 *Injuries*만 추적하고, 여주인공은 모든 것을 추적할 수 있습니다.

**Import from the Character Tracker**(**Track a character** 옆의 사람 아이콘)는 같은 책의 [Character Tracker](character-tracker.md)에 있는 인물들의 추적을 시작합니다. 책이 아직 추적하지 않는 인물들(이름 또는 별칭 기준)을 한 줄 설명(tagline)과 함께 나열하며, 모두 체크되어 있습니다. 제외할 인물은 체크를 해제하고, 가져오는 모든 인물이 받을 **tracked categories**(책의 것과 여러분의 것, 위와 같음)를 확인한 뒤 **Import**를 누릅니다. 이름만 가져옵니다. 나중에 연필 아이콘(pen)으로 인물에게 다른 카테고리를 추가할 수 있습니다.

추적 중인 모든 인물에게는 카드가 있으며, 처음에는 접혀 있습니다. 카드의 화살표를 눌러 열면 카테고리와 각 카테고리의 현재 값 또는 값들이 보입니다:

- **+**는 단일 값 또는 설명 카테고리의 값을 설정하거나(현재 값은 기록으로 갑니다) 목록에 항목을 추가합니다.
- 연필은 값을 편집하고, × 표시는 값을 **제거**합니다. 더 이상 사실이 아니므로 기록으로 가며 모델에게 보내지 않습니다.
- 자물쇠는 값을 **잠금**(locked) 상태로 표시합니다(흉터, 가문의 검 등). [정리](#tidying-the-state) 기능은 잠긴 값을 건드리지 않습니다. 다만 이야기는 여전히 잠긴 값을 바꿀 수 있습니다.
- **History**는 카테고리의 과거 값과 그 값이 끝난 이유(*replaced*, *removed*, *tidied*)를 보여줍니다. 모델이 값을 끝냈다면, 모델이 그것을 읽은 부분도 함께 보여줍니다. **Restore**는 과거 값을 다시 현재 값으로 만듭니다(단일 값 또는 설명 카테고리의 경우 현재 값은 그 자리를 대신해 기록으로 갑니다). Delete는 값을 영구히 삭제합니다.

인물의 연필 아이콘은 이름, 별칭, 카테고리를 편집합니다. 카테고리의 체크를 해제하면 숨겨지지만 값은 유지되며, 다시 체크하면 값이 돌아옵니다. 휴지통 아이콘은 인물의 추적을 멈추고 그 인물의 상태 전체를 삭제합니다.

## 이야기 따라가기

상태 탭 맨 위의 **처리(Processing)** 패널에서는 모델이 이야기를 읽고 무엇이 바뀌었는지 알아낼 수 있습니다. 강물에 젖은 망토, 다른 사람에게 건넨 등불, 뽑힌 검, 잃어버린 편지 같은 것들입니다. 모델은 활성 분기의 부분들을 순서대로 읽되, **시작 지점(Start point)**부터 읽습니다(기본값은 책의 처음이며, 시작 지점 앞의 부분은 절대 읽지 않습니다). 그리고 어디까지 읽었는지 기억합니다.

![처리 설정](../../images/plugin-statetracker-settings.png)

![변경 제안 검토](../../images/plugin-statetracker-review.png)

- **지금 처리(Process now)**는 아직 처리되지 않은 부분을 모두 읽고, **다음 부분 처리(Process next part)**는 다음 한 부분만 읽습니다. 긴 시리즈는 먼저 요청이 몇 번 필요한지 묻습니다. 이 버튼들 아래의 인물 목록을 아래로 스크롤하면, 탭 맨 위의 막대에도 **지금 처리**, **다음 부분 처리**, **상태 정리(Tidy the state)**가 나타납니다.
- 모델은 부분에 나타나는 추적 중인 인물들을, 각 인물의 범주, 지시문, 현재 값과 함께 받아 변경 사항을 답합니다. 모든 변경에는 부분에서 가져온 인용문이 있어야 합니다. 맞지 않는 변경(인물이 추적하지 않는 범주, 이미 가지고 있는 값, 존재하지 않는 부분에서 가져온 인용문)은 제외됩니다.
- 패널은 진행 상황과 모델이 작성하는 내용을 실시간으로 보여 줍니다. 그동안 계속 읽고 쓸 수 있습니다. **적용 전 확인(Ask before applying)**이 켜져 있으면(기본값) 실행은 당신의 확인을 기다립니다. **변경 검토(Review changes)**는 인물별로 변경 사항을 보여 주는데, 끝나는 값에는 취소선이 그어지고 새 값과 인용문이 함께 나옵니다. 새 값은 고칠 수 있습니다. 잘못된 항목은 체크를 해제하고 **적용(Apply)**을 누르십시오. **취소(Cancel)**를 누르면 아무것도 바뀌지 않으며, 같은 부분들이 다음번에 다시 제안됩니다.
- 모델이 읽은 값에는 그 값이 나온 부분이 표시됩니다. **처리된 부분(Processed parts)**은 읽은 부분들의 목록입니다. **여기서부터 다시 처리(Reprocess from here)**는 그 부분과 그 이후 부분에서 읽은 모든 것을 되돌리고 다시 읽습니다(당신이 쓰거나 고친 값은 그대로 남습니다). 앞부분을 고쳐 쓴 뒤에 이것을 하십시오. 다시 생성한 부분, 스와이프, 다른 분기는 더 이상 존재하지 않는 부분에서 가져온 내용을 스스로 되돌립니다.

<a id="the-story-clock"></a>

### 이야기 시계

설정에서 **이야기 시계(Story clock)**를 켜면(기본값은 꺼짐) 모델은 이야기의 시간도 따라갑니다. 상태와 같은 요청 안에서, 모델은 각 부분이 시간에 대해 말하는 내용을 보고합니다. 예를 들어 *다음 날 아침*, *사흘 뒤*, *그날 밤*, *깨어난 지 40일째*, *4월 20일에*, 대략적인 *몇 주가 뒤섞였다*(근사치로 표시됨), 또는 과거의 회상, 기억, 꿈처럼 시계를 움직이지 않고 상태도 바꾸지 않는 내용입니다. 모델은 날짜를 세지 않습니다. 날짜를 더하는 일은 플러그인이 합니다.

![처리 설정의 이야기 시계](../../images/plugin-statetracker-clock.png)

![손으로 부분의 시간 고치기](../../images/plugin-statetracker-clock-dialog.png)

- **1일차의 기준(Day 1 is the day of)**은 날짜를 세기 시작하는 사건의 이름입니다(*깨어난 날*). 그러면 시간은 *깨어난 뒤 14일째, 저녁*처럼 표시됩니다. **시작 지점의 날(Day at the start point)**, **시간대(Time of day)**, **시작 지점의 날짜(Date at the start point)**는 읽는 첫 부분 이전의 시간을 정합니다. 날짜를 넣으면 시계는 날짜도 셉니다(*1453년 4월 20일*).
- 처리 패널은 이제 **이야기 시간(story time)**을 보여 주고, 처리된 각 부분은 그 뒤의 시간을 보여 줍니다. 명시된 날이나 날짜는 추정치를 대신합니다.
- 부분의 시계 버튼(마지막 부분이라면 이야기 시간 줄의 시계 버튼)은 **시간을 손으로 설정합니다**. 이는 고정점(날, 시간대, 날짜)으로, 부분을 다시 읽어도 대체되지 않으며 시계는 이 점부터 계속 셉니다. 같은 대화상자의 **고정점 제거(Remove the fixed point)**를 누르면 모델의 판독이 다시 셀 수 있습니다.
- 검토에서는 시간이 가장 먼저 **이야기 시간(Story time)** 아래에 각 부분의 인용문과 함께 나옵니다. 잘못된 항목은 체크를 해제하십시오.
- 시계가 켜져 있으면 프롬프트 블록은 시간으로 시작합니다(*이야기 시간: 깨어난 뒤 14일째, 저녁.*). 장면에 추적 중인 인물이 없어도 마찬가지입니다.
- 값은 설정된 이야기 날을 기억합니다(*4일째*). 정리 작업은 그것이 얼마 전인지 알고(*찻잔, 9일 전 설정됨*), 시간이 지나 바랜 것은 버립니다.
- 시계가 켜져 있으면, 추적 중인 인물이 없는 부분도 포함해 모든 부분이 모델에 보내집니다. 어떤 부분이든 시간을 움직일 수 있기 때문입니다.
- 다시 처리, 다시 생성, 다른 분기는 사라진 부분에서 읽은 것을 상태와 마찬가지로 되돌립니다. 다만 당신이 설정한 고정점은 남습니다.

<a id="the-log-of-automatic-changes"></a>

### 자동 변경 기록

검토 없이 적용된 변경(**적용 전 확인**이 꺼진 상태의 실행, 자동 정리, `ask`이 없는 명령)은 처리 패널의 **자동 적용됨(Applied automatically)**에 기록됩니다. 기록에는 누가, 어떤 범주를, 어느 부분에서(또는 *정리됨*), 무엇이 바뀌었는지가 나옵니다(*+ 등불*, *− 밧줄*, *짧은 검 → 도끼*). 기록은 편집할 수 없지만, 모든 행에는 **되돌리기(Revert)** 버튼이 있습니다. 이는 검토에서 그 변경의 체크를 해제한 것과 같이 작동합니다. 변경이 만든 값은 삭제되고, 변경이 끝낸 값이 다시 현재 값이 됩니다. 그 이후에 값을 손으로 바꾸었다면(편집, 삭제, 복원 또는 삭제했거나, 한 범주에 다른 값을 주었다면) 그 행은 건드리지 않습니다. 기록은 최근 200개의 변경을 보관합니다.

![자동 변경 기록](../../images/plugin-statetracker-log.png)

<a id="returning-to-an-earlier-point"></a>

### 이전 시점으로 돌아가기

변경을 적용하는 모든 실행 전에(검토 여부와 관계없이 탭에서 실행하는 경우, 새 부분의 자동 읽기, 명령, 정리), 추적기는 **체크포인트**를 만듭니다. 이는 실행을 만났을 때의 인물들의 상태 전체이며, 이야기 시계와 읽기를 마친 지점(첫 실행 전에는 *책의 시작*)도 포함합니다. 처리 패널의 **체크포인트(Checkpoints)**는 이를 최신순으로 나열합니다. 각 행에는 추적기가 읽은 부분, 시간, 다음에 온 실행의 종류, 적용된 변경 수가 나옵니다. 활성 분기에 있는 부분의 체크포인트만 나열됩니다.

![되돌린 변경](../../images/plugin-statetracker-reverted.png)

행의 **이 시점으로 돌아가기(Return to this point)**는 그 실행과 그 이후의 모든 것을 취소합니다. 인물들의 값(현재와 과거 모두), 이야기 시계의 표시, 처리된 부분, 자동 변경 기록은 체크포인트의 것으로 돌아갑니다. 다음 실행은 그 부분 이후의 부분을 다시 읽으며, 취소된 실행의 부분도 포함됩니다. 추적기가 가지고 있던 것은 체크포인트(*체크포인트로 돌아가기 전*)로 보존되므로 다시 돌아갈 수 있습니다. 시작 지점, 설정, 시계 설정, 책의 범주는 지금 상태 그대로 유지됩니다(그 뒤에 삭제한 범주라도 체크포인트의 값이 그것을 사용하면 다시 나타납니다). 체크포인트 이후에 읽은 모든 것과, 그 이후에 손으로 한 변경도 취소되므로, 실행 전에 먼저 묻습니다. 실행 한 연속이 잘못되었을 때, 또는 책의 오래된 백업을 복원한 뒤 신뢰할 수 있는 지점부터 추적기가 따라잡게 하고 싶을 때 사용하십시오.

추적기는 책마다 최근 20개의 체크포인트를 보관합니다. 체크포인트는 책 안이 아니라 사용자의 파일(*리소스*, 책별로 묶여 있음)에 보관되므로, 책 백업이나 복사본에는 포함되지 않습니다.

<a id="tidying-the-state"></a>

### 상태 정리하기

어떤 상태는 이야기가 말하지 않아도 흐려집니다. 기분, 젖은 옷, 숨이 가쁜 상태, 식사가 끝난 뒤에도 오래 들고 있는 찻잔 같은 것들입니다. 처리 패널의 **상태 정리(Tidy the state)**는 모델에게 이런 것들을 묻습니다. 정리는 마지막으로 처리된 부분들을, 그 부분에 있는 추적 중인 인물들의 현재 값과 함께 읽고, 각 값에 대해 다음 중 하나를 할 수 있습니다.

![정리 검토](../../images/plugin-statetracker-tidy-review.png)

- **삭제(drop)**: 더 이상 사실이 아니거나 더 이상 간직할 가치가 없을 때.
- **갱신(update)**: 부분이 그것이 변했음을 보여 줄 때(분노가 안도로 바뀌었다).
- **병합(merge)**: 같은 것을 가리키는 목록 항목을 합칠 때(*밧줄*과 *밧줄 한 타래*).

정리가 언급하지 않은 값은 그대로 남으며, 잠긴 값도 마찬가지입니다. 각 변경에는 이유가 붙습니다. 정리가 쓴 값(갱신이나 병합)은 이야기가 그것을 명시하지 않았으므로, 마지막으로 읽은 부분과 함께 *정리에 의함*으로 표시됩니다. 그 값을 편집하면 당신의 값이 됩니다. 이 변경은 다른 실행과 같이 검토됩니다(또는 **적용 전 확인**이 꺼져 있으면 즉시 적용됩니다). 정리가 끝낸 값은 기록에 *정리됨*으로 남으며, 정리 전에 읽은 마지막 부분에서 **여기서부터 다시 처리(Reprocess from here)**를 하면 그것을 되돌립니다. 마지막 부분들에 없는 인물은 건드리지 않으므로, 스무 장 동안 자리를 비운 사람이 가진 밧줄은 그대로 남습니다.

**자동 정리(Tidy automatically)**가 켜져 있으면(기본값), 확인 없이 변경을 적용하는 실행이 끝날 때도 정리가 저절로 돌아갑니다. 마지막 정리 이후 **정리 주기(Tidy after this many parts)** 개수의 부분(기본값 10개)이 읽힌 뒤입니다. 검토하는 실행은 정리를 시작하지 않으므로, 두 번째 검토를 억지로 떠맡기지 않습니다.

설정(톱니바퀴)에서:

- **새 부분 자동 처리(Process new parts automatically)**: 부분이 확정되면 모델이 그것을 읽습니다(늦어도 다음 생성 전까지). **적용 전 확인**이 켜져 있으면, **지금 처리**를 누를 때만 읽습니다. 글을 쓰는 중에 검토를 강요하지 않기 위해서입니다.
- **적용 전 확인(Ask before applying)**: 꺼져 있으면 변경은 즉시 적용되고 기록(아래 참조)에 남습니다.
- **실행당 부분 수(Parts per run)**: 한 번의 요청이 몇 개의 부분을 읽는지 정합니다.
- **자동 정리(Tidy automatically)**와 **정리 주기(Tidy after this many parts)**: [상태 정리하기](#tidying-the-state)를 보십시오. 정리는 마지막으로 처리된 부분을 그 개수만큼 읽습니다.
- **모델용 로어북(Lorebook for the model)**: 부분이 활성화하는 항목(기본값), 로어북 전체, 또는 없음.
- **추출 모델(Model for the extraction)**과 **추출 프로토콜(Protocol for the extraction)**: 비워 두면 책의 모델을 사용합니다.
- **새 책에 이 설정 사용(Use these settings for new books)**은 이 책의 설정(모델과 프로토콜 포함, 구분자는 책에 그대로 남음)을, 상태 추적기를 한 번도 쓰지 않은 책이 시작할 때의 설정으로 저장합니다. **새 책 설정 잊기(Forget the settings for new books)**는 내장 설정으로 되돌립니다. 이미 추적기를 쓰고 있는 책은 자기만의 설정을 유지합니다.
<a id="prompts"></a>

## 프롬프트

읽기 단계의 시스템 메시지(**State extraction prompt**)와 정리 단계의 시스템 메시지(**State tidy prompt**)는 [상속된 설정](../books/prompts.md#inherited-settings)입니다. 책은 자체 설정을 쓰고, 없으면 위쪽에서 가장 가까이 설정된 폴더의 설정을 쓰고, 그것도 없으면 사용자 설정을 쓰고, 그것도 없으면 사용자의 프롬프트 언어로 된 내장 텍스트를 씁니다(영어 버전은 실제 모델로 시험했습니다).

책의 *Prompts* 탭에서 *Extension Settings* 아래에 설정하거나, 폴더의 대화상자에서 설정하거나, *Settings → Extension Settings → State Tracker*에서 모든 책에 대해 설정할 수 있습니다(비워 두면 회색으로 내장 텍스트가 표시됩니다). 내장 텍스트의 JSON 응답 형식은 그대로 유지하세요. 플러그인이 이 형식으로 응답을 읽기 때문입니다. 책이 시간을 따를 때는 [이야기 시계](#the-story-clock)의 규칙을 플러그인이 추출 프롬프트 뒤에 자동으로 추가하므로, 프롬프트에 이 규칙을 넣을 필요는 없습니다.

<a id="in-the-prompt"></a>

## 프롬프트에 넣기

기어 버튼에는 책의 설정이 들어 있습니다:

- **In prompt**을 켜면 모든 생성의 프롬프트에 장면 속 추적 중인 인물들의 상태가 삽입됩니다(켜져 있으면 기어 버튼이 초록색으로 바뀝니다).
- **Depth**와 **Role**은 작가의 노트에서와 같이 삽입 위치를 정합니다. *Depth*는 그 뒤에 오는 메시지의 개수입니다(0이면 턴의 지시문 뒤, 1이면 지시문 바로 앞).
- **Name separators**는 *Present Characters* 필드를 어떻게 나눌지 정합니다(기본값은 `,` `;` `/` `|` 및 줄바꿈입니다). 괄호 안의 메모는 무시되므로 `Mara (asleep), Fiora`는 둘 다 찾아냅니다.

프롬프트에는 할 말이 있는 장면의 인물들이 들어갑니다:

```
The current state of the characters of this scene. Keep to it; it changes only when the story changes it:

Fiora:
- Wearing: torn green cloak, leather boots
- Weapon at hand: none
- Carrying: rope; lantern
```

매크로 {%{`{{command::state-tracker-block::{{presentCharacters}}}}`}%}를 사용하면 템플릿의 어느 위치에나 같은 텍스트를 넣을 수 있습니다(인자로는 어떤 이름 목록이든 사용할 수 있습니다). 이 매크로는 **In prompt**의 켜짐 여부와 관계없이 상태를 출력하므로, 매크로를 사용할 때는 **In prompt**를 끄세요. 그렇지 않으면 모델이 상태를 두 번 받게 됩니다.

<a id="commands"></a>

## 명령

명령 막대와 에이전트에서 사용합니다:

| 명령 | 기능 |
|---|---|
| `state-status` | 설정, 책의 카테고리, 그리고 책에 사본이 없는 사용자 카테고리를 보여 줍니다. |
| `list-state-characters` | 추적 중인 인물과 각 인물의 카테고리를 보여 줍니다. |
| `track-state-character` | 인물 추적을 시작합니다: 이름, 별칭, 카테고리 이름을 지정합니다. |
| `stop-tracking-state-character` | 인물 추적을 중단하고 그 상태를 삭제합니다(먼저 확인을 묻습니다). |
| `list-character-state` | 인물의 현재 값과 과거 값을 번호와 함께 보여 줍니다. |
| `set-character-state` | 값을 설정합니다: 인물, 카테고리, 텍스트를 지정합니다. |
| `remove-character-state` | 번호로 지정한 값을 제거합니다. 제거된 값은 기록으로 넘어갑니다. |
| `state-tracker-block` | 인물 목록에 대한 프롬프트 텍스트(매크로)를 보여 줍니다. |
| `state-process` | 모델이 다음 부분을 읽고 변경 사항을 적용하게 합니다. `ask true`와 함께 쓰면 적용하지 않고 번호를 매긴 변경 사항을 돌려줍니다. |
| `apply-state-changes` | `state-process` 또는 `state-tidy`이 돌려준 변경 사항을 전부 또는 지정한 번호만큼 적용합니다. |
| `set-story-time` | 처리된 부분 뒤의 이야기 시간(요일, 시간대, 날짜)을 직접 설정합니다. 아무것도 지정하지 않으면 고정 시점을 제거합니다. |
| `state-tidy` | 희미해진 값을 모델이 삭제, 갱신 또는 병합하게 합니다. `ask true`와 함께 쓰면 변경 사항을 번호와 함께 돌려줍니다. |
| `state-reprocess` | 어떤 부분과 그 이후 부분에서 읽어 들인 내용을 되돌립니다(먼저 확인을 묻습니다). |
| `state-set-start` | 읽기를 시작할 부분을 설정합니다. |
