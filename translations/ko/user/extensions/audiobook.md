# 오디오북

텍스트 음성 변환 서버를 사용해 책을 파트 단위로 오디오북으로 만듭니다. 내레이터에게 목소리 하나를, 등장인물마다 목소리 하나씩을 주고, 이 목소리들은 책의 파트와 함께 저장되어 리더에서 재생됩니다. 초고를 만들 때는 자동으로 실행하게 둘 수 있습니다(모델이 누가 어떻게 말하는지 표시하고, 음성 서버가 읽습니다). 또는 **Audiobook studio**에서 파트를 하나씩 작업하면서 음성 서버로 정확히 무엇이 전송되는지 확인하고 직접 수정한 뒤, 결과를 챕터 표시가 있는 mp3 파일로 내보낼 수 있습니다.

이 확장 기능은 직접 음성을 만들지 않습니다. 사용자가 실행하는 **Chatterbox-TTS-Server**와 통신합니다([음성 서버 설정](audiobook-server.md) 참고). 책의 텍스트는 절대 바뀌지 않으며, 사용자가 지정한 서버 외에는 어디에도 전송되지 않습니다. 오디오는 사용자의 설치 환경에 파트와 연결된 리소스로 저장됩니다.

<a id="what-you-need"></a>

## 필요한 것

- 음성 서버와, 언어 모델과 그래픽 카드를 함께 쓰는 경우에는 음성 서버를 위해 자리를 비우고 다시 멈추는 요청([음성 서버 설정](audiobook-server.md)).
- 목소리: 복제하려는 목소리마다 짧은 **레퍼런스 클립**(한 사람의 12~30초 음성, 음악 없음), 또는 서버가 가진 목소리 파일 중 하나. 내레이터에게는 차분하고 안정적인 낭독 목소리가 필요합니다.
- 목소리가 여러 개인 책에는 텍스트에 표시를 달 수 있는 언어 모델이 필요합니다. 기본적으로는 책에 설정된 모델을 사용합니다.
- **ffmpeg**은 선택 사항입니다. 없으면 모든 기능이 mp3로 작동합니다. 서버에 ffmpeg가 있으면(Docker 이미지에 포함되어 있으며, 데스크톱에서는 `PATH` 또는 `/opt/homebrew/bin` 같은 일반적인 폴더에서 찾습니다. 다른 곳에 있으면 변수 `MARGINALIA_FFMPEG`로 경로를 지정합니다) 내보내기 형식으로 **m4b**를 사용할 수 있고, 관리자는 오디오를 wav로 저장하도록 설정할 수 있습니다.

<a id="the-settings"></a>

## 설정

*설정 → Extension Settings → Audiobook Settings*는 사용자 계정의 패널입니다. 변경한 뒤에는 *설정* 페이지를 저장하세요.

![백엔드와 배우가 있는 패널](../../images/plugin-audiobook-settings.png)

<a id="backends"></a>

### 백엔드

백엔드는 음성 서버와 그 서버가 사용하는 모델을 합친 것입니다. **+**로 백엔드를 추가합니다. **Duplicate**는 선택한 백엔드(주소, 키, GPU 잠금, 목소리, 기본값, 배치 전후의 요청)를 새 이름으로 복사합니다. 같은 컴퓨터에서 다른 모델의 백엔드를 빠르게 만드는 방법입니다. 예를 들어 Chatterbox 옆에 Higgs를 두고 싶다면, 복사한 뒤 모델, 주소, 시작 및 중지 요청을 바꾸면 됩니다.

| 설정 항목 | 기능 |
|---|---|
| Name | Convert 대화상자에 표시되는 이름입니다. |
| Address | 음성 서버의 기본 주소, 또는 그 서버로 요청을 전달하는 장치의 주소입니다. 예: `http://localhost:8004`. |
| Api key | 서버(또는 프록시)가 요구하면 bearer 토큰으로 전송됩니다. 암호화되어 저장되며 다시 표시되지 않습니다. 새 키를 입력해 교체하거나 **Remove the key**를 누르세요. |
| Speech model | **Chatterbox Turbo**(영어, `[sigh]` 같은 사운드 태그 지원, 가장 빠르며 기본값), **Chatterbox**(영어, 발화의 *exaggeration* 설정 지원), **Chatterbox Multilingual**(23개 언어), 또는 **Higgs Audio v3 in ComfyUI**(여러 언어, 대사의 분위기를 살리는 목소리, 울음·헐떡임·신음 같은 소리 지원; [아래](#higgs-audio-v3-emotions-and-sounds) 참고). 백엔드의 [GPU 잠금](../administration/gpus.md)(또는 배치 전 요청)은 이 모델이 로드된 상태로 두어야 합니다. 다른 모델이 필요한 책은 다른 백엔드를 사용합니다. |
| GPU lock | 서버가 실행되는 GPU의 [GPU 잠금](../administration/gpus.md)입니다. 언어 모델이나 다른 서버([이미지 생성기](image-generator.md) 포함)와 GPU를 공유할 때 사용합니다. 모든 배치와 샘플이 GPU를 차례로 사용하며, 잠금이 음성 서버를 먼저 로드합니다. 관리자가 GPU 잠금을 설정한 경우에만 표시됩니다. |
| The server is on this machine or on my network | 로컬 네트워크의 주소를 허용합니다. 클라우드의 서버라면 끄세요. 그러면 서버가 사용자의 컴퓨터를 호출하도록 만들 수 없습니다. |
| Timeout of a request | 음성 한 조각을 기다리는 시간입니다. |
| Restart the server after (pieces) | 메모리를 누수하다가 긴 배치 도중 시스템에 의해 종료되는 음성 서버를 위한 설정입니다. 이 개수만큼 조각을 처리한 뒤에는 배치 이후 요청을 보내고, 이어서 배치 이전 요청을 배치 중간에 다시 보냅니다(중지, 시작, 로드). 그러면 새 서버로 작업이 이어집니다. 0(기본값)이면 이 작업을 하지 않습니다. 서버가 종료되면 이 설정과 관계없이 다시 시작됩니다. [문제 해결](audiobook-server.md#troubleshooting)을 참고하세요. |
| Key of the requests around a batch | 배치 전후 요청이 `Authorization: Bearer`로 보내는 키입니다. 암호화되어 저장되며 다시 표시되지 않습니다(**Remove the key**로 지웁니다). 그래서 읽을 수 있는 상태로 각 요청의 헤더에 적을 필요가 없습니다. 비워 두면 위의 *Api key*가 사용됩니다. LiteLLM 같은 프록시 하나가 모든 요청을 처리할 때는 이 방식이 적합합니다. 자체 `Authorization` 헤더를 가진 요청은 그 헤더를 유지합니다. |
| Narrator voice | 등장인물이 없는 책의 내레이터입니다. 서버의 목소리 파일은 `predefined:Henry.wav`처럼 적습니다. |
| Precision | Higgs 전용: 모델이 계산하는 정밀도입니다. **fp32**(기본값)가 안전한 선택입니다. AMD 그래픽 카드에서 **bf16**을 쓰면 조각이 알아들을 수 없는 소리, 효과음, 잘못된 목소리로 바뀌었습니다. bf16은 그래픽 메모리를 약 절반(16 GB 대신 약 8 GB)만 필요로 하며, 작동하는 환경에서는 더 빠릅니다. |
| Send the text of the clip to Higgs | Higgs 전용, 실험적 기능입니다. 함께 [클립의 텍스트](#voices-and-clips)를 전송합니다. 테스트에서 목소리가 바뀌었으니 끄는 것을 권장합니다. |
| Check the length of the pieces | 기본적으로 켜져 있습니다. 텍스트보다 훨씬 긴 조각(4초 + 단어당 0.6초 기준. 모델이 말을 계속하거나 단어 대신 소리를 낸 경우)은 다음 시드로 다시 만들며, 최대 **재시도 횟수**까지 반복합니다. 적절한 길이의 첫 번째 테이크를 유지하고, 그런 테이크가 없으면 가장 짧은 것을 유지합니다. |
| Check the words with speech recognition | 기본적으로 꺼져 있으며, [음성 인식](#speech-recognition)이 필요합니다. 각 배치가 끝나면 모든 조각을 텍스트로 변환해 원문과 비교합니다. 단어의 **Max. word errors (%)**보다 많이 어긋난 조각은 다음 시드로 다시 만들고 다시 검사하며, 최대 **재시도 횟수** 라운드까지 반복합니다. 틀린 단어가 가장 적은 테이크를 유지합니다. 변환 결과에는 다시 만든 조각 수와 여전히 차이가 나는 조각 수가 표시됩니다. |
| Defaults of a segment | 조각을 시작할 때 쓰는 온도, CFG 가중치, 속도, 청크 크기입니다(스튜디오에서 조각 하나에 대해 바꿀 수 있습니다). Higgs는 온도만 사용합니다. |
| Before a batch, After a batch | 파트 배치(및 각 샘플) 전후에 GPU 잠금 안에서 보내는 요청입니다. 그래픽 카드를 비우고 음성 서버를 시작하는 일은 GPU 잠금이 담당합니다. [모델과 음성을 위한 GPU 하나](audiobook-server.md#one-gpu-for-the-model-and-the-speech)를 참고하세요. 비워 두면 아무 작업도 하지 않습니다. |

**Test connection**은 배치가 하는 작업을 그대로 수행합니다. GPU 잠금을 획득하고(중지된 음성 서버는 시작됩니다), 배치 이전 요청을 보내고, 서버가 응답하며 모델이 로드되어 있는지 확인한 뒤, 배치 이후 요청을 보냅니다. 잠금이나 요청이 없으면 확인만 합니다.

다른 문자 체계의 조각이 있는 책(영어 책 속의 일본어)은 해당 언어를 지정해 다국어 모델로 보냅니다. 다국어 모델용 백엔드가 있을 때만 해당합니다. 없으면 조각은 책의 모델에 그대로 남습니다. Higgs 책은 조각을 그대로 두며, Higgs가 같은 목소리로 직접 읽습니다.
<a id="higgs-audio-v3-emotions-and-sounds"></a>

### Higgs Audio v3: 감정과 소리

**Higgs Audio v3 in ComfyUI** 백엔드를 쓰면 언어 모델이 붙인 레이블이 음성에 반영됩니다. 주소는 ComfyUI의 주소입니다
(TTS Audio Suite 노드가 설치되어 있어야 하며, [음성 서버 설정](audiobook-server.md#higgs-audio-v3-in-comfyui)을 참고하세요).

- 음성 조각의 **전달 방식**은 다음과 같이 읽힙니다: 슬픔, 분노, 기쁨, 재미, 긴장, 두려움, 놀람, 다정함, 비꼼, 애원, 절박함,
  혐오, 흥분, 속삭임, 외침. 강한 전달 방식(강도 0.8 이상)은 더 표현적으로, 약한 전달 방식(0.2 미만)은 담담하게 읽힙니다.
  내레이터는 담담하게 읽습니다.
- 언어 모델은 Chatterbox Turbo보다 더 많은 **소리**를 음성에 넣을 수 있습니다: 웃음, 킥킥거림, 키득거림, 한숨, 헉 소리, 기침, 헛기침,
  코를 훌쩍임, 재채기, 신음, 흐느낌, 울음, 오열, 비명, 헐떡임, 신음(모an), 허밍, 쉿 소리.
- 프로그램은 **각 대사를 둘러싼 서술문**(영어)도 읽고, 모델이 소리를 넣지 않았다면 그 서술이 가리키는 소리를 대사에 넣습니다.
  *"You look funny," she giggled.*는 키득거림이, *She burst out laughing. "Careful!"*는 웃음이, *a soft moan escaped her lips. "Yes..."*는 신음이,
  *panting* 또는 *out of breath*는 헐떡임이, *cried quietly* 또는 *burst into tears*는 울음이 됩니다. 소리처럼 보이기만 하는 표현은 빼고 읽습니다: *"Stop!" she cried.*
  (감탄사), *moaned about the weather*(날씨에 대해 투덜거렸다), *the wind moaned*(바람이 울부짖었다), *the floorboards groaned*(마룻바닥이 삐걱거렸다), *stifled a giggle*(웃음을 참았다),
  *didn't laugh*(웃지 않았다), 그리고 서술이 다른 명명된 인물에게 준 소리도 제외합니다. *"You look funny," he mocked her.*는 비꼬는 또는 재미있어하는 전달 방식이 되고 소리는 붙지 않습니다. 서술 자체는 적힌 그대로 읽힙니다.
- **내레이터는 항상 담담하게 읽힙니다**: 소리도, 감정도 없습니다. 모델이 내레이터에게 맡긴 대사도 마찬가지입니다.
- Higgs는 감정마다 클립을 따로 둘 필요가 없습니다. 목소리의 클립 하나면 충분합니다. 클립의 녹음을 그대로 복제하므로, 깨끗한 클립이 Chatterbox에서보다 더 중요합니다
  ([좋은 클립](#a-good-clip)).
- 각 조각은 ComfyUI가 만들고 만든 뒤 메모리를 비웁니다(조각당 몇 초). 일부 그래픽 카드가 충돌하는 것을 막기 위해서입니다.
- Higgs는 대사의 마지막 단어 뒤에도 소리를 이어가는 경우가 많고(숨소리, 다른 소리의 시작), 클립이 그 중간에서 끊깁니다. 이는 쉼표 앞에 짧은 "휙" 소리로 들립니다. **ffmpeg**가 있으면 확장 기능이 그 꼬리를 잘라내고 각 조각을 페이드 아웃합니다. 없으면 조각은 Higgs가 만든 그대로 남습니다.
- Higgs Audio v3 모델은 **연구 및 비상업용 라이선스**에 따라 제공됩니다. 판매하는 오디오북에는 Boson AI의 라이선스가 필요합니다.

<a id="speech-recognition"></a>

### 음성 인식

**음성 인식**은 음성 대사가 무엇을 말하는지 받아 적습니다. 배치의 조각들을 확인하고(백엔드에 **Check the words with speech
recognition**이 설정된 경우), [음성 클립의 텍스트](#voices-and-clips)를 인식합니다. 실행 위치를 고르세요:

| 설정 | 기능 |
|---|---|
| Speech recognition | **ComfyUI (Granite ASR)**: ComfyUI에 있는 TTS Audio Suite의 Granite 음성 모델입니다(주소는 ComfyUI의 주소). **OpenAI-compatible (whisper)**: `/v1/audio/transcriptions`를 지원하는 모든 서버(faster-whisper, speaches 같은 whisper 서버 또는 OpenAI API)입니다. |
| Address, Api key | ComfyUI의 주소, 또는 API의 기본 주소(`/v1` 포함 또는 제외); 키는 암호화되어 저장됩니다. 주소를 비워 두면 음성 인식을 하지 않습니다. |
| GPU lock | 인식이 사용하는 [GPU 잠금](../administration/gpus.md)입니다. 하나의 카드에서 fp32 Higgs를 쓸 때는 단계를 ComfyUI 재시작으로 설정한 별도의 잠금을 주세요. ComfyUI는 음성 모델을 서버 메모리에 유지하며, 그 옆에 인식 모델을 올리면 서버 메모리가 부족해졌습니다. |
| Model of the recognition | 비워 두면 ComfyUI는 `granite-speech-4.1-2b`, OpenAI-compatible은 `whisper-1`를 씁니다. |
| Timeout, The server is on this machine or on my network | 백엔드와 같습니다. |

**Test connection**은 ComfyUI에 노드가 있는지, 또는 서버가 응답하는지 확인합니다. 배치의 조각들은 배치가 끝난 뒤, 음성 서버를 돌려줄 때 확인되므로, 인식과 음성 모델이 카드를 동시에 필요로 하는 일은 없습니다.

<a id="shared-speech-servers"></a>

### 공유 음성 서버

여러 사용자가 있는 설치에서 관리자는 모두가 쓸 수 있는 음성 서버를 둘 수 있습니다. 그러면 GPU 머신을 한 번만 설정하면 되고, 아무도 주소나 키를 입력할 필요가 없습니다. 관리자는 같은 패널에서 설정합니다(마지막 절들로, 관리자에게만 보입니다). **Shared speech servers**를 열면 자신의 백엔드와 같은 항목들이 있는 창이 열리고, 누가 쓸 수 있는지도 정합니다: **all users**(모든 사용자) 또는 목록에서 고른 사용자. 그 아래의 **Users may add speech servers of their own** 스위치는 아래의 백엔드를 계속 허용할지 정합니다.

이렇게 됩니다:

- 패널 맨 위의 **Backend in use**에는 쓸 수 있는 공유 서버(*(shared)*로 표시)와 자신의 서버가 나열됩니다. *Convert to audio* 창과 스튜디오는 고른 서버를 사용하며, 명령도 이를 사용합니다.
- 공유 서버는 이름만 보이고, 주소, 키, 요청은 보이지 않습니다. 같은 음성 서버 주소를 쓰는 모든 사용자의 배치는 서로 기다리므로, 두 사용자가 같은 GPU를 동시에 쓰는 일은 없습니다.
- 관리자가 서버 사용 권한을 빼앗으면, 아직 그 서버를 지정한 작업은 거부됩니다. 다른 서버를 고르세요.
- 관리자가 자신의 서버를 끄면 패널에 그 사실이 표시됩니다. 직접 추가한 서버는 남아 있으며, 스위치를 다시 켜면 다시 사용됩니다.
- 공유 서버의 *Narrator voice*는 서버의 음성 파일(`predefined:Henry.wav`)이어야 합니다. 참조 클립은 한 사용자의 리소스이므로 다른 사용자가 읽을 수 없습니다. 자신의 배우 목소리는 여전히 그대로 쓸 수 있습니다.

<a id="actors"></a>

### 배우

**배우**는 자신의 목소리입니다. 참조 클립(자신의 오디오 [리소스](../resources.md) 중 하나, 또는 여기서 새로 업로드한 것) 또는
서버의 음성 파일이며, **감정**(속삭임, 외침)이나 **언어**(일본어를 말하는 클립)를 위한 별도의 목소리를 가질 수 있습니다. 언어가 감정보다 우선하며, 이를 위한 목소리가 없으면 배우의 기본 목소리가 읽습니다. 배우는 자신의 계정에 저장되며, 어떤 책이든 내레이터와 등장인물에게 배우를 지정할 수 있습니다.

목소리 옆의 **미리 보기**(배우, 설정, 출연진 안에 있음)는 그 목소리로 말하는 몇 문장을 재생합니다(언어의 경우 그 언어로 된 짧은 문장). GPU가 다른 것을 점유 중이면 GPU 잠금이 먼저 음성 서버를 불러옵니다. 옆의 화살표는 다른 샘플을 제공합니다: 그 목소리를 지원하는 모델(Chatterbox Turbo, Higgs Audio v3)에서는 **with sounds**(한숨, 웃음, 헉 소리), Higgs에서는 레이블링된 모든 **감정**(슬픔, 속삭임, 비꼼...). 배우는 이름으로 나열됩니다.

각 샘플은 GPU를 자기 혼자만 사용합니다. 샘플 후에도 GPU는 음성 서버와 함께 계속 로드되어 있으므로, 언어 모델(또는 다른 서버)의 요청이 GPU를 필요로 하기 전까지 다음 샘플이 바로 재생됩니다. **Voices and clips**를 열면 음성 서버가 미리 로드되므로, 첫 샘플을 기다리지 않습니다.

### 음성과 클립

**음성과 클립**(배우 옆에 있음)은 배우와 그 목소리의 바탕이 되는 클립을 한 창에서 관리하는 곳입니다:

- **배우**: 각 배우마다 목소리, 다른 목소리(감정, 언어)가 몇 개 있는지, 그리고 클립들 중 가장 낮은 품질을 보여 줍니다. 배우를 추가, 편집 또는 삭제할 수 있습니다.
- **클립**: 각 클립마다 길이, **품질**, 그리고 어디에 쓰이는지(배우 - 감정이나 언어와 함께 - 그리고 백엔드의 내레이터)를 보여 줍니다.
  클립을 선택하면 무엇이 문제인지 읽을 수 있고, **재생**, **교체...**, **ffmpeg로 정리**(ffmpeg 필요)를 하거나 삭제할 수 있습니다(아무도 쓰지 않을 때만 가능).
- **교체...**는 여러분의 다른 클립이나 새로 업로드한 클립을 그 클립이 쓰이는 모든 곳에 넣습니다. 조각들은 새 목소리로 다시 만들어집니다.
  이전 클립은 여러분이 삭제하기 전까지 남아 있습니다.
- **클립의 텍스트**: 선택한 클립에서 말해지는 단어들입니다. 직접 입력하거나 **인식**을 눌러 [음성 인식](#speech-recognition)이 받아 적게 한 뒤, 고치고 **저장**하세요. 배우 대화상자에도 배우 목소리 클립에 대한 같은 입력란이 있습니다. 정리된 복사본과 교체된 클립은 텍스트를 그대로 이어받습니다. Higgs는 백엔드가 보낼 때에만 텍스트를 받습니다(기본적으로 꺼져 있음).
- **ffmpeg로 정리**는 클립 옆에 정리된 복사본을 만듭니다(잡음과 윙윙거림을 줄임). 이 복사본은 다시 측정되어 재생해서 비교할 수 있습니다. 더 나아 보이면 클립을 그 복사본으로 교체하세요.
  음악, 효과음, 다른 목소리는 제거하지 않습니다.

<a id="a-good-clip"></a>

#### 좋은 클립

음성 모델은 목소리만이 아니라 **녹음 자체**를 따라 합니다. 방의 울림, 쉬익거리는 잡음, 영화 장면 아래의 음악까지 모든 대사에 되살아나며, 종종 말 아래에 희미한 "쉬익" 소리로 남고 결과물의 어떤 필터로도 완전히 지워지지 않습니다. 그러므로:

- 한 사람이 말한 깨끗한 녹음을 쓰고, 실제로 쉬는 틈이 있어야 합니다(성우의 샘플, 조용한 방에서 집에서 한 낭독). 길이는 12초에서 30초입니다. 영화나 드라마에서 잘라낸 클립은 최악의 경우입니다.
- 품질 표시는 클립에서 측정됩니다. **깨끗함**(쉬는 부분이 말소리보다 최소 45 dB 낮음), **보통**(35~45 dB, 또는 Chatterbox가 잘라내는 30초보다 긴 경우), **나쁨**(배경음, 35 dB 미만; 왜곡됨; 8초보다 짧음). 깨끗하지 않은 클립은 추가할 때 알려 줍니다.
- 최상의 결과를 원하면 직접 클립을 정리하세요. 클립의 쉬는 부분에서 잡음 프로필을 얻어 [Audacity](https://www.audacityteam.org/)의 잡음 제거 기능을 쓰거나, 음악이 섞인 클립이라면 [Ultimate Vocal Remover](https://github.com/Anjok07/ultimatevocalremovergui) 같은 보컬 분리 도구를 쓰세요. ffmpeg 정리는 일정하게 깔린 잡음만 줄입니다. 영화 클립에서 테스트했을 때 약 3 dB 개선되었지만 클립은 여전히 *나쁨*이었습니다.

## 책의 등장인물과 발음

둘 다 책과 함께 보관되며(백업에도 함께 들어갑니다), **오디오로 변환** 대화상자에서 편집합니다.

**등장인물**은 누가 읽는지 정합니다. **내레이터**에는 배우 한 명을, **다른 화자**(등장인물 목록에 없는 화자를 모델이 지정한 경우; 비어 있으면 내레이터가 읽음)에는 배우 한 명을, 그리고 **각 등장인물**마다 배우 한 명을 지정합니다. 등장인물에는 이름과, 본문에서 그 인물을 가리킬 수 있는 다른 이름들(*Tomáš Novák*에 대한 *Tom*)이 있으며, 쉼표로 구분합니다. 대사는 그 인물의 이름, 다른 이름 중 하나, 또는 다른 인물과 공유하지 않는 이름의 한 단어가 대소문자와 악센트를 무시하고 일치할 때 그 인물에게 배정됩니다. **책의 등장인물 추가**는 부분들의 시점 인물과 등장 인물로 목록을 채웁니다.

![책의 등장인물](../../images/plugin-audiobook-cast.png)

**발음**은 텍스트가 *음성을 위해* 어떻게 표기될지를 정합니다. 책 자체는 결코 바뀌지 않습니다. **사전**은 단어 전체를(대소문자가 중요함) 그 단어가 말해질 방식으로 바꿉니다. 이름이나 여러분이 만든 단어의 다른 철자 표기, 또는 일본어의 가나 읽기가 그 예입니다. 영어 책에서는 규칙이 다른 것들도 소리 내어 읽습니다. 숫자, 서수, 연도, 시각, 금액, 약어가 단어로 읽히고, 숫자만 있는 제목은 *Chapter four. The Arch*처럼 읽힙니다(숫자 앞의 단어는 여러분이 정합니다). 마크다운 표시 `*` 같은 것은 무시되며, 장면 구분(`***`, `---`)은 읽히지 않고 더 긴 쉼으로 처리됩니다. 다른 언어의 책이라면 규칙을 끄세요. 사전은 그래도 적용됩니다. **텍스트 시험**은 어떤 텍스트가 어떻게 읽힐지 보여 줍니다. 말해지는 텍스트가 바뀌는 조각은 다시 만들어지고, 나머지는 그대로 유지됩니다.

## 오디오북 변환

*스토리 편집기의 도구 메뉴(톱니바퀴 버튼) → **오디오로 변환***.

![시작하기 전의 대화상자](../../images/plugin-audiobook-convert.png)

1. **백엔드**를 고르고 **불러오기**를 누르면, 활성 가지의 텍스트가 있는 부분들이 각각의 상태와 함께 나열됩니다(첫 번째 부분은 1). 상태는 다음 중 하나입니다.
   *생성 안 됨*, *레이블 지정됨*(모델의 레이블은 저장되었지만 아직 오디오는 없음), *생성됨*(재생 버튼과 다운로드 버튼이 있음), 또는
   *생성됨 (텍스트 변경됨)*(오디오가 이전 텍스트로 만들어졌으므로 다시 만들어야 함). 스튜디오에서 *최종*으로 표시한 부분에는 *(최종)*이 덧붙습니다.
2. 기본 버전을 원하면 **언어 모델로 부분에 레이블 붙이기**를 끈 상태로 두세요. 이때 내레이터가 모든 문단을 읽습니다. 이 옵션을 켜면 모델이 각 대사를 누가 말하는지, 어떻게 말하는지(차분하게, 속삭이며, 소리치며...), 그리고 효과음 태그를 어디에 넣을지 정하고, 등장인물 목록이 목소리를 배정합니다. 책의 모델이 선택되어 있으며, 원하면 다른 모델을 고를 수 있습니다. 부분에는 먼저 레이블이 붙고, 그다음 읽힙니다. 텍스트에 대한 레이블이 이미 있는 부분은, 상자를 껐을 때도 그 레이블을 사용해 읽습니다(모델에게 다시 묻지 않습니다). 그래서 레이블이 있는 책을 상자를 끈 채로 다시 실행해도 대사가 평범한 서술로 바뀌지 않습니다. 평범한 서술을 원하거나 새 레이블을 원할 때는 **레이블 제거**를 누르세요.
3. 부분들을 선택하고(머리글의 상자는 전체를 선택합니다) **계획**을 세워 각 부분에 무엇을 할지 정합니다. **계획** 열에 그 내용이 보이지만 아직 아무것도 실행되지 않습니다.
   **생성**(없는 것만 만듦. 최신 상태인 부분은 다시 만들지 않음), **다시 생성**(오디오를 지우고, 레이블을 제거한 뒤 생성), **오디오 삭제**(부분의 조각들과 합쳐진 오디오를 삭제함. 레이블은 남음), **레이블 제거**(부분을 다음에 만들 때 모델에게 다시 물음), **계획 지우기**. 한 부분에는 단계가 누적됩니다(**생성** 없이 **오디오 삭제**와 **레이블 제거**만 고르면 정리만 합니다). *최종*으로 표시된 부분은 어떤 계획에서도 제외됩니다.
4. **시작**을 누르면 계획이 실행됩니다. 오디오나 레이블을 없애는 단계가 있으면 먼저 확인을 묻습니다. 생성할 항목은 대기열에 들어가며, 이 대기열은 창을 닫거나 페이지를 떠나도 계속 진행됩니다. 대기하거나 실행 중인 부분은 계획에서 제외됩니다. 부분의 행에는 상태, 지금까지 만들어진 조각들, 작업의 메시지가 표시됩니다.
   모델이 부분에 레이블을 붙이는 동안에는 행에 *조각 17–32 레이블 지정 중 (전체 120)*과 같이 표시됩니다(모델에게는 한 번에 조각 16개씩 묻습니다). 레이블이 붙은 부분의 **상태를 클릭**하면, 요청마다 모델의 추론과 답변이 도착하는 대로 읽을 수 있습니다. 이 내용은 완료된 작업을 지우거나(*완료 항목 지우기*) 애플리케이션을 다시 시작할 때까지 작업과 함께 메모리에 보관됩니다.

![대기열: 지금까지 만들어진 조각들, 부분이 끝나면 다운로드 링크](../../images/plugin-audiobook-queue.png)

부분이 만들어지는 과정은 다음과 같습니다.

- 텍스트는 모델이 아니라 **프로그램이 나눕니다**. 서술 조각과 직접 대화 조각으로 나뉘며, 대화는 직선형 또는 곡선형 큰따옴표나 일본식 낫표(「」) 사이에 있는 것으로 봅니다. 제목은 서술로 취급합니다. 모델은 번호가 붙은 조각에 *레이블만* 붙입니다. 효과음 태그가 있는 텍스트는, 태그만 추가되고 다른 것은 전혀 바뀌지 않은 조각일 때만 사용됩니다. 그러므로 모델이 책을 바꿀 수는 없습니다.
- **대사를 누가 말하는지는 모델이 정하고, 서술은 내레이터가 맡습니다.** 편지, 쪽지, 메시지, 등장인물의 생각에는 큰따옴표가 없으므로 프로그램은 이를 서술로 봅니다. 이런 조각은 **기울임꼴로 시작하고**(`*...*` 또는 `_..._`) 모델이 문맥(서명, "글씨체를 보니 분명했다" 같은 표현)으로 등장인물을 밝힌 경우에만 그 인물(등장인물 목록의 목소리)이 읽습니다. 3인칭 서술은, 등장인물의 시점에서 쓰였더라도("그녀는 퍼시가 방을 가로지르는 것을 지켜보았다") 항상 내레이터가 읽습니다. 기울임꼴이 없는 조각에 모델이 등장인물을 배정하더라도 프로그램은 이를 무시합니다. 강조, 소리, 외래어를 위한 기울임꼴도 서술로 취급합니다. 단어는 언제나 작가님의 것입니다.
- **모델에게 주는 지시는 바꿀 수 있는 템플릿입니다.** *설정 → 확장 기능 설정 → 오디오북 설정 → 레이블 지정 프롬프트*가 기본값이며, 책(*프롬프트* 탭 → *확장 기능 설정* → *오디오북*)이나 폴더도 자기만의 지시를 가질 수 있습니다. 비워 두면 상위 폴더의 지시를 쓰고, 그것도 없으면 작가님의 기본값을, 그다음에는 내장된 지시를 씁니다. 지시문은 다른 [프롬프트](../books/prompts.md)와 같은 방식으로 작성합니다. 변수는 `{{characters}}`, `{{deliveries}}`, `{{tags}}`, `{{wordsPerTag}}`이며, 힌트 팝오버에는 **기본 템플릿 삽입**이 있습니다. 지시를 바꾸면, 다음에 만들 때 그 부분들의 레이블을 모델에게 다시 묻습니다.
- **부분들의 음량은 맞춰집니다.** 프로그램 ffmpeg가 설치되어 있으면(`.m4b`을 만드는 것과 같은 프로그램) 모든 부분의 합쳐진 오디오가 같은 음량(EBU R128, 선형, 따라서 다이내믹은 유지됨)으로 맞춰집니다. 기본 목표는 **-18 LUFS**이며, *설정 → 확장 기능 설정 → 오디오북 설정*에서 바꾸거나 끌 수 있습니다. 조각들은 서버가 만든 그대로 보관되고, 합쳐진 부분만 음량이 조정되므로 오디오북이 부분마다 음량이 튀지 않습니다. **이전에 만들어진 부분**은 다시 변환하기 전까지 건드리지 않습니다. 다시 변환하면 보관된 조각들에서 다시 합치고 음량을 맞추며, 음성 서버에는 아무것도 요청하지 않습니다(언어 모델을 내리지도 않습니다). 음량 맞추기를 끄면 이미 맞춰진 부분은 그대로 남습니다. 어떤 부분에서 ffmpeg가 실패하면 그 부분은 원래 오디오를 유지하며, 결과에 그 사실이 표시됩니다.
- 한 번의 클릭으로 시작한 모든 부분은 **음성 모델마다 한 묶음(배치)**으로 만들어집니다. 배치 앞의 요청은 한 번 실행되고, 그다음 모든 조각을 읽고, 그다음 배치 뒤의 요청이 한 번 실행됩니다. 이렇게 해야 그래픽 카드가 부분마다 모델을 바꾸는 일을 막을 수 있습니다.
- 모든 조각은 **내용**(텍스트, 목소리, 모델, 언어, 설정, 시드)으로 보관됩니다. 이미 최신인 부분은 비용이 들지 않고, 바뀐 문단의 조각만 다시 만들어지며, 실패한 부분은 **다시 시도**를 누르면 이미 만들어진 조각을 유지합니다.
- 조각들은 위치에 따라 달라지는 쉼(제목 뒤, 문단 사이, "그가 말했다" 앞)으로 이어져 부분마다 mp3 파일 하나가 되며, 그 부분과 함께 보관됩니다.
- 작가님이 시작한 생성이 실행되는 동안 음성 작업은 기다리므로, 언어 모델이 그 아래에서 내려가지 않습니다.
- 스튜디오에서 **최종**으로 표시한 부분은 건드리지 않으며, 대화상자에 그 개수가 표시됩니다.
- **오디오북 전체**는 최신 오디오가 있는 모든 부분을 mp3 하나로 합치고, 부분마다 챕터 표시를 붙입니다. 목록 아래에 다운로드 링크가 나타나며(제외된 부분의 이름도 표시됩니다), 같은 파일이 내보내기 형식 *챕터 표시가 있는 mp3 하나*에도 해당합니다.
- **모두 중지**는 기다리는 부분을 취소하고 실행 중인 부분을 즉시 멈춥니다. 언어 모델(레이블 지정)이나 음성 서버(읽히는 조각)에 보낸 요청은 기다리지 않고 버려집니다. 시작 전에 멈춘 배치는 앞선 요청을 보내지 않으므로 언어 모델은 메모리에 남습니다. **다운로드**는 완료된 부분의 mp3를 내려받게 합니다.
<a id="the-audiobook-studio"></a>

## 오디오북 스튜디오

*도구 메뉴 → **Audiobook studio*** (선택한 조각의 음성과 미리 듣기는 화자 옆에 있습니다)는 최종 오디오북을 한 번에 한 파트씩 만드는 곳입니다. 대본을 보고, 고치고, 조각을 들어 본 뒤 파트를 만듭니다.

![선택한 발화가 있는 스튜디오](../../images/plugin-audiobook-studio.png)

- 파트에 주석을 달거나 만드는 동안에는 작업이 진행 중이라는 막대가 나타나고, 추가 작업을 시작하는 버튼은 기다리는 상태가 됩니다.
- **주석 달기**는 파트의 대본을 만듭니다. 요청하면 언어 모델로, 그렇지 않으면 내레이터로 만듭니다. 그리고 조각들을 표로 보여 줍니다. 표에는 화자, 전달 방식, 강도, 말하는 텍스트, 그리고 직접 바꾼 조각을 표시하는 표시가 나옵니다. 실행 중에는 옆에 **중지** 버튼이 나타나며, 이 버튼을 누르면 언어 모델에 보낸 요청이 끝납니다.
- 조각을 선택하면 **speaker**, **spoken text**, **delivery**, **intensity**(목소리의 과장 정도, 이를 지원하는 모델에서만 쓰입니다), **language**, **seed**, **pause after**를 고칠 수 있습니다. Higgs에서는 전달 방식과 강도가 말하는 텍스트 맨 앞에 있는 `<|emotion:sadness|>` 같은 표시로 나타나며, 이 값을 바꾸면 표시도 함께 따라 바뀝니다. **적용**을 누르면 변경 내용이 저장되고 조각이 **locks**됩니다. 잠긴 조각은 새 주석 달기를 해도 그대로 유지됩니다. **Unlock**을 누르면 조각이 다시 주석 달기의 대상이 됩니다. *The request the speech server gets*에서는 음성 서버에 보낸 정확한 요청을 볼 수 있습니다.
- **Hear**는 조각 하나의 오디오를 만듭니다. 이때 음성 서버는 그 조각을 위해서만 시작됩니다. **Another take**는 새 seed로 다시 만들며, **takes**는 모두 보관되어 마음에 드는 것을 고를 수 있습니다(*Use this take and hear it*). 좋은 목소리는 흔히 seed 값에 달려 있습니다.
- **Make the part from this script**는 새 주석 없이 조각들을 현재 상태 그대로 이어 붙입니다.
- 파트의 **status**는 *draft*, *reviewed*, *final* 중 하나입니다. 최종(*final*) 파트는 다시 주석이 달리거나 변환되지 않으며, 내보내기를 최종 파트로만 제한할 수 있습니다.

<a id="exporting"></a>

## 내보내기

오디오북은 책의 *이야기 내보내기*에서 고를 수 있는 형식입니다. **Audiobook (one mp3 per chapter, in a zip)**, **Audiobook (one mp3 with chapter marks)**, 그리고 ffmpeg가 설치되어 있으면 **Audiobook (one m4b with chapters)**가 있습니다. 이 파일들은 최신 상태인 파트의 오디오로 만들어집니다. 오디오가 없는 파트나, 텍스트 또는 스튜디오의 대본보다 오래된 오디오가 있는 파트는 제외되며, 창에 어떤 파트인지 표시됩니다. mp3 파일에는 ID3 태그(책 제목, 장, 트랙 번호)가 들어가고, 단일 파일에는 VLC나 대부분의 오디오북 앱에서 보이는 장 표시가 들어갑니다. zip에는 재생 목록이 들어갑니다. 확인란 **Audiobook: only the parts marked final**을 선택하면 스튜디오에서 완료한 파트만 내보내집니다.

**m4b**는 Apple Books와 대부분의 휴대폰 오디오북 앱이 요구하는 형식입니다. 장, 제목, 저자, 장르가 들어간 MP4 컨테이너에 AAC 오디오(64 kbit/s, 음성에는 충분한 품질)를 담습니다. ffmpeg가 이 파일을 만들기 때문에, 이 형식은 ffmpeg가 있는 서버에서만 제공됩니다. mp3로 저장된 오디오는 이를 위해 두 번째로 인코딩되고, wav로 저장된 오디오는 한 번만 인코딩됩니다.

<a id="how-the-audio-is-stored"></a>

### 오디오 저장 방식

관리자는 *Settings → Extension Settings → Audiobook Settings*(관리자만 볼 수 있는 마지막 섹션)에서 설치 전체에 적용할 저장 방식을 고를 수 있습니다.

- **mp3**(기본값): 용량이 작고, 디코더 없이 이어 붙이며, ffmpeg가 필요하지 않습니다. m4b를 만들 때는 손실 압축이 한 번 더 일어납니다.
- **wav**: 무손실이며 용량은 약 10배입니다(한 시간의 음성이 약 170 MB). ffmpeg가 필요합니다. 조각들은 음성 서버에 wav로 요청되고 wav로 이어 붙여집니다. 브라우저는 이를 그대로 재생합니다. mp3와 zip 내보내기는 ffmpeg로 인코딩되며(96 kbit/s), m4b는 한 번만 인코딩됩니다.

이 선택은 이후에 만들어지는 것부터 적용됩니다. 그 전에 만든 파트는 기존 오디오를 유지하며 그대로 처리됩니다. 두 방식이 섞인 파트(이전에 만든 스튜디오의 잠긴 조각)는 wav로 이어 붙여집니다. 두 종류의 파트가 섞인 내보내기도 동작하지만 ffmpeg가 필요합니다.

책 전체의 내보내기는 파트에 저장된 파일로부터 서버의 임시 파일을 만들어 만들어지고, 그곳에서 다운로드됩니다. 그래서 길이는 애플리케이션의 메모리에 제한되지 않습니다. 다만 만드는 동안 임시 폴더에 책 오디오의 약 두 배 공간이 필요합니다(wav라면 한 시간당 약 350 MB).

![오디오북 형식이 있는 내보내기 대화상자](../../images/plugin-audiobook-export.png)

<a id="automatic-conversion"></a>

## 자동 변환

책은 파트가 최종 상태가 되는 즉시 새 파트의 오디오를 스스로 만들 수 있습니다. 책에 자동 주석 달기, 재작성, 번역이 있다면 그 뒤에, [파트 뒤에 오는 작업](../books/story-editor.md#what-follows-a-generated-part)의 마지막 단계로 실행됩니다. 오디오가 만들어질 때까지 실행 중인 작업 패널에서 확인할 수 있으며, 그곳의 **중지**를 누르면 파트가 대기열에서 빠집니다. 이 기능은 기본적으로 **꺼져** 있습니다. 책의 *프롬프트* 탭에서 확장 설정 아래에 있는 항목을 고르거나, 책 폴더 단위로, 또는 오디오북 설정에서 모든 책에 대해 고를 수 있습니다. 가장 가까운 설정이 적용됩니다.

- **아니요**,
- **Yes: the narrator reads the part**,
- **Yes: labelled by the model of the book, the cast gives the voices**. 책에 모델이 없으면 일반 내레이션이 적용되며, 그 사실이 알림으로 표시됩니다.

![책에서의 설정](../../images/plugin-audiobook-auto.png)

파트는 책의 출연진(캐스트)과 발음 정보와 함께 대기열에 들어갑니다. 대기열에 들어갔다는 알림과, 오디오가 준비되었거나 실패했다는 알림이 따로 표시됩니다. 이 알림은 생성을 시작한 페이지에서만 보이지만, 작업 자체는 어느 경우든 *Convert to audio* 창에 나타납니다.

<a id="listening"></a>

## 듣기

오디오가 있는 파트를 가진 책(또는 리더)에는 재생 막대가 나타납니다. 재생 막대에는 재생, 일시 정지, 중지, 재생 속도가 있으며, 지금 읽히는 파트는 본문에 표시됩니다. 재생은 선택한 곳에서, 또는 화면에 보이는 첫 파트에서 시작합니다. 파트를 순서대로 재생하며, 현재 파트가 재생되는 동안 다음 파트를 미리 가져옵니다. 기기의 미디어 컨트롤도 이 책을 인식합니다. 파트의 이전 텍스트로 만든 오디오는 제공되지 않습니다. 오디오는 책의 소유자에게 제공되며, 책이 공개되어 있는 동안에는 책을 열 수 있는 모든 사람에게도 제공됩니다. 공개를 취소한 책은 즉시 오디오 제공이 중단됩니다(플레이어가 다음 파트를 불러올 때 적용됩니다).

![리더의 플레이어](../../images/plugin-audiobook-player.png)

<a id="a-part-without-audio"></a>

### 오디오가 없는 파트

플레이어는 오디오가 없는 파트에서 멈추어, 이야기의 일부가 건너뛰어지지 않도록 하고 그 사실을 알려 줍니다. [Read Aloud](tts-reader.md) 확장이 설치되어 있으면, 재생 막대에 스피커 버튼도 표시됩니다. 버튼의 이름은 **Read this part (and the next ones without audio) with the voice of the browser**입니다. 직접 누르지 않는 한 기계 음성으로 아무것도 읽히지 않습니다. 버튼을 누르면 그 파트와, 이어지는 오디오가 없는 파트들을 기기의 음성으로 읽습니다. 오디오가 있는 파트에 이르면 플레이어가 다시 재생을 이어받습니다. 같은 청취 중에 나오는 나머지 오디오 없는 파트도 다시 묻지 않고 같은 방식으로 읽힙니다. **중지**를 누르면 음성이 멈추고, 플레이어를 다시 시작하면 다시 묻습니다. 음성, 속도, 음높이는 Read Aloud의 설정을 따릅니다.
<a id="commands"></a>

## 명령

[명령](../commands/index.md)과 같은 것들입니다(스토리 편집기의 명령줄, 템플릿의 `command` 매크로, 에이전트). 부분은 변환 대화상자가 번호를 매기는 방식대로 번호가 붙거나, 핸들 이름으로 지정합니다.

| 명령 | 기능 |
|---|---|
| `/audiobook-status [from [to]]` | 사용 중인 음성 서버, 책이 자체적으로 변환하는 방식, 오디오가 있는 부분의 수(없음, 준비됨, 텍스트보다 오래됨, 스크립트보다 오래됨), 스튜디오에 나열된 각 부분의 상태, 그리고 대기열을 보여줍니다. 책이 길 때만 느립니다. |
| `/audiobook-convert [from [to [labelling [what [wait]]]]]` | 부분들을 대기열에 넣습니다(인수가 없으면 책 전체, `from`만 주면 한 부분). `labelling` `true`는 책의 모델을 사용합니다. `what`는 `audio` 또는 `script`입니다(스튜디오용 스크립트만 만들고, 아무것도 읽어주지 않습니다). `wait` `true`를 주면 작업이 끝날 때까지 명령이 계속 실행되며, 진행 상황을 보여주고 각 작업이 어떻게 끝났는지 알려줍니다. 명령을 멈추면 아직 시작하지 않은 작업은 취소됩니다. |
| `/audiobook-stop` | 대기 중인 부분을 취소합니다. 실행 중인 부분은 한 조각을 마친 뒤 멈춥니다. |
| `/audiobook-set-part-status part status` | 스튜디오에서 `draft`, `reviewed` 또는 `final`; 이 부분에는 스크립트가 필요합니다. |
| `/audiobook-cast` | 내레이터, 대체 음성, 그리고 각 배우가 지정된 등장인물 캐스트. |

![명령의 결과](../../images/plugin-audiobook-command.png)

오디오는 [에이전트](../agents.md)의 숨겨진 작업 사본이 아니라 **여러분의** 책을 위해 만들어집니다. 에이전트는 캐스트를 읽을 수 있지만, 다른 명령은 거부되며 직접 실행해야 한다는 안내를 받습니다. 명령줄에서 실행하거나, 에이전트에게 책을 준비하는 일(주석 달기, 검토)을 맡긴 뒤 직접 변환하세요.

<a id="notifications"></a>

## 알림

변환 일괄 작업이 끝나면 브라우저가 알려줄 수 있습니다([알림](../account.md#notifications)). 음성 서버가 작업하는 동안 탭을 떠나 있어도 됩니다. *설정* 페이지의 알림 목록에는 두 줄이 있습니다. **Convert to audio**(대화상자나 명령으로 시작한 일괄 작업)와 **Convert to audio (automatic)**(자동으로 오디오가 된 새 부분). 중단한 일괄 작업은 알리지 않으며, 실패한 부분이 있는 일괄 작업은 실패했다고 알립니다.

![알림 목록](../../images/plugin-audiobook-notifications.png)

<a id="what-it-does-not-do-yet"></a>

## 아직 지원하지 않는 기능(추후 예정)

- mp3와 wav만 지원합니다(opus는 지원하지 않음). 조각들의 음량은 음성이 내는 그대로입니다.
- 효과음이나 배경음은 없습니다.
- 음성 엔진은 두 가지입니다. Chatterbox와 Higgs Audio v3(ComfyUI 내).
- 세그먼트 바깥에서 음성을 미리 듣는 기능(오디션).
- 캐스트는 책 백업에 *배우* 정보로 포함되지 않습니다. 복원된 책은 캐스트를 유지하지만, 계정에 존재해야 하는 배우 이름을 가리킵니다.
