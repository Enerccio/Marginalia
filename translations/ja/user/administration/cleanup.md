# クリーンアップ

Marginalia でユーザーが本、ストーリーのパート、ロアブック、推論プロバイダーなどを削除すると、それは一覧から消えますが、データベースには残ります。これにより削除は安全に行え、参照も維持されます（本は、そのパートを書いたプロバイダーを引き続き把握しています）。それまでは、ユーザーは [ゴミ箱](../trash.md) タブから削除したオブジェクトを復元できます。**クリーンアップ**は、そうした削除済みのデータを完全に取り除き、データベースを小さく保ちます。

![クリーンアップタブ](../../images/admin-cleanup.png)

<a id="running-a-cleanup"></a>

## クリーンアップの実行

!!!warning
クリーンアップは取り消せません。削除されたものは [ゴミ箱](../trash.md) からも消えます。先に [データベースのバックアップを作成](database-backups.md) してください。
!!!

1. 管理ページの **クリーンアップ** タブを開き、**分析** をクリックします。この時点では何も変更されません。
2. 結果を確認します（下記参照）。
3. **クリーンアップを実行** をクリックし、*n 件のオブジェクトが完全に削除されます* の確認に応答します。

クリーンアップはすべてのユーザーのデータが対象です。

クリーンアップがデータベースから削除するのはエントリーと、[エージェント](../agents.md) のファイルのみです。具体的には、完全削除されたエージェントのワークスペースと、完全削除された実行のフォルダーです。削除された [リソース](../resources.md)（パートの画像）のファイルは、[リソースファイル](resource-files.md) タブで削除するまで、所有者のデータフォルダーに残ります。

<a id="seeing-what-is-deleted"></a>

## 削除されたものの確認

テーブルの下の **ゴミ箱** には、すべてのユーザーの削除済みオブジェクトが 1 オブジェクトにつき 1 行で一覧表示されます（テーブルを読み込むには開いてください）。これにより、クリーンアップで何が削除されるかを確認でき、誰かに復元を頼まれたものを戻せます。ユーザーと種類によるフィルターや *拡張コンテンツ* のリンクを含め、[ゴミ箱](../trash.md) タブと同じテーブルです。

![クリーンアップタブのゴミ箱セクション](../../images/admin-trash.png)

<a id="reading-the-analysis"></a>

## 分析結果の読み方

最初のテーブルには、データの種類ごとに 1 行あります。

| 列 | |
|---|---|
| **エンティティ** | データの種類です。`Manuscript`（本）、`ChatMessage`（ストーリーのパート）、`Lorebook`、`LorebookEntry`、`AI`（推論プロバイダー）、`Protocol`、`Summary`、`Tag`、`TagRelation`、`User` など。 |
| **削除済み** | 削除されている件数です。 |
| **完全削除の対象** | *クリーンアップを実行* によって削除される件数です。削除済みオブジェクトに属するデータも含みます。 |
| **ブロック中** | 削除済みですが、まだ使用中のため残されます。 |

**使用中の削除済みオブジェクト** には、ブロックされたオブジェクトが名前と **参照元**（それを今も使っているもの）とともに一覧表示されます。

<a id="what-is-removed"></a>

## 削除されるもの

クリーンアップは、生きているものがもう使っていない削除済みオブジェクトを、それだけに属するデータとともに削除します。

| 削除済み | 一緒に削除されるもの |
|---|---|
| 本 | そのすべてのストーリーのパート、要約、タグの紐付け |
| ロアブック | そのエントリーとタグの紐付け。ほかのロアブックは、それをサブロアブックとして含まなくなります |
| ストーリーのパート | パート本体（その子はすでに親に移動されています）と、その要約 |
| 推論プロバイダーまたはプロトコル | *設定* にあるユーザーの既定値から削除されます |
| タグ | 本とエントリーへの紐付け |
| ユーザー | そのユーザーが所有していたすべて。本（そのストーリーのパートと要約を含む）、ロアブック、推論プロバイダー、プロトコル、タグ、設定 |

<a id="what-is-kept"></a>

## 残されるもの

削除済みオブジェクトは、生きているものがまだ使用している間は **ブロック中** となり、残されます。

| ブロック中 | 理由 | ブロックを解除するには |
|---|---|---|
| 削除された推論プロバイダーまたはプロトコル | 本がそれをモデルまたはプロトコルとして使用している | 本の **概要** タブで別のものを選ぶか、本を削除する |
| 削除されたロアブック（そのエントリーを含む） | 本がそれを使用している | 本で別のロアブックを選ぶか、クリアする |
| 削除されたストーリーのパート | 本のアクティブなブランチの最後のパートである | 本を別のブランチに切り替えるか、本を削除する |
| 削除されたユーザー | 別のユーザーのものが、そのユーザーのデータを使用している（そのユーザーの推論プロバイダーやロアブックを使う本など） | 別のユーザーの本を変更するか、削除する |

ブロックを解除したあとは、もう一度 *分析* を実行してください。

<a id="reference-model"></a>

## 参照モデル

下部の **参照モデル** には、データの種類どうしのすべての参照と、そのポリシーが一覧表示されます。何かがブロックされている理由を理解したいときに役立ちます。

| ポリシー | 意味 |
|---|---|
| **完全削除を阻止** | 削除されたターゲットは、それを参照する生きたオブジェクトがある間は残されます。 |
| **対象と共に完全削除** | 参照元のオブジェクトはターゲットに属しており、ターゲットと一緒に削除されます（エントリーはそのロアブックと一緒に）。 |
| **対象を所有** | ターゲットは参照元のオブジェクトに属します（要約はそのパートに属する）。 |
| **完全削除時に解除** | ターゲットが完全削除されるときに、参照は取り除かれます（サブロアブック、既定のモデル）。 |

拡張機能は、独自のルールでクリーンアップに参加できます。
