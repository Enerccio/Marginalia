# 有声书

将一本书逐部分转换为有声书，借助文本转语音服务器完成：为叙述者和每个角色分配一种声音，这些声音与书的各部分一起保存，并可在阅读器中播放。你可以让它自动运行（模型标注谁在说话、以何种方式说，语音服务器负责朗读），用于快速生成草稿；也可以在 **Audiobook studio** 中逐部分处理，查看发送给语音服务器的确切内容并手动修改，最后导出带章节标记的 mp3 文件。

该扩展本身并不合成语音，它与你运行的 **Chatterbox-TTS-Server** 通信（参见[设置语音服务器](audiobook-server.md)）。书的正文从不被修改，也只会发送给你指定的服务器；生成的音频保存在你自己的安装环境中，作为资源关联到各个部分。

<a id="what-you-need"></a>

## 你需要准备什么

- 一台语音服务器；如果它与你的语言模型共用显卡，还需要相应的请求，以便在合成前腾出显存、合成后释放显存（[设置语音服务器](audiobook-server.md)）。
- 声音：对于每个要克隆的声音，需要一段简短的**参考片段**（一个人说话 12 到 30 秒，不含音乐），或服务器自带的某个声音文件。叙述者需要一种平静、稳定的朗读声音。
- 对于有多个角色声音的书，需要一个能为文本加标注的语言模型。默认使用该书所用的模型。
- **ffmpeg** 是可选的。没有它，一切仍可使用 mp3。如果服务器上装有它（Docker 镜像中已包含；在桌面环境中，它会出现在 `PATH` 或 `/opt/homebrew/bin` 等常见目录中；若安装在其他位置，则使用变量 `MARGINALIA_FFMPEG` 指定路径），导出时即可得到 **m4b** 格式，管理员还可以选择将音频存储为 wav。

<a id="the-settings"></a>

## 设置

*Settings → Extension Settings → Audiobook Settings* 是你账户的面板。修改后请保存 *Settings* 页面。

![带有一个后端和多个角色的面板](../../images/plugin-audiobook-settings.png)

<a id="backends"></a>

### 后端

后端指语音服务器及其所用的模型。点击 **+** 添加一个后端。**Duplicate** 会以新名称复制所选后端（包括地址、密钥、GPU 锁、声音、默认参数以及批处理前后的请求）。这是在同一台机器上快速添加另一种模型后端的方法，例如在 Chatterbox 旁边添加 Higgs：之后只需修改模型、地址以及启动和停止请求即可。

| 设置项 | 作用 |
|---|---|
| Name | 在转换对话框中显示的名称。 |
| Address | 语音服务器的基础地址，或转发到该服务器的地址，例如 `http://localhost:8004`。 |
| Api key | 如果服务器（或你的代理）需要，则以 bearer token 的形式发送。密钥会加密存储且不再显示；输入新密钥即可替换，或使用 **Remove the key** 删除。 |
| Speech model | **Chatterbox Turbo**（英语，支持 `[sigh]` 等声音标签，速度最快，为默认选项）、**Chatterbox**（英语，可调节朗读的 *exaggeration*）、**Chatterbox Multilingual**（支持 23 种语言）或 **Higgs Audio v3 in ComfyUI**（支持多种语言，可根据台词情绪发声，并能produce哭泣、喘息、呻吟等声音；参见[下文](#higgs-audio-v3-emotions-and-sounds)）。该后端的 [GPU 锁](../administration/gpus.md)（或批处理前的请求）必须让此模型保持加载状态。需要其他模型的书，应使用另一个后端。 |
| GPU lock | 服务器所用 GPU 的 [GPU 锁](../administration/gpus.md)，适用于它与语言模型或其他服务器（包括 [Image Generator](image-generator.md)）共用 GPU 的情况：每次批处理和试听都要轮流使用 GPU，锁会先加载语音服务器。仅当管理员设置了 GPU 锁时才显示。 |
| The server is on this machine or on my network | 允许访问本地网络地址。如果服务器在云端，请关闭此项：这样它就无法被用来调用你自己的机器。 |
| Timeout of a request | 等待一段语音生成完成的时间上限。 |
| Restart the server after (pieces) | 针对会泄漏内存、在长时间批处理中被系统终止的语音服务器：每处理这么多段之后，批处理中途会重新发送批处理后的请求，然后是批处理前的请求（停止、启动、加载），之后工作会在一个全新的服务器上继续。默认值 0 表示从不这样做。服务器崩溃时无论此设置如何都会自动重启，参见[故障排除](audiobook-server.md#troubleshooting)。 |
| Key of the requests around a batch | 批处理前后的请求以 `Authorization: Bearer` 头携带的密钥。密钥加密存储且不再显示（**Remove the key** 可清除它），因此无需将其写入每个请求的头部（那样会被明文读取）。留空时使用上方的 *Api key*，这正是你希望的做法：例如一个 LiteLLM 代理负责所有服务时。请求若已有自己的 `Authorization` 头，则保留该头。 |
| Narrator voice | 没有角色表的书的叙述者。服务器上的声音文件写作 `predefined:Henry.wav`。 |
| Precision | 仅适用于 Higgs：模型计算时使用的精度。**fp32**（默认）是安全的选择：在 AMD 显卡上，**bf16** 会使语音片段变成乱码、音效异常以及声音错误。bf16 所需显存约为一半（约 8 GB，而非 16 GB），且在支持的环境中速度更快。 |
| Send the text of the clip to Higgs | 仅适用于 Higgs，属实验性功能：会随请求一同发送[片段的文本](#voices-and-clips)。建议关闭：测试中它会改变声音。 |
| Check the length of the pieces | 默认开启。若某段语音远长于其文本（基准为 4 秒加每词 0.6 秒：模型说个不停，或发出的是声音而非文字），则会使用下一个随机种子重新生成，最多重试 **Retries** 次；保留第一个长度合适的版本，否则保留最短的一个。 |
| Check the words with speech recognition | 默认关闭，需要[语音识别](#speech-recognition)。每批处理完成后，系统会对每段语音进行转录并与其文本比对。若错误词的比例超过 **Max. word errors (%)**，则使用下一个随机种子重新生成并再次检查，最多进行 **Retries** 轮；保留错误词最少的版本。转换结束后会显示有多少段被重新生成，以及仍有多少段存在差异。 |
| Defaults of a segment | 每段语音开始时使用的温度、CFG 权重、语速和分块大小（工作室可以为单段语音单独修改）。Higgs 只使用温度。 |
| Before a batch, After a batch | 围绕每批部分（以及每次试听）发送的请求，在 GPU 锁内执行。释放显卡及启动语音服务器的工作由 GPU 锁负责；参见[一块 GPU 同时用于模型和语音](audiobook-server.md#one-gpu-for-the-model-and-the-speech)。留空则不执行任何操作。 |

**Test connection** 执行的操作与批处理相同：它会获取 GPU 锁（因此已停止的语音服务器会被启动），发送批处理前的请求，询问服务器是否在线且已加载模型，然后发送批处理后的请求。若没有锁或请求，则仅进行询问。

如果一本书中包含其他文字系统的段落（例如英文书中的日文），并且你为该语言配置了后端，这些段落会以其语言交由多语言模型处理；若没有对应后端，则仍使用该书的模型。Higgs 书籍则会保留这些段落：Higgs 会自行朗读它们，且使用同一个声音。
<a id="higgs-audio-v3-emotions-and-sounds"></a>

### Higgs Audio v3：情绪与声音

在 **Higgs Audio v3 in ComfyUI** 后端中，语言模型标注的语气和声音会被听出来。后端地址就是你的 ComfyUI
（需要带 TTS Audio Suite 节点，参见 [设置语音服务器](audiobook-server.md#higgs-audio-v3-in-comfyui)）。

- 一段语音的**表达方式**会被朗读出来：悲伤、愤怒、喜悦、愉快、紧张、恐惧、惊讶、温柔、讽刺、恳求、绝望、
  厌恶、情欲、耳语或呼喊。强度较高（0.8 及以上）的表达更有感染力，强度较低（低于 0.2）的则平淡朗读。
  旁白始终平淡朗读。
- 语言模型可能会在语音中加入比 Chatterbox Turbo 更多的**声音**：笑声、轻笑、咯咯笑、叹气、倒吸气、咳嗽、清嗓子、
  抽鼻子、打喷嚏、呻吟、哭声、啜泣、尖叫、喘息、低吟、哼唱和嘘声。
- 程序还会读取**每段语音周围的叙述**（英文），并为模型未加声音的语音补上叙述中提到的声音：
  *"You look funny," she giggled.* 会加上咯咯笑，*She burst out laughing. "Careful!"* 会加上笑声，*a soft moan escaped her lips. "Yes..."* 会加上呻吟，
  *panting* 或 *out of breath* 会加上喘息，*cried quietly* 或 *burst into tears* 会加上哭声。像 *"Stop!" she cried.*（感叹）、*moaned about the weather*、*the wind moaned*、*the floorboards groaned*、*stifled a giggle*、*didn't laugh*，以及叙述中归于另一个有名字角色的声音，这些只是看起来像声音的文字，程序会忽略。*"You look funny," he mocked her.* 会得到讽刺或愉快的表达，但不加声音。叙述本身按原文朗读。
- **旁白始终平淡朗读**：不加声音，也没有情绪，即使是模型交给旁白的语音也一样。
- Higgs 不需要为每种情绪准备一段音频：一个声音的一段音频就够了。它会复制音频片段的录音，因此干净的片段比 Chatterbox 更重要（[好的音频片段](#a-good-clip)）。
- 每段语音都由 ComfyUI 生成，之后会清空其显存（每段约需几秒），这可以避免部分显卡崩溃。
- Higgs 常常会在最后一个字之后继续（一次换气，或另一个声音的开头），音频片段会在这段尾巴中间结束，听起来像停顿前的一声短促“呼”。使用 **ffmpeg** 扩展功能可以剪掉这段尾巴，并让每段语音淡出；没有它，各段语音保持 Higgs 生成的样子。
- Higgs Audio v3 模型采用**研究和非商业许可**：如果你要销售有声书，需要向 Boson AI 申请许可。

<a id="speech-recognition"></a>

### 语音识别

**语音识别**会把语音说的内容写下来。它会检查一批语音中的每段（当后端勾选了 **Check the words with speech recognition** 时），并识别[语音片段的文字](#voices-and-clips)。请选择它的运行位置：

| 设置 | 作用 |
|---|---|
| Speech recognition | **ComfyUI (Granite ASR)**：你的 ComfyUI 中 TTS Audio Suite 的 Granite 语音模型（地址即 ComfyUI 的地址）。**OpenAI-compatible (whisper)**：任何提供 `/v1/audio/transcriptions` 的服务器，例如 whisper 服务器（faster-whisper、speaches）或 OpenAI API。 |
| Address, Api key | ComfyUI 的地址，或 API 的基础地址（可带或不带 `/v1`）；密钥会加密保存。地址为空：不进行语音识别。 |
| GPU lock | 识别所占用的 [GPU 锁](../administration/gpus.md)。若单张显卡上运行 fp32 版 Higgs，请为识别单独设置一个锁，并让其步骤重启 ComfyUI：ComfyUI 会把语音模型保存在服务器内存中，若在旁边加载识别模型，服务器会内存不足。 |
| Model of the recognition | 留空：ComfyUI 用 `granite-speech-4.1-2b`，OpenAI-compatible 用 `whisper-1`。 |
| Timeout, The server is on this machine or on my network | 与后端相同。 |

**Test connection** 用于检查 ComfyUI 是否具有这些节点，或服务器是否有响应。一批语音的检查在批次完成之后进行，此时语音服务器已交还，因此语音识别和语音模型永远不需要同时占用显卡。

<a id="shared-speech-servers"></a>

### 共享语音服务器

在多用户的安装中，管理员可以为所有人保留语音服务器，这样一台 GPU 机器只需设置一次，无需人人填写地址或密钥。管理员在同一面板中进行设置（位于最后几节，仅管理员可见）：**Shared speech servers** 会打开一个窗口，字段与你自己的后端相同，另外还可以设置谁可以使用：**all users**（所有用户），或列表中选定的用户。那里还有一个开关 **Users may add speech servers of their own**，决定是否仍允许下面的后端。

你可以获得以下功能：

- 面板顶部的 **Backend in use** 会列出你可以使用的共享服务器（标记为 *(shared)*）以及你自己的服务器。*Convert to audio* 窗口和工作室使用你选择的那一个，命令也会使用它。
- 你只能看到共享服务器的名称，看不到它的地址、密钥或请求。同一服务器地址上所有用户的批次会相互等待，因此两个用户无法同时启动同一块 GPU。
- 当管理员收回你对某服务器的使用权时，仍指定该服务器的任务会被拒绝；请改选其他服务器。
- 当管理员关闭你自己的服务器时，面板会提示。你添加的服务器会被保留，如果开关重新打开，它们会再次可用。
- 共享服务器的 *Narrator voice* 应当是该服务器上的语音文件（`predefined:Henry.wav`）：参考音频片段是某个用户的资源，其他人无法读取。你的配音演员一如既往地可用。

<a id="actors"></a>

### 配音演员

**配音演员**是你的一种声音：一段参考音频（你的音频[资源](../resources.md)之一，或在此上传的新音频），或服务器上的语音文件，并可为某种**情绪**（耳语、呼喊）或某种**语言**（说日语的音频片段）设置单独的声音。语言优先于情绪；若没有为它们设置声音，则使用配音演员的主声音朗读。你的配音演员保存在你的账户中；任何书籍都可以把配音演员分配给其旁白和角色。

配音演员旁边的**预览**（在配音演员、设置和演员表中）会用它朗读几句话（语言声音使用该语言的一句短话）并播放；若 GPU 正被其他内容占用，GPU 锁会先加载语音服务器。旁边的箭头可提供其他示例：**with sounds**（叹气、笑声、倒吸气），适用于支持这些声音的模型（Chatterbox Turbo、Higgs Audio v3）；对于 Higgs，则提供标签中的每种**情绪**（悲伤、耳语、讽刺……）。配音演员按名称列出。

每个示例只为其自身占用 GPU。播放示例后，GPU 会与语音服务器保持加载，因此后续示例会立即播放，直到语言模型（或其他服务器）的请求需要 GPU 为止。打开 **Voices and clips** 会预先加载语音服务器，使其第一个示例不必等待。

<a id="voices-and-clips"></a>

### 声音与片段

**声音与片段**（位于演员旁边）是一个窗口，用于管理您的演员以及他们声音所克隆的片段：

- **演员**：每位演员都有自己的声音，以及其他声音（情绪、语言）的数量，以及其片段的最差质量；可添加、编辑或删除。
- **片段**：每个片段显示其时长、**质量**，以及它的使用位置（演员，附带情绪或语言，以及您后端的旁白）。
  选择一个片段可查看其存在的问题，或**播放**它、**替换...**它、**用 ffmpeg 清理**（需要 ffmpeg），或删除它（仅当没有任何地方在使用时）。
- **替换...** 会将另一个片段（您自己的或您上传的）放到该片段所有使用的位置。各部分会用新声音重新生成；
  旧片段会保留，直到您将其删除。
- **片段文本**：所选片段中所说的文字。您可以直接输入，或按**识别**，让[语音识别](#speech-recognition)将其转写下来，然后修正并**保存**。演员对话框中，演员声音的片段也显示同一字段。清理后的副本和替换片段会沿用该文本。Higgs 仅在后端发送该文本时才会使用（默认关闭）。
- **用 ffmpeg 清理**会在片段旁边生成一个清理后的副本（减少持续的嘶嘶声和嗡嗡声），并重新测量，供您播放比较；如果听起来更好，可用它替换原片段。它不会去除音乐、音效或其他人声。

<a id="a-good-clip"></a>

#### 好的片段

语音模型复制的是**录音本身**，而不仅仅是声音：房间、嘶嘶声、电影场景下的背景音乐都会出现在每一句台词中，通常表现为文字下方一种轻柔的“呼呼”声，而任何后期滤波都无法完全去除。因此：

- 请使用一位说话者的干净录音，并且包含真正的停顿（例如配音演员的样本，或在安静房间里在家录制的朗读），时长 12 到 30 秒。从电影或剧集中截取的片段是最糟糕的情况。
- 质量标记是根据片段测量得出的：**干净**（停顿比语音至少低 45 dB）、**一般**（低 35 到 45 dB，或超过 30 秒，Chatterbox 会将其截断）、**差**（背景声音，低于 35 dB；失真；短于 8 秒）。添加时，不干净的片段会被提示。
- 为获得最佳效果，请手动清理片段：使用 [Audacity](https://www.audacityteam.org/) 的降噪功能，并从片段的某个停顿处采集噪声样本；对于含有音乐的片段，可使用人声分离工具，例如 [Ultimate Vocal Remover](https://github.com/Anjok07/ultimatevocalremovergui)。ffmpeg 清理只能降低持续的稳态噪声：在一个电影片段的测试中，它仅提升了约 3 dB，片段仍为**差**。

<a id="the-cast-and-the-pronunciation-of-a-book"></a>

## 书籍的演员表与发音

两者都与书籍保存在一起（它们会随备份一起保存），并在**转换为音频**对话框中编辑。

**演员表**用于指定谁来朗读：**旁白**由一位演员朗读，**其他说话者**由一位演员朗读（即模型指定的、演员表中没有的任何人；若为空，则由旁白朗读），每个**角色**各由一位演员朗读。角色有一个名字，以及文本中可能用来指代它的其他名字（例如 *Tom* 对应 *Tomáš Novák*），各名字之间用逗号分隔；当某段台词中的名字、其他名字之一，或某个不与其他角色共享的名字中的词，与之匹配（忽略大小写和重音符号）时，该台词即归属于该角色。**添加本书的角色**会用各部分的视角人物和出场人物填充该列表。

![书籍的演员表](../../images/plugin-audiobook-cast.png)

**发音**是文本*为语音*所拼写的方式；书籍本身永远不会被修改。**词典**按整个单词替换（区分大小写），替换为朗读时所用的读法：为人名或您自创的词提供的拼读方式，或为日语提供的假名读法。对于英文书籍，规则还会将其他内容朗读出来：数字、序数词、年份、时间、金钱和缩写会以单词形式读出；仅由数字构成的标题会读作 *Chapter four. The Arch*（数字前的词由您决定）；诸如 `*` 之类的 Markdown 标记会被忽略；场景分隔符（`***`、`---`）不会被读出，但会形成一次较长的停顿。对于其他语言的书籍，请关闭这些规则；词典仍然适用。**试听文本**可显示一段文本将被朗读成什么样子。朗读文本发生变化的段落会重新生成，其他段落保留不变。

![书籍的发音](../../images/plugin-audiobook-pronunciation.png)
<a id="converting-a-book"></a>

## 转换一本书

*故事编辑器的工具菜单（齿轮按钮）→ **Convert to audio***。

![开始前的对话框](../../images/plugin-audiobook-convert.png)

1. 选择 **backend**，然后按 **Load**：列出当前分支中有文本的各部分（第一部分为 1），并显示每部分的状态：
   *Not generated*（未生成）、*Labelled*（已标注：模型的标注已保存，但尚无音频）、*Generated*（已生成：带有播放按钮和下载按钮）或
   *Generated (the text changed)*（已生成，但文本已更改：音频是根据旧文本生成的，将重新生成）。如果工作室将某部分标记为定稿，则会加上 *(final)*。
2. 若要普通版本，请保持 **Label the parts with a language model** 关闭：旁白者会朗读每一段。开启后，模型会决定每段对话由谁说、以何种方式说（平静、耳语、大喊……），以及声音标签应放在何处，角色表则为各角色分配声音。书籍所用的模型已选定；如果愿意，可以选择其他模型。各部分会先被标注，然后再朗读。对于文本已有标注的部分，即使该选项关闭，也会按照这些标注朗读（不会再询问模型）。因此，重新运行一本已标注的书而不勾选该选项，并不会把其中的对话变成普通旁白。**Remove labels** 则用于要求改为普通旁白或重新标注。
3. 勾选各部分（表头中的复选框会全部勾选），然后为它们 **plan**（计划）要执行的操作。**Plan** 列会显示计划，但此时尚未执行任何操作：
   **Generate**（生成缺失的部分；已是最新的部分不会重新生成）、**Regenerate**（删除音频、移除标注，然后生成）、
   **Delete audio**（删除该部分的音频片段和合并后的音频，标注保留）、**Remove labels**（下次生成该部分时会再次询问模型）、
   **Clear the plan**（清除计划）。各步骤会在同一部分上累加（**Delete audio** 和 **Remove labels** 若没有配合 **Generate**，则只做清理）。标记为定稿的部分会被排除在所有计划之外。
4. **Start** 执行计划。当计划要删除音频或标注时，会先询问。需要生成的内容会进入你的队列，队列在你关闭窗口或离开页面后仍会继续运行。正在等待或运行中的部分不会被计划纳入。每个部分的状态、已生成的音频片段以及任务消息都会显示在该部分的行中。
   模型在标注某个部分时，该行会显示 *Labelling pieces 17-32 of 120*（模型每次处理约 16 个片段）。**点击已标注部分的状态**，即可逐个请求查看模型的推理过程和回答，内容会随其到达而显示。这些内容与任务一起保存在内存中，直到已完成的任务被清除（*Clear finished*）或应用程序重启为止。

![队列：已生成的片段，以及部分完成时的下载](../../images/plugin-audiobook-queue.png)

以下说明一个部分是如何生成的，便于你了解预期结果：

- 文本由**程序**切分，而不是由模型切分，切分为旁白片段和直接对话片段（直接对话位于直引号或弯引号，或日文角括号之间；标题视为旁白）。模型只会为编号后的片段**添加标注**。只有当带有声音标签的文本是在添加标签后、其他内容未作任何改动的版本时，才会使用该版本，因此模型永远不会改动你的书。
- **谁说某个片段，对于对话是模型的判断；对于旁白则由旁白者负责。** 信件、便条、消息或角色的内心独白没有引号，因此程序将其视为旁白。只有当这类片段**以斜体开头**（`*...*` 或 `_..._`），并且模型根据上下文指出了角色（例如署名或“the handwriting was unmistakable”这类描述）时，才会由该角色（角色表中的声音）朗读。第三人称叙述即使是从角色视角出发的（"She watched as Percy crossed the room"），也始终由旁白者朗读：对于没有斜体的片段，程序会忽略模型指定的角色。用于强调、声音或外来词的斜体同样视为旁白。文字始终是你的。
- **给模型的指令是可以修改的模板。** *Settings → Extension Settings → Audiobook Settings → Labelling prompt* 中的内容是你的默认设置；某本书（*Prompts* 标签页 → *Extension Settings* → *Audiobook*）或某个文件夹可以有自己的指令。留空则使用上一级文件夹的指令，再其次是你的默认指令，最后是内置指令。该指令的写法与其他[提示词](../books/prompts.md)相同：变量为 `{{characters}}`、`{{deliveries}}`、`{{tags}}` 和 `{{wordsPerTag}}`，提示弹出框中有 **Insert Default Template**。修改指令后，相关部分的标注会在下次生成时重新请求模型。
- **各部分的响度会被统一**，前提是安装了程序 ffmpeg（与生成 `.m4b` 所用的是同一个程序）：每个部分的合并音频会被调整到同一响度（EBU R128，线性模式，因此动态范围保留）。**默认为 -18 LUFS**，除非你在 *Settings → Extension Settings → Audiobook Settings* 中更改，也可以在那里将其关闭。各片段保持服务器生成时的原样，只有合并后的部分会被调整响度，因此有声书在各部分之间不会出现音量跳变。**之前生成的部分**在你重新转换之前不会被改动：重新转换会从已保存的片段重新合并并调整响度，并且不会向语音服务器请求任何内容（也不会卸载语言模型）。关闭响度统一后，已经统一过的部分保持原样。如果某个部分的 ffmpeg 失败，它会保留原有音频，并在结果中说明。
- 一次点击所生成的所有部分，会按**每个语音模型一个批次**进行：批次之前的请求只运行一次，然后朗读所有片段，最后运行批次之后的请求，也只运行一次。这样可以避免显卡在每个部分之间切换模型。
- 每个片段都**按内容保存**（文本、声音、模型、语言、设置、随机种子）。已是最新的部分不会产生任何开销，改动过的段落是唯一被重新生成的片段；生成失败的部分会保留已生成的片段，点击 **Retry** 即可继续。
- 片段会按照所在位置加上停顿（标题之后、段落之间、*he said* 之前），合并为每个部分一个 mp3 文件，并与该部分一同保存。
- 你的生成任务运行期间，语音会等待，因此语言模型不会在其运行时被卸载。
- 你在工作室中标记为**定稿**的部分会被保持不变，对话框会说明共有多少个部分被跳过。
- **整本有声书**会将所有拥有最新音频的部分合并为一个 mp3，每个部分有一个章节标记，并在列表下方显示下载链接（未包含的部分会被列出）。同一文件也是导出格式 *one mp3 with chapter marks*（带章节标记的单一 mp3）。
- **Stop all** 会立即取消等待中的部分，并停止正在运行的部分：对语言模型的请求（标注）或对语音服务器的请求（正在朗读的片段）会被直接放弃，而不会等待完成。尚未开始的批次不会发送其之前的请求，因此语言模型保持加载。**Download** 可下载已完成部分的 mp3。
<a id="the-audiobook-studio"></a>

## 有声书工作室

*工具菜单 → **Audiobook studio***（所选片段的声音及其预览位于说话人旁边）是逐部分制作最终有声书的地方：你可以查看脚本、修改脚本、试听片段，并生成该部分。

![选中一段话语时的工作室](../../images/plugin-audiobook-studio.png)

- 当某部分正在标注或生成时，会显示一个进度条，表示有任务正在进行，而会启动更多工作的按钮将暂时等待。
- **Annotate** 用于生成该部分的脚本（如果你要求，会由语言模型完成，否则由旁白完成），并在表格中显示各个片段：说话人、朗读方式、强度、朗读的文本，以及你修改过的片段的标记。运行期间，旁边会出现 **Stop** 按钮，点击后会结束对语言模型的请求。
- 选择一个片段即可编辑其 **speaker**（说话人）、**spoken text**（朗读文本）、**delivery**（朗读方式）、**intensity**（强度，即声音的夸张程度，适用于支持该功能的模型；在 Higgs 上，朗读方式和强度是朗读文本开头的标记，例如 `<|emotion:sadness|>`，修改它们时这些标记会随之变化）、**language**（语言）、**seed**（种子）以及 **pause after**（之后的停顿）。点击 **Apply** 保存修改，同时会**锁定**该片段：新的标注不会改动已锁定的片段。点击 **Unlock** 可将其交还给标注。*The request the speech server gets* 会显示发送给语音服务器的确切请求。
- **Hear** 用于生成某个片段的音频（只生成该片段，此时会为其启动语音服务器）。**Another take** 会使用新的种子重新生成，**takes** 会被保留，以便你选择喜欢的版本（*Use this take and hear it*）。好的声音往往取决于种子。
- **Make the part from this script** 会按现有状态拼接各个片段，不会重新标注。
- 部分的**状态**有 *draft*（草稿）、*reviewed*（已审阅）和 *final*（定稿）三种。定稿的部分不会再次标注或转换，导出时也可以只包含定稿的部分。

<a id="exporting"></a>

## 导出

有声书是书籍 *Export story* 中的一种格式，包括：**Audiobook (one mp3 per chapter, in a zip)**、**Audiobook (one mp3 with chapter marks)**，以及在安装了 ffmpeg 时才会出现的 **Audiobook (one m4b with chapters)**。导出内容由各部分的最新音频构成：如果某部分没有音频，或其音频早于正文或工作室中的脚本，该部分会被排除在外，并且窗口会说明原因。mp3 文件带有 ID3 标签（书名、章节、音轨），单个文件中包含章节标记，VLC 和大多数有声书应用都能显示；zip 包中则附有播放列表。复选框 **Audiobook: only the parts marked final** 可将导出限制为你在工作室中已定稿的部分。

**m4b** 是 Apple Books 和大多数手机有声书应用所采用的格式：音频为 AAC（64 kbit/s，对语音已足够），封装在带有章节、书名、作者和类型信息的 MP4 容器中。该格式由 ffmpeg 生成，因此只有安装了 ffmpeg 的服务器才会提供此选项。以 mp3 存储的音频会为此被二次编码；以 wav 存储的音频只编码一次。

<a id="how-the-audio-is-stored"></a>

### 音频的存储方式

管理员可在 *Settings → Extension Settings → Audiobook Settings*（最后一节，仅管理员可见）中为整个安装实例选择存储方式：

- **mp3**（默认）：体积小，无需解码器即可拼接，不需要 ffmpeg。m4b 则是第二次有损编码。
- **wav**：无损，体积约为 mp3 的十倍（一小时的语音约 170 MB），需要 ffmpeg。片段以 wav 格式向语音服务器请求，并以 wav 拼接；浏览器直接播放该文件；mp3 和 zip 导出由 ffmpeg 编码（96 kbit/s），m4b 只编码一次。

该设置仅对此后生成的内容生效。此前生成的部分保留其音频，并按原样处理；如果一个部分同时包含两种格式的音频（例如工作室中较早锁定的片段），则会以 wav 拼接。同时包含两种格式的部分仍可导出，但需要 ffmpeg。

整本书的导出由服务器上的临时文件从各部分的已存储文件生成，然后从服务器下载，因此其长度不受应用内存的限制。不过，生成过程中临时文件夹需要约两倍于全书音频的空间（若为 wav，每小时约 350 MB）。

![包含有声书格式的导出对话框](../../images/plugin-audiobook-export.png)

<a id="automatic-conversion"></a>

## 自动转换

书籍可以在某个部分定稿后自动生成其音频：在自动标注、重新起草以及翻译（如果书籍有翻译）之后，作为 [该部分之后的流程](../books/story-editor.md#what-follows-a-generated-part) 的最后一步。（在生成音频之前，可在运行面板中查看进度；点击 **Stop** 可将该部分移出队列。）此功能默认**关闭**。你可以在书籍的 *Prompts* 标签页的扩展设置中开启，也可以为一个文件夹中的书籍或你所有书籍在有声书设置中开启；以最近的设置为准：

- **No**（否），
- **Yes: the narrator reads the part**（是：由旁白朗读该部分），
- **Yes: labelled by the model of the book, the cast gives the voices**（是：由书籍的模型进行标注，由角色表分配声音）。若书籍没有设置模型，则使用普通旁白，并会提示你。

![书籍中的设置](../../images/plugin-audiobook-auto.png)

该部分会进入你的队列，并附带书籍的角色表和发音设置。系统会通知你已加入队列，以及音频已就绪或生成失败；这些通知只会显示在发起生成的页面中，不过任务始终可以在 *Convert to audio* 窗口中查看。

<a id="listening"></a>

## 收听

已发布的书籍（或阅读器）若有带音频的部分，会显示一个播放条：包括播放、暂停、停止、语速，以及正在朗读的部分（文本中会标出）。播放从所选部分或当前可见的第一部分开始，按顺序播放各部分，并在当前部分播放时预先获取下一部分。设备的媒体控制也能识别该书。由旧版本文本生成的音频不会被提供。音频会提供给书籍的所有者；书籍发布期间，所有能打开该书的人也都可以获取。撤回发布的书籍会立即停止提供音频（在下一部分加载时生效）。

![阅读器中的播放器](../../images/plugin-audiobook-player.png)

<a id="a-part-without-audio"></a>

### 没有音频的部分

播放器遇到没有音频的部分时会停下来，以免跳过故事的某一部分，并会说明原因。若已安装扩展 [Read Aloud](tts-reader.md)，播放条还会显示一个扬声器按钮 **Read this part (and the next ones without audio) with the voice of the browser**。除非你按下该按钮，否则不会用机器声音朗读任何内容。按下后，它会用你设备的语音朗读该部分以及之后没有音频的部分；当遇到有音频的部分时，播放器会重新接管。同一次收听中，之后没有音频的部分会以相同方式朗读，不再重复询问；点击 **Stop** 可使其静音，重新启动播放器则会再次询问。朗读的声音、语速和音调均使用 Read Aloud 的设置。
<a id="commands"></a>

## 命令

与[命令](../commands/index.md)含义相同（即故事编辑器的命令行、模板中的 `command` 宏，以及智能体）。各部分的编号与转换对话框中的编号一致，也可以用其句柄来指定。

| 命令 | 作用 |
|---|---|
| `/audiobook-status [from [to]]` | 当前使用的语音服务器、书籍自动转换的方式、有多少部分已有音频（无、就绪、比文本旧、比脚本旧）、工作室中每个列出部分的状态，以及队列。仅当书籍很长时才会较慢。 |
| `/audiobook-convert [from [to [labelling [what [wait]]]]]` | 将部分加入队列（不带参数时加入整本书；只给出 `from` 时加入一个部分）。`labelling` `true` 使用书籍的模型；`what` 即 `audio` 或 `script`（仅为工作室生成脚本，不朗读任何内容）。加上 `wait` `true` 后，命令会一直运行到任务结束，显示进度并说明每个任务的结束方式；中止它会取消尚未开始的任务。 |
| `/audiobook-stop` | 取消等待中的部分；正在运行的部分会在当前片段结束后停止。 |
| `/audiobook-set-part-status part status` | 在工作室中使用 `draft`、`reviewed` 或 `final`；该部分需要有脚本。 |
| `/audiobook-cast` | 旁白、备用声音，以及演员表中的角色及其配音演员。 |

![命令的执行结果](../../images/plugin-audiobook-command.png)

音频是为**你的**书制作的，而不是为[智能体](../agents.md)的隐藏工作副本制作的：智能体可以读取演员表，但会被其他命令拒绝，并提示你必须自己运行这些命令。请在命令行中运行它们，或者让智能体负责准备书籍（标注、审校），然后由你自己进行转换。

<a id="notifications"></a>

## 通知

当一批转换完成时，浏览器可以通知你（[通知](../account.md#notifications)，这样在语音服务器工作时你可以离开该标签页）。在 *Settings* 页面的通知列表中有两行：**Convert to audio**（你在对话框中或通过命令启动的批次）和 **Convert to audio (automatic)**（由系统自动转换为音频的新部分）。你中止的批次不会发出通知；包含失败部分的批次会提示失败。

![通知列表](../../images/plugin-audiobook-notifications.png)

<a id="what-it-does-not-do-yet"></a>

## 目前尚不支持的功能

- 仅支持 Mp3 和 wav（不支持 opus）；各片段的响度取决于语音本身的输出。
- 不支持音效或环境音。
