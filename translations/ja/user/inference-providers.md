# 推論プロバイダー

推論プロバイダーとは、モデルへの接続のことです。APIのアドレス、APIキー、モデル、そしてその上限値を指定します。各書籍は1つのプロバイダーを使用します。プロバイダーはいくつでも登録できます。たとえば、物語の執筆には大規模なクラウドモデルを、試作には小さなローカルモデルを使うといった使い分けができ、書籍ごとにいつでも切り替えられます。

プロバイダーはあなたのアカウントに属します。他のユーザーには、プロバイダーもそのAPIキーも見えません。APIキーは暗号化して保存されます（[データフォルダー](administration/index.md#the-data-folder)を参照してください）。

プロバイダーを追加するには、権限 **独自のモデルの作成** が必要です。この権限は管理者が付与します（管理者は常にこの権限を持っています。[権限](administration/permissions.md)を参照してください）。この権限がない場合は、管理者が[共有](#shared-providers)したプロバイダーしか使えません。その場合、**推論プロバイダーを追加** ボタンは表示されません。

![推論プロバイダータブ](../images/inference-providers-list.png)

<a id="supported-apis"></a>

## 対応しているAPI

Marginaliaは、**OpenAI Chat Completions** インターフェースを実装しているAPIであれば、どれとでも動作します（ストリーミング対応のものに限ります：`/v1/chat/completions`）。多くのサービスやローカルサーバーがこれに対応しています。

| サービス | OpenAI URL |
|---|---|
| OpenAI | `https://api.openai.com/v1` |
| OpenRouter | `https://openrouter.ai/api/v1` |
| LiteLLM proxy | `http://localhost:4000/v1` |
| llama.cpp (`llama-server`) | `http://localhost:8080/v1` |
| LM Studio | `http://localhost:1234/v1` |
| Ollama | `http://localhost:11434/v1` |
| vLLM | `http://localhost:8000/v1` |

ポート番号は各サーバーの既定値です。実際にサーバーが使用しているポートを指定してください。

!!!warning ポート8080
Docker版のMarginaliaもポート8080を使用します。同じマシンでllama.cppを動かす場合は、別のポートで起動してください（`llama-server --port 8081`）。
!!!

!!!
[Docker版](getting-started/docker-server.md)では、`localhost`はMarginaliaのコンテナを指します。同じマシン上のモデルサーバーには`http://host.docker.internal:<port>/v1`を使ってください。詳しくは[同じマシン上のモデル](getting-started/docker-server.md#models-on-the-same-machine)を参照してください。
!!!
<a id="adding-a-provider"></a>

## プロバイダーを追加する

**推論プロバイダー**タブを開き、**推論プロバイダーを追加**をクリックします。既存のプロバイダーは鉛筆のボタンで編集し、ごみ箱のボタンで削除します。二枚重ねのシートのボタン（複製）を押すと、プロバイダーのコピーを作れます。コピーの名前は、元の名前に *(Copy)* を付けたものが提案されるので、確認してから確定します。コピーは同じアドレス、モデル、**APIキー**（または拡張機能の設定）、推論の設定、トークン上限、パラメータを持つため、同じサービスの別のモデルを使いたいときは、名前を付けてクリックするだけで済みます。コピーは共有されず、独自の上限や使用量も持ちません。複製できるのは自分のプロバイダーだけです（管理者が共有したものは、そのキーを見られてはいけないので複製できません）。また、プロバイダーを作成する権限があるときに限られます。

ダイアログの上部には次の項目があります。

| 項目 | |
|---|---|
| **名前** | このプロバイダーに付ける名前です。作品のモデルを選ぶときに表示されます。モデル名を含めてください（例: `OpenRouter - Claude Sonnet`）。 |
| **種類** | API の種類です。**OpenAI 互換**、または[拡張機能](extensions/index.md)が提供するプロバイダー用の**拡張機能**があります（その拡張機能が読み込まれている間だけ選べます。例: [Google Gemini](extensions/google-genai.md) や [Anthropic Claude](extensions/anthropic.md)）。種類はプロバイダーを作成した後では変更できません。 |
| **プロバイダー** | 種類が**拡張機能**のときだけ使います。どの拡張機能のプロバイダーかを指定します。その拡張機能の独自の設定が、*種類別設定*タブに表示されます。 |

<a id="per-type-settings"></a>

### 種類別設定

![モデル一覧を読み込んだ状態の種類別設定](../images/inference-provider.png)

このタブはダイアログより背が高く、スクロールして使います。下の方の項目は次のとおりです。

![タイムアウト、再試行回数、追加パラメータ、接続テスト](../images/inference-provider-2.png)

| 項目 | |
|---|---|
| **OpenAI URL（/v1 で終わる）** | API の基本アドレスです。[上の表](#supported-apis)を参照してください。`/chat/completions` は含めません。 |
| **APIキー** | サービスのキーです。ローカルのサーバーは通常キーを確認しないので、空欄のままにしてください。その場合 Marginalia は代わりのプレースホルダー `none` を送ります。 |
| **モデル** | 使用するモデルです。**更新**をクリックすると API からモデル一覧を読み込みます。モデルの ID を直接入力することもできます（例: OpenRouter では `anthropic/claude-sonnet-4.5`）。 |
| **タイムアウト（秒）** | API の応答を待つ時間と、書き始めた後に次の文章を待つ時間です。既定値は 300 です。推論モデルは最初の文章が出るまで数分かかることがあります。この時間の間まったく応答がないリクエストは、タイムアウトのメッセージとともに失敗します（モデルの思考も文章と見なされるので、考え続けているモデルが途中で打ち切られることはありません）。変更は次のリクエストから適用されます。作業中のエージェントのリクエストも含みます。 |
| **再試行回数** | API がレート制限（429）やサーバーエラー（5xx）を返したとき、または接続できなかったときに、リクエストを何回繰り返すかを指定します。試行の間隔は徐々に長くなり、API の `Retry-After` ヘッダーは尊重されます。既定値は 2 です。0 にすると再試行しません。再試行されるのはリクエストの開始部分だけで、すでに届いた文章が二重に書き込まれることはありません。 |
| **トークナイザー** | Marginalia がこのプロバイダー向けに文章のトークン数を数える方法です。**自動**（既定値）は、サーバーのトークナイザーのエンドポイント（OpenAI、llama.cpp、LiteLLM）を順に試し、最初に応答したものを使います。どれも応答しない場合は、ローカルの推定値を使います。特定のものだけを使いたい場合は、それを選んでください。**LOCAL_TOKKIT** を選ぶと、サーバーを一切呼ばないローカルの推定値を使います（数えるためにサーバーが別のモデルを読み込んでしまう場合に便利です）。プラグインのトークナイザーもここに表示されます。プラグインには、アドレス、モデル、文章が渡されますが、APIキーは渡されません。また、選んだときにだけ使われます。**トークナイザーをテスト**を押すと、サンプルの文章を、このプロバイダーが試すトークナイザーで数え、それぞれの応答を表示します。プロバイダーを新規作成するときは、アドレスに合うプラグインのトークナイザーが、自分で選ぶまで初期選択されます。 |
| **思考を送り返す** | 次のリクエストで、モデル自身の思考を送り返すかどうかを指定します。[思考を送り返す](#send-the-thinking-back)を参照してください。OpenAI 互換のプロバイダーでのみ使われます。Anthropic と Google のプロバイダーは、それぞれの API に必要なものを自分で送ります。 |
| **追加パラメータ** | このプロバイダーへのすべてのリクエストに加える追加フィールドを入れる JSON オブジェクトです（例: ローカルサーバー向けの `{"top_k": 40, "min_p": 0.05}`、OpenRouter 向けの `{"provider": {"order": ["anthropic"]}}`）。ここで設定した値は、[プロトコル](protocols.md)（例: `temperature`）や応答の上限（`max_completion_tokens`）から来る同じ設定より優先されます。有効な JSON オブジェクトか、空欄である必要があります。 |

既存のプロバイダーを編集するとき、APIキーは再び表示されません。**APIキーをリセット**をクリックして新しいキーを入力しない限り、現在のキーがそのまま保持されます。

**更新**を押すと、フォームに入力された URL とキーを使って API にモデル一覧を問い合わせます（`/v1/models`）。*モデル一覧の取得に失敗しました*と表示された場合は、URL（`/v1` で終わる必要があります）、キー、サーバーが起動しているかを確認してください。モデル一覧を返さないサービスもあります。その場合は、モデルの ID を直接入力してください。

**接続テスト**は、保存せずにフォームの値を確認します。API にモデル一覧を問い合わせ、続けて選択中の**モデル**に 1 トークンだけの応答を求めます。再試行は行いません。成功のメッセージが出れば、URL、キー、モデルが正しく連携して動作することを意味します。失敗した場合は原因が示されます（[エラーメッセージ](#error-messages)を参照）。モデル一覧のないサービスもあります。その場合、テストは 1 トークンの応答だけを確認します。

<a id="general-settings"></a>

### 一般設定

![推論プロバイダーの一般設定](../images/inference-provider-general.png)

| 項目 | |
|---|---|
| **最大コンテキストサイズ** | 必須です。プロンプトと応答を合わせて、モデルが受け付けるトークンの合計数です。 |
| **最大応答トークン数** | 必須です。モデルが書いてよい応答の最大長です。API には `max_completion_tokens` として送られ、この分の量がコンテキストの中で応答用に空けられます。*最大コンテキストサイズ*より小さい値にしてください。 |
| **接続数** | このモデルに同時に送ってよいリクエストの数です。すべてのユーザーと、すべての種類（自分の生成、補助的な問い合わせ、翻訳、注釈、[エージェント](agents.md#one-model-several-agents)、プラグイン）を合わせた数になります。超えた分は順番に待ちます。待機中の生成には *モデルの応答待ち: この前に N 件のリクエスト* と表示され、**停止**を押すと待ち行列から外れます。既定値は **1** です。GPU が一つだけの、スロットが一つのローカルサーバーではこの値を使います。同時に複数のリクエストに応答できるクラウドのモデルでは、より大きな値にして、生成と並行して補助的な問い合わせを走らせることができます。 |
| **ロア画像を送る** | 作品が使う[ロアブックのエントリーの画像](lorebooks/lorebooks.md#editing-in-full-screen)を、そのテキストとともに送ります。既定ではオフです。画像を受け付けるモデルでのみオンにしてください。画像に対応していないモデルはリクエストを拒否し、そのターンは失敗します。ロアブロック内のエントリーの画像は、システムプロンプトの直後に専用のメッセージとして送られます（モデルが短い応答を返します）。それ以外の画像は、あなたのプロンプトとともに送られます。 |
| **画像をシステムメッセージに入れる** | （OpenAI 互換で、*ロア画像を送る*がオンのとき）ロアブロックの画像を、ロアのテキストと並べて、システムメッセージそのものに入れます。画像をそこで受け付けるサーバーとチャットテンプレートでのみ使ってください。大半はそうではないので、リクエストが失敗します。 |
| **ジェイルブレイクが必要**、**ジェイルブレイクプロンプト** | 特定の内容の執筆を拒否するモデル向けの追加プロンプトです。チェックを入れると、ジェイルブレイクプロンプトがプロンプトの一番先頭に置かれます。 |
| **推論（リーズニング）を有効にする**、**推論の強度** | 推論（「思考」）を行うモデル向けです。[推論モデル](#reasoning-models)を参照してください。 |

Marginalia は、最大応答トークン数の分をコンテキストの中で応答用に空けておき、残りをプロンプトで埋めます。テンプレート、[ロアブック](lorebooks/index.md)のエントリー、[要約](books/summaries.md)はトークン数に含まれ、収まらない古い部分の物語は除外されます。コンテキストが 32 000 トークンで、応答が最大 2 000 トークンの場合、プロンプトには 30 000 トークンが割り当てられます。

**最大コンテキストサイズ**はサービスのドキュメントから確認し、それより少し小さめに設定してください。トークン数は必ずしも正確ではなく、実際の上限を超えたリクエストは失敗します。[プロトコル](protocols.md)は、一部の作品について両方の上限を下げることはできますが、上げることはできません。
<a id="error-messages"></a>

## エラーメッセージ

API がリクエストを拒否した場合、Marginalia は内部エラーを表示する代わりに、何を修正すればよいかを伝え、その後に API 自身が返したメッセージを表示します。

![ユーザーに表示されるプロバイダーのエラー](../images/error-dialog.png)

| メッセージ | 原因 |
|---|---|
| *The provider rejected the API key.* | **APIキー**が間違っている、期限切れである、または未入力である。 |
| *The API key is not allowed to use this model or endpoint.* | キーは有効だが、そのモデルへのアクセス権がない。 |
| *The provider does not know the configured model.* | **モデル**が間違っている。**更新**を使うと、API が認識している名前を確認できる。 |
| *Nothing was found at the configured URL.* | **OpenAI URL** が間違っている。通常は `/v1` で終わる。 |
| *The prompt does not fit into the context of the model.* | **最大コンテキストサイズ**が、モデルが実際に受け付ける値より大きい。値を下げる。 |
| *The provider is limiting requests.* | 再試行の後も、レート制限またはクォータの上限に達している。 |
| *The provider failed to process the request.* | 再試行の後も、サービス側に問題がある（5xx）。 |
| *The provider did not answer in time.* | **タイムアウト（秒）**を上げるか、サーバーの状態を確認する。 |
| *Cannot connect to the provider.* | サーバーが起動していない、または Marginalia から到達できない。あるいは URL に誤字がある。 |
| *The provider rejected the request.* | その他の拒否。多くの場合、**追加パラメータ**にサポートされていないフィールドがあるか、モデルが対応していない推論を指定している。 |

<a id="warning-before-sending"></a>

## 送信前の警告

Marginalia は、コンテキストを **最大コンテキストサイズ** から **最大応答トークン数** を引いた分までしか埋めません。完成したプロンプトがそれでも大きすぎる場合（例えば拡張機能がテキストを追加した場合や、トークン数の見積もりが外れた場合）、リクエストを送信する前に、推定サイズを示す警告が表示されます。リクエストは、それでも送信されます。API がリクエストを拒否するか、プロンプトを切り詰める可能性があります。

![プロンプトが収まらない可能性があるという警告](../images/context-warning.png)

<a id="reasoning-models"></a>

## 推論モデル

推論モデルは、回答する前に考えます。**推論（リーズニング）を有効にする**にチェックを入れると、Marginalia は選択した **推論の強度**（*なし*、*低*、*中*、*高*）を `reasoning_effort` として API に送信します。強度を上げると、通常はより計画的な本文になりますが、応答は遅くなり、費用も高くなります。すべての API がこのパラメータに対応しているわけではありません。推論を有効にしたままリクエストが失敗する場合は、オフにしてください。

モデルが推論内容を返す場合（サーバーによって `reasoning_content` または `reasoning` として返されます）、その内容は **推論を表示** の下に、生成された部分の上に表示されます。推論内容は物語の一部ではなく、**思考を送り返す**（下記）を設定しない限り、モデルに送り返されることもありません。

<a id="send-the-thinking-back"></a>

### 思考を送り返す

**思考を送り返す**（OpenAI 互換プロバイダーの *種類別設定* にあります）は、モデルの思考を次のリクエストでモデルに送り返すかどうかを指定します。送り返す場合は、その前のメッセージの `reasoning_content` として送られます。

| 値 | |
|---|---|
| **なし**（既定） | 送り返さない。ほとんどのモデルやサーバー、未知のフィールドを拒否する API には適している。 |
| **ツール呼び出しの間** | 1 つの応答のツール呼び出しが続いている間だけ送り返す。ツールを呼び出したモデルは、その結果とともに自分の思考を受け取る。あなたの新しいメッセージは、古い思考を持たずに始まる。Google が Gemma 4 に求めている方式がこれです（*thoughts must not be removed between the function calls*、ただしターンの間では削除される）。 |
| **常に** | 思考を持つ以前の応答についても、チャットがそれを保持している場合は送り返す（アークアウトラインのプロットウィザードがこれに当たる）。Gemma 4 のように、古い思考を自分で落とすテンプレートのサーバーでは、この設定は無視される。 |

この設定は、ツールループ（プロットウィザードやツールを使う生成機能）と、エージェントに適用されます。エージェントは、1 つのターンのツール呼び出しが続いている間、以前のラウンドの思考を受け取ります（思考はコンソールのメッセージとともに保持され、保存されたメッセージには含まれません）。サーバーがこのフィールドを受け付ける必要があります。llama.cpp は受け付けます（`reasoning` ではなく `reasoning_content` を読みます）。LiteLLM の背後にある場合も同様です。不明なメッセージフィールドを拒否するプロバイダーでは失敗するため、その場合は *なし* のままにしてください。

![生成された部分の推論](../images/reasoning-view.png)

推論は応答トークンに含まれます。推論モデルには **最大応答トークン数** を大きめに設定してください。そうしないと、長い推論の後で本文が途中で切れることがあります。

<a id="token-counting"></a>

## トークンの計算

Marginalia は、物語がプロンプトのどれだけに収まるかを決めるために、トークンを数えます。可能な場合はプロバイダーに問い合わせ、次の方法を順に試します。

1. OpenAI のトークン計算エンドポイント（`/v1/responses/input_tokens`）、
2. llama.cpp の `/tokenize` エンドポイント、
3. LiteLLM の `/tokenize` エンドポイント、
4. LiteLLM の `/v1/messages/count_tokens` エンドポイント（Anthropic のモデルの場合）、
5. OpenAI のトークナイザーによるローカルの推定。

最初に成功した方法が、それ以降ずっと使われます。ローカルの推定は多くのモデルで近い値になりますが、正確ではありません。そのため、**最大コンテキストサイズ** を実際の上限より少し低く保つことをお勧めする理由の一つでもあります。*拡張機能* の種類のプロバイダーは、その拡張機能の方式で数えます。[Google Gemini](extensions/google-genai.md) と [Anthropic Claude](extensions/anthropic.md) のプロバイダーは、プロバイダーに数えるよう依頼します。

<a id="prompt-cache"></a>

## プロンプトキャッシュ

Marginalia が作業の種類ごとに行うすべてのリクエスト（新しい部分、注釈、書き直し、要約など）には、ヘッダー `X-Session-ID` が付きます。これは、同じユーザーと同じ種類の作業に対して常に同じ値になるハッシュです。プロンプトキャッシュを保持しているサーバーやプロキシは、この値を使って、その種類の前回のリクエストのキャッシュを見つけられます。この値を知らないサーバーは、無視します。ディスクに保存された llama.cpp のスロット 1 つを使う例については、[プロンプトキャッシュとセッション ID](prompt-cache.md) を参照してください。

<a id="shared-providers"></a>

## 共有プロバイダー

複数のユーザーがいるインストール環境では、管理者がプロバイダーを **共有** できます。プロバイダーのダイアログで **全ユーザーと共有** にチェックを入れてください（このチェックボックスは管理者にのみ表示されます）。すると、すべてのユーザーは自分の本の **モデル** の一覧と、自分の **推論プロバイダー** タブにそのプロバイダーを見つけられ、*共有* の欄には **はい** と表示されます。ユーザーはそれを使えますが、開いたり、アドレスや APIキーを見たり、変更したり、削除したりすることはできません。これができるのは所有者だけです。共有プロバイダーを参照している本、バックアップ、復元は、そのプロバイダーが見えるすべてのユーザーにとって引き続き機能します。

![一般ユーザーの推論プロバイダータブにある共有プロバイダー](../images/provider-shared-user.png)

プロバイダーを共有すると、他のユーザーは所有者のサービスのクォータを使えるようになります。ユーザーが自分のプロバイダーを追加できないようにして、共有されたものだけを使えるようにするには、[ユーザーとプロバイダー](administration/users.md#users-and-providers) を参照してください。
<a id="limits-of-shared-providers"></a>

## 共有プロバイダーの制限

管理者は、共有プロバイダーごとに各ユーザーができることを制限できます。**Inference Providers** タブで、共有プロバイダーを所有する管理者は、その行に **Limits**（錠前のアイコン付きのユーザー）ボタンを持っています。これを押すと、設定されている制限の一覧が表で開きます。**Add limit** を押すと新しい制限を作成できます。ユーザーと制限の種類を選んでください。

![共有プロバイダーの制限](../images/provider-limits.png)

| 制限の種類 | 意味 |
|---|---|
| Unlimited | 制限なし（制限を設定しないことと同じ）。 |
| Token limit | ユーザーは一定期間に指定したトークン数まで使用できます。 |
| Not available | ユーザーはプロバイダーを使用できません。そこへリクエストを送ろうとする操作はすべて失敗します。 |

**トークン制限**には **reset**（毎日、毎週月曜から、または毎月。期間はサーバーのタイムゾーンによる暦の期間です）と、3つの上限があります。各上限は空欄にすると制限なしになります。送信トークン（**sent**）、生成トークン（**generated**）、そして両方の合計（**in total**）です。どれか一つでも先に到達すると, 次のリセットまでユーザーは停止します。3つすべてを設定する場合、送信と生成の上限の合計が合計上限を下回ってはいけません（そうでないと合計上限に到達できなくなるため）。下回っている場合は、保存ダイアログが保存を拒否します。例えば、合計 100,000、送信 100,000、生成 20,000 は問題ありませんが、合計 100,000、送信 20,000、生成 10,000 は認められません。

![制限の追加](../images/provider-limit-edit.png)

タイマーによるリセットはありません。ユーザーが新しい期間で初めてプロバイダーを使うとき（または自分の制限を確認するとき）に、使用トークン数は 0 から始まります。リクエストのサイズは送信前にわかるため、プロンプトを送るとユーザーが **sent** または **in total** の上限を超えてしまうリクエストは拒否されます（プロンプトの大きさは Marginalia 独自の見積もりで測るため、サービスの数え方とは少し違うことがあります）。生成トークンは事前にはわかりません。リクエストが終わったときに数えられるため、ユーザーは上限に到達した後にはじめて停止し、最後の応答によって上限を超えることがあります。表に制限がないユーザーは制限されません。

生成トークンが上限を超えないようにするには、**Hard limit**（生成トークンの制限がある場合のみ選べます）にチェックを入れます。リクエストは、許可されている最大の応答分の枠（プロバイダーの **Max Response Size**、またはプロトコルの小さい方の値）を確保します。Hard limit の場合、その枠が生成上限の残りに収まらないとリクエストは拒否されます。そのため、プロバイダーの応答サイズより低い Hard limit を設定すると、すべてのリクエストが拒否されます。表とユーザーの情報では、このような制限の横に *hard* と表示されます。Hard limit が対象とするのは生成トークンだけです。**in total** の上限は、最後の応答によって依然として超えることがあります。

すべてのユーザーには、共有プロバイダーが自分のタブに読み取り専用の行として表示されます。共有プロバイダーの **info** ボタン（i の付いた丸い印）を押すと、自分の制限を確認できます。今期の使用量、制限、リセットの時期が表示されます。制限に到達すると、ストーリーエディター、要約、拡張機能はリクエストを送らずエラーを表示します。

![ユーザーが見る制限と今期の使用量](../images/provider-limit-info.png)

## 使用量

**Inference Providers** タブには、プロバイダーごとに、あなたがそのプロバイダーで使用した **Tokens sent**（プロンプト、「プリフィル」）と **Tokens generated**（応答、推論を含む）が表示されます。これは、すべての本、要約、拡張機能の合計です。共有プロバイダーでは、ユーザーごとに個別のカウントがあるため、表示されるのは自分の分だけです。

管理者には、タブに **Usage per user** ボタンも表示されます。これを押すと、すべてのユーザーが各プロバイダーで使用した量（送信トークン数、生成トークン数、リクエスト数、最後のリクエストの時刻）の表が開きます。

![ユーザー別の使用量](../images/provider-usage.png)

数値はサービスが報告した値です。数値を報告しないサービス（または途中で止めたリクエスト）は、[トークンの数え方](#token-counting)で説明しているローカルの見積もりで数えられるため、その数値はおおよその値です。テキストが一つも届く前に失敗したリクエストは数えられません。管理者が共有プロバイダーに対して[制限](#limits-of-shared-providers)を設定していない限り、これらの数値は情報表示のためだけのものです。

!!!
Marginalia は、トークン数を報告するようサービスに要求します（`stream_options` と `include_usage`）。プロバイダーごとにこの動作を変えるには、その **Additional Parameters** に独自の `stream_options` を入れてください。例えば `{"stream_options": {"include_usage": false}}` のように書きます。これは Marginalia の送信内容を置き換えるため、ローカルの見積もりが使われます。
!!!

<a id="using-a-provider-in-a-book"></a>

## プロバイダーを本で使う

各本のモデルは、その **About** タブの **Model** 欄で設定します。すべての新しい本で使うプロバイダーを決めるには、**Settings** タブで **Default Model** として選んでください。本のプロバイダーを変更すると、次に生成される部分から反映されます。それより前に書かれた部分はそのまま残ります。

<a id="troubleshooting"></a>

## トラブルシューティング

| 問題 | 確認すること |
|---|---|
| *Failed to download model list* | URL が `/v1` で終わっているか、API キー、サーバーが起動していて Marginalia から到達できるか。サービスがモデル一覧を提供しない場合は、モデルの ID を直接入力してください。 |
| *The provider did not answer in time.* | プロバイダーの **Timeout (seconds)** を増やしてください。推論モデルは数分かかることがあります。 |
| *The provider is limiting requests.* | 待つか、**Retries** を増やしてください。 |
| *Book is missing model.* | 本にプロバイダーが設定されていません。**About → Model** で一つ選んでください。 |
| *Contextual limit not sufficient.* | 物語を含まないプロンプトが、コンテキストから応答トークンを引いた量に収まりません。**Max Context Size**（またはプロトコルの **Max Context Tokens**）を増やすか、**Max Response Tokens** を減らすか、テンプレートやロアブックの項目を短くしてください。 |
| テキストが途中で止まる | **Max Response Tokens**（またはプロトコルの **Max Reply Tokens**）が少なすぎます。特に推論モデルの場合に起こりやすいです。 |
| 推論を有効にすると API からエラーが出る | API が `reasoning_effort` に対応していません。**Enable Reasoning** をオフにしてください。 |
