# 책 관리
<a id="the-book-list"></a>

## 책 목록

**책** 탭에는 내 책이 나열됩니다. 다른 사용자의 책은 표시되지 않습니다. 목록은 한 번에 하나의 [폴더](folders.md)를 보여 주며, 현재 폴더의 하위 폴더가 그 책들 위에 표시됩니다. 최상위 수준에서 폴더를 하나도 만들지 않았다면 내 모든 책이 그대로 나열됩니다.

![책 탭](../../images/books.png)

| 열 | |
|---|---|
| **이름** | 책의 이름입니다. |
| **태그** | 책의 태그입니다. |
| **생성됨** | 책을 만든 시각입니다. |
| **마지막 수정** | 책을 마지막으로 바꾼 시각입니다. |

목록은 *마지막 수정* 순으로, 최신순으로 정렬됩니다. 열 머리글을 클릭하면 그 열로 정렬됩니다. 여러 열로 정렬한 경우에는 지정한 순서대로 모든 열을 기준으로 정렬됩니다.

머리글 아래의 행은 목록을 거릅니다.

- **이름** - 이름이 입력한 텍스트로 *시작하는* 책. 와일드카드로 `*`를 쓰면 `*dragon`는 이름 어디에든 "dragon"이 들어 있는 모든 책을 찾습니다.
- **태그** - 선택한 태그를 *모두* 가진 책.

필터 행 끝에 있는 새로 고침 버튼은 목록을 다시 불러옵니다.

각 행에는 버튼이 있습니다. 별 버튼은 책을 [즐겨찾기](folders.md#favorites)로 지정하고, 연필 버튼은 책을 엽니다. **폴더로 이동**은 책을 [폴더](folders.md)에 넣고, 복제 버튼은 책의 사본을 만들며, 휴지통 버튼은 책을 삭제합니다. 머리글에는 **새 폴더**, **관리** 메뉴(**정리하기**, 책과 폴더를 [이동하고 복사](folders.md#organise)하는 창, **책에 태그 지정**, **통계**, **일괄 변경** 하위 메뉴)와 **가져오기**가 있습니다. **가져오기**는 가지고 있는 파일로 새 책을 만듭니다([책 가져오기](#importing-a-book) 참고).

<a id="a-book-is-open-in-one-window"></a>

### 책은 한 창에서만 열려 있습니다

책은 한 번에 한 창에서만 열 수 있습니다. 브라우저의 다른 탭, 다른 브라우저, 휴대전화에서도 마찬가지입니다. 다른 곳에서 이미 열려 있는 책을 열면 Marginalia는 그 책이 언제부터 열려 있었는지 알려 주고 **여기서 열기**를 묻습니다. **여기서 열기**를 선택하면 책이 여기서 열리고, 다른 곳의 창은 이유를 알리며 닫힙니다. 그곳에서 어떤 부분이 생성되고 있다면 질문에 그 사실이 표시되고, **여기서 열기**는 생성을 멈춥니다. 그때까지 쓰인 내용은 남습니다. **취소**를 선택하면 책은 원래 자리에 그대로 남습니다. 로그인했을 때 Marginalia가 마지막에 열었던 책을 다시 열면, 다른 창에 열려 있는 책을 빼앗지 않습니다. 그 책은 닫힌 상태로 두고 어디에서 열려 있는지 알려 줍니다. 닫힌 탭이나 꺼진 기기의 창은 책을 붙잡고 있지 않으므로, **여기서 열기**를 선택하면 바로 열 수 있습니다.

<a id="advanced-search"></a>

### 고급 검색

**검색**(머리글에서 **관리** 옆에 있습니다. 휴대전화에서는 머리글의 돋보기)은 필터 행으로는 찾을 수 없는 책을 찾는 창을 엽니다. 찾고 싶은 항목만 채우고 나머지는 비워 둔 채 **검색**을 누르거나(텍스트 입력란에서는 Enter) 누르십시오.

| 항목 | 찾는 책... |
| ----- | -------------- |
| **이름** | 이름에 텍스트가 들어 있는 책(`*`는 와일드카드). |
| **포함할 태그** | 태그를 가진 책. 입력란 옆에서 고른 대로 *모든 태그* 또는 *태그 중 하나*를 기준으로 합니다. |
| **제외할 태그** | 태그를 가지고 있지 않은 책. *태그 중 하나*를 고르면 그중 하나라도 가진 책은 빠지고, *모든 태그*를 고르면 모든 태그를 가진 책만 빠집니다. |
| **Created from / to**, **Modified from / to** | 지정한 기간에 생성되었거나 마지막으로 바뀐 책. *to* 날짜의 하루도 포함됩니다. |
| **Number of parts from / to** | 모든 분기를 합쳐 그 개수만큼의 부분을 가진 책(휴지통에 있는 부분은 세지 않습니다). |
| **텍스트** | 텍스트의 모든 단어를 가진 부분이 있는 책. 단어, `"phrases"`, `*`는 [이야기 검색](story-editor.md#searching-the-story)에서와 같이 동작합니다. |
| **Include versions** | 끄면(기본값) 부분의 현재 텍스트만 검색합니다. 켜면 부분 중 하나의 이전 버전에 단어가 있는 책도 찾습니다. [버전 기록](version-history.md#searching-the-old-text)을 참고하십시오. |
| **모든 분기에서 검색** | 끄면(기본값) 책을 열었을 때 있는 분기에서만 텍스트를 검색합니다(책을 열었을 때 보이는 이야기). 켜면 모든 분기의 부분에서 검색합니다. |

책은 입력한 모든 조건을 통과해야 합니다. 찾은 책은 태그와 함께 아래에 나열되며, 마지막으로 바뀐 책이 위에 옵니다. 열 머리글을 클릭하면 정렬됩니다. 폴더 버튼은 책을 엽니다(검색 결과 위의 창에서 열리므로, 책을 닫으면 결과 목록으로 돌아옵니다). **지우기**는 입력란을 모두 비웁니다.

![책 고급 검색](../../images/book-search-advanced.png)

<a id="cloning-a-book"></a>

### 책 복제하기

복제 버튼은 새 책의 **이름**을 묻습니다(기본값은 원래 이름에 *(Copy)*를 붙인 이름). 기본으로 체크되어 있는 **현재 분기만** 확인란도 있습니다. 새 책은 독립된 책이며 다음을 받습니다.

![책 복제하기](../../images/book-clone.png)

- 책의 설정(설명, 언어, 프롬프트, 시점, 시제, 문체, 백업 설정), 확장 기능이 책에 저장한 데이터, 그리고 태그.
- 같은 **모델**, **프로토콜**, 그리고 로어북. 로어북은 복사되지 않고 *연결*됩니다. 로어북을 바꾸면 두 책 모두에 반영됩니다.
- 이야기의 자체 사본. 부분, 요약, 그림이 함께 복사됩니다. **현재 분기만**을 선택하면 [활성 분기](branches-and-story-tree.md)의 처음부터 끝까지에 해당하는 부분만 복사되고, 선택하지 않으면 모든 분기가 복사됩니다.

복제본은 자체 [버전 기록](version-history.md#backups-copies-and-the-trash)을 시작합니다(부분마다 버전 하나). 원본의 기록은 복사되지 않습니다.

원본이 공개되어 있어도 복제본은 공개되지 않습니다. 원본은 바뀌지 않습니다. 복제본은 원본과 같은 [폴더](folders.md)에 들어갑니다.

<a id="tagging-many-books-at-once"></a>

### 여러 책에 한 번에 태그 지정하기

머리글의 **관리** 메뉴에 있는 **책에 태그 지정**은 책을 하나씩 열지 않고도 여러 책에 태그를 붙이거나 뗄 수 있는 창을 엽니다. **태그**를 고르거나(새 태그는 입력한 뒤 Enter) 목록을 보면 모든 책과 그 태그가 나타납니다. 고른 태그를 가진 책이 위에 오고, 그 태그가 강조 표시됩니다. 각 행에는 그 책에 태그를 붙이는 **+** 버튼과 떼는 **-** 버튼이 있습니다. 여러 책에 한꺼번에 적용하려면 확인란을 체크하고(머리글의 확인란을 누르면 모두 체크됩니다), 아래의 **선택한 항목에 태그 적용** 또는 **선택한 항목에서 태그 제거**를 사용합니다. 에이전트가 작업 중인 책은 회색으로 표시됩니다. 잠겨 있어서 실행을 일시 정지하거나 멈출 때까지 체크하거나 바꿀 수 없습니다. 같은 창에서 [로어북과 항목](../lorebooks/lorebooks.md#tagging-many-at-once)에도 태그를 지정할 수 있습니다.

![책에 태그 지정하기](../../images/multi-tag-books.png)

<a id="changing-the-model-and-protocol-of-many-books"></a>

### 여러 책의 모델과 프로토콜 바꾸기

**관리** 메뉴의 **일괄 변경** 하위 메뉴에는 **모델/프로토콜 일괄 변경** 항목이 있습니다. 이 항목은 여러 책에 하나의 **모델**이나 **프로토콜**을 각각 열지 않고 적용하는 창을 엽니다. 상자를 비워 두면(*바꾸지 않음*으로 표시됩니다) 그 항목의 책은 그대로 남습니다. 모델만 고르면 모델만 바뀌고 프로토콜은 그대로 유지됩니다. 표는 현재 [폴더](folders.md)에 있는 책을 이름순으로 나열하며, 각 책이 지금 가진 모델과 프로토콜을 보여 줍니다. **하위 폴더 포함**을 체크하면 그 아래의 책도 추가됩니다. **이름** 아래의 필터에 입력해 목록을 좁히고, 바꿀 책을 체크한 뒤(머리글의 확인란을 누르면 표시된 모든 책이 체크됩니다) **바꾸고 종료**를 누르십시오. 필터로 숨겨진 책은 체크가 해제되므로, 보이는 책만 바뀝니다. 에이전트가 작업 중인 책은 회색으로 표시됩니다. 잠겨 있어서 실행을 일시 정지하거나 멈출 때까지 체크하거나 바꿀 수 없습니다.

![여러 책의 모델과 프로토콜 바꾸기](../../images/mass-change-model-protocol.png)

같은 메뉴의 **언어 일괄 변경** 항목은 책의 **언어**에 대해 같은 방식으로 동작합니다. 언어를 고르고, 필터를 적용하고, 책을 체크한 뒤 **바꾸고 종료**를 누르십시오. 표에는 각 책이 지금 가진 언어가 표시되며, 폴더에서 물려받는 언어도 함께 나타납니다([언어](folders.md#language) 참고).

![여러 책의 언어 바꾸기](../../images/mass-change-language.png)

<a id="renaming-many-books"></a>

### 여러 책의 이름 한 번에 바꾸기

**일괄 이름 변경** 항목은 체크한 책의 이름을 한꺼번에 바꿉니다. 방식을 고르십시오.

| 방식 | 하는 일 |
|---|---|
| **접두사 추가** | 이름 앞에 **추가할 텍스트**를 붙입니다. |
| **접미사 추가** | 이름 뒤에 **추가할 텍스트**를 붙입니다. |
| **찾아서 바꾸기** | 이름에 있는 **찾을 내용**을 모두 **바꿀 내용**으로 바꿉니다(비워 두면 지웁니다). 입력한 텍스트는 패턴이 아니라 그대로 취급됩니다. **대소문자 구분**은 기본적으로 꺼져 있습니다. |
| **책에 번호 매기기** | 책에 번호를 붙입니다. **이름 패턴**이 새 이름이 되며, 현재 이름은 `{name}`, 번호는 `{n}`로 씁니다. 예를 들어 `{name} {n}`, `{n}. {name}` 또는 `Chapter {n}`처럼 씁니다. 체크된 첫 책에는 **시작 번호**가 붙고, 다음 책부터는 **증가 단위**만큼 더해집니다. **자릿수**는 번호를 0으로 채웁니다(`007`). |

![모든 폴더의 책에 번호 매기기](../../images/mass-rename.png)

**새 이름** 열은 입력하는 동안 체크된 각 책이 받게 될 이름을 보여 줍니다. **이름 바꾸기**를 누르기 전에 확인하십시오. 번호는 목록의 순서(이름순)대로 체크된 책을 셉니다. 새 이름의 앞뒤 공백은 제거됩니다. 텍스트가 없거나, 패턴에 `{n}`가 없거나, 이름이 하나도 바뀌지 않거나, 이름이 빈 값이 되는 경우에는 아무것도 바뀌지 않고 창이 열린 채 남습니다. 필터, **하위 폴더 포함**, 잠긴 책은 다른 일괄 변경과 같이 동작합니다.

**태그 지정**과 **폴더에 태그 지정** 항목도 현재 폴더의 책 또는 폴더에 대해 같은 방식으로 동작합니다.
<a id="creating-a-book"></a>

## 책 만들기

1. **책 추가**를 클릭합니다.
2. 이름을 입력하고 확인합니다.

새 책은 목록에 표시된 [폴더](folders.md)에 들어가며, 가져온 책도 마찬가지입니다. 새 책은 바로 열립니다.

설정해 두었다면 새 책은 *설정* 탭([계정 및 설정](../account.md) 참고)에서 지정한 **기본 모델**과 **기본 프로토콜**로 시작합니다. 설정하지 않았다면 생성하기 전에 *정보* 탭에서 직접 선택하세요.

<a id="importing-a-book"></a>

### 책 가져오기

목록 위쪽 머리글의 **가져오기**(휴대폰에서는 파일 버튼)를 누르면, 새 책을 만들 수 있는 모든 방법이 담긴 창이 열립니다.
**출처**를 고르면 그에 따라 아래의 안내 문구, 받을 수 있는 파일, 이름 아래의 옵션이 바뀝니다.

| 출처 | 업로드 | 옵션 |
|---|---|---|
| **아카이브에서 가져오기** | 각 파일이 하나의 파트가 되는 `.md` 파일들의 `.zip`, [책으로 가져오기](story-editor.md#importing-into-the-book) 참고 | 없음 |
| **SillyTavern에서 가져오기** | 하나 이상의 `.jsonl` 채팅, [아래](#importing-from-sillytavern) 참고 | 사용자와 어시스턴트 메시지를 하나의 파트로 병합 |
| **LM Studio에서 가져오기** | 하나 이상의 대화, [아래](#importing-from-lm-studio) 참고 | 사용자와 어시스턴트 메시지를 하나의 파트로 병합 |
| **문서에서 가져오기** | 한 파일로 된 원고(Word, LibreOffice, RTF, Markdown, 일반 텍스트, EPUB), [아래](#importing-a-finished-manuscript) 참고 | 파트당 단어 수, 챕터가 시작되는 제목 수준 |
| **Obsidian 보관함에서 가져오기** | 보관함(vault)의 `.zip`, [아래](#from-an-obsidian-vault-or-a-scrivener-project) 참고 | 같음 |
| **Scrivener 프로젝트에서 가져오기** | `.scriv` 프로젝트의 `.zip`, [아래](#from-an-obsidian-vault-or-a-scrivener-project) 참고 | 같음 |

파일을 업로드하고 책 이름을 지정한 뒤(이름은 파일, 문서의 제목 또는 채팅의 캐릭터에서 자동으로 채워지며, 비워 두면 책은 *New book*이 됩니다) **가져오기**를 클릭합니다. **중지**가 있는 진행 창에 저장되는 파트가 표시되며, 중지해도 이미 저장된 내용은 남습니다. 출처가 읽을 수 없는 파일은 경고와 함께 거부되며, 나머지 업로드 파일은 그대로 남습니다.

책의 설정 메뉴(⚙)에서 같은 창을 열면, 선택한 위치에 있는 그 책에 파트를 추가합니다. [책으로 가져오기](story-editor.md#importing-into-the-book) 참고.

### 완성된 원고 가져오기

이미 있는 초고라면 **문서에서 가져오기**를 고르고 파일을 업로드하세요. 가능한 형식은 다음과 같습니다: `.docx` (Word), `.odt` (LibreOffice, OpenOffice), `.rtf` (WordPad, TextEdit 등 다른 프로그램의 서식 있는 텍스트), `.md` (Markdown 파일 하나), `.txt` (일반 텍스트), `.epub` (전자책).

텍스트는 새 책의 파트가 되며, 모두 직접 쓴 글로 표시됩니다. 가져오기는 [통계](statistics.md)에서 집필로 계산되지 않으며, 파트의 기록에는 *문서에서 가져오기*라고 표시됩니다.

- **챕터.** *제목* 스타일의 문단(Markdown 파일에서는 `#` 제목)이 챕터를 시작하며, 각 챕터는 자기 제목으로 시작합니다(파트의 첫 제목이 [내보내기](export.md)에서와 같이 그 파트의 챕터 제목이 됩니다). **챕터가 시작되는 제목 수준**은 어떤 제목이 챕터인지를 정합니다. 선택한 수준과 그보다 위의 수준이 챕터가 됩니다(처음에는 문서에 있는 가장 얕은 수준이 선택됩니다). 그보다 깊은 제목은 작은 제목으로 본문에 남습니다. 제목이 없는 문서는 챕터 하나가 됩니다. 문서의 *제목*은 본문으로 가져오지 않고 책의 이름이 됩니다(Markdown 파일에서는 맨 위 머리글의 `title:`, 또는 `##` 챕터들 앞의 단독 `#` 제목). 일반 텍스트 파일에는 제목이 없으므로, `Chapter 12`, `Part IV: The Return`, `Book two` 또는 `Prologue`(그리고 `Epilogue`, `Interlude`, `Preface`, `Foreword`, `Afterword`)라고만 적힌 줄이 챕터를 시작합니다. 이 경우 제목 수준을 고를 필요는 없습니다.
- **파트당 단어 수.** 텍스트는 문단 사이에서 약 설정한 단어 수만큼씩(처음에는 1000) 잘려 파트가 되며, 이 수에 가장 가까운 문단 경계에서 나뉩니다. 한 파트에 한 챕터의 끝과 다음 챕터의 시작이 함께 들어가지 않으며, 챕터를 쓸데없이 자르지도 않습니다. 챕터 끝에 남는 부분이 이 수의 절반보다 적으면 앞 파트에 붙으므로, 이 수의 1.5배까지의 챕터는 한 파트가 됩니다. 이 수보다 긴 문단은 자르지 않습니다.
- 이름 아래의 줄에는 가져오기로 만들어질 챕터, 단어, 파트의 수가 표시되며, 옵션을 바꾸면 함께 바뀝니다.
- **텍스트 파일의 문단.** 빈 줄이 문단을 나누고, 한 문단의 줄들은 이어 붙습니다(일정한 너비에서 줄바꿈된 글은 한 문단이 됩니다). 빈 줄이 없는 파일은 줄마다 문단이 됩니다. Markdown 파일은 적힌 그대로 유지되며, 빈 줄, 제목, 코드 블록에서 나뉩니다. UTF-8이 아닌 Windows-1252 인코딩의 텍스트도 읽을 수 있습니다.
- **서식.** 기울임꼴과 굵은 글씨는 유지됩니다(Markdown `*italic*`, `**bold**`으로). 그 밖의 서식(글꼴, 크기, 정렬), 이미지, 머리글과 바닥글, 각주, 주석, 변경 내용 추적에서 삭제된 텍스트는 가져오지 않습니다. 표는 셀마다 읽습니다.

![약 500단어 단위의 파트로 나뉜 Word 문서 가져오기](../../images/document-import.png)

오래된 `.doc` 파일은 먼저 `.docx`, `.odt` 또는 `.rtf` 형식으로 저장해야 합니다.

**EPUB**은 읽기 순서대로 페이지마다 읽습니다. 페이지의 제목(`h1`부터 `h6`까지)이 챕터가 됩니다. 제목이 없는 페이지라도 전자책의 목차에 이름이 있으면 그 이름이 제목이 됩니다. 표지, 목차, 각주, 루비 텍스트의 읽기 표기는 제외되며, 전자책의 제목이 책의 이름이 됩니다. DRM으로 보호된 책은 읽을 수 없습니다.

<a id="from-an-obsidian-vault-or-a-scrivener-project"></a>

#### Obsidian 보관함이나 Scrivener 프로젝트에서

둘 다 폴더이므로, 먼저 폴더를 zip으로 압축하세요(Mac에서는 Finder의 **Compress**). Scrivener의 `.scriv`도 폴더입니다. 그런 다음 `.zip`을 업로드합니다. 옵션은 문서의 경우와 같습니다.

- **Obsidian 보관함.** 모든 노트(`.md`)는 노트 이름(또는 그 머리글의 `title:`)을 딴 챕터가 되며, 경로의 순서를 따르되 숫자는 숫자로 셉니다(`Chapter 2`이 `Chapter 10`보다 앞). 폴더는 그 안의 노트들을 담는 상위 파트가 되며, 노트 안의 제목은 노트 자체의 제목보다 한 단계 아래에 놓입니다. 링크 `[[Note|text]]`는 그 텍스트가 됩니다. 임베드(앞에 `!`이 붙은 `[[file]]`), 주석 `%%...%%`, 블록 ID, 콜아웃의 표시는 제거됩니다. 하이라이트 `==text==`는 일반 텍스트가 됩니다. 숨김 폴더(`.obsidian`, `.trash`), 첨부 파일, 텍스트가 없는 노트는 건너뜁니다. 보관함에 이야기의 일부가 아닌 노트가 있다면 압축하기 전에 삭제하세요.
- **Scrivener 프로젝트.** 원고(바인더의 *Draft* 폴더, Scrivener 2와 3)를 가져오며, 자료 조사, 휴지통, *included in compile*이 아닌 문서는 가져오지 않습니다. 폴더, 또는 아래에 문서를 가진 문서는 제목이 됩니다(바인더에서의 깊이가 수준이 되고, 제목이 텍스트가 됨). 폴더가 담고 있는 것이 모두 문서인 경우, 그 문서들은 장면이 되어 장면 구분선을 사이에 두고 차례로 이어집니다(장면의 제목은 쓰지 않습니다). 원고 바로 아래나 다른 폴더만 가진 폴더 안에 있는 문서는 제목을 가진 챕터가 됩니다. 프로젝트 이름이 책의 이름이 됩니다.

출처와 관계없이, 가져오기가 끝나면(중지한 경우에도) 새 책이 열리며, [**가져오기 완료**](story-editor.md#after-an-import) 창에서 파트의 요약을 작성하거나 에이전트에게 로어 노트를 맡길 수 있습니다.

<a id="importing-from-sillytavern"></a>

### SillyTavern에서 가져오기

[SillyTavern](https://github.com/SillyTavern/SillyTavern)에서 시작한 롤플레이나 이야기를 이어 쓰려면 **가져오기 → SillyTavern에서 가져오기**를 사용하세요. SillyTavern에서 채팅을 내보내고(*Manage chat files*, 또는 `data/<user>/chats/<character>/`에서 `.jsonl` 파일을 가져오기), 다음을 진행하세요:

1. `.jsonl` 채팅을 **하나 이상** 업로드하세요. SillyTavern 채팅이 아닌 파일은 거부되고, 나머지는 그대로 남습니다.
2. 책 이름을 입력하세요(첫 번째 채팅의 캐릭터 이름으로 채워집니다).
3. 한 턴마다 하나의 파트를 원하면 **사용자와 어시스턴트 메시지를 하나의 파트로 병합**을 선택하세요. 이 경우 사용자의 메시지(연속된 여러 메시지는 빈 줄로 이어 붙입니다)가 파트의 *instructions*가 되고, 그 뒤의 답변이 파트의 본문이 됩니다. 선택하지 않으면 메시지마다 하나의 파트가 되고, 메시지 내용이 파트의 본문이 되므로 책은 채팅이 진행된 것과 같은 모습으로 읽힙니다.
4. **가져오기**를 클릭합니다. **중지**가 있는 진행 창에 저장되는 파트가 표시되며, 중지해도 이미 저장된 내용은 남습니다.

![SillyTavern 채팅 가져오기](../../images/sillytavern-import.png)

SillyTavern은 *분기(branch)*나 *체크포인트(checkpoint)*를 만들 때 채팅을 복사하므로, 한 이야기의 채팅들은 시작 부분을 공유합니다. 이들을 함께 업로드하면 Marginalia는 공통된 메시지를 찾아 한 번만 저장합니다. 채팅들은 하나의 트리의 가지가 되며, 이는 [트리 보기](story-editor.md)에서 살펴볼 수 있습니다. 메시지의 *스와이프*(대체 답변)는 형제 파트가 되며, 책은 가장 나중에 쓰인 채팅(마지막 메시지의 날짜 기준)의 끝에서 열립니다. 같은 메시지로 시작하지 않는 채팅은 별도의 첫 파트가 됩니다. 숨겨진(시스템) 메시지는 건너뛰며, 빈 스와이프도 건너뜁니다. 답변의 추론 과정과 모델 이름은 파트와 함께 유지됩니다.

<a id="importing-from-lm-studio"></a>

### LM Studio에서 가져오기

[LM Studio](https://lmstudio.ai)에서 나눈 대화를 이어 쓰려면 **가져오기 → LM Studio에서 가져오기**를 사용하세요. LM Studio는 대화마다 홈 폴더 안의 `.lmstudio/conversations` 폴더에 있는 `<number>.conversation.json` 파일로 저장합니다(Windows에서는 `%USERPROFILE%\.lmstudio\conversations`). 작동 방식은 [SillyTavern에서 가져오기](#importing-from-sillytavern)와 같습니다:

1. 대화를 **하나 이상** 업로드하세요. LM Studio 대화가 아닌 파일은 거부되고, 나머지는 그대로 남습니다.
2. 책 이름을 입력하세요(대화의 이름으로 채워지며, 대화에 이름이 없으면 파일 이름으로 채워집니다).
3. 한 턴마다 하나의 파트로 하려면 **사용자와 어시스턴트 메시지를 하나의 파트로 병합**을 선택하세요(사용자의 메시지가 파트의 *instructions*가 됩니다). 선택하지 않으면 메시지마다 별도의 파트가 됩니다.
4. **가져오기**를 클릭합니다.

![대화 하나를 업로드한 LM Studio 가져오기 창](../../images/lmstudio-import.png)

LM Studio가 보관하는 메시지의 버전(다시 생성한 답변, 편집한 텍스트)은 형제 파트가 되며, 화면에 보이던 버전에서 책이 열립니다. 시작 부분을 공유하는 대화들은 하나의 트리로 합쳐집니다. 추론 모델의 생각 과정은 모델 이름과 함께 파트의 추론으로 유지됩니다. 대화의 시스템 프롬프트, 도구 호출, 첨부 파일은 가져오지 않습니다.

백업 파일로 책을 시작하려면 *설정* 탭의 **새 책으로 백업 가져오기**를 사용하세요([책 백업](backups.md#importing-a-backup-as-a-new-book) 참고).

| **현재 분기 단어 수**, **현재 분기 토큰 수** | [활성 분기](branches-and-story-tree.md)의 파트만 셉니다. |
| **분기의 저작 정보** | **계산**을 누르면 활성 분기의 단어 중 몇 퍼센트를 직접 썼고 몇 퍼센트를 모델이 생성했는지, 그리고 단어 수가 표시됩니다. 이 값은 모든 파트의 [버전 기록](version-history.md)을 바탕으로 계산하므로, 긴 책에서는 시간이 걸립니다. 기록이 꺼진 파트는 모델이 처음 생성한 텍스트와 비교합니다. 자세한 내용은 [생성된 텍스트 강조](story-editor.md#highlighting-generated-text)를 참고하세요. |

책에서 생성하려면 모델과 프로토콜이 필요합니다. 없으면 생성이 *책에 모델이 없습니다.* 또는 *책에 프로토콜이 없습니다.* 메시지와 함께 멈춥니다.

<a id="deleting-a-book"></a>

## 책 삭제하기

책 목록에서 휴지통 버튼을 누르고 확인하세요. 책이 목록에서 사라집니다.

책에서 무언가가 작업 중이면 삭제되지 않습니다. 생성 중인 파트, 요약 일괄 처리, 번역, 재작성 또는 주석 창, 다른 창에서 열린 책이 여기에 해당합니다. 이때 Marginalia는 무엇이 방해하는지 알려 줍니다(*사용 중입니다: ...*). 작업이 끝나기를 기다리거나 중지한 뒤 다시 삭제하세요. 다른 창이나 실행이 책에서 작업 중일 때 책에 [백업](backups.md)을 복원하는 경우에도 같은 규칙이 적용됩니다.

삭제된 책은 데이터베이스에서 바로 지워지지 않습니다. 관리자가 [정리](../administration/cleanup.md) 기능으로 모든 파트와 함께 책을 완전히 제거하기 전까지는 [휴지통](../trash.md) 탭에서 책을 되살릴 수 있습니다. 그전까지 데이터는 [데이터베이스 백업](../administration/database-backups.md)에 남아 있습니다. 책 자체의 [백업](backups.md)은 파일이므로 원래 있던 자리에 그대로 남습니다.
