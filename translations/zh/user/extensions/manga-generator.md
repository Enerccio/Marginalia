# 漫画生成器

把你的故事变成漫画：模型会把故事的部分内容改编成分页、分格的脚本，然后为每个分格写出图像生成标签，可直接用于 Stable Diffusion、Forge、Midjourney 等工具。它是 SillyTavern 的 [MangaGenerator](https://github.com/Enerccio/SillyTavern-MangaGenerator) 扩展的移植版。

<a id="opening-it"></a>

## 打开它

在 [故事编辑器](../books/story-editor.md) 的设置菜单（⚙）中选择 **漫画生成器**。会打开一个大窗口；故事界面本身不会增加任何内容。你可以拖动窗口并调整其大小。

<a id="mangas"></a>

## 漫画

一本书可以有多部漫画，显示为窗口顶部的标签页。标签页旁边的按钮可以添加漫画（+）、重命名、左右移动以及删除。漫画保存在书本中，因此会包含在书本的备份和副本里。

标签页下方是当前打开的漫画的设置：

| 设置 | 作用 |
|---|---|
| 模型和协议 | 请求发送到哪里。默认为书本自身的设置；上次的选择会被记住。 |
| Token 预算 | 要求模型输出的脚本长度（提示词中的 `{{tokenBudget}}`）。 |
| 每个章节的部分数 | 新章节改编故事的多少个部分。 |
| 前文 / 后文上下文 | 在这些部分之外，新章节还会给模型提供前面和后面各多少个部分作为背景。 |
| 脚本提示词、标签提示词 | 替换本漫画使用的内置提示词。**恢复默认** 会还原内置文本。 |
| 附加规则 | 填入脚本提示词中 `{{additionalRules}}` 的位置，用于你自己的规则（不要音效、某种风格……）。 |
| 全部复制 | 把本漫画的每一份脚本，然后每一段标签文本，复制到剪贴板。 |
| 连续模式 | 让漫画自动生成，见[连续模式](#continuous-mode)。 |

<a id="settings"></a>

## 设置

*设置 → 扩展设置 → 漫画生成器设置* 保存的是**新建**漫画的初始值：Token 预算、每个章节的部分数、前文和后文上下文、脚本提示词、标签提示词和附加规则，另外还有一段会附加在每次请求之前的文本，用于适用于所有漫画的指令。留空或未修改的提示词即为内置版本。你已经创建的漫画会保留它自己的设置。该面板通过 *设置* 页面的 **保存** 按钮保存。

<a id="sections"></a>

## 章节

**添加章节** 会为上一章节之后的故事部分添加一个章节（第一个章节从第 1 部分开始）。部分的编号与大纲一样从 1 开始。每个章节显示：

- **改编自部分 / 改编至部分** —— 模型转化为分格的部分，
- **上下文自部分 / 上下文至部分** —— 模型读取的部分；位于改编范围之外的部分只作为背景（前面的事件，或之后将发生的内容），模型会被告知不要改编它们。这四个数字都可以随时修改，以选取不同的范围。

每个章节有两个视图，**脚本** 和 **标签**：

1. **生成脚本** 会把脚本逐步输出到章节中。推理模型的思考过程会显示在其上方（*思考用时 12.3 秒*）。脚本会接续前一章节的页码，并且不会重复前一章节脚本已经覆盖的内容。
2. 切换到 **标签**，然后点击 **生成标签**：为脚本中的每个分格生成角色和场景的标签。

![显示某章节脚本的漫画生成器窗口](../../images/plugin-manga.png)

两种文本都可以手动 **编辑**（铅笔图标）、**复制**，生成过程也可以用 **中止** 停止——模型已经写出的内容会被保留。章节之间彼此独立，因此你可以同时启动多个；只要有任何模型正在写入，章节就无法删除，漫画也无法修改。

![标签视图中的同一章节](../../images/plugin-manga-tags.png)

**覆盖** 可以为某个章节单独设置脚本提示词、标签提示词或附加规则，或者设置一个 **规则补充**，它会被添加到漫画的规则之后，而不是替换它们。眼睛图标会显示模型将收到的完整请求及其大小。

<a id="continuous-mode"></a>

## 连续模式

**连续模式**（位于 *添加章节* 旁边）让漫画自动生成，每次生成一种文本，因此模型会反复收到相同的提示词（支持提示词缓存的服务器可以复用它）。在按钮旁边的选择框中选择要生成的内容：

- **仅脚本** —— 按顺序遍历各章节，为每个没有脚本的章节生成脚本（已有脚本的章节保持不变）。当所有章节都有脚本后，它会为故事的后续部分添加一个章节——与 *添加章节* 的做法相同，使用漫画的 *每个章节的部分数* 和上下文设置——生成其脚本，然后继续，直到故事中没有剩余部分可供再开一个章节为止。
- **仅标签** —— 为每个有脚本但没有标签的章节生成标签。它不会添加章节；当每份脚本都有标签时结束。

两种模式都会在你按下 **停止连续模式** 时结束（该按钮会变成它；模型已写出的内容会被保留）。模型出错、某章节的部分中没有文本，或模型返回空回答，也会使其停止，并给出提示。运行期间，章节无法手动生成或修改，漫画也无法修改。运行时关闭窗口，它会折叠进[运行面板](../books/story-editor.md#the-panel-of-the-runs)并继续运行；在该面板中关闭则会停止。它处理的每个章节都会被滚动到视野中。若要两者都完成，请先运行 *仅脚本*，再运行 *仅标签*。

<a id="the-lore-and-the-size-of-the-context"></a>

## 设定和上下文的大小

模型会收到章节各部分的文本，以及文本所需的设定：书本的设定集（及其子设定集）中，其过滤词出现在该文本中的条目，查找方式与生成时相同，包括扫描深度。始终启用的条目也会包含在内。因此，这些部分中的角色和地点连同其描述都会传给模型，而图像标签需要这些描述。

所有内容都必须能放入模型的**上下文大小**——即 AI 和协议的上下文，减去留给回复的空间。当条目放不下时，靠后的条目会被省略（会有提示说明省略了多少个；眼睛图标中也会显示）——可以把章节缩小，或把设定缩短。即使去掉设定也放不下的请求仍会发送，但会附带警告。

<a id="what-is-different-from-sillytavern"></a>

## 与 SillyTavern 的区别

- 一条聊天消息就是故事的一个**部分**；消息前面没有名字，没有 persona，也没有角色卡——角色来自设定集。
- 扩展的世界信息“触发”不再需要：设定由文本本身激活。
- 上下文大小取自 AI 和协议，没有对应的设置项。
- 新章节默认取 3 个部分，每侧各带 1 个部分的上下文，因为故事的一个部分远比一条聊天消息长。可以在设置中修改（见上文）。
- 标签页通过箭头按钮移动，而不是拖动。
