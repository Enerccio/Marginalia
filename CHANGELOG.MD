# Changelog

All notable changes to Marginalia are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Lorebooks: Mass edit.** The new button **Mass edit** (second row of the lorebook toolbar) opens a table with all the entries of the lorebook and of its subbooks, however deep, ordered by the order of the entries. The enabled box, name, order and tags are edited in place, the text is shown shortened; the **Lorebook** box of a row moves the entry to the lorebook itself or to one of its subbooks, and the entries that are ticked are moved together (**Move to lorebook** / **Move checked**). A lorebook an agent works on is locked: its entries are grayed out and read only and nothing can be moved into it (checked for each lorebook of the tree). `LorebookEntryService.move` now also refuses (`LorebookLockedException`) a locked target lorebook, before only the lorebook the entry was in was checked. New: `LorebookMassEditDialog`, `LorebookService.getLorebookTree` (the lorebook and its subbooks, however deep, a class that implements the interface has to add it), `LorebookView.openMassEditDialog` (`@PublicAPI`), the style `mass-edit-content`. Localization keys (English, Japanese, Chinese).
- **Lorebooks: the tokens with the subbooks.** The link **Count with subbooks** next to the token estimate of the lorebook view adds up the tokens of the enabled entries of the lorebook and of its enabled subbooks (a disabled subbook is left out with the lorebooks under it, as the generation does; a lorebook that is a subbook twice counts once). New `LorebookView.countTokensWithSubbooks`; `LorebookView.updateLorebookTokens` clears the total. Localization keys (English, Japanese, Chinese).
- **Books: switching between the subbooks in the Lorebook tab.** The Lorebook tab of the book window (desktop and phone) has a second box, **Shown lorebook**, with the lorebook of the book and all its subbooks, however deep: it shows any of them in the tab without binding it to the book (before, the only way to look at a subbook was to change the lorebook of the book). On the desktop a click on the name of a sub lorebook in the tab opens it too. The shown lorebook is remembered with the workspace (`shown` in the state of the tab). New: `LorebookView.setOnOpenSubbook`, `ManuscriptLorebookPart.refreshShown` / `showLorebook` (and the same in `PhoneManuscriptLorebookPart`); `autosave`, `load`, `storeState`, `restoreState` and `onTabEnter` of both parts have new locals. Localization key `LABEL_SHOWN_LOREBOOK` (English, Japanese, Chinese).
- **Lorebooks: show only root lorebooks, and open a sub-lorebook with a click.** A box **Only root lorebooks** next to the lorebook list hides the lorebooks that are a sub-lorebook of another one (the selected lorebook stays in the list). The box is remembered with the rest of the workspace (`UserSetting.workspaceState`, key `rootOnly` of the `LorebookView` state). A click on the name of a sub-lorebook in the **Sub-lorebooks** box opens that lorebook in the view. New: `JavascriptLibrary.fireChipClickEvent`, the style `clickable-chips`, `LorebookView.openSubbook`; `LorebookView.loadLorebooks` has a new local `subIds`. Localization key `LABEL_ONLY_ROOT_LOREBOOKS` (English, Japanese, Chinese).
- **Agents: the requests to the model are measured, and the Diagnostics show it.** Every answer of an agent (and of its sub-agents, and the summary of a compaction) is stored with what the runner knew about its request (`AgentMessage.telemetry`, an extended attribute, JSON, no migration): the time to the first word and the time of writing, why the answer ended (`stop`, `tool_calls`, `length`...), the tokens the server read from its cache and the tokens of reasoning (the usage of OpenAI-compatible servers, and the `timings` of llama.cpp), the calls of the answer against the ones that were made, and the wait for a place. The Diagnostics tab has a section **What the requests reported** with the totals, the tokens per second, the cache and the reasoning share, the reasons the answers ended and the same for each block of 25 rounds; runs made before this have none of it. `InferenceService.RoundUsage` has a third component, `RoundStats` (the two-argument constructor stays).
- **Agents: how many calls of one answer are made, and a batch policy of the commands.** The agent dialog has a box **Calls in one answer** (`Agent.batchMode`, an extended attribute): *All together, ignore the batch policies*, *Together, commands marked Alone by themselves* (the default) and *One call per answer* (only the first call is made and the agent writes the next after it has read the result). A command can declare how it is used among the calls of an answer, `@Command(batch = BatchPolicy.BATCHABLE | SINGLE)` (new `BatchPolicy`, `CommandDefinition.batch`; the runner takes a command as alone when any of its overloads is): a command that is alone is called in an answer of its own, the calls from it on are not made and the agent is told. The commands that make a call to a model (`next`, `swipe`, `regenerate`, `regenerate-summary`, `create-meta-summary`, `compact` and the tool `request_compaction` (a built-in tool declares it with the new `@LLMFunction(batch = ...)`), and the generating commands of the Lore Generator and Arc Outline plugins) are alone. The table of commands in the dialog has a **Batch** column, all its columns can be resized, and the dialog is wider. The agent is told the rule up front in its system message (one call per answer; or which commands are made alone), and the notice after the fact names the call that was made and says the others were not. The Diagnostics count the notices. Localization keys (English, Japanese, Chinese).
- **Tag many books, lorebooks or entries at once.** **Tag books** (next to **Add Book** in the Books tab) and the two tags buttons of the lorebook toolbar (**Tag lorebooks**, **Tag entries** for the selected lorebook) open a window to put one tag on many items, or take it off: pick the tag (or type a new one), see every item with its tags (the ones that have the picked tag first, the tag highlighted), apply or remove it per row, or for all the ticked rows with the buttons at the bottom. Items an agent works on are grayed out and can not be changed. New: `MultiTagDialog`, `TagRelationService.getTagsForObjects` (the tags of many objects in one query; a class that implements the interface has to add it), `TagRelationRepository.findTagsForObjects`; new styles `multi-tag-locked`, `multi-tag-chip`, `multi-tag-chip-marked`; new methods `ManuscriptPart.openTagDialog` and `LorebookView.openTagDialog` (`@PublicAPI`).
- **Agents: the Diagnostics tab of the console.** An eighth tab counts what the run did from its transcript, for tuning the tools and the prompt of an agent from a real run, also an old one (pick it in **Runs**): the calls by tool with their errors, cut results, characters and time, the rounds spent calling one tool after the other (marked when a search came before) and the calls made again, the calls that passed a text as `@file:` or wrote a long text out (and whether that text was one the agent had just been given in a result), what the model wrote (arguments, text beside the calls, reasoning) in blocks of 25 rounds, the longest arguments, the error messages (with the arguments of the first call that got each), the biggest results, the slowest rounds, the context at its peak and the compactions, your messages and the notices the runner gave the agent, and the sub-agents. **Download** (Markdown), **Download JSON** and **Copy**. New: `AgentRunner.diagnostics(run)` returning an `AgentDiagnostics.Report` (`domain.service.agent`), `AgentDiagnosticsView`.
- **Agents: the Context tab of the console.** A fifth tab shows what the model reads with its next request, taken apart: charts of the kinds of parts against the limit of the context (prompt, instructions, notes of the runner, tool definitions, summary, messages, answers, results), of every part in the order it is sent, and of the context the model reported at each answer; a table of the parts with their estimated tokens, the exact text of the picked one, and **Download** / **Copy** of the whole context as one Markdown document (system message, every tool with description and schema, the conversation). It is made when the tab is picked and by **Refresh**. New: `AgentRunner.context(run)` returning an `AgentContext` (`domain.service.agent`), `AgentContextView`; the system message is now made from `systemParts()`, the same list the request uses.
- **Agents: the review shows the changes word by word and takes them field by field.** Under the texts of a change, **Differences** shows what is only in the book now (struck through in red) and what is only in the text to apply (green), word by word, following what you write in the box; for a conflict it also shows what the agent and what you changed since the run started. A line the agent changed in more than one thing has a **Take this change** box per field: untick one and the line is applied without it. The place of a part goes with the part, and what the agent made or deleted is taken or left as a whole. New: `utils.WordDiff` (the word diff, Myers), `WordDiffView`, `MergeSelection.skippedFields` (the old three argument constructor stays).
- **Agents: sizes in the agent dialog and per answer in the Context tab.** The table of allowed commands has a **Tokens** column (what the definition of each command adds to every request) and a line under the instructions adds up the prompt, the instructions and the ticked commands. The third chart of the **Context** tab is now a stacked bar of what the context was made of at each answer (prompt, tools, summary, your messages, answers, results; estimated) with the size the model reported and the limit as lines; the Markdown download has the same as a table.
- **Agents: the Sub-agents tab.** A seventh tab of the console shows the conversation of each sub-agent of the run (what the agent told it, what it said, its commands with their results, how it ended), also while it works and for older runs picked in the **Runs** tab. A `spawn_agent` call in the transcript has a **Sub-agent** button that opens it. New: `AgentSubAgentsView`, `AgentTranscriptRenderer` (the rendering of the transcript, moved out of the console).
- **Agents: the Book copy tab and Show in the copy.** A sixth tab of the console shows the working copy of the book to read: one branch of the story at a time part by part, and the lorebooks with their entries, also while the agent works. It is not a window of the book, so nothing can be changed, no backup of the copy is made and no extension sees a book open. In the review, a line the agent made or changed has **Show in the copy**, which opens the copy at that part or entry. New: `AgentCopyService`, `AgentCopyView`; `StoryTree` of the read commands is public.
- **`/insert-part <text> <part> [before]`: insert a part into the story without deleting and recreating the parts below.** The new part goes right after `part` (right before it with `before` true); everything that followed the place, all branches, follows the new part, so the other parts keep their uuids, summaries and data and move one position down. The answer names the summaries that became outdated. For the command bar and for agents (non-destructive; in the *Editor* and *Drafter* roles). In the review of an agent's result an inserted part is an added part and the parts it took over are changed parts with the new field **Follows**, so taking the insertion over does not recreate them. New: `ChatMessageService.insertPart`, `ChatMessageRepository.reparentChildrenExcept` / `reparentRootsUnder`, `MergeDiff.PARENT`. A part is no longer always older than its child, so deleting a book for good now goes from the deepest part up instead of by id.
- **Agents: zip files in the workspace and the tool `unzip_file`.** The **Upload file** of the workspace tab of the console takes zip files (recognised by what they contain, up to 10 MB, `WorkspaceLimits.maxArchiveBytes`, kept as they are), and the agent has the new function `unzip_file(path, target)` (`AgentFileTools`) that unpacks one into a new folder (by default the path without `.zip`), all or nothing, through a temporary folder moved into place, within the limits of the workspace. The archive is not trusted (`ZipExtractor`, `java.util.zip`): an entry that leads above the folder or is absolute refuses the whole archive; every name goes through the rules of `VirtualPath` and the path is built from checked names only; nothing but files and folders is made (a link is an ordinary entry); only text, images and zip files are kept and the rest is left out and reported; the same name twice, names that differ only in case and a file that is a folder are refused; zip bombs are stopped by the number of entries (5 000), the bytes inflated (not more than the workspace holds, the declared size of an entry is not trusted) and the ratio of inflated to packed bytes (100) of an entry and of the archive; encrypted and damaged archives are errors. Plugin visible: `WorkspaceLimits` has the new component `maxArchiveBytes` (the old constructors stay) and `maxAnyFileBytes()`, `VirtualFileSystem` has `writeArchive` and `unzip`, `VirtualMount` has `writeArchive` and `unzip` (default: refuse); `read_file` on a zip file says to use `unzip_file`. The text of the message about an upload that is not text names zip files too (all bundles).
- **Agents: sub-agents.** An agent can hand a job to a sub-agent: a thread of the run with a conversation of its own, the same commands and files, the same working copy and workspace, that answers with a text. The new field **Most sub-agents** of the agent (`Agent.maxSubagents`, an extended attribute, 0 to 10, empty or zero is none and the agent gets no tools for them) is how many may work at once. The agent gets `spawn_agent(task, context?)`; with a limit of one the call waits until the sub-agent is done and returns its answer, with more it returns a handle at once, until the call that reaches the limit, which waits for one to end; then `await_agent`, `agent_status` and `cancel_agent` are offered too. A sub-agent can not start sub-agents, finish the run, ask the user or make checkpoints. Everything counts in the one budget of the run (rounds, tokens, limits); calls that change the book or the workspace, and the small writes of the run, are done one at a time. A pause of the run pauses the sub-agents (see the next entries), a discarding stop and the end of the agent's turn (once after a notice) end them. A sub-agent's conversation is not shown in the console, the download of the run has it. New `SubAgents`, `SubAgentTools`, `SubAgentControlTools` (`domain.service.agent`), `AgentRunService.getMaxSubagents`.
- **Agents: a paused run pauses its sub-agents, and a resume goes on with them (migration V18).** Before, a pause cut the sub-agents off and the call of the agent that waited for one was answered "was stopped". Now the conversation of every sub-agent is stored with the transcript of the run (new column `agent_messages.thread`, the handle of the sub-agent, null for the agent's own rows, and the extended attributes `threadTask`, `threadCall`, `threadEnd` of `AgentMessage`; the ordinal counts per thread and every query of the agent's transcript reads `thread IS NULL`, so nothing else changes). A pause (or a stop that keeps the run) stops the sub-agents at their next stable point as paused; a **Resume** continues their conversations and makes the call of the agent that waited for one (`await_agent`, or `spawn_agent` with a limit of one) again, which waits for the same sub-agent: nothing is started twice. A sub-agent that was over before the pause stays there for `await_agent` / `agent_status`. A restore of a checkpoint ends the sub-agents that waited (their book is gone), a rewind over the call that started one takes it with it. **Plugin visible:** `AgentMessageService` has `startThread`, `appendToThread`, `appendAnswerToThread`, `endThread`, `endOpenThreads`, `threads` and the record `SubThread` (a class that implements the interface has to add them); `SubAgents.create(task, callId)`, `restore`, `suspend`, the state `SUSPENDED`; `SubAgentToolsImpl` has two more constructor arguments. Migration `V18__agent_message_threads.sql`.
- **Agents: a call that was cut off in the middle no longer breaks every request after it.** The history of a run is sent back to the model at every request; a call whose answer ended in the middle of a text has arguments that are not valid JSON, and a server that parses the calls of the history (LiteLLM with llama.cpp) refused the whole request because of it, again and again, so the run was unusable until it was rewound. Such a call is now sent back with `{}` as its arguments (the transcript, the console and the download still show what the model wrote), and the error it gets says that the answer was cut off. A run that is stuck this way works again on a resume.
- **Agents: a call the model server can not read no longer leaves the run stuck.** When the answer of the model ended in the middle of a long text in a call (the limit of one answer, not the context), the server refused it ("Failed to parse tool call arguments as JSON") and the run paused; a resume sent the same conversation and failed the same way, so the run was unusable until the user rewound it. The agent (or the sub-agent) is now told in the transcript that its last answer could not be used and to write long text to a file in smaller steps (`Defaults.AGENT_UNREADABLE_CALL`), and asked again, up to three times in a row; if it still fails the run pauses with the notices in the transcript. No migration.
- **Agents: the console no longer loses what you selected while it refreshes.** The state line, the workspace list and the checkpoint list were rewritten at every poll, which dropped a selection made to copy from them; they are only touched when something changed (`UIUtils.setTextIfChanged`).
- **Agents: the console and the download show when each message was written.** Every message of the transcript in the **Run** tab has its time at the right of the first line (the time of day, with the date when it was another day, the whole time as the tooltip), and the Markdown download of a run has it in every heading and a section for each sub-agent (task, state, every message and call). New style `agent-time` (`CssStyles.AGENT_TIME`), `AgentTranscriptExport.export`.
- **Agents: a cap of requests to the model per run (the permission setting "Requests to the model at once").** The permission `AGENTS` has a new setting, **Requests to the model at once (per run)** (`Permission.agentsMaxConcurrency`, `AgentGrant.maxConcurrency`, an extended attribute; one when empty, unlimited for an administrator): how many requests one run can have in the air, the agent and its sub-agents together. With one, the agent waits while its sub-agent asks the model and the other way round; the cap of the AI (`AIGate`) applies besides. `AgentGrant` has the new component (the constructors with fewer arguments keep working and mean one), `AgentRunService.getMaxConcurrency`. No migration.
- **Agents: roles for the allowed commands.** The **Selection** box of the agent has four roles besides *All*, *None* and *All non-destructive*: **Auditor** (only reads), **Lore keeper** (also writes lorebooks), **Editor** (also revises parts, summaries and the book information) and **Drafter** (also adds parts and lets the model write the next turn). Each reads with every command that declares `readOnly` (the commands of extensions too) and writes with the named commands of its job; none has a command that removes data. `AgentCommandPreset` has `AUDITOR`, `LORE_KEEPER`, `EDITOR`, `DRAFTER` and `includes(row)`. New keys `ENUM_COMMAND_PRESET_*`, `HELP_COMMAND_PRESETS`.
- **Agents: a limit of concurrent requests per model (`AIGate`).** A model (the provider dialog, **Concurrent requests of agents**, `AI.maxConcurrentRequests`, an extended attribute) can be given how many requests of agents may be on the way to it at once; the others wait their turn in the order they came, their runs stay *Running*, and a pause or a stop ends the wait. For a server with one slot. It covers the rounds and compactions of the runner and the commands that start a model for an agent (`/next`, `/swipe`, `/regenerate`, the summaries; `ManuscriptWriteSupport.placeAt`); the user's own generation in the story window is not queued. New service `AIGate`. New keys `LABEL_MAX_CONCURRENT_REQUESTS`, `HELP_AI_MAX_CONCURRENT_REQUESTS`, `MSG_COMMAND_WAITING_FOR_MODEL`. No migration.
- **Agents: Pause now.** A button for a working run (Agents tab and console) that cancels the request to the model and the call that are going on and pauses at once; the answer is thrown away and the call in the air is answered as cut off (`Defaults.AGENT_PAUSED_CALL`, `AGENT_PAUSED_SKIPPED_CALL`) so the agent checks the state when it goes on. The ordinary pause and stop also end a wait for a place at a model. **Plugin visible:** `AgentRunner` has the new method `pauseNow(run)` (a class that implements it has to add it). New keys `LABEL_PAUSE_NOW`, `HELP_AGENT_PAUSE_NOW`.
- **Agents: the runner compacts a run by itself when the context fills up.** When the context passes a share of its cap (the new field **Compact at (% of context)** of the agent, 90 when empty, zero never, otherwise 50 to 99; `Agent.autoCompactPercent`, an extended attribute) and the agent did not call `request_compaction` after the warnings, the runner has it write the summary of its earlier work, the same compaction as `/compact`; the summary says "compacted automatically" (`Defaults.AGENT_AUTO_COMPACTED_NOTE`). A failure is reported to the agent and tried again only some rounds later. An agent that wants the old behaviour (warnings, then a pause at the cap) sets zero. New keys `LABEL_AGENT_AUTO_COMPACT`, `HELP_AGENT_AUTO_COMPACT`.
- **Agents: the model of the book is the agent's to choose.** The new setting **Write the book with the model of the agent** of the agent (`Agent.useAgentModel`, on by default; an extended attribute, copied by clone) decides what the run writes with. On: the working copy gets the AI and the protocol of the agent's main model (every time a worker starts, so an edited profile applies on resume) and the commands that start a model use it, whatever the book has; off: the model of the book, so models can be mixed (one thinks, another writes). The AI and the protocol are not compared when a run is merged back, so applying a result leaves the model of the book as it was. **Fixed:** the commands of the Lore Generator used the default model of the user in a run, whatever the agent or the book had; they (and the Arc Outline commands) now take the model from the scope of the command. **Plugin visible:** `CommandScope` has the new default method `getModel()` returning the record `CommandScope.ModelChoice(ai, protocol)` (null: no opinion, the command uses its own choice) - an extension command that calls a model should ask it first; new `AgentRunService.useAgentModel(run)`, `ManuscriptService.setAgenticCopyModel(copy, ai, protocol)`, `Agent.isUsingAgentModel()`. Rebuild the plugins `lore-generator` and `arc-outline` with the app. New keys `LABEL_AGENT_USE_OWN_MODEL`, `HELP_AGENT_USE_OWN_MODEL`.
- **Agents: default instructions in the user's settings.** The instructions ("agents.md") of an agent follow the same chain as the prompts: its own, when blank the new setting **Instructions of agents (agents.md)** of its user (`UserSetting.defaultAgentInstructions`, an extended attribute, in the Templates tab for users who may use agents), else none. The placeholder of the field in the agent dialog shows it; the prompt of the run and the `/AGENTS.md` file use it. New `AgentService.getInstructions(agent)` and `getDefaultInstructions()` (a class that implements `AgentService` has to add them). New keys `LABEL_AGENT_DEFAULT_INSTRUCTIONS`, `HELP_AGENT_DEFAULT_INSTRUCTIONS_USER`; the text of `HELP_AGENT_INSTRUCTIONS` says it.
- **Agents in the phone layout.** The phone workspace has the **Agents** tab (with the count of the agents that need the user) for users who may use agents: each agent is a card with its name, state and the buttons of the table; the console, the review, the agent dialog and the other agent windows fill the screen, their footers wrap, and the review puts the table above the detail. New `UIUtils.isPhone()`, `UIUtils.fitPhone(dialog, fullHeight)` and `UIUtils.PHONE_MAX_WIDTH_PX`, `new AgentPart(workspace, phone)`. **Plugin visible:** `PhoneWorkspace` has the new private method `addAgentsTab` and (when the user may use agents) a new section `agents`.
- **Agents: a message to a URL when the user is away (webhook).** For a user who may use agents, **Settings > General** has **Message to a URL when an agent needs you** (an ntfy topic, a Gotify message URL or a Discord webhook; the **Format** of the body; **Also when the application is open**; **Send a test message**). When an agent asks, waits, finishes, fails or pauses with a reason and the user has no screen open (or asked for it always), the server sends a short message in the user's language to that address on a thread of its own. Only `http` and `https` are called, redirects are not followed, the URL (which can hold a secret) is never logged. An administrator can turn it off for everybody (Admin > Agents, **Agents may send messages to the webhooks of users**). New services `AgentWebhookService` and the enum `WebhookFormat`; extended attributes `UserSetting.agentWebhookUrl`, `agentWebhookFormat`, `agentWebhookAlways` and `AppSettings.agentWebhooksDisabled`; `AgentAttentionServiceImpl.publish` calls the service. **Plugin visible:** `Localization` has the new method `getValue(Language, L)` (a class that implements it has to add it). New keys `ENUM_WEBHOOK_FORMAT_*`, `LABEL_AGENT_WEBHOOK_*`, `LABEL_AGENT_WEBHOOKS_ALLOWED`, `HELP_AGENT_WEBHOOK_URL`, `HELP_AGENT_WEBHOOKS_ALLOWED`, `MSG_AGENT_WEBHOOK_TEST_*`. No migration.
- **Agents: go back to a message.** Every message you wrote to an agent has a **Rewind** button in the transcript of the console: the agent forgets that message and everything after it (they stay greyed in the transcript), and the working copy and the workspace go back to the newest checkpoint made before it, so you do not have to pick a checkpoint. The confirmation names the checkpoint and the number of messages that go; a run that waits for you is paused for it, and you resume it afterwards. New `CheckpointService.planRewindToMessage` / `rewindToMessage` and the record `CheckpointService.RewindPlan` (a class that implements `CheckpointService` has to add them). New keys `MSG_AGENT_CONFIRM_ROLLBACK_MESSAGE`, `HELP_AGENT_ROLLBACK_MESSAGE`.
- **Agents: rewind a run to a checkpoint.** The **Checkpoints** tab of the console has a **Rewind** button for a paused or stopped run: like a restore it brings back the working copy and the workspace, and it also takes the conversation back to where the checkpoint was made. What came after is greyed in the transcript (still there to read) and the agent no longer reads it, so it does not remember work that is no longer in the book; it gets a notice and goes on when you resume. A checkpoint stores its place in the conversation (`meta.json`); older ones can only be restored. New `CheckpointService.rewind` / `rewindable`, `AgentMessageService.rewind` / `lastRow`.
- **Agents: the working copy catches up with the book on resume.** A paused or kept run does not lock your book, so you can edit it meanwhile. When the run is resumed, what you changed (parts, summaries, lorebook entries and lorebooks, settings, tags, extension data, parts and entries you added or deleted) comes into its working copy, except what the agent changed too: that stays as the agent has it and shows as a conflict in the review, so nothing the agent did is lost. The agent is told what came in and what did not, by handles, and has a new tool `get_sync_report` to ask again (offered only when something was reported). The state of the copy before is saved as an automatic checkpoint. New `AgentMergeService.sync`; a resume with nothing changed costs 0.1 s.
- **Agents: review and apply the result.** A run that is *Done* (or was stopped with *Stop and keep the result*) keeps its working copy until the result is applied or discarded, and the Agents tab and the console have a **Review changes** button. The window lists everything the agent changed (settings, tags and extension data of the book, parts, summaries, lorebooks and their entries) compared with the book **as it is now** and with the book as the run started, so what you changed meanwhile stays and a text both of you changed is a conflict. You tick the changes to take over (all, none, only the new parts, without conflicts), see the book's text beside the text that will be written, edit that text, and apply: the book is changed in place (parts keep their addresses, lorebooks keep their links, what was deleted goes to the trash) after a backup, all together or not at all. Lorebooks used by other books are marked shared. The run is then *Applied* and the copy and checkpoints are deleted; **Discard the result** drops the copy instead. New service `AgentMergeService`, `ChatMessageService.storeResponse`; a `DONE` run now counts toward the copies of the user until applied or discarded.
- **Agents: checkpoints.** A run keeps restore points of its working copy and its workspace (a ZIP in the folder of the run): one **at the start** (never rolled out), an **automatic** one before each round that may change something (when something changed since the last one; the last five are kept) and the ones made **on purpose**. The agent has new tools `checkpoint(label?)`, `checkpoint_list`, `checkpoint_restore(id)` (done when the round ends; the agent is told what came back) and `checkpoint_delete(id)`; the console has a **Checkpoints** tab (save, restore, download, delete, the usage). A restore makes a new working copy from the checkpoint and keeps the original pairs and the handles of the items that were there, and replaces the workspace. All the checkpoints of a run share a quota, the new permission setting **Checkpoints of a run (MB)** (an extended attribute of `Permission`, `AgentGrant.maxCheckpointBytes`, 100 MB when empty); a checkpoint made on purpose that does not fit is refused with the list and nothing is deleted behind the back of whoever made it, the automatic ones use a reserve. New services `CheckpointService`, `AgentRunService.replaceWorkingCopy`, `ManuscriptService.createAgenticCopyFromSnapshot` / `snapshotAgenticCopy`; `UuidPair` has a `handle`. The checkpoints are deleted with the working copy.
- **`@Command(readOnly = true)`.** A command can declare that it changes nothing (the default is `false`: it is taken to change data); `CommandDefinition` has a new `readOnly` component. The runner uses it to know which rounds of an agent need a checkpoint. Declared by the read commands of the app and the `get-` / `list-` commands of the Arc Outline and the Character Tracker plugins (rebuild them with the app).

- **An agent can pass a file as the text of an argument.** A text argument of a command that is exactly `@file:/path` is replaced, before the command runs, by the contents of that file of the agent's workspace (`CommandFunctions`, a new optional file reader of `forAgent` / `create`), so a long text is written once, checked and passed without the model writing it again in the call; the stored call keeps the short reference. The description of every text parameter and the note of the runner say so. A file that can't be read is an error naming the argument. In the `ASK` mode the approval window shows the text that will run. The `content` of the file tools `write_file` and `append_file` takes the same reference, so a file can be copied or added to another (`/book.md` built from `/parts/one.md`, `/parts/two.md`...) without the text passing through the model; the content is read before the target is changed.
- **More file tools for agents.** `list_files` and `grep_files` take a name pattern (`glob`: `*.md`, `chapters/*.md`, `**/draft-*`, `{md,txt}`; the case does not matter), `copy_file` copies a file or a folder with everything in it to a free name (all or nothing, within the limits of the workspace), and `merge_files` joins several files into one, in the order given, with a delimiter, without the text passing through the model (the last name of a path may be a pattern such as `/chapters/*.md`, the target left out so the merge can be repeated).
- **The agent is told how much it can read and write.** The system message of a run ends with the limits of its model (the context, and the longest answer: the lower of the protocol's reply tokens and the AI's max completion tokens), with the advice to write long texts in parts (`write_file`, then `append_file`), and `get_run_status` reports the longest answer too. Before, a model with a reply limit of 8000 tokens tried to write a file of 100 000 tokens in one call, which was cut off.
- **Agents: the console.** New button **Console** in the Agents tab opens `AgentConsoleDialog` for the latest run of the agent: the transcript (what the user and the agent said, each call folded with its arguments and result), the state, rounds and tokens of the run (with the token budget), the question of an `IDLE` run or the report of a `DONE` one, a box that sends the answer through `AgentRunner.send`, **Pause**, **Resume** and **Stop**, and a second tab, `AgentWorkspaceBrowser`, with the workspace of the agent: browse the folders, read a text file, download or delete a file, clear the workspace (not while the agent works). The console reads the run again every two seconds while it is open. 9 new `LABEL_*` and 7 new `MSG_AGENT_*` localization keys in the English, Japanese and Chinese bundles; the transcript uses the styles of the help assistant.
- **Agents: virtual file system and file tools.** New `AgentVirtualFileSystemService` (`open(run)`, `openWorkspace(agent)`, `getFileTools`, `getUsage`, `clearWorkspace`, `copyWorkspace`, `deleteWorkspace`, `deleteRunFolder`) and the package `domain.service.agent`: `VirtualPath` (absolute, NFC, `..` stops at the root, no empty or `.` parts, no control characters, drive letters, UNC or Windows device names, limits of length and depth), `VirtualFileSystem` over `VirtualMount`s (the workspace of the agent is the root, `/checkpoints` a read only list; symbolic links are never followed, names that differ only in case are one name, writes are atomic and under size, file size and file count limits `WorkspaceLimits`) and `RunFolder` (the layout `agent-runs/<run uuid>` and `agent-workspaces/<agent uuid>` in the application folder). The workspace belongs to the agent and stays between its runs; cloning an agent copies it, deleting the agent for good or purging it in the cleanup deletes it, and so for the folder of a run. New functions for the model, `AgentFileTools`: `list_files`, `read_file` (line ranges), `write_file`, `append_file`, `replace_in_file` (the text must be there exactly once), `regex_replace_in_file`, `grep_files`, `move_file` (the target must not exist), `delete_file`; results are bounded, errors name virtual paths only, regular expressions are stopped after three seconds. Plugin visible: `TextSearch.apply` and `TextSearch.matches` have an overload taking the view of the text the regular expression reads.

### Changed

- **Agents: an error ends the answer.** When a call of an answer fails, the calls after it are no longer made: each gets the result "not made because an earlier call of the same answer failed" and the agent reads the error first (`Defaults.AGENT_AFTER_ERROR_SKIPPED_CALL`; for the agent and its sub-agents). Before, the rest of the batch ran, and a batch of `create-part` calls that chained one to the next with `@result` failed all the way down after the first error.
- **Agents: `read_file` reminds the model that a file can be passed as a reference.** When a result is the whole of a file of 500 characters or more, one line follows it: pass `@file:/path` as the argument of a command or of `write_file` instead of writing the text out. A model that copies a text it has just read costs the time of every token of its output; the line is a few input tokens, comes at the moment of the copy and adds nothing to the definitions of the tools. A part of a file, a short file and a cut file get no line.
- **Agents: a round is streamed, so the timeout of the model is a wait for the next chunk.** `InferenceService.round` asked the provider for the whole answer in one response, so a reasoning model that thought for minutes before it wrote anything sent nothing and hit **Timeout (seconds)** (300 by default) even though it worked. The round is now streamed and put together (text, reasoning, calls, token counts and cancel as before), and the timeout applies to the gap between two chunks, the reasoning included.
- **Agents: a run that works uses the settings of its model as they are now.** The worker read the model (timeout, URL, key, protocol) once when it started, so a change in the provider dialog reached only a run that was resumed. It reads them again before each request.

- **Agents: the lore commands explain how to place an entry.** The descriptions the model reads for `create-lore-entry` and `update-lore-entry`, and for their `order` and `insertionMode` parameters, now say what the two do: `order` ranks the entry among the used entries of all the lorebooks (lower first, 100 when omitted, `list-lore-entries` shows the others) and `BEFORE_USER_PROMPT` puts the text right before the request instead of in the lore block. Text only, no signature changed (English, Japanese, Chinese plugin).
- **Agents: a queued message or command can be taken back.** The dashed bubble of a message (or command) that waits for the agent has a **trash** button next to **Send now**: the agent will not get it. New `AgentRunner.cancelQueued(run, id)` (a class that implements `AgentRunner` has to add it), key `HELP_AGENT_CANCEL_QUEUED` (English, Japanese, Chinese plugin).
- **Agents: a message to a conversation that works is read by the next request.** It used to wait for the end of the turn (a reply in text, `finish` or `ask_user`), which in a long run with many tool calls could be much later. Now the worker takes the queued messages at the top of every iteration of the loop, so the next request to the model contains them; commands still wait for the end of the turn, and **Send now** still drops the round in the air. Internal: `Inbox.takeMessages`, `Worker.deliverQueuedMessages`.

- **Agents: smaller tool definitions.** The note that a text argument can be given as `@file:/path` or `@result` is no longer repeated in the description of every text parameter of every command (it was more than a quarter of the tokens of all the tools: 89k characters became 62k with every command allowed). The note of the runner in the system prompt says it once.
- **Schema validation per table.** `persistence.xml` sets `hibernate.hbm2ddl.jdbc_metadata_extraction_strategy` to `individually`: the SQLite driver answers the columns of all tables with one compound SELECT, which SQLite refuses above 500 columns in total (the schema was at 490 before `V16`, the application did not start with more).
- **`SessionPoint` and `CommandUtils` (plugin API from 1.4.0).** `SessionPoint` got `getManuscriptSection()`, `getManuscriptWindow()`, `getCurrentManuscript()` and `getCurrentAI()` (the lookup in the workspace moved there from `CommandUtils`, whose methods now delegate to them). `CommandUtils.getSessionPoint()` also answers for request attributes that are not a servlet request when they hold an `AgenticSessionPoint`.

- **Generation controller (plugin API from 1.4.0).** `GenerationController` and `GenerationControllerEvent` have `getAi()` and `getProtocol()`, the model the generation really uses; read it there instead of `event.getManuscript().getAi()` / `getProtocol()`, which is the book's and may differ (the pipeline no longer reloads them into the book object). `GenerationController.getRequestAttributes()` returns `RequestAttributes` (was `ThreadCopyRequestAttributes`) and `ThreadCopyRequestAttributes.InRequestScope` takes any `RequestAttributes`. The `authorsnote` plugin counts its note with the model of the generation (`AuthorsNoteService.countTokens(AI, data)`).
- The command bar empties its field when a command starts.
- **Focus in dialogs.** Dialogs put the cursor into the field they are about when they open (name of an AI, a model protocol, a user, a new manuscript from a backup, a profile or a tab; the file name of an export; the search text of search and replace; the text of the input and selection dialogs; and the same in the arc-outline, character-tracker, lore-generator, reviewer and sidequery plugins). The new-turn popover of the story tab (desktop and phone) puts it into the instructions. New `DialogFocus.onOpen(dialog, field)` helper (`ui.widgets`) and `NewTurnForm.focusInstructions()` (plugin API from 1.4.0).
- **Two application switches became permissions.** `AppSettings.userAisAllowed` (users can create their own AIs) is now the permission `CREATE_AI` and `AppSettings.helpEnabled` (the help assistant) the permission `HELPER`, per user; administrators always have both. App migration 4 → 5 (`PermissionsMigration`) gives a permission to every existing user when its switch was on, new users have none. Removed: the checkbox *Users can create their own models* of the Users tab, the checkbox *Enabled* of the Help assistant tab, `AIService.isUserCreationAllowed` / `setUserCreationAllowed`, the component `userAisCheckbox` of `AdminPart.createUsersTab` (plugin API), the first component `enabled` of `HelpAssistantService.Settings` and its constructors. `HelpAssistantService.isAvailable` is per user now. The fields of `AppSettings` stay (deprecated), only for the migration.
- **Help assistant: per user settings.** *Apply limits* and *Allow navigating the interface* moved from the Help assistant tab to the `HELPER` permission of each user (extended attributes `Permission.helperApplyLimits` and `helperInteractions`), the migration copies the old application settings into the new `HELPER` permissions. `HelpAssistantService.Settings` is now `(aiUuid, adminPrompt, userPrompt, adminData)`. An administrator without the permission is answered with both off.
- **Agent console, Workspace tab.** Smaller text, compact rows, less space between the parts and no padding around the tab (the Run and Runs tabs got a small padding of their own), so a folder shows many files instead of one or two; the file list and the viewer have a fixed height (the viewer scrolls) and the viewer shows the first 2,000 characters of a file with a note of how long it is (it was 100,000), the download has the rest (new `workspace-browser` style; the text of `MSG_AGENT_FILE_CUT` takes the two numbers).

### Fixed

- **Google Gen AI: agents work with it.** The plugin did not implement `InferenceService.round`, the one request an agent runner makes, so a run with a Google model failed with "does not support single rounds". It does now (not streamed; the calls the model asks for are handed back, the usage has the cached and the thinking tokens). Not checked against the live API with a long run: a model that wants its thought signatures back with the calls of earlier answers (Gemini 3) may refuse a history that the runner rebuilds from its transcript.
- **Agents: taking over a run that made a whole lorebook tree failed with a NullPointerException.** A lorebook made while a run is taken over (or by `LorebookService.createSubbook`) had no list of subbooks until the transaction was flushed, so linking the subbooks under a root that the run made (a book that had no lorebook, the agent made the root and sub lorebooks) failed in `LorebookService.getSubbooks`, and nothing was applied. The lorebooks are made with an empty list, and `getSubbooks` copes with none.
- **Agents: `@result` can be given where a handle is expected.** The result of `create-part` and of the other commands that make something is a JSON object with the `handle`; passed whole as `@result` for the `parent` of the next `create-part` it was refused ("Give the handle…"), which was 18 of the 56 failed calls of a long import. A handle parameter now takes the `handle` out of such a result (`ManuscriptReadSupport.ref`).
- **Agents: a book without a lorebook can get its lore.** `create-lore-entry` and `create-lorebook` answered "The open book has no lorebook." and nothing else could make the root, so an agent given such a book could not write any lore. Now the two commands make the root lorebook first (named like the book), and taking the result of the run over gives the book that lorebook (before, the lorebook and its entries would have been left in no book).
- **The toolbar of the lorebook editor is cut off at the right edge.** With the search and replace and the tag buttons the single row of buttons ran over the edge of a 1920 pixel screen and hid **Refresh**. The toolbar is now two rows that wrap in a narrow window: the lorebook buttons (select, add, delete, import, export, **Tag lorebooks**) and, below, the buttons of the entries (**Add Entry**, **Search and replace**, **Tag entries**, **Refresh**).
- **A lorebook that an agent works on no longer hides Add Lorebook and Import.** With a read only (locked) lorebook selected in the Lorebooks tab the toolbar offered neither, so with every lorebook locked there was no way to create or import one. They stay (they have nothing to do with the lock); only **Delete Lorebook** is hidden for the locked one, and export and refresh work.
- **Stopping an agent run, or pausing it at once, did not stop the command that was going on.** An `async` command (a generation, a search and replace) went on in the background after the run was paused, stopped or sent a message at once, and could still change the working copy. The call is now cancelled: a command that is written to be stopped (it asks `CommandContext.isTerminated()` between its steps; its thread is interrupted too) ends at once. **Stop** no longer waits for the request or the call that is going on (a **Pause** still does); the agent is told in the transcript that the call was cut off and it is not known whether it was done. Plugin API: `FunctionContinuation.onCancel(Runnable)` (a default method) lets a function that hands its work to something stoppable stop it when its call is cancelled.
- **A write could fail with `database is locked` (`SQLITE_BUSY`, `SQLITE_BUSY_SNAPSHOT`) when threads wrote at once** (the agent and its sub-agents, usage counts, saves of the screens). A transaction begins deferred: it reads, takes its snapshot, and when another connection has committed before its first write, the write fails at once and `busy_timeout` does not help. The connections of read-write transactions now begin with the write lock (`transaction_mode=IMMEDIATE`, a second pool chosen by `ReadWriteRoutingDataSource`), so writers wait for each other for the busy timeout; read-only transactions keep the plain connections and do not wait for writers. No migration, no change for plugins.

- **Agents: an administrator has the limits of their own permission, like everybody.** `AgentService.getGrant` ignored the permission of an administrator: the quotas of the permission **Agents** (files per workspace, workspace size, file size, copies, checkpoints, most agents and runs, requests at once) had no effect for them, they were unlimited in agents, runs and requests and had the application defaults (500 files, 20 MB, 1 MB per file) in the workspace. Now an administrator needs no granted permission, but the settings of their permission apply, and an empty one is the same default as for a user (five agents, one run, one request at a time, the application default quotas). An administrator who needs more sets it in their own permission. The limits are read when a run's worker starts, so a changed setting applies after the run is paused and resumed.
- **Agent console: the result of a call shows when the call is made.** The results of a round were stored together after its last call, so a round of many or slow calls looked stuck. Each result is stored at once; a pause in the middle of a round also keeps the results of the calls made before it, they are no longer reported as interrupted.
- **Agents: a model that loops no longer overflows its context.** An answer with hundreds of the same call (seen with Gemma 4) made a request far over the context, because the cap is only checked against the previous request. The run now makes at most 32 calls of an answer, a repeat of a read-only call in the same answer is made once, and the agent is told.
- **Lore Generator commands did not build against the handle-based lorebook commands.** `generate-lore-entry` and `compact-lore-entry` take the `lorebook` and the `entry` as a handle or a number, like the other lorebook commands.
- **Agent console, Workspace tab:** the tab no longer scrolls over the file list and the viewer (three scrollbars): the list and the viewer share the height of the tab and scroll by themselves.
- A book created with **Add Book** is now remembered by the workspace autosave like a book opened from the list (the list did not know about its window).
- **Lorebook VCS: switching, adding or deleting a revision of an entry no longer closes the opened entries.** Only the row of the changed entry is redrawn instead of reloading the whole lorebook view.

### Known issues

- New users have neither `CREATE_AI` nor `HELPER`, an administrator gives them in the permissions of the user.

  the note. Generated arcs and chapters
  keep the reasoning and the answer of the model (`generationReasoning`, `generationResult`), shown in a popover.
  Stored in the book's attributes, no migration.
- Arc Outline: the wand next to *Add new arc* is a menu with *Generate an arc* and the new *Import from story*, which
  asks the model to summarize a range of the messages of the active branch of the book as an arc with chapters
  (optional exact number of chapters, state of the imported nodes, a counter with the approximate tokens of the range
  and of the whole prompt next to what the model takes). New prompt `Defaults.IMPORT_PROMPT` with the variables
  `{{backgroundLore}}`, `{{existingArcs}}`, `{{story}}`, `{{numberOfChapters}}`, editable in *Settings → Extension
  Settings → Arc Outline* (*Story import prompt*). Chapters with a note have a chevron that shows the note under the
  description in the list, without the dialog.
- `ModelProtocolPicker` (`ui.widgets`): a model and a protocol to choose from, for dialogs that run the model with a
  choice of their own. The Lore Generator dialog has one (it starts with the default model of the user settings), so
  has the Arc Outline generator (it starts with the model and protocol of the book).
- `IPCService`: extensions (and the application) offer text about a book or a story part to each other without
  importing each other: `registerManuscriptProvider` / `registerChatMessageProvider(bundleIdentifier, providerKey,
  providerName, callback)` with `ManuscriptPluginData` / `ChatMessagePluginData.getDataFor(entity, callerBundle,
  callerIdentifier)`, `getManuscriptProviders` / `getChatMessageProviders` (bundle → key → name, in registration order)
  and `getManuscriptData` / `getChatMessageData`. The providers of a bundle are removed when its extension unloads.
- Side Query: a plug button above a tab lists the sources of data other extensions offer; checked sources about the book
  are sent with the lore, sources about story parts are added after each included part. The Arc Outline offers its
  outline as two sources: the terse one (descriptions) and the full one (with the notes).
- `PartialJson.parse` (`domain.service.structured`): reads the unfinished JSON of a streamed answer (a markdown block
  around it is ignored) into a Jackson tree, to show what has arrived so far. New dependency
  `io.github.funnysaltyfish:partial-json-parser-jvm` (brings `kotlin-stdlib`).

- Workspace autosave: Marginalia remembers where the user was and restores it after the login - the selected tab, the
  filters of the book list, the lorebook and the open entries of the lorebook tab, the open book with its tab (and
  the open entries of its lorebook tab) and the new turn form of the story tab (scene, POV character, present
  characters, instructions). Both the desktop and the phone layout. Stored in the new `UserSetting.workspaceState`
  extended attribute (no migration). What was deleted meanwhile is skipped, a deleted book is not opened.
- `Restorable` (`ui`): `storeState()` / `restoreState(JsonObject)` for the UI classes that have state worth
  remembering, with the helpers in `RestorableState`. API changes plugins can see (since 1.3.0): `Workspace`
  extends `Restorable` and has `autosave()` and `restoreAutosaved()`; `WorkspaceComponent`, `ManuscriptDialogPart` and
  `PhoneManuscriptDialogPart` extend `Restorable` with default methods that store nothing, so existing parts compile
  unchanged; `ManuscriptDialog`/`PhoneManuscriptDialog` have `setOnStateChange` and `stateChanged()` (a plugin that
  adds a tab calls it), the lorebook views `setOnStateChange`, `NewTurnForm` `setOnChange`.
- New plugin **Name provider** (`marginalia/plugins/name-provider`): the model gets real names instead of generated ones.
  `list_real_name_lists` lists about 180 lists, `<Country> - Surnames` (75 countries) and `<Country> - Forenames` (106), and
  `pick_real_names` picks up to 100 of a list at random as pairs `{romanized, original}` (`Satō` / `佐藤`). The data is the
  popular names by country dataset (CC0), imported at build time into `name-lists.json` (committed; without network the
  committed file is used), the country codes are expanded to the English names of the countries.
- Name generator: 75 new categories `<Country> - Surnames` trained on the romanized surnames of the same dataset (new build
  step `import-popular-names`, `src/build/ImportPopularNames.java`), the tables and `chains.json` are extended, the
  existing ones are unchanged.

### Changed

- Character Tracker: the *Add relationship* button is above the fields of a new relationship, and closing the character dialog
  (Cancel, Esc) with unsaved changes asks for confirmation (Yes/No).
- The opened details of lorebook entries stay open when the entries are reloaded (refresh button, switching to the tab).
- Lore Generator and Arc Outline: the *Name tools* table lists the categories of the Name generator and of the Name provider
  together, with the prefix of the source (`Generator: `, `Provider: `), and the model gets the tools of the extensions that have a
  checked category: both, one or none. Each kind has its own hint in the settings (*Name generator hint*, the former *Name
  tools hint*, and the new *Name provider hint*, which tells the model to pick a name from the returned ones and keep it as
  it is). Categories saved before count as Generator ones. `NameGeneratorBridge` is now `NameToolsBridge`; the service
  methods `buildGenerationPrompt`, `buildPrompt` and `buildChapterPrompt` take the `FunctionSet` instead of a flag.

### Fixed

- Reviewer: the review dialog no longer saves an older copy of the part (reverting an edit or unlinking a summary made after the book was opened); it reloads the part before it reads or writes the reviews.
- Side Query: the sidebar tab no longer shows a second scrollbar around the message list (only the messages scroll), and the options bar wraps in a narrow sidebar.
- Saving the settings no longer writes back a copy of the user setting loaded when the tab was opened, which could undo
  a language chosen in the meantime.

## [1.2.0] - 2026-10-14

Four database migrations (`V10` to `V13`): a copy of the database is saved before they run, and 1.1.0 cannot open
a migrated database.

### Added

- `InferenceService.infer`: asks the model for the whole answer at once (no streaming, still asynchronous). With a JSON
  schema the provider is asked to follow it and the callback learns whether the answer is valid (`SchemaCheck`); with a
  Java class the answer is read into an object. The schema of a class is built from its fields and can be refined
  with the new annotations `@LLMSchema` and `@LLMField` (`StructuredOutputs`). The model can call functions during `infer` too. `InferenceService.stream` can pass a response schema to the provider (not validated). New dependency `json-schema-validator`.
- Settings → **Tags**: a table of all your tags with the number of objects related to each. A tag can be renamed or
  deleted (its relations are deleted with it). Renaming a tag to the name of another tag asks whether to merge them:
  yes moves the relations to the existing tag and deletes the renamed one, no leaves the tag unchanged
  (`TagService.findUsageForUser/findRenameConflict/rename/merge`, `TagRelationService.moveRelations/countRelationsByTag`;
  `TextInputDialog.Builder.initialValue`).
- Admin → Extensions: a **#** button next to the version of each extension shows the SHA-256 hash of its JAR on hover
  and copies it to the clipboard on click (`OsgiService.getSha256`).
- Shared inference providers: an administrator can check **Shared with all users** in a provider's dialog. Every user
  can then use it in their books, but not see its address or API key, change it or delete it. The rules are enforced in
  `AIService`, not only hidden in the UI (migration `V10`). A setting **Users can create their own models** (above the
  user list in the administration) lets administrators restrict users to the shared providers.
- Token usage per provider: the Inference Providers tab shows the tokens sent and generated with each provider, per user
  (a shared provider counts separately for each user); administrators get a **Usage per user** table with the tokens,
  requests and time of the last request of every user and provider (migration `V11`). The numbers are what the service
  reports (Marginalia asks for `stream_options.include_usage`) or a local estimate, and, unless an administrator limits a user (see below), nothing is limited by them.
- Limits of shared providers: the administrator who owns a shared provider sets, per user, a limit - unlimited, a token
  limit (tokens sent, generated and in total, each optional, reset daily, weekly or monthly) or not available - in the
  new **Limits** dialog of the Inference Providers tab. A request of a user who is over the limit or has the provider
  not available fails before anything is sent (a prompt that would go over the sent or total limit is refused, only the generated tokens can go over, unless the administrator makes that limit **hard**: then a request whose reserved
  response (the maximum response size) would not fit is refused too;
  `InferenceException` types `NOT_AVAILABLE` and `LIMIT_REACHED`, so
  generations, summaries and extensions all stop). Users see their own limit and what they used with the **info**
  button of a shared provider. The limits are stored in the provider (extended attribute `AI.limits`, a JSON object
  keyed by the uuid of the user, `AILimits`); the tokens used in the current period are two new columns of the `Usage`
  (migration `V12`), reset lazily when the user's last use is from an earlier period. New `AILimitService`; plugins
  that decorate `PhoneAIPart.createActions` see the new `infoButton` and `limitsButton`.
- LLM function calling: the model can call Java methods of an interface marked `@LLMFunction`
  (`FunctionRegistry`, `FunctionSet`, `FunctionContinuation`; asynchronous, JSON schema generated from the parameter
  types, up to 10 rounds per request with the last one forced to answer). `OpenAICompatibleInferenceService` runs the
  calls; extensions use it through `InferenceService.stream(payload, protocol, functions, callback)`.
- `InferenceServices.addToolRoleResolver` / `removeToolRoleResolver`: an extension can change the role the results of
  function calls are sent with.
- New widget `GraphView` (`ui.widgets`, `@PublicAPI` from 1.2.0): a graph drawn with Cytoscape.js (npm package
  `cytoscape`, `graph-connector.js`, `JavascriptLibrary.renderGraph`) - nodes with colors and images, labelled edges
  with arrows, nodes arranged in rings around a center node, re-centered by a double click. Plugins can use it.
- Plugin: **Character Tracker** — a *Characters* tab in the story sidebar: the characters of the book (name, tagline,
  note, icon scaled to at most 200 x 200 pixels, color) with relationships between them (directed or unidirectional,
  with a name and a tagline), a relationship map (double-click a character to arrange the map around it), and an import of lorebook entries (of the book's
  lorebook and its sub lorebooks) as characters. Stored in the attributes of the book. No
  changes to the application.
- Plugin: **Gemma 4 Tools Fix** — sends the results of function calls to Gemma 4 models with the role
  `tool_responses` instead of `tool`.
- Plugin: **Name generator** — the model can call `list_name_categories` and `generate_names` to get names from Markov
  chains instead of inventing them. About 1200 categories, trained at build time from the Onomastikon, fantasygen,
  Corpora and markov-namegen-lib (the build clones them, only the probabilities are committed). The length of the chain
  and the usual lengths of the names are set per category in `src/build/chains.json`, written by the tuning step
  (`mvn exec:exec@tune-chains`).
- Lore Generator: **Name tools** gives the model the functions of the Name generator for the categories you check, in a
  lazy table with a filter (the checked categories stay in it). The checked categories are remembered per entry with
  the other options of the generation. The default hint lets the model modify or remix the names it gets.
- Highlight of generated text: the settings menu (⚙) of the story has the checkable **Highlight Generated Text**. While
  it is on, the text of every part that is still the one the LLM wrote is highlighted, what the author added or
  rewrote is not (a word-by-word diff of the part against its new extended attribute `ChatMessage.originalResponse`,
  which generation fills and editing leaves alone). The switch is not saved. Existing parts get their current text as
  the original by the app migration 3 → 4 (`OriginalResponseMigration`, deleted parts too; no SQL migration), so what
  was edited before cannot be told apart. Only the desktop story tab has it. Plugins: `ChatMessage.originalResponse`,
  new `@Extendable` methods `ManuscriptStoryPart.createHighlightGeneratedMenuItem`, `setShowGeneratedDiff` and
  `ChatMessageCard.renderResponse` (`@PublicAPI` from 1.2.0).
- Reviewer plugin: a book can have its own reviewer profile. The info tab of the book (desktop and phone) has a
  **Reviewer Profile** combo box under the protocol; the chosen profile takes priority over the one selected in the
  settings (cleared: the selected one is used). The choice is stored in the book's attributes by the uuid of the profile,
  which profiles now have (profiles saved before get one the first time they are loaded), so renaming a profile keeps it.
  **Advanced Options** has a **Prompt from Profile** combo box that fills the prompt override with the review prompt of
  the chosen profile (only the prompt, not its model, protocol or pre-prompt).

### Changed

- A protocol can lower the context and response limits of a provider, but no longer raise them above the provider's.
- The story editors share their code: `ManuscriptStoryPart` and `PhoneManuscriptStoryPart` use the new classes of
  `ui.dialogs.story` (`StoryCards`, `StorySupport`, `StoryBackup`, `StoryGenerationListener`, `NewTurnForm`,
  `TurnDetailsForm`, `MessageMetrics`) and are about 300 lines shorter each. Plugins that decorate methods of these two
  classes should be checked against the new code.
- The phone workspace classes and more of the desktop UI classes are annotated with `@PublicAPI(from = "1.1.0")`
  and `PublicAPISignatureTest` checks the annotations against the compiled classes; the phone twins of the book tabs
  are listed as extension points in the developer manual.
- Vaadin is built with `optimizeBundle=false`.
- Lore Generator: the dialog is split into smaller classes (`NameToolsDialog`, `SavePromptAsDialog`,
  `AttachmentPanel`, `GenerationPane`).
- Deleting takes what belongs to the deleted object with it: a book its story parts, their summaries and its tags, a
  story part its summary and the parts below it, a lorebook its entries and their tags, an inference provider its usage
  numbers. The Trash restores them together with the object, and the cleanup keeps the contents
  of a deleted object it can't remove yet, so a restorable lorebook doesn't lose its entries. Services: `delete(x,
  false)` of `ManuscriptService`, `ChatMessageService`, `LorebookService`, `LorebookEntryService` and `AIService`
  cascades; new `TagRelationService.deleteForObject`, `ChatMessageService.softDeleteForManuscript`,
  `SummaryService.softDeleteForManuscript` / `softDeleteForMessages`. The messages and summaries of a book are soft
  deleted with one bulk update, so extensions get no save event for them.
- Trash: **Delete Permanently** removes deleted story parts and lorebook entries (with their summaries and tags) from
  the database right away, for users and administrators; other objects still wait for the cleanup, so nobody removes a
  whole book by accident. The parts below a removed part move to its parent. New `TrashService.deletePermanently` /
  `getPermanentlyDeletableTypes`; `TrashGrid` and `PhoneTrashGrid` get `createDeleteButton`, `deleteSelected` and the
  field `deleteButton` (`@PublicAPI` from 1.2.0).
- `@ExtendedAttribute(inject = true)` now works for any Java type, not only `JsonObject`: other types are converted
  to and from JSON with Gson (objects are stored flat as `<injectPrefix>_<key>`, lists and scalars under `injectPrefix`).

### Fixed

- Inference providers: the API key typed into a new provider is no longer lost when you visit *General Settings* before
  **OK** (the dialog read the enabled state of a field in a hidden tab). **Refresh** keeps the selected model. An empty
  API key works for local servers: a placeholder (`none`) is sent instead of failing in the client library.
- Regular users no longer get an *Application Error* dialog after every login (the admin part is refreshed only for
  administrators).
- Admin → Cleanup: purging an AI that has usage rows no longer fails (`usages.ai_id` is nullable, migration `V13`).
- Lore Generator: the Name generator is found by reflection and not imported, so it works when it is installed after the
  Lore Generator, and again after it was unloaded and installed again.
- The error dialog showed its message as HTML, so markup in an error message (provider replies, user input echoed in an
  exception) was rendered. It is shown as plain text now, line breaks kept.

## [1.1.0] - 2026-10-12

No database migration: a 1.0.0 database opens unchanged.

### Added

- Phone layout below 768 px: a phone workspace with a drawer, a phone book window, a phone story editor and phone
  versions of the book, lorebook, provider, protocol, settings and trash pages. The layout is chosen at page load.
  Not available on the phone: administration pages, the full lorebook editor and *Resources* (see the user manual).
- Per-user UI language: a language selector in the footer (only installed languages are listed), stored in the user
  settings and applied to all open sessions of the user. Japanese is built in.
- Extensions can add languages (`ExtensionHasLocalization`). The new Chinese Localization plugin is the worked example.
- Token breakdown: the tokens of every message of the final prompt are recorded with each generated part (parts from
  before have none) and shown in new Token Usage views with charts.
- Message attachments (images, audio, other files) can be passed to the model by the inference services. Used by the
  Lore Generator plugin; whether the model uses them depends on the model.
- Extension management: an extension can be stopped and started again without uninstalling it (`<jar>.STOPPED` flag
  file), and each extension has its own log file, rotated at 2 MB, shown in Admin → Extensions → Log. Plugins create
  their logger with `OsgiService.createLogger(bundle)`.
- Extensions can ship their own CSS (`ExtensionHasCss`), removed again when the extension is unloaded.
- Plugin: **Lore Generator** — generates the content of a lore entry from the existing lore, with saved prompts,
  attachments and a compaction step.
- Plugin: **Instruction Exporter** — copies the scene setting, POV character and present characters of the active
  branch to the clipboard.
- Plugin: **Chinese Localization** — Chinese UI texts as an extension.
- Root `pom.xml` as the parent of the application and all plugins: the version is defined in one place and
  `mvn package` in the root builds everything.
- `plugins/Dockerfile`, `plugins/docker-compose.yml` and `rebuild.sh` / `rebuild.bat` to build the plugins in a
  container and restart the stack with them.
- Documentation: user pages for the phone layout and the new plugins; developer pages for the new extension
  interfaces, token breakdown, message attachments and the parent POM.

### Changed

- Only the newest version of an extension is loaded at startup; older versions are moved to a separate folder.
- Story redraws keep the open tab sheet and the open reasonings.
- UI texts that were hard-coded (tree node cards, bundle states, error dialog button, prompt format list, login
  description, `ERROR` fallbacks) are localization keys.
- Inline styles were replaced by CSS classes (`shared-styles.css`, `CssStyles`) and all browser-side JavaScript moved to
  `ui.JavascriptLibrary`.
- The bundled plugins use the extension logger instead of `LoggerFactory`.
- Plugins built for 1.0.0 must be rebuilt from the 1.1.0 source tree; the plugin API is not frozen and the extension
  verifier shows plugins that no longer match as *Invalid*.

### Fixed

- A page reload logged out every user who had not chosen *Save login*; a user who is already logged in this session is
  now kept.
- `SessionManager` kept the session-scoped `user` proxy, so user filters running on another thread failed with
  `ScopeNotActiveException`; it now stores a plain copy taken at login.
- The plugin Docker image no longer runs the Vaadin frontend build.
- Summaries: the inference now starts after the transaction that creates the summary has committed. A fast answer
  could be saved before the new summary row was visible, which failed with `OptimisticLockException` and left the
  summary request unanswered (seen as intermittent `MetaSummaryTest` timeouts in CI).

### Known issues

- The Japanese and Chinese texts are machine translations that a native speaker should review.
- The phone layout does not follow a rotation, and `PhoneManuscriptStoryPart` duplicates much of
  `ManuscriptStoryPart`.
- Plugins' own texts, fixed words in exported files and default object names created by services are English only.
- A restored story part does not get its former children back.

## [1.0.0] - 2026-10-10

Initial release.

- Branching story tree (regenerate, swipe, branch), lorebooks with tag, text and regex activation and nested lorebooks,
  summaries and meta summaries, Handlebars and SillyTavern-macro prompts, SillyTavern import.
- Search across all branches, story export (TXT, Markdown, HTML, DOCX, PDF, EPUB), images on story parts.
- OpenAI-compatible providers with timeout, retries, classified errors and a connection test.
- Per-book backups, scheduled database backups with staged restore, a copy of the database before a migration, trash
  with restore.
- Login throttling per user and per address, encrypted API keys, server-side admin checks.
- OSGi extension system with verification of bundles, and the Author's Note, Chapter Marker, Lorebook VCS, Reviewer and
  Side Query plugins.
- Docker image (amd64, arm64), WAR and desktop archives for five targets.
