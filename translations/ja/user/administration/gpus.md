# GPU

グラフィックボードは多くの場合、一度に1つのモデルしか保持できません。言語モデル、画像モデル、音声モデルのいずれかです。管理ページの **GPU** タブでは、同じボード上のモデルやサーバーを順番に使えるようになります。これにより、言語モデルがボードを占有している間に画像やオーディオブックの生成が始まることはなく、必要になれば言語モデルが再び読み込まれます。

管理者が一度設定すれば、あとは各ユーザーがAIやバックエンドで使うロックを選ぶだけです。

<a id="what-it-is-made-of"></a>

## 構成要素

| | |
|---|---|
| **GPU** | 1枚のカード(または一度に1つのモデルしか保持できない任意のマシン)。名前のみ。 |
| **GPU ロック** | GPUの1つの使い方、つまりそのGPUに何を読み込んでおくかです。例えば、同じGPU上の *言語モデル*、*ComfyUI*、*Speech* などです。ロックには順序付きのステップが2つのリストとしてあります。**取得ステップ**はロックを読み込み(コンテナを起動する、モデルを読み込む、先に外すべきものをアンロードする)、**解放ステップ**はそのロックがカードを占有しないよう解放します(コンテナを停止する、モデルをアンロードする)。**同時ジョブ数**は、そのロックのジョブが同時に実行される数の上限です(一度に1枚の画像しか作らない画像サーバーなら1、制限なしなら0)。 |
| **GPU ステップ** | 1つのHTTPリクエストです。アドレス、メソッド、ヘッダー(`Name: value`、1行に1つ。暗号化して保存されるため、ここにベアラーキーを書けます)、本文、タイムアウト(空欄: 60秒)、回答後の待機時間から成ります。ステップは複数のロックで共有できます。例えば、画像と音声の両方のロックが最初に実行する *言語モデルをアンロード* ステップ1つです。**テスト** を押すと、そのリクエストをすぐに送信します。 |

ロックは次の場所で選びます。

- [AIの設定](../inference-providers.md)(一般設定の **GPU ロック**)。言語モデル用です。
- [画像生成](../extensions/image-generator.md#one-gpu-for-the-model-and-the-images)のバックエンド。
- [オーディオブック](../extensions/audiobook-server.md#one-gpu-for-the-model-and-the-speech)のバックエンド。

「**GPU ロック**」欄は、ロックが1つ以上存在する場合にのみ表示されます。

<a id="how-the-turns-work"></a>

## 順番の仕組み

- 言語モデルへのリクエスト、画像、オーディオブックのバッチやサンプルはすべて、そのAIまたはバックエンドのロックを、ジョブの実行時間の間ずっと取得します。
- 既にそのロックでGPUが読み込まれている場合、ジョブはすぐに始まり、ステップは実行されません。
- 別のロックで読み込まれている場合、ジョブはそのロックのジョブがすべて終わるまで待ちます。その後、そのロックの**解放ステップ**がすべて実行され(一部が失敗した場合も全部)、次に新しいロックの**取得ステップ**が順番に実行されます(最初の失敗で中断され、ジョブはそのステップのメッセージとともに失敗します)。
- 解放ステップが失敗した場合、新しいロックは一切読み込まれません(カードがまだ満杯の可能性があるためです)。ジョブはエラーで失敗し、GPUは元のロックのまま残ります。別のロックの次のジョブが、再度解放を試みます。
- ジョブの後も、GPUはそのロックで**読み込まれたまま**です。タイマーで解放されることはありません。開いたままの、折りたたまれた、または閉じた画像ウィンドウはGPUを保持せず、画像モデルは言語モデル(または別のロック)がカードを必要とするまで読み込まれたままです。
- ジョブは届いた順に待ちます。あるジョブが別のロックを待ち始めると、読み込み済みのロックの新しいジョブはその後ろで待ちます。そのため、忙しい言語モデルが画像を永久に待たせ続けることはありません。
- ロックがない、または削除されたロックを持つAIやバックエンドは、何も待ちません。

GPUが何を保持しているかは、アプリケーションが実行中の間だけ分かります。再起動後は何も読み込まれていないものとして扱われ、最初のジョブは取得ステップのみを実行します。

<a id="the-tab"></a>

## タブ

タブには、各GPUと現在読み込まれているロック(まだ何も実行していない、またはアンロードされた場合は *Unknown*)、そのGPUで実行中および待機中のジョブ数が一覧表示されます。続いてロックとステップが、それぞれ追加、編集、削除のボタン付きで表示されます。**更新** を押すと、GPUが保持しているものを読み直します。

**今すぐ解放** を押すと、GPUを手動で解放します。例えば、Marginalia の外の用途でカードを使いたいときなどです。実行中のジョブを待ち、読み込まれているロックの解放ステップを実行して、GPUの状態を不明のままにします(ステップが失敗した場合も同様で、メッセージにどのステップかが示されます)。次のジョブは、そのロックを再び読み込みます。

GPUを削除すると、そのロックも削除されます。ステップを削除すると、それを実行していたロックから取り除かれます。削除されたロックを指定していたAIやバックエンドは、ロックなしで実行されます。

<a id="an-example-one-card-three-models"></a>

## 例: 1枚のカードに3つのモデル

LiteLLM の背後で `llama-server` を動かし、コンテナを起動・停止する [`tools/gpu-control`](../extensions/audiobook-server.md#what-answers-those-addresses) 形式のプロキシを使う場合:

| ステップ | リクエスト |
|---|---|
| 言語モデルをアンロード | ヘッダー `X-Llama-Unload: all` を付けた `POST http://litellm:4000/v1/chat/completions` (see [別のモデルのためにGPUを解放する](../prompt-cache.md#freeing-the-gpu-for-another-model)) |
| ComfyUIを起動 / ComfyUIを停止 | `POST http://litellm:4000/gpu/comfy/start` / `.../stop` |
| 音声を起動 / 音声を停止 | `POST http://litellm:4000/gpu/tts/start` / `.../stop` |

| ロック | 取得ステップ | 解放ステップ | 同時ジョブ数 |
|---|---|---|---|
| 言語モデル | (なし: ルーターが次のリクエストでモデルを読み込む) | (なし) | 0 |
| ComfyUI | 言語モデルをアンロード、ComfyUIを起動 | ComfyUIを停止 | 1 |
| Speech | 言語モデルをアンロード、音声を起動 | 音声を停止 | 1 |
| Clip cleanup | 言語モデルをアンロード、ComfyUIを起動 | ComfyUIを停止 | 1 |

言語モデルのAIは *言語モデル* のロックを選び、画像のバックエンドは *ComfyUI*、音声のバックエンドは *Speech* を選びます。オーディオブックの[クリップのクリーンアップ](../extensions/audiobook.md#cleanup-of-clips)は *Clip cleanup* を選びます。画像と同じ ComfyUI 上で動きますが、専用のロックが間で ComfyUI を再起動するため、画像モデルとクリーンアップ用のモデルがメモリ上に同時に存在することは決してありません。チャットの後の音声のバッチ処理は *言語モデルをアンロード* と *音声を起動* を実行し、次のチャットメッセージでは、まず *音声を停止* が実行されます。
