# 管理

管理者はMarginaliaのインストールを管理します。ユーザーアカウント、データベースのバックアップ、削除されたデータのクリーンアップ、アップデート、拡張機能などが対象です。[初回起動](../getting-started/first-start.md)時に作成された最初のアカウントは管理者で、ほかのユーザーを管理者にすることもできます。

管理者も通常のユーザーで、自分の本を持っています。ほかのユーザーの本、ロアブック、設定は見えません。見えるのは、そのユーザーがすべてのユーザーと共有しているロアブックとプロトコルだけです。

<a id="the-admin-page"></a>

## 管理ページ

管理者のワークスペースの下部には**管理**ボタンがあります。[スマートフォン向けのレイアウト](../phone.md#administration)（幅768ピクセルより狭いウィンドウ）では、ドロワーのタブ**管理**になります。管理ページには次のタブがあります。

| タブ | |
|---|---|
| **ユーザー** | アカウントの作成、編集、削除、ユーザーへの[権限](permissions.md)の付与。[ユーザー](users.md)を参照。 |
| **データベースのバックアップ** | データベース全体のバックアップ（手動またはスケジュール）と復元。[データベースのバックアップ](database-backups.md)を参照。 |
| **クリーンアップ** | 削除されたデータを完全に削除します。[クリーンアップ](cleanup.md)を参照。 |
| **リソースファイル** | 使われなくなったリソースのファイルを探し、ZIPでダウンロードしてディスクから削除します。[リソースファイル](resource-files.md)を参照。 |
| **ヘルプアシスタント** | マニュアルの内容について質問に答えるチャット。モデル、プロンプト、そして費用を負担する人を設定します。[ヘルプアシスタント](help-assistant.md)を参照。 |
| **エージェント** | エージェントと、そのユーザーが独自のものを持っていない場合にエージェントが従うシステムプロンプトとコンパクションプロンプト。空欄は組み込みのプロンプトです。情報アイコンにある**既定のテンプレートを挿入**で内容を入れてから、コピーを編集できます。ユーザーがエージェントで何をできるかは、その[権限](permissions.md)で決まります。また**エージェントがユーザーのWebhookへメッセージを送ることを許可する**：エージェントが必要とし、ユーザーがアプリを閉じているとき、サーバーはそのユーザーが設定に入力したアドレスを呼び出します（[不在のとき](../agents.md#when-you-are-not-there)）。認められない場合はオフにしてください。 |
| **統計** | [執筆統計](../books/statistics.md)を記録するかどうか、保存期間、ユーザーまたは全員の統計を消去すること。[統計](statistics.md)を参照。 |
| **ジョブ** | 外部のAIに依頼されたすべての処理のログ（誰が、いつ、どの呼び出しを、どのように終了したか）、古いエントリーを手動で削除するフィルター、そして現在実行中のジョブを表示するページ`/jobs`。[ジョブ](jobs.md)を参照。 |
| **GPU** | 言語モデルと画像・音声サーバーで共有する1枚のグラフィックカード。GPU、GPUロック（各モデルの読み込み方法とカードからの解放方法）、実行される手順、各GPUが現在保持しているもの、そして**今すぐ解放**。[GPU](gpus.md)を参照。 |
| **アップデート** | Dockerサーバーでは、実行中のバージョン、サーバーが追うブランチの最新バージョン、そしてMarginaliaを更新して再起動するボタン。[アップデート](updates.md)を参照。 |
| **拡張機能** | 拡張機能のインストールと削除。[拡張機能の管理](extensions.md)を参照。 |

## データフォルダー

Marginaliaが保存するすべてのものは、それを実行するユーザーのホームディレクトリにある`.marginalia`フォルダーにあります（[Docker構成](../getting-started/docker-server.md)の場合はホストマシン上の`./data`）。

| パス | |
|---|---|
| `marginalia.sqlite`（`-wal`、`-shm`を含む） | データベース：ユーザー、本、ロアブック、設定などすべて。 |
| `secret.key` | データベース内のAPIキーを暗号化する鍵。最初の起動時に作成され、所有者のみが読み取れます（LinuxとmacOS）。これがないと保存されたAPIキーを読めません。コンピューターの他のユーザーが読める場合、ログにその旨が表示されます：`chmod 600 secret.key`。 |
| `db-backups/` | [データベースのバックアップ](database-backups.md)。 |
| `data/<login>/backups/manuscripts/<book id>/` | 各ユーザーの[本のバックアップ](../books/backups.md)。 |
| `extensions/` | インストール済みの[拡張機能](extensions.md)のJARファイル。 |
| `update/` | MarginaliaとDockerサーバーの[アップデート監視](updates.md#setting-up-the-watcher)がやり取りするファイル：状態、直近のアップデートのログ、リクエスト。 |
| `agent-workspaces/<agent id>/` | [エージェント](../agents.md#the-working-copy)のファイル（実行をまたいで保持されるメモとレポート）。 |
| `agent-runs/<run id>/` | エージェントの実行が保持するもの：変更を表示するための本の開始時点（作業コピーとともに削除）、チェックポイント、発見事項（クリーンアップで実行が消去されると削除）。 |
| `desktop/logs/` | [デスクトップアプリ](../getting-started/desktop-app.md)のログ。 |

インストール全体をバックアップするには、Marginaliaを停止してこのフォルダー（`secret.key`を含む）をコピーします。実行中は、データベースには[データベースのバックアップ](database-backups.md)を使ってください。本のバックアップと拡張機能は通常のファイルなので、いつでもコピーできます。
