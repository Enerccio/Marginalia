# 작업

애플리케이션이 **외부 AI**에 요청하는 것은 모두 *작업*(job)입니다. 생성, 요약, 주석, 에이전트 실행, 장(chapter)의 오디오 변환, 이미지 생성이 모두 여기에 해당합니다. 각 작업은 실행한 사용자, 시작 및 종료 시각, 종료 방식과 함께 기록됩니다. 또한 작업이 모델이나 음성 또는 이미지 백엔드에 한 *호출*(call)도 모두 기록되며, 각 호출에는 고유한 시작 및 종료 시각이 있습니다. 관리자 페이지의 **Jobs** 탭에서 기록을 볼 수 있고, `/jobs` 페이지에서는 지금 실행 중인 작업을 볼 수 있습니다.

메타데이터만 보관됩니다. 누가, 언제, 얼마나 걸렸는지, 어떤 AI 또는 서버를 썼는지(AI의 이름, 또는 음성이나 이미지 서버의 호스트. 주소 경로나 쿼리는 기록하지 않음), 어떤 모델인지, 어떻게 끝났는지, 실패했다면 짧은 오류 메시지가 기록됩니다. **프롬프트, 답변, 텍스트는 어떤 것도** 저장되지 않습니다.

<a id="what-is-one-job"></a>

## 작업 하나의 구성

- **묶이지 않는 개별 요청**(생성, 주석, 다시 쓰기, 대역 연기, 한 부분의 요약, 도움말 어시스턴트에 던진 질문, 부분 번역이나 설정 항목 번역 같은 플러그인 요청)은 호출 하나를 가진 독립된 작업입니다. 작업의 종류는 작업의 성격에 따라 정해집니다(`generation`, `annotate`, `summary` ...).
- **요약 다시 쓰기**는 작업 하나(`summary`)이며, 작성된 요약 하나당 호출이 하나씩 있습니다.
- **에이전트 실행의 작업 세션**은 작업 하나(`agent`)이며, 에이전트의 라운드마다 호출이 하나씩 있습니다. 일시 정지되었다가 재개된 실행은 세션마다 작업이 따로 생기며, 하위 에이전트의 요청도 각각 독립된 작업이 됩니다.
- **오디오 변환**은 부분 묶음(batch)마다 작업 하나(`audiobook`)가 생기며, 라벨링 모델에 보낸 요청과 음성으로 바뀐 각 조각이 호출로 기록됩니다.
- **Image Generator**로 만든 이미지는 이미지 호출 하나를 가진 독립된 작업(`image-generator`)입니다.

<a id="what-runs-now-jobs"></a>

## 지금 실행 중인 작업: `/jobs`

![생성이 진행 중인 /jobs 페이지](../../images/jobs-live.png)

Marginalia 주소의 `/jobs`를 여세요(예: `http://localhost:8080/jobs`). 탭의 **Open the live view** 링크를 누르면 같은 페이지로 이동합니다. 다른 페이지와 마찬가지로 로그인이 필요하며, 관리자가 아닌 사용자에게는 아무것도 보이지 않습니다. 목록은 2초마다 새로 고쳐지며, 실행 중인 작업마다 사용자, 작업 종류, 실행 시간, 완료된 호출 수, 지금 진행 중인 호출(AI 또는 서버와 호출이 기다린 시간)을 보여 줍니다. 또한 작업이 처리하는 실행의 책(book)과 **Stop** 버튼도 함께 표시됩니다. 서버가 바쁜 것 같을 때 빠르게 확인하는 용도로 좋습니다. 한 모델의 응답을 기다리는 호출이 길게 쌓여 있다면 모든 것이 느린 이유를 알 수 있습니다.

작업 목록 아래의 **Runs on the books**에는 지금 책에서 작업 중인 실행이 나열됩니다. 이 실행은 그 책의 일부가 실행 도중 삭제되거나 바뀌지 않도록 막습니다([실행 패널](../books/story-editor.md#the-panel-of-the-runs)에서도 각 사용자가 자신의 책에 대해 같은 정보를 볼 수 있습니다). 목록에는 사용자, 책, 실행이 하는 일, 현재 상태, 실행이 시작된 시각, 실행이 잡고 있는 객체 수(책, 부분 등)가 나타납니다. 상태에는 패널과 같이 *Waiting for the model*, *The model is thinking/writing...*, *Working*, *Waits for you*가 표시되며, 생성 작업이라면 *INFERENCE*처럼 현재 단계도 보입니다(열려 있는 책의 창에서는 이 부분이 표시되지 않습니다). 열려 있는 책의 창도 하나의 실행으로 집계됩니다. **Stop**은 실행을 그 사용자가 직접 멈춘 것처럼 중단합니다. **End**는 질문에 확인한 뒤 실행 작업을 멈추지 않고 종료합니다. 이때 실행이 잡고 있던 객체는 즉시 풀립니다. 끝나지 않는 실행에만 사용하세요. 종료된 실행의 작업이 나중에 깨어나면 여전히 무언가를 쓸 수 있습니다. 대부분의 실행은 스스로 끝납니다. 한 시간 동안 아무 작업도 하지 않고 사용자나 모델을 기다리지도 않는 실행은 서버가 종료하며, 닫힌 페이지의 창도 같은 방식으로 종료됩니다.

<a id="the-log-the-jobs-tab"></a>

## 기록: Jobs 탭

![관리자 페이지의 Jobs 탭](../../images/admin-jobs.png)

| | |
|---|---|
| **User, Kind, Status** | 필터입니다. *Kind*는 작업의 종류이며(`generation`, `summary`, `annotate`, `agent`, `audiobook`, `image-generator` ...), 작업 이름을 지정하지 않은 코드가 보낸 요청은 `untagged`로 표시됩니다. |
| **Older than (days)** | 지정한 일수 이전에 시작된 작업만 표시합니다. |
| **Refresh** | 기록을 다시 읽어 옵니다. |
| **Delete these jobs** | 필터에 표시된 작업과 그 호출을 영구히 삭제합니다. 삭제 전에 개수를 알려 주는 확인 질문이 나옵니다. 필터를 설정하지 않으면 기록 전체를 삭제합니다. |
| **Open the live view** | 새 탭에서 `/jobs`를 엽니다. |

행을 클릭하면 작업의 호출을 볼 수 있습니다. 호출의 유형(언어 모델, 오디오, 이미지), AI 또는 서버, 모델, 시작 및 종료 시각, 실행 시간, 상태가 표시되며, 실패한 호출에는 오류 내용도 나타납니다. 실패로 표시된 작업은 그 안의 호출이 실패했거나, 작업을 실행한 코드가 실패로 끝냈다는 뜻입니다. 취소된 호출은 여러분이 멈춘 호출이거나, 작업이 끝났을 때 아직 실행 중이던 호출입니다.

![오디오북 변환의 호출들](../../images/admin-jobs-calls.png)

실패한 작업에는 어떤 호출이 실패했고 이유가 무엇인지 나타납니다.

![음성 호출의 오류로 실패한 변환](../../images/admin-jobs-failed.png)

**기록은 저절로 삭제되지 않습니다.** 요청이 있을 때마다 기록이 쌓이므로 가끔 정리하세요. *Older than (days)*를 설정하고(예: 30), 목록을 확인한 뒤 삭제하면 됩니다. [정리](cleanup.md) 기능을 쓰면 사용자를 삭제할 때 그 사용자의 작업도 함께 지워집니다.

![30일이 지난 작업과 삭제 전 확인 질문](../../images/admin-jobs-old.png)

![작업을 삭제하기 전의 확인 질문](../../images/admin-jobs-delete.png)

작업은 끝날 때 기록에 쓰입니다. 아직 실행 중인 작업은 `/jobs`에만 있습니다. 애플리케이션이 멈추면 실행 중이던 작업은 끝나지 않은 것이므로 사라집니다. 누구도 끝내지 않았고 30분 동안 호출도 하지 않은 작업은 완료된 것으로 처리됩니다.
