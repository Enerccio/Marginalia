# 设定生成器

让模型为你撰写[设定集条目](../lorebooks/entries.md)的内容。它会读取你已有的设定，使新条目与世界观相吻合，并将结果压缩为设定条目最适合的简短、凝练的形式。

!!!
设定生成器可在[手机布局](../phone.md#extensions)中使用：条目所在行中有魔杖按钮，窗口上方是提示词，下方是结果。
!!!

<a id="opening-the-generator"></a>

## 打开生成器

安装该扩展后，设定集编辑器的每一行都会有一个魔杖按钮（**Generate lore entry**）。点击后会为该条目打开生成器。如果该条目已有内容，对话框顶部会有提示：将结果复制到条目会替换原有内容。

[全屏编辑器](../lorebooks/lorebooks.md#editing-in-full-screen)同样有魔杖按钮：在条目列表的每一行中，以及条目标签页名称行中的 **Generate lore entry**。复制到条目的内容会立即显示在其标签页中。从某个设定集（其 *Lorebook* 标签页，或故事的设定集标签页）打开编辑器时，编辑器知道该设定集，因此生成费用由该设定集承担，与在设定集页面上一样。

生成器默认使用*设置*中的 **Default Model** 和 **Default Protocol**，参见[账户与设置](../account.md)。对话框标题下方的 **Model** 和 **Protocols** 列表，可让你在本次生成中改用其他模型或协议（此选择不会被保存）；协议为可选项。若未选择模型，只会显示一条警告。

![设定生成器](../../images/plugin-loregenerator.png)

<a id="what-the-model-sees"></a>

## 模型能看到什么

对话框顶部的两个选项决定哪些设定会被放入请求中：

| 选项 | |
|---|---|
| **Current Lorebook**（默认）/ **All Lore** | 仅包含该条目所在设定集的条目，忽略其[子设定集](../lorebooks/lorebooks.md)；或包含该设定集及其所有子设定集的条目。 |
| **Only up to position (n)**（默认）/ **All entries** | *n* 为该条目的顺序。仅显示排在它之前的条目（顺序更小，或顺序相同但创建更早），这样模型会基于已有内容继续构建，而不会读到在该条目之后才写下的设定。*All entries* 则显示全部条目。 |

正在生成的条目始终不会被包含在内，无论它是否有内容。其他条目或设定集是否启用，它们的标签、过滤器和插入模式都会被忽略：你在此选择的内容就是被发送的内容，并按照条目被插入提示词的顺序排列。条目的模板照常处理。

<a id="prompts"></a>

## 提示词

生成提示词是你要求模型撰写的内容。提示词列在选项旁边的方框中，位于同一顶部行；所选提示词的文本显示在左侧的文本区域中，你可以在不保存的情况下仅对本次生成进行修改。对话框的两半由一个可拖动的分隔条隔开。

| 按钮 | |
|---|---|
| **Save** | 以所选名称保存文本。 |
| **Save as** | 要求输入名称，并将文本保存为一个新提示词（或在确认后替换同名的提示词）。 |
| **Delete** | 删除所选提示词。删除最后一个提示词后，内置的 `DEFAULT` 提示词会重新出现。 |

内置提示词中有方括号内的占位符（主题、需要包含的细节、长度、结构）：运行前请先填写。提示词属于你的账户；下次打开对话框时，会再次选中你上次使用的那个。

<a id="generation-and-compaction"></a>

## 生成与压缩

右侧有两个标签页。

**Generation**：**Run Generation** 会先发送设定，再发送生成提示词。回答会边写边显示；如果模型给出了推理过程，则会显示在上方的 *Thinking Process* 部分。**Stop**（位于 *Run Generation* 的位置）会提前结束生成；已写出的内容会被保留。

**Compaction**：生成完成后可用。**Run Compaction** 会发送相同的设定，再发送压缩提示词（其中包含已生成的文本），模型会将其浓缩为一个紧凑的条目。压缩提示词在*设置 → 扩展设置 → Lore Generator*中设定；若为空，则使用内置的提示词（它会去掉散文化的表述，保留事实）。再次运行生成会丢弃压缩结果。

![已生成条目的压缩](../../images/plugin-loregenerator-compaction.png)

模型工作时，除 **Stop** 外，所有控件都会被冻结；对话框也无法关闭。

<a id="remembered-per-entry"></a>

### 按条目记忆

当你点击 **Copy to Lore Entry** 时，本次生成的选项会与该条目一同保存：提示词文本、它来自哪个已保存的提示词、设定与条目的选择，以及勾选的名称分类。再次为该条目打开生成器时，这些选项会被恢复，优先于你上次使用的提示词以及你保存的名称分类。从未被生成过内容的条目，则以常规默认值打开。这些选项属于该条目，因此会随设定集的备份和导出一起保存。

<a id="tools"></a>

### 工具

当安装了[模型工具](tools.md)套件（来自[名称生成器](name-generator.md)或[名称提供者](name-provider.md)的名称，以及来自[地点提供者](place-provider.md)的地点）时，顶部行会出现 **Tools** 按钮。点击后会打开一个窗口，你可以在其中选择模型可以使用的套件，以及对于带有分类的套件，选择可用的分类；其工作方式参见[模型工具](tools.md)。只要勾选了某项，模型就可以在生成过程中调用这些工具（压缩过程中不可用），并且每个套件的提示说明会被添加到生成提示词的末尾。该选择会与你的账户及该条目一同保存。

<a id="attachments"></a>

### 附件

在提示词下方，你可以添加供模型查看的文件：参考图片、地图、角色设定表等。可以将文件拖放到上传区域、通过选择添加，或用 Ctrl+V 粘贴到提示词中（截图或复制的文件会成为附件；粘贴的文本则照常插入）。每个文件最大 20 MB。附件会以名称、类型和大小列出；垃圾桶按钮可删除其中一个。附件随生成一同发送，不随压缩发送；只有在没有生成任务运行时，才能添加和删除附件。

模型能否使用这些附件，取决于模型和[推理提供方](../inference-providers.md)：图片会以图片形式发送，音频仅支持 WAV 或 MP3，其他文件以文件形式发送。若提供方拒绝某个附件，你会收到一条提示，且不会生成任何内容。

<a id="copying-the-result"></a>

## 复制结果

当压缩有结果时，**Copy to Lore Entry** 可用。压缩后的文本会成为条目的 **content**（内容），压缩前生成的文本则放入其 **note**（备注）。两者都会被替换。如果压缩结果是一个代码块（内置提示词要求这样做，以便于复制文本），则会移除包裹它的代码块。设定集会刷新，对话框保持打开；**Exit** 则关闭对话框。
<a id="commands"></a>

## 命令

生成器也可以不通过对话框工作，提供三个用于命令行和[智能体](../commands/index.md)的[命令](../agents.md)。它们与对话框执行相同的两个步骤，并且和对话框一样，不保存任何内容：它们返回文本，而将文本放入条目（即 **Copy to Lore Entry** 所做的事）由调用者决定，因此三个命令都只读取数据。设定集和条目通过编号指定，与 `/list-lorebooks` 和 `/list-lore-entries` 相同；所用模型为你的默认模型和协议。

| 命令 | 作用 |
|---|---|
| `/list-lore-templates [template]` | 列出你保存的生成提示词（名称、长度、文本开头），以及最近一次使用的提示词。指定名称时，返回该提示词的完整文本。 |
| `/generate-lore-entry [prompt [template [lorebook [entry [order [scope [limit [images [compact]]]]]]]]]` | 基于设定集的设定生成文本，将其压缩（与 `/compact-lore-entry` 相同），并返回压缩后的文本；当 `compact` 为 `false` 时，返回原样的生成文本。发送的文本由一个模板加上调用者的提示词组成（见下文）。使用 `images` 时，模型同样会查看图片，与对话框中的附件一样。 |
| `/compact-lore-entry text [lorebook [entry [order [scope [limit]]]]]` | 使用相同的设定压缩文本，并返回结果（不带外层代码块）。 |

条目决定模型能看到哪些设定。将其句柄或编号作为 `entry` 给出（若按编号给出，还需提供其所在的 `lorebook`，可用句柄或编号），此时可见的设定与对话框中相同：`limit` 为 `UP_TO_POSITION`（默认值）时，只包括它之前的条目，条目本身永远不包括在内。尚不存在的条目没有编号：请改为给出它将获得的 `order`（即 `/list-lore-entries` 中的 `order`，数值越小越靠前），模型将看到该顺序之前的条目；两者都不给时，文本按照新条目排在所有其他条目之后来编写。`scope` 可为 `CURRENT_LOREBOOK`（默认）或 `ALL_LORE`，`limit` 可为 `UP_TO_POSITION` 或 `ALL_ENTRIES`，与对话框相同。

生成效果取决于提示词的质量，因此该命令总是从你保存的生成提示词之一开始（见[提示词](#prompts)）：即 `template` 中指定的那个，若未指定则使用最近一次使用的那个。调用者的 `prompt` 紧随其后，置于标题 *Task for this entry* 之下，用于填写主题、事实、长度和章节等模板所要求的内容。`template` 设为 `none` 时，只发送调用者的提示词，适用于调用者已自行写好完整提示词的情况，例如先从 `/list-lore-templates` 获取模板文本并加以修改。若调用时只给出模板而没有提示词，则只发送模板。

`/generate-lore-entry` 的 `images` 即对话框在生成时会附加的图片。[智能体](../agents.md)传入的是其工作区中图片文件的路径列表（如 `/refs/map.png`；最多 8 个，格式为 PNG、JPEG、GIF 或 WebP，较大的图片会被缩小），这些文件需事先通过工作区标签页中的 **Upload file** 放入工作区。命令栏无法指定图片，因此 `images` 仅供智能体使用。查看图片的是你的默认模型：若该模型不支持图片，命令将失败并给出提示。与对话框一样，只有生成步骤接受图片，压缩步骤仅处理文本。

`/generate-lore-entry` 的 `compact` 参数默认为 `true`：命令在一次调用中完成生成和压缩，因此[智能体](../agents.md)只需一个命令，不会遗漏第二步。若传入 `compact` `false`，则获得较长的原始生成文本（例如便于审阅或编辑），之后可对其运行 `/compact-lore-entry`。

此处模型不提供任何工具。若调用者需要人名，应先通过[人名生成器](name-generator.md)的 `/generate-names` 或[人名提供器](name-provider.md)的 `/pick-real-names` 获取，然后将满意的人名写入提示词。智能体也可以从 `/list-lore-templates` 获取模板文本，修改后将结果作为提示词传入。

<a id="storage"></a>

## 存储

提示词和压缩提示词与你的设置一起保存，因此[数据库备份](../administration/database-backups.md)会包含它们。设定集中不保存任何内容；生成的文本仅存在于对话框中，直到你将其复制出来为止。
