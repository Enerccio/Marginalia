# GPU

グラフィックカード1枚には、多くの場合一度に1つのモデルしか載せられません。言語モデル、画像モデル、音声モデルのいずれかです。管理ページの**GPU**タブでは、同じカード上のモデルやサーバーが順番にカードを使えるように設定できます。そのため、言語モデルがカードを占有しているときに画像やオーディオブックの生成が始まってしまうことはなく、必要になれば言語モデルが再び使えるようになります。

設定は管理者が一度行います。その後、各ユーザーは自分の AI やバックエンドにロックを選びます。

<a id="what-it-is-made-of"></a>

## 構成要素

| | |
|---|---|
| **GPU** | 1枚のカード（または一度に1つのモデルしか載せられない任意のマシン）。名前のみ。 |
| **GPU ロック** | GPUの使い方の1つで、そのGPUに何が読み込まれているかを表します。たとえば、同じGPU上の *言語モデル*、*ComfyUI*、*Speech* などです。ロックには順序付きの2つのステップリストがあります。取得ステップはロックを読み込み（コンテナの起動、モデルの読み込み、先に外すべきものの解放を行います）、解放ステップはカードからロックを外します（コンテナの停止、モデルの解放を行います）。**同時ジョブ数**は、そのロックのジョブを同時に何件まで実行するかを制限します（一度に1枚だけ画像を作る画像サーバーなら1、制限なしなら0）。 |
| **GPU ステップ** | 1回のHTTPリクエストです。アドレス、メソッド、ヘッダー（`Name: value`、1行に1つ。暗号化して保存されるため、ベアラーキーをここに書けます）、ボディ、タイムアウト（空欄なら60秒）、回答後の待機時間を指定します。1つのステップを複数のロックで共有できます。たとえば、画像ロックと音声ロックの両方が最初に実行する *言語モデルを解放* ステップを1つだけ作る、といった使い方です。**テスト**を押すと、すぐにリクエストを送ります。 |

次の場所でロックを選びます。

- [AIの設定](../inference-providers.md)（言語モデル用の一般設定にある **GPU ロック**）
- [画像ジェネレーター](../extensions/image-generator.md#one-gpu-for-the-model-and-the-images)のバックエンド
- [オーディオブック](../extensions/audiobook-server.md#one-gpu-for-the-model-and-the-speech)のバックエンド

**GPU ロック**欄は、ロックが1つ以上存在する場合にのみ表示されます。

<a id="how-the-turns-work"></a>

## 順番の仕組み

- モデルへのすべてのリクエスト、すべての画像、すべてのオーディオブックのバッチやサンプルは、その AI またはバックエンドのロックを**その処理の間ずっと**取得します。
- GPUにそのロックがすでに読み込まれていれば、ジョブはすぐに始まり、どのステップも実行されません。
- 別のロックが読み込まれている場合、ジョブはそのロックのジョブが終わるまで待ちます。その後、そのロックの解放ステップがすべて実行されます（一部が失敗しても全部実行されます）。続いて新しいロックの取得ステップを順に実行します（最初の失敗で中断し、ジョブはそのステップのメッセージとともに失敗します）。
- 解放ステップが失敗した場合、新しいロックは読み込まれません（カードがまだ埋まっているかもしれないためです）。ジョブはエラーで失敗し、GPUは元のロックのまま残ります。別のロックの次のジョブが、再び解放を試みます。
- ジョブの後もGPUは**読み込まれたまま**です。ロックがタイマーで解放されることはありません。開いたまま、折りたたまれた、または閉じられた画像ウィンドウはGPUを保持しませんが、画像モデルは言語モデル（または別のロック）がカードを必要とするまで読み込まれたままです。
- ジョブは到着順に待ちます。あるジョブが別のロックを待ち始めると、読み込まれているロックの新しいジョブはその後ろで待ちます。そのため、忙しい言語モデルが画像を永久に待たせ続けることはありません。
- ロックがない AI やバックエンド、または削除されたロックを指定しているものは、何も待ちません。

GPUに何が載っているかは、アプリケーションが動いている間だけ分かります。再起動後は何も読み込まれていないものとして扱われ、最初のジョブは取得ステップだけを実行します。

<a id="the-tab"></a>

## タブ

このタブには、各GPUの現在のロック（まだ何も実行されていない、または解放された場合は *Unknown*）と、そのGPUで実行中・待機中のジョブ数が一覧表示されます。続いて、ロックとステップが並び、それぞれに追加、編集、削除のボタンがあります。**更新**を押すと、GPUが保持しているものを再度読み取ります。

**今すぐ解放**は、GPUを手動で解放します。たとえば、Marginalia の外でカードを使いたいときに使えます。実行中のジョブの終了を待ち、読み込まれているロックの解放ステップを実行して、GPUの状態を不明のままにします（ステップが失敗した場合も同様で、メッセージにどのステップが失敗したかが表示されます）。次のジョブは、そのロックを再び読み込みます。

GPUを削除するとそのロックも削除されます。ステップを削除すると、それを実行していたロックから外れます。削除されたロックを指定していた AI やバックエンドは、ロックなしで動作します。

<a id="an-example-one-card-three-models"></a>

## 例：1枚のカードに3つのモデル

`llama-server` を LiteLLM の後ろに置き、コンテナの起動と停止を行う [`tools/gpu-control`](../extensions/audiobook-server.md#what-answers-those-addresses) 形式のプロキシを使う場合を考えます。

| ステップ | リクエスト |
|---|---|
| 言語モデルを解放 | ヘッダー `X-Llama-Unload: all` を付けた `POST http://litellm:4000/v1/chat/completions`（[別のモデルのためにGPUを解放する](../prompt-cache.md#freeing-the-gpu-for-another-model)を参照） |
| ComfyUIを起動 / ComfyUIを停止 | `POST http://litellm:4000/gpu/comfy/start` / `.../stop` |
| Speechを起動 / Speechを停止 | `POST http://litellm:4000/gpu/tts/start` / `.../stop` |

| ロック | 取得ステップ | 解放ステップ | 同時ジョブ数 |
|---|---|---|---|
| 言語モデル | （なし：次のリクエストでルーターが読み込む） | （なし） | 0 |
| ComfyUI | 言語モデルを解放、ComfyUIを起動 | ComfyUIを停止 | 1 |
| Speech | 言語モデルを解放、Speechを起動 | Speechを停止 | 1 |

言語モデルの AI には *言語モデル* のロックを、画像バックエンドには *ComfyUI* を、音声バックエンドには *Speech* を選びます。チャットの後に音声のバッチを実行すると、*言語モデルを解放* と *Speechを起動* が実行されます。次のチャットメッセージでは、先に *Speechを停止* が実行されます。
