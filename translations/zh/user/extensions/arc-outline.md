# 剧情大纲

侧边栏中的书籍规划：剧情弧（arc）各自分为若干章节，每一项都带有状态，还有一个可以为你撰写剧情弧和章节的模型。大纲不属于故事提示词的一部分；生成器和[侧边查询](side-query.md)可以在你要求时使用它。

<a id="the-arcs-tab"></a>

## Arcs 标签页

[故事编辑器](../books/story-editor.md)的左侧边栏会在 *Outline* 旁边多出一个 **Arcs** 标签页。点击 **Add new arc** 会打开剧情弧的对话框：

| Field | |
|---|---|
| Title | 必填。 |
| Description | 剧情内容。 |
| Note (private) | 给自己看的笔记。 |
| State | **Planned**、**Current** 或 **Finished**。 |
| Linked part | 剧情弧或章节所属的故事段落，见[下文](#linking-to-the-story)。 |

章节的字段与此相同。列表中每个剧情弧显示为一张卡片，其章节缩进排列在下方。卡片的颜色随其状态变化：计划中为灰色，当前的为蓝色，已完成的为绿色，标题变暗。卡片上的按钮：

| Button | |
|---|---|
| 日历 / 播放 / 对勾 | 状态；打开菜单以更改状态。 |
| 折叠箭头（剧情弧） | 隐藏或显示该剧情弧的章节。 |
| 折叠箭头（带备注的章节） | 显示或隐藏章节描述下方的备注，无需打开对话框即可阅读。 |
| 箭头 | 将剧情弧或章节上移或下移。 |
| 加号（剧情弧） | 在该剧情弧末尾添加一个章节。 |
| 魔杖（剧情弧） | 请模型为该剧情弧撰写章节，见[下文](#generating-chapters)。 |
| 靶心（已关联段落的剧情弧和章节） | 将故事滚动到其关联的段落。 |
| 钢笔 | 在对话框中打开它。 |
| 垃圾桶 | 删除它（连同其所有章节的剧情弧），需先确认。 |
| 机器人（生成的剧情弧和章节） | 显示模型撰写的内容，见[下文](#generating-an-arc)。 |

顶部魔杖旁边是一支带羽毛的钢笔：它会根据当前章节起草下一轮的指令，见[下文](#drafting-the-instructions-for-the-current-chapter)。

![Arcs 标签页：一个已完成、一个当前和一个计划中的剧情弧](../../images/plugin-arcoutline-tab.png)

<a id="linking-to-the-story"></a>

### 关联到故事

剧情弧或章节可以**关联到故事的某个段落**，这样你就能从规划直接跳转到正文中的对应位置。对话框中有 **Linked part** 字段：即活动分支中该段落的位置，编号从 1 开始，与 *Outline* 标签页中显示的一致（`#12`）。输入编号，或按其旁边的 **link** 按钮，即可取当前在故事中**最可见**的段落（先滚动到该位置，再打开对话框）；**target** 按钮会将故事滚动到字段中的段落。已关联的剧情弧或章节，其卡片上也会有 target 按钮。关联记录的是分支中的位置，因此当前面的段落被删除或插入时，它会指向另一段落；届时请进行修改。从故事导入时，会自动为章节建立关联，见[下文](#importing-an-arc-from-the-story)。

<a id="the-note-of-a-chapter"></a>

### 章节的备注

带有备注的章节，其右侧会显示一个折叠箭头。点击它会在列表中展开描述下方的备注，这样即使不打开对话框，你也能阅读章节的细节（例如模型为其撰写的内容）；再次点击即可隐藏备注。哪些备注处于展开状态不会被保存。

![显示备注的章节](../../images/plugin-arcoutline-note.png)

<a id="moving-chapters-between-arcs"></a>

### 在剧情弧之间移动章节

从所在剧情弧的第一位上移的章节，会被移到上一个剧情弧的末尾；从最后一位下移的章节，会被移到下一个剧情弧的开头。持续点击箭头，即可将章节移到任意所需的位置。

<a id="drafting-the-instructions-for-the-current-chapter"></a>

### 为当前章节起草指令

*Add new arc* 旁边带羽毛的钢笔会打开一个窗口，让模型[起草](../books/story-editor.md#drafting-the-instructions)下一轮的指令；其中以故事所处章节的数据作为 **Plan of the Story**。当前章节是第一个标记为 **Current** 的章节；若没有，则是第一个未标记为 **Finished** 的章节；已标记为当前但尚无章节的剧情弧单独成立。模型会获得该剧情弧和章节及其描述和备注，以及其后一章的标题和描述（不含备注），并附带警告：故事尚不应到达那里。窗口会以你在新一轮面板的 *Instructions* 中输入的内容作为指导开始；点击 **Use as Instructions** 会将草稿放入该面板并打开它。若没有当前章节，按钮会提示这一点。

同一数据也可作为[侧边查询](side-query.md)的来源，见[下文](#the-outline-as-a-source-for-other-extensions)。

<a id="finishing-an-arc"></a>

### 完成剧情弧

将剧情弧标记为 **Finished**，会同时把其所有章节也标记为 **Finished**。将剧情弧改为其他状态时，其章节保持不变。

大纲在你每次修改后都会立即随书籍保存，因此也包含在书籍的备份中。

<a id="the-outline-as-a-source-for-other-extensions"></a>

## 将大纲作为其他扩展的数据来源

大纲可作为书籍数据提供给其他扩展：在[侧边查询](side-query.md)的插件弹出面板中勾选 **Arc outline**，即可随问题一同发送剧情弧、其状态、描述和章节。提供两个版本：**Arc outline** 为精简版（仅描述），**Arc outline (with notes)** 会在每个剧情弧和章节的描述下方加入其备注，生成的剧情弧和章节的细节正是在这里。只有勾选第二项时，你的私密笔记才会被发送。第三个来源 **Arc outline: current chapter** 仅发送故事所处的剧情弧和章节（见[为当前章节起草指令](#drafting-the-instructions-for-the-current-chapter)）。

<a id="generating-an-arc"></a>

## 生成剧情弧

**Add new arc** 旁边的魔杖按钮会打开一个包含三项的菜单：**Generate an arc** 请模型撰写一个新剧情弧，**Import from story** 会总结你已写好的内容（见[下文](#importing-an-arc-from-the-story)），**Develop the plot** 则是与模型就故事走向进行的对话（见[下文](#developing-the-plot-in-a-conversation)）。

![魔杖菜单](../../images/plugin-arcoutline-menu.png)

 **Generate an arc** 的对话框分为两部分。

左侧：

| | |
|---|---|
| Prompt | 给模型的指令，包含三个变量：`{{backgroundLore}}`（书籍的世界书及其子世界书中的条目）、`{{existingArcs}}`（你的剧情弧和章节，含其状态和描述，但不含你的私密笔记）以及 `{{specification}}`。初始内容来自 *Settings → Extension Settings → Arc Outline* 中的提示词（若你未修改过，则为默认提示词）；你在此处的编辑仅对本次生成有效。 |
| Specification | 对剧情弧的要求：主题、角色、应走向何处。可留空。 |
| Tools | 仅在安装了[面向模型的工具](tools.md)套件（人名、地点）时出现：选择模型可以使用哪些套件及其类别，以代替凭空杜撰，与[世界书生成器](lore-generator.md)中的相同。 |
| Model, Protocols | 书籍的模型和协议作为初始值（若书籍未设置，则使用你在 *Settings* 中的默认值）。修改它们可仅为本次生成使用其他模型；该选择不会被保存。 |
| Generate | 启动模型。运行期间，按钮变为红色的 **Stop**，对话框中的其他内容全部禁用。 |

右侧会显示模型撰写时的 **reasoning**（推理过程）；回答一开始，它所提议的 **arc**（剧情弧）——包括名称、简要描述和较长的备注——便会以大纲中剧情弧的样式显示（备注位于描述下方），并随回答的流式输出逐渐完整。描述会显示在大纲中，因此要求模型将其控制在两句左右，并把细节写入备注；备注最终会成为保存后剧情弧的 **Note**。模型完成后，其回答会被检查；若不是有效的剧情弧（例如缺少备注），对话框会提示，且无法保存该剧情弧。

![生成剧情弧](../../images/plugin-arcoutline-generate-arc.png)

**Save as arc** 会将剧情弧添加到大纲末尾。若要重试，请再次点击 **Generate**，提示词或要求可保持不变，也可修改；之前的回答会被替换。
<a id="importing-an-arc-from-the-story"></a>

## 导入故事中的弧线

在魔杖菜单中选择**从故事导入**，模型会阅读你故事的一部分，并将其整理为一个弧线及其章节，这样你就可以把已经写好的书引入大纲。模型总是读取书籍的[当前分支](../books/branches-and-story-tree.md)，即你打开对话框时的状态。该对话框与弧线的对话框相似，左侧有以下选项：

| | |
|---|---|
| 从消息、到消息 | 要发送的故事范围。分支中有文本的消息从 1 开始编号；起初选中整个分支。每个字段下方都会显示它所指向消息的开头部分。 |
| 章节数量（可选） | 选择一个数字即可得到恰好那么多的章节（返回其他数量的回答会被拒绝）；留空则让模型在故事自然划分之处进行切分。 |
| 将章节链接到故事的各部分 | 初始为开启。发送范围内的消息从 1 开始编号，模型会说明每个章节从哪条消息开始；该章节会[链接](#linking-to-the-story)到故事的对应部分（按整个分支的编号计算，因此无论范围如何都是正确的），弧线则链接到其第一个章节开始的部分。若回答中提到了未被发送的消息，则该章节不会被链接。 |
| 导入弧线及其章节的状态 | 起初为**已完成**，因为故事已经写好；如有需要，可选择**当前**或**计划中**。 |
| 令牌计数器 | 范围内有多少条消息及其大约令牌数，以及整个提示（指令、背景设定、大纲和故事）的大约令牌数，并与模型可接收的上限并列显示。当提示超出容量时会显示警告，此时请选择更少的消息。它会随范围、章节数量、提示和模型而变化。 |
| 提示 | 给模型的指令，包含变量 `{{backgroundLore}}`、`{{existingArcs}}`、`{{story}}`（范围内的消息）和 `{{numberOfChapters}}`。它初始内容来自*设置 → 扩展设置 → Arc Outline* 中的**故事导入提示**。 |

![从故事导入弧线](../../images/plugin-arcoutline-import.png)

这里没有工具，名称都来自故事本身。右侧会显示推理过程，然后是模型生成的弧线及其章节。点击**保存为弧线**会将该弧线及其章节添加到大纲末尾；每个章节都保留模型的推理和回答，并拥有自己的机器人按钮。较长的故事最好分几步导入，每个范围导入为一个弧线。
<a id="developing-the-plot-in-a-conversation"></a>

## 在对话中发展情节

菜单中的 **Develop the plot** 魔杖按钮会打开一个与模型讨论情节的对话。聊天本身不会改变书中的任何内容：模型只看到你选择发送的内容并作出回答，当你们达成一致后，点击一下即可把结果交给弧线生成器。

左侧是你选择模型能看到什么、以及它如何提供帮助（这些选择会被记住，供下次使用），右侧是聊天区：

![情节向导：左侧是选项，右侧是对话](../../images/plugin-arcoutline-wizard.png)

| | |
|---|---|
| Model, Protocols | 默认使用本书的模型和协议。更改它们只对本次对话生效。 |
| How the model helps | **Free talk**（由你主导）、**Explore directions**（故事接下来可以走的几种不同方向）、**Find the problems**（从未解决的线索、无人兑现的承诺、与设定的矛盾、节奏问题）或 **Expand an idea**（把你的想法扩展成前提、转折点、结局，以及在你的弧线之后可以接续的章节）。 |
| Send the lorebook | 本书的设定集及其子设定集中的条目。 |
| Send the outline | **Not sent**（不发送）、**Descriptions only**（仅发送描述）或 **With the notes**（包括你的私人笔记）。 |
| Send the notes | 仅当安装了 [故事笔记](story-notes.md) 时可用：**Not sent**（不发送）、**Titles and first lines**（仅标题和首行，默认）或 **Full text**（全文），但不包括你对助手隐藏的页面。 |
| Send the summaries of the story | 摘要代替故事内容，覆盖到最新的那条摘要为止，与生成时发送摘要的方式相同。 |
| Send the latest parts of the story | 最新摘要之后的故事段落（若关闭摘要，则为全部段落），取最新的、且不超过 **Tokens of the story** 的部分。每个段落在故事大纲中的编号也会一并展示给模型。 |
| Tokens of the story | 故事段落所用的最大 token 数。留空时为模型可接收量的三分之一。 |
| Prompt | 给模型的指令，可使用变量 `{{backgroundLore}}`、`{{outline}}`、`{{notes}}`、`{{summaries}}`、`{{story}}` 和 `{{mode}}`。修改后会被记住。 |

选项下方有一行文字，说明模型会收到多少条摘要和故事段落，以及该请求中模型所需的 token 数。如果内容超出限制，这行文字会变成警告；此时请减少发送内容，或[对聊天进行摘要](#chats-branches-and-summaries)。每条消息发送时都会重新读取全书，因此你对大纲或故事的修改会在下一次回答中生效。

右侧是聊天区。输入消息后按 **Send** 发送（模型生成回答时按钮变为 **Stop**；已收到的内容会被保留）。每条消息都有若干按钮：复制、**branch from here**（从此处分支）、删除；对于模型的回答，还有一个魔杖按钮 **Generate an arc from this message**（以此消息生成弧线），点击后会打开弧线生成器，并将该消息作为规格说明。如果讨论较长，可以先让模型把你们的决定总结成一份规格说明。

<a id="letting-the-model-change-the-book"></a>

### 让模型修改书籍

选项下方是 **What the model may do**（模型可以做什么）。如果一个都不勾选，聊天就只是单纯的对话。勾选某一组后，模型就会获得相应的工具，并可以在你要求或同意时使用这些工具；它会被告知先查看再添加、优先添加而非替换，并说明它做了什么：

| 分组 | 模型可以 |
|---|---|
| **Planner** | 列出[规划器](../books/story-editor.md#the-planner-tab)中的场景，添加、修改、移动、删除它们，并将其标记为已完成。 |
| **Lorebook** | 搜索和阅读设定，创建条目并修改现有条目（不能删除）。 |
| **Outline** | 阅读大纲，添加弧线和章节，修改和移动它们（不能删除）。 |
| **Notes**（安装了[故事笔记](story-notes.md)时）| 搜索和阅读你的笔记并跟随其中的链接；在你要求它记录某些内容时新增页面或向已有页面添加内容；修改某页中的文字（不能删除页面）。你对助手隐藏的页面无法访问。 |
| **Generators** | 调用弧线和章节生成器；安装了 [Lore Generator](lore-generator.md) 时，还可以生成设定条目。它们只返回草稿，除非模型被明确告知，否则不会保存任何内容；模型会把草稿展示给你，待你同意后再保存。 |
| **Tools**（按钮，安装了[工具套件](tools.md)时出现）| 名称类工具（人名、地名），与生成器一样，使模型能够为你提供真实的名字。 |

- **Ask me before it changes or deletes something**（修改或删除前先询问我）（默认开启）：修改已有内容（设定条目、场景、弧线的文字）和删除操作，会先展示给你，包括模型想要传递的内容，模型会等待你点击 **Allow** 或 **Refuse**。添加场景、条目或弧线则不需要询问：你可以在聊天、规划器、设定集或大纲中看到它们，并且可以删除。
- 模型调用过的每个工具都会列在其回答下方（一行，包含名称和标记：✓ 表示成功，✗ 表示失败；展开可以查看传入了什么、返回了什么）。之后的消息会携带模型之前的调用及其返回结果（过长的结果会被截断），因此它知道自己已经做过什么，不会重复创建同样的条目；这些内容同样计入聊天的 token 上限。
- 工具的成本：它们的描述会包含在每次请求中，因此上下文空间紧张的模型可用的余量会更少。只有支持函数调用的模型才能使用此功能；如果某个模型不支持，对话框会提示。

![模型向规划器添加了两个场景；它的调用记录列在回答下方](../../images/plugin-arcoutline-wizard-tools.png)

<a id="chats-branches-and-summaries"></a>

### 聊天、分支与摘要

一本书可以有任意多个聊天；在消息上方的列表中选择一个，**+** 新建一个聊天，铅笔图标用于重命名（在此之前，聊天以你的第一条消息命名），垃圾桶图标用于删除。聊天与书一同保存。

- **Branch**（分支）会把当前聊天原样复制为一个新聊天；消息上的分支按钮则复制到该消息为止（包括该消息），以便从那里换一种方式继续讨论。之后，副本与原聊天互不相关。
- **Summarize the chat**（总结聊天）会先询问摘要应保留或强调什么（可选，例如"保留关于叛徒的转折和我们否决过的结局"；留空则由模型决定），然后请模型对聊天进行总结（你做出的决定、否决的方案、仍未解决的问题、已确定的名字），并将摘要作为一条消息添加进去。此后，模型只会收到该摘要及其之后的消息，**不会**收到摘要之前的消息；这些旧消息仍保留在屏幕上，但会变暗。当聊天变得太长、模型难以处理时，或者想在不丢失决定的前提下重新开始时，就可以使用它。之后再次总结时，新摘要会涵盖旧摘要的内容。如果希望模型保留完整的聊天记录，请先使用分支。

![询问摘要应保留什么内容](../../images/plugin-arcoutline-wizard-summarize.png)

![摘要之后的聊天：摘要之前的消息仍保留在屏幕上，但变暗](../../images/plugin-arcoutline-wizard-summary.png)
<a id="generating-chapters"></a>

## 生成章节

弧线上的魔杖按钮会请模型把该弧线划分为若干章节。对话框与弧线的对话框类似，左侧有以下选项：

| | |
|---|---|
| 模型对故事的了解 | **截至目前的整个故事**：直到本弧线为止的所有弧线，包括其全部章节。**仅弧线摘要**：同样的弧线，但不含章节。**弧线摘要与已完成章节**：同样的弧线，仅包含你标记为*已完成*的章节。此弧线之后的弧线永远不会发送。 |
| 你对章节的总体要求 | 节奏、基调、必须发生的事。可以留空。 |
| 章节数量 | 用文字填写（如"大约八章"），或选择一个确切数字。填写数字后，每个章节会出现一个文本框，可以说明该章应包含的内容；所有文本框均可选填。两者只能使用其一，填写其中一个会清空另一个。若指定了确切数字，模型返回的章节数不同时将被拒绝。 |
| 提示词 | 给模型的指令，可使用变量 `{{backgroundLore}}`、`{{outline}}`、`{{numberOfChapters}}`、`{{generalSpecification}}` 和 `{{chapterSpecification}}`。初始内容来自 *设置 → 扩展设置 → Arc Outline* 中的**章节生成提示词**。 |

右侧先显示推理过程，然后是该弧线已有的章节，以及模型逐步写出的新章节。点击**保存为章节**即可将其添加到弧线末尾，每个章节都有一个简要描述，详细内容写在备注中（与弧线相同）。每个新章节都保留模型的推理过程和回答，并带有自己的机器人按钮。

![生成弧线的章节](../../images/plugin-arcoutline-generate-chapters.png)

由模型编写的弧线或章节会保留其**推理过程**和生成它的**回答**。其上的机器人按钮会在一个小弹出框中打开它们，不占据主要界面。

## 命令

大纲及其生成器同时也是[命令](../commands/index.md)，可用于命令行和[代理](../agents.md)。它们作用于当前打开的书籍（代理则作用于其工作副本），打开的弧线选项卡会立即显示变更。弧线和章节通过**编号**指定，编号与大纲中显示的一致：第一条弧线为 `1`，某弧线的第一章为 `1`（若前面的内容被添加、删除或移动，编号会随之变化）。修改弧线或章节的命令只接受你提供的字段；空文本会清除描述或备注。

| 命令 | 作用 |
|---|---|
| `/get-arc-outline [arc [notes]]` | 以 JSON 形式返回弧线及其章节、状态和描述。仅当 `notes` 为 `true` 时返回私人备注；`arc` 则只返回该弧线。只读。 |
| `/add-arc title [description [note [state [position]]]]` | 添加一条弧线，默认添加到末尾，或添加到 `position` 指定的位置。 |
| `/update-arc arc [title [description [note [state]]]]` | 修改一条弧线。`state` 可为 `PLANNED`、`CURRENT` 或 `FINISHED`（完成弧线会同时完成其章节）。 |
| `/move-arc arc position` | 将弧线移动到 `position` 指定的位置（1 为第一位）。 |
| `/delete-arc arc` | 删除一条弧线及其章节，需先确认。 |
| `/add-outline-chapter arc title [description [note [state [position]]]]` | 为某弧线添加一章。 |
| `/update-outline-chapter arc chapter [title [description [note [state]]]]` | 修改一章。 |
| `/move-outline-chapter arc chapter position [to_arc]` | 在其所属弧线内移动章节，或将其移动到弧线 `to_arc` 中。 |
| `/delete-outline-chapter arc chapter` | 删除一章，需先确认。 |
| `/generate-arc [specification [save]]` | 请模型生成一条新弧线，与*生成弧线*功能相同。 |
| `/generate-outline-chapters arc [specification [count [context [save]]]]` | 请模型为某弧线生成章节，与该弧线上的魔杖功能相同。`count` 为确切的章节数；`context` 为 `EVERYTHING`（默认）、`ARCS_ONLY` 或 `ARCS_AND_FINISHED`，对应*模型对故事的了解*的各选项。 |
| `/import-arc-from-story [from [to [count [state [save [mapParts]]]]]]` | 请模型将当前活动分支中从 `from` 到 `to` 的消息（按含文本的消息编号，与*从故事导入*相同）概括为一条带章节的弧线。`state`（默认为 `FINISHED`）为保存的弧线及其章节的状态。当 `mapParts` 为 `true` 时，每个章节都会链接到其开始所在的消息（即其*关联片段*，与对话框中的*映射片段*复选框相同），回答中会给出每个章节的片段。 |

三个生成命令使用与对话框相同的提示词（即你在*扩展设置 → Arc Outline* 中的设置，或默认值）、书籍所使用的模型和协议（若书籍未指定模型，则使用你的默认模型），且不使用任何工具。若调用者需要人名，应先通过[人名生成器](name-generator.md)或[人名提供者](name-provider.md)的命令获取，再将其写入specification中。与对话框一样，这些命令仅在被要求时才保存：`save` 为 `false`（默认）时，它们以 JSON 形式返回弧线或章节，且不保存任何内容；`save` 为 `true` 时，则将其添加到大纲中（弧线添加到末尾，章节添加到该弧线的末尾），回答中会给出它们的编号。故事若对模型而言过长，`/import-arc-from-story` 会拒绝执行，此时请选择较少的消息。生成命令运行需要一段时间，运行被停止时也会随之停止。

添加和修改操作不具破坏性；只有两个 `delete` 命令具有破坏性，代理可以被设置为在执行前向你询问确认。
