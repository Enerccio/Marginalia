# 知識トラッカー

物語の登場人物が知っていることと、**知らない**ことを記録し、それをプロンプトに組み込みます。モデルは、ルールで防がれていない限り、登場人物が会ったことのない人物について（名前、職業、顔など）を知っているかのように振る舞いがちです。知識トラッカーを使うと、プロンプトには場面に登場する追跡対象の人物ごとに、その人物が何を知っていて、それ以外は何も知らないことが書き込まれます。

!!!
追跡する人物を選ぶのはあなたです。タブに追加した登場人物だけがモデルに説明され、しかもその人物が書かれている部分の*登場人物*に含まれている間だけです。物語の本文から推測されることはありません。
!!!

<a id="the-knowledge-tab"></a>

## 知識タブ

[ストーリーエディター](../books/story-editor.md)の左サイドバーには、*アウトライン*の隣に**知識**タブが表示されます。変更内容はすべて、その都度ブックに保存されます。

![知識タブ](../../images/plugin-knowledgetracker.png)

**人物を追跡**を押すと、**名前**と、任意で**別名**の入力を求められます。別名とは、部分の*登場人物*欄でその人物が書かれる別の表記のことで、カンマで区切ります。名前や別名は、一人の追跡対象の人物にしか属せません。

カードの矢印を押して人物を開くと、その人物が知っていることが表示されます。

| | |
|---|---|
| **知っている**（緑）／**知らない**（赤） | 人、場所、秘密、出来事など何についてでも、短い一文で書きます（*ピーターは公爵に対する陰謀について知っている*、*フィオラは、トマスが自分の父親であることを知らない*）。知らないことは明示的に書いてください。モデルはそれを尊重します。 |
| 並び順と **#12** | 新しい知識が上に来ます（古い知識も同様）。モデルが学習した項目には、それを学習した部分の小さな番号（**#12**）が付きます。クリックすると、その部分まで物語がスクロールして点滅します（スマートフォンでは先にドロワーを閉じます）。あなたが書いた項目には番号がなく、現在の分岐にない部分（別の分岐、または削除された部分）に由来する項目にも番号は付きません。 |
| **知識を追加** | 項目を追加し、すぐに有効になります。**ひとつの考え**に絞ってください。二つのことを述べる項目（*トマスが誰かを知らず、会ったこともない*）は、そのどちらかが真でなくなった時点で撤回されます。**編集**ボタンで文章と種類を変更できます。 |
| **撤回**（斜線の入った丸） | その項目はもう真ではありません（トマスと会った後の*トマスには会ったことがない*など）。削除されるわけではなく、*古い知識*になり、モデルには送られなくなります。 |
| **ロック**（南京錠、モデルが学習した項目に表示） | [整理の処理](#tidying-the-knowledge)は、ロックされた項目を一切参照しません。残しておくべきもの、裏切り、秘密などに使ってください。ただし、物語がロックされた項目と矛盾することはあります（記憶を失う人物など）。その場合、物語の読み取りで通常どおり撤回されます。 |
| **削除** | 確認の後、項目を完全に削除します。撤回であれば項目は残るので、迷ったら撤回を使ってください。 |
| **項目を選択**（**知識を追加**の隣） | 多くの項目をすばやく削除できます。古い項目を含め、その人物のすべての項目にチェックボックスが付きます。**すべて選択**／**選択解除**でまとめてチェックを入れたり外したりでき、**選択した項目を削除 (n)** を押すと、確認の後、チェックした項目を完全に削除します。**キャンセル**で選択を解除します。 |
| **会ったことがある人** | その人物が会ったことのある人々で、[処理](#processing)によって記録されます。処理によって、人ではない名前（登場人物欄の注記など）が記録されることもあります。その場合は**編集**を開き、**会ったことがある人**の一覧を、カンマで区切って一つずつ変更します。あなたが書いた名前は、物語を読み直してもそのまま残ります。削除した名前は、それが見られた部分を再度読んだときにのみ戻ってきます。 |
| **古い知識 (n)** | 初期状態では折りたたまれています。古い項目はそれぞれ**コピー**、**編集**、**復元**（再び有効になり、以降はモデルに送られます）、または削除できます。 |

<a id="mass-changes"></a>

### 一括変更

**一括変更**ボタン（**人物を追跡**の隣にあるリストのアイコン）を押すと、追跡対象のすべての人物と、古い項目を含むその人物のすべての項目を、チェックボックス付きの表で表示するウィンドウが開きます。表には、種類、本文、状態（*稼働中*、または古い項目としての*撤回*、*見直しで辞退*、*整理済み*）、由来（*初期状態*、*手入力*、*物語から学習*）、学習元の部分が表示されます。複数の表で好きなだけ項目にチェックを入れられます（表の見出しにあるボックスでその表のすべての項目にチェックが入ります。下部バーの**すべて選択**／**すべて解除**では、すべての人物のすべての項目が対象になります）。その後、次の操作を行えます。

| | |
|---|---|
| **選択した項目を撤回 (n)** | チェックした稼働中の項目を古い知識にします。一つずつ**撤回**するのと同じ動作です。 |
| **選択した項目を復元 (n)** | チェックした古い項目を再び有効にします（以降はモデルに送られます）。 |
| **選択した項目を削除 (n)** | 確認の後、チェックした項目を完全に削除します。 |

ボタンに表示される数は、それぞれの操作がチェックした項目のうち何件に作用するかを示します。変更後もチェックは残るので、撤回した項目をそのまま次に削除できます。

ウィンドウ上部の**JSONに書き出す**は、ブックの追跡対象の人物（名前、別名、種類・状態・由来・ロックを含む項目、会ったことがある人）をファイルとしてダウンロードします。処理に関する情報は含まれないため、どのブックにも移せます。**JSONから読み込む**は、そのようなファイルをブックに読み込み、追加だけを行います。ブックがすでに（名前または別名で）追跡している人物には、まだ持っていない別名、項目、会ったことがある人が追加されます（同じ種類と本文の項目はスキップされます）。それ以外の人物は新しい追跡対象として追加されます。別の人物がすでに持っている別名は除外されます。読み込まれた項目には、このブックの中に対応する部分がないため、再処理で消えることはありません。モデルが学習した項目は手入力扱いになり、古い項目は古いままです。読み込み後のメッセージには、追加または更新された人物の数と、追加された項目の数、およびすでに存在していた項目の数が表示されます。

<a id="what-goes-into-the-prompt"></a>

## プロンプトに含まれる内容

追跡対象の人物のうち、登場人物に含まれる人物ごとに、プロンプトには次のようなブロックが追加されます。

```
What the characters of this scene know. A character acts only on the knowledge listed for it:

Fiora knows: Mara, a courier of the Guild of Lamps and the sister of her friend Nell; she owes the Guild of Lamps forty crowns.
Fiora does not know: that her father is alive, or that Thomas is her father.
Fiora has met: Mara.
Fiora is currently with: Mara, Thomas.
Fiora has never met or heard of anyone else in this story and knows nothing else of its secrets, plans or events.
```

送られるのは稼働中の項目だけです。最後の行（**閉じた世界**の行）は、モデルが人物に持ち得ない知識を与えてしまうのを防ぎます。この行が扱うのは、物語が語るもの（人物、場所、秘密、計画、出来事）であり、その世界の人物なら誰でも知っていることは対象外です。そのため、登場人物は今いる町のことは引き続き知っています。この行は設定でオフにできます。追跡対象の人物が登場していない場合は、「知らない」と書いた行を含め、何も送られません。

<a id="who-is-present"></a>

### 誰が登場しているか

ブロックは、部分の**登場人物**欄の内容から作られます。この欄は自由記述なので、寛容に読み取られます。

- 括弧内の文字は無視されます。`Tomáš (tired), Mizuki` は Tomáš と Mizuki として扱われます。
- 名前は**区切り文字**（既定では `,` `;` 改行、`/`、`|`、`、` `，` `；`）で分けられます。
- ` - ` または `:` の後ろにあるものは注記とみなされ、捨てられます（`Mara - wounded`）。
- 大文字・小文字、アクセント記号、先頭の *the* は区別されません。
- 名前は**完全に**一致する必要があります。*Mara's brother* は *Mara* ではありません。人物が複数の書き方をされる場合は別名を使ってください。一致し損ねると一つのブロックが抜けるだけですが、誤って一致すると場面にいない人物を説明してしまうため、この方針になっています。

*視点人物*欄は単独では読み取られないので、視点人物も登場人物欄に書いてください。
<a id="processing"></a>

## 処理

プラグインは物語の流れに沿って動作します。**Processing** は、有効なブランチの部分を **start point** から順に読み、**cursor**（最後に読んだ部分）を保持します。モデルを使わない場合は、誰が誰と出会ったかを記録します。追跡対象のキャラクターは、現在のキャラクター欄に一緒に書かれているすべての名前と出会ったとみなされ、ブロックにその名前が並びます。モデルを使う場合は、キャラクターが **learned**（学んだこと）も見つけます（[キャラクターが学ぶことを読み取る](#reading-what-the-characters-learn) を参照）。

![処理パネル](../../images/plugin-knowledgetracker-processing.png)

タブの上部にあるパネルで現在の状態を確認できます。新しい部分が確定すると（自動注釈と再下書きがある場合はそのあと）、パネルは自動的に再読み込みされます。部分を別の方法で追加、編集、削除した場合は、歯車の横にある矢印ボタン **更新** を押して、物語を読み直してください。パネルには次のものがあります。

- **Process now**: まだ処理されていない部分を読みます。
- **Process next part**: まだ処理されていない最初の部分だけを一つずつ読みます（モデルを使う場合は、*Parts per run* の設定にかかわらず、その部分へのリクエストが1回だけ送られます）。設定を試したり、一つの部分についてモデルが何を見つけるかを確認したりするのに使います。`parts` を 1 に設定したコマンド `knowledge-process` も同じ動作をします。
- **Start point**: 処理を開始する部分です（デフォルトは *Start of the book*）。それより前の部分は一切読まれません。開始位置を前に戻すと、新しい開始位置から部分を読み直します。後ろに進めると、すでに読んだ分はそのまま残ります。
- **Processed parts**: 読まれた最新の部分の一覧です。**処理後にテキストが変更された**部分（編集または再下書きされた部分）には印が付きます。ただし、それを理由に自動的に再処理されることはありません。各行のボタン **Reprocess from here** は、その部分以降に由来するものを取り消し（手で入力した項目や取り消しはそのまま残ります）、改めて読み直します。

**Process new parts automatically** がオンのとき（デフォルトではオフ）、プラグインは次のことを自動的に行います。

- 生成が始まる前に、前回以降に書かれた部分を処理するので、プロンプトが誰が誰と出会ったかを把握できます。*再生成* やスワイプで置き換えられている部分はそのまま残されます。モデルを使う場合、モデルで読み取るのは **Ask before applying** がオフのときだけです。それ以外の場合は、誰が誰と出会ったかを記録するだけで、モデルが見つけたことはタブから開始します。生成の途中で確認を強いられることはないようにするためです。
- 部分が**再生成**され、新しいテキストが届くと、古いテキストから学んだことは取り消されます。
- **スワイプ**したり別のブランチに切り替えたりすると、カーソルは両方のブランチが共有する最後の部分に戻ります。
<a id="reading-what-the-characters-learn"></a>

## 登場人物が知ったことを読み取る

設定で **Read what the characters learn with the model** にチェックを入れます。すると **Process now** により、これから先の story の parts について、追跡対象の各キャラクターが何を **learned** したか（見た、聞いた、読んだ、伝えられた）を、モデルに尋ねます。また、story が **contradicts** している項目（例：*has never met Thomas* なのに、その後出会っている）も示されます。リクエストには、parts（その視点とその場にいる登場人物を含む）、各追跡キャラクターが今知っていること、そして選択に応じて lorebook が含まれます。モデルには、その世界の人物が元から知っていること（王が誰か）や、キャラクター自身から当然導かれること（サキュバスは尻尾があることを知っている）は除外し、確信がないことは報告しないよう指示されます。どの part にも登場しない追跡キャラクターについては、尋ねられません。

どの実行も、モデルへの 1 回のリクエストです。**Process now** が 3 回を超えるリクエストを必要とする場合（未処理の長い story の区間があるとき、または **Parts per run** が低く設定されているとき）、まず part とリクエストの数、そしておおよそどれだけのテキストがモデルを通るかを表示し、確認されてから開始します。各リクエストには指示文、lorebook、キャラクターの知識も含まれるため、実際のコストはテキストだけの分より高くなります。

**Ask before applying** がオフのときは、変更がすぐに適用され、それぞれの変更が **Applied automatically**（タブの Processing セクション）のログに、誰が何を得た、または失った、どの part から、という形で記録されます。ログは編集できませんが、どの行にも **Revert** ボタンがあります。追加された項目は取り消され（レビューでの却下と同様に *Old knowledge* に残ります）、撤回された項目は再び有効になります。その後に手で項目を編集・削除・撤回した行は、そのままになります。ログは直近 200 件の変更を保持します。

**Ask before applying** がオフのときは、新しい part が確定するとすぐに読み取られます。生成が終わったとき、または本に自動注釈（と再草稿）や翻訳が有効になっている場合はその処理が終わったときです。これにより、モデルはあなたが読んでいる間に作業できます。これは [what follows the part](../books/story-editor.md#what-follows-a-generated-part) の一段階です。次の生成では知識が最新の状態になっており、待たされません。残ったもの（途中で止めた実行、閉じたウィンドウ）は、次の生成の前にこれまでどおり読み取られます。

モデルが作業している間、ページの上に小さな **progress panel** が浮かびます。これは **not modal** なので、story を読んだり編集したりし続けられます。タイトルを掴んで **drag** することもできます。閉じると非表示になりますが、作業は続きます（**Cancel** で停止します）。

![The progress panel](../../images/plugin-knowledgetracker-progress.png)

モデルが回答している間、パネルには **What the model is writing** がその場で表示されます。まず推論、次に回答の順です。そのため、遅いモデルでの長い待ち時間も、空白のバーにはなりません。リクエストが終わると、同じテキストが **What the model thought** の下に残ります（実行中のリクエストごとにブロックがあり、何と答えたかが入ります）。何も提案されず、レビューも開かなかった場合でも同様です。タブには **Last run: what the model thought** というボタンが残るので、パネルを再び開いて、何も追加されなかった理由を確認できます。

モデルの回答が終わると、パネルにその旨が表示され、**Review changes** が示されます。同じボタンは、タブの処理パネルにもあります（*3 changes to review*）。**レビューが自動で開くことはありません。** レビューは、キャラクターごとにまとめられた変更の表です。

![Reviewing the changes](../../images/plugin-knowledgetracker-review.png)

表の下の **What the model thought**（最初は閉じています）には、モデルが回答より前に返してきた推論が入ります（送ってきた場合のみ）。なぜその変更が提案されたのか、あるいは期待した変更がなぜないのかが示されるので、適用する前に判断できます。推論をしないモデルでは、ここには何も表示されません。

| | |
|---|---|
| チェックボックス | 変更を適用するかどうか。最初はすべてチェックされています。各キャラクターには **Check all** / **Uncheck all** があります。 |
| **Retract** / **Add** | 撤回すると、その項目は古い項目になります（残ります。[the tab](#the-knowledge-tab) を参照）。追加は新しい項目で、*Knows* または *Does not know* です。追加の文言と種類は、適用する前に **edited** できます。 |
| 引用 | その事実を示す part の文言と、それがどの part にあるか。その part に見つからない引用には印が付きます。モデルが作り出した可能性があるので、受け入れる前に確認してください。 |

**Apply** は、チェックされた変更を適用して次に進みます。**Cancel** は、シリーズ全体を止めて何も変更しません。次回は同じ parts が再び提案されます。チェックを外した追加は、引用とともに **kept as old knowledge** になります（後で元に戻せます）。チェックを外した撤回は、項目をそのままにします。モデルが言ったもののうち使えなかったもの（尋ねていないキャラクター、そこにない項目、引用のない変更、そのキャラクターがすでに知っていること）は、*Left out* に一覧されます。適用された変更は、その part を持ち続けるので、**Reprocess from here** で再び取り消せます。レビュー中に story が変わった場合（別の分岐、part の削除など）、変更は適用されず、もう一度処理し直す必要があります。

parts は **runs** として、**Parts per run**（既定は 1）ずつ読まれます。モデルのコンテキストに収まらないものは、収まる分だけに切り詰められます。シリーズは、最後の確定した part まで、実行を重ねて続きます。確認を求めるシリーズでは、モデルが何も見つけなかった実行は、確認せずに飛ばされます。**Ask before applying** がオフのときは、変更がすぐに適用され、パネルには実行ごとに 1 行のログが残ります。

!!!
このプロンプトは、限られた数の場面でモデルに対してテストされたもので、広く検証されてはいません。登場人物が、知覚していないことを知ってしまわないようにはしますが、提案された内容、特に長い場面にいるキャラクターについては確認してください。リクエストは、下で選んだモデルに送られ、そのサービスの通常のコストとプライバシーが適用されます。
!!!

<a id="tidying-the-knowledge"></a>

## 知識を整理する

モデルは、各キャラクターが知ったことを書き留めます。長い story では一覧が増え、リクエストのたびにモデルへ送るには小さなことが多くなりすぎます。**Tidy knowledge**（**Process now** の隣にあり、モデルの設定が必要です）は、モデルに、キャラクターの知識を読み直すよう求めます。その際、story の最後に処理された parts を文脈として添えます。そして次のことを行います。

- 残す価値のない項目を **drop** する：些細なこと、そのシーンにいた全員が見ている場面の詳細（story 側に記録されている）、後の出来事に追い越されたもの、他の項目と同じことを言っているもの。
- 同じことに関する複数の項目を一つに **merge** する。ただし、すべての事実は残す。

削除または統合された項目は消えるわけではありません。*Old knowledge* になり、元に戻せます。変更は、読み取りの場合と同様にレビューされます（**Ask before applying** が決めます）。または、すぐに適用されて、**Revert** ボタン付きでログに記録されます。

整理の対象になるのは、モデルが学んだことのうち、あなたが **lock** していないものだけです。最初の項目、あなたが手で追加または編集した項目、ロックされた項目、古い項目は、決して変更されません（最初の二種類とロックされた項目は、モデルがそれを重複とみなせるように見せられます）。長い間どの part にも出てこない秘密は、削除の理由にはなりません。プロンプトもそう述べています。モデルが迷う場合は、その項目を残します。モデルが学んだ項目が **Tidy: from this many items**（8）個未満のキャラクターは、整理されません。**Tidy: parts of context**（10）は、読み取る処理済みの最後の part の数です。

**Tidy automatically**（設定、既定ではオフ）は、確認なしで適用される変更の実行の終わりに、整理を自動で行います（**Ask before applying** がオフなので、新しい part の自動読み取りも含みます）。最後の整理以降、モデルが **Tidy after this many parts**（10）個の part を読んだ後に実行されます。その変更は適用され、**Revert** ボタン付きでログに記録され、実行のログにもその旨が書かれます。レビューする実行が自動で整理を始めることはなく、項目が少なすぎるキャラクターは、モデルに尋ねずに飛ばされます。

コマンドバーからも同じことができます。`knowledge-tidy`（`ask true` を付けると、変更が一覧で返され、開いているタブにはレビュー用のボタンが表示されます）、そして `lock-knowledge` / `unlock-knowledge` でキャラクターと項目の番号を指定します。
<a id="settings"></a>

## 設定

*Track a character* の横にある歯車：

| 設定 | |
|---|---|
| **In prompt** | すべての生成のプロンプトにブロックを挿入します。オンのあいだ、ボタンは緑になります。 |
| **Depth** | プロンプトの末尾から数えたメッセージ数で、挿入位置を指定します。`0` はターンの指示の後、`1` はその直前です。システムプロンプトより前に入ることはありません。 |
| **Role** | *System*、*Assistant*、*User* のいずれのメッセージとして送るかを指定します。 |
| **Say that nothing else is known** | 「ほかのことは知られていない」という閉じた世界の一文です。 |
| **Give what the characters know to the annotation** | オン（既定）の場合、[AI で注釈を付ける](#annotating-with-what-the-characters-know)は、そのパートの開始時点で追跡対象のキャラクターが知っていたことを受け取ります。 |
| **Process new parts automatically** | [処理](#processing)を参照してください。 |
| **Read what the characters learn with the model** | 処理時に、追跡対象の各キャラクターが何を学んだかをモデルに尋ね、その提案を出します。オフ（既定）の場合、処理は誰が誰と会ったかを記録するだけで、費用はかかりません。 |
| **Ask before applying** | オン（既定）の場合、すべての提案がレビューのために表示されます。オフの場合、提案は直ちに適用され、記録されます。 |
| **Let the model read earlier parts** | 新しいパートを読む間、モデルは項目が学ばれたパート（項目には「パート 12 で学んだ」と書かれます）を読むことができます。読んだ内容が項目を確認するか、繰り返すか、矛盾するかを確かめるためです。たとえば、伝聞だったものを自分の目で確かめられるようになる、といった場合です。1 回のリクエストで 1 つのパートを読む回数は最大 5 回までで、長いパートのテキストはコンテキストに収まる分だけに切り詰められます。レビューには、読んだパートが表示されます。読み取りのたびにモデルへの往復が 1 回増えるため、既定ではオフです。関数を呼び出せないモデルは、従来どおりリクエストを読みます。 |
| **Parts per run** | 1 回のリクエストで読むパートの数です。大きいほど安上がりですが、回答が長くなり、レビューも難しくなります。 |
| **Tidy automatically**, **Tidy after this many parts** | 整理パスは、確認なしで変更を適用する実行の終わりに、このパート数ごと（10）に自動的に実行されます。既定ではオフです。 |
| **Tidy: parts of context** | 整理パスが読む、直近に処理されたパートの数です（10）。 |
| **Tidy: from this many items** | モデルが学んだ項目（かつロックされていない項目）がこの数より少ないキャラクターは、整理されません（8）。 |
| **Lorebook for the model** | *Entries the parts activate*（既定：これらのパートで生成が使うエントリ）、*The whole lorebook*（すべてのエントリ。コンテキストに収まらない場合は、有効化されたエントリだけを送り、その旨をメモに記します）、または *No lorebook* のいずれかです。 |
| **Model / Protocol for the extraction** | 空欄の場合は、その本のモデルを使います。この処理にはより安価なモデルで十分であり、プロンプトキャッシュを 1 つしか持たないサーバーでは、別のモデルを使うことで、そのキャッシュが置き換えられるのを防げます。 |
| **Separators of this book** | 登場人物の欄を名前ごとに分割する方法です（1 行に 1 つ。改行は `\n` で表します）。`and` のような語は空白で分割されるため、*Jack and Jill* は、区切り文字を追加するまで 1 つの名前のままです。 |
| **My separators (all books)** | すべての本に共通する設定です。本固有の区切り文字が優先され、どちらも設定されていない場合は組み込みの区切り文字が使われます。 |

<a id="prompts"></a>

## プロンプト

読み取りのシステムメッセージ（**Knowledge extraction prompt**）と整理パスのシステムメッセージ（**Knowledge tidy prompt**）は、[継承される設定](../books/prompts.md#inherited-settings)です。本は自身の設定を使い、なければ上位の最も近いフォルダで設定されたものを使い、それもなければ自分の設定、さらにそれもなければ実際のモデルで検証された組み込みのテキストを使います。

本の *Prompts* タブ、*Extension Settings* の下、フォルダのダイアログで設定するか、*Settings → Extension Settings → Knowledge Tracker* ですべての本に対して設定します（空欄の場合は、組み込みのテキストを灰色で表示します）。組み込みのテキストの JSON 回答形式は維持してください。プラグインは、その形式で回答を読み取ります。`read_part` の指示は、モデルが以前のパートを読んでもよい場合にプラグインが追加するため、独自のプロンプトに記述する必要はありません。

<a id="annotating-with-what-the-characters-know"></a>

## 注釈で、キャラクターが知っていることを使う

上の表示ブロックは、モデルが*書いている最中に*キャラクターを全知にしてしまうのを防ぎます。同じ記録は、それでも混入してしまった矛盾を見つけるのにも役立ちます。モデルが[パートに注釈を付ける](../books/annotations.md#letting-a-model-annotate)（**AI で注釈を付ける**、パートの範囲指定、自動注釈、`/generate-annotation`）とき、トラッカーは、追跡対象のキャラクターがそのパートの**開始時点で**知っていたことをモデルに伝えます。エディターは、知りえないことを言い、考え、行うキャラクターに注意を促します。たとえば *Fiora greets Thomas by name; the records say she has never met him.*（Fiora は Thomas を名前で呼んでいるが、記録では彼女は彼に会ったことがない）のように、その根拠となる事実を示します。

- **事実は、本の末尾ではなく、そのパートの時点のものです。** キャラクターが後のパートで学んだことは、まだ知られていないものとして扱います。後のパートで撤回される項目は、そのパートの時点ではまだ真でした。パート自身がもたらすこと（学ぶこと、会うこと、そのパートの中で成り立たなくなること）は別に示されるため、パートの前半が後半と混同されてチェックされることはありません。
- **対象のキャラクター。** 追跡対象のキャラクターのうち、そのパートの *Present Characters* にいる者、そのパートの視点人物である者、またはそのパートの本文で名前が挙がっている者です（単語全体、大文字小文字は問わず、別名も含みます）。
- **どの時点でも事実ではない項目**は除外されます。手動で撤回した項目、整理パスが削除した項目、レビューで却下した項目がこれにあたります。
- **記録されているものだけ。** モデルには、記録に書かれていないことは事実ではないと伝えられるため、トラッカーがまったく把握していないことについて、キャラクターを誤って指摘することはありません。*Say that nothing else is known* は、キャラクターが会った相手の欄に「(nobody else)」も加えます。
- レビュー対象のパートより前のパートが、トラッカーによって読み取られていない場合、その事実にはそのことが示されます。そのパートでキャラクターが学んだことが欠けており、先に **Process now** を実行すると、より良いレビューができます。
- 事実は、追跡対象のキャラクターがいるパートについてのみ、注釈のリクエストでトークンを消費します。**Give what the characters know to the annotation** をオフにすると、この機能を無効にできます。

<a id="the-block-as-a-macro"></a>

## ブロックをマクロとして使う

自動挿入の代わりに（または加えて）、[{%{`{{command::knowledge-tracker-block::<characters>}}`}%} マクロ](../templates/macros.md#commands)でブロックを自分で配置できます。引数はシーンの登場人物のリストなので、テンプレートでパートの登場人物欄を渡せます。

```
{%{{{command::knowledge-tracker-block::{{presentCharacters}}}}}%}
```

このマクロは、**In prompt** がオンかどうかに関係なくブロックを出力します。そのため、マクロを使うときはそれをオフにしてください。さもないと、モデルはブロックを二度受け取ります。深さとロールはマクロには適用されません（ブロックは、マクロを含むメッセージの一部になるためです）。リストされたキャラクターのいずれも追跡されていない場合は、何も出力しません。コマンドマクロの回答は、新しいパートが続く元のパートとともに保存されるため、同じパートからの 2 回目の生成では、そのあいだに行った変更は反映されません。再生成とスワイプでは、改めて問い合わせが行われます。

<a id="commands"></a>

## コマンド

[コマンドライン](../commands/index.md)とエージェント向け：

| コマンド | |
|---|---|
| `knowledge-status` | 設定と、処理の進行状況を示します。 |
| `list-tracked-characters`, `add-tracked-character`, `update-tracked-character`, `delete-tracked-character` | 追跡対象のキャラクターです。名前、別名、または番号で指定します。 |
| `list-knowledge`, `add-knowledge`, `retract-knowledge`, `restore-knowledge`, `delete-knowledge` | キャラクターの項目です。`list-knowledge` に表示される番号で指定します。 |
| `knowledge-process` | 今すぐ処理します（`parts`：その数まで）。モデルがオンの場合、`ask true` は、モデルが見つけた変更を番号付きで返し、保留します。まだ何も変更されません。開いている Knowledge タブには **changes found by a command** ボタンが表示され、通常のレビュー（Apply / Cancel）が開きます。エージェントは `apply-knowledge-changes` で適用します。 |
| `apply-knowledge-changes` | 保留中の変更をすべて、または指定した番号のものを適用します（タブのレビューにある **Apply** と同じです）。 |
| `knowledge-tidy` | 整理パスです。`ask true` を付けると、変更を番号付きリストで返し、保留します（タブにはそれを確認するボタンが表示され、`apply-knowledge-changes` で適用できます）。 |
| `lock-knowledge`, `unlock-knowledge` | 項目（キャラクター、項目番号）をロックして、整理パスがそれに手を加えないようにします。またはロックを解除します。 |
| `knowledge-reprocess` | 指定したパート（そのハンドルまたは位置）から再処理します。事前に確認を求めます。モデルがオンの場合、これは状態を戻すだけで、パートを読み直すのは `knowledge-process` です。 |
| `knowledge-set-start` | 開始地点を設定します。パートを指定しなければ、本の冒頭になります。 |
| `knowledge-tracker-block` | マクロ用に、ブロックをテキストとして出力します。 |

コマンドラインは、引数をスペースで区切ります。キャラクターのリストは引用符で囲んでください（`/knowledge-tracker-block "Fiora, Mara"`）。

## 保存
