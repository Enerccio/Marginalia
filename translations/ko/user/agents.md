# 에이전트 (실험적)

!!!warning 실험적 기능
에이전트는 1.4.0에서 새로 추가되었으며, 실제 모델과 함께 쓰인 경험이 많지 않습니다. 거친 부분이 있을 것으로 예상하세요. 성능이 낮은 모델이 도구 호출을 잘못하거나, 생각보다 많은 토큰이 들거나, 검토 화면이 필요 이상으로 번거롭거나, 버전에 따라 동작이 바뀔 수 있습니다. 책은 보호됩니다(에이전트는 사본에서 작업하고, 결과는 검토한 뒤에 적용하기 전에 백업이 만들어집니다). 하지만 **에이전트의 결과를 넘겨받기 전에는 반드시 직접 책을 백업해 두고**, 토큰 예산을 설정하고, 처음 몇 번의 실행은 [콘솔](#the-console)에서 지켜보세요. 무엇이 잘못되었는지 알려 주시면 감사하겠습니다.
!!!

**에이전트**는 여러분의 책 하나를 맡아 오랜 시간 스스로 작업하는 모델입니다. 허용된 [명령](commands/index.md)을 도구로 호출하면서, 이야기를 읽고, 로어북과 대조해 확인하고, 그 결과를 보고합니다. **에이전트** 탭에서 에이전트를 만들고, 각 에이전트가 할 수 있는 일을 정하고, 실행을 시작하거나 중지하고, [콘솔](#the-console)에서 대화하고, 복제할 수 있습니다.

**시작**을 누르면 에이전트가 백그라운드에서 한 라운드씩 작업합니다. 허용한 명령과 자체 파일 도구를 호출하면서, 작업을 마치거나, 질문을 하거나, 한계에 도달하거나, 여러분이 일시 정지 또는 중지할 때까지 계속합니다([실행 과정](#a-run) 참고). 에이전트는 책의 숨겨진 [사본](#the-working-copy)에서 작업하므로, 작업하는 동안 원본 책은 전혀 건드려지지 않습니다(책 자체는 [잠깁니다](#the-book-is-locked)). 작업이 끝나면 [결과를 검토](#reviewing-the-result)하고 원하는 부분만 넘겨받으면 됩니다.

이 탭은 관리자가 **에이전트** [권한](administration/permissions.md)을 준 경우에만 보입니다. 관리자는 항상 이 권한을 가지지만, 제한은 다른 모든 사용자와 같습니다. 관리자가 자신의 권한 설정을 직접 채우지 않으면 기본값이 적용되므로, 더 많은 에이전트, 실행, 작업 공간 용량이 필요한 관리자는 그곳에서 설정해야 합니다. 바뀐 제한은 일시 정지되었다가 재개되는 실행부터 적용됩니다. 휴대폰에서는 각 에이전트가 같은 버튼이 있는 카드로 보입니다. [휴대폰에서](#on-a-phone)를 참고하세요.

<a id="the-table"></a>

## 표

| 열 | |
|---|---|
| **에이전트 ID** | 에이전트의 식별자입니다. |
| **이름** | 여러분이 붙인 이름입니다. |
| **책** | 에이전트가 작업하는 책입니다. |
| **상태** | 실행이 무엇을 하고 있는지 나타냅니다: *실행 중*, *사용자를 기다리는 중*, *승인을 기다리는 중*, *일시 정지 중*, *일시 정지됨*, *중지 중*, *중지됨, 결과 유지*, *완료, 검토 대기 중*, *적용됨*. 실행이 없는 에이전트는 *실행 중 아님*으로 표시되며, 꺼져 있으면 *비활성화됨*으로 표시됩니다. |
| **마지막 실행** | 에이전트의 가장 최근 실행이 시작된 시각입니다. 실행이 한 번도 없었던 에이전트는 *없음*으로 표시됩니다. |

![에이전트 탭](../images/agents-tab.png)

표 위에 있는 두 입력란으로 목록을 좁힐 수 있습니다. **이름**과 **책** 입력란에는 입력한 단어들을 모두 포함하는 에이전트만 나타납니다. 단어의 순서와 대소문자는 상관없으며, **책**의 경우 책 이름에 포함되어도 됩니다. **이름**, **책**, **상태**, **마지막 실행** 머리글을 누르면 표가 정렬됩니다(다시 누르면 역순이 됩니다. 마지막 실행 기준 오름차순일 때는 한 번도 실행하지 않은 에이전트가 먼저 나옵니다). 휴대폰에서는 카드 위의 **정렬 기준** 선택기로 이름, 상태, 또는 최신 실행 순으로 정렬할 수 있습니다.

행 끝의 버튼은 실행 상태에 따라 달라집니다.

| 버튼 | |
|---|---|
| **시작** | 메뉴를 엽니다. **즉시 시작**: 에이전트가 자신의 작업(지시 사항)을 혼자 수행하고, 질문하거나 끝났을 때 알려 줍니다. **콘솔에서 시작**: [콘솔](#the-console)을 열고, 에이전트에게 지금 작업하지 말고 원하는 것이 무엇인지 즉시 물어보라고 지시합니다. 이 경우 실행은 **완료**를 누를 때까지 이어지는 [대화](#a-run)가 됩니다. |
| **재개** | 일시 정지되었거나 중지된 실행을 이어서 진행합니다(**시작** 대신 표시됩니다). 에이전트에게 전할 메모를 선택적으로 입력하라고 묻습니다. [실행 재개](#resuming-a-run)를 참고하세요. |
| **일시 정지** | 작업하거나 여러분을 기다리는 실행을 일시 정지합니다. |
| **지금 일시 정지** | 에이전트가 작업하는 동안 표시됩니다. 라운드가 끝나기를 기다리지 않고 즉시 일시 정지합니다. [일시 정지와 중지](#a-run)를 참고하세요. |
| **콘솔** | 에이전트의 [콘솔](#the-console)을 엽니다. |
| **중지** | 결과를 **유지할지**(나중에 실행을 재개할 수 있습니다) 또는 **삭제할지** 묻습니다. |
| **편집** | 에이전트를 엽니다. |
| **복제** | 에이전트를 복사합니다. [복제](#cloning)를 참고하세요. |
| **삭제** | 에이전트를 실행 기록과 함께 [휴지통](trash.md)으로 옮깁니다. |

에이전트가 비활성화되어 있거나, 모델이 없거나, 동시에 작업할 수 있는 실행 수를 모두 사용 중이면 이유와 함께 시작이 거부됩니다.

![시작 버튼의 메뉴](../images/agent-start-menu.png)

에이전트는 끝나지 않은 실행을 최대 하나만 가질 수 있으며, 책 하나에는 에이전트가 최대 하나만 연결됩니다.
<a id="a-run"></a>

## 실행

실행은 에이전트의 작업 단위입니다. 실행은 라운드 단위로 진행됩니다. 모델에 한 번 요청하면 모델은 텍스트를 답하거나 도구를 호출하거나 둘 다 합니다. 그 결과가 다시 모델에 전달되고, 이 과정이 반복됩니다.
모든 라운드는 저장되므로, 실행은 일시 정지했다가 나중에 이어서 진행할 수 있습니다. 서버를 재시작한 뒤에도 가능합니다. 에이전트는 사용자가 허용한 명령과 아래의 자체 도구를 사용할 수 있습니다:

| 도구 | |
|---|---|
| 파일 | 에이전트 자체 작업 공간(실행 사이에 유지되는 메모)에서 `list_files`, `read_file`, `write_file`, `append_file`, `replace_in_file`, `regex_replace_in_file`, `grep_files`, `move_file`, `copy_file`, `merge_files`, `unzip_file`, `delete_file`을 사용합니다. 작업 공간 옆에는 읽기 전용 파일 `/AGENTS.md`가 있습니다. 이 파일에는 실행을 시작할 때 사용자가 준 지침이 들어 있으며, 에이전트는 언제든 다시 읽을 수 있지만 바꿀 수는 없습니다. `list_files`와 `grep_files`는 이름 패턴을 받습니다(예: `glob`, `*.md` 또는 `chapters/*.md`). `copy_file`는 폴더 전체를 통째로 복사합니다(메모의 버전을 간단히 보관하는 방법입니다). `merge_files`는 여러 파일을 텍스트가 모델을 거치지 않고 하나로 합칩니다(경로의 마지막 이름은 `/chapters/*.md` 같은 패턴일 수 있습니다). `unzip_file`는 작업 공간의 [zip 파일](#unpacking-a-zip-file)을 새 폴더에 풀어 줍니다. `replace_in_file`와 `regex_replace_in_file`도 경로로 **폴더**를 받아, 그 아래 모든 텍스트 파일에서 등장하는 부분을 전부 바꿉니다(이름이 `glob`와 맞는 파일만, 지정된 경우에 한해서입니다). 파일마다 `path: n replacements` 항목으로 결과를 보고합니다. 에이전트가 `dry_run` false를 넘기지 않으면 **시험 실행**(dry run)이 되어, 아무것도 기록하지 않고 보고서에 무엇이 바뀔지만 나타냅니다. 이 명령은 전부 적용되거나 전혀 적용되지 않습니다(파일 하나라도 기록할 수 없으면 아무것도 바뀌지 않습니다). 바뀔 파일이 `max_files`개(에이전트가 더 많이 지정하지 않는 한 100개)를 넘으면 아무것도 바꾸지 않고 거부합니다. 단일 파일에도 시험 실행을 쓸 수 있습니다. `list_command_results`와 `save_command_result`는 명령의 긴 결과를 에이전트가 다시 쓰지 않고도 보관합니다. 최근 결과 열 개는 전체가 보관되고(에이전트는 긴 결과를 잘린 채로 봅니다), 결과 하나를 번호로 지정하면 파일로 저장할 수 있습니다. 번호를 지정하지 않으면 가장 최근 결과를 저장합니다. 이때 에이전트는 파일을 `@file:/path`로 넘깁니다. |
| `@file:/path` | 도구가 아니라 도구를 호출하는 방식입니다. 명령의 텍스트 인자가 정확히 `@file:/notes/chapter.md`이면, 에이전트 작업 공간의 해당 파일 내용으로 바뀝니다. 이렇게 하면 에이전트는 긴 글을 파일에 한 번 쓰고 검토한 뒤 명령에 넘길 수 있습니다(결과에는 호출 부분의 짧은 참조가 보이고, 명령은 실제 텍스트를 받습니다). `write_file`와 `append_file`도 내용 인자로 이 방식을 받습니다. 그래서 파일을 복사하거나 다른 파일에 덧붙일 수 있습니다. 긴 파일은 모델의 가장 긴 답변 한도 안에 들어가는 조각으로 나눠 쓴 뒤, 이 방식으로 합칠 수 있습니다. |
| `@result` | `@file:`와 같은 방식이지만 명령의 결과에 적용됩니다. 텍스트 인자가 정확히 `@result`이면 에이전트가 마지막으로 호출한 명령의 결과 전체로 바뀝니다. `@result:3`이면 해당 번호의 결과로 바뀝니다(번호는 `list_command_results`로 확인할 수 있습니다). 생성된 텍스트는 명령에서 다음 명령으로, 또는 `write_file`와 `append_file`로 에이전트가 직접 다시 쓰지 않고도 전달됩니다. |
| `search_manual`, `read_manual_page` | Marginalia 사용자 매뉴얼(도움 어시스턴트가 읽는 것과 같은 페이지)에서 무언가를 찾아봅니다. 예를 들어 프롬프트 템플릿이나 매크로가 어떻게 동작하는지, 로어북 설정이 무엇을 하는지 확인할 수 있습니다. 읽기 전용이며, 모든 에이전트가 가지고 있습니다. |
| `view_image` | 작업 공간의 이미지 파일(PNG, JPEG, GIF 또는 WebP)을 봅니다. 그림은 다음 메시지에서 모델에 보입니다. 모델이 이미지를 볼 수 있는 것으로 표시된 에이전트(에이전트 설정의 **모델이 이미지를 볼 수 있음**)만 이 도구를 가집니다. 큰 이미지는 보내기 전에 축소되며, GIF는 첫 프레임만 보입니다. 모델 앞에 남는 이미지는 최근 네 개뿐입니다(더 오래된 이미지는 메모로 바뀌며, 에이전트는 다시 볼 수 있습니다). 이미지는 사용자가 제공합니다(**파일 업로드**, 또는 [메시지에 첨부된](#the-console) 이미지). 에이전트는 이미지를 만들 수 없습니다. |
| 명령용 이미지 | [`generate-lore-entry`](extensions/lore-generator.md#commands)처럼 자체 모델로 그림을 보내는 명령은 `images` 매개변수를 받습니다. 이는 작업 공간 이미지 파일 경로의 목록입니다(최대 8개). 이미지를 보아야 하는 것은 에이전트의 모델이 아니라 명령의 모델입니다. 따라서 에이전트의 모델이 이미지를 볼 수 없더라도 에이전트는 이미지를 넘길 수 있습니다. |
| `update_plan` | 할 일 목록입니다. |
| `report` | 사용자를 위한 발견 사항입니다(무엇을, 어디서, 얼마나 심각하게 발견했는지 표시합니다: *메모*, *경고* 또는 *문제*). 에이전트는 이를 기록한 뒤 계속 진행합니다. 사용자는 발견 사항을 최종 보고서와 별도로 [콘솔](#the-console)과 [검토](#reviewing-the-result)에서 읽습니다. 호출 한 번에 발견 사항 하나이며, 실행 하나당 최대 200개입니다. |
| `get_run_status` | 사용한 라운드와 토큰 수, 컨텍스트 사용량, 쓸 수 있는 가장 긴 답변의 길이, 계획, 하위 에이전트를 보여 줍니다. 하위 에이전트는 각각 한 줄로 표시되며, 상태, 라운드, 토큰, 마지막 작업 내용, 맡은 과제가 나옵니다. 에이전트는 프롬프트에서 모델의 이러한 한도도 전달받으므로, 긴 글을 여러 부분으로 나누어 씁니다. |
| `checkpoint`, `checkpoint_list`, `checkpoint_diff`, `checkpoint_restore`, `checkpoint_delete` | [체크포인트](#checkpoints)입니다. 작업 복사본과 작업 공간의 복원 지점을 (이름표와 함께) 저장하고, 목록을 보고, 특정 지점 이후 무엇이 바뀌었는지 보여 줍니다. 바뀐 내용에는 설정, 부분, 로어북, 책의 항목 중 추가되거나 변경되거나 삭제된 것과 작업 공간의 파일이 포함됩니다. 경로를 지정하면 그 파일이나 폴더만 보여 주며, 텍스트 파일이면 다른 문장을 보여 줍니다. 특정 지점으로 되돌릴 수도 있습니다(라운드가 끝난 뒤에 적용됩니다). 필요 없는 지점은 삭제할 수 있습니다. |
| `get_sync_report` | 사용자의 변경 사항을 가져온 재개 뒤에만 쓸 수 있습니다. 실행이 일시 정지된 동안 책에서 사용자가 바꾼 내용과, 그중 에이전트의 복사본에 반영된 내용을 다시 나열합니다. [실행 재개하기](#resuming-a-run)를 보십시오. |
| `request_compaction` | 에이전트 자신의 컨텍스트를 압축합니다. 라운드가 끝나면 `/compact`와 같이 이전 작업의 요약을 씁니다. 에이전트는 먼저 메모를 파일에 저장하도록 지시받습니다. [컨텍스트가 가득 참](#running-a-command-yourself)을 보십시오. |
| `ask_user` | 사용자에게 하는 질문입니다. 실행은 기다립니다(*사용자를 기다리는 중*). |
| `finish` | 에이전트의 보고서입니다. 실행은 *완료* 상태가 됩니다. 보고서는 상태의 이유로 표시됩니다. |

실행이 작업의 한 단계를 끝내는 방식은 다음과 같습니다:

- **사용자를 기다리는 중:** 에이전트가 도구 호출 없이 답했거나 사용자에게 질문했습니다. [콘솔](#the-console)에서 답하십시오.
- **완료:** 에이전트가 `finish`를 호출했습니다(*즉시* 시작한 실행에서). *콘솔에서* 시작한 실행은 대화입니다. 에이전트의 보고서는 질문처럼 사용자에게 전달되고, 실행은 사용자의 다음 메시지를 기다립니다. 콘솔의 **완료**(또는 **중지**)를 눌러야만 끝납니다. *완료* 상태 실행의 결과는 사용자의 [검토](#reviewing-the-result)를 기다립니다.
- **일시 정지됨**(이유와 함께): 라운드 한도, 토큰 예산 또는 컨텍스트 한도에 도달했거나, 모델에 요청할 수 없었습니다(제공자의 오류, AI 사용 한도 등). 또는 서버가 재시작되었습니다. **재개**를 누르면 마지막으로 완료된 라운드부터 이어집니다. [서버가 중지될 때](#when-the-server-stops)를 보십시오.
- **Failed:** 실행기 자체가 고장 났습니다. 이유에 원인이 적혀 있습니다.

**일시 정지**는 두 라운드 사이에 적용됩니다. 모델 요청과 진행 중인 호출이 먼저 끝납니다. 모델이 느리거나 생성이 길면 시간이 오래 걸릴 수 있으므로 **지금 일시 정지**가 있습니다. 이는 모델에 대한 요청을 취소하며, 그 답은 버립니다. 진행 중이던 호출과, 아직 이루어지지 않은 라운드의 호출에는 취소되었다는 응답을 줍니다. 그러면 실행은 곧 *일시 정지됨* 상태가 됩니다. 버려진 요청이 들인 비용은 사라집니다. 평소처럼 재개하십시오. **중지**도 같은 일을 하지만, 요청이나 진행 중인 호출을 기다리지 않습니다. 이것들은 즉시 취소되고 실행은 바로 끝납니다(사용자가 고른 대로 결과를 보관하거나 버립니다).

![실행이 중지될 때의 질문](../images/agent-stop.png)

진행 중인 명령은 중단하라는 신호를 받습니다. 중단되도록 작성된 명령(모델로 쓰거나, 검색 및 바꾸기를 하는 명령)은 즉시 끝나며, 그때까지 한 작업은 그대로 남습니다. 중단할 수 없는 명령은 끝까지 실행될 수도 있습니다. 어느 경우든 에이전트에게는 호출이 수행되었는지 알 수 없다고 알려 주며, 다시 진행할 때 읽기 명령으로 상태를 확인하게 됩니다. 일시 정지, 중지 또는 즉시 메시지를 받았을 때 하위 에이전트의 명령도 같은 방식으로 취소됩니다.

에이전트가 모델의 빈 자리를 기다리는 동안([모델 하나, 여러 에이전트](#one-model-several-agents)를 보십시오)에는 *실행 중* 상태입니다. **일시 정지** 또는 **중지**를 누르면 그 기다림이 즉시 끝납니다.

## 콘솔

**콘솔**은 에이전트의 최신 실행을 보여 주는 창을 엽니다. 탭은 여덟 개입니다: **실행**, **실행 기록**, **작업 공간**, **체크포인트**, **컨텍스트**, **책 사본**, **하위 에이전트**, **진단**.

![콘솔에서 시작된 실행: 에이전트가 무엇을 할지 묻는다](../images/agent-console-start.png)

**실행** 탭은 *대화 기록*을 보여 줍니다. 사용자가 에이전트에게 한 말, 에이전트가 한 말([Markdown](https://commonmark.org/help/)으로 표시되므로 목록, 제목, 강조가 그대로 보입니다), 그리고 에이전트가 호출한 모든 명령과 파일 도구가 인자와 함께 한 줄로 접혀 나타납니다(클릭하면 인자와 결과를 일반 텍스트로 볼 수 있습니다). 모델이 **추론**(답하기 전에 생각한 내용)을 보내면, 답변 앞에 접힌 *추론* 블록으로 표시되며 다운로드 파일에도 포함됩니다. 추론이 나타나는지는 모델과 서버에 달려 있습니다. 서버가 이를 보고해야 하고, 사용하는 AI에서 추론이 켜져 있어야 합니다. 요청이 진행되는 동안 콘솔은 대화 기록 끝에 *작업 중...* 이라고 표시된 블록에 모델이 지금까지 쓴 내용(추론은 따라가 볼 수 있도록 펼쳐져 있고, 본문도 함께)을 보여 주며, 대기 중인 메시지들은 그 위에 놓입니다. 이 블록은 해당 라운드가 끝나면 실제 블록으로 대체됩니다. 이 블록이 보이는 동안 콘솔은 실행 상태를 2초에 두 번씩 읽고, 그렇지 않으면 2초마다 한 번씩 읽습니다. 이렇게 표시되는 것은 에이전트 자신뿐이며 하위 에이전트는 해당되지 않습니다. 또한 모델이 호출 안에서 쓰는 내용(예를 들어 긴 파일)은 라운드가 끝나야 나타납니다. 모든 메시지의 첫 줄 오른쪽에는 작성된 시각이 표시됩니다(시간만, 다른 날이면 날짜도 함께. 마우스를 올리면 전체 시각이 보입니다). 그래서 에이전트가 얼마나 오래 작업했고 언제 멈췄는지 알 수 있습니다. 실행의 상태, **컨텍스트**(마지막 요청이 모델의 한도에 비해 몇 개의 토큰을 사용했는지, 따라서 실행이 일시 중지에 얼마나 가까운지를 보여 줍니다), 사용한 라운드와 토큰(토큰 예산이 설정되어 있다면 예산도 함께)은 대화 기록이 스크롤되는 동안에도 그 위에 계속 표시되며, 그 아래에는 메시지 입력란이 있습니다. 에이전트가 기다리는 대상은 작성된 자리에 있는 대화 기록 안에 별도의 말풍선으로 나타나며, 실행이 계속되어도 그 자리에 남아 있습니다:

![에이전트가 작업하는 동안의 콘솔: 작성자의 메시지가 대기열에서 기다리고 있다](../images/agent-console-run.png)

- 실행이 *사용자를 기다리는 중*일 때는 **에이전트의 질문**이 표시됩니다. 입력란에 답을 쓰고 **보내기**(또는 **Ctrl+Enter**)를 누르면 에이전트가 계속 진행합니다.
- `finish`을 호출했을 때는 **에이전트 보고서**가 표시됩니다.

![에이전트의 질문과 에이전트가 제안하는 답변들](../images/agent-console-question.png)

![대화가 끝날 때 에이전트의 보고서](../images/agent-console-report.png)

대화 기록 위의 줄에는 실행의 상태와 수치가 표시됩니다: 라운드 수, 상한에 비한 컨텍스트 크기, **응답 제한**(에이전트의 모델이 한 번의 답변에서 쓸 수 있는 최대 토큰 수입니다. 이보다 많은 양이 필요한 호출은 잘리므로, 에이전트는 긴 글을 여러 부분으로 나누어 씁니다), 그리고 총 토큰 수. 에이전트가 계획(`update_plan`)을 세우면, 그 줄에 완료된 단계 수와 전체 단계 수가 표시된 **계획** 버튼(**계획 2/5**)이 나타납니다. 이 버튼을 누르면 단계들이 팝오버에 열리며, 각 단계에는 *완료*, *진행 중*, *할 일* 중 하나를 나타내는 표시가 붙어 있습니다. 에이전트가 발견 사항을 보고하면(`report`), 개수가 표시된 **발견 사항** 버튼(**발견 사항 3**)이 나타나고, 누르면 같은 방식으로 발견 사항이 열리며 각 항목에는 심각도가 함께 표시됩니다. 발견 사항은 실행과 함께 보관되므로, 일시 중지나 재시작 후에도, 기록에서 이전 실행을 볼 때도 그대로 남아 있습니다. 실행의 Markdown 파일(**다운로드**)에는 **발견 사항**이라는 절로 포함됩니다.

![에이전트의 계획](../images/agent-console-plan.png)

![에이전트의 발견 사항](../images/agent-console-findings.png)

대화 실행 중에도 에이전트가 **작업 중**일 때 메시지를 입력할 수 있습니다. 이 메시지는 **대기열**에 들어갑니다. 대화 기록 끝에 점선 말풍선으로 나타나며, 에이전트는 현재 진행 중인 라운드가 끝나는 즉시 이를 읽습니다. 이미 전송된 모델 요청과 에이전트가 한 호출은 먼저 끝나고, 다음 요청에 사용자의 메시지가 이미 포함됩니다(대기 중인 메시지가 여러 개면 함께 한 번에 전달됩니다). 그마저도 기다릴 필요가 없다면, 말풍선에 있는 작은 **지금 보내기**(번개 모양) 버튼을 누르십시오. 그러면 에이전트는 현재 라운드를 중단하고(모델 요청은 취소되고, 사용자의 승인을 기다리던 명령은 거부되며, 실행되지 않은 호출은 건너뜀으로 표시됩니다) 곧바로 사용자의 메시지를 읽습니다. 그 옆의 **휴지통** 버튼은 에이전트가 아직 읽지 않은 동안 메시지를 회수합니다(대기 중인 명령도 같은 방식입니다). 이미 실행된 명령은 그대로 완료 상태로 남습니다. 대기 중인 메시지와 명령은 서버를 재시작해도 유지되며(재개할 때 읽힙니다), *즉시* 시작된 실행처럼 대화가 아닌 실행은 작업 중에는 메시지를 받지 않습니다.
<a id="running-a-command-yourself"></a>

### 명령을 직접 실행하기

트랜스크립트 아래에는 애플리케이션의 명령줄이 있습니다(스토리 탭의 명령줄입니다. `/`을 입력하면 명령 목록과 도움말이 위에 나타납니다). 에이전트에게 실행을 허용한 명령은 `/compact`과 `/clear-workspace`이며, 그 밖에 [에이전트가 호출할 수 있는 명령](#allowed-commands)은 데이터를 읽거나 추가하기만 하는 것들입니다(데이터를 바꾸거나 지우는 명령은 제공되지 않습니다. 이런 명령은 책의 창에서 확인을 요청하게 되는데, 실행 중에는 그런 창이 없기 때문입니다). 명령은 에이전트가 아니라 여러분이 실행합니다. 에이전트에게는 여러분이 명령을 실행했고 그 결과가 무엇이었는지가 여러분의 메시지로 전달됩니다(명령이 작업 공간을 바꾸었다면 에이전트가 앞서 읽은 내용이 오래되었을 수 있다는 점도 함께 전달됩니다). 그래서 에이전트는 실행하지 않은 호출을 했다고 믿는 일이 없습니다. 명령은 메시지처럼 동작합니다. 실행이 대기 중이거나(*사용자를 기다리는 중*) *일시 정지됨* 상태이면 명령은 즉시 실행되고 실행 상태는 그대로 유지됩니다. [대화](#the-console)가 진행 중이면 명령은 대기열에 들어가며, *명령*이라고 표시된 점선 말풍선으로 나타나고, 에이전트의 턴이 끝날 때 실행됩니다(에이전트가 기다렸을 시점입니다. 이 명령 때문에 에이전트가 진행을 멈추지는 않습니다). 말풍선에 있는 작은 **지금 실행** 버튼을 누르면 에이전트가 있는 라운드를 버리고 명령을 바로 실행한 뒤 에이전트가 그 지점부터 계속 진행합니다. 오래 걸리는 명령은 입력창을 점유하므로, 에이전트에게 무언가를 쓰기 전에 명령이 끝나기를 기다리세요.

![작성자의 콘솔에서 실행한 명령: /compact](../images/agent-console-command.png)

**`/compact [what to stress]`**은 컨텍스트를 비웁니다. 에이전트는 지금까지의 모든 내용을 읽고 요약을 작성하도록 요청받습니다(요청받은 내용, 완료한 작업, 찾아낸 내용, 메모와 계획, 막 하려던 일을 담습니다). 이 요약이 모델이 읽는 내용에서 그 이전의 모든 것을 대신합니다. 트랜스크립트에는 여전히 모든 내용이 남아 있고, 요약은 접힌 블록 **이전 작업 요약**으로 표시됩니다. 내보내기에도 이 내용이 그대로 포함됩니다. 명령 뒤에 적은 텍스트가 있다면 요약에서 강조할 내용입니다. 이 요청은 에이전트 자신의 요청이며, 그 토큰은 실행의 토큰으로 계산됩니다. 에이전트에게 던지는 질문은 **압축 프롬프트**입니다. 에이전트에 설정된 것이 있으면 그것을, 없으면 [설정](account.md#templates)에서 정한 기본값을, 그것도 없으면 관리자가 정한 것을, 그것도 없으면 내장 프롬프트를 사용합니다. 컨텍스트가 이미 너무 가득 차서 요청이 들어가지 않으면 가장 오래된 메시지부터 요청에서 빠집니다(요약에 몇 개가 빠졌는지 적힙니다). 컨텍스트가 가득 차기 전에 실행하세요. 사용량 줄에서 얼마나 가까운지 확인할 수 있습니다. 압축 직후에 표시되는 컨텍스트 값은 다음 요청에 들어갈 내용(요약, 시스템 프롬프트, 도구 정의)을 추정한 것이며, 압축 후 모델의 첫 응답이 실제 값으로 이를 대체합니다.

**컨텍스트가 차오를 때.** 모델의 컨텍스트가 상한의 75%를 넘으면 에이전트는 라운드가 끝날 때마다 알림을 받습니다(실행 메시지로, 트랜스크립트에서 볼 수 있습니다). 알림에는 컨텍스트가 얼마나 찼는지, 잃으면 안 되는 내용을 작업 공간의 파일에 저장하고 계획을 갱신한 뒤 `request_compaction`를 호출해야 한다는 내용이 담깁니다. 90%를 넘으면 알림에는 컨텍스트가 가득 차면 실행이 중지된다고 적힙니다. 에이전트가 컨텍스트가 정의에 있는 **압축 기준** 비율(별도로 설정하지 않았다면 90%)을 넘기 전에 압축하지 않으면, 실행이 스스로 압축합니다. 같은 압축이 이루어지며, 요약은 "자동으로 압축됨"으로 시작하고, 에이전트에게는 따로 경고하지 않습니다. 압축이 실패하면 아무것도 바뀌지 않으며, 에이전트에게 그 사실이 알려지고, 실행은 몇 라운드 뒤에 다시 시도합니다. 에이전트가 요청하는 압축도 여러분이 실행하는 것과 같습니다(**압축 프롬프트**를 사용하고, 그 토큰은 실행의 토큰으로 계산됩니다. 자세한 내용은 [에이전트 만들기와 편집하기](#creating-and-editing-an-agent)를 보세요). 실패하면 아무것도 바뀌지 않으며 에이전트에게 알려집니다. 알림이 나오려면 컨텍스트 상한이 설정되어 있어야 합니다. 상한은 에이전트의 상한과 모델의 한도 가운데 가장 낮은 값입니다.

**모델 서버가 읽지 못한 호출.** 모델이 호출 안에 긴 텍스트를 쓸 때 응답이 텍스트 한가운데서 끊길 수 있습니다. 이는 *한 응답*의 한도(프로토콜의 **응답 토큰**이나 AI 쪽의 **최대 완성 토큰**)에 도달했거나, 두 값이 모두 설정되지 않아 서버 기본값이 적용되었거나, 모델이 그냥 멈춘 경우입니다(컨텍스트가 얼마나 가득 찼든 컨텍스트는 다른 한도입니다). 그러면 서버는 불완전한 호출을 거부합니다("Failed to parse tool call arguments as JSON"). 같은 대화로 다시 요청하면 같은 실수가 반복되므로, 실행은 단순히 일시 정지하지 않습니다. 에이전트에게는 트랜스크립트에서 마지막 응답을 사용할 수 없었고 아무것도 실행되지 않았다는 점, 그리고 긴 텍스트는 작업 공간의 파일에 여러 번에 나눠 작은 단계로 쓰라는 점이 알려집니다. 그 뒤 최대 세 번 연속으로 다시 요청합니다. 계속 실패하면 실행이 일시 정지하며, 에이전트에게 알려진 내용은 트랜스크립트에 남으므로, **재개**를 누르면 실패한 질문과 다른 질문이 전달됩니다. 하위 에이전트도 같습니다.

잘렸지만 애플리케이션에는 도달한 호출(호출 결과에 "not valid JSON ... cut off in the middle"이라고 표시됨)은 모델이 쓴 그대로 트랜스크립트에 남아 있어 읽을 수 있습니다. 다만 모델에는 인수를 비운 채로 보내집니다. 서버가 앞선 호출을 다시 읽을 때 그대로 두면 이후의 모든 요청이 거부되어, 되감기 없이는 실행을 계속할 수 없기 때문입니다.

**폭주하는 호출.** 모델은 루프에 빠져, 같은 호출을 한 응답 안에서 수백 번 쓸 수 있습니다. 그러면 결과가 다음 요청 전에 컨텍스트를 채워 버립니다. 실행은 한 응답에서 최대 32개의 호출만 처리하며, 읽기만 하는 호출이 반복되면(같은 응답 안에서 같은 도구에 같은 인수) 한 번만 실행합니다. 빠진 호출은 트랜스크립트에 나타나지 않으며, 에이전트에게는 그 사실을 알리는 알림이 전달됩니다.

**같은 자리를 맴돌기.** 모델은 여러 응답에 걸쳐 같은 일을 반복할 수도 있습니다. 같은 조회(파일 목록, 로어북 목록 등)를 같은 결과로 라운드마다 되풀이하며 진전이 없는 경우입니다. 실행은 이를 감시합니다. 에이전트가 바꾸는 것 없이 조회만 하는 라운드를 이전과 같은 호출, 같은 결과로 반복하면, 세 번째 라운드에서 아무것도 바뀌지 않았다고 알려집니다. 계속하면 다섯 번째에는 한 요청 동안 도구가 회수됩니다. 모델은 무엇을 하고 있었는지, 무엇이 막고 있는지를 일반 텍스트로 답해야 하며, 실행은 그 답을 마지막 메시지로 남긴 채 **일시 정지**합니다. 백 라운드를 더 쓰는 대신 왜 멈춰 있었는지 볼 수 있게 하려는 것입니다. **재개**(또는 메시지 입력)를 하면 도구가 돌아오고 셈도 처음부터 다시 시작합니다. 무언가 바뀐 라운드나 하위 에이전트가 작업 중인 동안의 라운드는 세지 않습니다. 반복하는 하위 에이전트도 같은 방식으로 멈추며, 그 하위 에이전트가 한 말이 실행을 시작한 에이전트에게 돌아가는 답이 됩니다.

**`/clear-workspace [what to keep]`**은 실행의 [작업 공간](#the-working-copy)에 있는 모든 파일과 폴더를 삭제합니다(작업 공간 버튼과 마찬가지로 확인 후 실행됩니다). 그 뒤에 남길 것을 공백으로 구분해 적으세요. 파일, 폴더(안의 모든 내용과 함께), `*.md`이나 `chapters/*.md` 같은 패턴, 또는 공백이 있는 경로는 큰따옴표로 감싸 적습니다(`/clear-workspace /notes.md "/my drafts" *.png`). 남긴 파일 위에 있는 폴더는 유지됩니다. 적은 항목이 없으면 아무것도 삭제되지 않습니다. `/AGENTS.md`과 체크포인트는 작업 공간에 속하지 않으므로 절대 건드리지 않습니다. 에이전트에게는 무엇이 삭제되었고 무엇이 남았는지 알려집니다. 트랜스크립트에서 여러분이 실행한 명령은 명령과 그 응답이 담긴 말풍선으로 나타납니다.

모델이 이미지를 볼 수 있다면(자세한 내용은 [에이전트 만들기와 편집하기](#creating-and-editing-an-agent)를 보세요) **이미지 첨부** 버튼이 **보내기** 옆에 나타납니다. PNG, JPEG, GIF, WebP 파일을 고르거나, 클립보드의 그림을 메시지 입력창에 붙여 넣을 수 있습니다(**Ctrl+V**). 보내기 전까지 그림은 입력창 위에서 기다립니다(×를 누르면 취소됩니다). 한 메시지에는 최대 여덟 개의 이미지를 함께 보낼 수 있으며, 텍스트는 비워 두어도 됩니다. 이미지는 작업 공간의 **uploads** 폴더에 저장됩니다(이름이 이미 쓰이고 있으면 번호가 붙습니다: `map-2.png`). 저장은 작업 공간의 제한과 규칙을 따르며, 모델에는 여러분의 메시지와 함께 이미지가 보입니다. 더 이상 필요 없으면 **작업 공간** 탭에서 삭제하세요.

아래쪽 버튼은 **일시 정지**, **재개**, **중지**이며, 표에 적힌 대로 동작합니다. **완료**는 사용자를 기다리는 실행을 끝냅니다(작업이 끝났다는 뜻으로, *완료됨* 상태가 됩니다).

창은 열려 있는 동안 2초마다 실행 상태를 확인합니다. **새로 고침**을 누르면 즉시 확인합니다. **실행** 탭에는 버려지지 않은 가장 최근 실행이 표시됩니다. 그래서 끝났거나 실패한 실행도 에이전트가 새 실행을 시작하기 전까지는 거기서 읽을 수 있습니다. 더 오래된 실행은 **실행 기록**에 있습니다.

**실행 기록**은 에이전트의 이력입니다. 에이전트가 가졌던 모든 실행이 최신순으로 나타나며, 날짜, 상태, 라운드, 토큰, 결과가 함께 표시됩니다. 눈 아이콘으로 실행을 **실행** 탭에서 열어 단계와 보고서를 다시 읽을 수 있습니다(열어 둔 실행은 다른 실행을 열 때까지 그 탭에 남습니다). 화살표 아이콘으로 실행의 트랜스크립트를 Markdown 파일로 **내려받을** 수 있습니다(무엇이 언제 말해졌는지, 인수와 결과가 있는 모든 명령, 보고서, 하위 에이전트의 대화가 담깁니다). 휴지통 아이콘으로 **삭제**할 수 있습니다. 삭제한 실행은 [휴지통](trash.md)으로 갑니다. 진행 중인 실행은 삭제할 수 없으니 먼저 중지하세요. 중지하고 **버린** 실행도 목록에 있으므로, 무엇을 했는지 읽거나 삭제할 수 있습니다. **실행** 탭은 이런 실행을 직접 열었을 때만 보여줍니다.

![실행 기록 탭](../images/agent-runs.png)

**작업 공간**에는 에이전트의 파일이 표시됩니다. 에이전트는 메모와 보고서를 실행 사이에 보관합니다. 폴더를 누르면 안으로 들어가고(**위로**를 누르면 돌아옵니다), 텍스트 파일을 누르면 내용을 읽을 수 있습니다. 화살표로 파일을 내려받거나 휴지통으로 삭제할 수 있고, **지우기**를 누르면 모든 것이 삭제됩니다(오래된 메모는 새 실행을 잘못 이끌기 때문입니다). **새 폴더**는 열려 있는 폴더 안에 폴더를 만들고, **파일 업로드**는 내 컴퓨터의 파일을 거기에 올립니다. 그래서 에이전트에게 브리프, 문체 안내, 초고를 전달할 수 있습니다. 에이전트가 직접 만든 파일과 같은 규칙이 적용됩니다. 이름에는 `\ < > : " | ? *`, 끝의 점이나 공백을 쓸 수 없고, 너무 길거나 너무 깊으면 안 됩니다. 파일 크기와 파일 수의 제한도 적용됩니다. 업로드하는 파일은 텍스트(UTF-8)여야 합니다. 에이전트는 텍스트만 읽을 수 있기 때문입니다. 또는 이미지(PNG, JPEG, GIF, WebP. 이름이 아니라 파일의 내용으로 인식하며, 최대 5 MB이고, 다른 파일과 마찬가지로 전체 용량과 파일 수에 포함됩니다) 또는 zip 파일(최대 10 MB. 그대로 보관되며, 에이전트가 압축을 풉니다. [아래](#unpacking-a-zip-file)를 보세요)이어야 합니다. 업로드로 기존 파일이 교체되지는 않으니, 먼저 예전 파일을 삭제하세요. 에이전트가 작업하는 동안에는 파일을 바꿀 수 없으니, 먼저 일시 정지하세요. 작업 공간에는 크기, 파일 크기, 파일 수의 제한이 있으며, 관리자가 여러분의 [권한](administration/permissions.md#settings-of-a-permission)에서 설정할 수 있습니다. 표 아래 줄에 얼마나 사용했는지 표시됩니다. 맨 위의 `AGENTS.md` 이름은 에이전트가 보는 여러분의 지침이 차지하고 있습니다(이 파일은 쓰거나 삭제할 수 없습니다).

![작업 공간 탭](../images/agent-console-workspace.png)
<a id="unpacking-a-zip-file"></a>

### zip 파일 풀기

에이전트가 여러 파일을 한꺼번에 다뤄야 할 때, 예를 들어 초고의 여러 장을 다루어야 할 때는 **작업 공간** 탭에서 zip 파일을 업로드하고(**파일 업로드**) 풀어 달라고 요청하십시오. 에이전트에게는 `unzip_file` 도구가 있으며, 이 도구는 `/uploads/draft.zip`의 내용을 새 폴더 `/uploads/draft`에 풀거나(또는 에이전트가 지정받은 폴더에 풉니다. 이 폴더는 아직 존재하지 않아야 합니다) 합니다. 압축 풀기는 전부 성공하거나 전부 실패하며, 압축 파일의 내용은 결코 그대로 신뢰하지 않습니다.

- 텍스트 파일(UTF-8), 이미지(PNG, JPEG, GIF, WebP), zip 파일만 보관합니다. 나머지 항목은 제외되며, 그 이름이 에이전트에게 주는 답변에 적힙니다. 안에 든 zip 파일은 따로 풀지 않고 그대로 저장합니다.
- 파일들은 작업 공간이 수용할 수 있는 크기(전체 용량, 파일 하나의 크기, 파일 개수)에 맞아야 하며, 그렇지 않으면 아무것도 풀리지 않습니다.
- 폴더 바깥(`../x`)으로 벗어나는 항목이 있거나 `/`로 시작하는 항목이 있는 압축 파일은 통째로 거부됩니다. 같은 이름이 두 번 있는 경우(대소문자만 다른 경우 포함), 한 이름이 파일이면서 동시에 폴더인 경우, 항목이 5 000개를 넘는 경우, 암호화되었거나 손상된 경우에도 거부됩니다.
- 압축 폭탄은 거부됩니다. 작업 공간이 담을 수 있는 양보다 많이 풀리거나, 자기 크기의 100배를 넘게 풀리는 압축 파일이 해당합니다.

## 하위 에이전트

에이전트는 작업 하나를 **하위 에이전트**에게 맡길 수 있습니다. 하위 에이전트는 자기만의 대화를 가진 조력자로, 과제 하나를 수행하고 텍스트로 답합니다. 에이전트가 가진 명령과 파일을 쓸 수 있고(또는 [아래](#models-for-sub-agents)에서 설명하는, 그 하위 에이전트가 실행되는 모델이 가진 것을 씁니다), 같은 작업 복사본과 작업 공간에서 일합니다(책에서 바꾼 내용은 그대로 남습니다). 다만 에이전트의 대화는 알지 못하므로, 에이전트는 과제에 필요한 내용을 모두 과제 안에 적어야 합니다. 요점은 하위 에이전트가 읽고 시도하는 내용이 에이전트의 문맥 밖에 머문다는 것입니다. 예를 들어 장 하나를 점검하거나, 이름을 감사하거나, 한 부분을 초안으로 쓰는 일이 이에 해당합니다.

[에이전트](#creating-and-editing-an-agent)에서 **최대 하위 에이전트 수**를 동시에 일할 수 있는 개수로 설정하십시오. 0(기본값)은 하나도 없다는 뜻이며, 이 경우 에이전트에게는 하위 에이전트가 존재한다는 사실조차 알려지지 않습니다.

- **1**로 설정하면 에이전트는 하위 에이전트를 시작하고 그 작업이 끝날 때까지 기다립니다(이를 *대기 중*이라고 합니다). 호출은 하위 에이전트의 답을 반환합니다.
- **2 이상**으로 설정하면 하위 에이전트를 시작하는 호출은 즉시 돌아오고, 에이전트는 계속 일하면서 다른 하위 에이전트를 더 시작하거나, 그 상태를 살펴보거나(`agent_status`), 답을 기다리거나(`await_agent`), 하나를 중지할 수 있습니다(`cancel_agent`). 한도에 닿은 호출은 그중 하나가 끝날 때까지 기다렸다가, 끝난 것의 결과를 반환합니다.

어느 경우든 다음 규칙이 적용됩니다.

- 하위 에이전트는 작업 공간 전체를 **읽을 수 있지만, 쓰기는 자기만의 폴더 하나에서만 할 수 있습니다**. 이 폴더는 `/tmp/sub1`, `/tmp/sub2` … 와 같은 이름으로, 하위 에이전트가 시작될 때 만들어집니다. 같은 이름의 폴더에 이전 실행이 남긴 내용은 삭제됩니다. 하위 에이전트의 답은 `result.md`으로 그 폴더에 저장되므로, 긴 답이 잘린 채 표시되면 에이전트는 이 파일에서 전체를 읽습니다. 이 파일들은 **작업 공간** 탭에서 찾을 수 있으며, 작업 공간 할당량의 일부를 차지하고, 직접 비우기 전까지 남아 있습니다.
- 하위 에이전트는 에이전트의 주 모델에서 실행됩니다. 다만 에이전트가 다른 모델을 요청하면 그 모델에서 실행됩니다. [하위 에이전트용 모델](#models-for-sub-agents)을 보십시오.
- 데이터를 바꾸는 하위 에이전트의 명령은 에이전트의 **파괴적 명령** 설정을 따릅니다. **먼저 묻기**로 설정되어 있으면 같은 [창](#asking-you)에서 사용자에게 묻고, 그 하위 에이전트는 답을 기다립니다(실행을 일시 정지하면 그 요청은 거부됩니다).
- 하위 에이전트는 **하위 에이전트를 시작할 수 없고**, 실행을 끝낼 수 없으며, 사용자에게 물을 수 없고, 체크포인트를 만들 수도 없습니다. 하위 에이전트는 텍스트로 답하면서 끝납니다.
- 모든 것은 **실행 한 번의 공동 예산**에 포함됩니다. 라운드, 토큰, 모델의 한도가 여기에 해당합니다. 한도에 닿은 하위 에이전트는 실패하며 그 사실을 알립니다. 그러면 에이전트도 같은 한도에 닿게 됩니다.
- 모델로 동시에 전송 중인 요청 수는 관리자가 설정해 준 **모델에 동시에 보내는 요청 수**(설정이 없으면 1)에 따릅니다. 이 값이 1이면 에이전트와 그 하위 에이전트가 차례를 나눠 씁니다.
- 책이나 작업 공간을 바꾸는 호출은 누가 하든 한 번에 하나씩 처리되므로, 두 하위 에이전트가 같은 순간에 쓰는 일은 없습니다. 그래도 두 하위 에이전트에게 같은 부분을 바꾸라고 지시하지는 마십시오.
- **실행을 일시 정지하면 하위 에이전트도 함께 일시 정지됩니다.** 하위 에이전트는 다음 안정 지점(두 요청 사이나 두 호출 사이, 즉시 정지하면 바로)에서 멈추며, 그들이 말하고 한 일은 실행과 함께 보관됩니다. 그래서 **재개**를 누르면 멈춘 곳에서 그대로 이어집니다. 하위 에이전트는 대화를 계속하고, 그 결과를 기다리던 에이전트의 호출(`await_agent`, 또는 한도가 1일 때 `spawn_agent`)은 아무 일도 없었던 것처럼 다시 기다립니다. 일시 정지 전에 이미 끝난 하위 에이전트도 여전히 남아 있어서, 에이전트가 그 결과를 물어볼 수 있습니다. 실행을 중지하면서 보관하는 경우도 같습니다. 반면 실행을 버리는 경우, 체크포인트를 복원하는 경우(하위 에이전트가 작업하던 책이 교체됩니다), 그리고 에이전트가 끝나거나 사용자에게 무언가를 묻는 경우에는 하위 에이전트가 영구적으로 끝납니다. 하위 에이전트가 아직 일하는 중인데 에이전트가 자기 차례를 끝내면, 에이전트는 이를 한 번 알려받습니다. 같은 일을 또 하면 하위 에이전트는 중지됩니다.
- 하위 에이전트의 대화는 **실행** 탭에 나타나지 않습니다. 콘솔의 **하위 에이전트** 탭이 이를 보여 줍니다. 위에서 하나를 고르면 에이전트가 무엇을 지시했는지, 그 하위 에이전트가 무엇을 말했는지, 호출한 명령과 그 결과, 그리고 어떻게 끝났는지(낸 답이나 실패 또는 취소의 이유)를 읽을 수 있으며, 이는 실행 기록의 대화와 같은 블록으로 표시됩니다. 작업 중에는 실행을 따라가며 갱신되고, 이전 실행의 하위 에이전트도 보여 줍니다(먼저 **실행 기록** 탭에서 그 실행을 고르십시오). **실행** 탭의 `spawn_agent` 호출에는 그 대화를 여는 **하위 에이전트** 버튼이 있습니다. 에이전트가 되돌아간(되감기) 대화는 흐리게 표시되며 *에이전트가 잊음*이라고 표시됩니다. 실행의 **다운로드**(**실행 기록** 탭에서)에는 하위 에이전트마다 한 구역이 있으며, 그 과제, 상태, 모든 메시지와 호출이 담겨 있습니다.

### 하위 에이전트용 모델

에이전트에는 **주 모델** 하나가 있으며, 이는 대화 상자 위쪽에서 고릅니다. **하위 에이전트용 모델** 아래에 다른 모델을 더할 수 있습니다. 예를 들어 읽기만 하는 저렴한 모델이나, 초안을 쓰는 데 능숙한 모델을 더할 수 있습니다. 각 모델에는 **역할**(이름), **설명**(언제 쓸지. 에이전트가 이를 읽고 고릅니다), AI와 프로토콜, 선택 사항인 **문맥 한도**, 그리고 쓸 수 있는 기능이 있습니다.

![하위 에이전트용 모델](../images/agent-models.png)

- **명령과 도구 사용 가능.** 꺼져 있으면 이 모델에서 실행되는 하위 에이전트는 텍스트로만 답합니다. 명령도 도구도 받지 못합니다.
- **명령 제한.** 꺼져 있으면 이 모델의 하위 에이전트는 에이전트의 명령을 모두 가집니다. 켜면 체크한 명령만 가지며, 그 가운데서도 에이전트에게 허용된 명령만 가집니다(에이전트의 허용 명령이 여전히 상한입니다). 파일용 도구는 명령이 아니므로 모든 하위 에이전트가 가집니다. 주 모델도 같은 설정을 가지며, 이는 주 모델에서 실행되는 하위 에이전트에 적용됩니다(해당 행의 **편집** 버튼).

에이전트에게는 각 모델의 역할, 설명, 명령이 알려지며, 에이전트는 `profile`의 `spawn_agent`을(를) 사용해 그 모델에서 하위 에이전트를 시작합니다. 이 값을 빼면 자기 모델이 쓰입니다. 체크박스 **하위 에이전트가 주 모델에서 실행될 수 있음**(기본적으로 켜짐)을 끄면 이 마지막 선택지가 없어집니다. 그러면 에이전트는 다른 모델을 반드시 지정해야 하며, 지정할 모델이 없으면 하위 에이전트용 도구를 전혀 받지 못합니다. 하위 에이전트는 자기 모델의 한도(얼마나 읽을 수 있는지, 답이 얼마나 길어도 되는지)를 따르며, **하위 에이전트** 탭과 진단 정보는 각 하위 에이전트가 어느 모델에서 실행되었는지를 알려 줍니다.

## 한 모델, 여러 에이전트

로컬 서버는 흔히 슬롯 하나(GPU 하나)만 가집니다. 여기에 답을 두 개 동시에 요청하면 둘 다 느려지거나 시간 초과가 납니다. 모델의 **연결**([모델](inference-providers.md#general-settings)의 설정, 따로 지정하지 않으면 1)은 이 모델로 가는 모든 요청이 도착한 순서대로 차례를 지키도록 합니다. 여기에는 여러분 에이전트의 요청, 다른 사용자 에이전트의 요청, 그리고 이야기 창에서 여러분이 직접 쓰는 생성도 포함됩니다. 기다리는 실행은 *실행 중* 상태로 남으며, **일시 정지**나 **중지**를 누르면 기다림이 즉시 끝납니다. 에이전트는 모델의 두 답변 사이에는 연결을 잡고 있지 않으므로, 그 사이에 여러분의 생성이 끼어들 수 있습니다.
<a id="when-you-are-not-there"></a>

## 나와 함께 있지 않을 때

에이전트가 사용자의 도움을 필요로 하거나 끝나거나 실패하면, 열려 있는 애플리케이션 화면에 알립니다(탭의 배지, 안내 메시지). 사용자의 화면이 하나도 열려 있지 않을 때는, 관리자가 사용자에게 [권한 *Notifications*](account.md)를 부여했다면(관리자는 이 권한을 가집니다) ("Message to a URL when an agent needs you"), [설정](administration/permissions.md)에서 입력한 주소로 짧은 메시지를 보낼 수도 있습니다. 주소는 **ntfy** 토픽(ntfy 앱에서 바로 보입니다), **Gotify** 메시지 URL, 또는 **Discord** 웹훅 중 하나입니다. 서비스가 요구하는 **형식**을 고르세요. **테스트 메시지 보내기**는 입력란에 적힌 내용으로 실제 전송을 시도합니다. 메시지에는 에이전트의 이름과 무엇을 원하는지("사용자를 기다림", "완료됨", "명령 ...의 승인을 요청함", "실패함", "일시 정지됨: 사유")가 사용자의 언어로 적힙니다. **애플리케이션이 열려 있을 때도**를 켜면 화면이 열려 있든 아니든 항상 보냅니다.

메시지는 서버가 주소를 호출하는 방식으로 전송되므로, 관리자는 Admin의 *Agents* 항목에서 이 기능을 모든 사용자에 대해 끌 수 있습니다. 또한 관리자가 사용자의 권한에서 **이 컴퓨터와 사설 네트워크의 주소 허용**을 체크하지 않으면, 인터넷 주소로만 호출합니다. 같은 컴퓨터나 자신의 네트워크에 있는 ntfy나 Gotify를 쓰려면 관리자에게 이 설정을 요청하세요. 주소가 거부되면 테스트 메시지가 그 사실을 알려 줍니다. 주소에 비밀이 담겨 있다면 비밀번호처럼 다루세요. 그 주소를 아는 사람은 전송되는 내용을 읽을 수 있습니다. 서버는 주소를 로그에 남기지 않고, 리다이렉트를 따라가지 않으며, `http`와 `https` 주소로만 호출합니다.

<a id="asking-you"></a>

## 사용자에게 묻기

에이전트가 사용자의 도움을 필요로 하면, 앱의 어느 곳에 있든 그 사실을 알려 줍니다.

- **에이전트 탭**의 **숫자**는 사용자를 기다리는 에이전트의 수를 셉니다. 그런 에이전트의 **콘솔** 버튼은 강조 표시됩니다.
- **안내 메시지**가 나타나며, 그 안의 **열기** 버튼을 누르면 해당 에이전트의 콘솔이 열립니다.

에이전트가 *사용자에게 무언가를 묻거나 다음 메시지를 기다릴 때*, **명령의 승인을 요청할 때**, *완료되었을 때*, *실패했을 때*, 또는 *스스로 일시 정지되었을 때*(한도에 도달했거나, 모델에 요청할 수 없었거나, 서버가 다시 시작된 경우) 사용자의 도움이 필요한 것으로 봅니다. 사용자가 직접 요청한 일시 정지는 여기에 포함되지 않습니다.

에이전트는 사용자가 자리를 비운 동안에도 작업하므로, 이 알림은 앱이 열려 있는지와 관계없이 동작합니다. 다시 로그인하면 숫자가 그대로 남아 있고, 열려 있는 모든 브라우저 창에 안내 메시지가 뜹니다. 해당 에이전트의 콘솔을 열면 알림이 사라집니다(다른 창도 함께 갱신됩니다).

에이전트가 **먼저 묻기**로 설정되어 있고 데이터를 변경하거나 삭제하는 명령을 요청하면, 실행은 *승인을 기다리는 중* 상태에서 멈춥니다. 그러면 콘솔 위에 명령과 인자가 적힌 창이 뜹니다. **승인**을 누르면 명령이 실행되고, **거부**를 누르면 에이전트에게 사용자가 거절했다고 전달되며 에이전트는 계속 진행합니다. 실행을 일시 정지하거나 중지하는 것(또는 서버를 중지하는 것)은 거부로 간주되지 않습니다. 에이전트에게는 아무것도 전달되지 않으며, **재개**를 누르면 같은 명령에 대한 창이 다시 나타납니다. 이 명령은 여전히 책의 [사본](#the-working-copy)에 대해 실행됩니다. 콘솔을 닫았더라도 콘솔을 열면 창이 바로 나타납니다.

## 서버가 중지될 때

서버를 중지하면, **지금 일시 정지**를 눌렀을 때와 같이 작업 중인 실행을 먼저 일시 정지합니다(서버에 몇 초의 시간을 줍니다). 진행 중이던 요청과 호출은 중단되고, 실행은 "서버가 중지되었음"이라는 사유와 함께 *일시 정지됨* 상태가 되며, **재개**로 계속할 수 있습니다. 서버가 강제 종료되거나 충돌하면, 다음 시작 때 작업 중이던 실행을 일시 정지합니다("서버의 재시작으로 중단됨"). 실행이 한 일은 모두 보존됩니다. 저장된 라운드, 사본, 작업 공간, 그리고 대기 중이던 메시지와 명령이 그대로 남습니다. 잃는 것은 끝나지 않은 라운드뿐입니다. 재개하면 실행이 진행 중이던 호출을 다음과 같이 처리합니다.

- **아직 시작되지 않은** 호출(사용자의 승인을 기다리거나, 다른 호출 뒤에서 차례를 기다리던 호출)은 다시 수행됩니다. 따라서 승인이 필요한 명령은 다시 승인을 묻습니다. 읽기만 하는 호출도 다시 수행됩니다.
- **무언가를 바꾸기 시작한** 호출은 일부만 끝났을 수 있습니다. 이 경우 에이전트에게 그 결과를 알 수 없다고 전달하며, 에이전트는 다시 실행하기 전에 읽기 도구로 상태를 확인합니다. 그 뒤의 호출은 수행되지 않은 것으로 표시됩니다.
- 서버가 중지될 때 실행 중이던 사용자의 명령은 실행이 재개될 때 계속됩니다. `/compact`와 `/clear-workspace`는 다시 실행됩니다. 시작되었던 다른 명령은 **다시 실행되지 않습니다**(일부만 끝났을 수 있습니다). 이 사실은 에이전트에게 전달되고, 에이전트가 확인합니다. 그 뒤에 들어온 메시지와 명령은 평소처럼 전달됩니다.
- 에이전트의 계획과 명령의 결과(`list_command_results`, `@result`)도 보존되므로, 재시작 후에도 에이전트가 이를 가지고 있습니다.
- 하위 에이전트의 진행 중이던 호출도 에이전트의 경우와 같이 처리됩니다. 시작되지 않은 호출은 다시 수행되고, 시작되었던 호출은 "결과를 알 수 없음"으로 하위 에이전트에게 보고되며, 사용자의 승인을 기다리던 하위 에이전트는 다시 묻습니다.
- 명령이 실행되는 도중 서버가 **강제 종료**되면(`kill -9`, 정전 등), 그 명령도 함께 종료됩니다. 명령이 한 일은 위에서 설명한 대로 처리됩니다.

## 작업 사본

모든 실행은 실행이 시작될 때 앱이 만드는 **책의 사본**과 그 어휘 사전들의 사본에서 작업합니다. 사본에는 그 시점의 메시지, 요약, 태그, 설정이 그대로 담기며, 하위 어휘 사전이 포함된 어휘 사전도 함께 복사됩니다. 사본은 숨겨져 있어서 책과 어휘 사전의 목록에 나타나지 않습니다. 에이전트가 무엇을 하든 그 작업은 사본에 대해서만 이루어지며, 사용자의 책은 그대로 남습니다.

에이전트의 **에이전트의 모델로 책 쓰기** 설정이 켜져 있으면(기본값), 실행이 시작되거나 재개될 때마다 사본은 책의 AI와 프로토콜 대신 **에이전트의 모델**(주 모델 프로필의 AI와 프로토콜)을 사용합니다. 따라서 모델로 글을 쓰는 명령(`/next`, `/swipe`, `/regenerate`, `/redraft-part`, `/generate-annotation`, 요약)과 확장 기능의 모델 명령(Lore Generator, Arc Outline)은, 책이 다른 모델로 설정되어 있거나 모델이 없더라도 에이전트의 모델을 사용합니다. 다만 호출에 이름이 적힌 `profile`는 여전히 우선합니다. 이 설정이 꺼져 있으면 책의 모델을 사용합니다. 이것은 책의 변경이 아니므로, 검토 화면에는 나타나지 않으며, 결과를 적용해도 책의 AI와 프로토콜은 그대로 남습니다.

사본은 책이 속한 [폴더](books/folders.md)에 놓이므로, 에이전트는 책이 쓰는 것과 같이 폴더가 설정한 언어, 템플릿, 시점, 시제, 문체, 프롬프트를 적용하여 글을 씁니다. 사본은 폴더의 콘텐츠가 아니므로 폴더의 항목 수에 포함되지 않으며, 사본에서 한 작업은 폴더의 *마지막 수정* 시각을 바꾸지 않습니다. 실행이 일시 정지된 동안 책을 옮기면 사본도 따라 옮겨집니다. 결과를 적용해도 책의 위치는 바뀌지 않습니다.

일시 정지된 실행은 사본을 그대로 유지하고, 재개하면 그 사본에서 다시 작업합니다. *완료됨* 상태이거나 중지한 뒤 보관해 둔 실행은, [결과를 가져오거나 버릴 때까지](#reviewing-the-result) 사본을 유지합니다. 실행이 *실패함* 상태가 되었거나, 결과를 버렸거나, 변경 사항을 적용했다면, 사본은 영구히 삭제되며 다음 실행은 그 시점의 책으로부터 새 사본을 만듭니다.
<a id="resuming-a-run"></a>

## 실행 재개하기

일시 중지되었거나 보관된 실행은 책에 대한 잠금을 점유하지 않으므로, 그동안 책을 편집할 수 있습니다. 실행을 **재개**하면 작업 사본이 사용자가 한 작업을 따라잡습니다.

- 사용자가 변경했지만 에이전트는 변경하지 않은 것(파트, 로어북 항목, 설정, 태그 등)은 사본에 반영됩니다. 사용자가 추가한 파트도 들어오며, 에이전트는 그 위에 이어서 작업할 수 있습니다. 사용자가 삭제한 것은 사본에서도 삭제됩니다.
- 사용자와 에이전트가 서로 다른 텍스트로 함께 변경한 것은 **에이전트가 가진 상태를 그대로 유지합니다.** 에이전트가 한 작업은 하나도 잃지 않습니다. 이는 결과를 검토할 때 두 텍스트를 나란히 보고 해결해야 하는 [충돌](#reviewing-the-result)입니다.
- 사용자가 변경했지만 에이전트가 삭제한 것은 삭제된 상태로 남고, 사용자가 삭제했지만 에이전트가 변경한 것은 사본에 남아 있습니다. 검토 화면에서 두 경우 모두 확인할 수 있습니다.

별도로 클릭할 필요는 없습니다. 동기화는 재개 과정의 일부이며, 몇 초 정도 걸립니다(항목이 수백 개 바뀌었다면 조금 더 걸릴 수 있습니다). 동기화 전의 사본 상태는 자동 [체크포인트](#checkpoints)로 저장됩니다. 에이전트는 무엇이 일어났는지 항목의 이름으로 전달받습니다. 다시 시작할 때 "일시 중지된 동안 사용자가 책을 변경했습니다..."라는 메시지로 알려 주며, `get_sync_report`를 사용해 다시 확인할 수도 있습니다.

**충돌은 저절로 사라지지 않습니다.** 재개할 때마다 사본과 책을 다시 비교하므로, 충돌은 해결할 때까지 재개할 때마다 다시 보고되고 에이전트에게도 다시 전달됩니다. 해결하려면 책에서 사용자 쪽 텍스트를 바꾸거나(에이전트의 텍스트로 또는 원래 텍스트로 되돌리기), 검토 화면에서 처리하면 됩니다.

**재개 시 남기는 메모.** **재개**를 누르면 *에이전트에게 남기는 메모 (선택 사항)* 입력란이 있는 작은 창이 열립니다. 여기에 쓴 내용은 에이전트가 다시 시작할 때 가장 먼저 읽는 내용이며, 사용자가 책에서 한 변경 사항 보고 다음에 나옵니다. 이것은 방향을 바꿀 때 쓰도록 만들어졌습니다("로어북은 건드리지 마", "3장부터 시작해"). 대화에 보내는 메시지와 달리, 사용자의 메시지를 기다리지 않는 실행에도 모든 실행에서 작동합니다. 평소처럼 재개하려면 비워 두면 됩니다.

## 결과 검토하기

실행이 *완료*되었거나(또는 **중지하고 결과 유지**로 멈춘) 경우, 에이전트 행과 콘솔에 **변경 사항 검토** 버튼이 나타납니다. 이 버튼을 누르면 에이전트가 변경한 모든 내용을 **현재 상태의** 책과 비교하여 한 줄씩 보여 주는 창이 열립니다. 에이전트가 보고한 발견 사항이 있으면 변경 사항 위에 **발견 사항 (3)** 형태로 나열되므로, 아무것도 바꾸지 않은 점검이라도 보여 줄 내용이 있습니다.

![실행 결과 검토하기](../images/agent-review.png)

- **책:** 이름, 설명, 언어, 시점, 시제, 문체, 템플릿, 파트별로 보관하는 버전 수, 태그, 그리고 확장 기능이 책에 보관하는 데이터(아크 개요, 캐릭터 추적기)입니다.
- **파트:** 에이전트가 본문, 지시문, 장면 설정, 시점 인물, 등장인물 목록 또는 요약을 바꾼 파트, 에이전트가 쓴 파트, 에이전트가 삭제한 파트입니다. 파트와 함께 보관되는 생성 변수(및 확장 기능의 데이터)도 **데이터** 필드로 함께 가져옵니다.
- **로어북**과 **항목:** 에이전트가 만들었거나, 바꾸었거나(이동, 이름 변경, 다른 태그나 다른 하위 책 포함), 삭제한 로어북이나 항목입니다.
- **주석:** 에이전트가 만들었거나, 바꾸었거나(메모, 유형, 상태), 삭제한 파트 구절의 [메모](books/annotations.md#annotations-and-agents)입니다.

가져올 줄을 체크한 다음 **선택한 변경 사항 적용**을 누르세요. 목록 위의 버튼으로 **전체**, **없음**, **새 파트만**(에이전트가 쓴 새 분기만, 그 밖의 것은 제외), **주석만**, 또는 **충돌 없이 전부**를 한 번에 선택할 수 있습니다. 다른 줄에 의존하는 줄(새 파트가 따르는 파트가 역시 새 것이라면 그 파트도 필요합니다)은 체크할 때 함께 선택되고, 체크를 해제하면 그에 딸린 줄도 함께 해제됩니다. 줄을 클릭하면 오른쪽에서 내용을 볼 수 있습니다. 현재 책의 텍스트와 적용될 텍스트를 나란히 보여 주며, **적용하기 전에 편집할 수 있습니다.** 아무것도 쓰지 않으면 에이전트의 텍스트가 적용됩니다.

실행이 시작된 뒤에 책이 바뀌었을 수 있습니다(실행이 작업 중이 아니면 언제든 책을 편집할 수 있습니다). 사용자만 바꾼 내용은 목록에 나타나지 않으며 그대로 남습니다. 둘이 같은 내용으로 바꾼 것은 변경 사항이 아닙니다. 둘이 **서로 다른** 텍스트로 바꾼 것은 **충돌**입니다. 충돌은 기본적으로 체크되어 있지 않으며, 체크하면 오른쪽에 보이는 텍스트가 책의 텍스트를 대체합니다. **책의 것 사용**을 누르면 책의 텍스트가 입력 상자에 들어가고(이 줄은 해당 필드에 아무 변화도 주지 않습니다), **에이전트의 것 사용**을 누르면 에이전트의 텍스트가 다시 들어갑니다. 또는 결과를 직접 작성할 수도 있습니다. 적용할 수 없는 줄(딸린 파트나 속한 로어북이 책에서 삭제된 경우)은 그 사실을 알려 주며, 체크할 수 없습니다.

![검토 화면의 충돌](../images/agent-review-conflict.png)

텍스트 아래에 있는 **차이점**은 변경 사항을 **단어 단위로** 보여 줍니다. 현재 책에만 있는 내용은 빨간색 취소선으로, 적용될 텍스트에만 있는 내용은 초록색으로 표시됩니다(입력 상자에 쓴 내용을 따릅니다). 충돌의 경우에는 실행이 시작된 뒤 에이전트가 무엇을 바꾸었고 사용자가 무엇을 바꾸었는지도, 각각 당시의 책을 기준으로 보여 줍니다. 그래서 누가 무엇을 했는지 알 수 있습니다. 에이전트가 한 줄에서 둘 이상의 항목을 바꾼 경우(예: 파트의 본문과 장면 설정, 또는 새 내용과 메모가 모두 바뀐 항목)에는 각 항목 옆에 **이 변경 사항 적용** 체크박스가 있습니다. 하나를 체크 해제하면 그 항목만 제외하고 줄을 적용하며, 책은 해당 필드의 자체 값을 유지합니다. 파트의 이야기 속 위치는 파트와 함께 움직이며 별도의 체크박스가 없습니다. 에이전트가 만들거나 삭제한 항목은 전체로 가져오거나 남겨 둡니다. **사본에서 보기**(에이전트가 만들었거나 바꾼 줄에서)를 누르면 해당 파트나 항목 위치의 [책 사본](#the-copy-of-the-book)이 열려, 그 자리에서 내용을 읽을 수 있습니다.

![충돌의 차이점, 단어 단위](../images/agent-review-differences.png)

### 확장 기능이 보관하는 데이터(JSON)

확장 기능은 자체 데이터를 책, 그 파트, 로어북과 항목(아크 개요, 캐릭터 추적기, 생성의 변수 등)에 보관합니다. 이 데이터는 JSON이며, 검토 화면에서는 **보기 좋게 정렬된 형태(pretty printed)**로 표시되고, 적용될 텍스트 옆에 **JSON 데이터 병합** 줄이 함께 나타납니다.
데이터는 통째로 가져오지 않습니다. 에이전트만 바꾼 부분은 에이전트의 것을 가져오고, 책에서만 바꾼 부분은 그대로 유지되며, 두 쪽이 **서로 다른 곳**을 바꾼 경우에는 곳마다 따로 합쳐집니다. 두 쪽이 **같은 곳**을 서로 다른 값으로 바꾼 경우에만 충돌이며(키의 순서는 상관없습니다), 결정하기 전까지는 그 곳에 에이전트의 버전이 사용됩니다.

**JSON 데이터 병합**을 누르면 세 버전의 데이터가 트리 형태로 겹쳐 보이는 창이 열립니다. *실행 시작 시점*, *현재 책*, *에이전트*, *결과*가 각각 한 열씩 나열되며, 무엇이 어디서 바뀌었는지(에이전트, 책, 둘 다, 충돌)를 표시합니다. 바뀐 곳만 표시되며(**변경된 것만**의 체크를 모두 해제하면 모든 곳이 표시됩니다), 각 곳은 열어야만 펼쳐지므로 큰 문서도 문제가 되지 않습니다.

![여러 버전의 확장 기능 데이터가 겹쳐 보이는 모습](../images/agent-json-merge.png)

- 곳을 선택하고 한 버전에서 데이터를 가져옵니다(**에이전트의 것 사용**, **책의 것 사용**, **실행 시작 시점의 것 사용**). 또는 **제외**(해당 키나 요소가 결과에 없음), 또는 **Put together from inside**(안에 있는 곳들이 각자 결정함)를 고릅니다. 한 버전에만 있는 키나 요소는 그 버전에서 가져와 결과에 복사됩니다. 객체나 목록 전체를 한 버전에서 가져오면 그 안에서 고른 내용은 무시되지만, 영구적으로 사라지지는 않습니다. 다시 **Put together from inside**를 하면 선택이 되살아납니다.
- **목록**의 요소에는 이름이 없으므로, 그것이 무엇인지에 따라 짝을 맞춥니다. 먼저 같은 데이터, 그다음 같은 `uuid`, `id` 또는 `name`, 그다음 가장 비슷해 보이는 것 순서입니다. 남은 것들 중 개수와 종류가 같은 것은 바뀐 것으로 봅니다. 추측이 틀렸다면 요소를 각 버전의 것들로 **분할**하거나, **다음과 일치시키기…**로 첫 요소와 공통된 버전이 전혀 없는 다른 요소와 짝을 맞춥니다.
- **열기**(또는 더블클릭)는 한 곳에만 작용합니다. 트리 위의 경로를 누르면 위로 돌아갈 수 있습니다.
- **텍스트** 탭은 열린 곳의 데이터를 텍스트로 보여 줍니다. 에이전트의 데이터는 **편집**할 수 있고, 나머지(책, 실행 시작 시점, 결과)는 읽기만 가능합니다. **다음과의 차이 보기**는 차이를 단어 단위로 표시합니다. 입력한 내용은 트리로 돌아가거나, 표시 내용을 바꾸거나, 다른 곳을 열거나, 결과를 사용할 때 JSON으로 검사됩니다. 올바른 JSON이 아니면 그 자리에 머무르며 무엇이 잘못되었는지 알려 주고, 아무것도 바뀌지 않습니다. 올바른 텍스트는 그 곳의 에이전트 데이터를 대체하며, 그 안의 모든 내용은 다시 비교됩니다.
- **처음부터 다시**는 결정하고 입력한 내용을 모두 지웁니다. **결과 사용**은 결과를 검토 화면으로 넘기며, 거기서 적용될 텍스트가 됩니다(검토 화면이 열려 있는 동안 해당 줄은 두신 대로 유지됩니다).

검토 화면에도 이런 필드를 위해 **에이전트의 것 사용**과 **책의 것 사용**이 있어, 두 가지 중 하나를 그대로 가져올 수 있습니다. **처음부터 다시**를 누르면 합쳐진 데이터로 돌아갑니다.

![검토 화면의 아크 개요 데이터와 JSON 데이터 병합](../images/agent-review-json.png)

다른 책들이 사용하는 로어북에는 **공유됨** 표시가 붙습니다. 변경 사항은 로어북 자체에 적용되므로 다른 책들도 이를 받게 됩니다. 이 옵션은 처음에는 체크가 해제되어 있습니다.

적용은 책에 **제자리에서** 이루어집니다. 파트는 주소를 그대로 유지하고, 다른 책들은 로어북에 대한 링크를 그대로 유지하며, 에이전트가 삭제한 것은 휴지통으로 갑니다. 먼저 **변경 전 책의 백업**이 만들어집니다(책의 백업 목록에 로어북과 함께 들어 있습니다). 변경 사항은 모두 한꺼번에 적용되거나 전혀 적용되지 않습니다. **에이전트가 끝낸 분기 보기**는 적용한 항목에 포함되어 있을 경우, 에이전트가 있던 분기로 책을 전환하기도 합니다. 수정된 파트의 요약은 직접 편집한 뒤와 마찬가지로 오래된 상태가 됩니다. 에이전트가 직접 쓴 요약은 그대로 가져옵니다.

변경 사항이 적용되면 실행은 *적용됨* 상태가 되고, 그 사본과 체크포인트는 삭제됩니다. **결과 폐기**는 사본을 버리고 책은 그대로 둡니다. 둘 중 하나를 할 때까지 에이전트의 실행은 끝나지 않은 상태로 남으며, 다른 실행을 시작할 수 없습니다.

<a id="the-copy-of-the-book"></a>

### 책 사본

**책 사본** 탭은 에이전트가 작업하는 책을 읽기 전용으로 보여 줍니다. **스토리**는 한 번에 한 분기씩 보여 줍니다(위에서 분기를 고르세요. 각 파트는 번호, 같은 파트에서 다른 것들 가운데 몇 번째 스와이프인지, 단어 수, 장면 설정, 시점, 그리고 접혀 있는 지시문과 요약과 함께 표시됩니다). **로어북**은 항목과 함께 보여 줍니다(하나를 고르면 내용, 메모, 태그, 설정을 볼 수 있습니다). 이것은 책의 창이 아닙니다. 아무것도 바꿀 수 없고, 사본에 대해서는 백업도 만들어지지 않으며, 확장 기능도 책이 열린 것으로 보지 않습니다. 이 탭을 열 때와 **새로 고침**을 누를 때 읽으며, 에이전트가 작업하는 동안에도 읽으므로 지금까지 에이전트가 쓴 내용을 보여 줍니다. 실행이 사본을 가지고 있는 동안에만 존재합니다(결과가 적용되거나 폐기된 뒤에는 없습니다).

### 진단

**진단** 탭은 실행의 기록에서 실행이 무엇을 했는지 세어, 에이전트에게 도구와 프롬프트로 무엇이 필요한지 알아봅니다. 어떤 실행에도 작동하며, 오래된 실행도 가능합니다(먼저 **실행 기록**에서 고르세요). 이 탭을 열 때와 **새로 고침**을 누를 때 만들어집니다.

![진단 탭](../images/agent-diagnostics.png)

- **Overview**: 라운드와 호출 수, 실패한 호출 수, 모델의 시간, 호출의 시간, 일시 정지의 시간(두 단계 사이의 간격이 30분 이상이면 작업이 아닌 일시 정지로 봅니다), 최고점과 끝에서의 컨텍스트, 토큰, 컨텍스트 압축, 사용자의 메시지, 실행기가 에이전트에게 준 알림(읽을 수 없는 호출, 너무 많은 호출, 가득 찬 컨텍스트).
- **도구**: 도구마다 호출 수, 오류, 잘린 결과, 라운드에서 유일한 호출이었던 횟수, 에이전트가 쓴 글자 수, `@file:` 또는 `@result`로 텍스트를 넘긴 호출 수, 긴 텍스트(300자 이상)를 직접 써낸 호출 수와 그중 방금 받은 결과에서 베껴 온 호출 수, 결과의 토큰 수(글자 수로부터 대략 계산), 전체 결과에서 차지하는 비율, 가장 긴 결과, 시간.
- **What the requests reported**: 실행 중에 기록되므로, 이 기능이 추가된 뒤에 만들어진 실행에만 해당합니다(이전 실행에는 기록이 없다고 나옵니다). 요청이 첫 단어를 기다린 시간(서버가 프롬프트를 읽는 시간이므로, 시간이 짧으면 캐시가 따뜻했다는 뜻입니다), 답변을 작성하는 데 걸린 시간과 초당 토큰 수, 서버가 다시 읽지 않은 프롬프트의 비율(캐시. llama.cpp와 OpenAI가 보고합니다), 답변 중 추론이 차지한 비율, 답변이 끝난 이유(`length`는 한 답변의 제한이 답변을 잘랐다는 뜻입니다), 모델이 쓴 호출 중 실행되지 않은 것(반복, 제한, 배치 정책), 요청이 자리를 기다린 시간, 작성된 요약과 그에 걸린 것, 그리고 25라운드 묶음마다 같은 항목.
- **What the model wrote**: 인자, 호출 옆의 텍스트, 추론의 글자 수를 전체와 25라운드 묶음마다 모델의 시간과 함께 보여 주어, 출력이 어디로 가는지, 그리고 어느 시점부터 `@file` 사용을 멈췄는지 알 수 있게 합니다. **Longest arguments**는 가장 큰 호출들의 시작 부분을 보여 주며, 파일 도구의 경로도 함께 표시합니다.
- **Rounds lost to a pattern**: 같은 도구가 라운드마다 (세 번 이상) 호출된 경우로, 그 직전에 검색이 있었으면 표시됩니다. 또한 같은 인자로 다시 이루어진 호출도 포함합니다. 이것들은 여러 항목을 한 번에 받는 도구나 한 답변에서 여러 호출을 할 수 있는 방식이 있었다면 라운드를 아꼈을 곳을 보여 줍니다.
- **Errors**: 각 메시지를 받은 첫 호출의 인자(호출이 실패했을 때 모델이 무엇을 보냈는지 보기 위함), **biggest results**, **slowest rounds**, **compactions**, 그리고 각 **sub-agents**가 호출한 도구.

**다운로드**는 보고서를 Markdown으로 내보내고, **JSON 다운로드**는 JSON으로, **복사**는 Markdown을 클립보드에 넣습니다. 시간은 저장된 행 사이의 간격이므로 대략적인 값입니다. 답변의 시간에는 모델에서 빈 자리를 기다리는 시간이 포함됩니다.
<a id="the-context"></a>

### 컨텍스트

**컨텍스트** 탭은 모델이 **다음 요청**에서 읽게 될 내용을 부위별로 나누어 보여 줍니다. 덕분에 토큰이 어디에 쓰이는지 확인할 수 있고, 이상하게 동작하는 에이전트를 디버깅할 수 있습니다. 이 내용은 탭을 열 때와 **새로 고침**을 누를 때 만들어집니다(실행이 진행 중일 때는 만들어지지 않습니다. 모든 부위의 토큰을 세기 때문입니다).

- 차트는 세 가지입니다. 첫째, **부위의 종류**별 크기를 컨텍스트 한도와 비교한 차트입니다. 종류는 에이전트의 프롬프트, 사용자의 지시, 러너의 메모, 도구 정의, 압축(compaction)의 요약, 사용자의 메시지, 에이전트의 답변, 도구 호출 결과, 그리고 남은 공간입니다. 둘째, **부위를 보낸 순서대로** 나열한 차트입니다. 부위마다 막대가 하나씩 있으며 색은 종류에 따릅니다. 설명이 지나치게 긴 도구나 컨텍스트를 가득 채우는 결과는 눈에 띄게 드러납니다. 셋째, **모델의 답변마다의 컨텍스트**를 보여 주는 차트입니다. 각 답변 시점의 구성 요소를 쌓아 올린 막대(종류는 같고 추정치입니다)로 나타내며, 모델이 **보고한** 크기는 선으로, 한도는 점선으로 표시합니다. 선이 막대 위에 있다면 모델이 추정치보다 많이 센 것입니다(이미지나 제공자의 형식 때문입니다). 막대가 줄어드는 곳은 압축이나 되돌리기가 일어난 곳입니다.
- **부위 표**에는 종류, 이름, 토큰 수, 컨텍스트에서 차지하는 비율이 나옵니다. 행을 선택하면 그 부위에 대해 모델이 받는 **정확한 텍스트**를 읽을 수 있습니다. 시스템 메시지의 한 절, 도구 하나의 설명과 매개변수, 메시지, 호출의 인자, 또는 호출 결과가 해당합니다.
- **다운로드**를 누르면 전체 컨텍스트가 하나의 Markdown 파일로 저장됩니다(섹션이 포함된 시스템 메시지, 설명과 스키마가 붙은 모든 도구, 메시지별로 정리된 대화. 각 텍스트는 코드 펜스에 담깁니다). **복사**를 누르면 같은 내용이 클립보드에 복사됩니다.

![컨텍스트 탭](../images/agent-context.png)

부위의 크기는 추정치입니다. 모델이 보고한 수치가 실제 값입니다(요청과 그 답변 기준). 답변 차트에서 프롬프트, 지시, 도구는 지금 상태 그대로입니다(설정을 바꾸었다면 이전 답변은 다른 설정을 가졌을 수 있습니다). 대화는 그 당시의 상태를 따릅니다. 요약은 그 앞의 내용을 대체하며, 되돌리기가 거슬러 간 부분은 그 뒤 답변에서 사라집니다(되돌려진 압축은 다시 살아나지 않으므로, 그 뒤 막대가 조금 작게 보입니다). 시스템 메시지와 도구는 다음 요청이 사용할 것이므로, 프롬프트, 지시 또는 허용된 명령을 바꾸면 즉시 반영됩니다. 메시지는 저장된 기록 그대로이며, 재개할 때 추가되는 내용(“계속”이라는 메시지, 중단으로 열려 있던 호출의 답변)은 포함되지 않습니다. 추론 내용은 컨텍스트에 포함되지 않으며(모델에게 다시 보내지 않습니다), 이미지는 파일 이름으로 표시됩니다. 압축으로 대체된 내용도 컨텍스트에 들어 있지 않습니다. 다만 **실행** 탭과 **실행 기록** 다운로드에는 남아 있습니다.

## 체크포인트

**체크포인트**는 실행의 작업 사본(부위, 요약, 로어북, 확장 기능의 데이터, 그리고 에이전트에게 주어진 핸들)과 에이전트의 작업 공간에 대한 복원 지점입니다. 덕분에 잘못된 작업을 되돌릴 수 있습니다. 에이전트는 `checkpoint_restore`로 되돌아가거나, 콘솔의 **체크포인트** 탭에서 직접 되돌릴 수 있습니다. 체크포인트를 만드는 주체는 다음과 같습니다.

- **실행 시작**: 실행이 시작될 때 만들어집니다. 이것은 절대 밀려나지 않습니다.
- **자동**: 에이전트가 책이나 작업 공간을 바꿀 수 있는 것(단순 읽기가 아닌 명령이나 쓰기를 하는 파일 도구)을 호출하는 라운드 직전에, 실행이 만듭니다. 마지막 체크포인트 이후 무언가 바뀐 경우에만 만들어집니다. 최근 다섯 개가 보관되며, 새로 만들어질 때 가장 오래된 것이 사라집니다.
- **의도적으로 만듦**: 에이전트가 `checkpoint`로 만들거나(위험한 단계 전에 만들라는 지시를 받았을 때), 사용자가 **체크포인트 저장**으로 만듭니다. 삭제하기 전까지 남아 있습니다.

![체크포인트 탭](../images/agent-checkpoints.png)

한 실행의 모든 체크포인트는 **할당량**을 공유합니다. 관리자가 [권한](administration/permissions.md#settings-of-a-permission)에서 설정하며, 비어 있으면 100MB입니다. 이 중 일부는 자동 체크포인트를 위해 남겨 두어, 에이전트가 전부 써 버리지 못하게 합니다. 공간에 맞지 않는 의도적 체크포인트는 **거부**됩니다. 요청한 사람 모르게 아무것도 삭제되지 않습니다. 그러면 에이전트는 목록을 받아 필요 없는 것을 삭제합니다(시작 체크포인트와 가장 최근 것은 제외). 사용자는 탭에서 어떤 것이든 삭제할 수 있습니다. 각 체크포인트는 아카이브(책을 JSON으로 담은 ZIP, 쌍과 작업 공간 파일 포함)이며, **다운로드**할 수 있습니다.

**복원**은 체크포인트로부터 작업 사본을 다시 만듭니다. 새 사본이 만들어지고 기존 사본은 삭제되며, 작업 공간은 저장된 상태가 됩니다(그 이후에 쓰인 파일은 사라집니다). 그 당시 있던 항목에 대한 에이전트의 핸들은 여전히 동작합니다. 복원 전 상태는 공간이 있다면 먼저 자동 체크포인트로 저장되므로, 복원을 되돌릴 수 있습니다. 복원에는 실행 시작과 비슷한 시간이 걸립니다(부위 2000개짜리 책에 약 30초). 에이전트가 작업하지 않을 때는 복원할 수 있습니다. 에이전트는 라운드 사이에 스스로 복원하며, 무엇이 돌아왔는지 통보받습니다. 실행이 사본을 놓아 주면 체크포인트도 사라집니다.

**되돌리기**는 *대화*까지 되돌리는 복원입니다. 복원만 하면 에이전트는 책에 더 이상 없는 작업을 계속 기억하므로, 다른 방향으로 보내고 싶은 실행에는 되돌리기가 필요합니다. 작업 사본과 작업 공간이 체크포인트 시점으로 돌아가고, 체크포인트가 만들어진 지점 이후의 메시지는 기록에서 회색으로 표시됩니다(여전히 읽을 수 있고 내보내기에도 포함됩니다). 에이전트는 그 메시지들을 더 이상 읽지 않습니다. 또한 무슨 일이 있었는지 알리는 공지가 에이전트에게 전달되므로, 여전히 필요하다면 작업을 다시 합니다. 되돌리기를 하려면 실행이 일시 정지되었거나 중지되어 있어야 합니다(사용자를 기다리는 에이전트라면 먼저 일시 정지하십시오). 그 뒤 **재개**하면 공지에서 이어서 진행합니다. 체크포인트는 대화에서 그 자리가 여전히 실행의 일부일 때만 되돌릴 수 있습니다. 더 이른 체크포인트로 되돌린 뒤에는, 되돌려진 대화에 속했던 이후의 체크포인트는 복원만 가능합니다. 되돌리기 기능이 생기기 전에 만들어진 체크포인트는 대화에서의 자리를 알지 못하므로 복원만 가능합니다. 체크포인트 이후 압축이 한 일은 되돌리기로 취소되며, 에이전트는 압축이 대체했던 메시지를 다시 읽습니다.

**메시지로 돌아가기.** 체크포인트를 고를 필요는 없습니다. 사용자가 에이전트에게 보낸 모든 메시지에는 **실행** 탭의 기록에서 그 아래에 **되돌리기** 버튼이 있습니다. 이 버튼은 대화를 그 메시지 이전으로 되돌립니다. 에이전트는 그 메시지와 그 이후의 모든 것을 잊고, 작업 사본과 작업 공간은 그 전에 만들어진 가장 최근 체크포인트로 돌아갑니다(러너는 무언가 바꾸는 라운드마다 그 전에 체크포인트를 만들므로, 보통 메시지 바로 앞 시점과 맞습니다). 실행의 상태는 체크포인트 시점에만 알려지므로, 가장 가까운 체크포인트가 메시지보다 오래되었다면 그 체크포인트와 사용자의 메시지 사이에 있던 메시지도 함께 잊힙니다. 확인 창에는 어느 체크포인트인지와 몇 개의 메시지가 사라지는지가 표시됩니다. 잊힌 메시지는 회색으로 기록에 남습니다. 이 버튼은 에이전트가 사용자를 기다리는 동안(그 때문에 일시 정지된 상태), 일시 정지된 상태에서, 또는 중지되어 보관된 상태에서 동작합니다. 에이전트가 작업 중일 때는 비활성화됩니다. 그 뒤 실행을 **재개**하면 공지에서 이어서 진행합니다.

## 에이전트 만들기와 편집하기

**새 에이전트**를 누르면 **편집**과 같은 창이 열립니다:

![새 에이전트 창](../images/agent-dialog.png)

| 필드 | |
|---|---|
| **이름** | 필수입니다. |
| **사용** | 비활성화된 에이전트는 시작할 수 없으며, 이미 실행 중인 실행은 그대로 둡니다. |
| **책** | 에이전트가 작업할 책으로 필수입니다. 에이전트가 없는 책만 선택할 수 있으며, 에이전트가 맡은 책은 나중에 바꿀 수 없습니다. |
| **모델**, **프로토콜** | 에이전트가 통신할 모델과 프로토콜입니다. 둘 다 지정하거나 둘 다 비워 두어야 하며, 둘 중 하나라도 없는 에이전트는 시작할 수 없습니다. |
| **에이전트의 모델로 책 쓰기** | 기본값은 켜짐입니다. 모델이 있는 명령은 책에 설정된 모델과 상관없이 위의 모델을 사용해 다음 턴, 스와이프, 요약, 그리고 로어 생성기나 아크 개요 같은 확장 명령의 결과물을 작성합니다. 끄면 책의 모델을 사용합니다(책에 모델이 없으면 확장 명령은 [설정](account.md)에서 지정한 기본 모델을 사용합니다). 이렇게 모델을 섞어 쓸 수 있습니다. 생각을 깊이 하는 강력한 모델과, 더 저렴하거나 문장이 자연스러운 모델을 나눠 쓰는 식입니다. 명령은 에이전트에 속한 다른 모델 프로필을 지정할 수도 있습니다. |
| **한 번의 응답 안의 호출** | 에이전트가 한 응답에 쓴 호출 중 몇 개를 실행할지 정합니다. *모두 함께, 일괄 정책 무시*: 모든 호출을 함께 실행합니다(가장 빠릅니다). *함께, 단독으로 표시된 명령은 따로*(기본값): 호출을 함께 실행하지만, **일괄** 열에 *단독*으로 표시된 명령(모델을 호출하는 명령 등)은 자기만의 응답에서 실행하며, 에이전트에게 이 사실을 알려 줍니다. *응답당 호출 하나*: 첫 번째 호출만 실행하고, 에이전트는 결과를 읽은 뒤 다음 호출을 작성합니다. 느리지만(모든 호출이 모델의 생각을 거치는 별도의 라운드가 됩니다) 각 결과에 반응할 수 있습니다. **오류가 나면 모든 모드에서 응답이 즉시 끝납니다.** 실패한 호출 뒤의 호출은 실행되지 않으며("앞선 호출이 실패해 실행되지 않음"으로 응답됩니다), 에이전트는 먼저 오류를 읽게 됩니다. |
| **모델이 이미지를 볼 수 있음** | 모델이 이미지를 받아들이는 경우에 체크합니다(모델 API로는 알 수 없으므로 직접 확인해야 합니다). 체크하면 에이전트에 `view_image` 명령이 생기고 메시지에 이미지를 첨부할 수 있습니다. 체크하지 않으면 에이전트는 그림을 전혀 받지 못합니다. |
| **언어** | 에이전트가 읽는 모든 것의 언어입니다. 명령의 설명, 결과, 오류 메시지, 그리고 실행에 쓰이는 내장 문구(기본 시스템 프롬프트, 실행 중 알림, 압축 프롬프트)를 포함하며, 해당 언어(영어, 일본어, 중국어)로 된 문구가 있는 경우에 한합니다. 설정의 [프롬프트 언어](account.md#prompt-language)는 에이전트에 적용되지 않습니다. 기본값은 영어이며, 명령과 매개변수가 언어와 무관하게 영어로 되어 있어서(다른 언어로 된 설명은 두 언어가 섞입니다) 가장 안전한 선택입니다. 특히 작은 모델일수록 이렇게 할 때 도구를 더 안정적으로 사용합니다. 목록에는 애플리케이션에 설치된 언어가 나타나며, 확장 기능이 언어를 추가할 수도 있습니다(예: 중국어 현지화). 이 설정은 **책의 언어와는 무관합니다**. 에이전트는 책의 텍스트를 책의 언어로 쓰도록 지시받으며, 이는 `get-book-info` 명령으로 읽을 수 있습니다. 실행은 시작할 때의 언어를 유지하며, 변경 사항은 다음 실행부터 적용됩니다. |
| **파괴적 명령** | 에이전트가 데이터를 바꾸거나 삭제하는 명령을 원할 때 일어날 일입니다. *실행하기*, *먼저 묻기*(승인을 요청하는 [창](#asking-you)이 뜹니다), *거부하기* 중 하나를 고릅니다. |
| **최대 라운드 수**, **실행당 토큰 예산**, **컨텍스트 한도** | 한 번의 실행에 대한 선택적 제한입니다. 관리자가 지정한 한도는 어떤 경우에도 적용됩니다. |
| **최대 하위 에이전트 수** | 에이전트가 동시에 작업시킬 수 있는 [하위 에이전트](#sub-agents)의 수로, 0에서 10까지입니다. 비워 두거나 0이면 하위 에이전트를 쓰지 않습니다. |
| **하위 에이전트용 모델** | 하위 에이전트가 실행될 수 있는 [모델](#models-for-sub-agents)과, 주 모델에서도 실행될 수 있는지 여부입니다. |
| **압축 기준 (컨텍스트의 %)** | 모델의 컨텍스트가 한도의 이 비율을 넘었는데 에이전트가 자신의 작업을 [직접 압축](#running-a-command-yourself)하지 않았다면, 실행이 이를 대신 수행합니다. 에이전트가 앞선 작업의 요약을 작성하고, 그 요약이 이전 작업을 대체합니다. 비워 두면 90, 0이면 압축하지 않습니다(이 경우 컨텍스트가 가득 차면 실행이 멈춥니다). 그 밖의 값은 50에서 99 사이여야 합니다. |
| **시스템 프롬프트** | 에이전트에게 어떤 존재로 행동하라고 지시하는 내용입니다. 비워 두면 에이전트는 기본값을 따릅니다. 기본값은 [설정](account.md#templates)에서 지정한 것이 있으면 그것을, 없으면 관리자가 지정한 것을, 그것도 없으면 내장 기본값을 사용하며, 회색으로 표시됩니다. 정보 아이콘에는 **기본 템플릿 삽입** 버튼이 있어서, 기본값을 채워 넣고 그 복사본을 편집할 수 있습니다. 기본값을 다시 따르려면 필드를 비우면 됩니다. |
| **압축 프롬프트** | [`/compact`](#running-a-command-yourself)할 때 에이전트에게 요청하는 내용으로, 앞선 작업을 대체할 요약을 작성하게 합니다. 비워 두면 시스템 프롬프트와 마찬가지로 기본값을 따르며, 같은 정보 아이콘을 사용합니다. |
| **지시문 (agents.md)** | 에이전트에게 주는 지침으로, 모든 실행에서 프롬프트에 덧붙여집니다. 에이전트는 이를 읽을 수 있지만 바꿀 수는 없습니다. 비워 두면 [설정](account.md#templates)에 지정한 기본값을 따르며(회색으로 표시됩니다), 기본값도 없으면 지시문이 없습니다. 정보 아이콘에는 **기본 템플릿 삽입** 버튼이 있어서, 기본값을 채워 넣고 그 복사본을 편집할 수 있습니다. 그 아래 줄에는 **모든 요청마다** 프롬프트, 지시문, 체크된 명령이 차지하는 토큰 수가 표시됩니다(추정치이며, 파일과 실행을 위한 도구, 실행기의 메모가 추가로 더해집니다). |
| **허용된 명령** | 아래를 참고하세요. |

### 허용된 명령

에이전트에는 사용자가 체크한 명령만 제공됩니다. 표에는 모든 명령과 그 효과가 나열됩니다(*파괴적*은 데이터를 바꾸거나 삭제하고, *비파괴적*은 읽기만 하거나 추가만 합니다). **선택 항목** 상자를 이용하면 여러 명령을 한 번에 체크할 수 있습니다. **전체**, **없음**, **파괴적이지 않은 모든 것**(새 에이전트의 기본값) 중에서 고르거나 역할을 고를 수 있습니다. 명령을 직접 체크하면 선택 항목은 *사용자 지정*이 됩니다. 표 위의 **명령 검색** 필드는 입력한 모든 단어를 포함하는 명령만 보여 줍니다(단어의 순서는 상관없으며, 이름 또는 설명에서 찾습니다). 선택은 숨겨진 명령을 포함한 모든 명령에 그대로 적용됩니다. 확장 기능이 제공하는 명령은 해당 확장 기능이 로드되지 않아도 허용된 상태로 남으며, 다만 보이지 않게 됩니다. **일괄** 열은 명령이 한 응답에서 다른 호출과 *함께* 쓰이는지, 아니면 *단독*으로 쓰이는지를 나타냅니다(`next`, `swipe`, `regenerate`, `redraft-part`, `generate-annotation`처럼 모델을 호출하는 명령이나 압축은 단독입니다. 아래의 **한 번의 응답 안의 호출**을 참고하세요). 모든 열의 너비는 조절할 수 있습니다. **토큰** 열은 명령의 정의(이름, 설명, 매개변수)가 에이전트의 모든 요청에 더하는 양을 보여 줍니다. 지시문 아래의 줄은 체크된 명령의 합계를 보여 줍니다. 전체 세트는 약 20 000 토큰이므로, 더 작게 선택하면(역할 등) 작업을 위한 컨텍스트 공간이 더 넉넉해집니다.

![허용된 명령과 선택 항목 상자의 역할](../images/agent-commands.png)

역할은 특정 작업을 위한 명령들의 묶음입니다. 모든 역할은 책과 로어북을 읽을 수 있으며(읽기만 하는 모든 명령, 확장 기능의 명령도 포함), 어느 역할도 데이터를 삭제할 수는 없습니다:

| 역할 | 읽기 외에 할 수 있는 일 |
|---|---|
| **감사자** | 없음: 연속성 검사, 이름과 용어 감사, 보고서 작성. |
| **로어 관리자** | 로어북 항목과 로어북, 그 태그와 하위 로어북을 만들고 갱신합니다. |
| **편집자** | 파트를 편집하고 그 뒤에 덧붙이며 필드를 설정하고, 요약을 관리하고(모델에게 다시 작성하게 하는 것도 가능), 책 정보와 태그를 관리합니다. |
| **초안 작성자** | 파트와 분기를 추가하고, 편집하고 덧붙이며, 모델이 다음 턴을 쓰게 하고(`/next`, `/swipe`), 요약을 관리하고, 자신이 지어낸 내용의 로어북 항목을 만들고 갱신합니다. |

체크된 명령마다 그 정의가 모든 요청에 더해지므로, 역할은 약한 모델에게 짧은 프롬프트를 주는 가장 저렴한 방법이기도 합니다.

## 휴대폰에서

휴대폰 화면 구성에는 서랍에 **에이전트** 탭이 있습니다. 에이전트를 사용할 수 있는 사용자를 위한 탭이며, 이름 옆에 사용자의 확인이 필요한 에이전트 수가 표시됩니다. 각 에이전트는 이름, 상태, 표의 버튼이 들어 있는 카드로 나타납니다(버튼은 여러 줄로 나뉩니다). 콘솔, 검토 화면, 에이전트 설정 같은 창은 화면 전체를 채우며, 검토 화면에서는 표가 항목의 상세 내용 위에 나타납니다. 모든 기능은 데스크톱과 같고, 화면만 작아졌습니다. 콘솔은 엄지손가락으로 조작하기 편하도록 배치되어 있습니다:

![휴대폰의 에이전트 탭](../images/phone-agents.png)

![휴대폰의 콘솔](../images/phone-agent-console.png)

![휴대폰의 에이전트 탭](../images/phone-agents.png)

![휴대폰의 콘솔](../images/phone-agent-console.png)

- **탭은 아이콘입니다**(실행, 실행 목록, 작업 공간, 체크포인트, 맥락, 책 사본, 하위 에이전트, 진단). 열려 있는 탭의 이름은 창의 제목에 표시됩니다.
- **일시 정지, 즉시 일시 정지, 재개, 완료, 중지는 하단의 아이콘 버튼이며, 지금 사용할 수 있는 것만 표시됩니다.** **변경 사항 검토**는 글자를 그대로 유지합니다. 완료된 실행이 기다리고 있는 것이 바로 이것이기 때문입니다. **새로 고침**과 **닫기**는 머리글의 아이콘입니다.
- **메시지 입력란은 한 줄이며**, 그 옆에 **보내기**와 **이미지 첨부** 아이콘이 있습니다. **명령줄**(터미널 아이콘)은 열기 전까지 숨겨져 있어서, 쓸 일이 없을 때 키보드가 대화 기록을 가리지 않습니다. 대화 기록의 메시지는 화면 너비 전체를 씁니다.
- **표는 카드 목록으로 바뀝니다.** 실행, 체크포인트, 에이전트 설정의 명령, 검토 화면의 항목은 열 대신 각각 이름과 상태를 보여 주고, 그 아래에 세부 정보가, 맨 아래에 버튼이 놓입니다. 작업 공간의 파일은 이름 아래에 크기를 보여 주며, 작업 공간의 도구 모음은 아이콘으로 이루어집니다. 맥락 표는 번호, 이름, 토큰을 그대로 유지하고, 선택한 부분의 종류와 비율은 그 부분의 본문 아래에 표시됩니다.

- **상단 표시줄에서 사용자를 기다리는 대상을 확인할 수 있습니다.** 서랍이 닫혀 있을 때는 상단 표시줄(열려 있는 부분의 제목 옆)에 빨간 숫자가 나타나 사용자의 확인이 필요한 에이전트 수를 셉니다. 서랍 안의 **에이전트** 탭 배지와 같은 역할입니다. 이 숫자를 누르면 **에이전트** 탭으로 이동합니다. 기다리는 대상이 없을 때, 서랍이 열려 있을 때, 그리고 에이전트 탭 자체에서는 숨겨집니다.
- **부분 사이를 스와이프로 이동합니다.** 내용 위에서 좌우로 스와이프하면 서랍의 다음 부분(왼쪽으로 스와이프)이나 이전 부분(오른쪽으로 스와이프)으로 이동합니다. 서랍이 열려 있거나 응용 프로그램이 탐색을 잠근 동안에는 아무 일도 일어나지 않습니다. 텍스트 입력란, 표, 또는 좌우로 스크롤되는 요소에서 시작한 터치는 그 요소가 처리합니다.

긴 작업으로 대화 기록이나 검토 화면을 자세히 봐야 한다면, 더 큰 화면이 여전히 편리합니다.

## 복제

**복제**는 이름을 묻고, 에이전트가 없는 책을 고르게 한 뒤, 에이전트의 정의와 파일(실행 기록은 제외)을 그 책의 새 에이전트로 복사합니다. 관리자가 다른 숫자를 정하지 않았다면 다섯 개까지 에이전트를 가질 수 있으며, 복제본도 여기에 포함됩니다. 한도에 도달하면 **새 에이전트**와 **복제**가 꺼지고 그 이유가 표시됩니다.

## 가져온 책의 설정 노트

원고를 [가져온](books/story-editor.md#after-an-import) 뒤 응용 프로그램은 책의 설정을 정리하는 에이전트를 제안합니다. 이 항목은 **에이전트로 설정 노트 작성...**이라는 이름으로, 이야기의 설정 메뉴 ⚙에도 있습니다(**분석** 항목). 먼저 확인을 요청합니다:

![에이전트가 시작되기 전의 질문](../images/lore-notes-confirm.png)

그런 다음 책을 위해 **설정 노트**라는 에이전트를 만들고, 책의 모델과 프로토콜을 지정한 뒤 시작합니다(콘솔이 열립니다).

- 에이전트는 이야기를 첫 부분부터 마지막 부분까지, 몇 개 부분씩 나누어 읽고, 작업 공간의 파일에 노트(인물, 장소, 사물, 용어)를 기록합니다. 그래서 일시 정지한 뒤에도 이어서 작업할 수 있습니다. 요약은 길을 찾는 데 도움을 주고, 원본이 되는 것은 부분들입니다.
- 그다음 인물, 장소, 사물, 집단 또는 용어마다 항목 하나를 책의 설정집에 씁니다(설정집이 없으면 책을 위해 하나 만듭니다). 이야기에서 쓰는 이름을 필터로 사용하며, 항목은 책의 언어로 작성됩니다. 이미 있는 항목에는 사실을 덧붙이고, 같은 내용을 두 번 쓰지 않습니다.
- 에이전트는 이야기와 설정집을 읽고 항목을 쓸 수 있지만, 이야기를 바꾸거나 무엇인가를 삭제할 수는 없습니다.

이 에이전트도 다른 에이전트와 같습니다. 작업하는 동안 책은 [잠기고](#the-book-is-locked), 에이전트는 [사본](#the-working-copy)에서 작업하며, 에이전트가 쓴 내용은 [검토한](#reviewing-the-result) 뒤 받아들여야만 사용자의 것이 됩니다. 받아들이기 전에 항목을 읽으십시오. 에이전트는 본문이 말하는 것만 알고 있으며, 긴 책은 요청이 많이 듭니다. 지침은 에이전트의 것입니다(**편집**에서 보고, 시작하기 전에 바꿀 수 있습니다). 에이전트를 사용할 권한이 없을 때, 책에 모델이 없을 때, 그리고 책에 이미 에이전트가 있을 때(책마다 하나만 가능합니다) 실행이 거부됩니다.

<a id="the-book-is-locked"></a>

## 책이 잠겨 있습니다

에이전트의 실행이 작업하거나 사용자를 기다리는 동안에는 **그 책이 잠깁니다**. 책을 읽을 수는 있지만 아무것도 바꿀 수 없으므로, 에이전트가 자기 아래에서 움직이는 본문을 다루는 일은 없습니다. 책 목록은 잠긴 책을 열지 않고, 어느 에이전트가 그 책을 점유하고 있는지 알려 줍니다. 잠긴 책에 대해서는 생성, 편집, 검색 및 바꾸기, 요약, 책 삭제가 거부됩니다. 책을 다시 편집하려면 실행을 **일시 정지**하거나 **중지**하십시오. 일시 정지, 중지, 완료된 실행은 책을 잠그지 않습니다.

![책 목록에서 에이전트가 작업 중인 책](../images/agent-locked-book.png)

**책의 설정집**도 함께 잠깁니다. 책이 사용하는 설정집과 그 하위 설정집이 여기에 해당합니다. 설정집 탭에서 이런 설정집은 휴대폰에서 보는 것처럼 편집 없이 일반 텍스트로 표시되며, 어느 에이전트가 점유하고 있는지 알리는 안내가 함께 나타납니다. 일시 정지나 중지 후에는 **새로 고침**을 눌러야 다시 편집할 수 있게 표시됩니다. 다른 설정집은 영향을 받지 않습니다.

<a id="agents-and-folders"></a>

### 에이전트와 폴더

에이전트가 작업하는 책이 [폴더](books/folders.md) 안에 있으면 그 책은 자기 위치와 설정을 유지합니다. 그 위의 폴더를 옮기거나 삭제하는 것, 그리고 폴더가 하위로 전달하는 설정(언어, 템플릿, 시점, 시제, 문체, 프롬프트)을 바꾸는 것은 책 이름과 에이전트 이름을 함께 알리며 거부됩니다. 폴더의 이름을 바꾸거나 설명을 바꾸는 것은 거부되지 않습니다. 일시 정지, 중지, 완료된 실행은 폴더를 놓아 줍니다.
