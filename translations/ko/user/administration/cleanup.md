# 정리

Marginalia에서 사용자가 책, 스토리 파트, 로어북, 추론 제공자 같은 항목을 삭제하면 목록에서는 사라지지만 데이터베이스에는 그대로 남습니다. 그래서 삭제가 안전하고 참조도 계속 유지됩니다(책은 여전히 자신의 파트를 작성한 제공자를 알고 있습니다). 그 전까지 사용자는 [휴지통](../trash.md) 탭에서 삭제한 객체를 복원할 수 있습니다. **정리**는 이런 삭제된 데이터를 영구적으로 제거해 데이터베이스 크기를 줄입니다.

![정리 탭](../../images/admin-cleanup.png)

<a id="running-a-cleanup"></a>

## 정리 실행하기

!!!warning
정리는 되돌릴 수 없으며, 정리로 제거된 데이터는 [휴지통](../trash.md)에서도 사라집니다. 먼저 [데이터베이스 백업을 만드세요](database-backups.md).
!!!

1. 관리자 페이지의 **정리** 탭을 열고 **분석**을 클릭합니다. 아직 아무것도 변경되지 않습니다.
2. 결과를 확인합니다(아래 참조).
3. **정리 실행**을 클릭하고 *n개의 객체가 영구적으로 제거됩니다*라는 메시지를 확인합니다.

정리는 모든 사용자의 데이터를 대상으로 합니다.

정리는 데이터베이스의 항목을 삭제하며, [에이전트](../agents.md)의 파일도 삭제합니다. 제거된 에이전트의 작업 공간과 제거된 실행의 폴더가 여기에 해당합니다. 삭제된 [리소스](../resources.md)(파트의 그림)의 파일은 [리소스 파일](resource-files.md) 탭에서 직접 제거하기 전까지 소유자의 데이터 폴더에 남습니다.

<a id="seeing-what-is-deleted"></a>

## 삭제된 항목 확인하기

표 아래의 **휴지통** 섹션에는 모든 사용자의 삭제된 객체가 객체당 한 행씩 나열됩니다(표를 불러오려면 열어 보세요). 그래서 정리로 무엇이 제거될지 미리 보고, 누군가 복원을 요청한 항목을 되돌릴 수 있습니다. 사용자 및 유형별 필터와 *확장 콘텐츠* 링크를 포함해 [휴지통](../trash.md) 탭과 같은 표입니다.

![정리 탭의 휴지통 섹션](../../images/admin-trash.png)

<a id="reading-the-analysis"></a>

## 분석 결과 읽기

첫 번째 표에는 데이터 종류별로 한 행씩 있습니다:

| 열 | |
|---|---|
| **엔티티** | 데이터의 종류: `Manuscript`(책), `ChatMessage`(스토리 파트), `Lorebook`, `LorebookEntry`, `AI`(추론 제공자), `Protocol`, `Summary`, `Tag`, `TagRelation`, `User`... |
| **삭제됨** | 삭제된 개수입니다. |
| **제거 대상** | *정리 실행*으로 제거될 개수이며, 삭제된 객체에 속한 데이터도 포함합니다. |
| **차단됨** | 삭제되었지만 아직 사용 중이므로 유지되는 개수입니다. |

**아직 사용 중인 삭제된 객체**에는 차단된 객체의 이름과 **참조하는 곳**(아직 이를 사용하는 대상)이 나열됩니다.

<a id="what-is-removed"></a>

## 제거되는 항목

정리는 살아 있는 어떤 것도 더 이상 사용하지 않는 삭제된 객체를, 그것에만 속한 데이터와 함께 제거합니다:

| 삭제된 항목 | 함께 제거되는 항목 |
|---|---|
| 책 | 모든 스토리 파트, 요약, 태그 연결 |
| 로어북 | 항목과 태그 연결. 다른 로어북은 이 로어북을 하위 로어북으로 더 이상 포함하지 않습니다 |
| 스토리 파트 | 해당 파트(자식은 이미 부모로 옮겨졌습니다)와 그 요약 |
| 추론 제공자 또는 프로토콜 | 사용자의 기본값에서 *설정*을 통해 지워짐 |
| 태그 | 책 및 항목과의 연결 |
| 사용자 | 소유한 모든 것: 책(스토리 파트와 요약 포함), 로어북, 추론 제공자, 프로토콜, 태그, 설정 |

<a id="what-is-kept"></a>

## 유지되는 항목

삭제된 객체는 살아 있는 무언가가 여전히 사용하는 동안 **차단됨** 상태로, 즉 유지됩니다:

| 차단됨 | 이유 | 차단 해제 방법 |
|---|---|---|
| 삭제된 추론 제공자 또는 프로토콜 | 책이 이를 모델 또는 프로토콜로 여전히 사용 | 책의 *정보* 탭에서 다른 것을 선택하거나, 책을 삭제합니다 |
| 삭제된 로어북(항목 포함) | 책이 여전히 사용 | 책에서 다른 로어북을 선택하거나, 비웁니다 |
| 삭제된 스토리 파트 | 책 활성 분기의 마지막 파트 | 책을 다른 분기로 전환하거나, 책을 삭제합니다 |
| 삭제된 사용자 | 다른 사용자의 무언가가 이 사용자의 데이터를 사용 중(그 사용자의 추론 제공자나 로어북을 쓰는 다른 사용자의 책) | 다른 사용자의 책을 변경하거나 삭제합니다 |

차단을 해제한 후에는 *분석*을 다시 실행하세요.

<a id="reference-model"></a>

## 참조 모델

하단의 **참조 모델**에는 데이터 종류 사이의 모든 참조와 그 정책이 나열됩니다. 무언가가 왜 차단되었는지 이해하고 싶을 때 유용합니다:

| 정책 | 의미 |
|---|---|
| **차단 정책** | 살아 있는 객체가 참조하는 동안 삭제된 대상은 유지됩니다. |
| **대상과 함께 제거됨** | 참조하는 객체는 대상에 속하며 대상과 함께 제거됩니다(로어북과 함께 제거되는 항목). |
| **대상을 소유** | 대상은 참조하는 객체에 속합니다(요약과 파트의 관계). |
| **제거 시 비워짐** | 대상이 제거되면 참조가 삭제됩니다(하위 로어북, 기본 모델). |

확장 기능은 자체 규칙으로 정리에 참여할 수 있습니다.
