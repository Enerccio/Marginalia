# 注釈

**注釈**とは、パートの一節についてあなたに宛てて残すメモのことです。たとえば *弱いシーン*、*時系列が違う*、*見直す* といった内容です。ワープロのコメント機能に近い仕組みで、ストーリー本文はきれいなまま、該当箇所に印が付き、メモはそのすぐ近くに保存されます。メモはモデルや、ストーリーをチェックする[拡張機能](../extensions/index.md)からも作成されることがあります。

注釈は**作者のためのもの**です。そのメモについて指定しない限り、モデルに送られることはありません。詳しくは [メモをモデルに渡す](#giving-a-note-to-the-model) を参照してください。

<a id="what-an-annotation-is"></a>

## 注釈とは

| | |
|---|---|
| **該当箇所** | メモが対象とする語句、または**パート全体**。 |
| **メモ** | 覚えておきたい内容。 |
| **種類** | 任意で付ける語（*整合性*、*文体*、*展開のテンポ*...）。 |
| **作成元** | 誰が書いたか：あなた、モデル（*AI*）、*エージェント*、または*拡張機能*。本文上の印は作成元ごとに色が異なります。 |
| **ステータス** | *開く*、*解決済み*、*却下*、*対象なし* のいずれか。開いている注釈だけが本文に印として表示されます。 |

1つのパートには、重なり合う箇所を含めて、いくつでも注釈を付けられます。

<a id="making-an-annotation"></a>

## 注釈を作る

**一節に対して。** パートの本文で語句を選択します（書式が付いていても構いませんし、選択範囲が厳密に一致している必要もありません）。そのうえで**右クリック**（スマートフォンでは長押し）し、**選択範囲に注釈を付ける** を選ぶか、そのための[キー](story-editor.md#keyboard-shortcuts)（`a`）を押します。ウィンドウに該当箇所が表示されるので、メモ、任意の種類、そしてそのメモをモデルに渡すかどうかを指定して、**保存** を押します。パートのメニュー（☰）にはこの項目はありません。メニューを開くと選択が解除されてしまうためです。右クリックメニューには **選択範囲に注釈を付ける**、[**選択範囲を書き直す**](story-editor.md#redrafting-only-a-passage)、**コピー** があり、パート本文上ではブラウザー標準のメニューに代わって表示されるため、**コピー** も含まれています。パートを編集中は、エディター内の選択範囲が使われます。その場合、先に編集内容が保存されます。

**パート全体に対して。** パートのメニューから **パートに注釈を付ける** を選びます。

**モデルと一緒に。** **AI で注釈を付ける** を選びます。詳しくは[下記](#letting-a-model-annotate)を参照してください。

**コマンドラインから**（拡張機能からも）: [`/create-annotation`](../commands/index.md#annotations)。

![新しい注釈のウィンドウ](../../images/annotation-dialog.png)

<a id="reading-the-annotations"></a>

## 注釈を読む

開いている注釈が付いた一節には**波線**が引かれ、そのメモを書いた人によって色が変わります（青はあなた、オレンジはモデル、緑はエージェント、赤は拡張機能）。別の注釈の中にある注釈は、より低い位置に線が引かれるため、両方を確認できます。

![印の位置で開いた、下線付きの一節のメモ](../../images/annotation-popover.png)

- **下線の付いた本文をクリック**すると、その箇所を覆うメモが表示されます（該当箇所が重なっている場合はすべて）。メモは本文の横に開きます。スマートフォンでは、該当箇所をタップします。
- パートの見出しにある**数字付きの吹き出し**は、確認が必要なメモの件数を示します。クリックするとすべてのメモが表示されます。パート全体に対するメモや、該当箇所を失ったメモも含まれます。
- **余白**に表示する（ストーリーの歯車メニューの **注釈を余白に表示**。デスクトップのみで、設定は保存されます）と、各パートのメモが、ポップオーバーではなく、本文の左側に該当箇所の順番どおり縦に並んで表示されます。ポインターの下にあるメモとその下線の付いた箇所が同時に強調され、箇所をクリックするとそのメモが見える位置に移動します。表示されるのは同じメモです（解決、編集などもできます）。解決済みと却下されたメモは、下線も引かれないため、ここには表示されません。
- **注釈**タブでは、ブック全体のメモがストーリーの順でパートごとにまとめて一覧表示されます。フィルターとして *要確認*、*完了*、*すべて* があります。**ストーリーで表示**（またはパートの番号）を押すと、そのパートに移動します。

![パートの余白に表示されたメモ](../../images/annotations-margin.png)

![注釈タブ](../../images/annotations-tab.png)

各メモには、誰が書いたか、種類、ステータス、該当箇所、メモの内容と、次の操作が表示されます。

| | |
|---|---|
| ✓ **解決済みにする** | 問題に対処済みであることを示します。メモは本文から消えますが、一覧には残ります。 |
| ✗ **却下する** | このメモに対応する価値はないと判断します。扱いは解決と同じです。 |
| ↶ **再び開く** | 完了したメモを開き直します。 |
| ✎ **編集** | メモと種類を変更します。 |
| 🗑 **削除** | メモを削除します。[ごみ箱](../trash.md)から復元できます。 |
| **パートと一緒にモデルへ渡す** | 下記を参照してください。 |
| **選択範囲に付ける** | 該当箇所のないメモ用です。パート内の語句を選択してからクリックします。 |

<a id="annotations-follow-the-text"></a>

## 注釈は本文に追従する

編集するときに、メモがどこにあるかを気にする必要はありません。Marginalia は、各メモの該当箇所を、その対象だった語句とともに保持します。

- 該当箇所**より前**で文字を追加・削除すると、該当箇所も一緒に移動します。
- 該当箇所の**内側**を編集すると、該当箇所の長さが変わります。
- 該当箇所の**直前や直後**に入力した語句は、該当箇所の外側になります。
- 一語だけの該当箇所で誤字を直した場合は、その語にメモが残ります。

該当箇所が**削除**されたり、書き換えられて見つけられなくなったりすると、メモは**対象なし**になります。メモは残るので、別の箇所に付け直す（**選択範囲に付ける**）か、却下するか、削除できます。語句を元に戻す（取り消し）と、メモは再び該当箇所を見つけます。

パートが**生成し直された**場合、本文は新しくなるため、メモは引用されていた語句をもとに該当箇所を探し直します。対応する語句がなくなったメモは、対象なしになります。2つのパートを[統合](story-editor.md#merging-a-part-into-the-previous-one)した場合、後ろのパートのメモは統合後のパートに移動します。パートの**分岐**では、そのパートのメモもコピーされます。メモは[バックアップ](backups.md)、ブックのコピー、バックアップのエクスポートにも含まれます。
<a id="letting-a-model-annotate"></a>

## AI による注釈の依頼

パートのメニューにある **Annotate with AI** を使うと、モデルにパートを確認してもらえます。確認してほしい点を入力し（*flag continuity errors*、*weak dialogue*、*contradicts the lore* など。空欄の場合は、本、そのフォルダ、または設定で[一度設定した](prompts.md#annotate-prompt)内容を使います。それもなければプロンプトのタスクを使います）、モデルを選んで **Annotate** を押します。

モデルは、[書き直し](story-editor.md#redrafting-a-part)のときと同じようにパートを読みます。読むのは、パート本文、その前の物語（古い部分は[要約](summaries.md)として）、後ろの物語のうち収まる分、本のロアとスタイル、そしてそのパートにすでにある注釈です。これは重複を避けるためです。モデルは位置を示すことはなく、本文の一節を**引用**します。Marginalia がその引用を本文から探します。引用が見つからなかった場合も注釈は失われません。パート全体についての注釈として提案され、*not found in the text*（本文に見つからない）と印が付きます。

**あなたが承認するまで、本には何も追加されません。** モデルが提案した注釈は、それぞれチェックボックス付きで一覧表示されます（初期状態ではすべてチェック済み）。不要なものはチェックを外し、**Add the selected annotations**（選択した注釈を追加）を選びます。

モデルが作業している間、ウィンドウは物語の操作を妨げません。また、ページの隅に折りたたむこともできます。詳しくは [ウィンドウを開いたまま作業する](story-editor.md#working-beside-the-redraft-and-annotation-windows) を参照してください。

| オプション | |
|---|---|
| **Model** | 確認を行うモデル。空欄の場合は、[設定](../account.md#general-settings)の **Default model for annotating**、なければ本のモデルを使います。確認は分析作業なので、文章を書くモデルとは別のものを選ぶことが多いです。 |
| **Answer format** | *Automatic*（モデルが JSON で答えられる場合は構造化）、*Structured (JSON)*、*Text blocks*（形式を守らないモデル向け）、*Free critique, then extraction*（モデルがまず自由な批評を書き、続けて2つ目のモデル（通常はより安価なもの）が注釈に変換します。このモデルは **Model that extracts the notes** で選びます）。 |

![パートに対してモデルが提案した注釈](../../images/annotate-ai-proposals.png)

**パートの範囲（一括）。** パートのメニューにある **Annotate with AI** は、そのパートだけを確認します。複数のパートをまとめて確認するには、物語の設定メニュー（⚙）を開き、**Annotate a range of parts with AI** を選びます（スマートフォンでも可能です）。同じウィンドウで、**From part**（開始パート）と **To part**（終了パート）を選びます。両方とも必須で、どちらが前でも構いません。本文のあるパートだけが一覧に出ます。**Annotate** を押すと、範囲内のパートを順番に確認します。指示、回答形式、モデルは共通で、各パートは単独のパートのときと同じく、前後の物語を含めて読まれます。提案はパートの番号ごとにまとめて表示され、すべてチェック済みです。**Add the selected annotations** を押すと、それぞれの注釈が元のパートに追加されます。**Stop** は、処理中のパートを停止し、次のパートには進みません。それまでに見つかった注釈は一覧に残ります。回答を読めない、またはモデルのコンテキストに収まらないパートはスキップされ（ウィンドウにその旨が表示されます）、処理は続きます。ただし、モデルの失敗は実行全体を終了させます。パートごとにモデルへのリクエストが1回発生するため、範囲が長いほどリクエスト数（とトークン数）も増えます。

![パートの範囲の確認：提案はパートの番号ごとに一覧表示される](../../images/annotate-ai-batch.png)

**拡張機能からの事実。** 物語の本文以上のことを知っている[拡張機能](../extensions/index.md)は、その情報を確認役に渡せます。確認役は、その情報と矛盾する一節を連続性の誤りとして注釈します。[Knowledge Tracker](../extensions/knowledge-tracker.md#annotating-with-what-the-characters-know) がその例です。この拡張機能は、パート開始時点で追跡対象の各キャラクターが何を知っていたかをモデルに伝えます。そのため、聞いたこともない名前を使うキャラクターがいれば、それが注釈されます。これらの事実は、内蔵の [annotate プロンプト](prompts.md#annotate-prompt) に組み込まれています（自分で作ったプロンプトでは `{%{{{facts}}}%}` を使う必要があります）。そのような拡張機能がなければ、プロンプトは従来どおりです。

回答を読めない場合、Marginalia は一度だけ再依頼します。それでも読めない場合は、作業が失われないようにモデルの回答をそのまま表示します。プロンプトは [annotate プロンプト](prompts.md#annotate-prompt) です。

<a id="annotating-every-new-part-automatically"></a>

### 新しいパートを自動で注釈する

物語の設定メニュー（⚙）には **Automatic annotation** があります（スマートフォンでも可能です。オンのときはチェックマークが表示されます）。これを有効にすると、パートが生成された直後に本が自動で確認し、必要に応じて書き直しも行います。設定は本と一緒に保存されます。

| オプション | |
|---|---|
| **Model**、**Protocol** | 確認を行うモデル。空欄の場合は本のモデルを使います（自分で開くウィンドウが最初に使う設定の **Default model for annotating** ではありません）。 |
| **What to look for** | 指示です。**Annotate with AI** と同じです。空欄の場合は、本が引き継いだ内容を使います（[Annotate prompt](prompts.md#annotate-prompt) を参照）。それもなければプロンプトのタスクを使います。空欄のまま開始すると、この欄には使われたテキストが表示されます。 |
| **Annotate every generated part automatically** | オンにします。パートが生成された後（新しいパート、スワイプ、再生成のいずれか。中断または失敗したものは除く）、モデルはウィンドウを開かずに**すぐ**に確認します。[実行パネル](story-editor.md#the-panel-of-the-runs) には、[パートの後に続く処理](story-editor.md#what-follows-a-generated-part) のひとつとして表示されます。 |
| **Add the annotations without asking** | モデルが終わると、見つかった注釈が自動で追加されます。オフの場合、注釈ウィンドウが提案とともに開き（生成したページで開きます。どのページからでも、パネルの **Review** から開けます）、あなたが自分で開始したときと同じく、選択されるまで待ちます。 |
| **Then redraft the part to address the annotations** | 上の項目がオンのときだけ有効です。注釈が追加された後、モデルはそのパートの未解決の注釈を使い、独自の指示なしで[書き直し](story-editor.md#redrafting-a-part)を行います。書き直しには本のモデルを使い、要約には手を加えません。パートは新しく作られたもので、どの要約もそれを説明していないからです。何も見つからなかったモデルは、書き直すものがありません。 |
| **Apply the redraft without asking** | 書き直しがオンのときだけ有効です。モデルが終わると、書き直した文章がパートの本文に置き換わり、対応した注釈は解決済みとしてマークされます。オフの場合、またはモデルが書いている間にあなたがパートを変更していた場合は、結果を表示した書き直しウィンドウが開き、あなたの操作を待ちます。 |

あなたの操作を待つ書き直しウィンドウには、2つのタブがあります。**Redrafted text**（書き直した文章、その推論、パートとの差分）と **Original text with annotations**（元のパート。未解決の注釈の箇所が物語と同じようにマークされており、その下に注釈が並びます）です。マークをクリックすると対応する注釈に移動し、どちらかにカーソルを合わせると両方が強調されます。元の文章を見れば、モデルに何への対応を求めたのかが分かります。そのうえで、文章を変更するか、適用します。

![自動注釈の設定](../../images/annotate-auto.png)

**あなたの操作を待つウィンドウを閉じる、またはパネルの Stop を押すと、そのパートに続く処理も終了します。** それ以上の注釈追加や適用は行われず、後続の処理（翻訳、音声など）も実行されません。パネルのメッセージには、それらの名前が表示されるので、手作業で実行できます。すでに追加または適用されたものはそのまま残ります。書き直しの実行中は、新しいパートを生成できません（古い文章の続きになってしまうためです）。注釈を作成している間は、生成できます。

生成したパートごとに、モデルへのリクエストが少なくとも1回追加で発生します（書き直しをする場合は2回）。キャッシュを1つのプロンプトしか保持しないローカルサーバーで生成している場合、確認によってそのキャッシュの物語が入れ替わるため、次の生成では物語を最初から読み直すことになります。その場合は、確認用の **Model** を別のものにするか、もう1台サーバーを用意してください。

<a id="giving-a-note-to-the-model"></a>

## 注釈をモデルへの指示として渡す

注釈に **Give to the model with the part** のチェックを入れると、その注釈はモデルへの指示にもなります。プロンプトに含まれるパートの注釈は、マスターテンプレートの `{%{{{annotations}}}%}` に入ります（内蔵テンプレートには *Author's notes on the story* というブロックがあります。自分のテンプレートでは、この変数を使う必要があります）。渡されるのは、**未解決**で、このチェックが入っている注釈だけです。また、プロンプトに収まるパートのものに限られます。モデルが続きを書くときに心に留めておいてほしいこと（*this character is hiding the letter*）に使ってください。編集用のメモには使わないでください。

<a id="redrafting-to-address-the-notes"></a>

## 注釈に対応するための書き直し

パートに未解決の注釈があると、[書き直し](story-editor.md#redrafting-a-part) ウィンドウに **Deal with the open annotations of the part** のチェックボックスが表示されます。チェックを入れると、モデルは注釈（一節と注釈の内容）をあなたの指示とともに受け取り、それらに対応するようにパートを書き直します。書き直しを **Apply** すると、それらの注釈は解決済みとしてマークされます。[選択範囲の書き直し](story-editor.md#redrafting-only-a-passage) では、一節が選択範囲と重なる注釈だけが渡されます。
<a id="commands"></a>

## コマンド

[`/list-annotations`](../commands/index.md#annotations)、`/get-annotation`、`/create-annotation`、`/update-annotation`、
`/resolve-annotation`、`/reattach-annotation`、`/delete-annotation` を使うと、コマンドラインから注釈を操作できます。
拡張機能も同じコマンドを使えます。[`/generate-annotation <part>`](../commands/index.md#annotations) は、コマンドとして実行する **AI で注釈を付ける** です。モデルは書籍のモデルを使って（エージェントで *エージェントのモデルで書籍を書く* がオンのときは、エージェント自身のモデルを使います。`profile` を指定すると、エージェントの別のモデルプロファイルを選べます）、書籍の指示・回答形式・プロンプトに従ってパートを確認し、見つけた注釈をすべて一度に追加します。選ぶ人がいないためです。モデルへのリクエストは 1 回だけで、単独で実行され、トークンを消費します。

<a id="annotations-and-agents"></a>

## 注釈とエージェント

[エージェント](../agents.md) も同じコマンドで注釈を読み書きできます。書籍全体に注釈を付けたり（*continuity*、*style* など）、対応済みの注釈を解決したり、注釈を編集・削除したりできます。エージェントは書籍のコピーに対して作業するため、[結果を確認](../agents.md#reviewing-the-result)するまで注釈があなたのノートに反映されることはありません。

- エージェントが作成した注釈は **Annotation - Added** の行になります。解決・却下・書き換えた注釈は **Changed** の行になり（注釈、種類、状態、*give to the model* の各項目にそれぞれ **Take this change** の欄があります）、削除した注釈は **Deleted** の行になります。エージェントが削除したパートの注釈はそのパートと一緒に消え、行は表示されません。
- 行には、注釈がどのパートにあるかが表示されます（`3: ` と注釈の冒頭）。**Show in the copy** を押すと、エージェントのコピーでそのパートが開きます。エージェントが書いたパートの注釈には、そのパートも必要です。注釈にチェックを入れると、パートにもチェックが入ります。
- リストの上にある **Only annotations** にチェックを入れると、注釈だけが選ばれます。取り込んだ注釈の位置は、パートの本文が同じであれば変わりません。エージェントの新しい本文を取り込んだ場合、またはあなたの本文と違う場合は、注釈は書籍の本文の中で元の文言を探し直します。見つからなければ、パート全体についての注釈になります。
- エージェントが一時停止している間にあなたが書いた注釈は、再開時にエージェントのコピーに入ります（解決した注釈もそこで解決済みになります）。そのため、エージェントはその変更を把握できます。あなたとエージェントの両方が変更した注釈は、他の場合と同じく競合になります。
