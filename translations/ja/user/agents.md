# エージェント（実験的）

!!!warning 実験的機能
エージェントは1.4.0で追加されたばかりで、実際のモデルでの利用はまだ少ないです。粗い部分があることを想定してください。たとえば、弱いモデルがツール呼び出しを誤る、想定より多くのトークンを消費する、確認画面の操作が面倒、バージョンによって動作が変わる、といったことが起こりえます。
本はあなたを守るようになっています（エージェントは本のコピーで作業し、結果は確認され、適用前にバックアップが取られます）。ただし、**エージェントの結果を取り込む前には、本のバックアップを自分で取っておいてください**。また、トークンの予算を設定し、最初の数回の実行は[コンソール](#the-console)で見守ってください。何がうまくいかなかったかの報告は歓迎します。
!!!

**エージェント**とは、あなたの本の一つに対して、自分で長時間作業するモデルのことです。許可された[コマンド](commands/index.md)をツールとして呼び出します。たとえば、物語を読み、ロアブックと照らし合わせて確認し、結果を報告できます。**エージェント**タブでは、エージェントを作成し、それぞれができることを設定し、実行の開始と停止を行い、[コンソール](#the-console)でエージェントと話し、複製することができます。

**開始**を押すと、エージェントはバックグラウンドで、一度に一ラウンドずつ作業します。許可されたコマンドと、自身のファイルツールを呼び出しながら、終了する、あなたに何かを尋ねる、上限に達する、またはあなたが一時停止・停止させる、までこれを続けます（[実行](#a-run)を参照）。エージェントは本の隠れた[コピー](#the-working-copy)で作業するため、作業中もあなたの本には一切触れません（本自体は[ロック](#the-book-is-locked)されています）。完了したら、[結果を確認](#reviewing-the-result)し、取り入れたいものを選んで取り込みます。

このタブが表示されるのは、管理者があなたに**エージェント**の[権限](administration/permissions.md)を与えた場合だけです（管理者は常にこの権限を持ちますが、制限は他の全員と同じです。つまり、自分の権限の設定に入力しない限りデフォルトの値が適用されます。エージェントの数、実行数、ワークスペースの容量を増やす必要がある管理者は、そこで設定してください。変更した制限は、実行中の処理が一時停止されて再開されたときに反映されます）。スマートフォンでは、各エージェントが同じボタンを備えたカードとして表示されます。[スマートフォンでの操作](#on-a-phone)を参照してください。

表の上にある二つの入力欄で一覧を絞り込めます。**名前**と**本**では、入力した単語がすべて含まれるエージェントだけが表示されます。単語の順番は問わず、大文字と小文字も区別されません。本の名前で絞り込む場合も同様です。列見出しの**名前**、**本**、**ステータス**、**最終実行**をクリックすると表を並べ替えできます（もう一度クリックすると逆順になります。最終実行を昇順にすると、一度も実行していないエージェントが先頭に来ます）。スマートフォンでは、カードの上にある**並べ替え**の選択肢で、名前、ステータス、または最新の実行が新しい順に並べられます。

行の末尾にあるボタンは、実行の状態によって変わります。

| ボタン | |
|---|---|
| **開始** | メニューを開きます。**すぐに開始**：エージェントは自分の課題（指示内容）に取りかかり、質問があるか完了したときにあなたに知らせます。**コンソールで開始**：[コンソール](#the-console)を開き、エージェントにまだ作業せず、何をしてほしいかをすぐに尋ねるよう伝えます。この場合、実行は**終了**を押すまで続く[会話](#a-run)になります。 |
| **再開** | 一時停止中または停止中の実行を続けます（**開始**の代わりに表示されます）。任意でエージェントへのメモを入力できます。[実行の再開](#resuming-a-run)を参照してください。 |
| **一時停止** | 作業中または、あなたの入力を待っている実行を一時停止します。 |
| **今すぐ一時停止** | エージェントが作業中に表示されます。ラウンドの終了を待たずに一時停止します。[一時停止と停止](#a-run)を参照してください。 |
| **コンソール** | エージェントの[コンソール](#the-console)を開きます。 |
| **停止** | 結果を**保持**（後で実行を再開できます）するか、**破棄**するかを尋ねます。 |
| **編集** | エージェントを開きます。 |
| **複製** | エージェントをコピーします。[複製](#cloning)を参照してください。 |
| **削除** | エージェントを、その実行とともに[ごみ箱](trash.md)に移動します。 |

エージェントが無効になっている場合、モデルがない場合、または同時に実行できる上限に達している場合は、理由とともに開始が拒否されます。

![開始ボタンのメニュー](../images/agent-start-menu.png)

一つのエージェントが同時に終わっていない実行を持てるのは一つだけで、一つの本に割り当てられるエージェントも一つだけです。

## ラン

ランは、エージェントの仕事の単位です。ランは複数のラウンドで進みます。モデルに一度問い合わせると、テキストやツール呼び出しで応答し、その結果が返され、というように繰り返します。
各ラウンドは保存されるため、ランは一時停止して後で再開できます。サーバーを再起動した後でも可能です。エージェントは、あなたが許可したコマンドに加えて、次のツールを使えます:

| ツール | |
|---|---|
| ファイル | `list_files`、`read_file`、`write_file`、`append_file`、`replace_in_file`、`regex_replace_in_file`、`grep_files`、`move_file`、`copy_file`、`merge_files`、`unzip_file`、`delete_file`。これらは、エージェント専用のワークスペース(ラン同士の間で保持されるメモ)内で動作します。ワークスペースの隣には、読み取り専用のファイル `/AGENTS.md` があり、ランの開始時点でのあなたの指示が入っています。エージェントはいつでもこれを読み直せますが、変更はできません。`list_files` と `grep_files` は名前のパターン(`glob`、例えば `*.md` や `chapters/*.md`)を受け取ります。`copy_file` はフォルダをその中身ごとコピーします(メモのバージョンを残す手軽な方法です)。`merge_files` は、複数のファイルを1つに結合します。テキストはモデルを経由しません(パスの最後の名前には `/chapters/*.md` のようなパターンを使えます)。`unzip_file` は、ワークスペース内の [zipファイル](#unpacking-a-zip-file) を新しいフォルダに展開します。`replace_in_file` と `regex_replace_in_file` はパスとしてフォルダも受け取ります。その場合、配下にあるすべてのテキストファイルの、あらゆる出現箇所を変更します(`glob` を指定した場合は、その名前に一致するファイルだけ)。ファイルごとに `path: n replacements` と報告します。エージェントが `dry_run` を false にしない限り、これは**ドライラン**です(何も書き込まれず、報告は何が変わるかを示します)。処理は全か無かで行われます(1つのファイルでも書き込めなければ、どれも変更されません)。また、変更対象のファイルが `max_files`(エージェントが指定しない限り100)を超える場合は、何も変更せずに拒否されます。単一のファイルでもドライランにできます。`list_command_results` と `save_command_result` は、エージェントが書き直さなくても、コマンドの長い結果を保持します。直近10件の結果はそのまま保持され(長すぎるものはエージェントには途中で切られて見えます)、番号を指定して1件をファイルに保存できます(番号を省略すると最新のもの)。その後、そのファイルを `@file:/path` として渡します。 |
| `@file:/path` | ツールではなく、ツールを呼び出す方法です。コマンドのテキスト引数がちょうど `@file:/notes/chapter.md` である場合、エージェントのワークスペースにあるそのファイルの内容に置き換えられます。これにより、エージェントは長い文章を一度ファイルに書き、確認してから、コマンドに渡せます(結果には呼び出しの中の短い参照が表示され、コマンドには本文が渡されます)。`write_file` と `append_file` も内容としてこれを受け取ります。これにより、ファイルのコピーや、別のファイルへの追記ができます。長いファイルは、モデルの最長の応答に収まる長さの部分に分けて書き、この方法でまとめられます。 |
| `@result` | `@file:` と同様ですが、コマンドの結果に使います。テキスト引数がちょうど `@result` である場合、エージェントが最後に呼び出したコマンドの結果全体に置き換えられます。`@result:3` は、その番号の結果に置き換えられます(番号は `list_command_results` で確認できます)。生成されたテキストは、エージェントが書き出さなくても、あるコマンドから次のコマンドへ、あるいは `write_file` や `append_file` へ渡せます。 |
| `search_manual`、`read_manual_page` | Marginalia のユーザーマニュアル(ヘルプアシスタントが読むのと同じページ)で調べます。プロンプトテンプレートやマクロの仕組み、ロアブックの設定の働きなどが対象です。読み取りのみで、すべてのエージェントが使えます。 |
| `view_image` | ワークスペース内の画像ファイル(PNG、JPEG、GIF、WebP)を見ます。画像は次のメッセージでモデルに表示されます。エージェントのモデルが画像を扱えるとマークされている場合(エージェントの **モデルが画像を扱える**)にのみ、このツールがあります。大きな画像は送信前に縮小されます。GIFは最初のフレームが表示されます。モデルの前に残るのは最新の4枚の画像だけです(古い画像は注記に変わり、エージェントは再び見直せます)。画像はあなたから提供されます(**ファイルをアップロード**、または[メッセージに添付](#the-console)したもの)。エージェントが画像を作ることはできません。 |
| コマンド用の画像 | [`generate-lore-entry`](extensions/lore-generator.md#commands) のように、独自のモデルに画像を送るコマンドは、`images` パラメータを受け取ります。これはワークスペースの画像ファイルのパスのリストです(最大8件)。画像を見るのはエージェントのモデルではなく、コマンドのモデルである必要があります。そのため、エージェント自身のモデルが画像を扱えなくても、エージェントは画像を渡せます。 |
| `update_plan` | エージェントの、やることのリストです。 |
| `report` | あなたへの発見事項です(何を見つけたか、どこか、どの程度深刻か: *メモ*、*警告*、*問題* のいずれか)。エージェントは報告の後も作業を続けます。発見事項は[コンソール](#the-console)と[レビュー](#reviewing-the-result)で確認できます。最終報告は別です。1回の呼び出しで1件で、1回のランで最大200件です。 |
| `get_run_status` | 使ったラウンド数とトークン数、コンテキストの残り、書ける最長の応答。その計画。サブエージェントの一覧: 各サブエージェントについて、状態、ラウンド、トークン、直前にした作業、タスクを1行ずつ示します。エージェントは、モデルのこれらの制限についても、プロンプトで知らされています。そのため、長い文章を分けて書けます。 |
| `checkpoint`、`checkpoint_list`、`checkpoint_diff`、`checkpoint_restore`、`checkpoint_delete` | [チェックポイント](#checkpoints)の操作です。作業コピーとそのワークスペースの復元ポイントを(ラベル付きで)保存し、一覧を表示し、ある時点以降の変更点を表示し(設定、パート、ロアブック、本の項目で追加・変更・削除されたもの、およびワークスペースのファイル。パスを指定すると、そのファイルまたはフォルダだけ。テキストファイルの場合は、異なる文を表示します)、ある時点に戻り(ラウンドの終了時に)、不要になったものを削除します。 |
| `get_sync_report` | あなたの変更を取り込んだ再開の後にだけ使えます。ランが一時停止している間に本で行ったあなたの変更と、そのうちエージェントの作業コピーに入ったものを、改めて一覧にします。[ランの再開](#resuming-a-run)を参照してください。 |
| `request_compaction` | 自分のコンテキストを圧縮します。ラウンドの終了時に、それまでの作業の要約を書きます(`/compact` と同じです)。その前に、メモをファイルに保存するよう指示されています。[コンテキストが埋まってきたとき](#running-a-command-yourself)を参照してください。 |
| `ask_user` | あなたへの質問です。ランは待機します(*あなたの入力待ち*)。 |
| `finish` | エージェントの報告です。ランは *完了* になります。報告は状態の理由として表示されます。 |

ランの作業の区切りは次のように終わります:

- **あなたの入力待ち:** エージェントがツール呼び出しなしで応答したか、あなたに何かを尋ねました。[コンソール](#the-console)で答えてください。
- **完了:** エージェントが `finish` を呼び出しました(*即時*に開始したランの場合)。*コンソールで*開始したランは会話です。エージェントの報告は質問のようにあなたに届き、ランはあなたの次のメッセージを待ちます。コンソールの **終了**(または **停止**)によってのみ終わります。*完了*になったランの結果は、あなたの[レビュー](#reviewing-the-result)を待ちます。
- **一時停止**(理由付き): ラウンドの上限、トークンの予算、またはコンテキストの上限に達した場合、モデルに問い合わせられなかった場合(プロバイダーのエラー、AIに対するあなたの上限)、またはサーバーが再起動された場合です。**再開** を押すと、最後に完了したラウンドから続行します。[サーバーが停止したとき](#when-the-server-stops)を参照してください。
- **失敗:** ランナー自体が壊れました。理由に原因が書かれています。

**一時停止** は、ラウンドとラウンドの間で有効になります。モデルへの問い合わせと、進行中のツール呼び出しが、先に完了します。これには長い時間がかかることがあります(遅いモデル、長い生成など)。そのため **今すぐ一時停止** があります。これはモデルへの問い合わせを取り消します。その応答は捨てられます。また、進行中の呼び出しは、そのラウンドのうち通常の呼び出しとして行われなかったものへの応答として扱われ、ランは間もなく *一時停止* になります。捨てられた問い合わせにかかった費用は失われます。通常どおり再開してください。**停止** も同じことをしますが、問い合わせや進行中の呼び出しを待ちません。それらは取り消され、ランはすぐに終わります(あなたの選択に応じて、結果は残すことも捨てることもできます)。

![ランを停止したときの質問](../images/agent-stop.png)

進行中のコマンドには停止が指示されます。停止できるように作られたコマンド(モデルで書き込んだり、検索して置換したりするもの)は、すぐに終わり、それまでの作業結果を残します。停止できないコマンドは、完了することもあります。どちらの場合も、エージェントには、その呼び出しが実行されたかどうかは分からないと伝えられ、続行時には読み取り用のコマンドで状態を確認します。サブエージェントのコマンドも同様に、ランが一時停止・停止された場合、またはすぐにメッセージが送られた場合に取り消されます。

エージェントがモデルの空き枠を待っている間([一つのモデル、複数のエージェント](#one-model-several-agents)を参照)は、*実行中* です。**一時停止** または **停止** を押すと、その待ちはすぐに終わります。
<a id="the-console"></a>

## コンソール

**コンソール** を開くと、エージェントの最新の実行を表示するウィンドウが開きます。タブは八つあります。**実行**、**実行履歴**、**ワークスペース**、**チェックポイント**、**コンテキスト**、**ブックのコピー**、**サブエージェント**、**診断** です。

![コンソールで開始された実行。エージェントが何をするかを尋ねている](../images/agent-console-start.png)

**実行** には *トランスクリプト* が表示されます。あなたがエージェントに伝えたこと、エージェントの返答（どちらも [Markdown](https://commonmark.org/help/) として表示されるので、リストや見出し、強調は書式どおりに見えます）、そしてエージェントが呼び出したコマンドやファイルツールの一つ一つが、引数とともに一行に折りたたまれて並びます。その行をクリックすると、引数と結果（プレーンテキストで表示）が見られます。モデルが **推論**（回答する前に考えたこと）を送ってきた場合は、回答の前に折りたたまれた *推論* ブロックとして表示され、ダウンロードにも含まれます。推論が得られるかどうかは、モデルとサーバーしだいです。モデルとサーバーの両方が推論を報告できる必要があり、さらにお使いのAIで推論が有効になっている必要があります。リクエストが処理されている間、コンソールは、モデルがここまでに書いた内容（推論は、流れを追えるように開いた状態で、そして本文も）を、トランスクリプトの末尾にある *作業中...* のブロックに表示します。その下には待機中のメッセージが並びます。この一回のやり取りが終わると、このブロックは実際のブロックに置き換わります。このブロックが表示されている間、コンソールは実行の内容を二秒に一回読み込みます。それ以外の時は二秒ごとです。この表示方式がとられるのはエージェント本人だけで、そのサブエージェントは対象外です。また、呼び出しの中でモデルが書く内容（たとえば長いファイル）は、そのやり取りが終わってから初めて表示されます。どのメッセージにも、書かれた時刻が最初の行の右側に表示されます（時刻だけの場合もあれば、別の日であれば日付も付きます。完全な時刻はカーソルを重ねると見られます）。これにより、エージェントがどのくらい作業したか、いつ止まったかが分かります。実行の状態、**コンテキスト**（直前のリクエストがモデルの上限のうち何トークンを使ったかを示すので、実行が一時停止にどれくらい近いかが分かります）、使ったラウンド数とトークン数（トークンの予算が設定されていれば、その予算も）は、トランスクリプトの上に表示されたままです。メッセージを入力する欄もその下にあり、トランスクリプトだけがスクロールします。エージェントが待っている内容は、書かれた場所にトランスクリプトの吹き出しとして残ります。実行が進んでも、その吹き出しは残ったままです。

![エージェントの作業中のコンソール。作者のメッセージが待ち行列で待っている](../images/agent-console-run.png)

- **エージェントの質問**。実行が *あなたの入力待ち* のときに出ます。欄に回答を書いて **送信**（または **Ctrl+Enter**）を押すと、エージェントは作業を再開します。
- **エージェントの報告**。エージェントが `finish` を呼び出したときに出ます。

![会話の終わりのエージェントの報告](../images/agent-console-report.png)

![エージェントの質問。提案された回答つき](../images/agent-console-question.png)

![会話の終わりのエージェントの報告](../images/agent-console-report.png)

トランスクリプトの上の行には、実行の状態と数値が表示されます。ラウンド数、上限に対するコンテキストの大きさ、**返信の上限**（エージェントのモデルが一回の回答で書ける最大トークン数です。これを超える呼び出しは途中で打ち切られるので、エージェントは長い文章を分けて書きます）、そして合計のトークン数です。エージェントが計画を立てると（`update_plan`）、その行に **計画** ボタンが現れます。ボタンには **計画 2/5** のように、全体のうち完了した手順の数が表示されます。クリックすると手順がポップオーバーに開きます。各手順には *完了*、*進行中*、*未着手* のいずれかの印が付いています。エージェントが所見を報告すると（`report`）、その件数を示す **所見** ボタン（例：**所見 3**）が現れます。同じように開くと、それぞれの重要度とともに所見が表示されます。所見は実行に紐づけて保存されるので、一時停止や再起動の後も、履歴で古い実行を開いたときにも残っています。実行のMarkdownファイル（**ダウンロード**）には、**所見** という節として含まれます。

![エージェントの所見](../images/agent-console-findings.png)

会話の中では、エージェントが**作業している**間にもメッセージを書けます。そのメッセージは **待ち行列** に入ります。トランスクリプトの末尾に破線の吹き出しとして表示され、エージェントは、いま進行中のラウンドが終わるとすぐにそれを読みます。送信途中のモデルへのリクエストと、すでに行った呼び出しは先に終わります。次のリクエストには、あなたのメッセージがすでに含まれています。待ち行列のメッセージが複数ある場合は、まとめて一度に読まれます。そこまで待つ必要がない場合は、吹き出しの横にある小さな **今すぐ送信**（稲妻のマーク）ボタンを押します。すると、エージェントは進行中のラウンドを打ち切ります（モデルへのリクエストは取り消され、あなたの承認を待っていたコマンドは拒否され、まだ行われていない呼び出しは省略とマークされます）。そのうえで、次にあなたのメッセージを読みます。その隣の **ゴミ箱** ボタンは、エージェントがまだ読んでいないメッセージを取り消します（待ち行列のコマンドも同じです）。すでに実行されたコマンドは、そのまま完了した状態で残ります。待ち行列のメッセージとコマンドは、サーバーを再起動しても保存されます（再開したときに読まれます）。また、会話ではない実行（*すぐに* 開始されたもの）は、作業中にメッセージを受け付けません。

### コマンドを自分で実行する

記録の下には、アプリケーションのコマンド入力欄（ストリーにあるタブで `/` を入力すると、一覧とヘルプが上に表示されます）があり、エージェントに対して実行できるものが並んでいます。`/compact`、`/clear-workspace`、そして読み取りまたはデータ追加のみを行う[エージェントが呼び出せるコマンド](#allowed-commands)です。データを変更・削除するコマンドは表示されません（確認のために本のウィンドウを開く必要があり、実行中にはそれができないためです）。実行するのはあなたであり、エージェントではありません。エージェントには、あなたがコマンドを実行したこと、その応答の内容を、あなたのメッセージとして伝えます（コマンドが作業コピーを変更した場合は、それ以前に読んだ内容が古くなっている可能性があることも伝えます）。そのため、エージェントが実行していない呼び出しを実行したと思い込むことはありません。コマンドはメッセージとして扱われます。実行が待機中（*あなたの入力待ち*）または*一時停止*の場合、コマンドはすぐに実行され、実行はそのまま続きます。[会話](#the-console)が進行中の場合は、*コマンド*と書かれた破線の吹き出しとしてキューに入り、エージェントのターンの終わりに実行されます。エージェントが待機していたはずの場所で実行されるため、エージェントはそのために先へ進むことはありません。吹き出し上の小さな**今すぐ実行**ボタンを押すと、エージェントがいるラウンドを破棄してコマンドを実行し、その後エージェントを先へ進めます。時間のかかるコマンドは入力欄を占有するため、エージェントに書き込む前に完了を待ってください。

![作成者によるコンソールでのコマンド：/compact](../images/agent-console-command.png)

**`/compact [重視する内容]`** は文脈を解放します。エージェントはこれまでのすべてを読み、要約を書くよう求められます（依頼内容、完了したこと、見つけたこと、メモと計画、これから行おうとしていたこと）。その要約が、モデルが読む内容のうち、それ以前のすべてに置き換わります。記録上は、すべてが残っており、要約は折りたたまれたブロック**これまでの作業の要約**として表示されます。エクスポートにも残ります。コマンドの後に続く文字列があれば、それが要約で重視される内容になります。要約の依頼はエージェント自身のものであり、そのトークンは実行のトークンとして数えられます。エージェントに投げかける質問は、その**圧縮プロンプト**です。エージェントに設定されたもの、なければ[設定](account.md#templates)で指定した既定のもの、なければ管理者のもの、それもなければ組み込みのものが使われます。文脈がすでに満杯で依頼が収まらない場合は、古いメッセージから順に依頼から除外されます（要約にその件数が記載されます）。文脈がいっぱいになる前に実行してください。使用量の行で、どれくらい近いかを確認できます。圧縮直後に表示される文脈の量は、次のリクエストに含まれるもの（要約、システムプロンプト、ツールの定義）の推定値です。圧縮後にモデルが最初に返す応答で、実際の数値に置き換わります。

**文脈が一杯に近づいている場合。** モデルの文脈がその上限の75%を超えると、エージェントはラウンドごとに通知を受け取ります（実行のメッセージとして記録に表示されます）。そこには、どれくらい埋まっているか、失いたくないものをワークスペースのファイルに保存すること、計画を更新して `request_compaction` を呼び出すことが書かれています。90%を超えると、文脈が埋まった時点で実行が停止すると通知されます。エージェントが、その定義の**圧縮開始**の割合（指定しなければ90%）を超える前に圧縮を行わなかった場合、実行が自動的に圧縮します。同じ圧縮ですが、要約は「自動的に圧縮されました」で始まり、エージェントには追加の通知は行われません。失敗した圧縮は何も変更せず、その旨がエージェントに伝えられます。実行は、数ラウンド後に再試行します。エージェントが要求する圧縮は、あなたが実行するものと同じです（その**圧縮プロンプト**は[エージェントの作成と編集](#creating-and-editing-an-agent)を参照してください。トークンは実行のトークンとして数えられます）。失敗した場合は何も変更されず、エージェントに伝えられます。通知には文脈の上限が必要です。上限はエージェントに設定された上限と、そのモデルの制限のうち、低い方が使われます。

**モデルサーバーが読み取れなかった呼び出し。** モデルが呼び出しの中で長い文章を書くと、その応答が文章の途中で終わることがあります（*1回の応答*の上限、プロトコルの**応答トークン**、または AI の**最大完了トークン**に達した場合、どちらも設定されていなければサーバーの既定値が適用されます。あるいはモデルが単に止まった場合です。文脈がどれだけ埋まっていても、これは別の上限です）。その結果、サーバーは不完全な呼び出しを拒否します（「Failed to parse tool call arguments as JSON」）。同じ会話でもう一度尋ねても同じ誤りを繰り返すだけなので、実行は一時停止せず、エージェントに対して、最後の応答が使えなかったこと、何も行われていないこと、長い文章はワークスペースのファイルに数回に分けて書くことを、記録上で伝えます。その後、連続して最大3回まで再度尋ねられます。それでも失敗が続く場合は実行が一時停止します。伝えられた内容は記録に残るため、**再開**すると、失敗したものとは別の問いかけが行われます。サブエージェントの場合も同じです。

切り捨てられた呼び出しでも、アプリケーションに届いたもの（呼び出し結果に「not valid JSON ... cut off in the middle」と書かれたもの）は、モデルが書いた状態のまま記録に残るので読むことができます。ただし、モデルに送り返すときには引数が空の状態になります。前の呼び出しを再度読み込むサーバーは、そうしないと以後のすべてのリクエストを拒否してしまい、巻き戻しなしでは実行を続けられなくなるからです。

**暴走する呼び出し。** モデルは一つの応答の中で同じ呼び出しを何百回も書くような無限ループに陥ることがあります。その結果は次のリクエストの前に文脈を埋め尽くしてしまいます。実行は一つの応答につき最大32件の呼び出しを行い、読み取りのみを行う呼び出し（同じツールで同じ引数、同じ応答内）の繰り返しは一度だけ実行されます。除外された呼び出しは記録に含まれず、エージェントにはその旨の通知が届きます。

**同じことを繰り返すとき。** モデルは、多くの応答にわたって同じ調べものを繰り返すこともあります（ファイルの一覧やルアーブックの一覧など）。結果も同じままで、何も前進しません。実行はこれを監視します。エージェントが、何も探さず、何も変えず、以前と同じ（同じ呼び出し、同じ結果）ラウンドを続けた場合、三回目で「何も変わっていない」と伝えられます。それでも続けると、五回目でそのリクエストの間だけツールが取り上げられます。エージェントは、何をしていたのか、何が妨げになっているのかを平文で答えなければならず、実行はその答えを最後のメッセージとして**一時停止**します。こうして、無駄に百ラウンド以上費やす前に、なぜ止まっていたのかを確認できます。**再開**（または書き込み）するとツールが戻り、数え直しになります。何かが変わったラウンドや、サブエージェントが作業中のラウンドは数えません。繰り返すサブエージェントも同様に停止し、その発言は、それを開始したエージェントへの回答になります。

**`/clear-workspace [残す内容]`** は、実行の[ワークスペース](#the-working-copy)のファイルとすべてのフォルダを削除します（ワークスペースのボタンと同じく、確認後に行われます）。残すものは、スペースで区切って後ろに指定します。ファイル、フォルダ（中身ごと）、または `*.md` や `chapters/*.md` のようなパターンを指定できます。スペースを含むパスは、二重引用符で囲みます（`/clear-workspace /notes.md "/my drafts" *.png`）。残したファイルの上位フォルダは残ります。指定したものがない場合、何も削除されません。`/AGENTS.md` とチェックポイントは、ワークスペースの一部ではないため、決して変更されません。エージェントには、何が削除され、何が残されたかが伝えられます。記録では、あなたが実行したコマンドは、コマンドとその応答を含む吹き出しとして表示されます。

モデルのエージェントが画像を認識できる場合（[エージェントの作成と編集](#creating-and-editing-an-agent)を参照）、**画像を添付**は**送信**の横にあります。PNG、JPEG、GIF、WebP のファイルを選ぶか、クリップボードの画像をメッセージ入力欄に貼り付けます（**Ctrl+V**）。画像は、送信するまで入力欄の上で待機します（×で取り消せます）。メッセージ一つに付けられる画像は最大8枚です。本文は空でもかまいません。画像はワークスペースの**uploads**フォルダに保存されます（同名のファイルがある場合は番号が付きます：`map-2.png`）。保存はワークスペースの制限と規則に従います。モデルには、あなたのメッセージとともに画像が見せられます。不要になったら、**ワークスペース**タブで削除してください。

下部のボタンは、**一時停止**、**再開**、**停止**です。これらは表の通りに動作します。また、あなたを待っている実行を終えるための**終了**（作業が終わり、*完了*になります）があります。

ウィンドウは、開いている間、実行の状態を2秒ごとに確認します。**更新**を押すと、すぐに確認します。**実行**タブには、破棄されていない最新の実行が表示されるので、完了または失敗した実行も、エージェントが新しい実行を始めるまではそこで読めます。それ以前の実行は**実行履歴**にあります。

**実行履歴**は、エージェントのすべての実行の履歴です。新しいものが上に来るように並び、日付、状態、ラウンド数、トークン、結果が表示されます。目のアイコンで実行を**開く**と、**実行**タブでそのステップと報告をもう一度読めます（開いた実行は、別のものを開くまでそこに残ります）。矢印アイコンで、その実行の記録を Markdown ファイルとして**ダウンロード**できます（誰が何をいつ言ったか、すべてのコマンドとその引数・結果、報告、サブエージェントの会話を含みます）。ゴミ箱アイコンで**削除**できます。削除された実行は[ゴミ箱](trash.md)に移動します。実行中のものは削除できないので、まず停止してください。停止して**破棄**した実行も一覧に残るので、何をしたかを読んだり、削除したりできます。**実行**タブには、それらを開いたときにだけ表示されます。

![実行履歴タブ](../images/agent-runs.png)

**ワークスペース**には、エージェントのファイルが表示されます。これらはメモや報告で、実行の間も保持されます。フォルダをクリックすると中に入ります（**上へ**で戻ります）。テキストファイルをクリックすると読めます。矢印でファイルをダウンロードし、ゴミ箱で削除できます。**クリア**はすべてを削除します（古いメモは新しい実行を誤らせるため）。**新しいフォルダ**は開いているフォルダの中にフォルダを作成し、**ファイルをアップロード**は、あなたのコンピューターからそこにファイルを置きます。これによって、ブリーフ、スタイルガイド、下書きをエージェントに渡せます。エージェント自身のファイルと同じ規則が適用されます。名前に `\ < > : " | ? *` を含めることはできず、末尾にピリオドや空白があるものも、長すぎたり階層が深すぎたりするものも不可です。ファイルサイズとファイル数の上限も適用されます。アップロードするファイルはテキスト（UTF-8）である必要があります。エージェントが読めるのはテキストだけだからです。画像（PNG、JPEG、GIF、WebP。名前ではなく中身で判別されます。5 MBまで。合計とファイル数にも他のファイルと同じく数えられます）、またはZIPファイル（10 MBまで。そのまま保存され、エージェントが展開します。[下記](#unpacking-a-zip-file)を参照）もアップロードできます。アップロードでファイルが置き換わることはありません。古いファイルを先に削除してください。エージェントが作業中はファイルを変更できないため、先に一時停止してください。ワークスペースにはサイズ、ファイルサイズ、ファイル数の上限があり、管理者が[権限](administration/permissions.md#settings-of-a-permission)で設定します。表の下の行には、どれだけ使われているかが表示されます。上部の `AGENTS.md` という名前は、あなたの指示であり、エージェントはそこで読めます（このファイルは書き込みも削除もできません）。

### zipファイルの展開

多数のファイル（たとえば原稿の複数の章）をエージェントに一度に扱わせたいときは、**ワークスペース**タブでzipファイルを**ファイルをアップロード**からアップロードし、展開を依頼してください。エージェントにはツール `unzip_file` があり、`/uploads/draft.zip` を新しいフォルダ `/uploads/draft` に展開します（別のフォルダを指定することもできます。そのフォルダはまだ存在しないことが必要です）。展開は全部成功するか、全部失敗するかのどちらかです。また、アーカイブは決して信頼されません。

- テキストファイル（UTF-8）、画像（PNG、JPEG、GIF、WebP）、zipファイルのみが残ります。それ以外のエントリは除外され、エージェントへの回答でその名前が示されます。内部にあるzipファイルは、単独で展開されることはなく、そのまま保存されます。
- ファイルは、ワークスペースに空きがあるサイズ（容量、ファイルサイズ、ファイル数）に収まる必要があります。収まらない場合は、何も展開されません。
- 次のいずれかに該当するアーカイブは、全体が拒否されます。フォルダの外に出るエントリ（`../x`）や `/` で始まるエントリを含むもの。同じ名前が2つある（大文字と小文字の違いを含む）もの。ファイルとフォルダの両方になる名前があるもの。5 000件を超えるエントリがあるもの。暗号化されているもの、または破損しているもの。
- zip爆弾は拒否されます。ワークスペースに収まらない量に展開される、または元のサイズの100倍を超える量に展開されるアーカイブがこれにあたります。

## サブエージェント

エージェントは仕事を**サブエージェント**に渡すことができます。サブエージェントは、独自の会話を持つ補助役で、一つの作業を行い、テキストで回答します。エージェントが持つコマンドやファイル（または[下記](#models-for-sub-agents)のとおり、それが動作するモデルのもの）を使い、同じ作業コピーとワークスペースで作業します（本に加えた変更は残ります）。ただし、エージェントの会話は知らないため、エージェントはタスクの中ですべてを伝える必要があります。サブエージェントが読んだり試したりした内容はエージェントのコンテキストに入らないのが狙いです。たとえば、章の確認、名前の監査、部分の下書きなどに使います。

[エージェント](#creating-and-editing-an-agent)の**サブエージェントの最大数**に、同時に作業できる数を設定します。0（既定値）はなしで、エージェントにはサブエージェントが存在することすら知らされません。

- **1** の場合、エージェントはサブエージェントを開始し、それが終わるまで待機します（*一時停止*状態になります）。呼び出しはサブエージェントの回答を返します。
- **2 以上** の場合、サブエージェントの開始はすぐに戻り、エージェントは先に進めます。さらに別のサブエージェントを開始したり、状態を確認したり（`agent_status`）、回答を待ったり（`await_agent`）、停止したり（`cancel_agent`）できます。上限に達した呼び出しは、いずれかが終わるまで待ち、終わったものの結果を返します。

どちらの場合にも共通する規則は次のとおりです。

- サブエージェントは**ワークスペース全体を読めますが、書き込みは自分専用のフォルダ内に限られます**。フォルダは `/tmp/sub1`、`/tmp/sub2` などで、サブエージェントの開始時に作られます。同じ名前のフォルダに前回の実行が残したものは削除されます。回答は `result.md` として同じフォルダに保存されるので、長い回答が途中で切れて表示された場合、エージェントはこのファイルから全文を読みます。これらのファイルは**ワークスペース**タブで確認できます。ワークスペースの容量の一部を使い、クリアするまで残ります。
- サブエージェントは、エージェントが別のモデルを指定しない限り、エージェントのメインモデルで動作します。[サブエージェント用のモデル](#models-for-sub-agents)を参照してください。
- データを変更するサブエージェントのコマンドは、エージェントの**破壊的コマンド**の設定に従います。*先に確認する*の場合、同じ[ウィンドウ](#asking-you)があなたに確認し、そのサブエージェントはあなたの回答を待ちます（実行の一時停止は拒否扱いになります）。
- サブエージェントは**サブエージェントを開始すること**、**実行を終了すること**、**あなたに質問すること**、**チェックポイントを作ること**はできません。サブエージェントは、テキストで回答することで終わります。
- すべては**実行の共通予算**に計上されます。ラウンド数、トークン数、モデルの上限などです。上限に達したサブエージェントは失敗し、その旨を伝えます。すると、エージェントも同じ上限に達します。
- モデルへ同時に送られる要求の数は、管理者が設定した**モデルへの同時要求数**（未設定の場合は1）で決まります。1の場合、エージェントとサブエージェントは順番に使います。
- 本やワークスペースを変更する呼び出しは、誰が行うかにかかわらず一度に一つずつ行われます。そのため、二つのサブエージェントが同時に書き込むことはありません。ただし、同じ部分を変更するよう二つのサブエージェントに指示しないでください。
- **実行を一時停止すると、サブエージェントも一時停止します。** サブエージェントは次の安定した地点（二つの要求の間、または二つの呼び出しの間。すぐに一時停止した場合は直ちに）で停止します。言ったことと行ったことは実行とともに保存されるため、**再開**すると、すべてが中断した地点から続きます。サブエージェントは会話を続け、サブエージェントの終了を待っていたエージェントの呼び出し（`await_agent`、または上限が1の`spawn_agent`）は、何事もなかったかのように再び待機します。一時停止の前にすでに終わっていたサブエージェントは残っており、エージェントが問い合わせることができます。実行を停止して保存する場合も同じように扱われます。破棄する場合、チェックポイントに戻す場合（サブエージェントが作業していた本が置き換えられる）、エージェントが終了する場合、またはあなたに何かを尋ねる場合は、サブエージェントは完全に終わります。サブエージェントがまだ作業中にターンを終えたエージェントには、一度だけ通知されます。それでも同じことを繰り返した場合、サブエージェントは停止されます。
- サブエージェントの会話は**実行**タブには表示されません。コンソールの**サブエージェント**タブに表示されます。上から一つ選ぶと、エージェントが伝えた内容、サブエージェントの発言、呼び出したコマンドとその結果、そして終わり方（与えた回答、または失敗・キャンセルの理由）を、トランスクリプトと同じブロック形式で読めます。実行中は追従して更新され、古い実行のサブエージェントも表示されます（先に**実行履歴**タブでその実行を選んでください）。**実行**タブの`spawn_agent`呼び出しには**サブエージェント**ボタンがあり、その会話を開きます。エージェントが巻き戻した（ロールバックした）会話は灰色で表示され、*エージェントは忘れました*と記されます。実行の**ダウンロード**（**実行履歴**タブ）には、サブエージェントごとのセクションがあり、タスク、状態、すべてのメッセージと呼び出しが含まれます。

### サブエージェント用のモデル

エージェントには一つの**メインモデル**があり、ダイアログの上部で選びます。**サブエージェント用のモデル**の下に、ほかのモデルを追加できます。たとえば、読むだけの安価なモデルや、下書きに優れた流暢なモデルなどです。各モデルには、**役割**（名前）、**説明**（いつ使うか。エージェントが選ぶときに読みます）、AIとプロトコル、任意の**コンテキスト上限**、そして使用できるものを設定します。

![サブエージェント用のモデル](../images/agent-models.png)

- **コマンドとツールを使える。** オフの場合、このモデルのサブエージェントはテキストで回答するだけで、コマンドもツールも与えられません。
- **コマンドを制限する。** オフの場合、このモデルのサブエージェントはエージェントのコマンドをすべて使えます。オンの場合は、チェックしたものだけが使え、さらにそのうちエージェントに許可されたものだけになります（エージェントに許可されたコマンドが上限のままです）。ファイルを扱うツールはコマンドではないため、どのサブエージェントも必ず使えます。メインモデルにも同じ設定があり、そこで動作するサブエージェント向けです（その行の**編集**ボタン）。

エージェントには各モデルの役割、説明、コマンドが伝えられ、`spawn_agent`の`profile`を指定してそのモデルでサブエージェントを開始します。省略すると、そのエージェント自身のモデルになります。チェックボックス**サブエージェントをメインモデルで実行してよい**（既定でオン）は、この最後の選択肢をオフにします。この場合、エージェントは別のモデルを指定しなければならず、指定がなければサブエージェント用のツールは一切与えられません。サブエージェントには、それぞれのモデル自身の上限（読める量や回答の長さなど）が適用されます。**サブエージェント**タブと診断では、各サブエージェントがどのモデルで動作したかがわかります。
<a id="one-model-several-agents"></a>

## 1モデル、複数のエージェント

ローカルサーバーは、多くの場合スロット（GPU）が1つしかありません。同時に2つの回答を求めると、両方とも遅くなるか、タイムアウトします。[モデル](inference-providers.md#general-settings)の**接続数**（指定しなければ1）により、そのモデルへのすべてのリクエストは順番待ちになり、届いた順に処理されます。対象はあなたのエージェントの要求、他のユーザーのエージェントの要求、そして物語ウィンドウでのあなた自身の執筆です。待機中の実行は*実行中*のままで、**一時停止**または**停止**を押すと待機がすぐに終わります。モデルの1回の応答と次の応答の間、エージェントは接続を保持しないため、その間にあなたの生成を割り込ませることができます。

<a id="when-you-are-not-there"></a>

## あなたがいないとき

あなたを必要とするエージェント、または完了・失敗したエージェントは、開いているアプリケーションの画面に知らせます（タブのバッジや通知）。開いている画面が1つもないときは、管理者が[権限*通知*](account.md)を付与している場合（管理者は必ず持っています）、[設定](administration/permissions.md)で指定したアドレスに短いメッセージを送ることもできます（「エージェントが助けを必要とするとき、URLにメッセージを送る」）。指定できるのは、**ntfy**のトピック（スマートフォンのntfyアプリにすぐ表示されます）、**Gotify**のメッセージURL、または**Discord**のWebhookです。サービスが求める**形式**を選んでください。**テストメッセージを送る**は、入力欄の内容でそのまま送信を試します。メッセージにはエージェントの名前と、その要求内容（「あなたの応答を待っています」「完了しました」「コマンド ... の承認を求めています」「失敗しました」「一時停止されました：理由」）が、あなたの言語で書かれます。**アプリを開いているときも送る**を有効にすると、アプリが開いていても必ず送信されます。

通知の送信はサーバーが行うため、管理者は全員に対してこの機能をオフにできます（管理画面の*エージェント*）。また、管理者があなたの権限で**このマシンとプライベートネットワークのアドレスを許可**にチェックを入れない限り、呼び出されるのはインターネット上のアドレスだけです。同じマシンや自分のネットワーク上のntfyやGotifyを使いたい場合は、管理者に依頼してください。アドレスが拒否された場合は、テストメッセージでその旨が表示されます。アドレスに秘密情報が含まれる場合は、パスワードと同じように扱ってください。そのアドレスを知っている人は、送信される内容を読むことができます。サーバーはアドレスをログに書き込まず、リダイレクトにも従わず、`http`と`https`のアドレスにのみ接続します。

<a id="asking-you"></a>

## あなたへの問い合わせ

エージェントがあなたを必要とするとき、アプリのどこにいてもそれが伝えられます。

- **エージェントタブの数字**は、あなたの応答を待っているエージェントの数を示し、そのようなエージェントの**コンソール**ボタンは強調表示されます。
- **通知**がポップアップし、そのエージェントのコンソールを開く**開く**ボタンが付いています。

エージェントがあなたを必要とするのは、*あなたに何かを尋ねるか、次のメッセージを待っている*とき、コマンドの**承認**を求めるとき、*完了*したとき、*失敗*したとき、または*自ら一時停止*したとき（上限に達した、モデルに問い合わせられなかった、サーバーが再起動された）です。あなたが自分で依頼した一時停止は、これに含まれません。

エージェントはあなたが離れている間も作業を続けるため、これはアプリが開いているかどうかに関係ありません。数字はログインし直したときにも残っており、開いているすべてのブラウザーウィンドウに通知が届きます。エージェントのコンソールを開くと、その通知は消えます（他のウィンドウも更新されます）。

エージェントが**先に確認する**に設定されていて、データを変更または削除するコマンドを実行しようとすると、実行は*承認待ち*で止まり、コンソールの上にコマンドとその引数を示すウィンドウが表示されます。**承認**を押すとコマンドが実行され、**拒否**を押すとエージェントに拒否したことが伝えられ、エージェントは作業を続けます。実行を一時停止または停止した場合（またはサーバーを停止した場合）は、拒否とはみなされません。エージェントには何も伝えられず、**再開**すると同じコマンドについてウィンドウが再び表示されます。コマンドは引き続き本の[作業用コピー](#the-working-copy)に対して動作します。コンソールが閉じられている場合でも、コンソールを開けばすぐにウィンドウが表示されます。

![コマンドの承認を求めるウィンドウ](../images/agent-approval.png)

<a id="when-the-server-stops"></a>

## サーバーが停止したとき

サーバーを停止すると、作業中の実行は**今すぐ一時停止**と同様に一時停止されます（サーバーには数秒の猶予が与えられます）。進行中のリクエストと呼び出しは中止され、実行は理由「サーバーが停止されました」付きの*一時停止*になり、**再開**で続きから進めます。サーバーが強制終了またはクラッシュした場合は、次回の起動時に、作業中だった実行が「サーバーの再起動により中断されました」という理由で一時停止されます。実行が行ったことはすべて保持されます。保存済みのラウンド、コピー、ワークスペース、キューに入れたメッセージやコマンドがそれにあたります。失われるのは、完了しなかったラウンドだけです。再開時には、実行が途中だった呼び出しが次のように扱われます。

- **まだ開始されていなかった**呼び出し（あなたの承認を待っていた、または別の呼び出しの後の順番を待っていた）は、もう一度実行されます。そのため、承認が必要なコマンドは、再び承認を求めてきます。読み取りだけを行う呼び出しも、もう一度実行されます。
- **何かを変更し始めていた**呼び出しは、一部だけ完了している可能性があります。エージェントには結果が不明であることが伝えられ、繰り返す前に読み取り用のツールで結果を確認します。その後の呼び出しは「実行されなかった」と印が付けられます。
- サーバー停止時に実行中だったあなたのコマンドは、実行の再開とともに続行されます。`/compact`と`/clear-workspace`はもう一度実行されます。それ以外の、すでに開始されていたコマンドは**もう一度は実行されません**（一部だけ完了している可能性があるため）。エージェントにはその旨が伝えられ、結果を確認します。その後に届いたメッセージやコマンドは、通常どおり配信されます。
- エージェントの計画と、そのコマンドの結果（`list_command_results`、`@result`）も保持されるため、再起動後もエージェントはそれらを利用できます。
- 進行中だったサブエージェントの呼び出しも、エージェント本体と同じように扱われます。開始されていなかったものは実行され、開始済みのものは「結果不明」としてサブエージェントに報告されます。あなたの承認を待っていたサブエージェントは、再び承認を求めます。
- コマンドの実行中にサーバーが**強制終了**された場合（`kill -9`、停電など）、そのコマンドも同時に終了します。実行された内容は上記のとおりです。
<a id="the-working-copy"></a>

## 作業コピー

実行のたびに、アプリは開始時点で書籍とそのロアブックのコピーを作成し、そのコピーに対して作業します。コピーの内容は、その時点での書籍のメッセージ、要約、タグ、設定と、ロアブックおよびそのサブロアブックです。このコピーは非表示で、書籍やロアブックの一覧には表示されません。エージェントが何をしても、その変更はコピーに対して行われ、書籍は元のままです。

エージェントの**Write the book with the model of the agent**（エージェントのモデルで書籍を書く）がオン（既定値）の場合、実行が開始または再開されるたびに、コピーには書籍の AI とプロトコルの代わりに、エージェントの**モデル**（メインのモデルプロファイルの AI とプロトコル）が設定されます。そのため、モデルを使って書き込むコマンド（`/next`、`/swipe`、`/regenerate`、`/redraft-part`、`/generate-annotation`、要約）や、拡張機能のモデルコマンド（Lore Generator、Arc Outline）は、書籍が別のモデルに設定されていても、またはモデルが未設定でも、エージェントのモデルを使います。ただし、呼び出しで指定された `profile` が優先されます。この設定がオフの場合は、書籍のモデルを使います。これは書籍の変更ではありません。レビューには表示されず、結果を適用しても書籍の AI とプロトコルはそのままです。

コピーは書籍の[フォルダ](books/folders.md)に配置されるため、エージェントは書籍と同じく、フォルダが設定する言語、テンプレート、視点、時制、文体、プロンプトを使って書きます。コピーはフォルダの内容ではないため、フォルダの件数には数えられず、その中の作業もフォルダの*Last modified*を変更しません。一時停止中に書籍を移動した場合、コピーも書籍に従って移動します。結果を適用しても、書籍が移動することはありません。

一時停止された実行はコピーを保持し、再開するとそのコピーで作業を続けます。*Done*（完了）の実行、または停止して保持された実行も、[結果を採用するか破棄する](#reviewing-the-result)までコピーを保持します。実行が*Failed*（失敗）になった場合、結果を破棄した場合、または変更を適用した場合は、コピーは完全に削除され、次の実行では、その時点の書籍から新しいコピーが作成されます。

<a id="resuming-a-run"></a>

## 実行の再開

一時停止中または保持中の実行は書籍のロックを保持しないため、その間も書籍を編集できます。実行を**Resume**（再開）すると、その作業コピーは、あなたが行った変更に追いつきます。

- あなたが変更し、エージェントは変更しなかった内容（パート、ロアブックのエントリ、設定、タグなど）は、コピーに反映されます。あなたが追加したパートも反映され、エージェントはそれを土台にして作業できます。あなたが削除したものは、コピーからも削除されます。
- あなたとエージェントの両方が、異なる文章に変更した内容は、**エージェントが持っている状態のまま**残ります。エージェントが行ったことは何も失われません。これは[競合](#reviewing-the-result)であり、結果をレビューする際に両方の文章を並べて見ながら解決します。
- あなたが変更し、エージェントが削除した内容は削除されたままになり、あなたが削除し、エージェントが変更した内容はコピーに残ります。どちらもレビューに表示されます。

操作は不要です。同期は再開の一部として自動的に行われ、数秒かかります（数百件を変更していた場合はもう少しかかることもあります）。同期の前のコピーの状態は、自動の[チェックポイント](#checkpoints)として保存されます。エージェントには、何が起きたかが、エージェントが項目を認識している名前で伝えられます。作業を再開するメッセージの中で「一時停止中にユーザーが書籍を変更しました…」と知らされ、`get_sync_report` を使って改めて確認することもできます。

**競合は自然には解消されません。** 再開するたびにコピーと書籍が比較されるため、競合は毎回報告され、エージェントにも毎回伝えられます。解決するまでこれが続きます。解決するには、書籍側の自分の変更を（エージェントの文章に合わせるか、元の内容に戻すかして）直すか、レビューで解決します。

**再開時のメモ。** **Resume**（再開）を押すと、*Note for the agent (optional)*（エージェントへのメモ（任意））という欄がある小さなウィンドウが開きます。ここに書いた内容は、書籍への変更の報告の後に、エージェントが作業を再開して最初に読む内容になります。方向転換を伝えるためのもの（「ロアブックには触れないで」「第3章から始めて」など）で、会話へのメッセージとは異なり、ユーザーの入力を待たない実行でも使えます。何も書かなければ、これまでどおり再開されます。

![メモを付けて実行を再開する](../images/agent-resume.png)
<a id="reviewing-the-result"></a>

## 実行結果を確認する

実行が**完了**した場合(または**停止して結果を残す**で止めた場合)、エージェントの行とコンソールに**変更を確認**ボタンがあります。これを押すと、エージェントが変更したものすべてを、ブックの**現在の状態**と比べて1行ずつ表示するウィンドウが開きます。エージェントが所見を報告していた場合は、変更の上に**所見 (3)**として一覧されます。そのため、何も変更しなかった監査でも確認できる内容があります。

![実行結果の確認](../images/agent-review.png)

- **ブック:** 名前、説明、言語、視点、時制、文体、テンプレート、パートごとに保持するバージョン数、タグ、そして拡張機能がブックに保存しているデータ(アークのアウトラインやキャラクタートラッカーなど)。
- **パート:** エージェントがテキスト、指示、シーン設定、視点キャラクター、登場キャラクター、要約のいずれかを変更したパート、エージェントが書いたパート、エージェントが削除したパート。生成がパートとともに保持する変数(および拡張機能のデータ)は、**データ**という項目として一緒に引き継がれます。
- **ロアブック**と**エントリ**: エージェントが作成した、変更した(移動、名前変更、タグやサブブックの変更を含む)、または削除したロアブックやエントリ。
- **注釈:** エージェントが作成した、変更した(メモ、種類、状態)、または削除した、パートの一節に付けた[メモ](books/annotations.md#annotations-and-agents)。

取り込みたい行にチェックを入れてから、**選択した変更を適用**を押します。一覧の上のボタンで、**すべて**、**なし**、**新しいパートのみ**(エージェントが書いた新しい分岐のみで、それ以外は含まない)、**注釈のみ**、または**競合を除くすべて**にチェックを入れられます。ある行が別の行を必要とする場合(新しいパートが、それに続くパートも新しい場合は、そのパートを必要とする)、チェックを入れると一緒に選ばれ、チェックを外すとそれに続く行も外れます。行をクリックすると右側に表示されます。そこには、ブックの現在のテキストと、書き込まれる予定のテキストがあり、適用前に**編集できます**。何も書かなければ、エージェントのテキストが適用されます。

実行の開始後にブックが変更されている場合があります(エージェントが作業中でなければ、いつでも編集できます)。あなただけが変更した内容は一覧に含まれず、そのまま残ります。両方が同じ内容に変更した場合は、変更なしとして扱われます。両方が**異なる**テキストに変更した場合は**競合**となります。競合の行は初期状態ではチェックが外れており、チェックを入れると、右側に表示されているテキストがブックのテキストに置き換わります。**ブックの内容を使う**を押すと、ブックのテキストが入力欄に入ります(その行はその項目について何も変更しなくなります)。**エージェントの内容を使う**を押すと、エージェントのテキストに戻ります。あるいは、結果を自分で書くこともできます。引き継げない行(それが続くパート、またはそれが含まれるロアブックがブックから削除されている場合)には、その旨が表示され、チェックできません。

![変更の確認での競合](../images/agent-review-conflict.png)

テキストの下にある**差分**には、何がどのように変わるかが**単語単位**で表示されます。ブックに現在しかない部分は赤で取り消し線が付き、適用されるテキストにしかない部分は緑で表示されます(入力欄に書いた内容に従って変わります)。競合の場合は、エージェントが変更した内容と、実行開始後にあなたが変更した内容も、それぞれ当時のブックを基準に表示されるので、誰が何をしたかが分かります。エージェントが複数の点を変更した行(テキストとシーン設定の両方が変わったパート、新しい内容とメモの両方が変わったエントリなど)には、それぞれの横に**この変更を取り込む**のチェックボックスがあります。一つのチェックを外すと、その項目を除いて行を適用し、ブックは自分の値を保持します。パートの物語内での位置はそのパートに付随し、チェックボックスはありません。エージェントが作成または削除したものは、全体として取り込むか、取り込まないかのどちらかになります。**コピーで表示**(エージェントが作成または変更した行で使用)を押すと、そのパートまたはエントリの位置で[ブックのコピー](#the-copy-of-the-book)が開き、前後の文脈の中で読むことができます。

![競合の差分(単語単位)](../images/agent-review-differences.png)
<a id="data-that-extensions-keep-json"></a>

### JSON で保持される拡張機能のデータ

拡張機能は、ブック、そのパート、ロアブック、エントリーの中に独自のデータを保持します(アークの概要、キャラクター追跡表、生成の変数など)。これは JSON であり、レビューでは **整形済み** の形で表示され、適用されるテキストの横に **JSONデータを統合** という行が出ます。データは全体がまるごと引き継がれるわけではありません。エージェントだけが変更した部分はエージェントから取り込まれ、ブック側だけが変更した部分はそのまま残り、**異なる場所** を変更した両者は場所ごとに組み合わされます。両方が同じ場所を異なる値に変更した場合のみ競合となります(キーの順序は関係ありません)。あなたが決めるまでは、その場所にはエージェントのバージョンが使われます。

**JSONデータを統合** を選ぶと、3つのバージョンのデータを重ねてツリーとして並べたウィンドウが開きます。列は、*実行開始時のもの* (*実行開始時*)、*現在のブックの内容*、*エージェント*、そして *結果* の4つです。どの場所が、誰によって(エージェント、ブック、両方、競合)変更されたかには印が付きます。変更された場所だけが表示されます(すべてについて **変更のみ** のチェックを外してください)。場所は開いたときにだけ展開されるので、大きなドキュメントでも問題ありません。

![拡張機能のデータを重ねて表示したところ](../images/agent-json-merge.png)

- 場所を選択し、いずれかのバージョンからデータを取ります(**エージェントの内容を使う**、**ブックの内容を使う**、**実行開始時のものを使う**)。または **除外する**(そのキーや要素は結果に含まれません)、あるいは **内側から統合する**(内側の場所がそれぞれ個別に決めます)を選びます。どちらか一方のバージョンにしかないキーや要素は、そのバージョンから結果にコピーされます。オブジェクトやリスト全体を一方のバージョンから取ると、その内側で行った選択は上書きされますが、それは恒久的ではありません。内側から統合し直せば、あなたの選択は元に戻ります。
- **リスト** の要素には名前がないため、それが何であるかによって対応付けられます。まず同じデータであるもの、次に同じ `uuid`、`id` または `name` を持つもの、そして最も似ているものです。残ったものは、同じ数で同じ種類のものが変更されたとみなされます。推測が外れた場合は、要素を **分割** して各バージョンのものに分けるか、最初の要素と共通のバージョンを一切持たない別の要素に **対応付ける…** ことができます。
- **開く**(またはダブルクリック)は、ひとつの場所だけに対して働きます。ツリーの上のパスをたどれば元に戻れます。
- **テキスト** タブには、開いている場所のデータがテキストとして表示されます。エージェントのデータは **編集** でき、それ以外(ブック、実行開始時、結果)は読み取りのみです。**差分の比較対象** を選ぶと、単語単位で違いに印が付きます。書き込んだ内容は、ツリーに戻るとき、表示を変えるとき、別の場所を開くとき、または結果を採用するときに JSON として検査されます。有効な JSON でなければそこに留まり、何が問題かが知らされ、何も変更されません。有効なテキストであれば、その場所のエージェントのデータを置き換え、その内側がすべて改めて比較されます。
- **最初からやり直す** は、あなたが決めた内容と書いた内容を忘れます。**結果を採用** は結果をレビューに渡します。そこでは適用されるテキストになります(レビューを開いている間は、あなたが残した行のまま保たれます)。

レビューには、そのようなフィールドについて **エージェントの内容を使う** と **ブックの内容を使う** もあります。これは、どちらか一方をそのまま採用するためのものです。また **最初からやり直す** で、統合後のデータに戻れます。

![レビューのアークの概要データ。JSONデータを統合を表示](../images/agent-review-json.png)

他のブックから使われているロアブックには **共有** の印が付きます。変更はロアブック自体に反映されるため、他のブックにも届きます。最初はチェックが外れています。

適用は、ブックに対して **その場で** 行われます。パートはそれぞれのアドレスを保ち、他のブックはロアブックへのリンクを保ち、エージェントが削除したものはごみ箱に入ります。その前に **変更前のブックのバックアップ** が取られます(ブックのバックアップの中に、ロアブックとともに含まれます)。変更はすべてまとめて適用されるか、まったく適用されないかのどちらかです。**エージェントが終えたブランチを表示する** は、適用した内容に含まれている場合、エージェントがいたブランチにブックを切り替えます。編集されたパートの要約は、手で編集した場合と同様に古いものとなります。エージェント自身の要約は、そのまま引き継がれます。

変更が適用されると、実行は *適用済み* となり、そのコピーとチェックポイントは削除されます。**結果を破棄** はコピーを捨て、ブックは元のままにします。どちらか一方を行うまでは、エージェントは未完了の実行を抱えたままとなり、別の実行を開始できません。

### ブックのコピー

**ブックのコピー** タブには、エージェントが作業しているブックが読み取り専用で表示されます。**本文** はブランチごとに表示されます(上でブランチを選びます。各パートには番号、同じパートの他の候補の中での切り替え位置、語数、場面設定、視点、そして折りたたまれた指示と要約が表示されます)。**ロアブック** は、そのエントリーとともに表示されます(ひとつを選ぶと、内容、メモ、タグ、設定が見られます)。これはあなたのブックの窓ではなく、そこでは何も変更できず、コピーのバックアップも取られず、どの拡張機能もブックを開いているとはみなしません。タブを開いたときと **更新** を押したときに読み込まれ、エージェントが作業中であっても読み込まれるため、エージェントがこれまでに書いた内容が表示されます。コピーを持っている間(結果が適用または破棄された後は除く)は、このタブが利用できます。

![ブックのコピータブ](../images/agent-book-copy.png)
<a id="diagnostics"></a>

### 診断

**診断**タブは、実行の記録（トランスクリプト）から何が行われたかを数え、エージェントがツールやプロンプトに何を必要としているかを調べるためのものです。どの実行にも使えます。古い実行でも使えます（先に**実行履歴**で選んでください）。タブを開いたときと**更新**を押したときに作成されます。

![診断タブ](../images/agent-diagnostics.png)

- **概要**: ラウンドと呼び出しの数、失敗した呼び出しの数、モデルの時間、呼び出しの時間、停止の時間（二つのステップの間が30分以上空いている場合は作業ではなく停止として扱います）、コンテキストのピークと終了時の大きさ、トークン、コンパクション、あなたのメッセージ、そして実行機能がエージェントに伝えた通知（読めない呼び出し、呼び出しの多すぎ、コンテキストの満杯）。
- **ツール**: ツールごとに、呼び出し数、エラー数、切り詰められた結果の数、ラウンドで唯一の呼び出しだった回数、エージェントが書いた文字数、テキストを `@file:` や `@result` として渡した呼び出しの数、長文（300文字以上）を書き出した回数とそのうち直前に受け取った結果からコピーしたものの数、結果のトークン数（文字数からの概算）、全結果に占める割合、最長の結果、そして時間。
- **リクエストの報告内容**: 実行の進行中に記録されるため、これが追加された後の実行にのみ表示されます（古い実行には無いと表示されます）。リクエストが最初の一語を待った時間（サーバーがプロンプトを読む時間。短ければキャッシュが温まっていたことを示します）、回答の書き上げにかかった時間と毎秒のトークン数、サーバーが再び読まなかったプロンプトの割合（キャッシュ。llama.cpp と OpenAI が報告します）、回答のうち推論に当たる割合、回答が終わった理由（`length` は一回の回答の上限で打ち切られたことを意味します）、モデルが書いたが実行されなかった呼び出し（重複、上限、バッチの方針による）、リクエストが空きを待った時間、書かれた要約の数とその所要時間、さらに25ラウンドのブロックごとの同じ内容。
- **モデルが書いたもの**: 引数、呼び出しに添えられた文章、推論の文字数を、全体と25ラウンドのブロックごとにモデルの時間とともに示します。出力がどこに行くのか、また途中で `@file` を使うのをやめていないかを確かめられます。**最長の引数**では、最も大きい呼び出しの冒頭を示し、ファイルツールの場合はそのパスも示します。
- **パターンによって失われたラウンド**: 同じツールがラウンドを重ねて（三回以上）呼ばれている場合は、その直前に検索があったときに印が付きます。また、同じ引数で繰り返された呼び出しも示します。これらは、多くの項目を受け取れるツールや、一回の回答でより多くの呼び出しができるようにすれば節約できるラウンドを示します。
- **エラー**: 各メッセージを最初に受けた呼び出しの引数（呼び出しが失敗したときにモデルが何を送ったかを確認するため）、**最大の結果**、**最も遅いラウンド**、**コンパクション**、そして各サブエージェントと、それが呼び出したツール。

**ダウンロード**では報告書を Markdown で、**JSONをダウンロード**では JSON で得られます。**コピー**は Markdown をクリップボードに置きます。時間は保存された行の間の間隔なので概算です。回答の時間には、モデルの空きを待つ時間も含まれます。

<a id="the-context"></a>

### コンテキスト

**コンテキスト**タブは、モデルが**次のリクエスト**で読む内容を部品ごとに分解して示します。トークンがどこに使われているかが分かり、おかしな振る舞いをするエージェントのデバッグに役立ちます。タブを開いたときと**更新**を押したときに作成されます（実行中には作成されません。各部品のトークンを数えるためです）。

- 三つのグラフ: コンテキストの上限に対する**部品の種類**別の内訳（エージェントのプロンプト、あなたの指示、実行機能のメモ、ツールの定義、コンパクションの要約、あなたのメッセージ、エージェントの回答、呼び出しの結果、そして空き容量）、**送信順のすべての部品**（種類ごとの色の棒が一本ずつ。説明が非常に長いツールや、コンテキストを埋める結果が目立ちます）、そして**モデルの回答ごとのコンテキスト**：その内訳を積み上げた棒（同じ種類で推定値）、モデルが**報告した**大きさを示す線、上限を示す破線。線が棒より上にある場合、モデルは推定より多く数えています（画像やプロバイダーの形式のため）。棒が下がっている箇所はコンパクションか巻き戻しです。
- **部品の表**: 種類、名前、トークン数、コンテキストに占める割合。行を選ぶと、その部品についてモデルに送られる**まさにその文章**を読めます。システムメッセージの一節、一つのツールの説明とパラメータ、一つのメッセージ、呼び出しの引数、あるいは一つの結果です。
- **ダウンロード**では、コンテキスト全体を一つの Markdown ファイルとして得られます（各節を持つシステムメッセージ、説明とスキーマを持つすべてのツール、メッセージごとの会話。各文章はコードフェンスに入ります）。**コピー**は同じ文章をクリップボードに置きます。

![コンテキストタブ](../images/agent-context.png)

部品の大きさは推定値です。モデルが報告した数が実際の値です（リクエストとその回答）。回答のグラフでは、プロンプト、指示、ツールは現在の状態のままです（古い回答は、あなたが変更する前のものだったかもしれません）。会話は当時のままです。要約は、それより前にあったものを置き換え、巻き戻しで遡られたものは、その後の回答からは消えています（巻き戻されたコンパクション自体は復元されません。その後の棒が少し小さくなります）。システムメッセージとツールは次のリクエストが使うものなので、プロンプト、指示、許可されたコマンドを変更するとすぐに反映されます。メッセージは保存された通りのトランスクリプトで、再開によって追加されるもの（「続けて」や、中断で未完了のままになった呼び出しへの回答）は含みません。推論はコンテキストに含まれません（モデルには送り返されないため）。画像はファイル名で表示されます。コンパクションによって置き換えられた内容もコンテキストには含まれません。それは**実行**タブと**実行履歴**のダウンロードにはまだ残っています。
<a id="checkpoints"></a>

## チェックポイント

**チェックポイント**は、実行の作業コピー（パーツ、要約、ロアブック、拡張機能のデータ。エージェントに渡されたハンドルを含む）と、エージェントのワークスペースの復元ポイントです。これにより、うまくいかなかった作業を取り消せます。エージェントは `checkpoint_restore` で戻すか、コンソールの **チェックポイント** タブで操作できます。作成の種類は次のとおりです。

- **実行の開始**: 実行の開始時に作成されます。これは決して削除されません。
- **自動**: 本や ワークスペースを変更する可能性のある処理（単なる読み取りではないコマンド、または書き込みを行うファイルツール）をエージェントが呼び出すラウンドの前に、実行によって作成されます。ただし、前回のチェックポイント以降に何かが変わった場合に限ります。直近の5件が保持され、新しいものが作られると最も古いものが削除されます。
- **手動**: エージェントが `checkpoint` を使って（危険な手順の前に作成するよう指示されている場合）、またはあなたが **チェックポイントを保存** で作成します。削除するまで残ります。

![チェックポイントタブ](../images/agent-checkpoints.png)

実行のすべてのチェックポイントは、管理者が[権限](administration/permissions.md#settings-of-a-permission)で設定する**クォータ**を共有します（空の場合は100 MB）。その一部は自動チェックポイント用に確保されているため、エージェントがすべてを使い切ることはありません。手動チェックポイントが収まらない場合は**拒否**されます。依頼者の知らないうちに何かが削除されることはありません。その後、エージェントは一覧を取得し、不要なものを削除します（開始時のチェックポイントと最新のものは除きます）。タブではどれでも削除できます。各チェックポイントはアーカイブ（本のJSON、ペア、ワークスペースのファイルを含むZIP）で、**ダウンロード**できます。

**復元**は、チェックポイントから作業コピーを作り直します。新しいコピーが作られ、古いコピーは削除されます。ワークスペースは保存された状態に戻り（その後に書き込まれたファイルは消えます）、既存の項目に対するエージェントのハンドルは引き続き有効です。復元の前の状態は、空きがあれば先に自動チェックポイントとして保存されるので、復元を取り消すことができます。復元には実行開始とほぼ同じ時間がかかります（パーツ2,000個の本で約30秒）。エージェントが作業していない間は復元できます。エージェントはラウンドの間に自分で復元し、何が戻ったかを知らされます。チェックポイントは、実行が作業コピーを手放すときに消えます。

**巻き戻す**は、復元に加えて*会話*も戻す操作です。復元だけでは、エージェントは本にもう存在しない作業を覚えたままになります。そのため、別の方向に進めたい実行では巻き戻しが必要です。作業コピーとワークスペースはチェックポイントの状態に戻り、チェックポイントが作られた箇所より後のメッセージは、トランスクリプトでグレー表示されます（読むことはできますし、エクスポートにも含まれます）。エージェントはそれらを読まなくなり、何が起きたかを知らせる通知が届くので、必要ならやり直します。実行は一時停止または停止している必要があります（エージェントがあなたを待っている場合は、まず一時停止してください）。その後に**再開**すると、通知の箇所から続行されます。チェックポイントに巻き戻せるのは、その会話上の位置がまだ有効な間だけです。より前のチェックポイントに巻き戻した後は、（取り消された会話の）後のチェックポイントは復元しかできません。巻き戻しの機能が存在する前に作られたチェックポイントは、会話上の位置を持たないため、復元しかできません。圧縮（コンパクション）がチェックポイントの後に行ったことは、巻き戻しによって取り消されます。エージェントは、圧縮によって置き換えられていたメッセージを再び読みます。

**メッセージまで戻る。** チェックポイントを選ぶ必要はありません。あなたがエージェントに送ったメッセージには、**実行**タブのトランスクリプトでそれぞれの下に**巻き戻す**ボタンがあります。このボタンは、そのメッセージより前まで会話を戻します。エージェントはそのメッセージとそれ以降を忘れ、作業コピーとワークスペースは、そのメッセージより前に作られた最新のチェックポイントの状態に戻ります（実行は何かを変更するラウンドの前に毎回チェックポイントを作るので、通常はメッセージの直前に戻ります）。実行の状態は、チェックポイントの時点でのみ分かります。そのため、最も近いチェックポイントがメッセージより古い場合は、そのチェックポイントからあなたのメッセージまでの間のメッセージも忘れられます。確認画面には、どのチェックポイントに戻るか、何件のメッセージが失われるかが表示されます。忘れられたメッセージはグレー表示でトランスクリプトに残ります。このボタンは、エージェントがあなたを待っている間（そのために一時停止している間）、一時停止中、または停止して保持されている間に機能します。エージェントが作業中は無効になります。その後、実行を**再開**すると、通知の箇所から続行されます。

### 許可するコマンド

エージェントには、あなたがチェックしたコマンドだけが提供されます。表には、すべてのコマンドとその効果が並びます（*破壊的*はデータを変更または削除し、*非破壊的*は読み取るか追加するだけです）。**選択**欄では、多くのコマンドを一度にチェックできます。**すべて**、**なし**、**破壊的でないものすべて**（新しいエージェントの既定）のほか、役割を選べます。自分でコマンドをチェックすると、選択は*カスタム*になります。表の上の**コマンドを検索**欄には、入力したすべての単語を（順不同で、名前または説明の中に）含むコマンドだけが表示されます。選択は、隠れているコマンドを含め、すべてのコマンドに適用されます。拡張機能が提供するコマンドは、その拡張機能が読み込まれていなくても許可されたままです。表示されないだけです。**バッチ**列は、そのコマンドが1回の回答で他の呼び出しと*まとめて*使われるか、*単独*で使われるかを示します（`next`、`swipe`、`regenerate`、`redraft-part`、`generate-annotation`、圧縮など、モデルへの呼び出しを行うコマンドは単独です。下の**1回の回答での呼び出し**を参照してください）。すべての列の幅は変更できます。**トークン**列は、コマンドの定義（名前、説明、パラメータ）がエージェントのすべてのリクエストに加える量を示します。指示の下の行には、チェックされたコマンドの合計が表示されます。全体ではおよそ20,000トークンになるため、選択を絞る（役割を選ぶ）と、作業のためのコンテキストに余裕が生まれます。

![許可するコマンドと選択欄の役割](../images/agent-commands.png)

役割は、ある仕事のためのコマンドの組み合わせです。どの役割も、本と設定集を読むことはできます（読み取るだけのコマンドはすべて、拡張機能のものも含みます）。ただし、どの役割もデータを削除することはできません。

| 役割 | 読み取りに加えてできること |
|---|---|
| **監査役** | 何もできません。整合性の確認、名前や用語の監査、報告書の作成を行います。 |
| **設定管理者** | 設定集の項目と設定集、そのタグとサブ設定集を作成・更新します。 |
| **編集者** | パートを編集し、追記し、そのフィールドを設定します。要約を保つ（モデルに要約を書き直させることもできます）。本の情報とタグを扱います。 |
| **執筆者** | パートとブランチを追加し、編集と追記を行います。モデルに次のターンを書かせ（`/next`、`/swipe`）、要約を保ちます。自分で考え出した内容について、設定集の項目を作成・更新します。 |

チェックしたコマンドはそれぞれ、そのエージェントのすべてのリクエストに定義を加えます。そのため、役割は、弱いモデルで短いプロンプトにするための最も安上がりな方法でもあります。

## スマホでの表示

スマホの画面では、ドロワーに**エージェント**タブがあります。エージェントを使ってよいユーザーに表示され、対応が必要なエージェントの数がその名前の横に出ます。各エージェントは、名前、状態、表の操作ボタンを載せたカードとして表示されます（ボタンは複数行に折り返します）。コンソール、レビュー、エージェントの設定といったウィンドウは画面いっぱいに広がり、レビューでは項目の詳細の上に表が表示されます。デスクトップと同じように使え、画面が小さくなっただけです。コンソールは親指で操作しやすいように配置されています。

![スマホのエージェントタブ](../images/phone-agents.png)

![スマホのコンソール](../images/phone-agent-console.png)

![スマホのエージェントタブ](../images/phone-agents.png)

![スマホのコンソール](../images/phone-agent-console.png)

- **タブはアイコンになります**（実行、実行履歴、ワークスペース、チェックポイント、コンテキスト、本のコピー、サブエージェント、診断）。開いているタブの名前はウィンドウのタイトルに表示されます。
- **一時停止、今すぐ一時停止、再開、完了、停止はアイコンのボタンとして下部に並び、今使えるものだけが表示されます**。**変更を確認**は文字のまま残します。完了した実行が待っているのはこの操作です。**更新**と**閉じる**はヘッダーのアイコンです。
- **メッセージ欄は1行で**、横に**送信**と**画像を添付**のアイコンがあります。**コマンドライン**（ターミナルのアイコン）は開くまで隠れているので、キーボードがやり取りの記録を無駄に覆うことはありません。やり取りの記録のメッセージは画面の横幅いっぱいに使います。
- **表はカードの一覧になります**。実行、チェックポイント、エージェントの設定のコマンド、レビューの項目は、表の列の代わりに、名前と状態を見せ、その下に詳細、さらに下に操作ボタンを置いたカードで表示されます。ワークスペースのファイルは名前の下にサイズが出ます。ワークスペースのツールバーはアイコンです。コンテキストの表は番号、名前、トークン数を残します。パーツの種類と割合は、選んだパーツの本文の下に表示されます。

- **上部バーに、あなたを待っている相手が表示されます。** ドロワーが閉じているとき、上部バーの（開いている部分のタイトルの横にある）赤い数字が、対応が必要なエージェントの数を示します。ドロワーのエージェントタブのバッジと同じ数です。タップすると**エージェント**タブに移動します。誰も待っていないとき、ドロワーが開いているとき、エージェントタブそのものを表示しているときは隠れます。
- **部分の間をスワイプで移動できます。** 内容の上で横にスワイプすると、ドロワーの次の部分（左にスワイプ）または前の部分（右にスワイプ）に移ります。ドロワーが開いているとき、またはアプリケーションがナビゲーションをロックしているときは何もしません。テキスト欄、表、横にスクロールするものの上で始まったタッチは、それぞれの操作に任されます。

やり取りの記録やレビューを長く扱う作業には、大きな画面の方がまだ快適です。

## 取り込んだ本の設定メモ

原稿を[取り込んだ](books/story-editor.md#after-an-import)あと、アプリケーションは本の設定を読み取るエージェントを提案します。それが**設定メモを取る（エージェントで）...**です（同じ項目は、物語の設定メニュー⚙の**分析**にもあります）。最初に確認を求めます。

![エージェントを開始する前の確認](../images/lore-notes-confirm.png)

確認すると、その本のために**設定メモ**という名前のエージェントを、本のモデルとプロトコルで作成し、開始します（そのコンソールが開きます）。

- 物語を最初の部分から最後の部分まで、数部分ずつ読み進めます。メモはワークスペースのファイルに（人物、場所、物、用語）保存されるので、一時停止しても続きから再開できます。あらすじは目印として役立ち、部分そのものが元の資料です。
- その後、人物、場所、物、集団、用語のそれぞれについて項目を一つずつ、本の設定集に書き込みます（設定集が無ければ本のために作成されます）。物語で使われている名前を絞り込みの条件にし、本の言語で書きます。既存の項目があればそこに事実を追加し、同じことを二度書くことはありません。
- 物語と設定集を読み、項目を書き込むことができます。物語を変更することはできず、何かを削除することもできません。

ほかのエージェントと同じく、作業中は本が[ロック](#the-book-is-locked)され、作業は[コピー](#the-working-copy)の上で行われます。書いた内容があなたのものになるのは、[レビュー](#reviewing-the-result)して取り込んだあとだけです。取り込む前に項目を読んでください。エージェントはテキストに書かれていることしか知らず、長い本では多くのリクエストがかかります。指示はそのエージェントのものです（**編集**で確認でき、開始し直す前に変更できます）。エージェントを使う権限がないとき、本にモデルがないとき、本にすでにエージェントがあるとき（本には一つだけ）は、開始を断られます。

<a id="the-book-is-locked"></a>

## 本がロックされる

エージェントの実行が作業中またはあなたの応答を待っている間、**その本はロックされます**。読むことはできますが、何も変更されません。エージェントが動いている文章が、その下で変わることはないようにするためです。本の一覧はロックされた本を開かず、どのエージェントが保持しているかを示します。また、本の生成、編集、検索と置換、あらすじ、本の削除は断られます。本をもう一度編集するには、実行を**一時停止**するか**停止**してください。一時停止、停止、完了した実行は本をロックしません。

![一覧でエージェントが作業している本](../images/agent-locked-book.png)

**本の設定集**もいっしょにロックされます。本が使う設定集とそのサブ設定集がそうです。設定集タブでは、そのような設定集はスマホでの表示と同じ形で、プレーンテキストとして、編集はできない状態で表示されます。どのエージェントが保持しているかも表示されます。実行を一時停止または停止したあとに**更新**を押すと、再び編集できる状態で表示されます。ほかの設定集は影響を受けません。

### エージェントとフォルダー

エージェントが作業している本が[フォルダー](books/folders.md)の中にあるとき、その本は場所と設定を保ちます。その上位のフォルダーを移動または削除すること、そしてフォルダーが下の本へ引き継ぐ設定（言語、テンプレート、視点、時制、文体、プロンプト）を変更することは、本の名前とエージェントの名前を示して断られます。フォルダーの名前を変えることや説明を変更することは断られません。一時停止、停止、完了した実行はロックを解放します。
