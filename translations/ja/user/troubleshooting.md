# トラブルシューティングとFAQ

<a id="where-are-the-logs"></a>

## ログはどこにありますか？

ほとんどの問題はログに記録されます：

| 導入形態 | ログ |
|---|---|
| デスクトップアプリ | `~/.marginalia/desktop/logs/marginalia.log`（Windowsでは`%USERPROFILE%\.marginalia\desktop\logs`）。前回の実行のログは`marginalia.log.1`にあります |
| Docker | `docker compose logs -f marginalia` |

アプリケーションのエラーダイアログ（*内部サーバーエラー*など）にもエラーが表示されますが、詳細はログにあります。

問題を報告するときは、ページ左下のバージョンの表示（例：`Marginalia 1.5.0 (93ec118)`。バージョンとビルドのGitコミット）を含めてください。

<a id="installing-and-starting"></a>

## インストールと起動

**macOSで、アプリが「壊れている」または「開けません」と表示されます。**
アプリはまだ署名されていません。アプリを右クリックして*開く*を選ぶか、`xattr -dr com.apple.quarantine /Applications/Marginalia.app`を実行してください。[デスクトップアプリ](getting-started/desktop-app.md)を参照してください。

**Windows SmartScreenがアプリをブロックします。**
*More info* → *Run anyway* をクリックしてください。

**ブラウザが8765以外のポートで開きます。**
ポート8765が使用中だったため、デスクトップアプリが空いているポートを選びました。トレイメニューの**Open Marginalia**を使うか、`--port`付きで起動してポートを固定してください。

**"Marginalia did not start in time"。**
デスクトップアプリがサーバーを起動できませんでした。理由はログにあります。多くは別のプログラムがファイルを使用中であるか、拡張機能が壊れていることが原因です（[下記](#extensions)を参照）。

**Docker：ポート8080がすでに使用中です。**
`docker-compose.yml`のポートマッピングの左側（ホスト側）を変更してください。たとえば`"8081:8080"`のようにし、ポート8081を開いてください。

**Marginaliaが遅い、または"OutOfMemoryError"で停止します。**
メモリを増やしてください。`JAVA_TOOL_OPTIONS`内の`docker-compose.yml`に`-Xmx2g`（またはそれ以上）を設定します。

<a id="logging-in"></a>

## ログイン

**"Save login"を選んでも、ログイン状態が保たれません。**
保存されたログインは、サーバー上でHTTPSを使う必要があります。Marginaliaをリバースプロキシの背後に置き、HTTPSを有効にしてください。[サーバー（Docker）](getting-started/docker-server.md#https-and-reverse-proxy)を参照してください。

**パスワードを忘れました。**
管理者が新しいパスワードを設定するか、パスワードを消去できます。パスワードを空にすると、空のパスワードでログインし、自分で新しいパスワードを設定できます。これは*Admin → Users*で行います（[パスワードを忘れた場合のリセット](administration/users.md#resetting-a-forgotten-password)を参照）。
メールによるパスワードリセットはありません。

**管理者としてログインできる人がいなくなりました。**
管理者がいない場合、パスワードはデータベース内でしかリセットできません：

1. Marginaliaを停止し、[データフォルダ](administration/index.md#the-data-folder)から`marginalia.sqlite`をバックアップとしてコピーします。
2. `sqlite3`ツールで管理者のパスワードを削除します：
   ```sh
   sqlite3 marginalia.sqlite "UPDATE users SET passwordHash = NULL WHERE login = 'admin';"
   ```
   （正しいユーザー名を使ってください）。
3. Marginaliaを起動し、そのユーザー名と**空の**パスワードでログインして、すぐに**パスワードを変更**で新しいパスワードを設定します。

**"Server connection lost"、またはページが繰り返し再読み込みされます。**
リバースプロキシの背後では、プロキシがWebSocketを転送し、長いリクエストを許可する必要があります。nginxの例は[サーバー（Docker）](getting-started/docker-server.md#https-and-reverse-proxy)を参照してください。デスクトップアプリの場合は、アプリが終了した可能性があります。再度起動してください。

**ワークスペースを開くとブラウザが固まります。**
Marginaliaは、前回離れたときに開いていたものを再び開くため、非常に長い本（たとえばアーカイブからインポートした本）は、何かを変更する前にページを固めることがあります。Marginaliaのアドレスの後ろに`/reset`を付けて（例：`https://marginalia.example.com/reset`）開き、ログインしてください。ワークスペースの保存された状態（開いている本、選択されたタブ、フィルター）は忘れられ、空のワークスペースに入ります。その後、[アカウント](account.md)で**ストーリーで一度に読み込むパート数**を設定してから、本をもう一度開いてください。

<a id="models-and-generation"></a>

## モデルと生成

**"Failed to download model list"。**
URLが`/v1`で終わっているか、APIキーが正しいか、モデルサーバーが動いているかを確認してください。モデル一覧を返さないサービスもあります。その場合はモデルIDを直接入力してください。[推論プロバイダー](inference-providers.md#per-type-settings)を参照してください。

**Docker：同じマシン上のモデルサーバーに到達できません。**
コンテナの内部では、`localhost`はそのコンテナ自身を指します。`http://host.docker.internal:<port>/v1`を使い、モデルサーバーがすべてのアドレスで待ち受けるようにしてください。[同じマシン上のモデル](getting-started/docker-server.md#models-on-the-same-machine)を参照してください。

**"Book is missing model." / "Book is missing protocol."**
本の*概要*タブで選択してください。新しい本にも設定されるように、*設定*で*既定のモデル*と*既定のプロトコル*を設定してください。

**"Contextual limit not sufficient."**
ストーリーなしのプロンプトだけで、応答の後にコンテキストに残る余裕より大きくなっています。プロバイダーの*最大コンテキストサイズ*（またはプロトコルの*最大コンテキストトークン数*）を上げるか、*最大応答トークン数*を下げるか、テンプレート、ロアブックのエントリ、要約を短くしてください。[制限](protocols.md#limits)を参照してください。

**モデルがコンテキストが長すぎると報告します。**
Marginaliaのトークン数の見積もりは、一部のモデルではわずかにずれます。*最大コンテキストサイズ*を数百トークン下げてください。プロンプトがすでに大きすぎそうな場合、リクエストの前に警告が出て、推定サイズが示されます。

**"The provider did not answer in time"、"The provider is limiting requests"、"The provider rejected the API key"...**
Marginaliaは、モデルAPIの失敗を平易な言葉で説明します。[エラーメッセージ](inference-providers.md#error-messages)を参照してください。プロバイダーのダイアログにある*接続テスト*は、本がなくてもURL、キー、モデルを確認します。タイムアウトとリトライはプロバイダーごとに設定します。

**テキストが文の途中で止まります。**
応答の上限に達しました。*最大応答トークン数*（またはプロトコルの*最大返信トークン数*）を上げてください。推論モデルは、推論部分もトークンに含まれるため、はるかに多く必要です。

**推論を有効にすると、リクエストが失敗します。**
APIが`reasoning_effort`をサポートしていません。プロバイダーで*推論（リーズニング）を有効にする*をオフにしてください。

**"The summaries of the messages with IDs ... are outdated ... Continue generation and delete them?"**
要約でカバーされている部分が編集または削除されました。*はい*を選ぶと古い要約を削除して生成を続け、その後新しい要約を生成します。*いいえ*を選ぶと止めて要約を残します。要約の一覧で古いものとして印が付くので、まだ正しい内容のものは再検証できます。[要約が古くなるとき](books/summaries.md#when-summaries-become-outdated)を参照してください。

**プロンプトに"Error"という語が含まれています。**
テンプレートが存在しない変数またはマクロを使っています。多くは`instructions`の代わりに`instruction`と書いたような誤字です。テンプレートの入力欄の下に、そうした名前が一覧表示されます。[誤字](templates/templates.md#typos)を参照してください。

<a id="lorebooks"></a>

## ロアブック

**エントリが使われません。** [有効化](lorebooks/entries.md#activation)の条件を順に確認してください：

- エントリは有効ですか？そこに至るまでのロアブック（およびそのすべての下位ロアブック）も有効ですか？
- エントリにタグがありますか？ある場合、本はそのうちの1つを持つ必要があります（本のタグは*概要*タブにあります）。否定タグがあれば、そのエントリは除外されます。
- ロアブック自体に**タグ**がありますか？ その場合、すべてのエントリに適用されます。
- フィルターがありますか？フィルターは**書いているパートの指示のみ**を対象とし、それ以前のストーリーは見ません。*登場人物*か指示に、そのキャラクターの名前を書いてください。
- フィルターは正規表現ですか？無効な正規表現は決して一致しません。

生成されたパートの**プロンプトを表示**を押すと、送られたロアがわかります。

<a id="prompts-and-settings"></a>

## プロンプトと設定

**別のタブに切り替えられません。**
*設定*タブに保存されていない変更があります。**保存**または**変更を破棄**をクリックしてください。

**要約プロンプトが使われません。**
本自身の要約プロンプト（*プロンプト*タブ）は、*設定*の*既定の要約プロンプト*より優先されます。既定を使うには、本の欄を空にしてください。メタ要約には独自のプロンプト、*既定のメタ要約プロンプト*があります。

**Style、Point of View、Tenseのマクロが機能しません。**
これらの欄は単なるテキストで、マクロを処理するのはテンプレートだけです。マクロをマスターテンプレートかユーザープロンプトに入れてください。

<a id="backups"></a>

## バックアップ

**データベースのバックアップを復元しましたが、何も変わりません。**
復元は次回の起動時に適用されます。Marginaliaを再起動してください。[復元](administration/database-backups.md#restoring)を参照してください。

**別のコンピューターに移動すると、本のバックアップがありません。**
本のバックアップはデータベースの一部ではなくファイルです。`data`フォルダもコピーしてください。[データフォルダ](administration/index.md#the-data-folder)を参照してください。

<a id="extensions"></a>

## 拡張機能

**インストールした拡張機能が表示されません。**
本を閉じて開き直すか、ページを再読み込みしてください。

**拡張機能の読み込みに失敗し、Admin → Extensionsに表示されません。**
Marginaliaを停止し、`extensions`フォルダからそのJARを削除して、再度起動してください。[拡張機能が失敗したとき](administration/extensions.md#when-an-extension-fails)を参照してください。

**Marginaliaを更新した後、拡張機能が拒否されたか、動かなくなりました。**
拡張機能は特定のバージョンのMarginaliaに向けてビルドされ、読み込み時に検査されます。レポートを開き（Admin → Extensions → *検証*）、お使いのMarginaliaに合ったバージョンの拡張機能を読み込んでください。[拡張機能が失敗したとき](administration/extensions.md#when-an-extension-fails)を参照してください。

**拡張機能を更新した後も、古いバージョンが動き続けます。**
まず古いバージョンをアンロードしてから新しいバージョンを読み込むか、Marginaliaを再起動してください。
<a id="faq"></a>

## よくある質問

**私の文章はどこかに送信されますか？**
設定した推論プロバイダーにのみ送信されます。各パートのプロンプト（およびトークン数を数えるリクエスト）は、そのプロバイダーのAPIに送られます。自分のコンピュータで動かしているモデルを使う場合は、何も外部に出ません。Marginaliaはテレメトリを送信しません。

**どのモデルを使えばよいですか？**
優れた小説を書け、十分に大きなコンテキストを持つモデルであれば何でも構いません。長編には32 000トークン以上のコンテキストがあると快適です。同じ本で何種類か試してみてください。プロバイダーの切り替えは、*概要*タブでワンクリックです。

**複数の人で一冊の本に取り組めますか？**
いいえ。すべての本は一人のユーザーに属します。[公開](books/publishing.md)すると、ほかのユーザーが読むことができます。

**Marginaliaはオフラインで使えますか？**
はい。ローカルで動かしたモデル（llama.cpp、LM Studio、Ollamaなど）を使えば可能です。Marginalia自体はインターネット接続を必要としません。

**本をMarginaliaから取り出すにはどうすればよいですか？**
*ストーリー*タブの設定メニュー（⚙）から、[ストーリーをエクスポート](books/export.md)してテキスト、HTML、Word、PDF、EPUBの形式で保存できます。
すべてのブランチを含めて保存したい場合は、[本のバックアップをエクスポート](books/backups.md#exporting-and-importing)（JSON）してください。
[ビューア](books/publishing.md)で読むこともできます。

**スマートフォンで使えますか？**
[ビューア](books/publishing.md)はスマートフォン向けに作られており、Marginaliaはブラウザのメニューから（*Install app* / *Add to Home Screen*）ホーム画面にアプリとして追加できます。エディタは、ブラウザの窓の幅が768ピクセルより狭いと、[スマートフォン向けのレイアウト](phone.md)になります。管理ページはなく、ロアブックエディタは機能が限られ、すべての拡張機能も使えないため、執筆と読書に向いています。初期設定や管理は、より大きな画面のほうが行いやすいです。

**ライトテーマや他の言語はありますか？**
どちらもあります。言語選択の横にある太陽/月のボタンでテーマを切り替えられます（初期設定はダーク）。言語選択では、日本語と、拡張機能が追加する言語を選べます（[アカウント](account.md#theme)を参照）。
