# ステートトラッカー

登場人物の**状態**を記録します。どんな服を着ているか、何を持っているか、手に持っている武器、負傷、気分、その他あなたが定義したものが対象です。モデルは、剣を二章前に失ったことや、マントが濡れていることをすぐに忘れてしまいます。ステートトラッカーを使うと、シーンに登場する追跡対象の各キャラクターについて、今どうなっているかをプロンプトに書き込みます。

!!!
追跡するキャラクターと、そのキャラクターについて何を追跡するかは、あなたが決めます。タブに追加したキャラクターだけがモデルに説明され、それも書いている部分の*登場人物*に含まれている間だけです。状態はあなたが自分で管理することも、モデルに物語を読ませて変更を提案させることもできます([物語に追従させる](#following-the-story)を参照)。
!!!

<a id="categories"></a>

## カテゴリ

**カテゴリ**は、キャラクターについて追跡できる一つの項目です。各カテゴリには次のものがあります。

- **名前**。プロンプトでもこの名前で表示されます(*Wearing*、*Weapon at hand*、*Carrying*など)。
- **種類**:
  - **単一の値**: 短い値が一つだけあり、新しい値が古い値を置き換えます(手に持つ武器や場所など)。
  - **リスト**: 項目を一つずつ追加・削除します(持ち物や負傷など)。
  - **説明**: 一つのテキストを全体として書き直します(服装や気分など)。
- **モデルへの指示**: そのカテゴリに何を入れ、何を入れないかの指定です。モデルは物語に追従するときにこれを読みます。
- **テキストに書かれていることだけ**: オンにすると、値は本文がそう書いている場合にだけ変わります。オフにすると、明白な結果にも反応します(泳いだ後に濡れている、など)。
- **空の場合は「none」と言う**: キャラクターがその値を持たない場合(武器を失った場合など)、カテゴリを省くのではなく、プロンプトに*none*と書きます。

<a id="my-categories"></a>

### 自分のカテゴリ

自分のカテゴリは、**Settings → Extension Settings → State Tracker**にあります。書籍は、ここからカテゴリをコピーします。変更しない限り、最初から五つの組み込みカテゴリがあります。*Wearing*、*Weapon at hand*、*Carrying*、*Injuries*、*Mood*です。カテゴリの追加、編集、削除はそこで行い、Settings画面で**Save**を押します。**Reset to the built-in categories**を押すと、組み込みの五つに戻ります。

<a id="the-categories-of-a-book"></a>

### 書籍のカテゴリ

書籍は、使っている各カテゴリの**独自のコピー**を持ちます。そのため、バックアップやエクスポートにはすべてが含まれ、自分のカテゴリを削除しても書籍が壊れることはありません。Stateタブの**Categories of this book**ボタンで、それらの一覧が表示されます。

- **Add from my categories**は、自分のカテゴリの一つを書籍にコピーします。
- **New category for this book**は、この書籍だけに存在するカテゴリを作ります(船の積荷や魔法の結びつきなど)。このカテゴリには*Only in this book*と付きます。**Save to my categories**を押すと、自分のカテゴリに追加され、他の書籍でも使えるようになります。
- 自分のカテゴリと同じではなくなったコピーには、*Differs from your category*と付きます。**Update from my categories**を押すと、自分のカテゴリの版を取り込みます。指示文を変えるとモデルの動作も変わるため、あなたの操作なしには何も更新されません。
- カテゴリを編集すると、変更されるのはこの書籍だけです。そのカテゴリの値をキャラクターが持っている間は、種類は変えられません。
- 書籍からカテゴリを削除すると、そのカテゴリに含まれる全キャラクターの値も削除されます。

<a id="the-state-tab"></a>

## Stateタブ

[物語エディタ](../books/story-editor.md)の左サイドバーに**State**タブが追加されます。変更するたびに、すべてが書籍に保存されます。

![追跡中のキャラクターがあるStateタブ](../../images/plugin-statetracker.png)

![値の履歴](../../images/plugin-statetracker-history.png)

**Track a character**を押すと、**name**、任意の**aliases**(部分の*Present Characters*欄にカンマ区切りで書かれる、そのキャラクターの別名)、**tracked categories**を尋ねられます。一覧には書籍のカテゴリと自分のカテゴリが表示され、自分のカテゴリを選ぶとそれが書籍にコピーされます。馬は*Injuries*だけを追跡し、ヒロインはすべてを追跡する、といった使い分けができます。

**Import from the Character Tracker**(**Track a character**の横の人型アイコン)を押すと、同じ書籍の[キャラクタートラッカー](character-tracker.md)にあるキャラクターの追跡を始められます。書籍がまだ追跡していないキャラクター(名前または別名で判断)が、キャッチフレーズ付きで一覧表示され、すべてチェックが入った状態になります。除外したいものはチェックを外し、取り込まれる全キャラクターが受け取る**tracked categories**(書籍のものと自分のもの、前述のとおり)を選んで、**Import**を押します。取り込まれるのは名前だけです。後からペンのボタンで別のカテゴリを追加できます。

追跡中の各キャラクターにはカードがあり、最初は閉じています。カードの矢印で開くと、各カテゴリとその現在の値または値の一覧が表示されます。

- **+**は、単一の値または説明カテゴリの値を設定します(現在の値は履歴に移ります)。リストの場合は項目を追加します。
- ペンは値を編集し、十字は値を**削除**します。その値はもう正しくないので、履歴に移り、モデルには送られません。
- 錠のアイコンは値を**locked**(ロック済み)にします(傷跡や家伝の剣など)。[整理](#tidying-the-state)はロックされた値に手を加えません。ただし、物語はロックされた値も変更できます。
- **History**は、そのカテゴリの過去の値と、それが終わった理由(*replaced*、*removed*、*tidied*)を表示します。モデルがその値を終わらせた場合は、それを読み取った部分も表示されます。**Restore**は、過去の値を再び現在の値にします(単一の値または説明カテゴリの場合、現在の値は代わりに履歴へ移ります)。Deleteは値を完全に削除します。

キャラクターのペンは、名前、別名、カテゴリを編集します。カテゴリのチェックを外すとそのカテゴリは非表示になりますが、値は残ります。再びチェックを入れると値が戻ります。ゴミ箱のボタンは、キャラクターの追跡を止め、その状態全体を削除します。
<a id="following-the-story"></a>

## 物語を追う

State タブの上部にある **Processing** パネルでは、モデルに物語を読ませて、何が変わったかを割り出せます。たとえば、川で濡れたマント、ほかの人に渡されたランタン、抜かれた剣、失われた手紙などです。モデルは有効なブランチのパートを順番に読み、**Start point**（初期設定では本の冒頭。それより前のパートは決して読まれません）から始めて、どこまで読んだかを覚えています。

![処理設定](../../images/plugin-statetracker-settings.png)

![提案された変更のレビュー](../../images/plugin-statetracker-review.png)

- **Process now** は未処理のパートをすべて読み、**Process next part** は次の1つだけを読みます。長いシリーズの場合は、何回のリクエストが必要になるかを最初に尋ねます。これらのボタンの下にあるキャラクターの一覧を下にスクロールすると、タブ上部のバーにも **Process now**、**Process next part**、**Tidy the state** が表示されます。
- モデルには、パートに登場する追跡対象のキャラクターが、そのカテゴリー、各項目の指示、現在の値とともに渡され、モデルは変更を返します。どの変更にも、パートからの引用が必要です。合わない変更（キャラクターが追跡していないカテゴリー、すでに持っている値、存在しないパートからの引用）は除外されます。
- パネルには進捗と、モデルが書いている間の出力が表示されます。その間も読んだり書いたりを続けられます。**Ask before applying** がオン（初期設定）の場合、実行はあなたの確認を待ちます。**Review changes** でキャラクターごとの変更を確認できます。終わる値には取り消し線が引かれ、新しい値と引用が示されます。新しい値は修正できます。誤りのある項目はチェックを外して **Apply** を押してください。**Cancel** を押すと何も変わらず、同じパートが次回また提案されます。
- モデルが読んだ値には、その出どころのパートが示されます。**Processed parts** は読まれたパートの一覧を示し、**Reprocess from here** は、そのパートとそれ以降から読まれたものをすべて取り消し（あなたが書いた値や修正した値は残ります）、もう一度読み直します。前のパートを書き直したあとに使ってください。再生成されたパート、スワイプ、別のブランチは、もうそこに存在しないパートから来たものを自動的に取り消します。

<a id="the-story-clock"></a>

### 物語の時計

**Story clock** をオン（設定内。初期値はオフ）にすると、モデルは物語の時間の流れも追います。状態と同じリクエストの中で、各パートがその時間について何を述べているかを報告します。たとえば *翌朝*、*3日後*、*その夜*、*目覚めてから40日目*、*4月20日*、曖昧な *数週間が曖昧に過ぎた*（概算と明記されます）、あるいは過去のフラッシュバック、記憶、夢などです。フラッシュバック、記憶、夢は時計を進めず、状態も変えません。モデルは数えません。日数の合計はプラグインが行います。

![処理設定の中の物語の時計](../../images/plugin-statetracker-clock.png)

![パートの時刻を手動で修正する](../../images/plugin-statetracker-clock-dialog.png)

- **Day 1 is the day of** は、日数を数える起点となる出来事（*the awakening* など）を指定します。時刻は *Day 14 after the awakening, evening* のように表示されます。**Day at the start point**、**Time of day**、**Date at the start point** は、読まれる最初のパートより前の時刻を指定します。日付を指定すると、時計は日付も数えます（*20 April 1453*）。
- Processing パネルには現在の **story time** が表示され、処理済みの各パートには、そのパートの後の時刻が表示されます。明示された日数や日付は、推定値より優先されます。
- パートの時計ボタン（最後のパートの場合は story time の行）から、**時刻を手で設定**できます。これは固定点（日、時間帯、日付）で、パートを読み直しても置き換えられず、時計はこの点から数え続けます。同じダイアログにある **Remove the fixed point** を使うと、モデルの読み取りによる数え直しが再び有効になります。
- レビューでは時刻が最初に、**Story time** の下に、各パートの引用とともに表示されます。誤りがあればチェックを外してください。
- プロンプトブロックは時刻から始まります（*Story time: day 14 after the awakening, evening.*）。追跡対象のキャラクターがシーンにいない場合でも同様です。
- 値は、それが設定された物語の日を覚えています（*day 4*）。整理は、それがどれくらい前だったかを把握し（*a cup of tea, set 9 days ago*）、時間とともに薄れてよいものを削除します。
- 時計がオンの場合、追跡対象のキャラクターがいないパートも含め、すべてのパートがモデルに送られます。どのパートも時間を動かしうるためです。
- 再処理、再生成、別のブランチは、状態と同様に、消えたパートから読まれた内容を取り消します。ただし、あなたが設定した固定点は残ります。

<a id="the-log-of-automatic-changes"></a>

### 自動変更のログ

確認なしに適用されるもの（**Ask before applying** をオフにした実行、自動の整理、`ask` のないコマンド）は、Processing パネルの **Applied automatically** に記録されます。記録されるのは、誰の変更か、どのカテゴリーか、どのパートから（または *tidied*）、そして何がどう変わったか（*+ lantern*、*− rope*、*short sword → axe*）です。ログは編集できませんが、各行には **Revert** ボタンがあります。これは、レビューでその変更のチェックを外したのと同じように働きます。変更によって設定された値は削除され、変更が終わらせた値が再び現在の値になります。その後に値を手で変更した（編集、削除、復元、消去した、または単一のカテゴリーに別の値を設定した）行は、そのままにされます。ログには直近200件の変更が残ります。

![自動変更のログ](../../images/plugin-statetracker-log.png)

<a id="returning-to-an-earlier-point"></a>

### 以前の時点に戻る

変更を適用する実行の前（レビューの有無にかかわらずタブでの実行、新しいパートの自動読み取り、コマンド、整理）には、トラッカーが**チェックポイント**を作ります。これは、実行前にあったキャラクターの状態全体で、物語の時計と読み込み済みの位置（最初の実行前は *Start of the book*）を含みます。Processing パネルの **Checkpoints** は、新しいものから順に一覧表示します。トラッカーが読んだ位置となったパート、時刻、次に行われた実行の種類、適用された変更の数が示されます。有効なブランチ上のパートに属するチェックポイントだけが表示されます。

![取り消された変更](../../images/plugin-statetracker-reverted.png)

行の **Return to this point** は、その実行とそれ以降のすべてを取り消します。キャラクターの値（現在のものと過去のもの）、物語の時計の印、処理済みパート、自動変更のログは、チェックポイントの時点のものに戻ります。次の実行は、そのパートより後のパートを読み直します。取り消された実行のパートも含みます。トラッカーが持っていた状態は、*before a return to a checkpoint* としてチェックポイントに残るので、そこに戻ることもできます。設定、開始点、時計の設定、本のカテゴリーは現在のまま残ります（チェックポイントの値が使っていて、その後削除されたカテゴリーは、その値が使われるときに戻ります）。チェックポイント以降に読まれたものはすべて取り消されるため、その後に手で行った変更も失われます。そのため、実行前に確認を求めます。シリーズの実行が誤った方向に進んだとき、あるいは本の古いバックアップを復元したあとで、信頼できる時点からトラッカーに追いつかせたいときに使ってください。

トラッカーは本ごとに直近20件のチェックポイントを保持します。これらは本の中ではなく、あなたのファイル（*Resources*、本ごとにグループ化）の中に保存されるため、本のバックアップやコピーには含まれません。

<a id="tidying-the-state"></a>

### 状態の整理

物語が何も言わないまま、状態が薄れていくことがあります。気分、濡れた服、息切れ、食後も長く手に持ったままのカップなどです。Processing パネルの **Tidy the state** は、モデルにそれらを確認させます。モデルは直近の処理済みパートと、それらのパートに登場する追跡対象キャラクターの現在の値を読み、各値について次のいずれかを行えます。

![整理のレビュー](../../images/plugin-statetracker-tidy-review.png)

- **drop**：もはや正しくない、または残す価値がないため、削除する。
- **update**：パートでは値が変化したことが示されている（怒りが安堵に変わった）ため、更新する。
- **merge**：同じものを指すリストの項目（*rope* と *coil of rope*）を統合する。

言及されていない値はそのまま残り、ロックされた値も同様です。各変更には理由が付きます。整理が書き込んだ値（更新または統合）には、読み込んだ最後のパートとともに *by the tidy* と印が付きます。物語がその値を明示していないためです。その値を編集すると、あなたのものになります。整理は他の実行と同じようにレビューされます（**Ask before applying** がオフの場合は、すぐに適用されます）。整理によって終了した値は *tidied* として履歴に記録され、整理の前に読まれた最後のパートでの **Reprocess from here** がそれを取り消します。最後に読まれたパートにいないキャラクターは対象外です。そのため、二十章にわたって不在の人物が持っているロープは残ります。

**Tidy automatically** がオン（初期設定）の場合、整理は、確認なしで変更を適用した実行の終わりにも自動で動きます。その条件は、最後の整理以降に **Tidy after this many parts** 件のパート（初期設定では10）が読まれたことです。レビューを要する実行は整理を開始しません。二度目のレビューを強いられないようにするためです。

設定（歯車アイコン）では次の項目を設定できます。

- **Process new parts automatically**：パートが確定すると、モデルがそれを読みます（遅くとも次の生成の前）。**Ask before applying** がオンの場合は、**Process now** を押したときだけ読まれます。執筆の途中でレビューを強いられることはありません。
- **Ask before applying**：オフの場合、変更はすぐに適用され、ログに記録されます（下記参照）。
- **Parts per run**：1回のリクエストで読むパートの数。
- **Tidy automatically** と **Tidy after this many parts**：[状態の整理](#tidying-the-state)を参照してください。整理は、最後に処理された同じ数のパートも読みます。
- **Lorebook for the model**：パートが呼び出すエントリー（初期設定）、ロアブック全体、またはなし。
- **Model for the extraction** と **Protocol for the extraction**：空欄の場合は本のモデルを使います。
- **Use these settings for new books**：この本の設定（モデルとプロトコルを含む。区切り文字は本に残ります）を、State Tracker をまだ使っていない新しい本の初期設定として保存します。**Forget the settings for new books** は組み込みの設定に戻します。すでにトラッカーを使っている本は、それぞれ独自の設定を保ちます。
## Prompts

**State extraction prompt**と**State tidy prompt**のシステムメッセージは、[継承される設定](../books/prompts.md#inherited-settings)です。本に独自の設定があればそれを使い、なければ上位のフォルダで設定されている最も近いものを使います。それもなければ自分の設定を使い、それもなければ、プロンプト言語の組み込みテキストを使います（英語版は実際のモデルで検証済みです）。

これらは、本の *Prompts* タブの *Extension Settings*、フォルダのダイアログ、または *Settings → Extension Settings → State Tracker* で、すべての本について設定できます（空欄の場合は、組み込みテキストがグレーで表示されます）。組み込みテキストの JSON 回答形式は維持してください。プラグインは回答をその形式で読み取ります。本が時間を追跡する場合、[ストーリークロック](#the-story-clock)のルールは、抽出プロンプトの後にプラグインが追加するため、プロンプトに書く必要はありません。

<a id="in-the-prompt"></a>

## プロンプトへの組み込み

歯車ボタンには、本の設定があります:

- **In prompt** は、シーンの追跡対象キャラクターの状態を、すべての生成のプロンプトに挿入します（オンのあいだ、歯車は緑色になります）。
- **Depth** と **Role** は、作者のノートと同じように、挿入位置を指定します。*Depth* は、挿入位置より後にあるメッセージの数です（0 はターンの指示の後、1 は指示の直前です）。
- **Name separators** は、*Present Characters* 欄の分割方法を指定します（既定では `,` `;` `/` `|` と改行）。角括弧内のメモは無視されるため、`Mara (asleep), Fiora` で両方が見つかります。

プロンプトには、発言すべきことがあるシーンのキャラクターが渡されます:

```
The current state of the characters of this scene. Keep to it; it changes only when the story changes it:

Fiora:
- Wearing: torn green cloak, leather boots
- Weapon at hand: none
- Carrying: rope; lantern
```

同じテキストは、テンプレート内の任意の場所に、マクロ {%{`{{command::state-tracker-block::{{presentCharacters}}}}`}%} で挿入できます（引数には任意の名前のリストを使えます）。このマクロは **In prompt** のオン・オフに関係なく状態を出力します。そのため、マクロを使うときは **In prompt** をオフにしてください。そうしないと、モデルが状態を二度受け取ってしまいます。

<a id="commands"></a>

## コマンド

コマンドバーとエージェントで使います:

| コマンド | 内容 |
|---|---|
| `state-status` | 設定、本のカテゴリー、本にコピーがないあなたのカテゴリーを表示します。 |
| `list-state-characters` | 追跡対象キャラクターと、そのカテゴリーを表示します。 |
| `track-state-character` | キャラクターの追跡を開始します。名前、別名、カテゴリー名を指定します。 |
| `stop-tracking-state-character` | キャラクターの追跡を停止し、その状態を削除します（確認あり）。 |
| `list-character-state` | キャラクターの値（現在と過去）を番号付きで表示します。 |
| `set-character-state` | 値を設定します。キャラクター、カテゴリー、テキストを指定します。 |
| `remove-character-state` | 番号で値を削除します。削除された値は履歴に移ります。 |
| `state-tracker-block` | キャラクターのリストについて、プロンプトのテキストを表示します（マクロ）。 |
| `state-process` | モデルに次の部分を読ませ、変更を適用させます。`ask true` を付けると、代わりに変更を番号付きで返します。 |
| `apply-state-changes` | `state-process` または `state-tidy` が返した変更を、すべてまたは指定した番号のものだけ適用します。 |
| `set-story-time` | 処理済みの部分の後の物語時間を手動で設定します（日、時間帯、日付）。いずれも指定しない場合は、固定点を削除します。 |
| `state-tidy` | モデルに、薄れた値を削除、更新、統合させます。`ask true` を付けると、変更を番号付きで返します。 |
| `state-reprocess` | ある部分と、それ以降の部分から読み取った内容を取り消します（確認あり）。 |
| `state-set-start` | 読み取りを開始する部分を設定します。 |
