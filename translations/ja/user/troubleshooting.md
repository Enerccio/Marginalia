# トラブルシューティングとFAQ

<a id="where-are-the-logs"></a>

## ログはどこにありますか？

ほとんどの問題はログに記録されます。

| インストール方法 | ログ |
|---|---|
| デスクトップアプリ | `~/.marginalia/desktop/logs/marginalia.log`（Windowsでは `%USERPROFILE%\.marginalia\desktop\logs`）。前回の実行分は `marginalia.log.1` にあります |
| Docker | `docker compose logs -f marginalia` |

アプリのエラーダイアログ（*内部サーバーエラー*）にもエラーが表示されますが、詳細はログにあります。

問題を報告するときは、ページ左下にあるバージョン表記を含めてください（例: `Marginalia 1.5.0 (93ec118)`。バージョンとビルドのGitコミットです）。

<a id="installing-and-starting"></a>

## インストールと起動

**macOSで「壊れている」「開けません」と表示される。**
アプリはまだ署名されていません。アプリを右クリックして *開く* を選ぶか、`xattr -dr com.apple.quarantine /Applications/Marginalia.app` を実行してください。[デスクトップアプリ](getting-started/desktop-app.md)を参照してください。

**WindowsのSmartScreenでアプリがブロックされる。**
*詳細情報* → *実行* の順にクリックしてください。

**ブラウザが8765以外のポートで開く。**
ポート8765が使用中だったため、デスクトップアプリが空いているポートを選びました。トレイメニューの **Open Marginalia** を使うか、`--port` を指定して起動するとポートを固定できます。

**「Marginalia did not start in time」と表示される。**
デスクトップアプリがサーバーを起動できませんでした。理由はログに記録されています。多くの場合、別のプログラムがファイルを使用中か、拡張機能が壊れていることが原因です（[下記](#extensions)を参照）。

**Docker: ポート8080がすでに使用中。**
`docker-compose.yml` のポートマッピングの左側を変更してください（例: `"8081:8080"`）。その後、ポート8081を開いてください。

**Marginalia が遅い、または「OutOfMemoryError」で停止する。**
メモリを増やしてください。`docker-compose.yml` の `JAVA_TOOL_OPTIONS` で `-Xmx2g`（またはそれ以上）を指定します。

<a id="logging-in"></a>

## ログイン

**「Save login」を選んでもログイン状態が保持されない。**
ログイン状態の保持にはサーバー上でのHTTPSが必要です。HTTPSを備えたリバースプロキシの後ろにMarginaliaを置いてください。[Server（Docker）](getting-started/docker-server.md#https-and-reverse-proxy)を参照してください。

**パスワードを忘れた。**
管理者が新しいパスワードを設定するか、パスワードを消去してください。消去後は空のパスワードでログインし、自分で新しいパスワードを設定できます。手順は *Admin → Users* にあります（[パスワードを忘れた場合](administration/users.md#resetting-a-forgotten-password)を参照）。メールによるパスワードリセットはありません。

**管理者としてログインできる人がいなくなった。**
管理者がいなくなった場合、データベースを直接操作してパスワードをリセットするしかありません。

1. Marginaliaを停止し、[データフォルダ](administration/index.md#the-data-folder)にある `marginalia.sqlite` をバックアップとしてコピーします。
2. `sqlite3` ツールで管理者のパスワードを削除します。
   ```sh
   sqlite3 marginalia.sqlite "UPDATE users SET passwordHash = NULL WHERE login = 'admin';"
   ```
   （ユーザー名は正しいものに置き換えてください。）
3. Marginaliaを起動し、そのユーザー名と**空**のパスワードでログインして、すぐに **パスワードを変更** で新しいパスワードを設定します。

**「Server connection lost」と表示される、またはページが再読み込みを繰り返す。**
リバースプロキシの背後では、プロキシがWebSocketを転送し、長時間のリクエストを許可する必要があります。nginxの例は[Server（Docker）](getting-started/docker-server.md#https-and-reverse-proxy)にあります。デスクトップアプリの場合は、アプリが終了している可能性があります。もう一度起動してください。

**ワークスペースを開くとブラウザが固まる。**
Marginaliaは前回離れたときに開いていたものを再び開くため、非常に長い本（たとえばアーカイブからインポートした本）があると、何か操作する前にページが固まることがあります。Marginaliaのアドレスの `/reset`（例: `https://marginalia.example.com/reset`）を開き、ログインしてください。ワークスペースの保存状態（開いている本、選択中のタブ、フィルター）が消去され、空のワークスペースが開きます。その後、本を開き直す前に[アカウント](account.md)で **ストーリーで一度に読み込むパート数** を設定してください。

<a id="models-and-generation"></a>

## モデルと生成

**「Failed to download model list」と表示される。**
URLが `/v1` で終わっているか、APIキーが正しいか、モデルサーバーが起動しているかを確認してください。モデル一覧を返さないサービスもあります。その場合はモデルIDを直接入力してください。[推論プロバイダー](inference-providers.md#per-type-settings)を参照してください。

**Docker: 同じマシン上のモデルサーバーに接続できない。**
コンテナの内部では、`localhost` はコンテナ自身を指します。`http://host.docker.internal:<ポート>/v1` を使い、モデルサーバーがすべてのアドレスで待ち受けるように設定してください。[同じマシン上のモデル](getting-started/docker-server.md#models-on-the-same-machine)を参照してください。

**「Book is missing model.」/「Book is missing protocol.」と表示される。**
本の *概要* タブでモデルとプロトコルを選んでください。新しい本にも設定されるように、*設定* で **既定のモデル** と **既定のプロトコル** を設定してください。

**「Contextual limit not sufficient.」と表示される。**
ストーリーを含まないプロンプトだけで、応答の後に残るコンテキストの容量を超えています。プロバイダーの **Max Context Size**（またはプロトコルの **最大コンテキストトークン数**）を上げるか、**最大応答トークン数** を下げるか、テンプレート、ロアブックのエントリー、要約を短くしてください。[制限](protocols.md#limits)を参照してください。

**モデルがコンテキストが長すぎると報告する。**
Marginaliaのトークン数は、一部のモデルでは少しずれることがあります。**最大コンテキストサイズ** を数百トークン下げてください。プロンプトが大きすぎそうな場合は、リクエストの前に推定サイズを示す警告が表示されます。

**「The provider did not answer in time」「The provider is limiting requests」「The provider rejected the API key」など。**
Marginaliaは、モデルAPIの失敗を平易な言葉で説明します。[エラーメッセージ](inference-providers.md#error-messages)を参照してください。プロバイダーのダイアログにある **接続テスト** で、本を使わずにURL、キー、モデルを確認できます。タイムアウトと再試行はプロバイダーごとに設定します。

**文が途中で止まる。**
応答の上限に達しています。**最大応答トークン数**（またはプロトコルの Max Reply Tokens）を上げてください。推論モデルは推論の部分もトークンに数えられるため、より多くのトークンが必要です。

**推論を有効にするとリクエストが失敗する。**
APIが `reasoning_effort` に対応していません。プロバイダーの **推論（リーズニング）を有効にする** をオフにしてください。

**「The summaries of the messages with IDs ... are outdated ... Continue generation and delete them?」と表示される。**
要約でカバーされている部分が編集または削除されました。**はい** を選ぶと古い要約を削除して生成を続けられます。その後、新しい要約を生成してください。**いいえ** を選ぶと停止し、要約はそのまま残ります。要約は要約の一覧で印が付くため、まだ正しい内容の要約は再検証できます。[要約が古くなるとき](books/summaries.md#when-summaries-become-outdated)を参照してください。

**プロンプトに「Error」という単語が含まれている。**
テンプレートが存在しない変数やマクロを使っています。`instructions` の代わりに `instruction` と書くなどの誤字が原因であることがよくあります。テンプレートの入力欄の下に、そうした名前が表示されます。[誤字](templates/templates.md#typos)を参照してください。

<a id="lorebooks"></a>

## ロアブック

**エントリーが使われない。** [有効化](lorebooks/entries.md#activation)の条件を順に確認してください。

- エントリーは有効になっていますか？ そのロアブックと、そこに至るまでのすべてのサブロアブックは有効になっていますか？
- エントリーにタグがありますか？ その場合は、本にそのタグのどれかが必要です（本のタグは *概要* タブにあります）。除外タグは該当するエントリーを除外します。
- ロアブック自体に **タグ** がありますか？ そのタグはすべてのエントリーに適用されます。
- フィルターがありますか？ フィルターが見るのは**書いているパートの指示文だけ**で、それ以前のストーリーは見ません。**登場人物** か指示文にキャラクターの名前を書いてください。
- フィルターは正規表現ですか？ 不正な正規表現は一致することがありません。

生成されたパートの **プロンプトを表示** を使うと、どのロアが送信されたかがわかります。

<a id="prompts-and-settings"></a>

## プロンプトと設定

**別のタブに切り替えられない。**
*設定* タブに保存されていない変更があります。**保存** をクリックするか、**変更を破棄** をクリックしてください。

**自分の要約プロンプトが使われない。**
本自身の要約プロンプト（*プロンプト* タブ）は、*設定* の **既定の要約プロンプト** より優先されます。既定の設定を使うには、本の入力欄を空にしてください。メタ要約には専用のプロンプト、**既定のメタ要約プロンプト** があります。

**Style、Point of View、Tense のマクロが動かない。**
これらの入力欄はプレーンテキストで、マクロを処理するのはテンプレートだけです。マクロをマスターテンプレートかユーザープロンプトに書いてください。

<a id="backups"></a>

## バックアップ

**データベースのバックアップを復元したが、何も変わらない。**
復元は次回の起動時に適用されます。Marginaliaを再起動してください。[復元](administration/database-backups.md#restoring)を参照してください。

**別のコンピュータに移行した後、本のバックアップが見つからない。**
本のバックアップはデータベースの一部ではなく、ファイルです。`data` フォルダもコピーしてください。[データフォルダ](administration/index.md#the-data-folder)を参照してください。

<a id="extensions"></a>

## 拡張機能

**インストールした拡張機能が表示されない。**
本を閉じて開き直すか、ページを再読み込みしてください。

**拡張機能の読み込みに失敗し、Admin → Extensions に表示されない。**
Marginaliaを停止し、`extensions` フォルダからその JAR を削除して、再び起動してください。[拡張機能が失敗したとき](administration/extensions.md#when-an-extension-fails)を参照してください。

**Marginaliaを更新した後、拡張機能が拒否された、または動かなくなった。**
拡張機能は特定のバージョンのMarginalia向けにビルドされており、読み込み時に検査されます。Admin → Extensions の **検証** でレポートを開き、お使いのMarginaliaに合った拡張機能のバージョンを読み込んでください。[拡張機能が失敗したとき](administration/extensions.md#when-an-extension-fails)を参照してください。

**拡張機能を更新した後も、古いバージョンが動いている。**
先に古いバージョンを読み込み解除してから新しいバージョンを読み込むか、Marginaliaを再起動してください。
<a id="faq"></a>

## よくある質問

**私の文章はどこかに送信されますか?**
送信されるのは、あなたが設定した推論プロバイダーだけです。各パートのプロンプト(およびトークン数を数えるリクエスト)は、そのプロバイダーの API に送られます。ご自身のコンピューター上で動かしているモデルを使う場合、データはどこにも出ていきません。Marginalia にテレメトリはありません。

**どのモデルを使えばよいですか?**
良い小説が書けて、十分に大きなコンテキストを持つモデルであれば何でも構いません。長編には 32 000 トークン以上のコンテキストがあると快適です。同じ本で何種類か試してみてください。プロバイダーの切り替えは **概要** タブでワンクリックでできます。

**複数の人で一冊の本を共同執筆できますか?**
いいえ。すべての本は一人のユーザーに属します。[公開](books/publishing.md)すれば、ほかのユーザーも読むことができます。

**Marginalia はオフラインで使えますか?**
はい。ローカルで動いているモデル(llama.cpp、LM Studio、Ollama など)を使えば可能です。Marginalia 自体はインターネット接続を必要としません。

**本を Marginalia の外に出すにはどうすればよいですか?**
**ストーリー** タブの設定メニュー(⚙)から、[ストーリーをエクスポート](books/export.md)してテキスト、HTML、Word、PDF、EPUB の形式で保存できます。すべてのブランチを含めて全部残したい場合は、[本のバックアップをエクスポート](books/backups.md#exporting-and-importing)(JSON)してください。[ビューアー](books/publishing.md)で読むこともできます。

**スマートフォンで使えますか?**
[ビューアー](books/publishing.md)はスマートフォン向けに作られており、Marginalia はブラウザのメニューから(*Install app* / *Add to Home Screen*)ホーム画面にアプリとして追加できます。ブラウザウィンドウの幅が 768 ピクセルより狭いとき、エディターは[スマートフォン用のレイアウト](phone.md)に切り替わります。ただし管理ページはなく、ロアブックエディターも機能が縮小され、すべての拡張機能が使えるわけではないので、執筆と閲覧に向いています。初期設定や管理は、大きな画面のほうが簡単です。

**ライトテーマや別の言語はありますか?**
どちらもあります。言語セレクターの隣にある太陽/月のボタンでテーマを切り替えられます(初期設定はダーク)。言語セレクターには日本語のほか、拡張機能が追加する言語も表示されます([アカウント](account.md#theme)を参照)。
