# リソース

**リソース**タブには、Marginaliaにアップロードしたファイルが一覧表示されます。ここには、本の部分の[画像](books/story-editor.md#images)や、[Audiobook](extensions/audiobook.md)などの拡張機能が保存した音声が含まれます。このタブは、ファイルを探し直す、音声を聴く、ダウンロードする、ファイルを使っている本に手を加えずに、より良いものに差し替える、不要になったものを削除する、といった作業をする場所です。

![リソースタブ](../images/resources-tab.png)

ファイルは、それを使っているものごとにまとめられています。表の各行は1つのオブジェクトで（例：本の部分 `ChatMessage #123`）、そのファイルの数、合計サイズ、最も新しいファイルの日付が表示されます。行の矢印をクリックするとオブジェクトが開き、そのファイルを確認できます。表はスクロールやグループを開くのに合わせて読み込まれるため、数千のファイルがあっても動作は軽快なままです。列見出しをクリックするとその列で並べ替えでき、グループ内のファイルもそれに従います。既定では、最も新しいものが先頭に来ます。

| 行 / 列 | |
|---|---|
| **使用元** | ファイルが追加されたオブジェクトです。*なし*は、どこからも使われていないファイルをまとめます。名前の後ろの *(gone)* は、そのオブジェクトが削除されたか、もう存在しないことを意味します。その場合、ファイルはおそらく不要です。グループ内では、画像の小さなプレビューとアップロード時のファイル名が表示されます。 |
| **種類** | ファイルの種類です（例：`image/png`）。 |
| **サイズ** | ファイルのサイズです。グループの場合は、含まれるファイルの合計です。 |
| **作成日時** | ファイルがアップロードされた日時です。グループの場合は、最も新しいファイルの日時です。 |

これは参考のために残している情報にすぎません。Marginaliaはこの関係を強制しません。画像は、それを追加した部分がなくなった後も引き続き機能しますし、同じ画像を複数の部分で使うこともできます（たとえば[分岐](books/branches-and-story-tree.md)させた後、分岐先は元の部分と同じ画像を持ちます）。

<a id="play"></a>

## 再生

音声の種類（`audio/mpeg`、`audio/wav`など）のファイルには、他のボタンの前に**再生**ボタン（三角形）があります。ページ内でファイルを再生します。再生中はボタンが**一時停止**に変わり、停止するか音声が終わると再生に戻ります。同時に再生されるのは1つのファイルだけです。別のファイルを再生し始めると、再生中のものは止まります。

<a id="download"></a>

## ダウンロード

行のダウンロードボタン（下向き矢印）で、ファイルをコンピューターに保存します。

<a id="replace-the-content"></a>

## 内容の差し替え

行のアップロードボタンを押すと、新しいファイルを選択するダイアログが開きます。新しい内容は新しいファイルとして保存され、そのエントリーは新しいファイルを指すようになります。そのため、**そのエントリーを使っているものはすべて新しい内容を表示します**。部分を変更する必要はありません。画像をより良いバージョンに差し替えたり、誤ったアップロードを直したりするのに使ってください。

- 画像は画像（PNG、JPEG、GIF、WebP、10 MBまで。[画像の追加](books/story-editor.md#images)と同じ条件）でのみ差し替えられます。
- エントリーの名前は、新しいファイルの名前になります。
- 以前のファイルはデータフォルダーから削除されません。[下記](#what-delete-does)を参照してください。

![リソースの内容を差し替える](../images/resources-replace.png)

<a id="deleting"></a>

## 削除

行のゴミ箱ボタンで、ファイルを1つ削除します。複数のファイルを削除するには、先頭の列でそれらにチェックを入れ、表の上にある**選択したものを削除**を選びます。グループ（オブジェクトの行）にチェックを入れると、そのファイルがすべて削除されます。見出しのチェックボックスを使うと、すべてのグループを選択できます。Marginaliaは削除する前に確認します。

<a id="what-delete-does"></a>

### 削除の働き

- ファイルは表から消え、それを使っている部分からも消えます。部分は単に画像を表示しなくなります。部分の本文、要約、エクスポートは変更されません。
- エントリーは**削除済みとしてマークされる**だけです。管理画面の[クリーンアップ](administration/cleanup.md)で、データベースから完全に取り除かれます。
- **ファイルはデータフォルダー**（`data/<your login>/images`）**に残ります**。クリーンアップの後も同様です。リソースを削除しても、それだけでディスク容量が空くことはありません。管理者は、管理画面の[リソースファイル](administration/resource-files.md)タブで、どこからも使われていないファイルを削除します。
- クリーンアップがエントリーを削除するまでは、[ゴミ箱](trash.md)から復元できます。ファイルはまだデータフォルダーにあるため、画像は再び機能します。クリーンアップの後は、それより前に作られた[データベース全体のバックアップ](administration/database-backups.md)だけがエントリーを含みます。ファイル自体は引き続きフォルダーに残っています。
