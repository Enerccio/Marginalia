# 推論プロバイダー

推論プロバイダーとは、モデルへの接続のことです。APIのアドレス、APIキー、モデル、およびその上限値を含みます。どの本も、必ず1つのプロバイダーを使います。プロバイダーはいくつでも登録できます。たとえば、物語の執筆には大規模なクラウドモデルを、実験には小規模なローカルモデルを使い分けることができ、本ごとにいつでも切り替えられます。

プロバイダーはあなたのアカウントに属します。他のユーザーには見えず、APIキーも見えません。APIキーは暗号化して保存されます（[データフォルダー](administration/index.md#the-data-folder)を参照してください）。

プロバイダーを追加するには、権限 **独自のモデルの作成** が必要です。この権限は管理者が付与します（管理者は常にこの権限を持っています。[権限](administration/permissions.md)を参照してください）。この権限がない場合は、管理者が[共有](#shared-providers)してくれたプロバイダーしか使えず、**推論プロバイダーを追加** ボタンは表示されません。

![推論プロバイダータブ](../images/inference-providers-list.png)

<a id="supported-apis"></a>

## 対応しているAPI

Marginaliaは、**OpenAI Chat Completions** インターフェース（`/v1/chat/completions`、ストリーミング対応）を実装しているAPIであれば、どれとでも連携できます。多くのサービスやローカルサーバーがこれに対応しています。

| サービス | OpenAIのURL |
|---|---|
| OpenAI | `https://api.openai.com/v1` |
| OpenRouter | `https://openrouter.ai/api/v1` |
| LiteLLM proxy | `http://localhost:4000/v1` |
| llama.cpp (`llama-server`) | `http://localhost:8080/v1` |
| LM Studio | `http://localhost:1234/v1` |
| Ollama | `http://localhost:11434/v1` |
| vLLM | `http://localhost:8000/v1` |

ポート番号は各サーバーの既定値です。実際にお使いのサーバーが動作しているポートを指定してください。

!!!warning ポート8080
Docker版のMarginaliaもポート8080を使用します。同じマシンでllama.cppを動かす場合は、別のポートで起動してください（`llama-server --port 8081`）。
!!!

!!!
[Docker版](getting-started/docker-server.md)では、`localhost` はMarginaliaのコンテナ自身を指します。同じマシン上のモデルサーバーには `http://host.docker.internal:<ポート>/v1` を使ってください。詳しくは[同じマシン上のモデル](getting-started/docker-server.md#models-on-the-same-machine)を参照してください。
!!!
<a id="adding-a-provider"></a>

## プロバイダーを追加する

**推論プロバイダー**タブを開き、**推論プロバイダーを追加**をクリックします。既存のプロバイダーは鉛筆ボタンで編集し、ゴミ箱ボタンで削除します。クローンボタン（2 枚の紙のアイコン）を使うと、確認した名前でプロバイダーのコピーを作成できます（名前は元の名前に *(Copy)* を付けたものになります）。コピーには同じアドレス、モデル、**APIキー**（または拡張機能の設定）、推論の設定、トークン上限、パラメータが引き継がれるため、同じサービスの別のモデルを使いたいときは、名前を付けてクリックするだけで済みます。コピーは共有されず、独自の上限や使用量も持ちません。クローンできるのは自分で作成したプロバイダーだけです（管理者が共有しているプロバイダーのキーは見えないため、クローンできません）。また、プロバイダーを作成する権限があるときにのみクローンできます。

ダイアログの上部には次の項目があります。

| 項目 | |
|---|---|
| **名前** | プロバイダーに付ける名前で、本のモデルを選ぶときに表示されます。モデル名も含めてください（例：`OpenRouter - Claude Sonnet`）。 |
| **種類** | API の種類です。**OpenAI 互換**、または（読み込まれている[拡張機能](extensions/index.md)が提供する）プロバイダーの場合は**拡張機能**を選びます（[Google Gemini](extensions/google-genai.md) や [Anthropic Claude](extensions/anthropic.md) など。該当する拡張機能が読み込まれているときにのみ選べます）。種類はプロバイダーを作成した後に変更できません。 |
| **プロバイダー** | 種類が**拡張機能**のときのみ使います。どの拡張機能のプロバイダーかを指定します。その拡張機能固有の設定は**種類別設定**タブに表示されます。 |

<a id="per-type-settings"></a>

### 種類別設定

![モデル一覧を読み込んだ状態の種類別設定](../images/inference-provider.png)

このタブはダイアログより背が高く、スクロールして操作します。下の方の項目は次のとおりです。

![タイムアウト、再試行回数、追加パラメータ、接続テスト](../images/inference-provider-2.png)

| 項目 | |
|---|---|
| **OpenAI URL（/v1 で終わる）** | API のベースアドレスです。[上の表](#supported-apis)を参照してください。`/chat/completions` は含めません。 |
| **APIキー** | サービスのキーです。ローカルサーバーは通常キーを確認しないため、空欄のままにしておけば、Marginalia はプレースホルダーの `none` を送信します。 |
| **モデル** | 使用するモデルです。**更新**をクリックすると API からモデル一覧を読み込みます。または、モデル ID を直接入力することもできます（例：OpenRouter の `anthropic/claude-sonnet-4.5`）。 |
| **タイムアウト（秒）** | API が応答するまで、また書き始めた後に次のテキストが届くまで待つ時間です。既定値は 300 です。推論モデルは最初のテキストまでに数分かかることがあります。この時間の間、何も届かないリクエストはタイムアウトのメッセージとともに失敗します（モデルの思考もテキストとみなされるため、思考を続けているモデルは打ち切られません）。変更は次のリクエストから反映され、作業中のエージェントのリクエストも対象になります。 |
| **再試行回数** | API がレート制限（429）やサーバーエラー（5xx）を返した場合、または接続できなかった場合に、リクエストを繰り返す回数です。試行の間隔は徐々に長くなり、API の `Retry-After` ヘッダーも尊重されます。既定値は 2 で、0 にすると再試行をしません。再試行されるのはリクエストの開始部分だけで、すでに届いたテキストが二重に書き込まれることはありません。 |
| **トークナイザー** | Marginalia が、このプロバイダー向けにテキストのトークン数をどのように数えるかを決めます。**自動**（既定値）は、サーバーのトークナイザー用エンドポイント（OpenAI、llama.cpp、LiteLLM）を順に試し、最初に応答したものを使います。どれも応答しない場合は、ローカルの推定値を使います。特定のものだけを使う場合はそれを選び、サーバーを呼び出さないローカルの推定値を使う場合は **LOCAL_TOKKIT** を選びます（数えることでサーバーが別のモデルを読み込んでしまう場合に便利です）。プラグインのトークナイザーもここに表示されます。プラグインのトークナイザーには、アドレス、モデル、テキストが渡されますが、APIキーは渡されず、選んだ場合にのみ使われます。**トナイザーをテスト**は、サンプルテキストを、このプロバイダーが試す方法で数え、それぞれの応答を表示します。プロバイダーを新規作成するとき、アドレスに合うプラグインのトークナイザーが、自分で選ぶまで初期選択されます。 |
| **思考を送り返す** | モデルが次のリクエストで、自分の思考を受け取るかどうかを決めます。詳しくは[思考を送り返す](#send-the-thinking-back)を参照してください。OpenAI 互換のプロバイダーにのみ使われ、Anthropic と Google のプロバイダーは、それぞれの API に必要なものを自動的に送信します。 |
| **追加パラメータ** | このプロバイダーへのすべてのリクエストに追加するフィールドを持つ JSON オブジェクトです。たとえばローカルサーバーなら `{"top_k": 40, "min_p": 0.05}`、OpenRouter なら `{"provider": {"order": ["anthropic"]}}` です。ここで設定したフィールドは、[プロトコル](protocols.md)から来る同じ設定（例：`temperature`）や、応答の上限（`max_completion_tokens`）より優先されます。有効な JSON オブジェクトであるか、空である必要があります。 |

既存のプロバイダーを編集する場合、APIキーは再び表示されません。**APIキーをリセット**をクリックして新しいキーを入力しない限り、そのまま保持されます。

**更新**は、フォームに入力された URL とキーを使って API にモデル一覧（`/v1/models`）を問い合わせます。*Failed to download model list* で失敗した場合は、URL（`/v1` で終わっている必要があります）、キー、サーバーが起動しているかを確認してください。モデル一覧を提供していないサービスもあります。その場合はモデル ID を直接入力してください。

**接続テスト**は、保存せずにフォームの値を確認します。API にモデル一覧を問い合わせ、続けて選択中の**モデル**に 1 トークンだけの応答を求めます。再試行は行いません。成功メッセージが表示されれば、URL、キー、モデルが一緒に機能していることを意味します。失敗した場合は、原因が示されます（[エラーメッセージ](#error-messages)を参照してください）。モデル一覧を提供していないサービスもあり、その場合は 1 トークンの応答だけが確認されます。

<a id="general-settings"></a>

### 全般設定

![推論プロバイダーの全般設定](../images/inference-provider-general.png)

| 項目 | |
|---|---|
| **最大コンテキストサイズ** | 必須です。モデルが受け付けるトークンの合計数（プロンプトと応答を合わせた数）です。 |
| **最大応答トークン数** | 必須です。モデルが書き出してよい最長の応答です。API には `max_completion_tokens` として送信され、この分だけコンテキストの一部が応答のために空けられます。*最大コンテキストサイズ*より小さい値にしてください。 |
| **接続数** | このモデルへ同時に送ってよいリクエストの数です。すべてのユーザーとすべての種類（自分の生成、補助的な問い合わせ、翻訳、注釈、[エージェント](agents.md#one-model-several-agents)、プラグイン）の合計で数えます。超えた分は順番を待ち、来た順に処理されます。待機中の生成には *モデルの応答待ち：このリクエストの前に N 件* と表示され、**停止**をクリックするとキューから外れます。既定値の **1** は、スロットが 1 つだけのローカルサーバー（GPU が 1 つ）向けです。同時に複数のリクエストに応答できるクラウドモデルでは、生成と並行して補助的な問い合わせを走らせられるよう、より大きな値を設定できます。 |
| **ロア画像を送る** | 本の、ターンで使用される[ロアブックのエントリーの画像](lorebooks/lorebooks.md#editing-in-full-screen)を、テキストと一緒に送信します。既定ではオフです。画像を受け付けるモデルでのみオンにしてください。画像に対応していないモデルはリクエストを拒否し、そのターンは失敗します。ロアブロックにあるエントリーの画像は、システムプロンプトの直後に独立したメッセージとして（モデルの短い回答を添えて）送られ、それ以外のエントリーの画像は、あなたのプロンプトと一緒に送られます。 |
| **画像をシステムメッセージに入れる** | （OpenAI 互換で、*ロア画像を送る*が有効なとき）ロアブロックの画像を、ロアのテキストと並べて、システムメッセージそのものに入れます。画像をそこで受け付けるサーバーとチャットテンプレートでのみ使用してください。ほとんどのものは対応していないため、リクエストが失敗します。 |
| **ジェイルブレイクが必要**、**ジェイルブレイクプロンプト** | 特定の内容の執筆を拒否するモデルのための追加プロンプトです。チェックを入れると、ジェイルブレイクプロンプトがプロンプトの最初に置かれます。 |
| **推論（リーズニング）を有効にする**、**推論の強度** | 推論（「思考」）モデル向けです。[推論モデル](#reasoning-models)を参照してください。 |

Marginalia は、コンテキストのうち**最大応答トークン数**分を応答のために空け、残りをプロンプトで埋めます。テンプレート、[ロアブック](lorebooks/index.md)のエントリー、[要約](books/summaries.md)はトークン数に含まれ、収まらない物語の古い部分は除外されます。コンテキストが 32,000 トークンで、応答が最大 2,000 トークンの場合、プロンプトには 30,000 トークンが割り当てられます。

**最大コンテキストサイズ**は、サービスのドキュメントから取得し、それより少し小さい値を設定してください。トークン数は必ずしも正確ではなく、実際の上限を超えたリクエストは失敗します。[プロトコル](protocols.md)は、一部の本について両方の上限を下げることはできますが、引き上げることはできません。
<a id="error-messages"></a>

## エラーメッセージ

API がリクエストを拒否した場合、Marginalia は内部エラーを表示する代わりに、何を直せばよいかを伝えます。その後に API 自身が返した内容が続きます:

![プロバイダーのエラーがユーザーに表示される例](../images/error-dialog.png)

| メッセージ | 原因 |
|---|---|
| *The provider rejected the API key.* | **APIキー**が間違っているか、期限切れか、未入力です。 |
| *この API キーでは、このモデルまたはエンドポイントを利用できません。* | キーは有効ですが、そのモデルへのアクセス権がありません。 |
| *The provider does not know the configured model.* | **モデル**の指定が間違っています。**更新** を使うと、API が認識している名前を確認できます。 |
| *Nothing was found at the configured URL.* | **OpenAI URL** が間違っています。通常は `/v1` で終わります。 |
| *The prompt does not fit into the context of the model.* | **最大コンテキストサイズ** がモデルの実際の受付上限より大きくなっています。値を下げてください。 |
| *The provider is limiting requests.* | 再試行の後もレート制限または利用枠の上限に達しています。 |
| *The provider failed to process the request.* | 再試行の後もサービス側に問題があります（5xx）。 |
| *The provider did not answer in time.* | **タイムアウト（秒）** を増やすか、サーバーの状態を確認してください。 |
| *Cannot connect to the provider.* | サーバーが起動していないか、Marginalia から到達できないか、URL に誤字があります。 |
| *The provider rejected the request.* | その他の拒否です。多くは **追加パラメータ** にあるモデルが対応していないフィールドか、モデルが対応していない推論の指定が原因です。 |

<a id="warning-before-sending"></a>

## 送信前の警告

Marginalia は、コンテキストを **最大コンテキストサイズ** から **最大応答トークン数** を引いた分までしか埋めません。完成したプロンプトがそれでも大きすぎる場合（たとえば拡張機能がテキストを追加した場合や、トークン数の見積もりが外れた場合）、リクエストを送信する前に、推定サイズを示す警告が表示されます。リクエストはそれでも送信されます。API が拒否するか、プロンプトを切り詰める可能性があります。

![プロンプトが収まらないおそれがあるという警告](../images/context-warning.png)

<a id="reasoning-models"></a>

## 推論モデル

推論モデルは、答える前に考えます。**推論（リーズニング）を有効にする** にチェックを入れると、Marginalia は選んだ **推論の強度**（*なし*、*低*、*中*、*高*）を `reasoning_effort` として API に送ります。強度を上げると一般に計画の行き届いた文章になりますが、応答は遅く、高価になります。すべての API がこのパラメータに対応しているわけではありません。推論を有効にしてリクエストが失敗する場合は、オフにしてください。

モデルが推論内容を返す場合（サーバーによって `reasoning_content` または `reasoning` として）、生成された部分の上に **推論を表示** の下で表示されます。推論は物語の一部ではなく、下の **思考を送り返す** を設定しない限り、モデルに送り返されることもありません。

<a id="send-the-thinking-back"></a>

### 思考を送り返す

**思考を送り返す**（OpenAI 互換プロバイダーの *種類別設定* 内）は、モデルの思考を次のリクエストでモデルに戻すかどうかを指定します。戻す場合は、そのモデルの以前のメッセージの `reasoning_content` として送られます:

| 値 | |
|---|---|
| **なし**（既定） | 送り返しません。ほとんどのモデルやサーバーに適しており、未知のフィールドを拒否する API にも適しています。 |
| **ツール呼び出しの間** | 1 回の回答でツール呼び出しが続いている間だけ送り返します。ツールを呼び出したモデルは、その結果とともに自分の思考を受け取ります。あなたの新しいメッセージからは、古い思考を含まずに始まります。Google が Gemma 4 に求めている方式がこれです（*thoughts must not be removed between the function calls*、ただしターンをまたぐと削除）。 |
| **常に** | 思考を保持しているチャットの、以前の回答にも送り返します（アークアウトラインのプロットウィザードがこれにあたります）。Gemma 4 のサーバーのように、古い思考を自動的に落とすテンプレートのサーバーでは、この設定は無視されます。 |

この設定はツールループ（プロットウィザード、ツールを使う生成機能）とエージェントに適用されます。エージェントは、1 回のターンのツール呼び出しが続いている間、それ以前のラウンドの思考を受け取ります（思考はコンソールのメッセージに保持され、保存されたメッセージには含まれません）。サーバーがこのフィールドを受け付ける必要があります。llama.cpp は対応しており（`reasoning` ではなく `reasoning_content` を読みます）、LiteLLM を経由する場合も同様です。未知のメッセージフィールドを拒否するプロバイダーでは失敗するため、その場合は *なし* のままにしてください。

![生成された部分の推論](../images/reasoning-view.png)

推論もまた応答の一部として数えられます。推論モデルには **最大応答トークン数** を大きめに設定してください。長い推論の後に、テキストが途中で切れることがあるためです。

<a id="token-counting"></a>

## トークンの計算

Marginalia は、物語のどこまでをプロンプトに収めるかを決めるためにトークンを数えます。可能な場合はプロバイダーに問い合わせ、次の方法を順に試します:

1. OpenAI のトークン計算エンドポイント（`/v1/responses/input_tokens`）、
2. llama.cpp の `/tokenize` エンドポイント、
3. LiteLLM の `/tokenize` エンドポイント、
4. LiteLLM の `/v1/messages/count_tokens` エンドポイント（Anthropic のモデル向け）、
5. OpenAI のトークナイザーによるローカルの推定。

最初に成功した方法が、それ以降ずっと使われます。ローカルの推定は多くのモデルで近い値になりますが、正確ではありません。これも **最大コンテキストサイズ** を実際の上限より少し低く保つべき理由の一つです。種類が *拡張機能* のプロバイダーは、その拡張機能が定める方法で数えます。[Google Gemini](extensions/google-genai.md) と [Anthropic Claude](extensions/anthropic.md) の拡張機能は、プロバイダーに数えてもらいます。

<a id="prompt-cache"></a>

## プロンプトキャッシュ

作業の種類（新しい部分、注釈、書き直し、要約など）ごとに Marginalia が送るリクエストには、すべて `X-Session-ID` ヘッダーが付きます。これは、同じユーザーと同じ種類に対して常に同じ値になるハッシュです。プロンプトキャッシュを保持するサーバーやプロキシは、これを使って同じ種類の前のリクエストのキャッシュを見つけられます。このヘッダーを知らないサーバーは無視します。ディスクに保存される llama.cpp のスロットを一つ使う例については、[プロンプトキャッシュとセッション ID](prompt-cache.md) を参照してください。

## 共有プロバイダー

複数のユーザーがいる環境では、管理者はプロバイダーを **共有** できます。プロバイダーのダイアログで **全ユーザーと共有** にチェックを入れてください（このチェックボックスは管理者にだけ表示されます）。すると、他のすべてのユーザーは自分の本の **モデル** の一覧と、自分の **推論プロバイダー** タブにそのプロバイダーを見つけられます。その際、*共有* の欄には **はい** と表示されます。ユーザーはそれを使えますが、開いて接続先やAPIキーを見たり、変更したり、削除したりすることはできません。これができるのは所有者だけです。共有プロバイダーを参照している本、バックアップ、リストアは、それを見られるすべてのユーザーにとって引き続き動作します。

![一般ユーザーの推論プロバイダータブに表示された共有プロバイダー](../images/provider-shared-user.png)

プロバイダーを共有すると、他のユーザーが所有者のサービス利用枠を消費できるようになります。ユーザーが自分のプロバイダーを追加できないようにして、共有されたものだけを使えるようにするには、[ユーザーとプロバイダー](administration/users.md#users-and-providers) を参照してください。

## 共有プロバイダーの制限

管理者は、共有プロバイダーごとに、各ユーザーができることを制限できます。**Inference Providers** タブで、共有プロバイダーを所有する管理者には、その行に **Limits** ボタン（錠前のアイコン付き）があります。これを押すと、設定済みの制限を一覧する表が開きます。**Add limit** を押すと新しい制限を作成できます。ユーザーと制限の種類を選択してください。

![共有プロバイダーの制限](../images/provider-limits.png)

| 制限の種類 | 意味 |
|---|---|
| Unlimited | 制限なし（制限を設定していないのと同じです）。 |
| Token limit | ユーザーは、一定期間に指定されたトークン数まで使用できます。 |
| Not available | ユーザーはそのプロバイダーを使用できません。そこへリクエストを送ろうとする操作はすべて失敗します。 |

**トークン制限**には **reset**（リセット）があります。毎日、毎週月曜日から、または毎月のいずれかで、暦に基づく期間になります（期間はサーバーのタイムゾーンで計算されます）。さらに、送信トークン（**sent**）、生成トークン（**generated**）、そして両方の合計（**in total**）の3つの上限があり、それぞれ空欄にすると上限なしになります。どれか一つでも先に到達すると、次のリセットまでユーザーは使用できなくなります。3つすべてを設定する場合、送信トークンの上限と生成トークンの上限の合計が、合計の上限を下回ってはいけません（下回ると合計の上限に到達できなくなるためです）。そうでない場合、ダイアログは保存を受け付けません。例えば、合計10万に対して送信10万、生成2万は問題ありません。しかし、合計10万に対して送信2万、生成1万では保存できません。

![制限の追加](../images/provider-limit-edit.png)

タイマーで自動的にリセットされることはありません。ユーザーが新しい期間に初めてプロバイダーを使うとき（または自分の制限を確認するとき）に、使用済みトークン数がゼロから数え始めます。リクエストのサイズは送信前に分かるため、プロンプトを送ると**送信**または**合計**の上限を超えてしまう場合、そのリクエストは拒否されます（プロンプトの長さは Marginalia 独自の見積もりで測るため、サービス側のカウントとわずかに異なることがあります）。生成トークンは事前には分からないため、リクエストが終わった時点で数えられます。そのため、ユーザーは上限に到達したときに初めて停止され、最後の応答によって上限を超えることがあります。表に制限のないユーザーは、制限されません。

生成トークンが上限を超えないようにするには、**Hard limit**（厳格な上限）にチェックを入れてください（生成トークンの制限がある場合のみ選択できます）。リクエストは、許可されている最大の応答分のトークン数（プロバイダーの **Max Response Size**、またはプロトコルの小さい方の値）を確保します。厳格な上限を設定している場合、その確保分が生成トークンの残りに収まらないと、リクエストは拒否されます。そのため、プロバイダーの応答サイズより低い厳格な上限を設定すると、すべてのリクエストが拒否されます。表やユーザーの情報には、このような制限の横に *hard* と表示されます。厳格な上限は生成トークンにのみ適用されます。**in total** の上限は、最後の応答によって依然として超えることがあります。

すべてのユーザーは、自分のタブで共有プロバイダーを読み取り専用の行として見ることができます。共有プロバイダーの **info** ボタン（*i* の付いた丸いアイコン）を押すと、自分の制限が表示されます。今期の使用量、制限の内容、リセットされるタイミングです。制限に到達すると、ストーリーエディター、要約、拡張機能はリクエストを送信せず、エラーを表示します。

![ユーザーに表示される制限と、今期の使用量](../images/provider-limit-info.png)

## 使用量

**Inference Providers** タブには、プロバイダーごとに、あなたがそのプロバイダーで使用した **Tokens sent**（プロンプト、「プリフィル」）と **Tokens generated**（応答、推論を含む）が表示されます。これらはすべての本、要約、拡張機能について合計した値です。共有プロバイダーについては、ユーザーごとに別々に数えられるため、表示されるのはあなたの分だけです。

管理者には、このタブに **Usage per user** ボタンも表示されます。これを押すと、すべてのユーザーが各プロバイダーで使用した量（送信トークン、生成トークン、リクエスト数、最後のリクエストの時刻）を示す表が開きます。

![ユーザー別の使用量](../images/provider-usage.png)

表示される数値は、サービスが報告した値です。サービスが報告しない場合（または途中で停止したリクエストの場合）は、[トークンのカウント](#token-counting)で説明している local estimate（ローカルの推定値）で数えるため、数値はおおよその値になります。テキストが届く前に失敗したリクエストは、数えられません。管理者が共有プロバイダーに対して[制限](#limits-of-shared-providers)を設定していない限り、これらの数値は参考情報としてのみ表示されます。

!!!
Marginalia は、サービスにトークン数を報告するよう要求します（`stream_options` の `include_usage`）。プロバイダーごとにこの動作を変えるには、**Additional Parameters**（追加パラメータ）に独自の `stream_options` を入れてください。例えば `{"stream_options": {"include_usage": false}}` と入力します。これは Marginalia が送信する内容を置き換えるため、ローカルの推定値が使われます。
!!!

## 本でプロバイダーを使う

各本のモデルは、その **About** タブにある **Model** 欄で設定します。すべての新しい本でプロバイダーを使うには、**Settings** タブで、そのプロバイダーを **Default Model**（既定のモデル）として選択します。本のプロバイダーを変更すると、次に生成される部分から反映されます。変更前に書かれた部分は、そのままになります。

<a id="troubleshooting"></a>

## トラブルシューティング

| 問題 | 確認すること |
|---|---|
| *Failed to download model list* | URL が `/v1` で終わっているか、API キー、サーバーが起動していて Marginalia から到達できるか。サービスにモデル一覧がない場合は、モデル ID を直接入力してください。 |
| *The provider did not answer in time.* | プロバイダーの **Timeout (seconds)**（タイムアウト（秒））を上げてください。推論モデルは数分かかることがあります。 |
| *The provider is limiting requests.* | 待つか、**Retries**（再試行回数）を上げてください。 |
| *Book is missing model.* | 本にプロバイダーが設定されていません。**About → Model** で選択してください。 |
| *Contextual limit not sufficient.* | 物語を含まないプロンプトが、コンテキストから応答トークンを引いた量に収まりません。**Max Context Size**（最大コンテキストサイズ）（またはプロトコルの **Max Context Tokens**（最大コンテキストトークン数））を上げるか、**Max Response Tokens**（最大応答トークン数）を下げるか、テンプレートやロアブックの項目を短くしてください。 |
| テキストが途中で止まる | **Max Response Tokens**（またはプロトコルの **Max Reply Tokens**（最大返信トークン数））が低すぎます。特に推論モデルの場合に起こりがちです。 |
| 推論を有効にするとAPIからエラーが出る | APIが `reasoning_effort` に対応していません。**Enable Reasoning**（推論（リーズニング）を有効にする）をオフにしてください。 |
