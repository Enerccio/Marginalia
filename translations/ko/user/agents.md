# 에이전트 (실험적)

!!!warning 실험적 기능
에이전트는 1.4.0에서 새로 도입되었으며, 실제 모델과 함께 사용된 경험이 거의 없습니다. 약한 모델이 도구 호출을 잘못하거나, 예상보다 많은 토큰을 소비하거나, 검토 화면이 필요 이상으로 번거롭거나, 버전에 따라 동작이 바뀌는 등 다듬어지지 않은 부분이 있을 수 있습니다.
책은 보호됩니다(에이전트는 사본에서 작업하고, 결과는 검토한 뒤 백업을 만든 다음에만 적용됩니다). 그래도 **에이전트의 결과를 넘겨받기 전에는 책을 직접 백업해 두시고**, 토큰 예산을 설정하고, 처음 몇 번의 실행은 [콘솔](#the-console)에서 지켜보시기 바랍니다. 무엇이 잘못되었는지 알려 주시면 감사하겠습니다.
!!!

**에이전트**는 사용자의 책 한 권을 맡아 오랜 시간 스스로 작업하는 모델입니다. 허용된 [명령](commands/index.md)을 도구로 호출하여 이야기를 읽고, 설정집과 대조해 확인하고, 결과를 보고할 수 있습니다. **에이전트** 탭에서 에이전트를 만들고, 각 에이전트가 할 수 있는 일을 정하고, 실행을 시작하거나 중지하고, [콘솔](#the-console)에서 대화하고, 복제할 수 있습니다.

**시작**을 누르면 에이전트가 백그라운드에서 한 라운드씩 작업합니다. 허용된 명령과 자체 파일 도구를 호출하며, 작업이 끝나거나, 질문을 하거나, 한도에 도달하거나, 사용자가 일시 정지 또는 중지할 때까지 계속합니다([실행](#a-run) 참고). 에이전트는 책의 숨겨진 [사본](#the-working-copy)에서 작업하므로 작업 중에도 원본 책은 전혀 건드려지지 않습니다(책 자체는 [잠겨](#the-book-is-locked) 있습니다). 작업이 끝나면 [결과를 검토](#reviewing-the-result)하고 원하는 부분만 넘겨받으시면 됩니다.

이 탭은 관리자가 **에이전트** [권한](administration/permissions.md)을 부여한 경우에만 표시됩니다(관리자는 항상 이 권한을 가지지만, 제한은 모든 사용자와 같습니다. 관리자가 자신의 권한 설정에서 값을 채우지 않는 한 기본값이 적용되므로, 더 많은 에이전트, 실행 수, 작업 공간 용량이 필요한 관리자는 거기서 설정해야 합니다. 변경된 제한은 일시 정지 후 재개되는 실행에 적용됩니다). 휴대폰에서는 각 에이전트가 같은 버튼을 가진 카드로 표시됩니다([휴대폰에서](#on-a-phone) 참고).

## 표

| 열 | |
|---|---|
| **에이전트 ID** | 에이전트의 식별자입니다. |
| **이름** | 사용자가 붙인 이름입니다. |
| **책** | 에이전트가 작업하는 책입니다. |
| **상태** | 실행이 무엇을 하고 있는지 나타냅니다: *실행 중*, *사용자를 기다리는 중*, *승인을 기다리는 중*, *일시 정지 중*, *일시 정지됨*, *중지 중*, *중지됨, 결과 유지*, *완료, 검토 대기 중*, *적용됨*. 실행이 없는 에이전트는 *실행 중 아님*으로 표시되며, 꺼져 있으면 *비활성화됨*으로 표시됩니다. |
| **마지막 실행** | 에이전트의 가장 최근 실행이 시작된 시각입니다. 한 번도 실행하지 않은 에이전트는 *없음*으로 표시됩니다. |

![에이전트 탭](../images/agents-tab.png)

표 위의 두 입력란으로 목록을 좁힐 수 있습니다. **이름**과 **책** 입력란에 입력한 단어가 모두 포함된 에이전트만 표시되며(순서와 대소문자는 무관합니다), 책 이름 기준으로도 검색됩니다. **이름**, **책**, **상태**, **마지막 실행** 머리글을 누르면 표가 정렬됩니다(다시 누르면 역순이 되며, 마지막 실행 오름차순일 때는 한 번도 실행하지 않은 에이전트가 먼저 나옵니다). 휴대폰에서는 카드 위의 **정렬 기준** 선택기로 이름, 상태, 또는 가장 최근 실행 순으로 정렬할 수 있습니다.

행 끝의 버튼은 실행 상태에 따라 달라집니다:

| 버튼 | |
|---|---|
| **시작** | 메뉴를 엽니다. **즉시 시작**: 에이전트가 지시 사항(작업 내용)에 따라 혼자 작업하며, 질문하거나 끝나면 알려 줍니다. **콘솔에서 시작**: [콘솔](#the-console)을 열고, 에이전트에게 아직 작업하지 말고 원하는 것을 바로 물어보라고 알려 줍니다. 이 경우 실행은 **완료**를 누를 때까지 이어지는 [대화](#a-run)가 됩니다. |
| **재개** | 일시 정지되었거나 중지된 실행을 이어 갑니다(**시작** 대신 표시됩니다). 에이전트에게 남길 메모를 선택적으로 입력받습니다. [실행 재개하기](#resuming-a-run) 참고. |
| **일시 정지** | 작업 중이거나 사용자를 기다리는 실행을 일시 정지합니다. |
| **지금 일시 정지** | 에이전트가 작업하는 동안 표시됩니다. 라운드가 끝날 때까지 기다리지 않고 바로 일시 정지합니다. [일시 정지와 중지](#a-run) 참고. |
| **콘솔** | 에이전트의 [콘솔](#the-console)을 엽니다. |
| **중지** | 결과를 **유지**할지(나중에 실행을 재개할 수 있습니다) 또는 **삭제**할지 묻습니다. |
| **편집** | 에이전트를 엽니다. |
| **복제** | 에이전트를 복사합니다. [복제](#cloning) 참고. |
| **삭제** | 에이전트를 실행 기록과 함께 [휴지통](trash.md)으로 옮깁니다. |

에이전트가 비활성화되어 있거나, 모델이 없거나, 동시에 작업할 수 있는 실행 수를 모두 사용 중이면 이유와 함께 시작이 거부됩니다.

![시작 버튼의 메뉴](../images/agent-start-menu.png)

에이전트에게는 끝나지 않은 실행이 최대 하나만 있을 수 있으며, 책 하나에는 에이전트가 최대 하나만 연결됩니다.
<a id="a-run"></a>

## 실행

실행(run)은 에이전트가 맡은 작업이다. 실행은 라운드 단위로 진행된다. 모델에게 한 번 질문하면 모델은 텍스트나 도구 호출, 또는 둘 다로 답하고, 그 결과가 다시 모델에게 전달되며, 이 과정이 반복된다.
모든 라운드는 저장되므로, 실행은 일시 정지했다가 나중에 이어서 진행할 수 있다. 서버를 다시 시작한 뒤에도 가능하다. 에이전트는 사용자가 허용한 명령과 아래의 자체 도구를 사용할 수 있다.

| 도구 | |
|---|---|
| 파일 | `list_files`, `read_file`, `write_file`, `append_file`, `replace_in_file`, `regex_replace_in_file`, `grep_files`, `move_file`, `copy_file`, `merge_files`, `unzip_file`, `delete_file` 등, 에이전트 자체 작업 공간(실행 사이에 유지되는 메모)에서 동작한다. 작업 공간 옆에는 읽기 전용 파일 `/AGENTS.md`가 있으며, 이는 실행을 시작할 때 사용자가 준 지침이다. 에이전트는 이 파일을 언제든 다시 읽을 수 있지만 바꿀 수는 없다. `list_files`와 `grep_files`는 이름 패턴(`glob`, 예: `*.md` 또는 `chapters/*.md`)을 받는다. `copy_file`은 폴더를 그 안의 모든 내용과 함께 복사한다(메모의 버전을 간단히 보관하는 방법이다). `merge_files`는 여러 파일을 모델을 거치지 않고 하나로 합친다(경로의 마지막 이름은 `/chapters/*.md` 같은 패턴일 수 있다). `unzip_file`은 작업 공간의 [zip 파일](#unpacking-a-zip-file)을 새 폴더에 풀어 놓는다. `replace_in_file`과 `regex_replace_in_file`은 경로로 **폴더**도 받는다. 이 경우 그 아래의 모든 텍스트 파일에서 등장하는 것을 모두 바꾸고(`glob`이 주어졌다면 이름이 맞는 파일만), 파일마다 `path: n replacements` 형식으로 결과를 보고한다. 에이전트가 `dry_run`을 false로 주지 않는 한 **시험 실행**(dry run)이다. 아무것도 쓰지 않고, 보고서에 무엇이 바뀔지만 나온다. 전부 아니면 전무 방식이다(한 파일이라도 쓸 수 없으면 아무것도 바뀌지 않는다). 바뀔 파일이 `max_files`(에이전트가 따로 말하지 않으면 100개)를 넘으면 아무것도 바꾸지 않고 거부한다. 단일 파일에도 시험 실행을 쓸 수 있다. `list_command_results`와 `save_command_result`는 에이전트가 다시 쓰지 않아도 명령의 긴 결과를 보존한다. 최근 열 개의 결과는 전체가 보관되며(에이전트에게는 긴 결과가 잘려 보인다), 번호로 지정한 결과를 파일로 저장할 수 있다. 번호를 주지 않으면 가장 최근 결과를 저장한다. 이후 그 파일을 `@file:/path` 형태로 넘긴다. |
| `@file:/path` | 도구가 아니라 도구를 호출하는 방식이다. 명령의 텍스트 인자가 정확히 `@file:/notes/chapter.md`이면, 에이전트 작업 공간에 있는 해당 파일의 내용으로 바뀐다. 따라서 에이전트는 긴 글을 파일에 한 번 쓰고, 확인한 뒤 명령에 넘길 수 있다(호출 결과에는 짧은 참조가 보이고, 명령은 실제 텍스트를 받는다). `write_file`과 `append_file`도 내용 인자로 이 방식을 받는다. 이렇게 하면 파일을 복사하거나 다른 파일에 덧붙일 수 있다. 긴 파일은 모델이 한 번에 쓸 수 있는 가장 긴 답변 안에 들어갈 만큼씩 여러 번에 나눠 쓴 뒤, 이 방식으로 이어 붙일 수 있다. |
| `@result` | `@file:`과 비슷하지만 명령의 결과에 쓴다. 텍스트 인자가 정확히 `@result`이면 에이전트가 마지막으로 호출한 명령의 전체 결과로 바뀐다. `@result:3`이면 해당 번호의 결과로 바뀐다(`list_command_results`가 번호를 보여 준다). 생성된 텍스트는 에이전트가 다시 쓰지 않아도 한 명령에서 다음 명령으로, 또는 `write_file`과 `append_file`로 넘어간다. |
| `search_manual`, `read_manual_page` | Marginalia 사용자 매뉴얼(도움 어시스턴트가 읽는 것과 같은 페이지)에서 찾아본다. 프롬프트 템플릿이나 매크로가 어떻게 동작하는지, 로어북 설정이 무엇을 하는지 등을 확인한다. 읽기 전용이며, 모든 에이전트가 가지고 있다. |
| `view_image` | 작업 공간의 이미지 파일(PNG, JPEG, GIF 또는 WebP)을 본다. 그림은 다음 메시지에서 모델에게 보인다. 모델이 이미지를 볼 수 있도록 표시된 에이전트만 이 도구를 가진다(에이전트의 **모델이 이미지를 볼 수 있음**). 큰 이미지는 보내기 전에 축소되고, GIF는 첫 프레임만 보이며, 모델 앞에는 가장 최근 이미지 네 개만 남는다(더 오래된 이미지는 메모로 바뀌고, 에이전트는 다시 볼 수 있다). 이미지는 사용자가 제공한다(**파일 업로드**, 또는 [메시지에 첨부](#the-console)). 에이전트는 이미지를 만들 수 없다. |
| 명령용 이미지 | [`generate-lore-entry`](extensions/lore-generator.md#commands)처럼 자체 모델로 그림을 보내는 명령은 `images` 매개변수를 받는다. 이는 작업 공간 이미지 파일 경로의 목록이다(최대 8개). 이미지를 봐야 하는 것은 에이전트의 모델이 아니라 명령의 모델이므로, 에이전트 자신의 모델이 이미지를 보지 못하더라도 에이전트는 이미지를 넘길 수 있다. |
| `update_plan` | 할 일 목록이다. |
| `report` | 사용자를 위한 발견 사항이다(무엇을 찾았는지, 어디인지, 얼마나 심각한지: *메모*, *경고* 또는 *문제*). 에이전트는 이를 보고한 뒤에도 계속 진행한다. 사용자는 발견 사항을 [콘솔](#the-console)과 [검토](#reviewing-the-result)에서 읽는다. 에이전트의 최종 보고서는 별도다. 호출 한 번에 발견 사항 하나이며, 실행 하나당 최대 200개다. |
| `get_run_status` | 사용한 라운드 수와 토큰, 컨텍스트 사용량, 쓸 수 있는 가장 긴 답변의 길이를 알려 준다. 또한 계획과 하위 에이전트를 보여 준다. 하위 에이전트는 각각 한 줄로, 상태, 라운드, 토큰, 마지막 작업, 과제가 나온다. 에이전트는 프롬프트에서 모델의 이러한 한계도 알고 있으므로, 긴 글을 여러 부분으로 나누어 쓴다. |
| `checkpoint`, `checkpoint_list`, `checkpoint_diff`, `checkpoint_restore`, `checkpoint_delete` | 에이전트의 [체크포인트](#checkpoints)이다. 작업 사본과 작업 공간의 복원 지점을 (이름표와 함께) 저장하고, 목록을 보여 주고, 그 이후 바뀐 내용을 보여 주며(책의 설정, 부분, 로어북, 항목 중 추가·변경·삭제된 것과 작업 공간의 파일들. 경로를 주면 그 파일이나 폴더만. 텍스트 파일이라면 달라진 문장), 특정 지점으로 되돌리고(라운드가 끝날 때 적용), 필요 없는 지점을 삭제한다. |
| `get_sync_report` | 사용자가 바꾼 내용을 가져온 뒤 이어서 진행한 실행에서만 쓸 수 있다. 실행이 일시 정지된 동안 사용자가 책에서 바꾼 내용과, 그 중 에이전트의 사본에 들어간 내용을 다시 나열한다. [실행 재개](#resuming-a-run)를 보라. |
| `request_compaction` | 에이전트 자신의 컨텍스트를 압축한다. 라운드가 끝나면 `/compact`처럼 앞서 한 작업의 요약을 쓴다. 먼저 메모를 파일에 저장하도록 지시받는다. [컨텍스트가 차오를 때](#running-a-command-yourself)를 보라. |
| `ask_user` | 사용자에게 던지는 질문이다. 실행은 기다린다(*사용자를 기다리는 중*). |
| `finish` | 에이전트의 보고서다. 실행은 *완료*된다. 보고서는 상태의 이유로 표시된다. |

실행이 끝나는 여러 경우는 다음과 같다.

- **사용자를 기다리는 중:** 에이전트가 도구 호출 없이 답했거나, 사용자에게 질문했다. [콘솔](#the-console)에서 답하라.
- **완료:** 에이전트가 `finish`를 호출했다(*즉시* 시작한 실행의 경우). *콘솔에서* 시작한 실행은 대화다. 에이전트의 보고서는 질문처럼 사용자에게 전달되고, 실행은 사용자의 다음 메시지를 기다린다. 콘솔에서 **완료**(또는 **중지**)를 눌러야만 끝난다. *완료된* 실행의 결과는 [검토](#reviewing-the-result)를 기다린다.
- **일시 정지됨**(이유와 함께): 라운드 한도, 토큰 예산, 또는 컨텍스트 한도에 도달했거나, 모델에 요청할 수 없었다(제공자의 오류, 또는 AI에 대한 사용자의 한도). 또는 서버가 다시 시작되었다. **재개**를 누르면 마지막으로 완료된 라운드부터 이어간다. [서버가 멈출 때](#when-the-server-stops)를 보라.
- **실패:** 실행기 자체가 고장 났다. 이유에 원인이 나온다.

**일시 정지**는 두 라운드 사이에 적용된다. 모델 요청과 진행 중인 호출이 먼저 끝난다. 이는 오래 걸릴 수 있다(느린 모델, 긴 생성). 그래서 **지금 일시 정지**가 있다. 이는 모델에 대한 요청을 취소하며, 그 답은 버린다. 진행 중인 호출과, 라운드에서 아직 실행되지 않은 호출에도 응답하고, 잠시 후 실행은 *일시 정지됨*이 된다. 버린 요청이 들였을 비용은 잃게 된다. 평소처럼 재개하라. **중지**도 같은 일을 하지만, 요청이나 진행 중인 호출을 기다리지 않는다. 이들은 즉시 취소되고, 실행은 바로 끝난다(사용자가 고른 대로 결과를 남기거나 버린다).

![실행을 중지할 때 나오는 질문](../images/agent-stop.png)

진행 중인 명령은 멈추라는 신호를 받는다. 멈출 수 있도록 만들어진 명령(모델로 쓰거나, 검색하고 바꾸는 명령)은 즉시 끝나며, 그때까지 한 작업을 남긴다. 멈출 수 없는 명령은 끝까지 실행될 수도 있다. 어느 경우든 에이전트는 그 호출이 수행되었는지 알 수 없다는 말을 듣고, 다시 진행할 때 읽기 명령으로 상태를 확인한다. 하위 에이전트의 명령도 실행이 일시 정지되거나, 중지되거나, 즉시 메시지를 받을 때 같은 방식으로 취소된다.

에이전트가 모델의 빈자리를 기다리는 동안(see [하나의 모델, 여러 에이전트](#one-model-several-agents))에는 *실행 중*이다. **일시 정지** 또는 **중지**를 누르면 그 기다림이 즉시 끝난다.

## 콘솔

**콘솔**을 열면 에이전트의 최근 실행을 보여 주는 창이 열리며, 탭은 여덟 개입니다: **실행**, **실행 기록**, **작업 공간**, **체크포인트**, **컨텍스트**, **책 사본**, **하위 에이전트**, **진단**.

![콘솔에서 시작된 실행: 에이전트가 무엇을 할지 묻는 모습](../images/agent-console-start.png)

**실행**은 *대화 기록(transcript)*을 보여 줍니다. 여기에는 사용자가 에이전트에게 한 말, 에이전트의 응답([Markdown](https://commonmark.org/help/)으로 표시되어 목록, 제목, 강조가 그대로 보입니다), 그리고 에이전트가 호출한 모든 명령과 파일 도구가 포함됩니다. 호출 항목은 인수 한 줄로 접혀 있으며, 클릭하면 인수와 결과(일반 텍스트로 표시)를 볼 수 있습니다. 모델이 **추론**(응답 전에 생각한 내용)을 보내면, 응답 앞에 접힌 *추론* 블록으로 표시되고 다운로드 파일에도 포함됩니다. 추론이 표시될지는 모델과 서버에 따라 다릅니다. 모델이 이를 보고해야 하고, 사용 중인 AI에서 추론 기능이 켜져 있어야 합니다. 요청이 진행되는 동안 콘솔은 모델이 지금까지 쓴 내용(추론은 따라 읽을 수 있도록 펼쳐진 상태로, 그리고 본문 텍스트)을 대화 기록 끝, 대기 중인 메시지 위의 *작업 중...* 블록에 보여 줍니다. 이 응답 차례가 끝나면 실제 블록들로 대체됩니다. 이 블록이 보이는 동안 콘솔은 실행 상태를 2초가 아닌 0.5초마다 읽습니다. 이렇게 표시되는 것은 에이전트 자신뿐이며 그 하위 에이전트는 포함되지 않습니다. 또한 모델이 호출 안에서 작성하는 내용(예: 긴 파일)은 해당 차례가 끝나야 나타납니다. 모든 메시지에는 첫 줄 오른쪽에 작성된 시각이 표시됩니다(시각만, 다른 날이면 날짜도 함께; 마우스를 올리면 전체 시각이 보입니다). 그래서 에이전트가 얼마나 오래 작업했고 언제 멈췄는지 알 수 있습니다. 실행의 상태, **컨텍스트**(마지막 요청이 모델의 한도 중 얼마를 사용했는지, 즉 실행이 일시 정지에 얼마나 가까운지), 사용한 차례와 토큰(토큰 예산이 있는 경우 예산도 함께)은 대화 기록이 스크롤되는 동안에도 그 위에 계속 보이며, 그 아래에는 메시지 입력란이 있습니다. 에이전트가 기다리는 것은 작성된 위치에 말풍선으로 표시되며, 실행이 계속되어도 그 자리에 남습니다.

![작업 중인 콘솔: 작성자의 메시지가 대기열에서 기다리는 모습](../images/agent-console-run.png)

- 실행이 *사용자를 기다리는 중*일 때 나타나는 **에이전트의 질문**. 입력란에 답을 쓰고 **보내기**(또는 **Ctrl+Enter**)를 누르면 에이전트가 계속 진행합니다.
- 에이전트가 `finish`를 호출했을 때 나타나는 **에이전트 보고서**.

![에이전트의 질문과 에이전트가 제안하는 답변들](../images/agent-console-question.png)

![대화가 끝났을 때의 에이전트 보고서](../images/agent-console-report.png)

![에이전트의 질문과 에이전트가 제안하는 답변들](../images/agent-console-question.png)

![대화가 끝났을 때의 에이전트 보고서](../images/agent-console-report.png)

대화 기록 위의 줄에는 실행의 상태와 수치가 표시됩니다. 차례 수, 한도 대비 컨텍스트 크기, **응답 제한**(에이전트 모델이 한 번의 응답에서 쓸 수 있는 최대 토큰 수; 이보다 많이 필요한 호출은 잘리므로, 에이전트는 긴 글을 여러 부분으로 나누어 씁니다), 그리고 전체 토큰 수가 나타납니다. 에이전트가 계획(`update_plan`)을 세우면, 그 줄에 완료한 단계와 전체 단계 수를 보여 주는 **계획** 버튼(**계획 2/5**)이 나타납니다. 이를 누르면 각 단계가 팝오버로 열리며, 각 단계에는 *완료*, *진행 중*, *할 일* 중 하나의 표시가 붙습니다. 에이전트가 발견 사항을 보고하면(`report`), 개수가 함께 표시된 **발견 사항** 버튼(**발견 사항 3**)이 나타나며, 누르면 같은 방식으로 발견 사항이 열리고 각 항목에 심각도가 표시됩니다. 발견 사항은 실행과 함께 저장되므로, 일시 정지 후나 서버 재시작 후, 또는 기록에서 이전 실행을 볼 때도 그대로 남아 있습니다. 실행의 Markdown 파일(**다운로드**)에는 **발견 사항**이라는 절로 포함됩니다.

![에이전트의 계획](../images/agent-console-plan.png)

![에이전트의 발견 사항](../images/agent-console-findings.png)

대화형 실행에서는 에이전트가 **작업하는** 동안에도 메시지를 쓸 수 있습니다. 이 메시지는 **대기열**에 들어갑니다. 대화 기록 끝에 점선 말풍선으로 나타나며, 에이전트는 현재 진행 중인 차례가 끝나는 즉시 이를 읽습니다. 즉, 이미 나간 모델 요청과 그 요청에서 한 호출들이 먼저 끝나고, 다음 요청에 사용자의 메시지가 이미 포함됩니다(여러 개의 대기 메시지는 한꺼번에 함께 전달됩니다). 그마저도 기다릴 필요가 없다면, 말풍선에 있는 작은 **지금 보내기**(번개) 버튼을 누르세요. 에이전트는 현재 차례를 중단하고(모델 요청은 취소되고, 사용자의 승인을 기다리던 명령은 거부되며, 하지 않은 호출은 건너뜀으로 표시됩니다) 곧바로 사용자의 메시지를 읽습니다. 그 옆의 **휴지통** 버튼은 에이전트가 아직 읽지 않은 동안 메시지를 회수합니다(대기 중인 명령도 같은 방식입니다). 이미 실행된 명령은 그대로 완료 상태로 남습니다. 대기 중인 메시지와 명령은 서버를 재시작해도 유지되며(재개할 때 읽힙니다), 대화형이 아닌 실행(*즉시* 시작한 실행)은 작업 중에 메시지를 받지 않습니다.
<a id="running-a-command-yourself"></a>

### 명령을 직접 실행하기

대화 기록 아래에는 애플리케이션의 명령줄(이야기 탭의 것: `/`를 입력하면 목록과 도움말이 그 위에 나타납니다)이 있고, 여기서 에이전트에게 실행할 수 있는 명령이 함께 있습니다. 실행 가능한 명령은 `/compact`, `/clear-workspace`, 그리고 데이터를 읽거나 추가만 하는 [에이전트가 호출할 수 있는 명령](#allowed-commands)입니다(데이터를 바꾸거나 지우는 명령은 제공되지 않습니다. 그런 명령은 책의 창에서 확인을 요청하는데, 실행 중에는 그런 창이 없기 때문입니다). 에이전트가 아니라 여러분이 명령을 실행합니다. 에이전트에게는 여러분이 명령을 실행했다는 것과 그 응답이 여러분의 메시지로 전달됩니다(명령이 작업 공간을 바꿨다면 앞서 읽은 내용이 오래되었을 수 있다는 내용도 함께 전달됩니다). 따라서 에이전트는 자신이 하지 않은 호출을 했다고 믿지 않습니다. 명령은 메시지처럼 동작합니다. 실행이 대기 중(*사용자를 기다리는 중*)이거나 *일시 정지됨* 상태이면 명령은 즉시 실행되고 실행 상태는 그대로 유지됩니다. [대화](#the-console)가 진행 중이면 명령은 대기열에 들어가 *명령*이라고 표시된 점선 말풍선으로 나타나고, 에이전트의 턴이 끝날 때 실행됩니다(에이전트가 기다리고 있었을 시점입니다. 이 명령 때문에 에이전트가 진행하는 것은 아닙니다). 말풍선의 작은 **지금 실행** 버튼을 누르면 에이전트가 있는 라운드를 버리고 명령을 바로 실행한 뒤, 에이전트가 그 지점부터 계속 진행하도록 합니다. 오래 걸리는 명령은 입력창을 점유하므로, 에이전트에게 무언가를 쓰기 전에 끝날 때까지 기다리세요.

![작성자의 콘솔에서 실행한 명령: /compact](../images/agent-console-command.png)

**`/compact [강조할 내용]`**은 컨텍스트를 비웁니다. 에이전트에게 지금까지의 모든 내용을 읽고 요약을 작성하도록 요청합니다(무엇을 요청받았는지, 무엇이 끝났는지, 무엇을 찾았는지, 메모와 계획, 그리고 막 하려던 일). 이 요약이 모델이 읽는 내용에서 그 이전의 모든 것을 대체합니다. 대화 기록에서는 여전히 모든 내용을 볼 수 있고, 요약은 접힌 블록 **이전 작업 요약**으로 표시됩니다. 내보내기에도 요약이 그대로 남습니다. 명령 뒤에 적은 텍스트가 있다면, 요약이 그 내용을 강조해야 합니다. 이 요청은 에이전트 자신의 요청이며 그 토큰은 실행 분량에 포함됩니다. 에이전트에게 던지는 질문은 **압축 프롬프트**입니다. 에이전트의 것이 있으면 그것을 쓰고, 없으면 [설정](account.md#templates)에서 지정한 기본값을 쓰고, 그것도 없으면 관리자의 것을 쓰고, 그것도 없으면 내장된 것을 씁니다. 컨텍스트가 이미 너무 가득 차서 요청이 들어갈 수 없으면, 가장 오래된 메시지부터 요청에서 빠집니다(요약에 몇 개가 빠졌는지 적힙니다). 컨텍스트가 가득 차기 전에 실행하세요. 사용량 줄을 보면 얼마나 가까운지 알 수 있습니다. 압축 직후 표시되는 컨텍스트는 다음 요청이 담게 될 내용(요약, 시스템 프롬프트, 도구 정의)을 추정한 값이며, 압축 뒤 모델의 첫 응답이 이를 실제 수치로 바꿉니다.

**컨텍스트가 차오름.** 모델의 컨텍스트가 상한의 75%를 넘으면, 에이전트는 라운드마다 알림을 받습니다(실행 중 메시지로, 대화 기록에서 볼 수 있습니다). 알림에는 얼마나 찼는지, 잃으면 안 되는 내용을 작업 공간의 파일에 저장하고 계획을 갱신한 뒤 `request_compaction`을 호출해야 한다는 내용이 담깁니다. 90%를 넘으면 알림은 컨텍스트가 가득 차면 실행이 중단된다고 알려 줍니다. 에이전트가 컨텍스트가 정의에 있는 **압축 기준**(별도로 지정하지 않으면 90%)을 넘기 전에 압축하지 않으면, 실행이 스스로 압축합니다. 같은 압축이며, 요약은 "자동으로 압축됨"으로 시작하고 에이전트에게는 추가 경고를 하지 않습니다. 실패한 압축은 아무것도 바꾸지 않으며, 에이전트에게 그 사실이 알려지고, 실행은 몇 라운드 뒤에 다시 시도합니다. 에이전트가 요청하는 압축은 여러분의 것과 같습니다(압축 프롬프트, [에이전트 만들기와 편집](#creating-and-editing-an-agent)을 참조하세요. 토큰은 실행 분량에 포함됩니다). 실패하면 아무것도 바뀌지 않고 에이전트에게 알려집니다. 알림을 받으려면 컨텍스트 상한이 있어야 합니다. 상한은 에이전트의 상한과 모델의 한도 중 가장 낮은 값입니다.

**모델 서버가 읽지 못한 호출.** 모델이 호출 안에 긴 텍스트를 쓸 때, 응답이 그 텍스트 중간에서 끝날 수 있습니다(*한 응답*의 한도, 즉 프로토콜의 **reply tokens** 또는 AI의 **max completion tokens**에 도달하거나, 둘 다 설정되지 않아 서버 기본값이 적용되거나, 모델이 그냥 멈춘 경우입니다. 컨텍스트가 얼마나 찼든 이것은 다른 한도입니다). 그러면 서버는 불완전한 호출을 거부합니다("Failed to parse tool call arguments as JSON"). 같은 대화로 다시 물으면 같은 실수가 반복되므로, 실행은 그냥 일시 정지하지 않습니다. 에이전트에게 대화 기록에서 마지막 응답을 쓸 수 없었고 아무 작업도 수행되지 않았다고 알리고, 긴 텍스트는 작업 공간의 파일에 여러 번에 나눠 작은 단계로 쓰라고 알립니다. 그런 다음 최대 세 번 연속으로 다시 묻습니다. 계속 실패하면 실행이 일시 정지되며, 에이전트에게 알린 내용은 대화 기록에 남습니다. 따라서 **재개**를 누르면 실패한 것과 다른 질문이 전달됩니다. 하위 에이전트도 마찬가지입니다.

애플리케이션에 도달했지만 잘린 호출(호출 결과가 "not valid JSON ... cut off in the middle"이라고 말함)은 모델이 쓴 그대로 대화 기록에 남아 읽을 수 있지만, 빈 인자와 함께 모델에 다시 보내집니다. 그렇지 않으면 앞선 호출을 다시 읽는 서버가 그 뒤의 모든 요청을 거부하게 되어, 되돌리기 없이는 실행을 이어갈 수 없습니다.

**폭주하는 호출.** 모델은 루프에 빠져 같은 호출을 하나의 응답 안에서 수백 번 쓸 수 있습니다. 그러면 다음 요청 전에 결과가 컨텍스트를 채워 버립니다. 실행은 한 응답에서 최대 32개의 호출만 수행하며, 읽기만 하는 호출의 반복(같은 응답 안에서 같은 도구와 같은 인자)은 한 번만 수행됩니다. 빠진 호출은 대화 기록에 나타나지 않으며, 에이전트에게는 그 사실을 알리는 알림이 전달됩니다.

**같은 자리를 맴돎.** 모델은 여러 응답에 걸쳐 같은 말을 반복할 수도 있습니다. 같은 조회(파일 목록, 로어북 목록...)를 같은 결과와 함께 라운드마다 되풀이하며 아무 진전이 없는 경우입니다. 실행은 이를 감시합니다. 에이전트의 라운드가 조회만 하고, 아무것도 바꾸지 않고, 앞선 라운드와 같을 때(같은 호출, 같은 결과), 세 번째에 아무것도 바뀌지 않았다는 말을 듣습니다. 계속하면, 다섯 번째에 도구가 한 요청 동안 회수됩니다. 에이전트는 무엇을 하고 있었는지, 무엇이 막고 있는지를 일반 텍스트로 답해야 하며, 실행은 그 답을 마지막 메시지로 남기고 **일시 정지**합니다. 따라서 백 라운드를 더 쓰기 전에 왜 막혔는지 알 수 있습니다. **재개**(또는 메시지 보내기)를 하면 도구가 돌아오고 횟수 세기가 처음부터 다시 시작됩니다. 무언가 바뀐 라운드나 하위 에이전트가 작업 중인 동안은 세지 않습니다. 같은 자리를 맴도는 하위 에이전트는 같은 방식으로 중단되며, 그 하위 에이전트가 한 말이 그것을 시작한 에이전트에게 전달되는 답이 됩니다.

**`/clear-workspace [남길 것]`**은 실행의 [작업 공간](#the-working-copy)에 있는 모든 파일과 폴더를 삭제합니다(작업 공간의 버튼처럼 확인 후에 삭제됩니다). 명령 뒤에 남길 것을 공백으로 구분해 적으세요. 파일, 폴더(안의 모든 것과 함께), `*.md`나 `chapters/*.md` 같은 패턴, 공백이 있는 경로는 큰따옴표로 감싸면 됩니다(`/clear-workspace /notes.md "/my drafts" *.png`). 남긴 파일 위의 폴더는 그대로 남습니다. 적은 것이 없으면 아무것도 삭제되지 않습니다. `/AGENTS.md`와 체크포인트는 작업 공간의 일부가 아니므로 결코 건드리지 않습니다. 에이전트에게는 무엇이 삭제되었고 무엇이 남았는지 알려집니다. 대화 기록에서 여러분이 실행한 명령은 명령과 그 응답을 담은 말풍선으로 나타납니다.

에이전트의 모델이 이미지를 볼 수 있을 때([에이전트 만들기와 편집](#creating-and-editing-an-agent) 참조), **이미지 첨부**가 **보내기** 옆에 나타납니다. PNG, JPEG, GIF 또는 WebP 파일을 고르거나, 클립보드의 그림을 메시지 입력창에 붙여 넣을 수 있습니다(**Ctrl+V**). 그러면 보낼 때까지 입력창 위에서 기다립니다(X 표시로 취소할 수 있습니다). 메시지 하나에는 이미지를 최대 여덟 개까지 함께 보낼 수 있으며, 텍스트는 비워 둘 수 있습니다. 이미지는 작업 공간의 **uploads** 폴더에 저장됩니다(이름이 이미 있으면 번호가 붙습니다: `map-2.png`). 작업 공간의 한도와 규칙을 따릅니다. 모델은 여러분의 메시지와 함께 이미지를 보게 됩니다. 더 이상 필요하지 않으면 **작업 공간** 탭에서 삭제하세요.

창 아래쪽의 버튼은 **일시 정지**, **재개**, **중지**이며, 각각 표에 나온 대로 동작합니다. 그리고 여러분을 기다리는 실행을 끝낼 때 쓰는 **완료**가 있습니다(작업이 끝났다는 뜻으로 *완료됨*이 됩니다).

창이 열려 있는 동안 실행 상태는 2초마다 확인됩니다. **새로 고침**을 누르면 즉시 확인합니다. **실행 기록** 탭은 버려지지 않은 가장 최근 실행을 보여 주므로, 끝났거나 실패한 실행도 에이전트가 새 실행을 시작하기 전까지는 거기서 읽을 수 있습니다. 더 오래된 실행은 **실행 기록**에 있습니다.

**실행 기록**은 에이전트의 이력입니다. 에이전트가 가졌던 모든 실행이 최신순으로, 날짜, 상태, 라운드, 토큰, 결과와 함께 나열됩니다. 눈 아이콘을 누르면 실행을 **실행** 탭에서 **열어** 단계와 보고서를 다시 읽을 수 있습니다(열어 둔 실행은 다른 실행을 열기 전까지 그곳에 머뭅니다). 화살표 아이콘은 실행의 대화 기록을 Markdown 파일로 **내려받습니다**(무엇이 언제 말해졌는지, 명령과 인자, 결과, 보고서, 하위 에이전트의 대화를 모두 포함합니다). 휴지통 아이콘은 실행을 **삭제**합니다. 삭제한 실행은 [휴지통](trash.md)으로 갑니다. 진행 중인 실행은 삭제할 수 없으니 먼저 중지하세요. 중지하고 **버린** 실행도 목록에 있으므로, 그 실행이 무엇을 했는지 읽거나 삭제할 수 있습니다. **실행** 탭은 그것들을 열었을 때에만 보여 줍니다.

![실행 기록 탭](../images/agent-runs.png)

**작업 공간**에는 에이전트의 파일이 보입니다. 에이전트는 메모와 보고서를 실행 사이에 보관합니다. 폴더를 클릭하면 안으로 들어가고(**위로**로 돌아갑니다), 텍스트 파일을 클릭하면 읽을 수 있습니다. 화살표로 파일을 내려받고, 휴지통으로 삭제할 수 있습니다. **지우기**는 모든 것을 삭제합니다(오래된 메모는 새 실행을 잘못 이끌기 때문입니다). **새 폴더**는 열린 폴더 안에 폴더를 만들고, **파일 업로드**는 컴퓨터의 파일을 거기에 넣어 줍니다. 그래서 에이전트에게 지침, 문체 가이드, 초안을 건넬 수 있습니다. 에이전트가 직접 만든 파일과 같은 규칙이 적용됩니다. 이름에는 `\ < > : " | ? *`를 쓸 수 없고, 끝에 점이나 공백이 있을 수 없으며, 너무 길거나 너무 깊을 수 없습니다. 파일 크기와 파일 개수의 한도도 적용됩니다. 업로드한 파일은 텍스트(UTF-8)여야 합니다. 에이전트는 텍스트만 읽을 수 있기 때문입니다. 또는 이미지(PNG, JPEG, GIF 또는 WebP이며, 이름이 아니라 파일의 내용으로 인식합니다. 5MB까지이고, 다른 파일과 같이 총량과 파일 개수에 포함됩니다)나 zip 파일(10MB까지이며, 그대로 보관됩니다. 에이전트가 압축을 풉니다. [아래](#unpacking-a-zip-file)를 참조하세요). 업로드로 파일이 교체되는 일은 없습니다. 기존 파일을 먼저 삭제하세요. 에이전트가 작업하는 동안에는 파일을 바꿀 수 없으니, 먼저 일시 정지하세요. 작업 공간에는 크기, 파일 크기, 파일 개수의 한도가 있으며, 관리자가 [권한](administration/permissions.md#settings-of-a-permission)에서 설정할 수 있습니다. 표 아래 줄에는 사용량이 표시됩니다. 맨 위의 `AGENTS.md`라는 이름은 여러분의 지침이 차지하고 있으며, 에이전트는 거기서 이를 봅니다(이 파일은 쓰거나 삭제할 수 없습니다).

![작업 공간 탭](../images/agent-console-workspace.png)
<a id="unpacking-a-zip-file"></a>

### zip 파일 풀기

에이전트가 여러 파일을 한꺼번에 다뤄야 할 때(예: 원고의 장들), **작업 공간** 탭에서 zip 파일을 **파일 업로드**로 올리고 풀어 달라고 요청하십시오. 에이전트에게는 `unzip_file` 도구가 있으며, 이 도구는 `/uploads/draft.zip`을 새 폴더 `/uploads/draft`에 풉니다(또는 에이전트가 지정받은 폴더에 풉니다. 이 폴더는 아직 없어야 합니다). 풀기는 전부 아니면 전무이며, 압축 파일은 결코 무조건 신뢰하지 않습니다.

- 텍스트 파일(UTF-8), 이미지(PNG, JPEG, GIF, WebP), zip 파일만 보관됩니다. 나머지 항목은 제외되며, 에이전트에 대한 답변에 그 이름이 적힙니다. 안에 든 zip 파일은 따로 풀리지 않고 그대로 저장됩니다.
- 파일들은 작업 공간에 남은 용량(전체 크기, 파일 크기, 파일 개수)에 맞아야 하며, 그렇지 않으면 아무것도 풀리지 않습니다.
- 폴더 바깥을 가리키는 항목(`../x`)이나 `/`로 시작하는 항목이 있는 압축 파일은 통째로 거부됩니다. 같은 이름이 두 번 나오는 경우(대소문자만 다른 경우 포함), 같은 이름이 파일이면서 동시에 폴더인 경우, 항목이 5 000개를 넘는 경우, 암호가 걸렸거나 손상된 경우에도 마찬가지입니다.
- 압축 폭탄은 거부됩니다. 작업 공간이 담을 수 있는 양보다 많이 풀리거나, 자기 크기의 100배를 넘게 풀리는 압축 파일이 여기에 해당합니다.

<a id="sub-agents"></a>

## 하위 에이전트

에이전트는 작업 하나를 **하위 에이전트**에게 넘길 수 있습니다. 하위 에이전트는 자기 대화를 가진 조력자로, 과제 하나를 수행하고 텍스트로 답합니다. 에이전트의 명령과 파일(또는 [아래](#models-for-sub-agents)에서 설명하는, 하위 에이전트가 실행되는 모델의 명령과 파일)을 쓸 수 있으며, 같은 작업 복사본과 작업 공간에서 일합니다(하위 에이전트가 책에서 바꾼 내용은 그대로 남습니다). 그러나 에이전트의 대화는 알지 못하므로, 에이전트는 과제 안에 필요한 내용을 모두 적어야 합니다. 이렇게 하는 이유는, 하위 에이전트가 읽고 시도한 내용이 에이전트의 문맥 밖에 머물게 하기 위해서입니다. 예를 들어 장 하나를 점검하거나, 이름을 감사하거나, 한 부분을 초안으로 쓰는 일을 맡길 수 있습니다.

[에이전트](#creating-and-editing-an-agent)에서 **하위 에이전트 수 상한**(Most sub-agents)을 동시에 일할 수 있는 개수로 설정하십시오. 0(기본값)이면 하나도 없으며, 에이전트는 하위 에이전트가 있다는 사실조차 듣지 못합니다.

- **1**로 설정하면, 에이전트는 하위 에이전트를 시작하고 그것이 끝날 때까지 기다립니다(*대기 상태*가 됩니다). 호출은 하위 에이전트의 답을 돌려줍니다.
- **2 이상**으로 설정하면, 하위 에이전트를 시작하는 호출은 곧바로 돌아오고, 에이전트는 계속 일하면서 다른 하위 에이전트를 더 시작하거나, 상태를 보거나(`agent_status`), 답을 기다리거나(`await_agent`), 하나를 중지할 수 있습니다(`cancel_agent`). 상한에 도달한 호출은 하나가 끝날 때까지 기다렸다가, 끝난 것들의 결과를 돌려줍니다.

어느 경우든 적용되는 규칙은 다음과 같습니다.

- 하위 에이전트는 **작업 공간 전체를 읽을 수 있지만, 쓰기는 자기 전용 폴더에서만 합니다.** 그 폴더는 `/tmp/sub1`, `/tmp/sub2`... 입니다(하위 에이전트가 시작될 때 만들어지며, 같은 이름의 폴더에 이전 실행이 남긴 내용은 삭제됩니다). 그 답은 `result.md`로 거기에 저장되므로, 긴 답이 잘려 보일 때 에이전트는 이 파일에서 전체를 읽습니다. 파일은 **작업 공간** 탭에서 찾을 수 있으며, 작업 공간 할당량의 일부를 차지하고, 직접 비울 때까지 남습니다.
- 하위 에이전트는 에이전트가 따로 지정하지 않는 한 에이전트의 주 모델에서 실행됩니다. [하위 에이전트용 모델](#models-for-sub-agents)을 참고하십시오.
- 데이터를 바꾸는 하위 에이전트의 명령은 에이전트의 **파괴적 명령** 설정을 따릅니다. **먼저 묻기**일 때는 같은 [창](#asking-you)이 여러분에게 묻고, 그 하위 에이전트는 여러분의 답을 기다립니다(실행을 일시 정지하면 거부됩니다).
- 하위 에이전트는 **하위 에이전트를 시작할 수 없고**, 실행을 끝낼 수 없으며, 여러분에게 물을 수 없고, 체크포인트를 만들 수도 없습니다. 텍스트로 답하는 것으로 끝납니다.
- 모든 것은 실행의 **하나의 예산**에 합산됩니다. 즉 라운드, 토큰, 모델의 한도가 그렇습니다. 한도에 걸린 하위 에이전트는 실패하며 그 사실을 알립니다. 그러면 에이전트도 같은 한도에 걸리게 됩니다.
- 모델에 동시에 나가는 요청 수는 관리자가 여러분에게 준 **모델에 대한 동시 요청 수**(설정이 없으면 1)에 따릅니다. 1이면 에이전트와 하위 에이전트가 차례를 나눠 씁니다.
- 책이나 작업 공간을 바꾸는 호출은 누가 하든 한 번에 하나씩 처리되므로, 두 하위 에이전트가 같은 순간에 쓰는 일은 없습니다. 그래도 두 하위 에이전트에게 같은 부분을 바꾸라고 지시하지는 마십시오.
- **실행을 일시 정지하면 하위 에이전트도 함께 멈춥니다.** 하위 에이전트는 다음 안정된 지점(두 요청 사이나 두 호출 사이, 즉시 일시 정지하면 바로)에서 멈추고, 말하고 한 내용은 실행과 함께 보존됩니다. 그래서 **재개**를 누르면 멈췄던 곳부터 이어집니다. 하위 에이전트는 대화를 계속하고, 하위 에이전트를 기다리던 에이전트 호출(`await_agent`, 또는 상한이 1인 `spawn_agent`)은 마치 아무 일도 없었던 것처럼 다시 기다립니다. 일시 정지 전에 이미 끝났던 하위 에이전트는 여전히 남아 있어서 에이전트가 그것에 대해 물어볼 수 있습니다. 실행을 중지하고 보존하는 경우도 마찬가지입니다. 반면 실행을 버리거나, 체크포인트를 복원하거나(하위 에이전트가 작업하던 책이 교체됩니다), 에이전트가 끝내거나 여러분에게 무언가를 물으면 하위 에이전트는 완전히 끝납니다. 하위 에이전트가 아직 일하는 중에 에이전트가 턴을 끝내면 한 번 알림을 받으며, 그런 일이 다시 생기면 하위 에이전트는 중지됩니다.
- 하위 에이전트의 대화는 **실행** 탭에 나타나지 않습니다. 콘솔의 **하위 에이전트** 탭에 나타나며, 위에서 하나를 골라 에이전트가 무엇을 지시했는지, 그 하위 에이전트가 무엇을 말했는지, 호출한 명령과 결과, 그리고 어떻게 끝났는지(내놓은 답, 또는 실패하거나 취소된 이유)를 대화 기록과 같은 블록으로 읽을 수 있습니다. 작업하는 동안에는 실행을 따라가며, 이전 실행의 하위 에이전트도 보여줍니다(먼저 **실행 기록** 탭에서 그 실행을 고르십시오). **실행** 탭의 `spawn_agent` 호출에는 그 대화를 여는 **하위 에이전트** 버튼이 있습니다. 에이전트가 되돌아간(되감기) 대화는 흐리게 표시되고 *에이전트가 잊음*이라고 표시됩니다. (**실행 기록** 탭의) 실행의 **다운로드**에는 하위 에이전트마다 한 섹션이 있으며, 그 과제, 상태, 모든 메시지와 호출이 들어 있습니다.

![하위 에이전트 탭](../images/agent-subagents.png)

### 하위 에이전트용 모델

에이전트에는 **주 모델** 하나가 있으며, 대화창 위쪽에서 고릅니다. **하위 에이전트용 모델** 아래에서 다른 모델을 더 추가할 수 있습니다. 예를 들어 읽기만 하는 저렴한 모델이나, 초안을 쓰는 유창한 모델을 둘 수 있습니다. 각 모델에는 **역할**(이름), **설명**(언제 쓸지. 에이전트가 이것을 읽고 고릅니다), AI와 프로토콜, 선택 사항인 **문맥 한도**, 그리고 쓸 수 있는 것들이 있습니다.

![하위 에이전트용 모델](../images/agent-models.png)

- **명령과 도구 사용 가능.** 꺼져 있으면 이 모델의 하위 에이전트는 텍스트로만 답합니다. 명령도 도구도 받지 못합니다.
- **명령 제한.** 꺼져 있으면 이 모델의 하위 에이전트는 에이전트의 명령을 모두 가집니다. 켜면 체크한 명령만 가지며, 그중에서도 에이전트에게 허용된 것만 가집니다(에이전트의 허용 명령이 여전히 상한입니다). 파일용 도구는 명령이 아니므로, 모든 하위 에이전트가 가집니다. 주 모델에도 같은 설정이 있으며, 주 모델에서 실행되는 하위 에이전트에 적용됩니다(해당 행의 **편집** 버튼).

에이전트에게는 각 모델의 역할, 설명, 명령이 알려지며, 에이전트는 `spawn_agent`의 `profile`로 그중 한 모델에서 하위 에이전트를 시작합니다. 이 값을 생략하면 자기 모델을 씁니다. **하위 에이전트는 주 모델에서 실행될 수 있음**(기본적으로 켜져 있음) 체크박스를 끄면 이 마지막 선택이 막힙니다. 그러면 에이전트는 다른 모델을 지정해야 하며, 지정할 모델이 없으면 하위 에이전트용 도구를 전혀 받지 못합니다. 하위 에이전트에는 자기 모델의 한도가 적용됩니다(읽을 수 있는 양, 답의 길이 한도). **하위 에이전트** 탭과 진단 정보에는 각 하위 에이전트가 어떤 모델에서 실행되었는지가 표시됩니다.

<a id="one-model-several-agents"></a>

## 한 모델, 여러 에이전트

로컬 서버는 흔히 슬롯이 하나(GPU 하나)뿐입니다. 한꺼번에 두 답을 요청하면 둘 다 느려지거나 시간 초과가 납니다. [모델](inference-providers.md#general-settings)의 **연결** 수(따로 설정하지 않으면 1)는 그 모델로 가는 모든 요청이 도착한 순서대로 차례를 지키게 합니다. 여기에는 여러분의 에이전트, 다른 사용자의 에이전트, 그리고 이야기 창에서 쓰는 여러분의 글 요청이 모두 포함됩니다. 기다리는 실행은 *실행 중* 상태로 남고, **일시 정지**나 **중지**를 누르면 즉시 대기가 끝납니다. 모델의 두 답 사이에는 에이전트가 연결을 잡고 있지 않으므로, 그 사이에 여러분의 글 생성이 끼어들 수 있습니다.
<a id="when-you-are-not-there"></a>

## 사용자가 없을 때

에이전트가 사용자를 필요로 하거나 작업을 마치거나 실패하면, 열려 있는 애플리케이션 화면(탭의 배지, 알림)에 이를 알립니다. 사용자의 화면이 하나도 열려 있지 않을 때는, 관리자가 사용자에게 [권한 *알림*](account.md)을 부여했다면(관리자는 이 권한을 가집니다) [설정](administration/permissions.md)에 입력한 주소로 짧은 메시지를 보낼 수도 있습니다("에이전트가 사용자를 필요로 할 때 URL로 메시지 보내기"). 주소는 **ntfy** 토픽(휴대폰의 ntfy 앱에 즉시 표시됩니다), **Gotify** 메시지 URL 또는 **Discord** 웹훅 중 하나입니다. 서비스가 요구하는 **형식**을 고르세요. **테스트 메시지 보내기**를 누르면 입력란에 적힌 내용으로 바로 시험해 볼 수 있습니다. 메시지에는 에이전트의 이름과 그 요구 사항(“사용자를 기다림”, “완료됨”, “명령 ... 승인 요청”, “실패”, “일시 정지됨: 사유”)이 사용자의 언어로 적힙니다. **애플리케이션이 열려 있을 때도**에 체크하면 화면이 열려 있는 경우에도 항상 보냅니다.

메시지는 서버가 주소를 호출해서 보내므로, 관리자는 이 기능을 모든 사용자에 대해 끌 수 있습니다(관리자 메뉴, *에이전트*). 또한 관리자가 사용자의 권한에서 **이 컴퓨터와 사설 네트워크의 주소 허용**에도 체크하지 않는 한, 인터넷상의 주소로만 호출합니다. 같은 컴퓨터나 자신의 네트워크에 있는 ntfy나 Gotify를 사용하려면 관리자에게 이 설정을 요청하세요. 주소가 거부되면 테스트 메시지에 그 사실이 표시됩니다. 주소에 비밀 정보가 담겨 있다면 비밀번호처럼 다루세요. 이 주소를 아는 누구든 전송되는 내용을 읽을 수 있습니다. 서버는 주소를 로그에 기록하지 않고, 리다이렉트를 따라가지 않으며, `http`와 `https` 주소만 호출합니다.

<a id="asking-you"></a>

## 사용자에게 묻기

에이전트가 사용자를 필요로 하면, 앱의 어느 화면에 있든 그 사실을 알려 줍니다.

- **에이전트** 탭의 **숫자**는 사용자를 기다리는 에이전트의 수를 셉니다. 이런 에이전트의 **콘솔** 버튼은 강조 표시됩니다.
- **알림** 창이 뜨며, **열기** 버튼을 누르면 해당 에이전트의 콘솔이 열립니다.

에이전트가 사용자를 필요로 하는 경우는 *사용자에게 무언가를 묻거나 다음 메시지를 기다릴 때*, **명령 승인**을 요청할 때, *작업을 마쳤을 때*, *실패했을 때*, 또는 *스스로 일시 정지되었을 때*(한도에 도달했거나, 모델에 요청할 수 없었거나, 서버가 다시 시작된 경우)입니다. 사용자가 직접 요청한 일시 정지는 여기에 해당하지 않습니다.

에이전트는 사용자가 자리를 비운 동안에도 작업하므로, 이 알림은 앱이 열려 있는지와 무관하게 동작합니다. 숫자는 다시 로그인했을 때도 그대로 남아 있고, 열려 있는 모든 브라우저 창에도 알림이 뜹니다. 해당 에이전트의 콘솔을 열면 알림이 지워집니다(다른 창도 함께 갱신됩니다).

에이전트가 **먼저 묻기**로 설정되어 있고 데이터를 변경하거나 삭제하는 명령을 요청하면, 실행은 *승인을 기다리는 중* 상태에서 멈추고, 콘솔 위에 명령과 인수가 적힌 창이 뜹니다. **승인**을 누르면 명령이 실행되고, **거부**를 누르면 에이전트에게 사용자가 거절했다고 알려 주며 에이전트는 계속 진행합니다. 실행을 일시 정지하거나 중지하는 것(또는 서버를 중지하는 것)은 거부로 간주되지 않습니다. 에이전트에게는 아무것도 알려지지 않으며, **재개**하면 같은 명령에 대한 창이 다시 나타납니다. 이 명령은 여전히 책의 [사본](#the-working-copy)에 적용됩니다. 콘솔을 닫았더라도, 콘솔을 다시 열면 창이 바로 나타납니다.

![명령 승인을 요청하는 창](../images/agent-approval.png)

<a id="when-the-server-stops"></a>

## 서버가 중지될 때

서버를 중지하면, **지금 일시 정지**를 눌렀을 때와 마찬가지로 작업 중인 실행이 먼저 일시 정지됩니다(서버에 몇 초의 시간을 줍니다). 진행 중이던 요청과 호출은 중단되고, 실행은 "서버가 중지되었습니다"라는 사유와 함께 *일시 정지됨* 상태가 되며, **재개**를 누르면 계속 진행할 수 있습니다. 서버가 강제 종료되거나 충돌한 경우에는, 다음 시작 때 작업 중이던 실행을 찾아 일시 정지합니다("서버를 다시 시작하여 중단됨"). 실행이 한 모든 작업은 유지됩니다. 저장된 라운드, 사본, 작업 공간, 그리고 대기 중이던 메시지와 명령도 그대로입니다. 잃는 것은 끝나지 않은 라운드뿐입니다. 재개하면 실행이 진행 중이던 호출을 다음과 같이 처리합니다.

- **아직 시작되지 않은** 호출(사용자의 승인을 기다리거나, 다른 호출 다음 차례를 기다리던 것)은 다시 요청됩니다. 따라서 사용자의 승인이 필요한 명령은 다시 묻습니다. 읽기만 하는 호출도 다시 요청됩니다.
- **이미 무언가를 변경하기 시작한** 호출은 일부만 실행되었을 수 있습니다. 이 경우 에이전트에게 그 결과가 *불확실하다*고 알리고, 에이전트는 반복하기 전에 읽기 도구로 결과를 먼저 확인합니다. 그 뒤의 호출은 실행되지 않은 것으로 표시됩니다.
- 서버가 중지되었을 때 실행 중이던 사용자의 명령은, 실행이 재개되면 함께 계속됩니다. `/compact`와 `/clear-workspace`는 다시 실행됩니다. 시작되었던 다른 명령은 **다시 실행되지 않습니다**(일부만 실행되었을 수 있기 때문입니다). 에이전트에게 이 사실이 알려지고, 에이전트가 결과를 확인합니다. 그 뒤에 쌓인 메시지와 명령은 평소처럼 전달됩니다.
- 에이전트의 계획과 명령 결과(`list_command_results`, `@result`)도 유지되므로, 재시작 후에도 에이전트가 이를 사용할 수 있습니다.
- 하위 에이전트의 진행 중이던 호출도 에이전트의 경우와 같이 처리됩니다. 시작되지 않은 호출은 다시 요청되고, 시작되었던 호출은 하위 에이전트에게 "결과 불명"으로 보고되며, 사용자의 승인을 기다리던 하위 에이전트는 다시 묻습니다.
- 명령이 실행 중일 때 서버가 **강제 종료**(`kill -9`, 정전)되면 명령도 함께 종료됩니다. 명령이 한 작업은 위에서 설명한 대로 처리됩니다.

<a id="the-working-copy"></a>

## 작업 사본

모든 실행은 실행이 시작될 때 앱이 만드는 **책의 사본**과 그 로어북들에서 작업합니다. 사본에는 그 시점의 메시지, 요약, 태그, 설정이 담기며, 로어북은 하위 로어북과 함께 복사됩니다. 사본은 숨겨져 있어서 책과 로어북 목록에 나타나지 않습니다. 에이전트가 무엇을 하든 사본에만 적용되며, 사용자의 책은 그대로 남습니다.

에이전트의 **에이전트의 모델로 책 쓰기**가 켜져 있으면(기본값), 실행이 시작되거나 재개될 때마다 사본은 책의 AI와 프로토콜 대신 **에이전트의 모델**(주 모델 프로필의 AI와 프로토콜)을 사용합니다. 따라서 모델로 글을 쓰는 명령(`/next`, `/swipe`, `/regenerate`, `/redraft-part`, `/generate-annotation`, 요약)과 확장 기능의 모델 명령(로어 생성기, 아크 개요)은, 책이 다른 모델로 설정되어 있거나 아무 모델도 없더라도 에이전트의 모델을 사용합니다. 다만 호출에서 지정한 `profile`이 있으면 그것이 우선합니다. 이 설정을 끄면 책의 모델을 사용합니다. 이것은 책의 변경이 아니므로, 검토 화면에는 나타나지 않으며, 결과를 적용해도 책의 AI와 프로토콜은 그대로 유지됩니다.

사본은 책이 속한 [폴더](books/folders.md)에 놓이므로, 에이전트는 책과 마찬가지로 폴더가 설정한 값(언어, 템플릿, 시점, 시제, 문체, 프롬프트)에 따라 글을 씁니다. 사본은 폴더의 내용이 아니므로 폴더에 집계되지 않으며, 사본에서의 작업이 폴더의 *마지막 수정*을 바꾸지도 않습니다. 실행이 일시 정지된 동안 책을 다른 폴더로 옮기면 사본도 따라갑니다. 결과를 적용해도 책의 위치는 바뀌지 않습니다.

일시 정지된 실행은 사본을 그대로 보관하고, 재개하면 그 사본에서 다시 작업합니다. *완료됨* 상태이거나, 중지한 뒤 보관해 둔 실행은 [결과를 채택하거나 버릴 때까지](#reviewing-the-result) 사본을 유지합니다. 실행이 *실패*했거나, 결과를 버렸거나, 변경 사항이 적용되었다면 사본은 영구히 삭제되며, 다음 실행은 그 시점의 책으로부터 새 사본을 만듭니다.
<a id="resuming-a-run"></a>

## 자동 실행 재개하기

일시 정지되었거나 보관된 실행은 책에 대한 잠금을 유지하지 않으므로, 그 사이에도 책을 편집할 수 있습니다. 실행을 **재개**하면 실행의 작업 사본이 사용자가 한 작업을 따라잡습니다.

- 사용자가 변경했고 에이전트는 변경하지 않은 것(부분, 로어북 항목, 설정, 태그 등)은 사본에 들어갑니다. 사용자가 추가한 부분도 들어가며, 에이전트가 그 위에 이어서 작업할 수 있습니다. 사용자가 삭제한 것은 사본에서도 삭제됩니다.
- 사용자와 에이전트가 모두 서로 다른 텍스트로 변경한 것은 **에이전트가 가진 상태 그대로 유지됩니다**. 에이전트가 한 작업은 하나도 사라지지 않습니다. 이는 결과를 검토할 때 두 텍스트를 나란히 보고 해결해야 하는 [충돌](#reviewing-the-result)로 처리됩니다.
- 사용자가 변경했지만 에이전트가 삭제한 것은 삭제된 상태로 남고, 사용자가 삭제했지만 에이전트가 변경한 것은 사본에 남습니다. 검토 화면에서 두 경우를 모두 보여 줍니다.

별도로 누를 버튼은 없습니다. 동기화는 재개 과정의 일부이며 잠시(변경한 항목이 수백 개라면 몇 초) 걸립니다. 동기화 전 사본의 상태는 자동 [체크포인트](#checkpoints)로 저장됩니다. 에이전트는 실행이 다시 진행될 때 무엇이 바뀌었는지 알림을 받습니다. 이 알림에는 에이전트가 항목을 알고 있는 이름으로 적혀 있으며("일시 정지된 동안 사용자가 책을 변경했습니다..."라는 메시지로 전달됩니다). `get_sync_report`로 다시 요청할 수도 있습니다.

**충돌은 저절로 사라지지 않습니다.** 재개할 때마다 사본과 책을 다시 비교하므로, 충돌은 해결될 때까지 재개할 때마다 다시 보고되고 에이전트에게도 매번 다시 알려집니다. 해결하려면 사용자 쪽 책을 바꾸거나(에이전트의 텍스트로 또는 원래 텍스트로 되돌려서), 검토 화면에서 처리하면 됩니다.

**재개 시 메모 남기기.** **재개**를 누르면 *에이전트에게 남기는 메모 (선택 사항)* 입력란이 있는 작은 창이 열립니다. 여기에 적은 내용은 에이전트가 다시 작업을 시작할 때 가장 먼저 읽는 내용이며, 사용자가 책에서 한 변경 사항 보고 다음에 놓입니다. 이 메모는 방향을 바꿀 때 쓰도록 만들어졌습니다("로어북은 건드리지 마", "3장부터 시작해" 등). 대화에 보내는 메시지와 달리, 사용자의 메시지를 기다리지 않는 실행을 포함해 모든 실행에서 동작합니다. 평소처럼 재개하려면 비워 두면 됩니다.

<a id="reviewing-the-result"></a>

## 결과 검토하기

실행이 *완료*되었거나(또는 **중지하고 결과 유지**로 멈추었을 때) 에이전트 행과 콘솔에 **변경 사항 검토** 버튼이 나타납니다. 이 버튼을 누르면 에이전트가 변경한 모든 내용을 **지금 현재의** 책과 비교해 한 줄씩 보여 주는 창이 열립니다. 에이전트가 보고한 발견 사항이 있으면 변경 사항 위에 **발견 사항 (3)**처럼 나열되므로, 아무것도 바꾸지 않은 점검이라도 보여 줄 내용이 있습니다.

![실행 결과 검토하기](../images/agent-review.png)

- **책:** 이름, 설명, 언어, 시점, 시제, 문체, 템플릿, 부분마다 보관하는 버전 수, 태그, 그리고 확장 기능이 책에 보관하는 데이터(아크 개요, 캐릭터 추적기)입니다.
- **부분:** 에이전트가 본문, 지시문, 장면 설정, 시점 인물, 등장 인물, 요약을 바꾼 부분, 에이전트가 쓴 부분, 에이전트가 삭제한 부분. 생성 과정이 부분과 함께 보관하는 변수(및 확장 기능의 데이터)는 **데이터** 항목으로 함께 가져옵니다.
- **로어북**과 **항목:** 에이전트가 만들었거나, 바꾸었거나(이동, 이름 변경, 태그나 하위 책이 달라진 경우 포함), 삭제한 로어북 또는 항목.
- **주석:** 에이전트가 만들었거나, 바꾸었거나(메모, 유형, 상태), 삭제한 부분 본문의 구절에 대한 [메모](books/annotations.md#annotations-and-agents).

가져올 줄을 체크한 다음 **선택한 변경 사항 적용**을 누릅니다. 목록 위의 버튼으로 **전체**, **없음**, **새 부분만**(에이전트가 쓴 새 가지만, 다른 것은 제외), **주석만**, 또는 **충돌 제외 전체**를 한 번에 체크할 수 있습니다. 다른 줄에 의존하는 줄(새 부분이 그 뒤를 잇는 부분도 새 것이라면 그 부분이 필요합니다)은 체크할 때 그 줄을 함께 체크하고, 체크를 해제하면 그 줄에 의존하던 줄도 함께 해제됩니다. 줄을 클릭하면 오른쪽에서 내용을 볼 수 있습니다. 책의 현재 텍스트와 적용될 텍스트를 함께 보여 주며, **적용 전에 적용될 텍스트를 편집할 수 있습니다**. 아무것도 적지 않으면 에이전트의 텍스트가 적용됩니다.

실행이 시작된 뒤에 책이 바뀌었을 수 있습니다(에이전트가 작업 중이 아니면 언제든 책을 편집할 수 있습니다). 사용자만 바꾼 내용은 목록에 나타나지 않으며 그대로 유지됩니다. 둘 다 같은 내용으로 바꾼 경우에는 변경이 아닙니다. 둘 다 **서로 다른** 텍스트로 바꾼 경우는 **충돌**입니다. 충돌은 기본적으로 체크되지 않은 상태로 시작하며, 체크하면 오른쪽에 보이는 텍스트가 책의 텍스트를 대체합니다. **책의 것 사용**을 누르면 책의 텍스트가 입력 상자에 들어가고(이 경우 그 줄은 해당 필드를 바꾸지 않습니다), **에이전트의 것 사용**을 누르면 에이전트의 텍스트가 다시 들어갑니다. 또는 결과를 직접 적을 수도 있습니다. 적용할 수 없는 줄(그 줄이 뒤를 잇는 부분이나 속한 로어북이 책에서 삭제된 경우)은 그 사실을 알려 주며 체크할 수 없습니다.

![검토 화면의 충돌](../images/agent-review-conflict.png)

텍스트 아래의 **차이점**은 변경 내용을 **단어 단위로** 보여 줍니다. 책에만 있는 내용은 빨간색 취소선으로, 적용될 텍스트에만 있는 내용은 초록색으로 표시됩니다(입력 상자에 적은 내용을 따릅니다). 충돌의 경우에는 실행이 시작된 뒤 에이전트가 바꾼 내용과 사용자가 바꾼 내용을, 각각 그 당시의 책을 기준으로 함께 보여 주므로 누가 무엇을 바꿨는지 알 수 있습니다. 에이전트가 여러 항목을 함께 바꾼 줄(장면 설정과 본문이 함께 바뀐 부분, 새 내용과 메모가 함께 바뀐 항목)에는 각 항목 옆에 **이 변경 사항 적용** 상자가 있습니다. 하나를 체크 해제하면 줄은 나머지만 적용되고, 책은 그 필드에 자기 값을 유지합니다. 부분이 이야기에서 놓인 위치는 부분과 함께 움직이며 상자가 없습니다. 에이전트가 만들었거나 삭제한 항목은 전체로 가져가거나 남깁니다. **사본에서 보기**(에이전트가 만들었거나 바꾼 줄에서)를 누르면 해당 부분이나 항목이 있는 위치에서 [책의 사본](#the-copy-of-the-book)을 열어 제자리에서 읽을 수 있습니다.

![충돌의 차이점, 단어 단위로 표시](../images/agent-review-differences.png)
<a id="data-that-extensions-keep-json"></a>

### extensions가 보관하는 데이터 (JSON)

확장 기능은 책, 그 파트, 로어북과 항목(아크 개요, 캐릭터 추적기, 생성의 변수 등)에 자신의 데이터를 보관합니다. 이 데이터는 JSON이며, 검토 화면에서는 **보기 좋게 정리된 형태**로 보여 주고, 적용될 텍스트 옆에 **JSON 데이터 병합** 줄이 함께 표시됩니다. 데이터는 통째로 가져오지 않습니다. 에이전트만 바꾼 부분은 에이전트의 것을 쓰고, 책만 바꾼 부분은 책의 것을 유지하며, 두 쪽이 **서로 다른 곳**을 바꾼 경우에는 곳마다 따로 합칩니다. 두 쪽이 **같은 곳**을 서로 다른 값으로 바꾼 경우에만 충돌이며(키의 순서는 상관없습니다), 결정하기 전까지는 그 자리에 에이전트의 버전이 쓰입니다.

**JSON 데이터 병합**을 누르면 세 버전의 데이터가 나무 구조로 겹쳐 열리는 창이 나타납니다. 열의 제목은 *실행 시작 시점*, *현재 책*, *에이전트*, *결과*이고, 각 곳이 무엇이 어떻게 바뀌었는지(에이전트, 책, 둘 다, 충돌)를 표시로 보여 줍니다. 바뀐 곳만 표시되며(모두에 대해 **변경된 것만**의 체크를 해제하면 전체가 보입니다), 곳은 열어야만 펼쳐지므로 큰 문서도 문제없습니다.

![확장 기능 데이터를 겹쳐 놓은 모습](../images/agent-json-merge.png)

- 곳을 선택하고 한 버전에서 데이터를 가져옵니다(**에이전트의 것 사용**, **책의 것 사용**, **실행 시작 시점의 것 사용**). 또는 **제외**(그 키나 항목을 결과에 넣지 않음)를 고르거나, **안에서부터 다시 합치기**(안에 있는 곳들이 각각 스스로 결정)를 고를 수 있습니다. 한 버전에만 있는 키나 항목은 그 버전에서 가져와 결과에 복사됩니다. 객체나 목록 전체를 한 버전에서 가져오면 그 안에서 고른 것은 무시되지만, 영구적으로 사라지는 것은 아닙니다. 다시 안에서부터 합치면 고른 내용이 되살아납니다.
- **목록**의 항목에는 이름이 없으므로, 항목이 무엇인지로 짝을 짓습니다. 먼저 같은 데이터, 다음으로 같은 `uuid`, `id` 또는 `name`, 그다음으로 가장 비슷해 보이는 항목을 찾습니다. 그래도 남은 항목은 같은 개수와 같은 종류끼리 바뀐 것으로 봅니다. 추측이 틀렸다면, 항목을 **분할**해 각 버전의 항목으로 나누거나, 첫 항목과 공통 버전이 없는 다른 항목과 **다음과 일치시키기…**를 사용하세요.
- **열기**(또는 더블 클릭)는 한 곳만 따로 엽니다. 나무 위의 경로를 누르면 위로 돌아갑니다.
- **텍스트** 탭은 열린 곳의 데이터를 텍스트로 보여 줍니다. 에이전트의 데이터는 **편집**할 수 있고, 나머지(책, 실행 시작 시점, 결과)는 읽기만 가능합니다. **다음과의 차이 보기**를 누르면 단어 단위로 다른 부분이 표시됩니다. 입력한 내용은 나무 구조로 돌아갈 때, 보여 주는 대상을 바꿀 때, 다른 곳을 열 때, 결과를 사용할 때 JSON으로 검사됩니다. 올바른 JSON이 아니면 그 자리에 머물며 무엇이 잘못되었는지 알려 주고, 아무것도 바뀌지 않습니다. 올바른 텍스트라면 그 곳의 에이전트 데이터를 대체하고, 그 안의 모든 내용이 다시 비교됩니다.
- **처음부터 다시**는 지금까지 정하고 입력한 내용을 모두 잊고, **결과 사용**은 결과를 검토 화면에 넘깁니다. 검토 화면에서는 그것이 적용될 텍스트가 되며, 검토 화면이 열려 있는 동안 줄은 떠나올 때의 상태로 남습니다.

검토 화면에도 이런 필드를 위한 **에이전트의 것 사용**과 **책의 것 사용**이 있어, 둘 중 하나를 그대로 고를 수 있습니다. **처음부터 다시**를 누르면 합쳐진 데이터로 돌아갑니다.

![검토 화면의 아크 개요 데이터와 JSON 데이터 병합](../images/agent-review-json.png)

다른 책들이 함께 쓰는 로어북에는 **공유됨** 표시가 붙습니다. 이때 변경은 로어북 자체에 적용되므로, 다른 책들도 그 변경을 받게 됩니다. 이 체크는 처음에는 해제되어 있습니다.

적용은 책에 **그 자리에서** 이루어집니다. 파트들은 주소를 그대로 유지하고, 다른 책들은 로어북과의 연결을 유지하며, 에이전트가 삭제한 것은 휴지통으로 갑니다. 적용 전에 **수정 전 책의 백업**이 먼저 만들어지며(로어북과 함께 책의 백업 목록에 들어갑니다), 변경은 모두 한꺼번에 적용되거나 아예 적용되지 않습니다. 적용한 항목에 포함되어 있다면 **에이전트가 끝낸 분기 보기**를 누를 때 책도 에이전트가 있었던 분기로 전환됩니다. 편집된 파트의 요약은 직접 편집했을 때와 마찬가지로 오래된 것이 되며, 에이전트가 직접 쓴 요약은 그대로 가져옵니다.

변경이 적용되면 실행 기록은 *적용됨* 상태가 되고, 그 사본과 체크포인트는 삭제됩니다. **결과 폐기**를 누르면 사본을 버리고 책은 그대로 둡니다. 둘 중 하나를 하기 전까지 에이전트는 끝나지 않은 실행을 안고 있어서 다른 실행을 시작할 수 없습니다.

<a id="the-copy-of-the-book"></a>

### 책의 사본

**책 사본** 탭은 에이전트가 작업하는 책을 읽기 전용으로 보여 줍니다. **이야기**는 한 번에 한 분기씩 보여 주며(위에서 분기를 고릅니다), 각 파트는 번호, 같은 파트의 다른 것들 가운데 선택된 스와이프, 단어 수, 장면 설정, 시점과 접혀 있는 지시문 및 요약과 함께 나타납니다. **로어북**은 그 항목들과 함께 보여 주며(하나를 고르면 내용, 메모, 태그, 설정이 나타납니다). 이것은 책의 창이 아니므로, 여기서 아무것도 바꿀 수 없고, 사본에 대한 백업도 만들지 않으며, 어떤 확장 기능도 열린 책을 보지 않습니다. 이 내용은 탭을 열 때와 **새로 고침**을 누를 때 읽히며, 에이전트가 작업하는 동안에도 읽히므로 에이전트가 지금까지 쓴 내용을 볼 수 있습니다. 사본은 실행이 사본을 가지고 있는 동안에만 있습니다(결과가 적용되거나 폐기된 뒤에는 없습니다).

<a id="diagnostics"></a>

### 진단

**진단** 탭은 실행이 한 일을 그 기록(트랜스크립트)에서 세어, 에이전트가 도구와 프롬프트에 무엇을 필요로 하는지 알아내게 해 줍니다. 어떤 실행에도 사용할 수 있으며, 오래된 실행도 가능합니다(먼저 **실행 기록**에서 고르세요). 이 내용은 탭을 열 때와 **새로 고침**을 누를 때 만들어집니다.

![진단 탭](../images/agent-diagnostics.png)

- **개요**: 라운드와 호출 수, 실패한 호출 수, 모델의 시간, 호출의 시간, 멈춤의 시간(두 단계 사이가 30분 이상 떨어져 있으면 작업이 아니라 멈춤으로 봅니다), 최고점과 끝의 컨텍스트, 토큰, 압축 횟수, 사용자의 메시지, 그리고 실행기가 에이전트에게 알린 공지(읽을 수 없는 호출, 호출이 너무 많음, 컨텍스트가 가득 참)를 보여 줍니다.
- **도구**: 도구별로 호출 수, 오류, 잘린 결과, 한 라운드에서 유일한 호출이었던 횟수, 에이전트가 쓴 글자 수, `@file:` 또는 `@result`로 텍스트를 넘긴 호출 수, 긴 텍스트(300자 이상)를 쓴 횟수와 그중 방금 받은 결과에서 복사한 횟수, 결과의 토큰 수(글자 수로 추정), 전체 결과 중 비중, 가장 긴 결과, 그리고 시간을 보여 줍니다.
- **요청이 보고한 내용**: 실행 중에 기록되므로, 이 기능이 추가된 뒤에 만들어진 실행에만 해당합니다(더 오래된 실행에는 이 정보가 없다고 표시됩니다). 요청이 첫 단어를 기다린 시간(서버가 프롬프트를 읽는 시간이므로, 짧으면 캐시가 따뜻하다는 뜻입니다), 답변을 쓰는 데 걸린 시간과 초당 토큰 수, 서버가 다시 읽지 않은 프롬프트의 비율(캐시; llama.cpp와 OpenAI가 보고합니다), 답변 중 추론이 차지한 비율, 답변이 끝난 이유(`length`는 한 답변의 한도에 잘렸다는 뜻입니다), 모델이 쓴 호출 중 실행되지 않은 것(반복, 한도, 일괄 처리 정책), 요청이 자리를 기다린 시간, 작성된 요약과 그 소요 시간, 그리고 25라운드 블록마다 같은 항목을 보여 줍니다.
- **모델이 쓴 내용**: 인수, 호출 옆의 텍스트, 추론의 글자 수를 전체와 25라운드 블록마다 모델의 시간과 함께 보여 주어, 출력이 어디로 가는지, 그리고 어느 시점에 `@file` 사용을 멈췄는지 확인하게 해 줍니다. **가장 긴 인수**는 가장 큰 호출들의 시작 부분을 보여 주며, 파일 도구의 경우 경로도 함께 표시합니다.
- **패턴 때문에 낭비된 라운드**: 같은 도구가 라운드마다 연속으로 호출된 경우(세 번 이상)를 표시하며, 바로 앞에 검색이 있었다면 그것도 표시합니다. 또 같은 인수로 다시 만들어진 호출도 보여 줍니다. 이것들은 여러 항목을 받는 도구나 한 답변에서 더 많은 호출을 할 수 있게 하면 라운드를 얼마나 아낄 수 있는지 보여 줍니다.
- **오류**: 각 메시지를 받은 첫 호출의 인수(호출이 실패했을 때 모델이 무엇을 보냈는지 확인하기 위함), **가장 큰 결과**, **가장 느린 라운드**, **압축**, 그리고 각 하위 에이전트가 호출한 도구와 함께 **하위 에이전트**를 보여 줍니다.

**다운로드**는 보고서를 Markdown으로, **JSON 다운로드**는 JSON으로 내려받게 하며, **복사**는 Markdown을 클립보드에 넣습니다. 시간은 저장된 행 사이의 간격이므로 대략적인 값입니다. 답변의 시간에는 모델에서 빈자리를 기다린 시간도 포함됩니다.
<a id="the-context"></a>

### 컨텍스트

**Context** 탭은 모델이 **다음 요청**에서 읽는 내용을 부분별로 나누어 보여 줍니다. 덕분에 토큰이 어디에 쓰이는지 확인할 수 있고, 이상하게 동작하는 에이전트를 디버그할 수 있습니다. 이 내용은 탭을 열 때와 **새로 고침**을 누를 때 만들어집니다(실행이 진행 중일 때는 만들어지지 않습니다. 모든 부분의 토큰을 세기 때문입니다).

- 차트는 세 가지입니다. 첫째는 **부분의 종류**별 크기를 컨텍스트 한도와 비교한 차트입니다(에이전트의 프롬프트, 사용자의 지시, 실행기의 메모, 도구 정의, 압축의 요약, 사용자의 메시지, 에이전트의 답변, 도구 호출 결과, 그리고 남은 공간). 둘째는 **보내지는 순서대로 본 모든 부분**입니다(부분마다 막대가 하나씩 있고 종류에 따라 색이 다릅니다. 설명이 아주 긴 도구나 컨텍스트를 가득 채우는 결과가 두드러져 보입니다). 셋째는 **모델의 답변마다의 컨텍스트**입니다. 누적 막대는 그 컨텍스트를 이루던 내용을 같은 종류로 추정한 것이고, 모델이 **보고한** 크기는 선으로, 한도는 점선으로 표시됩니다. 선이 막대 위에 있으면 모델이 추정보다 많이 센 것입니다(이미지나 제공자의 형식 때문입니다). 막대가 줄어드는 곳은 압축이나 되돌리기가 있었던 곳입니다.
- **부분의 표**에는 종류, 이름, 토큰 수, 컨텍스트에서 차지하는 비율이 나옵니다. 행을 고르면 그 부분에 대해 모델이 받는 **정확한 텍스트**를 읽을 수 있습니다. 시스템 메시지의 한 섹션, 도구 하나의 설명과 매개변수, 메시지 하나, 호출의 인자, 또는 호출의 결과가 여기에 해당합니다.
- **다운로드**를 누르면 컨텍스트 전체를 Markdown 파일 하나로 받을 수 있습니다(섹션이 포함된 시스템 메시지, 설명과 스키마가 있는 모든 도구, 메시지 단위로 정리된 대화. 각 텍스트는 코드 펜스 안에 들어갑니다). **복사**를 누르면 같은 텍스트가 클립보드에 복사됩니다.

![Context 탭](../images/agent-context.png)

부분의 크기는 추정치입니다. 모델이 보고한 수치가 실제 값입니다(요청과 그에 대한 답변을 기준으로 합니다). 답변 차트에서 프롬프트, 지시, 도구는 지금 상태 그대로입니다(지시나 프롬프트를 바꾸었다면 이전 답변은 다른 내용을 가졌을 수 있습니다). 대화는 그 당시의 상태입니다. 요약은 그 앞에 있던 내용을 대신하고, 되돌리기가 되돌아간 내용은 그 뒤 답변에서 사라집니다(되돌려진 압축은 다시 살아나지 않으므로, 그 뒤의 막대는 조금 작게 나옵니다). 시스템 메시지와 도구는 다음 요청이 사용할 것이므로, 프롬프트, 지시, 허용된 명령을 바꾸면 바로 반영됩니다. 메시지는 저장된 기록 그대로이며, 재개할 때 추가되는 내용(예: "계속"이라는 메시지, 중단으로 열려 있던 호출에 대한 답변)은 포함되지 않습니다. 추론 과정은 컨텍스트에 포함되지 않으며(모델에게 다시 보내지지 않습니다), 이미지는 파일 이름으로 표시됩니다. 압축이 대체한 내용도 컨텍스트에 없습니다. 이 내용은 **실행** 탭과 **실행 기록** 다운로드에서 여전히 볼 수 있습니다.

## 체크포인트

**체크포인트**는 실행 작업 복사본(부분, 요약, 로어북, 확장 기능의 데이터, 에이전트에게 주어진 핸들)과 에이전트의 작업 공간에 대한 복원 지점입니다. 잘못된 작업을 되돌릴 수 있도록 만들어집니다. 에이전트는 `checkpoint_restore`로 되돌아갈 수 있고, 여러분은 콘솔의 **체크포인트** 탭에서 직접 되돌릴 수 있습니다. 체크포인트를 만드는 주체는 다음과 같습니다.

- **실행 시작**: 실행이 시작될 때 만들어집니다. 이 체크포인트는 절대 밀려나지 않습니다.
- **자동**: 에이전트가 책이나 작업 공간을 바꿀 수 있는 무언가를 호출하는 라운드(일반 읽기가 아닌 명령이나 쓰기를 하는 파일 도구) 전에 실행이 만듭니다. 마지막 체크포인트 이후 무언가 바뀐 경우에만 만들어집니다. 최근 다섯 개가 보관되며, 새 것이 만들어지면 가장 오래된 것이 사라집니다.
- **의도적으로 만듦**: 에이전트가 `checkpoint`로 만들거나(위험한 단계 전에 만들도록 지시받습니다), 여러분이 **체크포인트 저장**을 눌러 만듭니다. 삭제하기 전까지 유지됩니다.

![Checkpoints 탭](../images/agent-checkpoints.png)

한 실행의 모든 체크포인트는 관리자가 [권한](administration/permissions.md#settings-of-a-permission)에서 설정하는 **할당량**을 공유합니다(비어 있으면 100MB입니다). 그중 일부는 자동 체크포인트를 위해 남겨 두어, 에이전트가 전부 써 버리지 못하게 합니다. 의도적으로 만든 체크포인트가 공간에 들어가지 않으면 **거부**되며, 요청한 사람이 모르는 사이에 아무것도 삭제되지 않습니다. 이후 에이전트는 목록을 받아 필요 없는 것을 삭제합니다(시작 체크포인트와 가장 최근 체크포인트는 제외됩니다). 여러분은 탭에서 아무 체크포인트나 삭제할 수 있습니다. 각 체크포인트는 아카이브(책을 JSON으로 담은 것, 쌍들, 작업 공간 파일을 담은 ZIP)이며 **다운로드**할 수 있습니다.

**복원**을 누르면 체크포인트에서 작업 복사본을 다시 만듭니다. 새 복사본이 생기고 이전 복사본은 삭제되며, 작업 공간은 저장된 상태가 됩니다(그 뒤에 쓰인 파일은 사라집니다). 그 시점에 있던 항목에 대한 에이전트의 핸들은 계속 작동합니다. 복원하기 전의 상태는 공간이 있으면 먼저 자동 체크포인트로 저장되므로, 복원을 되돌릴 수 있습니다. 복원은 실행을 시작하는 데 걸리는 시간과 비슷하게 걸립니다(부분이 이천 개인 책이라면 약 30초). 에이전트가 작업하지 않을 때 복원할 수 있습니다. 에이전트는 라운드와 라운드 사이에 스스로 복원하며, 무엇이 돌아왔는지 전달받습니다. 실행이 자신의 복사본을 놓으면 체크포인트도 사라집니다.

**되돌리기**는 *대화*까지 되돌리는 복원입니다. 복원만 하면 에이전트는 더 이상 책에 없는 작업을 기억하고 있으므로, 다른 방향으로 보내고 싶은 실행에는 되돌리기가 필요합니다. 작업 복사본과 작업 공간은 체크포인트로 돌아가고, 체크포인트가 만들어진 지점 이후의 메시지는 기록에서 회색으로 표시됩니다(여전히 읽을 수 있고 내보내기에도 포함됩니다). 에이전트는 그 메시지들을 더 이상 읽지 않습니다. 무슨 일이 있었는지를 알리는 안내가 에이전트에게 전달되므로, 여전히 필요한 작업이라면 다시 수행합니다. 실행은 일시 정지되거나 중지되어 있어야 합니다(먼저 여러분을 기다리는 에이전트를 일시 정지하세요). 이후 **재개**를 누르면 실행은 안내 지점부터 계속됩니다. 체크포인트는 대화에서 그 위치가 아직 그 대화의 일부일 때만 되돌릴 수 있습니다. 더 이른 체크포인트로 되돌린 뒤에는, 되돌려진 대화에 속한 이후의 체크포인트는 복원만 할 수 있습니다. 되돌리기가 생기기 전에 만들어진 체크포인트는 대화에서의 위치를 알지 못하므로 복원만 할 수 있습니다. 체크포인트 이후에 압축이 한 일은 되돌리기로 취소되며, 에이전트는 압축이 대체했던 메시지를 다시 읽게 됩니다.

**메시지로 되돌아가기.** 체크포인트를 고를 필요는 없습니다. 여러분이 에이전트에게 보낸 메시지마다 **실행** 탭의 기록에서 그 아래에 **되돌리기** 버튼이 있습니다. 이 버튼은 대화를 그 메시지 이전으로 되돌립니다. 에이전트는 그 메시지와 그 뒤의 모든 것을 잊고, 작업 복사본과 작업 공간은 그 이전에 만들어진 가장 최근 체크포인트로 돌아갑니다(실행기는 무언가를 바꾸는 라운드 전마다 체크포인트를 만들므로, 보통 메시지 바로 앞 시점과 맞습니다). 실행의 상태는 체크포인트에서만 알 수 있으므로, 가장 가까운 체크포인트가 메시지보다 오래되었다면 그 체크포인트와 여러분의 메시지 사이에 있던 메시지도 함께 잊힙니다. 확인 창에는 어느 체크포인트인지, 그리고 몇 개의 메시지가 사라지는지가 나옵니다. 잊힌 메시지는 기록에 회색으로 남습니다. 이 버튼은 에이전트가 여러분을 기다리는 동안(이를 위해 일시 정지된 상태), 일시 정지된 상태에서, 또는 중지된 뒤 보존된 상태에서 작동합니다. 에이전트가 작업 중일 때는 비활성화됩니다. 이후 실행을 **재개**하면 안내 지점부터 계속됩니다.

## 에이전트 만들기와 편집하기

**새 에이전트**를 누르면 **편집**과 같은 창이 열립니다:

![새 에이전트 창](../images/agent-dialog.png)

| 필드 | |
|---|---|
| **이름** | 필수입니다. |
| **사용** | 비활성화된 에이전트는 시작할 수 없습니다. 이미 실행 중인 실행은 건드리지 않습니다. |
| **책** | 에이전트가 작업할 책으로, 필수입니다. 에이전트가 없는 책만 선택할 수 있으며, 에이전트의 책은 나중에 바꿀 수 없습니다. |
| **모델**, **프로토콜** | 에이전트가 통신할 모델과 프로토콜입니다. 둘 다 지정하거나 둘 다 지정하지 않아야 하며, 둘 중 하나라도 없으면 에이전트를 시작할 수 없습니다. |
| **에이전트의 모델로 책 쓰기** | 기본값은 켜짐입니다. 켜져 있으면 모델이 필요한 명령(다음 턴, 스와이프, 요약, 그리고 Lore Generator나 Arc Outline 같은 확장 기능의 명령)은 책에 설정된 모델과 관계없이 위의 모델을 사용해 글을 씁니다. 꺼져 있으면 책의 모델을 사용합니다(책에 모델이 없으면 확장 기능 명령은 [설정](account.md)에 있는 기본 모델로 대체됩니다). 이렇게 모델을 섞어 쓸 수 있습니다. 생각을 많이 하는 강력한 모델과 더 저렴하거나 문장이 더 자연스러운 모델을 함께 쓰는 식입니다. 명령에서 에이전트의 다른 모델 프로필을 지정할 수도 있습니다. |
| **한 번의 응답 안의 호출** | 에이전트가 한 응답에서 작성하는 호출 중 어떤 것을 실행할지 정합니다. *모두 함께, 일괄 정책 무시*: 모든 호출을 함께 실행합니다(가장 빠릅니다). *함께, 단독으로 표시된 명령은 따로* (기본값): 호출을 함께 실행하지만, **일괄** 열이 *단독*으로 표시된 명령(모델을 호출하는 명령 등)은 자기만의 응답에서 실행되며 에이전트에게 이 사실이 알려집니다. *응답당 호출 하나*: 첫 번째 호출만 실행하고, 에이전트는 그 결과를 읽은 뒤 다음 호출을 작성합니다. 느리지만(호출마다 모델의 생각을 거치는 별도의 라운드가 필요합니다), 각 결과에 반응할 수 있습니다. **오류는 모든 모드에서 항상 응답을 끝냅니다.** 실패한 호출 뒤의 호출은 실행되지 않으며("앞선 호출이 실패해 실행되지 않음"이라고 답변됩니다), 에이전트는 먼저 오류를 읽습니다. |
| **모델이 이미지를 볼 수 있음** | 모델이 이미지를 처리할 수 있으면 체크하세요(모델 API가 이를 알려주지 않으므로 직접 지정해야 합니다). 체크하면 에이전트는 `view_image`를 사용할 수 있고 메시지에 이미지를 첨부할 수 있습니다. 체크하지 않으면 에이전트는 그림을 전혀 받지 못합니다. |
| **언어** | 에이전트가 읽는 모든 내용의 언어입니다. 여기에는 명령의 설명, 실행 결과와 오류 메시지, 그리고 실행의 내장 텍스트(기본 시스템 프롬프트, 실행 알림, 압축 프롬프트)가 포함되며, 해당 언어(영어, 일본어, 중국어)로 제공되는 경우에 한합니다. 설정의 [프롬프트 언어](account.md#prompt-language)는 에이전트에 적용되지 않습니다. 영어가 기본값이자 가장 안전한 선택입니다. 언어와 관계없이 명령과 매개변수가 영어로 되어 있기 때문입니다(다른 언어의 설명은 두 언어가 섞여 나타납니다). 특히 작은 모델은 이렇게 할 때 도구를 더 안정적으로 사용합니다. 목록에는 애플리케이션에 설치된 언어가 표시됩니다(중국어 현지화처럼 확장 기능이 언어를 추가할 수 있습니다). 이 설정은 **책의 언어와는 무관합니다**. 에이전트는 책의 텍스트를 책의 언어로 쓰도록 안내받으며, 이 언어는 `get-book-info`로 확인할 수 있습니다. 실행은 시작할 때의 언어를 유지하며, 변경 사항은 다음 실행부터 적용됩니다. |
| **파괴적 명령** | 에이전트가 데이터를 바꾸거나 삭제하는 명령을 요청했을 때의 처리 방식입니다. *실행하기*, *먼저 묻기*([창](#asking-you)에서 승인을 요청합니다), *거부하기* 중 하나를 선택합니다. |
| **최대 라운드 수**, **실행당 토큰 예산**, **컨텍스트 한도** | 한 번의 실행에 대한 선택적 한도입니다. 관리자가 정한 한도는 항상 함께 적용됩니다. |
| **최대 하위 에이전트 수** | 에이전트가 동시에 작업시킬 수 있는 [하위 에이전트](#sub-agents)의 수로, 0에서 10까지 지정할 수 있습니다. 비워 두거나 0이면 하위 에이전트를 만들지 않습니다. |
| **하위 에이전트용 모델** | 하위 에이전트가 실행될 수 있는 [모델](#models-for-sub-agents)과, 주 모델에서도 실행할 수 있는지 여부입니다. |
| **압축 시점 (컨텍스트의 %)** | 모델의 컨텍스트가 한도의 이 비율을 넘고 에이전트가 [작업을 직접 압축](#running-a-command-yourself)하지 않았다면, 실행이 자동으로 압축합니다. 에이전트가 이전 작업의 요약을 작성하고, 이 요약이 이전 작업을 대체합니다. 비워 두면 90, 0이면 압축하지 않습니다(컨텍스트가 가득 차면 실행이 멈춥니다). 그 밖의 값은 50에서 99 사이여야 합니다. |
| **시스템 프롬프트** | 에이전트가 어떤 역할을 할지 지시하는 내용입니다. 비워 두면 에이전트는 기본값을 따릅니다. 기본값은 [설정](account.md#templates)에서 지정한 것이 있으면 그것을, 없으면 관리자가 지정한 것을, 그것도 없으면 내장 기본값을 사용하며, 회색으로 표시됩니다. 정보 아이콘에는 **기본 템플릿 삽입** 버튼이 있어, 기본값을 채워 넣고 사본을 편집할 수 있습니다. 기본값을 다시 따르려면 입력란을 비우세요. |
| **압축 프롬프트** | [`/compact`](#running-a-command-yourself)를 실행할 때 에이전트에게 요청하는 내용으로, 이전 작업을 대체할 요약을 작성하게 합니다. 비워 두면 시스템 프롬프트와 마찬가지로 기본값을 따르며, 같은 정보 아이콘과 **기본 템플릿 삽입** 버튼을 사용합니다. |
| **지시문 (agents.md)** | 에이전트에게 주는 지시사항으로, 모든 실행의 프롬프트에 추가됩니다. 에이전트는 이를 읽을 수 있지만 바꿀 수는 없습니다. 비워 두면 [설정](account.md#templates)에서 지정한 기본값을 따릅니다(있는 경우 회색으로 표시됩니다). 기본값이 없으면 지시문은 없습니다. 정보 아이콘에는 **기본 템플릿 삽입** 버튼이 있어, 기본값을 채워 넣고 사본을 편집할 수 있습니다. 그 아래 줄에는 **매 요청마다** 프롬프트, 지시문, 선택된 명령이 차지하는 토큰 수가 표시됩니다(추정치이며, 파일과 실행을 위한 도구, 실행 도우미의 메모는 여기에 더해집니다). |
| **허용된 명령** | 아래를 참고하세요. |

<a id="allowed-commands"></a>

### 허용된 명령

에이전트에는 체크한 명령만 제공됩니다. 표에는 모든 명령과 그 효과가 나와 있습니다(*파괴적*은 데이터를 바꾸거나 삭제하고, *비파괴적*은 읽기만 하거나 추가만 합니다). **선택 항목** 상자로 여러 명령을 한꺼번에 체크할 수 있습니다. **전체**, **없음**, **파괴적이지 않은 모든 것**(새 에이전트의 기본값) 또는 역할을 고를 수 있으며, 명령을 직접 체크하면 선택 항목은 *사용자 지정*이 됩니다. 표 위의 **명령 검색** 입력란은 입력한 단어를 모두 포함하는 명령만 보여 줍니다(순서는 상관없고, 이름이나 설명에서 찾습니다). 선택 내용은 숨겨진 명령을 포함한 모든 명령에 그대로 적용됩니다. 확장 기능이 제공하는 명령은 해당 확장 기능이 로드되지 않아도 허용된 상태로 남으며, 다만 목록에 보이지 않을 뿐입니다. **일괄** 열은 해당 명령이 응답 안에서 다른 호출과 *함께* 쓰이는지, 아니면 *단독*으로 쓰이는지를 보여 줍니다(`next`, `swipe`, `regenerate`, `redraft-part`, `generate-annotation`, 압축처럼 모델을 호출하는 명령은 단독입니다. 아래 **한 번의 응답 안의 호출**을 참고하세요). 모든 열의 너비는 조절할 수 있습니다. **토큰** 열은 명령의 정의(이름, 설명, 매개변수)가 에이전트의 모든 요청에 더하는 양을 나타냅니다. 지시문 아래 줄에는 체크된 명령의 합계가 표시됩니다. 전체 명령 세트는 약 20 000 토큰이므로, 선택 범위를 줄이면(역할 사용 등) 작업을 위한 컨텍스트 공간이 더 넉넉해집니다.

![역할 선택 상자가 있는 허용된 명령](../images/agent-commands.png)

역할은 특정 작업을 위한 명령 묶음입니다. 모든 역할은 책과 로어북을 읽을 수 있으며(읽기만 하는 모든 명령, 확장 기능의 명령도 포함), 어느 역할도 데이터를 삭제할 수 없습니다:

| 역할 | 읽기 외에 할 수 있는 일 |
|---|---|
| **감사자** | 없음: 연속성 점검, 이름과 용어 감사, 보고서 작성. |
| **로어 관리자** | 로어북 항목과 로어북, 그 태그와 하위 로어북을 만들고 갱신합니다. |
| **편집자** | 파트를 편집하고 그 뒤에 추가하며, 파트의 필드를 설정합니다. 요약을 유지하고(모델에게 다시 쓰게 하는 것도 포함), 책 정보와 태그를 관리합니다. |
| **초안 작성자** | 파트와 분기를 추가하고, 편집하고 뒤에 추가합니다. 모델이 다음 턴을 쓰게 하고(`/next`, `/swipe`), 요약을 유지하며, 자신이 만들어 낸 내용의 로어북 항목을 만들고 갱신합니다. |

체크한 명령마다 그 정의가 모든 요청에 추가되므로, 역할은 약한 모델을 위해 프롬프트를 작게 만드는 가장 저렴한 방법이기도 합니다.

## 휴대폰에서

휴대폰 화면에는 서랍의 **에이전트** 탭이 있습니다. 에이전트를 사용할 수 있는 사용자에게 보이며, 탭 이름 옆에는 사용자의 확인이 필요한 에이전트 수가 표시됩니다. 각 에이전트는 이름, 상태, 표의 버튼이 들어간 카드로 나타나고, 버튼은 여러 줄로 나뉘어 표시됩니다. 콘솔, 검토 창, 에이전트 설정 창은 화면 전체를 채우며, 검토 창에서는 표가 항목의 상세 내용 위에 나타납니다. 모든 기능은 데스크톱과 같게 동작하고 화면만 작아집니다. 콘솔은 엄지손가락으로 조작하기 편하게 배치되어 있습니다:

![휴대폰의 에이전트 탭](../images/phone-agents.png)

![휴대폰의 콘솔](../images/phone-agent-console.png)

![휴대폰의 에이전트 탭](../images/phone-agents.png)

![휴대폰의 콘솔](../images/phone-agent-console.png)

- **탭은 아이콘**입니다 (run, runs, workspace, checkpoints, context, book copy, sub-agents, diagnostics). 열려 있는 탭은 창의 제목이 알려 줍니다.
- **일시 정지**, **Pause now**, **Resume**, **Finish**, **중지**는 화면 아래쪽의 아이콘 버튼이며, 지금 사용할 수 있는 버튼만 표시됩니다. **Review changes**는 글자를 그대로 유지합니다. 끝난 실행이 기다리는 대상이 바로 이것이기 때문입니다. **새로 고침**과 **Close**는 머리글의 아이콘입니다.
- **메시지 입력란은 한 줄**이며, 옆에 **보내기**와 **이미지 첨부** 아이콘이 있습니다. **명령줄**(터미널 아이콘)은 열기 전까지 숨겨져 있어서, 키보드가 대화 기록을 가리는 일이 없습니다. 대화 기록의 메시지는 가로 전체를 사용합니다.
- **표는 카드 목록**으로 바뀝니다. 실행, 체크포인트, 에이전트 설정의 명령, 검토 항목은 열 대신 각각 이름과 상태가 보이고, 그 아래에 상세 내용과 버튼이 놓입니다. 작업 공간의 파일은 이름 아래에 크기가 표시되며, 작업 공간의 도구 모음도 아이콘입니다. 컨텍스트 표에는 번호, 이름, 토큰이 그대로 남고, 각 부분의 종류와 비율은 선택한 부분의 글 아래에 표시됩니다.

- **상단 바에서 누가 기다리는지 볼 수 있습니다.** 서랍이 닫혀 있을 때 상단 바에 있는 빨간 숫자(열린 부분의 제목 옆)는 사용자의 확인이 필요한 에이전트 수를 셉니다. 서랍 안의 **에이전트** 탭 배지와 같은 값입니다. 이 숫자를 누르면 **에이전트** 탭으로 이동합니다. 기다리는 에이전트가 없을 때, 서랍이 열려 있을 때, 그리고 에이전트 탭 자체에 있을 때는 숨겨집니다.
- **부분 사이를 스와이프할 수 있습니다.** 내용 위에서 옆으로 스와이프하면 서랍의 다음 부분(왼쪽으로 스와이프)이나 이전 부분(오른쪽으로 스와이프)으로 이동합니다. 서랍이 열려 있을 때나 애플리케이션이 이동을 잠근 때는 동작하지 않으며, 텍스트 입력란, 표, 또는 가로로 스크롤되는 요소에서 시작한 터치는 해당 요소가 처리합니다.

대화 기록이나 검토 작업을 오래 해야 한다면 더 큰 화면이 여전히 편리합니다.

<a id="cloning"></a>

## 복제

**Clone**은 이름과, 에이전트가 없는 책을 묻습니다. 그런 다음 에이전트의 정의와 파일(실행 기록은 제외)을 그 책의 새 에이전트로 복사합니다. 에이전트는 관리자가 허용하는 만큼 만들 수 있으며, 기본값은 다섯 개입니다(관리자가 다른 숫자를 정하지 않았다면). 한도에 도달하면 **새 에이전트**와 **Clone**이 비활성화되고, 그 이유가 표시됩니다.

## 가져온 책의 로어 노트

원고를 [가져오면](books/story-editor.md#after-an-import) 애플리케이션은 책의 로어를 정리하는 에이전트를 제안합니다. 같은 항목이 이야기의 설정 메뉴 ⚙ 안, **분석**에도 있습니다: **Take lore notes with an agent...**. 시작하기 전에 먼저 확인을 요청합니다:

![에이전트를 시작하기 전의 질문](../images/lore-notes-confirm.png)

그러면 책의 모델과 프로토콜을 사용해 책 전용 **Lore notes** 에이전트를 만들고 시작합니다(콘솔이 열립니다).

- 이야기를 첫 부분부터 마지막 부분까지 몇 부분씩 나눠 읽고, 메모를 작업 공간의 파일(인물, 장소, 사물, 용어)에 기록하므로 일시 정지 후에도 이어서 작업할 수 있습니다. 요약은 길을 찾는 데 도움을 주고, 실제 근거는 부분의 본문입니다.
- 그다음 등장하는 인물, 장소, 사물, 집단, 용어마다 하나씩 항목을 책의 로어북에 씁니다(로어북이 없으면 책을 위해 하나 만듭니다). 필터로는 이야기가 사용하는 이름을 쓰고, 항목은 책의 언어로 작성됩니다. 이미 있는 항목에는 사실을 덧붙이며, 같은 내용을 두 번 쓰지 않습니다.
- 이야기와 로어북을 읽고 항목을 쓸 수 있지만, 이야기를 바꾸거나 무엇인가를 삭제할 수는 없습니다.

이 역시 다른 에이전트와 같은 에이전트입니다. 작업하는 동안 책은 [잠기고](#the-book-is-locked), 에이전트는 [사본](#the-working-copy)에서 작업합니다. 에이전트가 쓴 내용은 [검토](#reviewing-the-result)하고 인수한 뒤에야 비로소 사용자의 것이 됩니다. 인수하기 전에 항목을 읽으세요. 에이전트는 본문에 적힌 내용만 알고 있고, 긴 책은 요청을 많이 소모합니다. 지시문은 에이전트의 것입니다(**편집**에서 보이며, 다시 시작하기 전에 바꿀 수 있습니다). 다음의 경우에는 실행을 거절합니다: 에이전트를 사용할 권한이 없을 때, 책에 모델이 없을 때, 그리고 책에 이미 에이전트가 있을 때(책마다 하나만 가질 수 있습니다).

<a id="the-book-is-locked"></a>

## 책이 잠겨 있음

에이전트의 실행이 작업 중이거나 사용자의 확인을 기다리는 동안에는 **그 실행의 책이 잠깁니다**. 책은 읽을 수 있지만 아무것도 바꿀 수 없으므로, 에이전트가 움직이는 글 위에서 작업하는 일은 없습니다. 책 목록은 잠긴 책을 열지 않고, 어떤 에이전트가 그 책을 붙잡고 있는지 알려 줍니다. 잠긴 책에서는 생성, 편집, 검색 및 바꾸기, 요약, 책 삭제가 거절됩니다. 책을 다시 편집하려면 실행을 **일시 정지**하거나 **중지**하세요. 일시 정지, 중지, 완료된 실행은 책을 잠그지 않습니다.

![책 목록에서 에이전트가 작업 중인 책](../images/agent-locked-book.png)

**책의 로어북**도 함께 잠깁니다. 책이 사용하는 로어북과 그 하위 로어북이 해당합니다. Lorebooks 탭에서 이런 로어북은 휴대폰에서처럼 일반 텍스트로 표시되며 편집할 수 없고, 어떤 에이전트가 붙잡고 있는지 알려 주는 안내가 함께 나타납니다. 실행을 일시 정지하거나 중지한 뒤에는 **새로 고침**을 누르면 다시 편집할 수 있습니다. 다른 로어북은 영향을 받지 않습니다.

<a id="agents-and-folders"></a>

### 에이전트와 폴더

에이전트가 작업 중인 책이 [폴더](books/folders.md) 안에 있으면, 그 책은 자신의 위치와 설정을 유지합니다. 그 위에 있는 폴더를 옮기거나 삭제하는 것, 그리고 폴더가 하위로 전달하는 설정(언어, 템플릿, 시점, 시제, 문체, 프롬프트)을 바꾸는 것은 책 이름과 에이전트 이름을 함께 알려 주며 거절됩니다. 폴더의 이름을 바꾸거나 설명을 바꾸는 것은 거절되지 않습니다. 일시 정지, 중지, 완료된 실행은 잠금을 풉니다.
