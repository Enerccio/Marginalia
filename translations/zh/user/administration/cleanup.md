# 清理

当用户在 Marginalia 中删除某样东西（一本书、一个故事段落、一个世界书、一个推理提供商）时，它会从列表中消失，但仍保留在数据库里。这样删除是安全的，引用关系也不会断裂（一本书仍然知道写下其段落的提供商）。在此之前，用户可以从[回收站](../trash.md)标签页恢复已删除的对象。**Cleanup** 会永久移除这些已删除的数据，以减小数据库的体积。

![Cleanup 标签页](../../images/admin-cleanup.png)

<a id="running-a-cleanup"></a>

## 运行清理

!!!warning
清理无法撤销，被清理的内容也会从[回收站](../trash.md)中消失。请先[创建数据库备份](database-backups.md)。
!!!

1. 打开管理页面的 **Cleanup** 标签页，点击 **Analyze**。此时不会更改任何内容。
2. 查看结果（见下文）。
3. 点击 **Run Cleanup**，并确认 *将永久删除 n 个对象*。

清理针对所有用户的数据。

清理会从数据库中删除条目，对于文件，只会删除[智能体](../agents.md)的文件：已清除智能体的工作区以及已清除运行记录的文件夹。已删除[资源](../resources.md)的文件（段落的图片）会保留在其所有者的数据文件夹中，直到你在[资源文件](resource-files.md)标签页中将其删除。

<a id="seeing-what-is-deleted"></a>

## 查看已删除的内容

表格下方的 **Trash** 部分会列出所有用户的已删除对象，每个对象占一行（打开它即可加载表格）。这样你就能看到清理会删除哪些内容，并恢复别人请求你找回的内容。它与[回收站](../trash.md)标签页使用同一张表格，包括按用户和类型筛选的功能以及 *Extended Content* 链接。

![Cleanup 标签页中的 Trash 部分](../../images/admin-trash.png)

<a id="reading-the-analysis"></a>

## 阅读分析结果

第一张表格每种数据类型占一行：

| 列 | |
|---|---|
| **类型** | 数据的种类：`Manuscript`（书籍）、`ChatMessage`（故事段落）、`Lorebook`、`LorebookEntry`、`AI`（推理提供商）、`Protocol`、`Summary`、`Tag`、`TagRelation`、`User`…… |
| **已删除** | 已被删除的数量。 |
| **待清除** | 将被 *Run Cleanup* 移除的数量，包括属于已删除对象的数据。 |
| **被阻止** | 已删除，但仍在使用中，因此被保留。 |

**Deleted objects still in use** 列出被阻止的对象，显示其名称和 **Referenced by**，即仍在使用它们的对象。

<a id="what-is-removed"></a>

## 会被删除的内容

清理会删除没有任何未删除对象仍在使用的已删除对象，以及仅属于它们的数据：

| 已删除的对象 | 一并删除的内容 |
|---|---|
| 一本书 | 它的所有故事段落、摘要和标签关联 |
| 一个世界书 | 它的条目和标签关联；其他世界书不再将它作为子世界书包含在内 |
| 一个故事段落 | 该段落（其子段落已先移到父段落下）及其摘要 |
| 一个推理提供商或协议 | 从用户在 *Settings* 中的默认设置里清除 |
| 一个标签 | 它与书籍和条目之间的关联 |
| 一个用户 | 该用户拥有的一切：书籍（连同其故事段落和摘要）、世界书、推理提供商、协议、标签和设置 |

<a id="what-is-kept"></a>

## 会被保留的内容

当仍有未删除的对象在使用某个已删除对象时，该对象会被**阻止**清理，即被保留：

| 被阻止的对象 | 原因 | 如何解除阻止 |
|---|---|---|
| 已删除的推理提供商或协议 | 某本书仍将其用作模型或协议 | 在书籍的 *About* 标签页中选择另一个，或删除该书 |
| 已删除的世界书（及其条目） | 某本书仍在使用它 | 在该书中选择另一个世界书，或将其清空 |
| 已删除的故事段落 | 它是某本书当前活动分支的最后一个段落 | 将该书切换到另一个分支，或删除该书 |
| 已删除的用户 | 另一用户的内容仍在使用其数据（例如某本书使用了其推理提供商或世界书） | 修改或删除另一用户的那本书 |

解除阻止后，请再次运行 *Analyze*。

<a id="reference-model"></a>

## 引用模型

底部的 **Reference Model** 列出了各类数据之间的所有引用及其策略。当你想了解某个对象为何被阻止时，这部分很有用：

| 策略 | 含义 |
|---|---|
| **阻止清除** | 只要有未删除的对象引用已删除的目标，该目标就会被保留。 |
| **随目标一并清除** | 引用方对象属于目标，并随目标一起删除（条目随其世界书一起删除）。 |
| **归目标所有** | 目标属于引用方对象（摘要属于其段落）。 |
| **清除时清空** | 目标被清除时，引用会被移除（子世界书、默认模型）。 |

扩展可以以自己的规则参与清理。
