# 批注

**批注**是你为某个部分中的一段文字留下的备注，例如*场景较弱*、*时间线有误*、*需要重访*。它的作用类似文字处理软件中的注释：故事正文保持干净，段落只做标记，备注则附在旁边。备注也可能来自模型，或来自检查故事的[扩展](../extensions/index.md)。

批注**只供作者查看**。除非你为该条备注作出设定，否则它不会发送给模型，参见[把备注交给模型](#giving-a-note-to-the-model)。

<a id="what-an-annotation-is"></a>

## 什么是批注

| | |
|---|---|
| **段落** | 备注所针对的文字，或**整个部分**。 |
| **备注** | 你想记住的内容。 |
| **类型** | 你可以选填的一个词（*连贯性*、*文风*、*节奏*...）。 |
| **来源** | 由谁写的：你本人、模型（*AI*）、*代理*或*扩展*。正文中的标记对每种来源使用不同颜色。 |
| **状态** | *打开*、*已解决*、*已忽略*或*孤立*。只有打开状态的备注会在正文中做标记。 |

一个部分可以有任意数量的批注，包括段落互相重叠的批注。

<a id="making-an-annotation"></a>

## 添加批注

**针对一段文字。** 在部分的正文中选中文字（文字可以带格式，选区不必十分精确），然后**右键单击**（在手机上为长按），选择 **Annotate selection**，或按其[快捷键](story-editor.md#keyboard-shortcuts)（`a`）。窗口会显示该段落；填写备注、可选的类型，并决定是否把备注交给模型，然后点击 **Save**。部分的菜单（☰）中没有此项：打开菜单会取消选区。右键菜单中有 **Annotate selection**、[**Redraft selection**](story-editor.md#redrafting-only-a-passage) 和 **Copy**，它取代了浏览器在部分正文上的菜单，因此也包含 **Copy**。部分处于编辑状态时，使用编辑器中的选区，并且会先保存该次编辑。

**针对整个部分。** 在部分的菜单中选择 **Annotate part**。

**借助模型。** 选择 **Annotate with AI**，参见[下文](#letting-a-model-annotate)。

**通过命令行**（以及供扩展使用）：[`/create-annotation`](../commands/index.md#annotations)。

![新建批注的窗口](../../images/annotation-dialog.png)

<a id="reading-the-annotations"></a>

## 阅读批注

带有打开状态备注的段落会以**波浪线**标示，颜色取决于备注的作者：蓝色为你，橙色为模型，绿色为代理，红色为扩展。位于另一条备注内部的备注，下划线位置更低，因此两者都能看到。

![打开标记处的备注，显示带下划线的段落](../../images/annotation-popover.png)

- **点击带下划线的文字**，可查看覆盖该位置的所有备注（段落重叠时全部显示）。它们会在文字旁打开；在手机上请点按该段落。
- 部分标题处带数字的**语音气泡**会统计该部分中需要查看的备注数量。点击即可查看全部备注，包括针对整个部分的备注，以及已失去段落的备注。
- 在**页边**（故事的齿轮菜单中的 **Annotations in the margin**；仅限桌面端，并会记住你的设置）中，每个部分的备注会按其段落的先后顺序排成一列，位于正文左侧，而不再显示在弹出框中。鼠标指向的备注与其带下划线的段落会同时高亮；点击段落会让对应备注显示在视野内。这些备注与其他位置的是同一批（可以解决、编辑等）；已解决和已忽略的备注不会在此显示，因为它们也不带下划线。
- **Annotations** 标签页列出整本书的备注，按故事中的顺序分组到各部分，并带有筛选器（*需要查看*、*已关闭*、*全部*）。**Show in story**（或部分的编号）会带你跳转到该部分。

![部分页边中的备注](../../images/annotations-margin.png)

![Annotations 标签页](../../images/annotations-tab.png)

每条备注会显示其作者、类型、状态、段落、备注内容，以及以下操作：

| | |
|---|---|
| ✓ **Resolve** | 问题已处理。备注离开正文，但仍保留在列表中。 |
| ✗ **Dismiss** | 备注不值得处理。效果同上。 |
| ↶ **Reopen** | 将已关闭的备注重新打开。 |
| ✎ **Edit** | 修改备注内容和类型。 |
| 🗑 **Delete** | 删除备注；可从[回收站](../trash.md)中恢复。 |
| **Give to the model with the part** | 见下文。 |
| **Attach to selection** | 用于没有段落的备注：先在部分中选中文字，再点击它。 |

<a id="annotations-follow-the-text"></a>

## 批注跟随文字移动

编辑时无需关心备注的位置。Marginalia 会让每条备注的段落与其原本所指的文字保持对应：

- 在段落**之前**添加或删除文字，段落会随之移动；
- 在段落**内部**进行编辑，段落会相应变长或变短；
- 你在段落**最开头或最末尾**输入的文字，不属于该段落；
- 修正只有一个词的段落中的错别字，备注仍保留在该词上。

当段落被**删除**，或被改写到无法再找到时，备注会变为**孤立**状态。它会被保留：你可以将它附到另一段文字上（**Attach to selection**），也可以忽略或删除它。如果你恢复了这些文字（撤销），备注会重新找到它的段落。

当某个部分被**重新生成**时，文字已是新的，备注会根据它所引用的文字重新寻找段落；原文字已不存在的备注则变为孤立。当两个部分被[合并](story-editor.md#merging-a-part-into-the-previous-one)时，后面那个部分的备注会移到合并后的部分。部分的**分支**会复制其备注。备注也属于[备份](backups.md)的内容，包括书籍的副本以及备份的导出文件。
<a id="letting-a-model-annotate"></a>

## 让模型批注

各部分菜单中的 **用 AI 批注** 会请模型审阅该部分。你说明要查找什么（*标出连贯性错误*、
*对话乏力*、*与设定矛盾*；留空则使用本书、其文件夹或你的设置中
[预先设定](prompts.md#annotate-prompt)的内容，否则使用提示词的任务），选择模型，然后点击 **批注**。

模型读取该部分的方式与[重写](story-editor.md#redrafting-a-part)相同：该部分、它之前的故事（较早的故事以[摘要](summaries.md)形式提供）、故事之后能放入的部分、本书的设定和风格，以及该部分已有的批注，以免重复。模型从不给出位置：它**引用**原文段落，由 Marginalia 在正文中找到该引文。找不到的引文并不会丢失：该批注会作为关于整个部分的批注提出，并标记为*未在正文中找到*。

**在你接受之前，不会向书中添加任何内容。** 模型提出的批注会逐条列出，每条前都有一个复选框（默认全部勾选）；取消你不想要的，然后选择 **添加所选批注**。

在电脑上，该窗口不会阻塞故事的阅读；模型工作时，窗口可以折叠到页面角落，参见[在窗口旁边工作](story-editor.md#working-beside-the-redraft-and-annotation-windows)。

| 选项 | |
|---|---|
| **模型** | 进行审阅的模型。留空则使用你[设置](../account.md#general-settings)中的 **批注默认模型**，否则使用本书的模型。审阅属于分析工作，因此它往往不是写作正文的那个模型。 |
| **回答格式** | *自动*（模型能以 JSON 作答时使用结构化格式）、*结构化（JSON）*、*文本块*（适用于不太遵守格式的模型），或 *自由评论，然后提取*（模型先写出一段自由的评论，再由第二个模型——通常是更便宜的模型——将其转换为批注；请在 **用于提取批注的模型** 中选择它）。 |

![模型为某部分提出的批注](../../images/annotate-ai-proposals.png)

**一段范围内的部分（批量）。** 各部分菜单中的 **用 AI 批注** 只审阅该部分。若要审阅多个部分，请打开故事的设置菜单（⚙），选择 **用 AI 批注一段范围内的部分**（手机上同样可用）。这是同一个窗口，可选择 **起始部分** 和 **结束部分**（两者都是必填项，在选定之前 **批注** 不可用；谁前谁后无关紧要；只列出有正文的部分）。**批注** 随后会依次审阅范围内的各个部分，使用相同的指令、回答格式和模型，每个部分连同其周围的故事一起读取，如同单独的一个部分。批注会列在其所属部分的编号之下，全部勾选，**添加所选批注** 会把每条批注添加到其各自的部分。**停止** 会中止正在处理的部分，且不再开始新的部分；此前已找到的内容保留在列表中。若某部分的回答无法读取，或超出模型的上下文容量，则该部分会被跳过（窗口会说明原因），运行继续；模型出错则会结束整个运行。每个部分都是一次对模型的请求，因此范围越长，花费的请求（和 token）也越多。

![批注一段范围内的部分：批注列在其所属部分的编号之下](../../images/annotate-ai-batch.png)

**来自扩展的事实。** 某个[扩展](../extensions/index.md)若掌握的故事信息比其正文所说的更多，可以把这些信息提供给审阅者，审阅者随后会把与之矛盾的段落标为连贯性错误。[知识追踪器](../extensions/knowledge-tracker.md#annotating-with-what-the-characters-know)便是如此：它会告诉模型，该部分开始时每个被追踪的角色已经知道什么，因此某个角色使用了他从未听说过的名字，就会被记录下来。这些事实已写入内置的[批注提示词](prompts.md#annotate-prompt)中（你自己编写的提示词必须使用 `{%{{{facts}}}%}`）；若没有这类扩展，提示词保持原样。

若回答无法读取，Marginalia 会再问一次；若仍无法读取，则会显示模型的回答，以免工作丢失。提示词即[批注提示词](prompts.md#annotate-prompt)。

<a id="annotating-every-new-part-automatically"></a>

### 自动批注每个新部分

故事的设置菜单（⚙）中有 **自动批注**（手机上同样可用；打勾表示已开启）。开启后，本书会在每个部分生成之后立即审阅该部分，并可选择是否重写。这些设置随本书保存：

| 选项 | |
|---|---|
| **模型**、**协议** | 进行审阅的模型。留空则使用本书的模型（而不是你设置中的 **批注默认模型**，后者是你自己打开的窗口默认使用的模型）。 |
| **查找内容** | 指令，与 **用 AI 批注** 相同。留空则使用本书继承的内容（参见[批注提示词](prompts.md#annotate-prompt)），否则使用提示词的任务；若你在此留空开始，该字段随后会显示所使用的文本。 |
| **自动批注每个生成的部分** | 开启此项。某个部分生成之后（新部分、换一版或重新生成；被停止或失败的不算），模型会**立即**审阅它，无需窗口；[运行面板](story-editor.md#the-panel-of-the-runs)会将其显示为[该部分之后步骤](story-editor.md#what-follows-a-generated-part)中的一步。 |
| **不经询问直接添加批注** | 模型完成后，它找到的批注会被直接添加。不开启此项时，批注窗口会打开并列出提议（在你生成时所在的页面中；在任何页面中可从运行面板的 **审阅** 打开），等待你选择，与你自己启动时一样。 |
| **然后重写该部分以处理批注** | 仅在上一项开启时可用。添加批注之后，模型会结合该部分未解决的批注（不附加其他指令）[重写](story-editor.md#redrafting-a-part)该部分。它使用本书的模型来写作，且不改动摘要：该部分是新的，没有摘要描述它。若模型未找到任何问题，便无需重写。 |
| **不经询问直接应用重写** | 仅在重写开启时可用。模型完成后，重写稿会替换该部分的正文，所处理的批注标记为已解决。若未开启此项，或你在模型写作期间修改了该部分，则重写窗口会打开并显示结果，等待你处理。 |

等待你处理的重写窗口有两个标签页：**重写后的文本**（正文、其推理过程，以及与该部分原文的差异）和 **原文及批注**（该部分的原文，其中未解决批注的段落以故事中的方式标记，批注列在其下方；点击标记可跳转到对应批注，或将指针移到任一处即可同时高亮两者）。查看原文，可以了解模型被要求处理的内容，然后修改文本或应用它。

![自动批注的设置](../../images/annotate-auto.png)

**关闭一个等待你处理的窗口，或在面板中点击停止，会结束该部分之后的步骤。** 不会再添加或应用任何内容，之后的步骤（如翻译、音频）也不会运行；面板的提示会列出它们，以便你手动完成。已经添加或应用的内容保留不变。重写运行期间无法生成新部分（否则它会从旧文本继续）；而制作批注期间则可以生成。

每个生成的部分至少会多产生一次对模型的请求（若含重写则为两次）。若你使用的本地服务器只在缓存中保留一个提示词，审阅会取代缓存中的故事，下一次生成就必须重新读取故事：请为审阅选择另一个 **模型**，或使用第二台服务器。

<a id="giving-a-note-to-the-model"></a>

## 把批注交给模型

在某条批注上勾选 **随部分一同交给模型**，它也会成为给模型的批注。这些批注所在部分若在提示词之内，其批注会以 `{%{{{annotations}}}%}` 的形式放入主模板（内置模板有一个名为 *作者对故事的批注* 的区块；你自己的模板必须使用该变量）。只有勾选了此项的**未解决**批注会被提供，且只提供那些能放入提示词的部分。请用它来记录模型在续写时应当牢记的内容（*这个角色在藏着那封信*），而不要用于编辑性的备注。

<a id="redrafting-to-address-the-notes"></a>

## 重写以处理批注

当某个部分有未解决的批注时，[重写](story-editor.md#redrafting-a-part)窗口会出现复选框 **处理该部分未解决的批注**。勾选后，模型会同时获得这些批注（段落和批注内容）以及你的指令，并据此改写该部分以处理它们；当你 **应用** 重写稿时，这些批注会被标记为已解决。在[选段重写](story-editor.md#redrafting-only-a-passage)中，只会提供那些段落与所选内容有重叠的批注。
<a id="commands"></a>

## 命令

[`/list-annotations`](../commands/index.md#annotations)、`/get-annotation`、`/create-annotation`、`/update-annotation`、
`/resolve-annotation`、`/reattach-annotation` 和 `/delete-annotation` 可以在命令行中处理批注。
扩展也可以使用相同的命令。[`/generate-annotation <part>`](../commands/index.md#annotations) 是作为命令使用的 **Annotate with AI**：模型会结合全书的模型、指令、回答格式和提示词来审阅该部分（当智能体开启 *Write the book with the model of the agent* 时，智能体使用它自己的模型；`profile` 则会选择智能体的另一个模型配置）。它找到的每条批注都会立即添加，因为此时没有人来逐条挑选。这是对模型的一次请求，因此它单独运行，并会消耗 token。

<a id="annotations-and-agents"></a>

## 批注与智能体

[智能体](../agents.md)使用相同的命令读写批注：它可以为整本书添加批注（*continuity*、*style* 等），处理已解决的批注，也可以编辑或删除批注。它处理的是书稿的一个副本，因此在你[审阅结果](../agents.md#reviewing-the-result)之前，任何改动都不会进入你的批注：

- 智能体新增的批注显示为一行 **Annotation - Added**；它解决、驳回或改写过的批注显示为 **Changed**（其字段包括批注内容、类型、状态和 *give to the model*，每个字段都有各自的 **Take this change** 复选框）；它删除的批注显示为 **Deleted**。智能体删除的某个部分上的批注会随该部分一起消失，因此不会单独列出。
- 该行会说明批注位于哪个部分（`3: ` 以及批注内容的开头部分）。**Show in the copy** 会在智能体的副本中打开该部分。针对智能体所写部分的批注需要依赖该部分：勾选批注时，该部分也会被勾选。
- 列表上方的 **Only annotations** 只勾选批注本身。当部分的文本相同时，被采纳批注的原文定位保持不变；当你采用智能体对该部分的新文本，或你自己的文本有所不同时，批注会在你书稿的文本中重新查找它的原文；如果找不到，它就会变成针对整个部分的批注。
- 在智能体暂停期间你添加的批注，会在它恢复运行时进入其副本中（你已解决的批注也会在那里被标记为已解决），这样它就能知道这些变化；如果你和智能体都修改了同一条批注，则会像其他任何冲突一样处理。
