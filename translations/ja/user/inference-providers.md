# 推論プロバイダー

推論プロバイダーは、モデルへの接続です。APIのアドレス、APIキー、モデルとその上限値が含まれます。どの本でも必ず1つのプロバイダーを使います。複数登録することもでき、たとえば物語には大規模なクラウドモデルを、実験には小規模なローカルモデルを使うといったように、本ごとにいつでも切り替えられます。

プロバイダーはあなたのアカウントに属します。他のユーザーには、プロバイダーもそのAPIキーも見えません。APIキーは暗号化して保存されます（[データフォルダー](administration/index.md#the-data-folder)を参照してください）。

プロバイダーを追加するには、**独自のモデルの作成**の権限が必要です。この権限は管理者が付与します（管理者は常にこの権限を持っています。[権限](administration/permissions.md)を参照してください）。この権限がない場合は、管理者があなたと[共有](#shared-providers)したプロバイダーのみを使えます。その場合、**推論プロバイダーを追加**ボタンは表示されません。

![推論プロバイダータブ](../images/inference-providers-list.png)

<a id="supported-apis"></a>

## 対応しているAPI

Marginaliaは、**OpenAI Chat Completions**インターフェース（`/v1/chat/completions`、ストリーミング対応）を実装しているAPIであれば、どれでも利用できます。ほとんどのサービスやローカルサーバーがこれに対応しています。

| サービス | OpenAI URL |
|---|---|
| OpenAI | `https://api.openai.com/v1` |
| OpenRouter | `https://openrouter.ai/api/v1` |
| LiteLLM proxy | `http://localhost:4000/v1` |
| llama.cpp (`llama-server`) | `http://localhost:8080/v1` |
| LM Studio | `http://localhost:1234/v1` |
| Ollama | `http://localhost:11434/v1` |
| vLLM | `http://localhost:8000/v1` |

ポート番号は各サーバーの既定値です。実際にサーバーが使用しているポートを指定してください。

!!!warning ポート 8080
Docker版のMarginaliaもポート8080を使用します。同じマシンでllama.cppを動かす場合は、別のポートで起動してください（`llama-server --port 8081`）。
!!!

!!!
[Docker版](getting-started/docker-server.md)では、`localhost`はMarginaliaのコンテナを指します。同じマシン上のモデルサーバーには`http://host.docker.internal:<port>/v1`を使ってください。[同じマシン上のモデル](getting-started/docker-server.md#models-on-the-same-machine)を参照してください。
!!!
<a id="adding-a-provider"></a>

## プロバイダーを追加する

**推論プロバイダー**タブを開き、**推論プロバイダーを追加**をクリックします。既存のプロバイダーは鉛筆のボタンで編集し、ゴミ箱のボタンで削除します。二枚重ねのシートのボタン（複製）を押すと、プロバイダーのコピーを作成できます。名前は確認画面で指定し、元の名前に *(Copy)* が付いた名前が初期値になります。コピーは同じアドレス、モデル、**APIキー**（拡張機能の設定の場合はその設定）、推論の設定、トークン上限、パラメータを引き継ぐので、同じサービスの別のモデルを使いたいときは、名前を付けてクリックするだけで済みます。コピーは共有されず、独自の上限や使用量も持ちません。複製できるのは自分のプロバイダーだけです（管理者が共有しているプロバイダーは、そのAPIキーを見てはいけないため複製できません）。また、プロバイダーを作成する権限があるときにだけ複製できます。

ダイアログの上部には次の項目があります。

| 項目 | |
|---|---|
| **名前** | 本を書くときにモデルを選ぶ際に表示される、プロバイダーの名前です。例えば `OpenRouter - Claude Sonnet` のように、モデル名を含めてください。 |
| **種類** | APIの種類です。**OpenAI 互換**、または[拡張機能](extensions/index.md)が提供するプロバイダー用の**拡張機能**があります。**拡張機能**は、対応する拡張機能が読み込まれているときだけ選べます（例：[Google Gemini](extensions/google-genai.md) や [Anthropic Claude](extensions/anthropic.md)）。種類は、プロバイダーを作成した後は変更できません。 |
| **プロバイダー** | 種類が**拡張機能**の場合のみ表示されます。このプロバイダーがどの拡張機能のものかを指定します。その拡張機能固有の設定は、*種類別設定*タブに表示されます。 |

<a id="per-type-settings"></a>

### 種類別設定

![モデル一覧を読み込んだ状態の種類別設定](../images/inference-provider.png)

このタブはダイアログより高さがあり、スクロールして操作します。下の方の項目は次のとおりです。

![タイムアウト、再試行回数、追加パラメータと接続テスト](../images/inference-provider-2.png)

| 項目 | |
|---|---|
| **OpenAI URL（/v1 で終わる）** | APIのベースとなるアドレスです。[上の表](#supported-apis)を参照してください。`/chat/completions` は付けないでください。 |
| **APIキー** | サービスのキーです。ローカルサーバーは通常キーを確認しないので、この欄は空のままにしてください。その場合、Marginalia はプレースホルダーの `none` を送信します。 |
| **モデル** | 使用するモデルです。**更新**をクリックするとAPIからモデル一覧を読み込みます。または、モデルのIDを直接入力することもできます（例：OpenRouter では `anthropic/claude-sonnet-4.5`）。 |
| **タイムアウト（秒）** | APIの応答を待つ時間です。応答が書き始められた後は、次の文章が届くまでの待ち時間になります。初期値は 300 です。推論モデルは、最初の文章が出るまで数分かかることがあります。この時間の間に何も届かないリクエストは、タイムアウトのメッセージで失敗します（モデルの思考も文章として数えられるので、考え続けているモデルが途中で打ち切られることはありません）。変更は次のリクエストから適用されます。エージェントが作業中の場合も同様です。 |
| **再試行回数** | APIがレート制限（429）やサーバーエラー（5xx）を返したとき、または接続できなかったときに、リクエストを繰り返す回数です。試行の間隔は徐々に長くなり、APIの `Retry-After` ヘッダーは尊重されます。初期値は 2 です。0 にすると再試行しません。再試行されるのはリクエストの開始部分だけで、すでに届いた文章が二重に書き込まれることはありません。 |
| **トークナイザー** | このプロバイダーで、Marginalia が文章のトークン数をどのように数えるかを指定します。**自動**（初期値）は、サーバーのトークナイザーのエンドポイント（OpenAI、llama.cpp、LiteLLM）を順番に試し、最初に応答したものを使います。どれも応答しない場合は、ローカルの推定値を使います。一つだけを選ぶと、そのエンドポイントだけを使います。**LOCAL_TOKKIT** を選ぶと、サーバーを呼び出さずにローカルで推定します（数えるためにサーバーが別のモデルを読み込んでしまう場合に便利です）。プラグインのトークナイザーもここに表示されます。プラグインには、アドレス、モデル、文章が渡されます。APIキーは渡されません。また、選んだ場合にだけ使われます。**トークナイザーをテスト**を押すと、サンプルの文章を使って、このプロバイダーが試す各トークナイザーで数え、それぞれの応答を表示します。プロバイダーを新しく作成すると、自分で選ぶまでは、アドレスに合うプラグインのトークナイザーが初期選択されます。 |
| **思考を送り返す** | モデルが自分の思考を次のリクエストで受け取るかどうかを指定します。詳しくは[思考を送り返す](#send-the-thinking-back)を参照してください。OpenAI 互換のプロバイダーにのみ適用されます。AnthropicとGoogleのプロバイダーは、各APIに必要なものを自動的に送信します。 |
| **追加パラメータ** | このプロバイダーへのすべてのリクエストに追加するフィールドを含む JSON オブジェクトです。例えば、ローカルサーバー向けの `{"top_k": 40, "min_p": 0.05}`、または OpenRouter 向けの `{"provider": {"order": ["anthropic"]}}` などを指定します。ここで設定した値は、[プロトコル](protocols.md)（例：`temperature`）や応答の上限（`max_completion_tokens`）から来る同じ設定より優先されます。有効な JSON オブジェクトであるか、空にしてください。 |

既存のプロバイダーを編集するとき、APIキーは再表示されません。**APIキーをリセット**をクリックして新しいキーを入力しない限り、現在の値がそのまま保持されます。

**更新**は、フォームに入力された URL とキーを使ってAPIにモデル一覧を問い合わせます（`/v1/models`）。*モデル一覧の取得に失敗しました*というエラーで失敗した場合は、URL（`/v1` で終わる必要があります）、キー、サーバーが起動しているかを確認してください。モデル一覧を提供しないサービスもあります。その場合は、モデルのIDを直接入力してください。

**接続テスト**は、保存せずにフォームの値を確認します。APIにモデル一覧を問い合わせ、その後、選択された**モデル**に対して1トークンだけの応答を求めます。再試行は行いません。成功メッセージが表示されれば、URL、キー、モデルが正しく連携して動作しています。失敗した場合は原因が表示されます（[エラーメッセージ](#error-messages)を参照してください）。モデル一覧を提供しないサービスもあります。その場合、テストは1トークンの応答だけを確認します。

<a id="general-settings"></a>

### 一般設定

![推論プロバイダーの一般設定](../images/inference-provider-general.png)

| 項目 | |
|---|---|
| **最大コンテキストサイズ** | 必須です。プロンプトと応答を合わせて、モデルが受け付けるトークンの合計数です。 |
| **最大応答トークン数** | 必須です。モデルが書く応答の最大長です。API には `max_completion_tokens` として送信され、この分のコンテキストは応答用に空けられます。*最大コンテキストサイズ*より小さい値にしてください。 |
| **接続数** | このモデルに同時に送ることができるリクエストの数です。すべてのユーザー、すべての種類（自分の生成、補助的な問い合わせ、翻訳、注釈、[エージェント](agents.md#one-model-several-agents)、プラグイン）のリクエストを合わせた数です。それ以外のリクエストは、来た順番に待ちます。待機中の生成には *このリクエストの前に N 件のリクエストがあるためモデルを待っています* と表示され、**停止**を押すと待ち行列から外れます。初期値の **1** は、一つのスロット（GPU 一枚）しかないローカルサーバー向けです。同時に複数のリクエストに応答できるクラウドのモデルでは、より大きな値にすることで、生成と並行して補助的な問い合わせを実行できます。 |
| **GPU ロック** | 管理者が [GPU](administration/gpus.md) を設定している場合にのみ表示されます。このモデルが動作する GPU のロックです。そのカードが他のモデルや画像・音声のサーバーと共有されている場合に使用します。この場合、すべてのリクエストは GPU 上での順番を待ち（前にあるリクエストの数を数えて）、GPU が別のものを保持している場合は、それを解放してからロックの手順でこのモデルを読み込みます。空欄の場合、ロックは使われません。 |
| **ロア画像を送る** | 文章の生成で使われる[ロアブックのエントリーの画像](lorebooks/lorebooks.md#editing-in-full-screen)を、テキストと一緒に送信します。初期値はオフです。画像を受け付けるモデルでのみオンにしてください。画像に対応していないモデルはリクエストを拒否し、そのターンは失敗します。ロアブロック内のエントリーの画像は、システムプロンプトの直後に、専用のメッセージとして送られます（モデルからの短い応答付き）。それ以外のエントリーの画像は、あなたのプロンプトと一緒に送られます。 |
| **画像をシステムメッセージに入れる** | （OpenAI 互換で、*ロア画像を送る*がオンの場合）ロアブロックの画像を、ロアのテキストと並べてシステムメッセージ自体に入れます。画像をそこで受け付けるサーバーとチャットテンプレートでのみ使用してください。多くの場合は対応していないため、リクエストが失敗します。 |
| **ジェイルブレイクが必要**、**ジェイルブレイクプロンプト** | 一部の内容の執筆を拒否するモデルのための追加プロンプトです。チェックを入れると、ジェイルブレイクプロンプトがプロンプトの先頭に配置されます。 |
| **推論（リーズニング）を有効にする**、**推論の強度** | 推論（「思考」）モデル用です。詳しくは[推論モデル](#reasoning-models)を参照してください。 |

Marginalia は、**最大応答トークン数**分のコンテキストを応答用に空けておき、残りをプロンプトで埋めます。テンプレート、[ロアブック](lorebooks/index.md)のエントリー、[要約](books/summaries.md)はトークン数に含まれ、収まらない古い部分の物語は除外されます。コンテキストが 32 000 トークンで、応答の上限が 2 000 トークンの場合、プロンプトには 30 000 トークンが割り当てられます。

**最大コンテキストサイズ**は、サービスのドキュメントに記載された値を使い、それより少し小さく設定してください。トークン数は必ずしも正確に数えられるとは限らず、実際の上限を超えたリクエストは失敗します。一部の本では、[プロトコル](protocols.md)によってこの両方の上限を下げることができますが、上げることはできません。
<a id="error-messages"></a>

## エラーメッセージ

APIがリクエストを拒否した場合、Marginaliaは内部エラーを表示する代わりに、何を修正すればよいかを伝え、その後にAPIそのものが返したメッセージを表示します。

![利用者に表示されるプロバイダーのエラー](../images/error-dialog.png)

| メッセージ | 原因 |
|---|---|
| *プロバイダーが APIキー を拒否しました。* | **APIキー** が誤っているか、期限切れか、未入力です。 |
| *この APIキー では、このモデルまたはエンドポイントを利用できません。* | キーは有効ですが、そのモデルへのアクセス権がありません。 |
| *プロバイダーは設定されたモデルを認識していません。* | **モデル** が誤っています。**更新** を使うと、APIが認識しているモデル名を確認できます。 |
| *設定された URL で何も見つかりませんでした。* | **OpenAI URL** が誤っています。通常は `/v1` で終わります。 |
| *プロンプトがモデルのコンテキストに収まりません。* | **最大コンテキストサイズ** が、モデルが実際に受け付ける値より大きくなっています。値を下げてください。 |
| *プロバイダーがリクエストを制限しています。* | 再試行後もレート制限、または利用枠の上限に達しています。 |
| *プロバイダーがリクエストを処理できませんでした。* | サービス側に問題があります(5xx)。再試行後も続いています。 |
| *プロバイダーが時間内に応答しませんでした。* | **タイムアウト（秒）** を増やすか、サーバーの状態を確認してください。 |
| *プロバイダーに接続できません。* | サーバーが起動していない、または Marginalia から到達できないか、URL に誤りがあります。 |
| *プロバイダーがリクエストを拒否しました。* | その他の拒否です。多くの場合、**追加パラメータ** の未対応フィールド、またはモデルが対応していない推論が原因です。 |

<a id="warning-before-sending"></a>

## 送信前の警告

Marginaliaは、コンテキストを **最大コンテキストサイズ** から **最大応答トークン数** を引いた分までしか埋めません。完成したプロンプトがそれでもその値を超える場合（拡張機能がテキストを追加した場合や、トークン数の見積もりがずれた場合など）、リクエストを送信する前に、推定サイズを示す警告が表示されます。リクエストは送信されますが、APIに拒否されるか、プロンプトが切り詰められる可能性があります。

![プロンプトが収まらない可能性があるという警告](../images/context-warning.png)

<a id="reasoning-models"></a>

## 推論モデル

推論モデルは、回答する前に考えます。**推論（リーズニング）を有効にする** をチェックすると、Marginaliaは選択した **推論の強度**（*なし*、*低*、*中* または *高*）を `reasoning_effort` としてAPIに送信します。強度を高くすると、一般に計画された文章になりますが、応答は遅く、費用も高くなります。このパラメータをすべてのAPIがサポートしているわけではありません。推論を有効にした状態でリクエストが失敗する場合は、オフにしてください。

モデルが推論内容を返す場合（サーバーによって `reasoning_content` または `reasoning` として）、それは生成された部分の上に **推論を表示** の下で表示されます。推論は物語の一部ではなく、下の **思考を送り返す** を設定しない限り、モデルに送り返されることはありません。

<a id="send-the-thinking-back"></a>

### 思考を送り返す

**思考を送り返す**（OpenAI互換プロバイダーの *種類別設定* 内）は、モデルの思考を次のリクエストで、そのモデルの以前のメッセージの `reasoning_content` として送り返すかどうかを決めます。

| 値 | |
|---|---|
| **なし**（既定） | 送り返しません。ほとんどのモデルやサーバー、また未知のフィールドを拒否するAPIに適しています。 |
| **ツール呼び出しの間** | 1回の応答でツール呼び出しが続いている間だけ送り返します。ツールを呼び出したモデルは、その結果とともに自身の思考を受け取ります。新しいメッセージを送ると、古い思考は引き継がれません。Googleが Gemma 4 に求めている設定です（*関数呼び出しの間では思考を削除してはならない*が、ターンの間では削除される）。 |
| **常に** | 思考を持つ以前の応答についても送り返します。チャットがそれを保持している場合に適用されます（アークアウトラインのプロットウィザードがこれに当たります）。Gemma 4 のサーバーのように、古い思考を自分で捨てるテンプレートのサーバーでは無視されます。 |

この設定は、ツールループ（プロットウィザードや、ツールを使う生成機能）と、エージェントに適用されます。エージェントは、1ターンのツール呼び出しが続いている間、以前のラウンドの思考を受け取ります（思考はコンソール内のメッセージと一緒に保持され、保存されたメッセージには含まれません）。サーバーがこのフィールドを受け付ける必要があります。llama.cpp は受け付けます（`reasoning` ではなく `reasoning_content` を読みます）。LiteLLM の背後にある場合も同様です。未知のメッセージフィールドを拒否するプロバイダーではエラーになるため、その場合は *なし* のままにしてください。

![生成された部分の推論](../images/reasoning-view.png)

推論は応答トークンに含まれます。推論モデルでは **最大応答トークン数** を大きくしてください。そうしないと、長い推論のあとに本文が途中で切れることがあります。

<a id="token-counting"></a>

## トークン数の計算

Marginaliaは、物語のどの部分がプロンプトに収まるかを決めるためにトークンを数えます。可能な場合はプロバイダーに問い合わせ、次の方法を順番に試します。

1. OpenAI のトークン数計算エンドポイント（`/v1/responses/input_tokens`）、
2. llama.cpp の `/tokenize` エンドポイント、
3. LiteLLM の `/tokenize` エンドポイント、
4. LiteLLM の `/v1/messages/count_tokens` エンドポイント（Anthropic のモデル用）、
5. OpenAI のトークナイザーによるローカルの推定。

最初に動作した方法が、以後ずっと使われます。ローカルの推定は多くのモデルでほぼ正確ですが、完全に一致するわけではありません。これも、**最大コンテキストサイズ** を実際の上限より少し低く保つ理由の一つです。*拡張機能* の種類のプロバイダーは、それぞれの拡張機能の方法で数えます。[Google Gemini](extensions/google-genai.md) と [Anthropic Claude](extensions/anthropic.md) のプロバイダーは、トークン数の計算をプロバイダーに依頼します。

<a id="prompt-cache"></a>

## プロンプトキャッシュ

Marginaliaが作業の種類（新しい部分の生成、注釈、書き直し、要約など）ごとに行うリクエストには、すべてヘッダー `X-Session-ID` が付きます。これは、同じユーザーと同じ種類の作業に対して常に同じ値になるハッシュです。プロンプトキャッシュを保持しているサーバーやプロキシは、これを使って同じ種類の前回のリクエストのキャッシュを見つけられます。これを知らないサーバーは無視します。ディスクに保存される llama.cpp のスロットを1つ使った例については、[プロンプトキャッシュとセッションID](prompt-cache.md) を参照してください。

<a id="shared-providers"></a>

## 共有プロバイダー

複数のユーザーがいるインストール環境では、管理者がプロバイダーを **共有** できます。プロバイダーのダイアログで **全ユーザーと共有** にチェックを入れてください（このチェックボックスは管理者にのみ表示されます）。すると、すべてのユーザーの書籍の **モデル** の一覧と、各自の **推論プロバイダー** タブにそのプロバイダーが現れ、*共有* が **はい** と表示されます。ユーザーはそれを使えますが、開いて、アドレスや APIキー を見たり、変更したり、削除したりすることはできません。できるのは所有者だけです。共有プロバイダーを参照している書籍、バックアップ、復元は、それを見られるすべてのユーザーにとって引き続き機能します。

![一般ユーザーの推論プロバイダータブにある共有プロバイダー](../images/provider-shared-user.png)

プロバイダーを共有すると、他のユーザーは所有者の利用枠をそのサービスで消費できます。ユーザーが独自のプロバイダーを追加できないようにし、共有されたものだけを使えるようにするには、[ユーザーとプロバイダー](administration/users.md#users-and-providers) を参照してください。
<a id="limits-of-shared-providers"></a>

## 共有プロバイダーの制限

管理者は、共有プロバイダーごとに各ユーザーが行える操作を制限できます。**推論プロバイダー**タブで、共有プロバイダーを所有する管理者は、その行にある**制限**ボタン（錠前のアイコンが付いたユーザー）を使えます。これを押すと、設定されている制限の一覧が表になって開きます。**制限を追加**で新しい制限を作成します。ユーザーと制限の種類を選びます。

![共有プロバイダーの制限](../images/provider-limits.png)

| 制限の種類 | 意味 |
|---|---|
| 無制限 | 制限なし（制限がない場合と同じ）。 |
| トークン制限 | ユーザーは、一定期間につき指定された数までのトークンを使えます。 |
| 利用不可 | ユーザーはそのプロバイダーを使えません。そこへリクエストを送ろうとする操作はすべて失敗します。 |

**トークン制限**には**リセット**（毎日、月曜始まりの毎週、毎月のいずれか。期間はサーバーのタイムゾーンでの暦上の期間です）と、3つの上限があります。各上限は空欄にすると制限なしになります。上限は、**送信**されたトークン数、**生成**されたトークン数、そして両方を合計した**合計**です。どれか一つでも先に上限に達すると、次のリセットまでユーザーは使えなくなります。3つすべてを設定する場合は、送信と生成の上限の合計が合計の上限以上である必要があります。そうでなければ、ダイアログは保存を受け付けません（合計の上限に到達できなくなるためです）。例えば、合計10万、送信10万、生成2万は問題ありません。合計10万、送信2万、生成1万は保存できません。

![制限の追加](../images/provider-limit-edit.png)

タイマーでリセットされることはありません。ユーザーが新しい期間に初めてプロバイダーを使うとき（または自分の制限を確認するとき）に、使用済みトークン数が0から始まります。リクエストを送る前にサイズはわかるので、プロンプトによって**送信**または**合計**の上限を超えてしまうリクエストは拒否されます（プロンプトの量は Marginalia 独自の見積もりで測るため、サービス側の数え方とわずかに違うことがあります）。**生成**トークンは事前にはわからず、リクエストが終わった時点で数えられます。そのため、上限に達して初めてユーザーは止められ、最後の応答によって上限を超えることがあります。表に制限がないユーザーは制限を受けません。

生成トークンが上限を超えないようにするには、**厳格な上限**にチェックを入れます（生成トークンの制限がある場合にのみ選べます）。リクエストは、許される最大の応答分の余裕を確保します（プロバイダーの**最大応答サイズ**、またはプロトコルの値のうち小さい方）。厳格な上限では、この余裕が生成上限の残りに収まらない場合、リクエストは拒否されます。そのため、プロバイダーの応答サイズより低い厳格な上限を設定すると、すべてのリクエストが拒否されます。表とユーザーの情報には、このような制限の横に*厳格*と表示されます。厳格な上限は生成トークンにのみ適用されます。**合計**の上限は、最後の応答によって依然として超えられることがあります。

すべてのユーザーには、共有プロバイダーが自分のタブに読み取り専用の行として表示されます。共有プロバイダーの**情報**ボタン（「i」の付いた丸）を押すと、自分の制限が表示されます。内容は、この期間に使った量、制限の内容、そしていつリセットされるかです。制限に達すると、ストーリーエディター、要約、拡張機能は、リクエストを送る代わりにエラーを表示します。

![ユーザーが見る制限と、この期間の使用量](../images/provider-limit-info.png)

<a id="usage"></a>

## 使用量

**推論プロバイダー**タブには、プロバイダーごとに、あなたがそのプロバイダーで使った**送信トークン数**（プロンプト、「プリフィル」）と**生成トークン数**（応答、推論を含む）が表示されます。これはすべての本、要約、拡張機能の合計です。共有プロバイダーでは、ユーザーごとに個別の数が数えられるため、表示されるのは自分の分だけです。

管理者は、このタブに**ユーザー別の使用量**ボタンも使えます。押すと、すべてのユーザーが各プロバイダーで使った量（送信トークン数、生成トークン数、リクエスト数、最後のリクエストの時刻）の表が開きます。

![ユーザー別の使用量](../images/provider-usage.png)

表示される数値は、サービスが報告した値です。サービスが報告しない場合（または途中で停止したリクエストの場合）は、[トークン数の数え方](#token-counting)で説明しているローカルの見積もりで数えられるため、数値はおおよその値になります。テキストが一つも届く前に失敗したリクエストは数えられません。管理者が共有プロバイダーに対して[制限](#limits-of-shared-providers)を設定していない限り、これらの数値は参考情報としてのみ表示されます。

!!!
Marginalia は、サービスにトークン数を報告するよう依頼します（`stream_options` と `include_usage`）。これを変更するには、プロバイダーの**追加パラメータ**に独自の `stream_options` を入力します。例えば `{"stream_options": {"include_usage": false}}` です。これは Marginalia が送る内容を置き換えるため、ローカルの見積もりが使われます。
!!!

<a id="using-a-provider-in-a-book"></a>

## プロバイダーを本で使う

各本のモデルは、その**概要**タブの**モデル**欄で設定します。すべての新しい本で使うプロバイダーを設定するには、**設定**タブで**既定のモデル**として選びます。本のプロバイダーを変更すると、次に生成される部分から反映されます。それ以前に書かれた部分はそのままです。

<a id="troubleshooting"></a>

## トラブルシューティング

| 問題 | 確認すること |
|---|---|
| *モデル一覧のダウンロードに失敗しました。* | URL が `/v1` で終わっているか、APIキー、サーバーが起動していて Marginalia から到達できるかを確認してください。サービスがモデル一覧を提供していない場合は、モデルIDを直接入力してください。 |
| *プロバイダーが時間内に応答しませんでした。* | プロバイダーの**タイムアウト（秒）**を上げてください。推論モデルは数分かかる場合があります。 |
| *プロバイダーがリクエストを制限しています。* | 待つか、**再試行回数**を上げてください。 |
| *本にモデルが設定されていません。* | その本にはプロバイダーがありません。**概要 → モデル**で選んでください。 |
| *コンテキストの上限が足りません。* | 本文を含まないプロンプトが、コンテキストから応答トークン数を引いた量に収まりません。**最大コンテキストサイズ**（またはプロトコルの**最大コンテキストトークン数**）を上げるか、**最大返信トークン数**を下げるか、テンプレートや設定集の項目を短くしてください。 |
| 文章が途中で止まる | **最大返信トークン数**（またはプロトコルの**最大応答トークン数**）が低すぎます。特に推論モデルの場合に起こりがちです。 |
| 推論を有効にしたときに API からエラーが出る | API が `reasoning_effort` に対応していません。**推論（リーズニング）を有効にする**をオフにしてください。 |
