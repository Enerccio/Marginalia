# 주석

**주석**은 파트의 구절에 대해 작성자에게 남기는 메모입니다. 예를 들어 *약한 장면*, *시간 순서가 틀림*, *다시 검토* 같은 내용을 적습니다. 워드프로세서의 댓글과 같은 방식으로 작동합니다. 이야기 본문은 깔끔하게 유지되고, 구절에는 표시만 남으며, 메모는 그 옆에 놓입니다. 메모는 모델이나 이야기를 검사하는 [확장 기능](../extensions/index.md)에서도 만들어질 수 있습니다.

주석은 **작성자를 위한 것**입니다. 해당 메모에 대해 따로 지정하지 않는 한 모델에 전달되지 않습니다. 자세한 내용은 [메모를 모델에 전달하기](#giving-a-note-to-the-model)를 참고하세요.

<a id="what-an-annotation-is"></a>

## 주석의 구성

| | |
|---|---|
| **구절** | 메모가 가리키는 단어들, 또는 **파트 전체**. |
| **메모** | 기억해 두고 싶은 내용. |
| **유형** | 직접 고르는 선택 단어(*연속성*, *문체*, *속도*...). |
| **출처** | 누가 작성했는지: 작성자, 모델(*AI*), *에이전트* 또는 *확장 기능*. 본문의 표시는 출처마다 색이 다릅니다. |
| **상태** | *열림*, *해결됨*, *무시됨* 또는 *고아 상태*. 열린 메모만 본문에 표시됩니다. |

한 파트에는 주석을 원하는 만큼 달 수 있으며, 겹치는 구절에 달아도 됩니다.

<a id="making-an-annotation"></a>

## 주석 달기

**구절에 달기.** 파트 본문에서 단어를 선택합니다(서식이 있어도 되고, 선택 범위가 정확할 필요는 없습니다). 그런 다음 **마우스 오른쪽 버튼**을 누르고(휴대폰에서는 길게 누릅니다) **선택 영역에 주석 달기**를 고르거나, 해당 [단축키](story-editor.md#keyboard-shortcuts)(`a`)를 누릅니다. 창에 구절이 표시되면 메모, 선택 사항인 유형, 그리고 모델에 메모를 전달할지 여부를 입력한 뒤 **저장**을 누릅니다. 파트의 메뉴(☰)에는 이 항목이 없습니다. 메뉴를 열면 선택 영역이 해제되기 때문입니다. 오른쪽 클릭 메뉴에는 **선택 영역에 주석 달기**, [**선택 영역 재작성**](story-editor.md#redrafting-only-a-passage), **복사**가 있으며, 파트 텍스트에서는 브라우저의 기본 메뉴를 대체하므로 **복사**도 포함되어 있습니다. 파트를 편집하는 중이라면 편집기에서 선택한 영역이 사용되며, 먼저 편집 내용이 저장됩니다.

**파트 전체에 달기.** 파트의 메뉴에서 **파트에 주석 달기**를 선택합니다.

**모델과 함께 달기.** **AI로 주석 달기**를 선택합니다. [아래](#letting-a-model-annotate)를 참고하세요.

**명령줄에서**(그리고 확장 기능용): [`/create-annotation`](../commands/index.md#annotations).

## 주석 읽기

열린 메모가 달린 구절에는 **물결선**이 그어지며, 메모를 쓴 주체에 따라 색이 다릅니다(파란색은 작성자, 주황색은 모델, 초록색은 에이전트, 빨간색은 확장 기능). 다른 메모 안에 들어 있는 메모는 더 아래쪽에 밑줄이 그어지므로 둘 다 보입니다.

![주석이 달린 구절이 표시를 기준으로 열린 모습](../../images/annotation-popover.png)

- **밑줄 그어진 텍스트를 클릭하면** 그 지점을 덮는 메모들이 표시됩니다(구절이 겹치는 경우에는 모두 표시됩니다). 메모는 텍스트 옆에 열립니다. 휴대폰에서는 구절을 탭하면 됩니다.
- 파트 머리글의 **숫자가 있는 말풍선**은 확인이 필요한 파트 메모의 개수를 보여 줍니다. 클릭하면 파트 전체에 대한 메모와 구절을 잃은 메모까지 모두 볼 수 있습니다.
- **여백**(이야기의 톱니바퀴 메뉴, **여백의 주석**; 데스크톱 전용이며 설정이 기억됩니다)에서는 모든 파트의 메모가 팝오버 대신 본문 왼쪽의 세로 열에 구절 순서대로 나타납니다. 포인터가 올라간 메모와 밑줄 그어진 구절이 함께 강조되며, 구절을 클릭하면 해당 메모가 화면에 보이도록 이동합니다. 메모는 동일하며(해결, 편집 등 가능), 해결됨 및 무시됨 메모는 밑줄이 없으므로 여기에도 표시되지 않습니다.
- **주석** 탭에는 책 전체의 메모가 이야기 순서대로 파트별로 묶여 나타나며, 필터(*확인 필요*, *닫힘*, *전체*)를 사용할 수 있습니다. **이야기에서 보기**(또는 파트 번호)를 누르면 해당 파트로 이동합니다.

![파트 여백의 메모들](../../images/annotations-margin.png)

![주석 탭](../../images/annotations-tab.png)

각 메모에는 작성자, 유형, 상태, 구절, 메모 내용과 다음 동작이 표시됩니다.

| | |
|---|---|
| ✓ **해결** | 문제가 처리되었습니다. 메모는 본문에서 사라지고 목록에는 남습니다. |
| ✗ **무시** | 처리할 가치가 없는 메모입니다. 결과는 같습니다. |
| ↶ **다시 열기** | 닫힌 메모를 다시 엽니다. |
| ✎ **편집** | 메모 내용과 유형을 바꿉니다. |
| 🗑 **삭제** | 메모를 삭제합니다. [휴지통](../trash.md)에서 복원할 수 있습니다. |
| **파트와 함께 모델에 전달** | 아래를 참고하세요. |
| **선택 영역에 연결** | 구절이 없는 메모의 경우: 파트에서 텍스트를 선택한 다음 이 버튼을 누릅니다. |

<a id="annotations-follow-the-text"></a>

## 주석은 텍스트를 따라갑니다

편집할 때 메모의 위치를 신경 쓸 필요가 없습니다. Marginalia는 각 메모의 구절을 그 구절이 가리키던 단어와 함께 유지합니다.

- 구절 **앞**에 텍스트를 추가하거나 삭제하면 구절이 그만큼 이동합니다.
- 구절 **안**을 편집하면 구절이 길어지거나 짧아집니다.
- 구절의 **맨 앞이나 맨 뒤**에 입력한 단어는 구절 바깥에 속합니다.
- 단어 하나로 된 구절의 오타를 고쳐도 메모는 그 단어에 그대로 남습니다.

구절이 **삭제**되거나 찾을 수 없을 만큼 다시 쓰이면 메모는 **고아 상태**가 됩니다. 메모는 보존되며, 다른 구절에 연결(**선택 영역에 연결**)하거나, 무시하거나, 삭제할 수 있습니다. 삭제했던 단어를 되살리면(실행 취소) 메모는 다시 자신의 구절을 찾습니다.

파트를 **다시 생성**하면 텍스트가 새로워지므로, 메모는 인용했던 단어를 기준으로 구절을 다시 찾습니다. 인용한 단어가 사라진 메모는 고아 상태가 됩니다. 두 파트를 [병합](story-editor.md#merging-a-part-into-the-previous-one)하면 나중 파트의 메모는 병합된 파트로 옮겨집니다. 파트를 **분기**하면 메모도 함께 복사됩니다. 메모는 [백업](backups.md), 책의 사본, 백업의 내보내기 파일에도 포함됩니다.
<a id="letting-a-model-annotate"></a>

## 모델에게 주석 달기 맡기기

메뉴에서 파트의 **AI로 주석 달기**를 선택하면 모델이 해당 파트를 검토하도록 요청합니다. **살펴볼 내용**에 무엇을 확인할지 적고(*연속성 오류 표시*, *약한 대사*, *설정집과 모순*), 모델을 고른 다음 **주석 달기**를 누르세요. 살펴볼 내용을 비워 두면 책, 책이 속한 폴더, 또는 [한 번 설정해 둔](prompts.md#annotate-prompt) 내용을 사용하고, 그것도 없으면 프롬프트의 작업 지시를 사용합니다.

모델은 [재작성](story-editor.md#redrafting-a-part)과 같은 방식으로 파트를 읽습니다. 파트 자체, 그 앞의 이야기(오래된 이야기는 [요약](summaries.md)으로), 들어갈 수 있는 만큼의 뒤 이야기, 책의 설정집과 문체, 그리고 해당 파트에 이미 달린 메모를 함께 읽어 같은 내용을 되풀이하지 않도록 합니다. 모델은 위치를 지정하지 않고 해당 구절을 **인용**하며, Marginalia가 그 인용문을 본문에서 찾습니다. 본문에서 찾지 못한 인용은 버려지지 않고, *본문에서 찾을 수 없음* 표시와 함께 파트 전체에 대한 메모로 제안됩니다.

**수락하기 전까지 책에는 아무것도 추가되지 않습니다.** 모델이 제안한 메모는 각각 체크 상자가 붙은 채 목록으로 표시되며(처음에는 모두 체크되어 있음), 원하지 않는 항목은 체크를 해제한 뒤 **선택한 주석 추가**를 누르세요.

컴퓨터에서는 이 창이 이야기 작업을 막지 않으며, 모델이 작업하는 동안 페이지 구석으로 접어 둘 수도 있습니다. [창을 옆에 두고 작업하기](story-editor.md#working-beside-the-redraft-and-annotation-windows)를 참고하세요.

| 옵션 | |
|---|---|
| **모델** | 검토를 수행하는 모델입니다. 비워 두면 [설정](../account.md#general-settings)의 **주석용 기본 모델**을 쓰고, 그것도 없으면 책의 모델을 씁니다. 검토는 분석 작업이므로 문장을 쓰는 모델과 다른 모델을 고르는 경우가 많습니다. |
| **응답 형식** | *자동*(모델이 JSON으로 답할 수 있으면 구조화된 형식), *구조화 (JSON)*, *텍스트 블록*(형식을 잘 지키지 않는 모델용), *자유 비평 후 추출*(모델이 자유롭게 검토를 쓰면, 보통 더 저렴한 두 번째 모델이 이를 메모로 바꿉니다. 이 모델은 **메모를 추출하는 모델**에서 고릅니다)입니다. |

![모델이 파트에 제안한 메모](../../images/annotate-ai-proposals.png)

**여러 파트 범위 검토(일괄 처리).** 파트 메뉴의 **AI로 주석 달기**는 그 파트 하나만 검토합니다. 여러 파트를 검토하려면 이야기의 설정 메뉴(⚙)를 열고 **AI로 파트 범위에 주석 달기**를 고르세요(휴대폰에서도 가능합니다). 같은 창이 열리며 **시작 파트**와 **끝 파트**를 골라야 합니다(둘 다 필수이며, 값을 고르기 전에는 **주석 달기**가 동작하지 않습니다. 어느 쪽이 앞 번호인지는 상관없습니다. 본문이 있는 파트만 목록에 나타납니다). **주석 달기**를 누르면 범위 안의 파트를 하나씩 차례로 같은 지시, 응답 형식, 모델로 검토하며, 각 파트는 앞뒤 이야기와 함께 단일 파트처럼 읽힙니다. 제안된 메모는 파트 번호별로 나뉘어 모두 체크된 상태로 표시되고, **선택한 주석 추가**를 누르면 각 메모가 해당 파트에 추가됩니다. **중지**를 누르면 진행 중인 파트가 멈추고 더 이상 시작하지 않습니다. 그때까지 찾은 내용은 목록에 남습니다. 응답을 읽을 수 없거나 모델의 문맥에 들어가지 않는 파트는 건너뛰며(창에 어떤 파트인지 표시됩니다) 작업은 계속됩니다. 다만 모델 호출 자체가 실패하면 작업이 끝납니다. 파트마다 모델에 요청을 한 번씩 보내므로, 범위가 길수록 요청(그리고 토큰)도 그만큼 더 듭니다.

![파트 범위 검토: 제안된 메모가 파트 번호별로 나뉘어 표시됨](../../images/annotate-ai-batch.png)

**확장 기능이 제공하는 사실.** 본문에 적힌 것보다 이야기를 더 많이 아는 [확장 기능](../extensions/index.md)은 그 정보를 검토자에게 전달할 수 있으며, 검토자는 이와 모순되는 구절을 연속성 오류로 표시합니다. [지식 추적기](../extensions/knowledge-tracker.md#annotating-with-what-the-characters-know)가 그렇게 합니다. 이 확장 기능은 추적 중인 각 인물이 파트 시작 시점에 무엇을 알고 있었는지 모델에게 알려 주므로, 한 번도 들은 적 없는 이름을 쓰는 인물이 있으면 메모로 표시됩니다. 이 사실들은 내장 [주석 프롬프트](prompts.md#annotate-prompt)에 들어 있습니다(직접 만든 프롬프트에는 `{%{{{facts}}}%}`를 사용해야 합니다). 이런 확장 기능이 없으면 프롬프트는 원래대로입니다.

응답을 읽을 수 없으면 Marginalia는 한 번 더 요청합니다. 그래도 읽을 수 없으면 작업이 사라지지 않도록 모델의 응답 원문을 보여 줍니다. 프롬프트는 [주석 프롬프트](prompts.md#annotate-prompt)입니다.

<a id="annotating-every-new-part-automatically"></a>

### 새로 생성되는 모든 파트 자동으로 주석 달기

이야기의 설정 메뉴(⚙)에는 **자동 주석**이 있습니다(휴대폰에서도 가능하며, 켜져 있으면 체크 표시가 나타납니다). 이 기능을 켜면 파트가 생성된 직후 책이 그 파트를 검토하고, 원하면 재작성까지 합니다. 설정은 책과 함께 저장됩니다.

| 옵션 | |
|---|---|
| **모델**, **프로토콜** | 검토를 수행하는 모델입니다. 비워 두면 책의 모델을 씁니다(직접 여는 창이 시작하는 **주석용 기본 모델**이 아닙니다). |
| **살펴볼 내용** | **AI로 주석 달기**와 같은 지시입니다. 비워 두면 책이 물려받은 내용을 사용하고([주석 프롬프트](prompts.md#annotate-prompt) 참고), 그것도 없으면 프롬프트의 작업 지시를 씁니다. 비워 둔 채로 시작하면 이 칸에 실제로 사용된 텍스트가 나타납니다. |
| **생성된 모든 파트에 자동으로 주석 달기** | 이 기능을 켭니다. 파트가 생성되면(새 파트, 스와이프, 재생성 모두 해당하며, 중지되었거나 실패한 생성은 제외) 모델이 창 없이 **즉시** 검토합니다. [실행 패널](story-editor.md#the-panel-of-the-runs)에는 [파트 이후에 이어지는 작업](story-editor.md#what-follows-a-generated-part)의 한 단계로 표시됩니다. |
| **묻지 않고 주석 추가** | 모델이 끝나면 찾은 메모가 바로 추가됩니다. 이 옵션이 꺼져 있으면 주석 창이 제안된 메모와 함께 열리고(생성한 페이지에서 열리며, 어느 페이지에서든 패널의 **검토**로 열 수 있습니다), 직접 시작했을 때와 마찬가지로 선택을 기다립니다. |
| **주석을 반영해 파트 재작성** | 위 옵션을 켰을 때만 동작합니다. 메모가 추가되면 모델이 파트의 열린 주석과 자체 지시 없이 파트를 [재작성](story-editor.md#redrafting-a-part)합니다. 재작성에는 책의 모델을 쓰며 요약은 건드리지 않습니다. 파트가 새로 만들어진 것이라 그것을 설명하는 요약이 없기 때문입니다. 아무것도 찾지 못한 모델은 재작성할 것이 없습니다. |
| **묻지 않고 재작성 적용** | 재작성을 켰을 때만 동작합니다. 모델이 끝나면 재작성 결과가 파트의 본문을 대신하고, 처리된 메모는 해결됨으로 표시됩니다. 이 옵션이 꺼져 있거나, 모델이 쓰는 동안 파트를 고쳤다면 재작성 창이 결과와 함께 열리고 선택을 기다립니다. |

선택을 기다리는 재작성 창에는 두 개의 탭이 있습니다. **재작성된 텍스트**(본문, 모델의 추론, 원래 파트와의 차이)와 **주석이 달린 원문**(바뀌기 전 파트이며, 열린 메모의 구절이 이야기에서처럼 표시되고 그 아래에 메모가 나열됩니다. 표시를 클릭하면 해당 메모로 이동하고, 어느 한쪽에 마우스를 올리면 양쪽이 함께 강조됩니다)입니다. 모델이 무엇을 다루도록 요청받았는지 보려면 원문을 살펴보세요. 그다음 본문을 고치거나 재작성을 적용하면 됩니다.

![자동 주석 설정](../../images/annotate-auto.png)

**선택을 기다리는 창을 닫거나 패널에서 중지하면 파트 이후의 작업이 끝납니다.** 더 이상 메모가 추가되거나 재작성이 적용되지 않으며, 이후 단계(번역, 오디오)도 실행되지 않습니다. 패널의 메시지에 그 작업들의 이름이 나오므로 직접 실행할 수 있습니다. 이미 추가되거나 적용된 내용은 그대로 남습니다. 재작성이 실행되는 동안에는 새 파트를 생성할 수 없습니다(이전 본문에 이어 쓰게 되기 때문입니다). 메모를 만드는 동안에는 생성할 수 있습니다.

생성된 파트마다 모델에 요청이 최소 한 번 더 가고(재작성까지 하면 두 번), 프롬프트를 하나만 캐시에 두는 로컬 서버로 생성하는 경우 검토가 캐시의 이야기를 밀어내므로 다음 생성 때 이야기를 처음부터 다시 읽어야 합니다. 그럴 때는 검토에 다른 **모델**을 고르거나 서버를 하나 더 두세요.

<a id="giving-a-note-to-the-model"></a>

## 모델에게 메모 전달하기

메모에서 **파트와 함께 모델에 전달**을 체크하면 그 메모는 모델을 위한 메모도 됩니다. 프롬프트에 들어가는 파트들의 메모는 마스터 템플릿의 `{%{{{annotations}}}%}`로 전달됩니다(내장 템플릿에는 *이야기에 대한 작가의 메모* 블록이 있으며, 직접 만든 템플릿에서는 이 변수를 써야 합니다). 체크된 **열린** 메모만 전달되며, 프롬프트에 들어갈 수 있는 파트에 대해서만 전달됩니다. 모델이 이야기를 이어 쓸 때 계속 염두에 두어야 할 내용(*이 인물은 편지를 숨기고 있다*)에 쓰고, 편집용 메모에는 쓰지 마세요.

<a id="redrafting-to-address-the-notes"></a>

## 메모를 반영해 재작성하기

파트에 열린 메모가 있으면 [재작성](story-editor.md#redrafting-a-part) 창에 **파트의 열린 주석 반영하기** 체크 상자가 나타납니다. 체크하면 모델은 메모(구절과 메모 내용)와 여러분의 지시를 함께 받아 그것들을 반영하도록 파트를 다시 씁니다. 재작성 결과를 **적용**하면 해당 메모들은 해결됨으로 표시됩니다. [선택 영역 재작성](story-editor.md#redrafting-only-a-passage)에서는 구절이 선택 영역과 겹치는 메모만 전달됩니다.
<a id="commands"></a>

## 명령

[`/list-annotations`](../commands/index.md#annotations), `/get-annotation`, `/create-annotation`, `/update-annotation`,
`/resolve-annotation`, `/reattach-annotation`, `/delete-annotation`는 명령줄에서 메모를 다룹니다.
확장 기능도 같은 명령을 사용할 수 있습니다. [`/generate-annotation <part>`](../commands/index.md#annotations)은 명령으로 실행하는 **AI로 주석 달기**입니다. 모델은 책의 모델로 해당 부분을 검토하며(*에이전트의 모델로 책 쓰기*가 켜져 있으면 에이전트는 자신의 모델을 사용합니다. `profile`은 에이전트의 다른 모델 프로필을 고릅니다), 책의 지시 사항, 답변 형식, 프롬프트를 그대로 따릅니다. 찾은 메모는 모두 한 번에 추가되는데, 골라 줄 사람이 없기 때문입니다. 모델에 대한 요청이 한 번 이루어지므로 단독으로 실행되며 토큰이 소모됩니다.

<a id="annotations-and-agents"></a>

## 주석과 에이전트

[에이전트](../agents.md)는 같은 명령으로 주석을 읽고 씁니다. 책 전체에 주석을 달거나(*일관성*, *문체*...), 처리한 메모를 해결 표시하거나, 메모를 편집하거나 삭제할 수 있습니다. 에이전트는 책의 사본에서 작업하므로, [결과를 검토](../agents.md#reviewing-the-result)하기 전까지는 메모에 아무것도 반영되지 않습니다.

- 에이전트가 만든 메모는 **Annotation - Added** 줄로 표시되고, 해결, 기각 또는 다시 쓴 메모는 **변경됨**(메모, 유형, 상태, *모델에 전달* 항목이 각각 자체 **이 변경 사항 적용** 상자와 함께 표시됨)으로 표시되며, 삭제한 메모는 **삭제됨**으로 표시됩니다. 에이전트가 삭제한 부분의 메모는 그 부분과 함께 사라지며 별도의 줄이 없습니다.
- 줄에는 메모가 어느 부분에 있는지(`3: `와 메모의 시작 부분)가 나타납니다. **사본에서 보기**를 누르면 에이전트의 사본에서 해당 부분이 열립니다. 에이전트가 작성한 부분에 대한 메모는 그 부분이 있어야 하므로, 메모를 선택하면 부분도 함께 선택됩니다.
- 목록 위의 **주석만**을 체크하면 메모만 선택됩니다. 선택한 메모의 구절은 부분의 텍스트가 같을 때 동일하게 유지됩니다. 에이전트의 새 텍스트를 반영하거나 여러분의 텍스트가 다르면, 메모는 책의 텍스트에서 자신의 단어를 다시 찾으며, 찾지 못하면 부분 전체에 대한 메모가 됩니다.
- 에이전트가 일시 정지된 동안 작성하거나 해결한 메모는, 에이전트가 재개될 때 그 사본에 반영되어(해결한 메모도 그곳에서 해결된 상태가 됩니다) 에이전트가 이를 알 수 있습니다. 여러분과 에이전트가 모두 바꾼 메모는 다른 충돌과 마찬가지로 충돌로 처리됩니다.
