# 批注

**批注**是你为某个部分中的一段文字留下的笔记，例如*场景较弱*、*时间线有误*、*需要重访*。它的工作方式类似文字处理软件中的注释：故事正文保持干净，段落只做标记，笔记则紧挨着它保存。笔记也可以来自模型，或来自检查故事的[扩展](../extensions/index.md)。

批注**供作者本人使用**。除非你为该条笔记另行指定，否则它不会发送给模型，参见[把笔记交给模型](#giving-a-note-to-the-model)。

<a id="what-an-annotation-is"></a>

## 什么是批注

| | |
|---|---|
| **段落** | 笔记所针对的文字，或**整个部分**。 |
| **笔记** | 你想记住的内容。 |
| **类型** | 你可以选择填写的一个词（*连贯性*、*风格*、*节奏*……）。 |
| **来源** | 谁写的：你本人、模型（*AI*）、*代理*或*扩展*。正文中的标记按来源使用不同颜色。 |
| **状态** | *待处理*、*已解决*、*已忽略*或*已孤立*。只有待处理的笔记会在正文中标记。 |

一个部分可以有任意数量的批注，包括重叠段落上的批注。

<a id="making-an-annotation"></a>

## 创建批注

**针对一段文字。**在部分的正文中选中文字（可以带有格式，选区不必精确），然后**右键单击**（在手机上长按），选择**批注所选内容**，或按其[快捷键](story-editor.md#keyboard-shortcuts)（`a`）。窗口会显示该段落；填写笔记、可选的类型，以及模型是否接收该笔记，然后点击**保存**。部分的菜单（☰）中没有此项：打开菜单会取消选区。右键菜单中有**批注所选内容**、[**重写所选内容**](story-editor.md#redrafting-only-a-passage)和**复制**，它取代了浏览器在部分文字上的菜单，因此也包含**复制**。部分正在编辑时，使用编辑器中的选区：编辑内容会先被保存。

**针对整个部分。**在部分的菜单中选择**批注整个部分**。

**借助模型。**选择**用 AI 批注**，参见[下文](#letting-a-model-annotate)。

**通过命令行**（以及供扩展使用）：[`/create-annotation`](../commands/index.md#annotations)。

![新建批注的窗口](../../images/annotation-dialog.png)

<a id="reading-the-annotations"></a>

## 阅读批注

带有待处理笔记的段落会以**波浪线**标出下划线，颜色取决于笔记的作者（蓝色为你，橙色为模型，绿色为代理，红色为扩展）。一条笔记位于另一条之内时，其下划线会更靠下，从而两者都能看到。

![打开标记处的下划线段落的笔记](../../images/annotation-popover.png)

- **点击带下划线的文字**即可查看覆盖该位置的笔记（段落重叠时显示全部）。它们会在文字旁边打开；在手机上请点按该段落。
- 部分标题处带数字的**对话气泡**统计了该部分中需要查看的笔记数量。点击它可查看全部笔记，包括针对整个部分的笔记，以及已失去段落的笔记。
- 在**页边**（故事的齿轮菜单，**页边显示批注**；仅限桌面端，并会为你记住此设置）中，每个部分的笔记会按其段落的先后顺序排成一列，位于正文左侧，而不再显示在弹出框中。鼠标指向的笔记与其带下划线的段落会同时高亮，点击段落则会将对应笔记滚动到视野中。笔记本身相同（可解决、编辑等）；已解决和已忽略的笔记不会在此显示，因为它们也不带下划线。
- **批注**标签页按故事顺序，按部分分组列出整本书的笔记，并提供筛选器（*需要查看*、*已关闭*、*全部*）。**在故事中显示**（或部分的编号）会带你到该部分。

![部分页边中的笔记](../../images/annotations-margin.png)

![批注标签页](../../images/annotations-tab.png)

每条笔记会显示其作者、类型、状态、段落、笔记内容以及以下操作：

| | |
|---|---|
| ✓ **解决** | 问题已处理。笔记离开正文，但仍保留在列表中。 |
| ✗ **忽略** | 该笔记不值得处理。效果同上。 |
| ↶ **重新打开** | 把已关闭的笔记重新打开。 |
| ✎ **编辑** | 修改笔记内容和类型。 |
| 🗑 **删除** | 删除笔记；可从[回收站](../trash.md)中恢复。 |
| **随部分交给模型** | 见下文。 |
| **附加到所选内容** | 针对没有段落的笔记：在部分中选中文字，然后点击它。 |

<a id="annotations-follow-the-text"></a>

## 批注跟随文字

你编辑时无需关心笔记位于何处。Marginalia 会让每条笔记的段落与它原先所指的文字保持对应：

- 在段落**之前**增加或删除文字，会使段落随之移动；
- 在段落**内部**的编辑会使段落变长或变短；
- 你在段落**最开头或最末尾**输入的文字不属于该段落；
- 修正只有一个词的段落中的错别字，笔记仍保留在该词上。

当段落被**删除**，或被改写到无法再找到时，笔记会变为**已孤立**。它会被保留：你可以把它附加到另一段文字上（**附加到所选内容**）、忽略它或将其删除。如果你恢复了那些文字（撤销），笔记会重新找到它的段落。

当某个部分被**重新生成**时，文字已是新的，因此笔记会根据它们引用的文字重新寻找段落；文字已不存在的笔记则会变为孤立。当两个部分被[合并](story-editor.md#merging-a-part-into-the-previous-one)时，较后那个部分的笔记会转移到合并后的部分。部分的**分支**会复制其笔记。笔记属于[备份](backups.md)的内容，书籍副本以及备份导出文件中同样包含笔记。
<a id="letting-a-model-annotate"></a>

## 让模型批注

第一部分菜单中的 **用 AI 批注** 会请模型审阅该部分。你说明要查找什么（*标出连贯性错误*、*对话薄弱*、*与设定矛盾*；留空则使用本书、其文件夹或你的设置中[一次设定](prompts.md#annotate-prompt)的内容，否则使用提示词的任务），选择模型，然后点击 **批注**。

模型读取该部分的方式与[重写](story-editor.md#redrafting-a-part)相同：该部分本身、它之前的故事（较早的故事以[摘要](summaries.md)形式提供）、其后尽可能多能放入的故事、本书的设定与风格，以及该部分已有的批注，以免重复。

模型从不给出位置，它只会**引用**原文，由 Marginalia 在正文中找到该引文。找不到的引文并不会丢失：该批注会被提议为针对整个部分的批注，并标记为*未在正文中找到*。

**在你接受之前，不会向书中添加任何内容。** 模型提出的批注会逐条列出，每条前面都有一个复选框（默认全部勾选）；取消勾选你不想要的批注，然后选择 **添加所选批注**。

在电脑上，该窗口不会阻挡故事的阅读；模型工作时，窗口可以收起到页面角落，参见[与重写和批注窗口并行工作](story-editor.md#working-beside-the-redraft-and-annotation-windows)。

| 选项 | |
|---|---|
| **模型** | 负责审阅的模型。留空则使用你[设置](../account.md#general-settings)中的**批注默认模型**，否则使用本书的模型。审阅属于分析工作，因此它往往不是负责写作正文的那个模型。 |
| **回答格式** | *自动*（模型能以 JSON 作答时采用结构化格式）、*结构化（JSON）*、*文本块*（适用于不能严格遵守格式的模型），或*自由评论，再提取*（模型先写出一段自由评论，再由第二个模型——通常是更便宜的模型——将其转换为批注：请在**用于提取批注的模型**下选择它）。 |

![模型为某部分提出的批注](../../images/annotate-ai-proposals.png)

**一段范围内的部分（批量）。** 某部分菜单中的 **用 AI 批注** 只审阅该部分。若要审阅多个部分，请打开故事的设置菜单（⚙），选择 **用 AI 批注一段范围内的部分**（手机上也有）。窗口与之相同，但需要选择 **起始部分** 和 **结束部分**（两者均为必填，未填写时 **批注** 不可用；先后顺序无关紧要；只列出带有正文的部分）。随后 **批注** 会依次审阅范围内的各部分，使用相同的指令、回答格式和模型，每个部分都连同其周围的故事作为一个单独的部分来阅读。提议的批注会列在其所属部分的编号之下，全部默认勾选，**添加所选批注** 会将每条批注添加到其各自的部分中。**停止** 会中止当前部分并且不再开始新的部分；此前已找到的内容仍保留在列表中。若某部分的回答无法读取，或超出模型的上下文容量，该部分会被跳过（窗口会说明原因），运行继续；若模型本身出错，则整个运行结束。每个部分都是一次对模型的请求，因此范围越长，所需的请求（以及 token）就越多。

![批量批注一段范围内的部分：提议的批注列在其所属部分的编号之下](../../images/annotate-ai-batch.png)

**来自扩展的事实。** 某个[扩展](../extensions/index.md)若掌握的故事信息多于正文所写的内容，它可以把这些信息提供给审阅者，审阅者随后会把与之矛盾的段落标为连贯性错误。[Knowledge Tracker](../extensions/knowledge-tracker.md#annotating-with-what-the-characters-know)即是如此：它会告诉模型，在该部分开始时，每个被追踪的角色知道些什么，于是一个从未听说某个名字的角色却使用了这个名字，就会被标注出来。这些事实位于内置的[批注提示词](prompts.md#annotate-prompt)中（你自己的提示词必须使用 `{%{{{facts}}}%}`）；若没有此类扩展，提示词保持原样。

若某个回答无法读取，Marginalia 会再请求一次；若仍无法读取，则会显示模型的回答，以免工作白费。提示词即是[批注提示词](prompts.md#annotate-prompt)。

<a id="annotating-every-new-part-automatically"></a>

### 自动批注每个新部分

故事的设置菜单（⚙）中有 **自动批注**（手机上也有；打勾表示已开启）。开启后，本书会在每个部分生成完毕后立即审阅它，并可选择是否顺带重写。这些设置随书保存：

| 选项 | |
|---|---|
| **模型**、**协议** | 负责审阅的模型。留空则使用本书的模型（而不是你设置中的**批注默认模型**——你自己打开的窗口默认以该模型开始）。 |
| **查找要点** | 指令内容与**用 AI 批注**相同。留空则使用本书继承的内容（参见[批注提示词](prompts.md#annotate-prompt)），否则使用提示词的任务；若你在留空的情况下开始，该字段会显示所用的文本。 |
| **自动批注每个生成的部分** | 开启此项。某部分生成完毕后（新部分、换一版或重新生成；被停止或失败的不算），模型会**立即**审阅它，无需窗口；它会在[运行面板](story-editor.md#the-panel-of-the-runs)中以[部分生成后的后续步骤](story-editor.md#what-follows-a-generated-part)的一个步骤显示。 |
| **不经询问直接添加批注** | 模型完成后，它找到的批注会被直接添加。若不开启此项，批注窗口会在你生成所在的页面打开并显示提议（在任何页面中，也可从运行面板的**审阅**打开），并等待你选择，与你自己启动时一样。 |
| **然后重写该部分以处理批注** | 仅在开启上一项时可用。添加批注后，模型会连同该部分未解决的批注（不附带其他指令）[重写](story-editor.md#redrafting-a-part)该部分。它使用本书的模型撰写，且不改动摘要：该部分是新的，没有摘要描述它。若模型未找到任何问题，便无需重写。 |
| **不经询问直接应用重写** | 仅在开启重写时可用。模型完成后，重写的文本会替换该部分的正文，所处理的批注会被标记为已解决。若不开启此项，或你在模型撰写期间修改了该部分，重写窗口会打开并显示结果，等待你处理。 |

等待你处理的重写窗口有两个标签页：**重写文本**（文本、其推理过程，以及与该部分的差异）和**原文及批注**（该部分的原样，其中未解决批注的段落以故事中的方式标出，批注列在其下方；点击标记可跳转到对应批注，或将鼠标指向两者之一以同时高亮两者）。查看原文，可以了解模型被要求处理的内容；之后你可以修改文本，或直接应用。

![自动批注的设置](../../images/annotate-auto.png)

**关闭等待你处理的窗口，或在面板中点击停止，会结束该部分之后的后续步骤。** 不会再添加或应用任何内容，之后的步骤（翻译、音频）也不会运行；面板中的提示会写明这些步骤，以便你手动完成。已经添加或应用的内容保留不变。重写运行期间无法生成新部分（否则它会接着旧文本继续写）；而批注正在生成时则可以。

每个生成的部分至少会额外产生一次对模型的请求（若包含重写则为两次）。若你使用的本地服务器只在缓存中保留一个提示词，审阅会替换其中的故事，下一次生成就必须重新读取整个故事：请为审阅选择另一个**模型**，或使用第二台服务器。

<a id="giving-a-note-to-the-model"></a>

## 把批注交给模型

在某条批注上勾选 **交给模型，随部分一同提供**，它也会成为给模型的批注：进入提示词的各部分的批注会以 `{%{{{annotations}}}%}` 的形式放入主模板（内置模板有一个名为*作者对故事的批注*的区块；自定义模板则必须使用该变量）。只有勾选了此项的**未解决**批注会被提供，并且仅限于能放入提示词的部分。请用它来记录模型在续写时应当牢记的内容（*这个角色在隐瞒那封信*），而不是用于编辑性的备注。

<a id="redrafting-to-address-the-notes"></a>

## 重写以处理批注

当某个部分有未解决的批注时，[重写](story-editor.md#redrafting-a-part)窗口中会有一个复选框 **处理该部分未解决的批注**。勾选后，模型会同时获得这些批注（段落和批注内容）以及你的指令，并重写该部分以处理它们；当你**应用**重写时，这些批注会被标记为已解决。在[选段重写](story-editor.md#redrafting-only-a-passage)中，只有那些段落与所选内容有重叠的批注会被提供给模型。
<a id="commands"></a>

## 命令

[`/list-annotations`](../commands/index.md#annotations)、`/get-annotation`、`/create-annotation`、`/update-annotation`、`/resolve-annotation`、`/reattach-annotation` 和 `/delete-annotation` 可以在命令行中处理批注。扩展也可以使用相同的命令。[`/generate-annotation <part>`](../commands/index.md#annotations) 相当于命令形式的 **Annotate with AI**：模型会结合全书的模型、指令、回答格式和提示词来审阅该部分，并把找到的每条批注一次性全部添加，因为没有人来逐条挑选。它只发出一次模型请求，因此单独运行，并会消耗 token。

<a id="annotations-and-agents"></a>

## 批注与代理

[代理](../agents.md)使用同样的命令读写批注：它可以为整本书添加批注（*continuity*、*style* 等），标记已处理的批注，并编辑或删除它们。代理在书的副本上工作，因此在你[审阅结果](../agents.md#reviewing-the-result)之前，任何改动都不会影响你的批注：

- 代理新建的批注显示为一行 **Annotation - Added**；它标记为已解决、已驳回或已改写的批注显示为 **Changed**（其字段包括批注内容、类型、状态和 *give to the model*，每个字段都有自己的 **Take this change** 复选框）；它删除的批注显示为 **Deleted**。代理删除的某个部分上的批注会随该部分一起移除，因此不会单独显示。
- 每行都会注明批注位于哪个部分（以 `3: ` 开头，后接批注开头的文字）。**Show in the copy** 会在代理的副本中打开该部分。若批注位于代理所写的部分上，则需要该部分一并采纳：勾选批注时，该部分也会被勾选。
- 顶部的 **Only annotations** 只勾选批注本身。若部分文字相同，被采纳批注的定位文字保持不变；如果你采纳了代理新写的部分文字，或你自己的文字与之不同，批注会在你书中的文字里重新查找它的原文；若找不到，它就会变成针对整个部分的批注。
- 代理暂停期间你写的批注会在其恢复时进入它的副本（你标记为已解决的批注也会在那里标记为已解决），因此代理能知道这些改动；若你和代理都修改了同一条批注，则按其他冲突一样处理。
