# 이미지 생성기

이야기의 한 부분에 대한 이미지를 만듭니다. 모델이 그 부분을 바탕으로 이미지 프롬프트를 작성하면, 여러분이 프롬프트를 편집하고, 이미지 백엔드가 그림을 그립니다. 마음에 들 때까지 다시 생성한 뒤 수락하면, 그 그림은 부분 메뉴의 *이미지*로 직접 추가한 이미지와 같은 방식으로 해당 부분의 이미지가 됩니다(이야기와 내보내기 결과에 표시됩니다).

이 확장 기능은 이미지를 직접 만들지 않습니다. **ComfyUI** 서버나 **OpenAI images API**를 제공하는 서버와 통신합니다(stable-diffusion.cpp, LiteLLM 및 많은 호스팅 서비스도 이 API를 사용합니다).

<a id="adding-a-backend"></a>

## 백엔드 추가하기

*설정 → Extension Settings → Image Generator Settings*에 백엔드 목록이 있습니다. 하나를 추가(+)하고 내용을 입력한 다음 *설정* 페이지를 저장하세요.

| 설정 | 역할 |
|---|---|
| Name, Type | 창에 표시되는 이름. **ComfyUI** 또는 **OpenAI images API**. |
| Address | 서버의 기본 주소입니다. 예: ComfyUI의 경우 `http://localhost:8188`. |
| Api key | 베어러 토큰으로 이미지 서버에 전송됩니다. 암호화되어 저장되며 다시 표시되지 않습니다. 새 키를 입력해 교체하거나 **Remove the key**를 누르세요. |
| Key of the requests around the images | [이미지 앞뒤의 요청](#one-gpu-for-the-model-and-the-images)에 자체 `Authorization` 헤더가 없으면 `Authorization: Bearer`으로 함께 전송됩니다(예: LiteLLM 프록시의 키). 암호화되어 저장됩니다. 비워 두면 api key를 사용합니다. |
| Model | OpenAI images API 전용: 요청의 `model`입니다. |
| Workflow | ComfyUI 전용: **Save (API Format)**으로 ComfyUI에 저장한 워크플로입니다. `{{prompt}}`, `{{negative}}`, `{{seed}}`, `{{width}}`, `{{height}}`을 필요한 위치에 적고, LoRA 로더에 `{{lora}}` / `{{lora_strength}}`을 적으면 [창에서 LoRA를 고를 수 있습니다](#choosing-a-lora). |
| The server is on this machine or on my network | 로컬 네트워크 주소를 허용합니다. 클라우드의 서버라면 끄세요. 그러면 서버가 여러분의 컴퓨터를 호출하도록 만들 수 없습니다. |
| Width, Height | 창을 열 때 처음 쓰이는 값입니다(이미지 하나에 대해서는 창에서 바꿀 수 있습니다). |
| Prompt form | 언어 모델이 이 백엔드의 프롬프트를 어떤 형식으로 쓸지 정합니다. 이미지 모델에 맞게 고르세요: **태그**(짧은 쉼표 구분 구절, SDXL, Pony, Illustrious용), **Descriptive sentences**(한 단락, Flux, Krea, Qwen-Image, Z-Image용), 또는 **Free text**(프롬프트 작성자에게 주는 여러분만의 지침이며, 선택된 지침에서 시작합니다). 이 설정이 생기기 전에 만들어진 백엔드는 태그를 쓰거나, 그때 설정한 지침을 Free text로 사용합니다. 내장 지침은 [프롬프트 언어](../account.md#prompt-language)로 되어 있으며, 이미지 모델이 가장 잘 읽는 영어로 이미지 프롬프트를 요청합니다. |
| Timeout | 이미지 하나를 기다리는 시간입니다. |
| GPU lock | 서버가 언어 모델이나 다른 서버와 GPU를 공유할 때, 서버가 실행되는 GPU의 [GPU 잠금](../administration/gpus.md)입니다. [GPU 하나](#one-gpu-for-the-model-and-the-images)를 참고하세요. 관리자가 GPU 잠금을 설정한 경우에만 표시됩니다. |

![설정의 백엔드](../../images/plugin-imagegenerator-settings.png)

**Test connection**은 주소와 키를 확인합니다.

이 패널에는 책마다 바꿀 수 있는 텍스트가 두 개 있습니다:

- **문체** - 모든 프롬프트 앞에 붙습니다: 그림의 느낌, 예를 들어 *watercolor, soft light*. 프롬프트 작성자에게도 이것을 알려주므로, 프롬프트가 다른 문체를 묘사하지 않습니다.
- **Negative prompt** - 그림에 나오면 안 되는 것. 가이던스 없이 실행되는 턴보 모델(CFG 1)은 이를 무시합니다. 백엔드가 전에 가지고 있던 negative prompt는 이 패널을 처음 열 때 가져옵니다.

패널에서 설정한 값이 기본값입니다. 책(*프롬프트* 탭) 또는 [폴더](../books/folders.md)는 *Extension Settings → Image Generator*에서 자체 값을 정할 수 있습니다. 책은 자체 값을, 없으면 가장 가까운 폴더의 값을, 그것도 없으면 여러분의 기본값을 사용합니다.

<a id="making-an-image"></a>

## 이미지 만들기

![부분 메뉴의 이미지 생성 항목](../../images/plugin-imagegenerator-menu.png)

1. 부분의 메뉴에서 **Generate image**를 선택합니다. 아직 모델로 아무것도 보내지 않습니다. 먼저 프롬프트 작성자가 따를 내용을 채운 다음 **Write the prompt with the model**을 누르세요(또는 *Details*에서 <kbd>Ctrl+Enter</kbd>). 창의 모델(기본값은 책의 모델이며, 마지막 선택이 기억됩니다)이 부분의 프롬프트를 작성합니다. **Abort**로 중지하거나, 프롬프트를 바꾸거나, 직접 작성하거나, 다시 작성할 수 있습니다. 이 설정들은 프롬프트 작성에만 적용되며 이미지 자체에는 적용되지 않습니다.
   - **Send lorebook entries** - 책의 로어북(및 하위 로어북)의 항목이 생성할 때처럼 모델에 전달되어, 모델이 등장인물과 장소의 모습을 알 수 있습니다. 항목은 필터의 단어가 부분에서 발견될 때 전달됩니다. 필터는 텍스트, 지침, 장면 설정, 시점, 등장하는 인물, 또는 *Details*에서 찾습니다. 항상 켜져 있는 항목도 포함됩니다. 모델의 컨텍스트에 들어갈 만큼만 전달되며, 몇 개가 빠졌는지 알림이 표시됩니다. 선택은 기억됩니다.
   - **Details** - 그림에 무엇이 보여야 하는지 또는 어떻게 보여야 하는지(*밤에, 그녀의 얼굴 클로즈업, 빨간 드레스*). 프롬프트 작성자가 이를 따릅니다. 이 창에만 적용됩니다.
2. 백엔드를 선택하고 **생성**을 누릅니다. 이미지는 앞에 **문체**를 붙인 **Prompt**와 **Negative prompt**로 만들어집니다. 둘 다 책의 값(또는 여러분의 기본값)에서 시작하며, 변경 사항은 이 창에만 적용됩니다(문체는 프롬프트 작성자에게도 전달됩니다). 크기는 백엔드의 값에서 시작하며 이 창에서만 바꿀 수 있습니다.
3. 이미지가 나타납니다. **Reroll**은 새 시드로 다시 만들고, **Discard**는 버리며, **Accept**는 부분에 추가하고 창을 닫습니다. **Abort**는 만들고 있는 이미지를 중지합니다(ComfyUI에는 작업 중단을 요청합니다).

![모델이 작성한 프롬프트가 있는 창](../../images/plugin-imagegenerator-prompt.png)

![Accept, Discard, Reroll 버튼이 있는 이미지](../../images/plugin-imagegenerator.png)

열린 부분에는 새 이미지가 텍스트 아래에 바로 표시됩니다.

창은 각 부분에 대해 사용한 값을 기억합니다. 세부 사항, 문체, negative prompt, 프롬프트, 크기는 프롬프트를 작성할 때와 생성할 때 부분과 함께 저장되며, 다음에 그 부분에서 창을 열면 이 값들로 시작합니다. 이미지를 만든 적이 없는 부분은 책의 문체와 negative prompt로 시작합니다.

<a id="choosing-a-lora"></a>

## LoRA 선택하기

LoRA는 이미지 모델에 덧붙이는 작은 추가 기능으로, 보통 문체용입니다. ComfyUI를 사용하면 LoRA마다 워크플로를 다시 저장하는 대신 창에서 LoRA를 고를 수 있습니다.

1. 내보낸 워크플로에서 LoRA 로더(*Load LoRA*, `LoraLoaderModelOnly` 또는 `LoraLoader`)의 `lora_name` 값으로 `{{lora}}`을 적고, 강도로 `{{lora_strength}}`을 적습니다(`strength_model`; `LoraLoader`에는 `strength_clip`도 적습니다).
2. 그러면 창에 **LoRA**와 서버의 LoRA 파일 목록(`models/loras` 폴더)이 표시되고, **LoRA strength**도 나타납니다. 목록에 없는 파일의 이름은 직접 입력할 수도 있습니다.
3. **없음**(빈 LoRA)을 선택하면 LoRA 로더가 워크플로에서 제거되므로, 이미지는 로더 없이 만들어집니다.

생성에 사용한 LoRA와 강도는 백엔드마다 기억되어 다음에도 그대로 있습니다. 목록도 마찬가지입니다. GPU를 공유하는 서버는 창을 열 때 대개 실행 중이 아니므로(첫 이미지 전의 요청이 서버를 시작합니다), 창은 서버가 마지막으로 나열한 LoRA를 보여주고 첫 이미지를 만든 뒤 다시 목록을 요청합니다. 한 번도 목록을 가져오지 못한 경우에만 LoRA 목록을 읽을 수 없었다는 알림이 표시되며, 그때도 파일 이름을 직접 입력할 수 있습니다.
<a id="one-gpu-for-the-model-and-the-images"></a>

## 하나의 GPU로 모델과 이미지 처리하기

GPU가 하나뿐이고 작은 경우, 언어 모델과 이미지 모델을 함께 불러올 수 없습니다. 관리자는 이를 한 번만 설정하면 되며, 같은 GPU를 쓰는 모든 모델과 서버에 적용됩니다. [관리자 → GPU](../administration/gpus.md)에서 언어 모델용 **GPU 잠금**과 이미지 서버용 **GPU 잠금**을 각각 만듭니다. 각 잠금에는 GPU를 불러오는 요청과 GPU를 비우는 요청이 들어갑니다. 백엔드의 **GPU 잠금** 항목에서 이미지 서버의 잠금을 고르고, 언어 모델의 잠금은 [AI 설정](../inference-providers.md)에서 고릅니다.

이후 모든 이미지는 GPU를 차례로 사용합니다.

- GPU에 이미지 서버가 이미 올라와 있으면 이미지는 바로 시작합니다. 다시 생성할 때마다 아무것도 내려가지 않습니다.
- GPU에 언어 모델(또는 다른 서버)이 올라와 있으면, 이미지는 모델이 응답을 마칠 때까지 기다립니다. 그다음 모델의 잠금이 GPU를 비우고, 이미지 서버의 잠금이 이미지 서버를 불러옵니다.
- 이미지와 이미지 사이에는 아무것도 점유하지 않습니다. 창을 닫거나 접어도, 열어 둔 채로 두어도 GPU는 점유되지 않습니다. 언어 모델에 다음 요청을 보내면 그때 이미지 서버가 차지한 GPU를 스스로 비우고, 그 전까지 이미지 서버는 올라와 있습니다.

창에는 순서를 기다리는 동안 *이미지 생성 중*이 표시됩니다.

**각 이미지 전후의 요청.** 백엔드에는 이미지마다 잠금 안에서 실행되는 요청 목록이 두 개 더 있습니다: **각 이미지 전**과 **각 이미지 후**입니다. GPU를 비우는 일은 GPU 잠금의 몫이므로, 이미지 전후로 서버에 필요한 다른 작업이 있을 때 이 목록을 사용하세요. 각 목록은 요청을 하나씩 순서대로 만듭니다(**요청 추가**는 하나를 추가하고, 휴지통 아이콘은 하나를 삭제합니다). 각 요청에는 주소, 메서드(기본값은 `POST`), 헤더(`Name: value`, 한 줄에 하나), 본문, **제한 시간**(비워 두면 60초, 최대 600초), 그리고 **이후 대기**(응답 후 멈출 초 단위 시간)가 있습니다. 헤더는 API 키와 마찬가지로 암호화되어 저장됩니다.

*이전* 목록의 요청이 실패하면 나머지 요청은 실행되지 않고 이미지 생성이 중단됩니다(메시지에 실패한 요청이 표시됩니다: *요청 2/3 실패: ...*). *이후* 목록은 요청 중 하나에 무슨 일이 생기더라도 **끝까지** 실행되며, 실패는 확장 기능의 로그에 기록됩니다. 이미지는 그대로 보존됩니다. 이전 버전의 단일 요청으로 저장된 백엔드는 목록의 첫 번째 요청으로 표시됩니다.

GPU 잠금이 생기기 전에 저장된 백엔드는 **GPU (이름)** 및 **유휴 후 해제** 설정을 잃습니다. 대신 GPU 잠금을 고르고, GPU를 비우던 요청(언어 모델 내리기, ComfyUI의 `POST <address>/free`)은 잠금 단계로 옮기세요.

<a id="what-is-not-done"></a>

## 하지 않는 것

- 백엔드는 책별이 아니라 사용자별로 관리됩니다.
