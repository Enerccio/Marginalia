# ジョブ

**外部AI**に対してアプリケーションが求めるものはすべて*ジョブ*です。生成、要約、注釈、エージェントの実行、章の音声への変換、画像などが該当します。各ジョブには、実行したユーザー、開始と終了の時刻、終了の仕方、そしてモデルや音声・画像バックエンドへの*呼び出し*のすべてが記録されます。呼び出しにもそれぞれ開始と終了の時刻があります。管理ページの **ジョブ** タブにはこの記録が表示され、ページ `/jobs` では今まさに実行中のものが表示されます。

保存されるのはメタデータだけです。誰が、いつ、どれくらいの時間、どのAIまたはサーバー（AIの名前、または音声・画像サーバーのホスト名。アドレスのパスやクエリは含みません）、どのモデル、どのように終了したか、失敗時の短いエラーメッセージ。**プロンプト、回答、本文は一切**保存されません。

<a id="what-is-one-job"></a>

## ジョブとは

- 何かにまとめられていない**単独のリクエスト**（生成、注釈、書き直し、なりきり、一部分の要約、ヘルプアシスタントへの質問、一部分の翻訳やロールブックの項目など、プラグインのリクエスト）は、呼び出しを1つ持つ独立したジョブになります。その種類は作業の種類（`generation`、`annotate`、`summary`…）です。
- **要約の書き直し**は1つのジョブ（`summary`）で、書かれた要約ごとに1回の呼び出しがあります。
- **エージェント実行の作業セッション**は1つのジョブ（`agent`）で、エージェントの各ラウンドごとに1回の呼び出しがあります。一時停止して再開された実行では、セッションごとにジョブができます。サブエージェントのリクエストはそれぞれ独立したジョブです。
- **音声への変換**は、パーツのまとまり（バッチ）ごとに1つのジョブ（`audiobook`）になります。ラベル付けを行うモデルへのリクエストと、読み上げられた各断片が呼び出しとして記録されます。
- **Image Generator**で作られた画像は独立したジョブ（`image-generator`）になり、画像の呼び出しを1つ持ちます。

<a id="what-runs-now-jobs"></a>

## 今実行中のもの: `/jobs`

![生成が進行中のページ /jobs](../../images/jobs-live.png)

Marginaliaのアドレスで `/jobs` を開きます（例: `http://localhost:8080/jobs`。タブの **ライブビューを開く** リンクからも開けます）。他のページと同じくログインが求められ、管理者以外のユーザーには何も表示されません。一覧は2秒ごとに更新され、実行中のジョブごとに、ユーザー、種類、実行時間、完了した呼び出しの数、そして現在進行中のもの（AIまたはサーバーと、呼び出しが待っている時間）を表示します。サーバーが混んでいるように見えるときの素早い確認に使えます。1つのモデルの応答を待つ呼び出しが長く並んでいれば、それが全体が遅い理由です。

ジョブの下には **書籍の実行** があり、書籍に対して今作業中のものが一覧されます。それらが書籍の一部を削除されたり、途中で変更されたりするのを防ぎます（[実行のパネル](../books/story-editor.md#the-panel-of-the-runs)を参照してください。同じ内容が各ユーザーに自分の書籍について表示されます）。ユーザー、書籍、何をしているか、どこにいるか（パネルに表示されるもの: *Waiting for the model*、*The model is thinking/writing...*、*Working*、*Waits for you*。生成の場合はその段階、例えば部分を書いている間は *INFERENCE*。開いている書籍のウィンドウではここには何も表示されません）、開始時刻、そして保持しているオブジェクトの数（書籍、パーツ）が分かります。開いている書籍のウィンドウも実行の1つです。**停止** は、そのユーザーが行うのと同じように実行を止めます。**終了** は、質問が出たあとに、作業を止めずに実行を終わらせます。実行が保持していたものはすぐに解放されます。終わらない実行（作業が行き詰まり、再起動まで書籍を保持し続けているもの）にだけ使ってください。その作業は、目覚めたときにまだ書き込むことがあります。

<a id="the-log-the-jobs-tab"></a>

## 記録: ジョブタブ

![管理ページのジョブタブ](../../images/admin-jobs.png)

| | |
|---|---|
| **User、Kind、Status** | 絞り込み。*種類*はジョブが何かを示します（`generation`、`summary`、`annotate`、`agent`、`audiobook`、`image-generator`…）。作業を名付けなかったコードによるリクエストは `untagged` になります。 |
| **経過日数（以上）** | 指定した日数以上前に開始されたジョブだけを表示します。 |
| **更新** | 記録を読み直します。 |
| **これらのジョブを削除** | フィルターで表示されているジョブとその呼び出しを、件数を示す確認のあと完全に削除します。フィルターを設定していなければ、記録全体を削除します。 |
| **ライブビューを開く** | `/jobs` を新しいタブで開きます。 |

行をクリックすると、そのジョブの呼び出しが表示されます。種類（言語モデル、音声、画像）、AIまたはサーバー、モデル、開始、終了、所要時間、状態、失敗した呼び出しのエラーです。失敗と表示されたジョブは、失敗した呼び出しがあったか、実行したコードによって失敗として終了させられたものです。キャンセルされた呼び出しは、あなたが停止したもの（またはジョブの終了時にまだ実行中だったもの）です。

![音声変換の呼び出し](../../images/admin-jobs-calls.png)

失敗したジョブは、どの呼び出しが、なぜ失敗したかを示します。

![音声呼び出しのエラーで失敗した変換](../../images/admin-jobs-failed.png)

**記録は自動では削除されません。** リクエストのたびに記録は増えていくので、ときどき整理してください。*経過日数（以上）* を設定し（例: 30）、表示された内容を確認してから削除します。[クリーンアップ](cleanup.md)では、ユーザーを削除するときに、そのユーザーのジョブも一緒に削除されます。

![30日より古いジョブと、削除前の確認](../../images/admin-jobs-old.png)

![ジョブを削除する前の確認](../../images/admin-jobs-delete.png)

ジョブは終了したときに記録に書き込まれます。まだ実行中のジョブは `/jobs` にだけあります。アプリケーションが停止すると、実行中だったジョブは失われます（完了していなかったためです）。誰も終了させず、30分間呼び出しを行わないジョブは、完了したものとして終了させられます。
