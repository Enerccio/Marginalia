# 리소스 파일

[리소스](../resources.md)의 파일(사용자가 스토리 파트에 첨부한 그림, 업로드한 파일)은 사용자마다 있는 데이터 폴더의 `data/<login>/images`와 `data/<login>/resources`에 저장됩니다. 리소스를 삭제하거나 내용을 바꾸면 데이터베이스만 바뀌고, 파일은 디스크에 그대로 남습니다. [정리](cleanup.md)나 다른 어떤 작업도 이 파일을 지우지 않습니다. **리소스 파일**은 더 이상 아무것도 사용하지 않는 파일을 찾아 내려받을 수 있게 하고, 디스크에서 삭제해 공간을 되찾을 수 있게 해 줍니다.

<a id="cleaning-up-the-files"></a>

## 파일 정리하기

1. 관리자 페이지의 **리소스 파일** 탭을 열고 **파일 스캔**을 클릭합니다. 읽고 있는 폴더가 진행 막대에 표시됩니다. 이 단계에서는 아무것도 바뀌지 않습니다.
2. 표에는 **어떤 리소스도 가리키지 않는** 파일이 나열됩니다. 각 행에는 경로(`<사용자 폴더>/images/<파일>`), 크기, 마지막으로 수정한 날짜가 표시됩니다. 모든 파일이 기본으로 선택되어 있습니다. 보관하고 싶은 파일의 선택을 해제하세요. **모두 선택**과 **선택 해제**는 모든 파일에 적용되며, 첫 번째 열 머리글의 화살표도 같은 일을 합니다. 표 위의 줄에는 사용되지 않는 파일의 개수, 전체 크기, 선택된 파일의 개수가 표시됩니다.
3. 선택적으로 **ZIP으로 다운로드**를 클릭하면 선택된 파일을 하나의 압축 파일로 받을 수 있습니다(항목 이름은 경로로 지정됩니다). 한 파일만 받으려면 해당 행의 화살표를 누르세요. 삭제하기 전에 보관해 둘 백업입니다.
4. **선택 항목 삭제**를 누르고 확인하면 선택된 파일이 디스크에서 제거됩니다. **닫기**를 누르면 표만 비워지고 아무 파일도 삭제되지 않습니다.

![스캔 후의 리소스 파일 탭](../../images/admin-resource-files.png)

!!!warning
삭제된 파일은 복구할 수 없습니다. 확신이 서지 않으면 먼저 ZIP으로 내려받으세요.
!!!

<a id="what-counts-as-used"></a>

## 사용 중인 파일의 기준

파일은 **어떤 사용자의 리소스라도 가리키고 있으면** 사용 중인 것으로 봅니다. 삭제된 리소스도 포함됩니다. [휴지통](../trash.md)에 있는 리소스는 복원할 수 있으므로, 그 그림도 다시 제대로 보여야 하기 때문입니다. 따라서 삭제된 리소스의 파일은 [정리](cleanup.md)가 리소스를 데이터베이스에서 제거한 뒤에야 목록에 나타납니다. 내용을 교체하면서 남겨진 이전 파일과 실패한 업로드가 남긴 파일도 마찬가지입니다.

파일은 이름(무작위 식별자)으로 비교하며, 모든 사용자의 폴더를 대상으로 합니다. 삭제된 사용자의 `<login>-deleted` 폴더도 포함됩니다. 이 폴더의 파일은 정리가 해당 사용자와 리소스를 완전히 제거할 때까지 *사용 중*으로 남습니다.

데이터 폴더 안의 폴더 중 `images`와 `resources` 폴더만 읽습니다. 그 밖의 것(데이터베이스 백업, 에이전트 작업 공간 등)은 읽지도 건드리지도 않습니다.

스캔 후에 사용자가 업로드한 파일은 삭제되지 않습니다. **선택 항목 삭제**를 누르면 데이터베이스를 다시 읽어, 그 시점에 리소스가 가리키는 파일은 남겨 둡니다(남겨진 파일의 개수가 메시지에 표시됩니다).

스캔은 데이터 폴더를 읽으므로 파일이 많으면 시간이 걸릴 수 있습니다. 진행 막대의 **중지**를 누르면 스캔이 취소됩니다.
