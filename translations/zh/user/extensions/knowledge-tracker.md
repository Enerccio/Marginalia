# 知识追踪器

记录故事中角色知道什么、不知道什么，并把这些信息放入提示词。除非指令加以防范，模型往往会让角色知道他们从未见过的人的事情（比如名字、职业、长相）。使用知识追踪器后，提示词会针对场景中每个被追踪的角色说明：该角色知道什么，以及它除此之外一无所知。

!!!
你决定谁被追踪。只有你添加到标签页中的角色会被描述给模型，并且只在它们是正在撰写的部分的 *present characters* 时才会如此。故事文本不会被用来猜测任何内容。
!!!

<a id="the-knowledge-tab"></a>

## Knowledge 标签页

[故事编辑器](../books/story-editor.md)的左侧边栏会在 *Outline* 旁边增加一个 **Knowledge** 标签页。你每次修改的内容都会即时保存到书中。

![Knowledge 标签页](../../images/plugin-knowledgetracker.png)

**Track a character** 会要求填写一个 **name**（名称），还可以选填 **aliases**（别名）：即该角色在某个部分的 *Present Characters* 字段中可能写成的其他名字，用逗号分隔。一个名称或别名只能属于一个被追踪的角色。

**Import from the Character Tracker**（**Track a character** 旁边的人形图标）会开始追踪同一本书中 [Character Tracker](character-tracker.md) 里的角色。它会列出本书尚未追踪的角色（按名称或别名匹配），并附上它们的标语，默认全部勾选；取消勾选你不想要的角色，然后点击 **Import**。只会导入名称：标语和备注只是描述角色，并不是角色所知道的内容。勾选 **Their relationships count as meetings** 后，导入的角色会被视为已与其在 Character Tracker 中有关系的人见过面（这些人会像你手动填写一样写入其 **Has met** 列表，因此处理时会保留它们）。

**Who has met whom**（握手图标，位于导入按钮旁）可一次性设置被追踪角色之间的相识关系，无需输入名字。在左侧选择一个角色；右侧每个其他被追踪的角色都有一个复选框，当所选角色与其见过面时即被勾选。勾选即添加相识关系，取消勾选即删除；每次更改都会立即保存，关闭窗口后卡片上会显示最新状态。相识关系是单向的：为 Fiora 勾选 Thomas 并不会为 Thomas 勾选 Fiora，除非勾选了 **Mutual**：此时每次勾选或取消都会同时在双方生效，若两人已经彼此熟识，这样会更快（它只对你在勾选状态下所做的更改生效，不影响已经设定好的相识关系）。已勾选的相识关系视为你的设定（处理时会保留）；你取消勾选、而故事中显示的相识关系，若该部分被重新阅读，会重新出现。至少需要两个被追踪的角色。

点击角色卡片上的箭头打开它，查看其所知内容：

| | |
|---|---|
| **Knows**（绿色）/ **Does not know**（红色） | 关于任何事物的一句简短陈述：人物、地点、秘密、事件（*Peter 知道针对公爵的阴谋*；*Fiora 不知道 Thomas 是她的父亲*）。请明确写下角色**不知道**的事情，模型会遵守这些内容。 |
| 排序与 **#12** | 最新的知识排在最上面（旧知识也一样）。模型学到的条目末尾会带有它所学自的部分的小编号（**#12**）：点击后故事会滚动到该部分并使其闪烁（在手机上会先关闭抽屉）。你手写的条目没有编号；若其所属部分不在当前分支上（位于其他分支，或该部分已被删除），也没有编号。 |
| **Add knowledge** | 添加一个条目，立即生效。请保持每个条目只表达**一个想法**：如果一个条目同时包含两层意思（*不知道 Thomas 是谁，从未见过他*），那么其中任何一层不再成立时，该条目就会被撤回。**edit** 按钮可修改文本和类型。 |
| **Retract**（带斜线的圆圈） | 该条目不再成立（例如二人相遇后，*has not met Thomas* 不再成立）。它不会被删除：而是变为 *old knowledge*，不再发送给模型。 |
| **Lock**（挂锁，用于模型学到的条目） | [整理过程](#tidying-the-knowledge)不会看到已锁定的条目：请用它来保留必须保留的内容，例如背叛、秘密。故事仍可能与已锁定的条目相矛盾（例如角色失去记忆）：此时故事的阅读会照常撤回该条目。 |
| **Delete** | 经确认后永久删除一个条目。**Retract** 会保留条目，因此拿不准时请使用它。 |
| **Select items**（位于 **Add knowledge** 旁） | 快速删除多个条目：该角色的每个条目（包括旧条目）都会出现复选框。**Select all** / **Deselect all** 用于勾选或清空全部，**Delete selected (n)** 经确认后永久删除已勾选的条目，**Cancel** 则退出选择。 |
| **Has met** | 该角色见过的人，由[处理过程](#processing)记录。处理过程可能会记下并非人物的名称（即在 *Present Characters* 字段中的一条备注）：打开 **Edit**，修改 **Has met** 列表，逐个填写名称并用逗号分隔。你写入的名称会在故事重新阅读时保留；你删除的名称，只有在它被看到的那个部分重新阅读时才会再次出现。 |
| **Old knowledge (n)** | 默认折叠。每个旧条目都会说明它为何成为旧条目：*retracted*（若是模型撤回的，还会显示撤回它的那个部分的编号）、在审阅中被 *declined*，或被 *tidied*。旧条目可以被 **copied**、**edited**、**restored**（从此刻起重新生效）或删除。 |

<a id="mass-changes"></a>

### 批量修改

**Mass changes** 按钮（位于 **Track a character** 旁的列表图标）会打开一个窗口，以带复选框的表格列出每个被追踪的角色及其全部条目（包括旧条目）：类型、文本、状态（*Active*，或旧条目的 *retracted*、*declined in a review*、*tidied*）、来源（*Initial state*、*Written by hand*、*Learned from the story*），以及其学到的部分。你可以在任意多个表格中勾选条目（表格标题处的复选框会勾选该表格的全部条目；底部栏中的 **Select all** / **Deselect all** 则会勾选或清空所有角色的全部条目），然后：

| | |
|---|---|
| **Retract selected (n)** | 已勾选的生效条目变为 *old knowledge*，与对单个条目使用 **Retract** 的效果相同。 |
| **Restore selected (n)** | 已勾选的旧条目从此刻起重新生效。 |
| **Delete selected (n)** | 经确认后永久删除已勾选的条目。 |
| **Copy selected (n)** | 复制已勾选的条目（可来自任意角色），以便粘贴到另一个角色中。 |
| **Paste (n)**（位于每个角色的标题处） | 将复制的条目添加到该角色。粘贴的条目视为手写条目（原本为初始状态的条目仍保持初始状态），并保留其类型、锁定状态以及是否为旧条目；若该角色已有相同的条目（类型和文本相同），则跳过。复制的条目会一直保留到下一次复制为止，即使关闭窗口后也是如此，因此可以粘贴到多个角色中。 |

按钮上的数字表示每个按钮将改变多少个已勾选的条目。更改后勾选状态会保留，因此接下来可以删除已撤回的条目。

**Export to JSON**（位于窗口顶部）会把本书中被追踪的角色（名称、别名、条目及其类型、状态、来源和锁定状态、见过的人）下载为一个文件；不包含处理过程的数据，因此适用于任何一本书。**Import from JSON** 会将此类文件读入本书，且只做添加：若书中已追踪某角色的名称（作为名称或别名），则该角色会获得其尚未拥有的别名、条目和见过的人（类型和文本相同的条目会被跳过）；其他角色则成为新的被追踪角色；已被其他角色占用的别名会被略去。导入的条目在本书中没有对应的部分，因此重新处理时不会删除它：模型学到的条目视为手写条目，旧条目保持为旧条目。导入后的提示信息会说明新增或更新了多少个角色，以及新增了多少条目，或有多少条目已经存在。
<a id="what-goes-into-the-prompt"></a>

## 提示词包含什么

对于每个被追踪且位于在场角色中的角色，提示词会获得一个如下的区块：

```
What the characters of this scene know. A character acts only on the knowledge listed for it:

Fiora knows: Mara, a courier of the Guild of Lamps and the sister of her friend Nell; she owes the Guild of Lamps forty crowns.
Fiora does not know: that her father is alive, or that Thomas is her father.
Fiora has met: Mara.
Fiora is currently with: Mara, Thomas.
Fiora has never met or heard of anyone else in this story and knows nothing else of its secrets, plans or events.
```

只会发送启用的条目。最后一行（**closed world** 行）用于防止模型让角色掌握其不可能知道的信息。它涵盖故事中讲述的内容（人物、地点、秘密、计划、事件），而不包括该世界中人人都知道的常识，因此角色仍然了解自己所在的城镇。你可以在设置中关闭这一行。被追踪但不在场的角色不会获得任何内容，连说明其不知情的行也没有。

<a id="who-is-present"></a>

### 谁在场

该区块由本部分的 **Present Characters** 字段生成。该字段是自由文本，因此读取时比较宽松：

- 括号中的文字会被忽略：`Tomáš (tired), Mizuki` 等同于 Tomáš and Mizuki；
- 名字会在**分隔符**处被切分（默认：`,` `;` 换行、`/`、`|`、`、` `，` `；`）；
- ` - ` 或 `:` 之后的内容是备注，会被丢弃（`Mara - wounded`）；
- 大小写、变音符号以及开头的 *the* 都不影响匹配；
- 名字必须**完整匹配**：*Mara's brother* 不等于 *Mara*。如果一个角色有多种写法，请使用别名。关键在于：漏掉一次匹配只会少一个区块，而误匹配则会描述一个并不在场景中的角色。

*Point of View* 字段不会被单独读取，因此也请把视角角色写入在场角色中。

<a id="processing"></a>

## 处理

插件会跟随故事进行。**Processing** 会按顺序读取当前分支中从**起点**开始的各部分，并保存一个**光标**（即它最后读取的部分）。不使用模型时，它只记录谁见过谁：被追踪的角色与其在在场角色字段中与之同时出现的每个名字都算见过，区块中会列出这些名字。使用模型时，它还会找出角色**了解到**的内容（参见[读取角色所了解的内容](#reading-what-the-characters-learn)）。

![处理面板](../../images/plugin-knowledgetracker-processing.png)

标签页顶部的面板显示当前进度。当一个新部分定稿后（如果书中启用了自动批注和重写，则在其之后），面板会自动重新加载；如果你以其他方式添加、编辑或删除了部分，请按 **Refresh** 按钮（齿轮旁的箭头图标）以重新读取故事。面板包括：

- **Process now**：读取尚未处理的部分。
- **Process next part**：只读取第一个尚未处理的部分，每次一步（使用模型时，无论 *Parts per run* 如何设置，对该部分只发出一次请求）。可用于试验设置，或查看模型对单个部分的发现。命令 `knowledge-process` 配合 `parts` 设为 1 效果相同。
- **Start point**：处理开始的部分（默认为 *Start of the book*）。在它之前的部分永远不会被读取。将其往前移会从新起点重新读取各部分，
  向后移则保留已读取的内容。
- **Processed parts**：最近读取过的各部分。若某部分的文本**在处理后有过变动**（你编辑或重写过它），该部分会被标记；但不会因此自动重新处理。每行的按钮 **Reprocess from here** 会撤销来自该部分及其之后各部分的内容（你手动编写的条目和撤回记录会保留），并重新读取这些部分。

当你向下滚动角色列表、越过这些按钮时，标签页顶部的工具栏也会提供 **Process now**、**Process next part** 和 **Tidy knowledge**，方便你无需滚回上方即可处理。

当 **Process new parts automatically** 开启时（默认关闭），插件会自动执行以下操作：

- 在开始生成之前，会处理自上次以来新写的各部分，以便提示词了解谁见过谁。正被 *Regenerate* 或 **swipe**（滑动切换）替换的部分则不做处理。使用模型时，只有在 **Ask before applying** 关闭时才会用模型读取（见下文）；否则它只记录谁见过谁，而模型的发现需要从标签页中手动启动，因为生成过程中从不强迫你进行审阅。
- 当某部分被**重新生成**且新文本到达时，从旧文本中学到的内容会被撤回。
- 当你**滑动切换**或切换到另一分支时，光标会回到两个分支共有的最后一个部分。
<a id="reading-what-the-characters-learn"></a>

## 阅读角色所了解的内容

在设置中勾选 **Read what the characters learn with the model**。然后点击 **Process now**，模型会针对故事的接下来几个部分，询问每个出现在其中的被追踪角色**了解到了**什么：它看见、听见、读到或被告知了什么。它还会指出哪些条目被故事**矛盾**（例如，角色在相遇之后仍是*从未见过 Thomas*）。请求包含这些部分（及其视角和在场角色）、每个被追踪角色当前所知的内容，以及你选择的世界书（如有）。模型会被告知：忽略这个世界中任何人本来就知道的事（例如谁是国王），以及由角色本身可以推出的事（例如魅魔知道自己有尾巴），并且不报告它不确定的内容。未出现在任何部分中的被追踪角色，根本不会被询问。

每次运行都是向模型发出的一次请求。当 **Process now** 需要发出超过三次请求时（例如一大段尚未处理的故事，或将 **Parts per run** 设得很低），它会先告诉你有多少个部分和请求，以及大约有多少文本会经过模型，并且只有在你确认后才开始。每个请求还包含指令、世界书和角色的已知内容，因此实际成本高于单纯的文本量。

当 **Ask before applying** 关闭时，更改会立即生效，并且每一项都会写入标签页“Processing”部分中的日志 **Applied automatically**：说明哪个角色在哪个部分中获得或失去了什么。日志中的内容不可编辑，但每一行都有一个 **Revert** 按钮：已添加的条目会被拒绝（它会留在 *Old knowledge* 下，与审阅中被拒绝的添加一样），已撤回的条目会重新变为有效。如果你之后手动编辑、删除或撤回了某行对应的条目，该行将保持不变。日志保留最近 200 次更改。

<a id="returning-to-an-earlier-point"></a>

### 回到较早的时间点

在每次会改变知识的运行之前（标签页的运行，无论是否经过审阅；新部分的自动阅读；`knowledge-process` 和 `knowledge-tidy` 命令；整理；以及不经过模型的阅读），追踪器都会创建一个**检查点**：运行开始前其角色的完整状态，以及它当时读到的位置（首次运行前为 *Start of the book*）。Processing 面板中的 **Checkpoints** 按从新到旧的顺序列出这些检查点：追踪器读到的部分、时间、接下来运行的类型，以及它新增和撤回的数量。只列出所在部分位于当前分支上的检查点。

在某一行上点击 **Return to this point**，会撤销该次运行及之后的所有运行：角色及其知识、已处理的部分和自动更改日志都会恢复为检查点时的状态，下一次运行会重新读取该部分之后的内容，包括被撤销运行中的那些部分。你的设置和起始点保持不变。此操作会先询问你，因为检查点之后学到的所有内容都会被撤销，包括之后你手动做出的更改；追踪器当前拥有的状态会保存为一个检查点（*before a return to a checkpoint*），因此你可以再回到它。当某次运行或一系列运行出错时，或者在你恢复了书籍的较早备份，并希望追踪器从你信任的某个时间点重新追赶进度时，可以使用此功能。

追踪器会为每本书保留最近 20 个检查点。它们保存在你的文件中（*Resources*，按书分组），而不在书籍内，因此书籍备份和副本不会包含它们。

当 **Ask before applying** 关闭时，新部分会在最终确定后立即被读取：即生成完成时；如果该书开启了自动注释（及重写）或翻译，则在这些完成后读取，这样模型可以在你阅读时读取你保留的文本并同时工作。它是[部分之后的步骤](../books/story-editor.md#what-follows-a-generated-part)中的一个环节。之后的生成会发现知识已是最新的，不必等待。剩下未完成的部分（你中止的运行，或你关闭的窗口）会在下一次生成之前读取，与以前一样。

模型工作时，一个小型**进度面板**会浮在页面上方。它是**非模态的**：你可以继续阅读和编辑故事，并且可以通过其标题栏**拖动**它。关闭它只会隐藏面板，工作仍会继续（**Cancel** 可以停止工作）。

![进度面板](../../images/plugin-knowledgetracker-progress.png)

模型作答时，面板会实时显示 **What the model is writing**：先是它的推理过程，然后是回答，因此在慢速模型上长时间等待时不会只是一个空白的进度条。请求结束后，同样的文本会保留在 **What the model thought** 下（运行中每个请求各占一块，包含它的回答），即使模型没有提出任何内容且没有打开审阅窗口也是如此。标签页中还保留一个按钮 **Last run: what the model thought**，点击后可以再次打开该面板，让你看到为什么没有添加任何内容。

模型作答后，面板会提示此事，并显示 **Review changes**；处理面板（*3 changes to review*）中也有同样的按钮。**审阅窗口从不自动打开。** 它是一张按角色分组的更改表：

![审阅更改](../../images/plugin-knowledgetracker-review.png)

表格下方的 **What the model thought**（默认折叠）保存了模型在回答之前的推理过程（如果模型发送了推理内容）。它会说明某项更改为何被提出，或某项你预期的更改为何缺失，方便你在应用之前判断更改是否合适。不进行推理的模型在此处不显示任何内容。

| | |
|---|---|
| 复选框 | 更改是否被应用。默认全部勾选；每个角色都有 **Check all** / **Uncheck all**。 |
| **Retract** / **Add** | 撤回会使条目变为旧条目（它会被保留，参见[标签页](#the-knowledge-tab)）。添加则是一个新条目，类型为 *Knows* 或 *Does not know*。添加的文本和类型可以在应用前**编辑**。 |
| 引文 | 部分中显示该更改的原文，以及它所在的部分。若在该部分中找不到引文，会被标记：模型可能编造了它，请在接受前检查。 |

**Apply** 会应用已勾选的更改并继续。**Cancel** 会停止整个系列且不做任何更改：下次会再次提出相同的部分。你取消勾选的添加项会作为带引文的**旧知识**保留（你可以恢复它）；未勾选的撤回则使条目保持原状。模型提出但无法使用的内容（不是询问对象的角色、不存在的条目、没有引文的更改、角色已经知道的内容）会列在 *Left out* 下。已应用的更改带有其所在部分的标记，因此 **Reprocess from here** 可以将其再次撤回。如果你在审阅期间故事发生了变化（例如另一个分支、某个部分被删除），这些更改将不会被应用，你需要重新处理。

部分以每次 **Parts per run**（默认为 1）为单位分批读取；超出模型上下文容量的批次会被截断至能容纳的范围。一个系列会逐批运行，直到最后一个已定型的部分；在需要询问的系列中，模型未发现任何内容的运行会被跳过而不询问。当 **Ask before applying** 关闭时，更改会立即应用，面板会保留日志，每次运行一行。

!!!
该提示词仅在少量场景上针对某个模型进行过测试，测试范围不广：它可以防止角色了解到其并未感知到的内容，但请检查所提出的更改，尤其是那些出现在长场景中的角色。请求会发送至你在下方选择的模型，其费用和隐私政策遵循该服务的规定。
!!!
<a id="tidying-the-knowledge"></a>

## 整理知识

模型会记下每个角色学到的内容。在长篇故事中，这份列表会越来越长，其中的小事也越来越多，而你并不希望每次请求都把它们全部发给模型。**Tidy knowledge**（位于 **Process now** 旁边，需要模型设置）会让模型重新阅读某个角色所知道的内容，并参考故事中最近处理过的部分作为上下文，然后：

- **删除**不值得保留的条目：琐碎的细节、场景中所有人都看到的细节（故事本身已记载）、已被后续事件推翻的内容，以及与另一条目内容重复的内容；
- **合并**关于同一件事的多个条目，合成一条并保留所有事实。

被删除或被合并的条目并不会真正消失：它会变成 *Old knowledge*，并且可以恢复。这些更改会像阅读时的更改一样接受审阅（由 **Ask before applying** 决定），或者立即应用，并记入日志，附带 **Revert** 按钮。

整理过程只能改动模型学到的、且你没有 **lock** 的内容。初始条目、你手动添加或编辑的条目、已锁定的条目以及旧条目永远不会被更改（前两类和已锁定的条目会展示给模型，以便它看出某个条目会与哪些内容重复）。一个很久没有被任何部分提及的秘密，并不构成删除它的理由，提示词中也对此作了说明；模型有疑问时会保留该条目。如果某角色由模型学到的条目少于 **Tidy: from this many items**（8）条，则不会对其进行整理。**Tidy: parts of context**（10）表示模型会读取最近处理过的多少个部分。

**Tidy automatically**（一项设置，默认关闭）会在一次运行结束时自动执行整理，前提是该次运行的更改无需询问即直接应用（即 **Ask before applying** 关闭，因此新部分的自动阅读也一并生效），并且自上次整理以来，模型已阅读了 **Tidy after this many parts**（10）个部分。整理所做的更改会直接应用，并记入日志，附带 **Revert** 按钮，该次运行的日志中也会注明这一点。需要你审阅的运行永远不会自行开始整理；条目过少的角色会被跳过，不会去询问模型。

在命令栏中也可以完成同样的操作：`knowledge-tidy`（`ask true` 可以以列表形式获取更改；此时打开的标签页会显示审阅按钮），以及带有角色和条目编号的 `lock-knowledge` / `unlock-knowledge`。

<a id="settings"></a>

## 设置

*Track a character* 旁边的齿轮图标：

| 设置 | |
|---|---|
| **In prompt** | 将该块插入每次生成的提示词中。开启时，按钮会变为绿色。 |
| **Depth** | 插入位置，以提示词末尾起算的消息数计：`0` 表示放在本轮指令之后，`1` 表示放在指令之前。它永远不会放在系统提示词之前。 |
| **Role** | 以 *System*、*Assistant* 还是 *User* 消息的形式发送。 |
| **Say that nothing else is known** | 封闭世界（closed world）声明行。 |
| **Give what the characters know to the annotation** | 开启（默认）：[用 AI 注释](#annotating-with-what-the-characters-know) 会获得该部分开始时被跟踪角色所知道的内容。 |
| **Process new parts automatically** | 参见 [处理](#processing)。 |
| **Read what the characters learn with the model** | 处理时会询问模型每个被跟踪角色学到了什么，并提出建议。关闭（默认）：处理仅记录谁与谁见过面，不产生任何费用。 |
| **Ask before applying** | 开启（默认）：每项建议都会显示供审阅。关闭：建议会立即应用并记入日志。 |
| **Let the model read earlier parts** | 在阅读新部分时，模型可以阅读某条目所学到的那个部分（条目中写着 "learned in part 12"），以判断它所读到的内容是证实、重复还是与之矛盾，例如原本是道听途说的事，现在亲眼所见。每次请求最多读取同一部分 5 次，较长部分的文本会被截断到能放入上下文的长度，审阅时会显示模型读取了哪些部分。每次读取都会增加一轮与模型的交互，因此默认关闭。无法调用函数的模型会像以前一样读取请求。 |
| **Parts per run** | 一次请求读取多少个部分。数值越大越便宜，但回答会更长，审阅也更困难。 |
| **Tidy automatically**，**Tidy after this many parts** | 整理过程会在一次无需询问即应用更改的运行结束时自动执行，每隔这么多个部分执行一次（10）。默认关闭。 |
| **Tidy: parts of context** | 整理过程读取最近处理过的多少个部分（10）。 |
| **Tidy: from this many items** | 模型学到的、且未被锁定的条目少于此数的角色不会被整理（8）。 |
| **Lorebook for the model** | *Entries the parts activate*（默认：生成这些部分时会使用的条目）、*The whole lorebook*（所有条目；若放不进上下文，则只发送已激活的条目，并在说明中注明）或 *No lorebook*（不使用设定集）。 |
| **Model / Protocol for the extraction** | 留空：使用本书的模型。这项工作用较便宜的模型即可；在只保留一份提示词缓存的服务器上，使用单独的模型可以避免本书的模型被替换掉。 |
| **Separators of this book** | 在场角色字段如何拆分为名字，每行一个（换行即 `\n`）。像 `and` 这样的词会按空格拆分，因此在你添加之前，*Jack and Jill* 仍会被视为一个名字。 |
| **My separators (all books)** | 对你所有的书籍都适用。本书自己的分隔符优先；两者都没有时，使用内置的分隔符。 |

（在模型设置下）**Use these settings for new books** 会将本书的设置保存为一本从未使用过 Knowledge Tracker 的新书的初始设置，包括借助模型读取以及模型和协议，因此新书从第一次运行起就使用你的模型。本书的分隔符仍保留在本书中。**Forget the settings for new books** 会恢复为内置设置。已经在使用跟踪器的书籍保留其各自的设置。

<a id="prompts"></a>

## 提示词

阅读的系统消息（**Knowledge extraction prompt**）和整理过程的系统消息（**Knowledge tidy prompt**）是[继承设置](../books/prompts.md#inherited-settings)：书籍优先使用自己的设置；否则使用其上方最近一个设置了它的文件夹的设置；再否则使用你的设置；最后才使用经过真实模型测试的内置文本。

你可以在书籍的 *Prompts* 标签页中、在 *Extension Settings* 下设置它们，也可以在文件夹的对话框中设置，或为你所有的书籍在 *Settings → Extension Settings → Knowledge Tracker* 中设置（留空时会以灰色显示内置文本）。请保留内置文本的 JSON 回答格式：插件通过它来读取回答。当模型可以读取更早的部分时，插件会添加 `read_part` 的说明，因此你的提示词无需包含这些说明。
<a id="annotating-with-what-the-characters-know"></a>

## 用角色所知的信息进行标注

上面的块可以防止模型在*写作的同时*让角色变得无所不知。这些记录也有助于找出仍然溜进来的疏漏。当模型[为某个部分添加标注](../books/annotations.md#letting-a-model-annotate)时（**Annotate with AI**、一段范围内的部分、自动标注，`/generate-annotation`），追踪器会告诉它该部分中被追踪的角色在**该部分开始时**知道什么。编辑器会标记出那些说出、想到或做出他们并不可能知道之事的角色：*Fiora 直呼 Thomas 的名字；记录显示她从未见过他。* 标注会指出具体的事实。

- **这些事实以该部分为准，而不是以全书结尾为准。** 角色在后面部分才得知的事，在此时尚不为人所知；后面部分撤回的条目，在此前仍然是真的。该部分自身带来的内容（得知了什么、见了谁、其中哪些事不再成立）会单独列出，因此该部分的前半段不会与后半段对照检查。
- **哪些角色。** 被追踪的角色中，凡是出现在该部分的 *Present Characters*（在场角色）中、是其视角人物，或在其文本中被提及的（整词匹配，不区分大小写，别名也算在内）。
- **在任何时候都不是事实的条目**会被排除：你手动撤回的、整理过程删除的，以及你在审阅中拒绝的条目。
- **只依据已记录的内容。** 模型会被告知：记录中没有写到的内容不是事实，因此不会因为追踪器从未获悉的事情而标记某个角色。*Say that nothing else is known*（说明没有其他已知信息）还会在角色见过谁的列表中加上 "(nobody else)"。
- 如果被审阅部分之前的某个部分未被追踪器读取，事实中会注明这一点：角色在那里获知的内容会缺失，此时先运行 **Process now** 会得到更好的审阅结果。
- 这些事实会占用标注请求中的 token，且仅针对含有被追踪角色的部分。若要关闭，请使用 **Give what the characters know to the annotation**。

<a id="the-block-as-a-macro"></a>

## 作为宏使用的块

除了（或代替）自动插入，你也可以使用[{%{`{{command::knowledge-tracker-block::<characters>}}`}%} 宏](../templates/macros.md#commands)自行放置该块。参数是场景中角色的列表，因此模板可以传入该部分的字段：

```
{%{{{command::knowledge-tracker-block::{{presentCharacters}}}}}%}
```

无论 **In prompt** 是否开启，宏都会输出该块，因此使用宏时请将其关闭，否则模型会收到两次。深度和角色设置不适用于宏（该块是包含宏的那条消息的一部分）。若列出的角色均未被追踪，则不输出任何内容。命令宏的结果会与新部分所接续的那个部分一同保存，因此从同一部分进行的第二次生成不会看到你在此期间所做的更改；重新生成（regenerate）和切换候选（swipe）则会再次请求。

<a id="commands"></a>

## 命令

以下用于[命令行](../commands/index.md)及智能体：

| 命令 | |
|---|---|
| `knowledge-status` | 设置以及处理进度。 |
| `list-tracked-characters`, `add-tracked-character`, `update-tracked-character`, `delete-tracked-character` | 被追踪的角色，可按名称、别名或编号指定。 |
| `list-knowledge`, `add-knowledge`, `retract-knowledge`, `restore-knowledge`, `delete-knowledge` | 某个角色的条目，按其在 `list-knowledge` 中的编号指定。 |
| `knowledge-process` | 立即处理（`parts`：最多处理这么多个）。开启模型时，`ask true` 会以编号列表的形式返回模型发现的更改并将其暂存：此时尚未更改任何内容。打开的 Knowledge 标签页会显示 **changes found by a command** 按钮，点击后打开常规审阅（Apply / Cancel）；智能体则使用 `apply-knowledge-changes` 应用这些更改。 |
| `apply-knowledge-changes` | 应用暂存的更改，全部应用或仅应用指定编号的更改（与该标签页审阅中的 **Apply** 相同）。 |
| `knowledge-tidy` | 整理过程。使用 `ask true` 时，它会以编号列表返回更改并暂存（标签页会显示用于审阅的按钮；`apply-knowledge-changes` 用于应用这些更改）。 |
| `lock-knowledge`, `unlock-knowledge` | 锁定某个条目（角色、条目编号），使整理过程不会处理它；或将其解锁。 |
| `knowledge-reprocess` | 从某个部分重新处理（使用其句柄或位置）；会先询问确认。开启模型时，它只是回退状态，`knowledge-process` 则会重新读取各部分。 |
| `knowledge-set-start` | 设置起始点；不指定部分时，则设为全书开头。 |
| `knowledge-tracker-block` | 以文本形式输出该块，供宏使用。 |

命令行按空格拆分参数：若要传入角色列表，请将其放在引号中（`/knowledge-tracker-block "Fiora, Mara"`）。

<a id="storage"></a>

## 存储

所有内容都随书籍保存（保存在其属性中），因此属于[书籍备份](../books/backups.md)和副本的一部分。[检查点](#returning-to-an-earlier-point)则不包含在内：它们是与该书链接的你自己的文件。
