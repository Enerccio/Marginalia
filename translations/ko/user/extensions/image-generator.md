# 이미지 생성기

이야기의 한 부분에 대한 이미지를 만듭니다. 모델이 부분의 내용으로 이미지 프롬프트를 쓰면, 사용자가 이를 편집하고, 이미지 백엔드가 그림을 그립니다. 맞는 그림이 나올 때까지 다시 뽑고, 수락하면 그 그림은 부분 메뉴에서 *이미지*로 직접 추가한 것과 같은 부분의 이미지가 됩니다(이야기에 표시되고 내보내기에도 포함됩니다).

이 확장 기능은 직접 이미지를 만들지 않습니다. **ComfyUI** 서버나 **OpenAI images API**를 쓰는 서버와 통신합니다(stable-diffusion.cpp, LiteLLM 및 많은 호스팅 서비스도 이 API를 씁니다).

<a id="adding-a-backend"></a>

## 백엔드 추가하기

*설정 → Extension Settings → Image Generator Settings*에 백엔드 목록이 있습니다. 하나를 추가(+)하고, 내용을 채운 뒤 *설정* 페이지를 저장하세요.

| 설정 | 역할 |
|---|---|
| Name, Type | 창에 표시되는 이름. **ComfyUI** 또는 **OpenAI images API**. |
| Address | 서버의 기본 주소. 예를 들어 ComfyUI라면 `http://localhost:8188`. |
| Api key | 베어러 토큰으로 전송됩니다. 암호화되어 저장되며 다시 표시되지 않습니다. 새 키를 입력해 교체하거나 **Remove the key**를 누르세요. |
| Model | OpenAI images API 전용: 요청의 `model`. |
| Workflow | ComfyUI 전용: **Save (API Format)**로 ComfyUI에 저장한 워크플로. `{{prompt}}`, `{{negative}}`, `{{seed}}`, `{{width}}`, `{{height}}`을 들어갈 자리에 적으세요. |
| The server is on this machine or on my network | 로컬 네트워크 주소를 허용합니다. 클라우드에 있는 서버라면 끈 상태로 두세요. 그러면 서버가 사용자 자신의 컴퓨터를 호출하도록 만들 수 없습니다. |
| Width, Height, Negative prompt | 창을 열 때 처음 쓰는 값입니다(한 이미지에 대해서는 창에서 바꿀 수 있습니다). |
| Timeout | 이미지 한 장을 기다리는 시간. |
| Release after idle | [한 GPU](#one-gpu-for-the-model-and-the-images) 참고. |

![설정의 백엔드](../../images/plugin-imagegenerator-settings.png)

**Test connection**은 주소와 키를 확인합니다.

이 패널에는 모든 프롬프트 앞에 붙는 **Style**(책의 분위기, 예를 들어 *watercolor, soft light*)과 **Instruction for the prompt writer**도 있습니다. 후자는 모델이 부분으로부터 프롬프트를 쓸 때 받는 지시문입니다. 비워 두거나 바꾸지 않으면 내장된 지시문을 씁니다.

<a id="making-an-image"></a>

## 이미지 만들기

![부분 메뉴의 Generate image](../../images/plugin-imagegenerator-menu.png)

1. 부분 메뉴에서 **Generate image**를 고릅니다. 창의 모델(기본은 책의 모델이며, 마지막 선택이 기억됩니다)이 부분의 프롬프트를 쓰기 시작합니다. **Abort**로 멈추거나, 프롬프트를 고치거나, **Write the prompt with the model**을 눌러 다시 쓰게 할 수 있습니다. 다시 쓰기 전에 다음 항목을 채울 수 있습니다.
   - **Send lorebook entries** - 책의 로어북(및 하위 로어북)의 항목이 생성 때와 같이 모델에 전달되므로, 모델이 등장인물과 장소의 모습을 알 수 있습니다. 항목은 필터(본문, 지시문, 장면 설정, 시점, 등장인물, 또는 *Details*)가 부분에서 발견될 때 전달됩니다. 항상 켜져 있는 항목도 포함됩니다. 모델의 컨텍스트에 들어가는 만큼만 보내지며, 몇 개가 빠졌는지 알림이 표시됩니다. 선택은 기억됩니다.
   - **Details** - 그림에 무엇이 보여야 하는지, 또는 어떻게 보여야 하는지(*at night, close up on her face, the red dress*). 프롬프트 작성기가 이를 따릅니다. 이 창에만 적용됩니다.
2. 백엔드를 고르고 **생성**을 누릅니다. *Size and negative prompt* 아래에서 이 창의 크기와 네거티브 프롬프트를 바꿀 수 있습니다.
3. 이미지가 나타납니다. **Reroll**은 새 시드로 다른 이미지를 만들고, **Discard**는 버리고, **Accept**는 부분에 추가한 뒤 창을 닫습니다. **Abort**는 만들어지고 있는 이미지를 멈춥니다(ComfyUI에는 작업 중단이 전달됩니다).

![모델이 쓴 프롬프트가 있는 창](../../images/plugin-imagegenerator-prompt.png)

![Accept, Discard, Reroll 버튼이 있는 이미지](../../images/plugin-imagegenerator.png)

열린 부분에는 새 이미지가 텍스트 아래에 바로 표시됩니다.

<a id="one-gpu-for-the-model-and-the-images"></a>

## 모델과 이미지를 위한 GPU 하나

GPU가 작으면 언어 모델과 이미지 모델을 함께 불러올 수 없습니다. 확장 기능은 메모리를 관리하지 않습니다. 대신 각 백엔드에는 직접 설정하는 두 가지 요청 목록을 둘 수 있습니다.

- **첫 이미지 전** - 창이 그 백엔드를 쓰기 시작할 때 한 번 보냅니다. 예를 들어 언어 모델을 내리고 이미지 모델을 올리라는 요청을 프록시에 보내는 것입니다.
- **마지막 이미지 후** - 수락, 버리기, 창 닫기 때, 또는 마지막 이미지 이후 **Release after idle** 초가 지났을 때 보냅니다(잊힌 창이 GPU를 붙잡고 있지 않도록 하며, 0이면 끕니다). ComfyUI의 경우 `POST <address>/free` 요청에 본문 `{"unload_models": true, "free_memory": true}`을 실을 수 있습니다. 프록시의 경우 언어 모델을 다시 불러오는 요청입니다.

LiteLLM 뒤에서 라우터 모드로 `llama-server`을 쓴다면, *첫 이미지 전* 요청이 프록시를 통해 언어 모델을 내릴 수 있습니다. [다른 모델을 위해 GPU 비우기](../prompt-cache.md#freeing-the-gpu-for-another-model)를 보세요.

두 시점 모두 **요청 목록**을 받으며, 요청은 차례대로 보내집니다(**Add a request**로 하나를 추가하고, 휴지통으로 하나를 지웁니다). 교체에는 보통 여러 요청이 필요합니다. 예를 들어 언어 모델을 내리고, 이미지 서버를 시작하고, 이미지가 끝나면 서버를 멈춥니다. 각 요청에는 주소, 메서드(기본값 `POST`), 헤더(`Name: value`, 한 줄에 하나), 본문, **timeout**(비우면 60초, 최대 600초이며, 큰 모델을 불러오는 서버에는 더 길게 주세요), **Wait afterwards**(응답 후 대기할 초. 응답은 했지만 아직 바쁜 서버용)가 있습니다. 헤더는 API 키처럼 암호화되어 저장됩니다(요청에는 흔히 `Authorization: Bearer ...`가 실립니다). 백엔드는 다시 뽑는 동안 계속 점유되므로, 교체 비용은 첫 이미지만 냅니다. 모델 앞의 프록시가 모델 이름으로 교체한다면 둘 다 비워 두세요.

*첫 이미지 전* 목록의 요청이 실패하면 나머지는 보내지 않고 이미지 작업도 멈춥니다. 메시지에 어느 요청이 실패했는지 나옵니다(*Request 2 of 3: ...*). 꽉 찬 GPU에 아무것도 올리지 않기 위해서입니다. *마지막 이미지 후* 목록은 요청 하나에 무슨 일이 생기든 **끝까지** 보내집니다(모든 서버가 멈춰야 하므로). 첫 번째 실패는 경고로 표시됩니다. 이전 버전의 단일 요청으로 저장된 백엔드는 그 요청을 목록의 첫 요청으로 보여 줍니다.

**한 GPU를 여러 사람이 쓸 때.** 같은 서버 주소(`http://host:port`)를 쓰는 모든 사용자의 백엔드는 하나의 관문을 통과합니다. *첫 이미지 전* 요청은 처음 시작하는 창을 위해, *마지막 이미지 후* 요청은 마지막 창이 끝날 때 한 번 보내집니다. 그래서 한 창을 닫아도 다른 사람의 이미지 아래에서 모델이 내려가지 않으며, 이미지는 한 번에 하나씩 만들어집니다(두 번째 창은 차례를 기다립니다). 요청은 가장 먼저 시작한 사용자와 마지막까지 남은 사용자의 것입니다.

백엔드는 자신이 돌아가는 GPU를 지정할 수도 있습니다(**GPU (name)**). 같은 GPU를 지정한 백엔드는 주소가 달라도 서로를 기다립니다. 여기에는 [오디오북](audiobook.md)의 백엔드도 포함됩니다(한 카드에 음성 서버와 이미지 서버가 있는 경우). 다른 모델이 필요한 사용자의 백엔드는 다른 작업이 끝날 때까지 기다린 뒤 자신의 요청을 실행합니다. 남의 적재 작업에 끼어들지 않기 위해서입니다. 비워 두면 같은 주소로 가는 요청끼리만 서로 기다립니다.

<a id="what-is-not-done"></a>

## 하지 않는 것

- 백엔드는 책별이 아니라 사용자별입니다.
