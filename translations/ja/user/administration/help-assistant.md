# ヘルプアシスタント

ヘルプアシスタントは、Marginaliaについてマニュアルに基づいて答えるチャットです。管理者は、アシスタントが使うモデルを選び、質問できるユーザーの[権限](permissions.md)に **ヘルプアシスタント** の権限を与えます（管理者は常に利用できます）。ユーザーは自分用のモデルを必要としません。権限が導入されたとき既に存在していたユーザーは、その時点でアシスタントが有効になっていればこの権限を得ます。新しいユーザーには権限がありません。

利用できるユーザーがウィンドウ右下に丸いロボットのボタンを見ることになります。それを押すとチャットが開きます。パネルには、どのモデルが答えるのか、そしてユーザーの制限が適用される場合には警告が表示されます（[誰が支払うか](#who-pays)を参照）。モデルはマニュアルで答えを探し（検索してページを読むことができます）、使用したページを[公開されたマニュアル](https://enerccio.github.io/Marginalia/)へのリンクとして示し（リンクは新しいタブで開きます）、説明します。モデルは何も変更せず、ユーザーが許可しない限りユーザーの本も見ることはありません（[あなたの本](#your-books)を参照）。何かが失敗したときには、何が起きたのかを確認することもでき（[問題が起きたとき](#when-something-goes-wrong)を参照）、許可されていれば、ユーザーを目的の場所へ案内することもできます（[道案内](#showing-the-way)を参照）。会話はユーザーがログアウトするまで保持されます（パネルを閉じても、ページを再読み込みしても保持されます）。ほうきのボタンで会話を消去します。マニュアルが翻訳されている場合は、ユーザーのインターフェースの言語でマニュアルを読み、リンクもその言語のマニュアルへ導きます。翻訳されていないページは英語で読まれます。

![ヘルプアシスタントが質問に答えている様子](../../images/help-assistant.png)

ボタンはユーザーがMarginaliaを開いたときに表示されます。モデルと制限の警告は、パネルを開くたびに読み込まれます。権限を取り消したりモデルを削除したりすると、既にそのページを開いているユーザーは、ページを再読み込みしたとき（またはパネルを開いたとき）にボタンを失います。

<a id="settings"></a>

## 設定

**管理 → ヘルプアシスタント** を開きます。

![ヘルプアシスタントのタブ](../../images/admin-help-assistant.png)

| 設定 | |
|---|---|
| **モデル** | *あなた自身の*[モデル](../inference-providers.md)のひとつで、ユーザーと共有するかどうかは問いません。他の管理者が共有しているモデルは一覧に表示されません。 |
| **管理データの読み取りを許可する** | 管理者が求めた場合に限り、アシスタントが拡張機能の状態とそのログ、データベースのバックアップ、その他の管理ページのデータを読めるようにします（[管理データ](#administration-data)を参照）。初期状態ではオフです。 |
| **管理者向けプロンプト**、**その他のユーザー向けプロンプト** | 質問のたびにモデルが受け取る指示です。[プロンプト](#prompts)を参照してください。 |

次の二つの設定はユーザーごとに異なり、そのユーザーの **ヘルプアシスタント** [権限](permissions.md#settings-of-a-permission)にあります（**管理 → ユーザー** の鍵のボタンで開きます。どちらも初期状態ではオフです）。

| 権限の設定 | |
|---|---|
| **制限を適用する** | 共有モデルの場合のみ有効です（[誰が支払うか](#who-pays)を参照）。 |
| **インターフェースの操作を許可する** | ユーザーが何かの場所を示すよう求めたとき、アシスタントがセクションを開いたり、タブを選んだり、何かを追加するためのダイアログを開いたりできるようにします（[道案内](#showing-the-way)を参照）。 |

このような権限を持たない管理者には、両方ともオフの状態で答えます。

設定は **保存** で保存されます。アシスタントは[プロトコル](../protocols.md)を使わずにモデルへ問い合わせるため、モデル自身の設定が適用されます。モデルが削除されたとき、またはその所有者がもう管理者でなくなったときには、自動的に動作を停止します。そのため、一般ユーザーの所有するモデルが誰にでも渡ってしまうことはありません。

<a id="what-the-assistant-sees-of-the-screen"></a>

## アシスタントが画面で見るもの

モデルは、ユーザーが今何をしているかを見ることができます（「ここ」や「これ」についての質問では、そのように伝えられます）。どのセクション、タブ、ダイアログが開いているかを、画面の各部分についての短い説明として受け取ります。例えば、開いている本のタイトルとその開いているタブ、または開いているダイアログのタイトルです。開いていないタブは一覧に示されるだけで、質問に必要な場合にのみ読まれます。開いているフォームについては、今何が問題になっているかも受け取ります。具体的には、フォームが無効だとマークしたフィールドとその表示メッセージ、空の必須フィールド、そしてフォームが複数のフィールドにまたがって確認する内容です（モデルの場合は、応答が文脈より小さくなければならない、など）。受け取るのは入力されたフィールドの *名前* だけで、入力内容は受け取りません。物語の本文、ロレブックの項目、APIキーやパスワードは決して受け取りません。

![新しいモデルのフォームをまだ保存できない理由を説明するアシスタント](../../images/help-assistant-form.png)

<a id="your-books"></a>

## あなたの本

アシスタントのパネルには **アシスタントに私の本を見せる** というチェックボックスがあります。初期状態ではオフで、各ユーザーが自分で設定します（設定に保存されます）。その下の注記で意味を説明しています。アシスタントはフォルダ名、タイトル、説明、本の執筆設定を読み、本のテキストを検索しますが、物語の本文は決して読みません。読んだ内容は、回答するAIに送られます。それは上で選んだモデルであり、あなたの管理外のサービスである場合は、その旨をユーザーに伝えてください。

![本についてのチェックボックスがあるアシスタントのパネル](../../images/help-assistant-books.png)

オンにすると、モデルは三つの機能を受け取ります。いずれも読み取り専用で、質問したユーザー自身の本にのみ働きます。

| 機能 | |
|---|---|
| `list_folder` | フォルダ直下のサブフォルダと、それぞれの下にある本の数、そしてそのフォルダの本のタイトルと説明です。`Sci-fi/Expanse` のようなパスはフォルダを指定し、何も指定しなければ最上位になります。 |
| `search_books` | タイトルや説明の語、または物語の本文から本を探します。必要に応じてフォルダ内に絞り込めます（「真の恋人たちについての本はどこ？」）。一致した場所とフォルダを示しますが、見つかった本文は返しません。 |
| `get_book_settings` | 本の言語、視点、時制、文体と、それぞれの出どころ（本そのもの、フォルダ、ユーザー設定、組み込みの初期値のいずれか）です。プロンプトは *カスタムの文章* か *組み込みの文章* のどちらかとして、その出どころと共に伝えられます。 |

アシスタントは何も変更、移動、作成できません。一覧は途中で打ち切られ（100件、一致は20件まで）、説明文は短くされます。

<a id="when-something-goes-wrong"></a>

## 問題が起きたとき

ユーザーが何かの失敗を伝えたとき（「エラーが出る」「保存されない」「モデルが応答しない」など）、アシスタントはMarginaliaがユーザーに表示した内容を読むことができます。直近のエラー、モデルプロバイダーへの失敗したリクエスト（誤ったキー、存在しないモデル、制限到達、タイムアウトなど）、警告、保存できなかったフォームのメッセージを、新しいものから順に、どれくらい前に起きたかと共に確認できます。メッセージの意味と直すべき点を説明し、開いているフォームについては変更すべきフィールドを示します。

記録される内容と、その保存先は次のとおりです。

* ユーザーに通知としてエラーや警告として表示されたすべてのもの、および失敗した検証のメッセージは、セッションの間保持されます（直近の20件）。
* 予期しない失敗（スタックトレースのダイアログが出るもの）と、プロバイダーへの失敗したリクエストは、ブラウザのタブにも保持されます（直近の3件、そのタブのセッションストレージに）。そのため、ページを再読み込みしたりセッションが期限切れになったりした後も残っています。

アシスタントが受け取るのは、ユーザーが見たテキストと、失敗の場合は例外の名前とメッセージです。スタックトレースは含まれません。各テキストは400文字で打ち切られ、キーやトークン、パスワードのように見える部分は取り除かれます。ただし、メッセージの本文には、プロバイダーやシステムが返した内容の一部（例えば、リクエストに対するプロバイダーの応答）が含まれたままになることがあります。回答するモデルは、あなたが選んだものです。それが外部のプロバイダーである可能性があることを、[選ぶとき](#settings)に心に留めておいてください。
<a id="showing-the-way"></a>

## 画面の案内

ユーザーの権限で**インターフェースの操作を許可する**がオンになっていると、アシスタントは利用者が頼んだときに画面の中で次のことができます
（「ロアブックはどこ？」「バックアップの画面に連れて行って」「モデルはどう追加する？」など）。セクション（Books、Lorebooks、Settings など）を開く、
Admin ページを開く（管理者だけが利用できます）、Settings・Admin ページ・ストーリーエディターのタブを選ぶ、または本、モデル、プロトコルを追加するダイアログを開くボタンを押す、といったことです。ダイアログは開くだけで、利用者が入力して確定するまで何も作成されません。また、別のダイアログが開いているときには提示されません。アシスタントは何をしたかを利用者に伝えます。
それ以外のことはできません。他のボタンを押す、入力する、保存する、削除する、生成する、ダイアログを閉じる、ログアウトする、といったことはしません。利用者が開けないものは、アシスタントに開かせることもできません。アシスタントは自分から動くことはなく、頼まれたときだけ動きます。
画面の移動がロックされている場合（開いているセクションに未保存の変更がある、本を生成中である、など）は移動できません。

![アシスタントが依頼に応じて Database Backups タブを開いたところ](../../images/help-assistant-navigate.png)

この許可をオンにすると、画面にある要素の名前と、それが何を提供しているかの情報もモデルに伝わります。これは [アシスタントが画面から見る情報](#what-the-assistant-sees-of-the-screen) と同じ種類の情報です。

<a id="administration-data"></a>

## 管理データ

ユーザーの権限で**管理データの読み取りを許可する**がオンになっていると、アシスタントは管理者が頼んだときに Admin ページのデータを読むことができます（「なぜ Side Query が動かないの？」「最後のバックアップはいつ？」など）。読めるのは管理者だけで、それ以外の人は設定に関係なく読めません。読むたびに、この確認は改めて行われます。

| 項目 | 読む内容 |
|---|---|
| Extensions | インストールされている各[拡張機能](../extensions/index.md)のバージョン、有効かどうか、あなたが停止したか起動に失敗したか、そして検証の結果 |
| 拡張機能のログ | そのログの最後の数行（既定では 40 行、最大 200 行）。**Admin → Extensions → Log** と同じもの |
| Users | 利用者の数、管理者の数、ロックアウトされている人の数。名前は含みません |
| Database backups | データベースのサイズ、バックアップの数と最新のバックアップの作成日時、スケジュール、復元待ちかどうか |
| Cleanup | [クリーンアップ](cleanup.md)で何が削除されるか（実際には何も削除されません）と、それを妨げているもの |
| Application | Java のバージョン、使用中のメモリ、アプリケーションが起動してからの時間 |

読み取り専用です。アシスタントはここで何かを開始、停止、削除することはできません。これらのデータはすべて、回答するモデルに送られることに注意してください。そのモデルは外部のプロバイダーのものかもしれません。また、拡張機能のログには拡張機能が書き出したテキストが含まれることがあります（ログの 1 行は 400 文字で切り詰められ、キー、トークン、パスワードは取り除かれますが、それ以上の加工はされません）。そのため、この設定は、あなたがオンにするまで無効になっています。

<a id="prompts"></a>

## プロンプト

プロンプトは 2 種類あります。管理者向け（Admin ページについて質問してよい）と、それ以外の全員向け（管理は管理者の仕事だと伝えられる）です。どちらも既定の内容で埋められています。文章を変えて保存することができ、**Reset to default** を押すと既定の内容に戻ります。空のプロンプトや既定と同じプロンプトは「既定」として保存されるので、Marginalia の新しいバージョンに合わせて改善されます。自分で変更したプロンプトは、自分で最新に保つ必要があります。

プロンプト内の `{{manualIndex}}` は、マニュアルのページの一覧（パス、タイトル、そのページの内容）で置き換えられます。これによってモデルは読めるページを知ることができます。これを省くと、モデルはページを検索でしか見つけられません。マニュアルで調べること、マニュアルに載っていない質問はそう伝えることという指示は残してください。そうしないと回答の信頼性が下がります。エラーを読むツール、画面を移動するツール、管理データを読むツールのための規則は、Marginalia がプロンプトに追加します（プロンプトに書き込んでおく必要はありません）。また、許可されているツールの分だけ追加されます。

<a id="who-pays"></a>

## 費用の負担

利用者はモデルやその API キーを見ることはありません。質問はアプリケーションを通して送られます。

| モデル | 利用者の権限の**制限を適用する** | 何が起こるか |
|---|---|---|
| 共有 | オン | 質問は、共有モデルへの他のリクエストと同じように扱われます。利用者に設定した[制限](../inference-providers.md#limits-of-shared-providers)が確認され、トークンは利用者の使用量に加算されます。制限に達した利用者（またはモデルの利用を許可されていない利用者）は回答を受け取れません。 |
| 共有 | オフ | モデルの所有者が費用を負担します。利用者の制限は無視され、利用者について何も数えられません。 |
| 共有でない | （影響なし） | モデルの所有者が費用を負担します。制限はなく、利用者について何も数えられません。そのモデルはアシスタントだけが使用します。 |

あなた自身の質問も同じように数えられます。あなたにとっては、このモデルも他のモデルと同じです。
