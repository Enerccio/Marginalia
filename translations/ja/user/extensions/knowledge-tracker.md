# ナレッジ・トラッカー

物語の登場人物が何を知っていて、何を**知らない**かを記録し、プロンプトに組み込みます。指示で防がない限り、モデルは登場人物に、会ったことのない人物の名前、職業、顔などを知っているように書きがちです。ナレッジ・トラッカーを使うと、プロンプトには場面に登場する追跡対象の人物ごとに、その人物が知っていることと、それ以外は何も知らないことが書き込まれます。

!!!
追跡する人物は、あなたが選びます。タブに追加した人物だけがモデルに説明され、しかもその人物が書かれているパートの*現在の登場人物*に含まれている間だけです。物語の本文から推測されることはありません。
!!!

<a id="the-knowledge-tab"></a>

## Knowledgeタブ

[ストーリーエディタ](../books/story-editor.md)の左サイドバーには、*Outline*の隣に**Knowledge**タブが追加されます。変更内容はすべて、変更するたびに本に保存されます。

![Knowledgeタブ](../../images/plugin-knowledgetracker.png)

**Track a character**では、**name**(名前)を入力し、必要に応じて**aliases**(別名)も入力できます。別名とは、パートの*Present Characters*欄でその人物が書かれる別の名前のことで、カンマで区切ります。名前または別名は、追跡対象の人物1人だけに属することができます。

**Import from the Character Tracker**(**Track a character**の隣の人物アイコン)を使うと、同じ本の[キャラクター・トラッカー](character-tracker.md)にある人物の追跡を開始できます。この機能は、まだ追跡していない人物(名前または別名)を、キャッチコピーとともに一覧表示します。最初はすべてチェックが入っています。除外したい人物のチェックを外し、**Import**を押してください。取り込まれるのは名前だけです。キャッチコピーとメモは人物の説明であり、その人物が知っていることではないため、取り込まれません。**Their relationships count as meetings**をオンにすると、取り込まれた人物は、キャラクター・トラッカーで関係のある人物と会ったことになります。その人物たちは、あなたが書いたかのように、その人物の**Has met**リストに書き込まれます(そのため、処理後も残ります)。

**Who has met whom**(握手のアイコン、取り込み機能の隣)を使うと、追跡対象の人物同士の出会いを、名前を書かずに一度に設定できます。左側で人物を選ぶと、右側には追跡対象の他のすべての人物にチェックボックスが表示されます。選んだ人物がその人物と会っている場合にチェックが入ります。チェックを入れると出会いを追加し、外すと削除します。変更はそのたびに即座に保存され、ウィンドウを閉じるとカードに反映されます。出会いは一方向です。Fiora で Thomas にチェックを入れても、Thomas で Fiora にチェックは入りません。ただし**Mutual**にチェックを入れると、チェックや解除はすべて両方向に同時に行われます。二人がすでに互いを知っている場合は、この方が早く設定できます。(これは、チェックをオンにしている間に行った変更に適用されます。すでに設定されている出会いには適用されません。)チェックを入れた出会いはあなたのものとして扱われ、処理後も残ります。物語が示している出会いのうち、あなたが外したものは、そのパートを再度読み込むと戻ってきます。この機能を使うには、追跡対象の人物が少なくとも2人必要です。

カードの矢印を押すと、その人物が何を知っているかを確認できます。

| | |
|---|---|
| **Knows**(緑) / **Does not know**(赤) | 人物、場所、秘密、出来事など、何についてでも短い一文で書きます。例:*ピーターは公爵に対する陰謀を知っている*、*フィオラはトマスが自分の父親であることを知らない*。登場人物が**知らない**ことは、明示的に書いてください。モデルはそれを尊重します。 |
| 順序と**#12** | 新しい知識が上に表示されます(古い知識も含みます)。モデルが学習した項目の末尾には、学習元のパートの小さな番号が付きます(例:**#12**)。クリックすると、物語がそのパートまでスクロールし、そのパートが点滅します(スマートフォンでは、先にドロワーが閉じます)。あなたが書いた項目には番号がありません。また、現在のブランチにないパート(別のブランチにあるか、削除されたパート)から学習した項目にも番号は付きません。 |
| **Add knowledge** | 項目を追加します。すぐに有効になります。一つの考えだけにしてください。二つのことを述べる項目(*トマスが誰かを知らない、一度も会ったことがない*など)は、どちらか一方が正しくなくなった時点で撤回されます。**edit**ボタンで、テキストと種類を変更できます。 |
| **Retract**(斜線の入った円) | その項目はもう真実ではありません(例:二人が会った後の*トマスには会ったことがない*)。項目は削除されず、*古い知識*になり、モデルに送信されなくなります。 |
| **Lock**(南京錠、モデルが学習した項目に表示) | [整理パス](#tidying-the-knowledge)は、ロックされた項目を一切参照しません。残しておくべきもの、たとえば裏切りや秘密に使ってください。物語がロックされた項目と矛盾することはあります(例:記憶を失う人物)。その場合、物語を読み込むと、通常どおりその項目は撤回されます。 |
| **Delete** | 確認の後、項目を完全に削除します。Retractは項目を残すので、迷ったらRetractを使ってください。 |
| **Select items**(**Add knowledge**の隣) | 多くの項目をすばやく削除します。その人物のすべての項目(古い項目を含む)にチェックボックスが表示されます。**Select all**/**Deselect all**でチェックを全て入れる/全て外し、**Delete selected (n)**で、確認の後、チェックした項目を完全に削除します。**Cancel**で選択を解除します。 |
| **Has met** | [処理](#processing)によって記録された、その人物が会った人々です。処理は、人物ではない名前も記録することがあります(現在の登場人物欄にあるメモなど)。その場合は**Edit**を開き、**Has met**リストを変更してください。名前はカンマで区切って一つずつ書きます。あなたが書いた名前は、物語を再度読み込んでも残ります。削除した名前は、その名前が見られたパートを再度読み込んだときにのみ戻ってきます。 |
| **Old knowledge (n)** | デフォルトでは折りたたまれています。古い各項目には、なぜ古いのかが表示されます。*retracted*(撤回:モデルが撤回した場合は、撤回を行ったパートの番号も表示されます)、*declined in a review*(レビューで却下)、*tidied*(整理済み)のいずれかです。古い項目は**copied**(コピー)、**edited**(編集)、**restored**(復元:再びアクティブになり、以後モデルに送信されます)、または削除できます。 |

<a id="mass-changes"></a>

### 一括変更

**Mass changes**ボタン(**Track a character**の隣のリストアイコン)を押すと、ウィンドウが開きます。ウィンドウには、追跡対象のすべての人物と、古い項目を含むそのすべての項目が、チェックボックス付きのグリッドで表示されます。表示される内容は、種類、テキスト、状態(*Active*、または古い項目の場合は*retracted*、*declined in a review*、*tidied*)、由来(*Initial state*、*Written by hand*、*Learned from the story*)、学習元のパートです。好きなだけ複数のグリッドで項目にチェックを入れられます(グリッドのヘッダーにあるボックスは、そのグリッドのすべての項目にチェックを入れます。下部のバーにある**Select all**/**Deselect all**は、すべての人物のすべての項目を対象にします)。その後、次の操作を行えます。

| | |
|---|---|
| **Retract selected (n)** | チェックしたアクティブな項目を古い知識にします。これは、一人の人物に対して**Retract**を使うのと同じです。 |
| **Restore selected (n)** | チェックした古い項目を、再びアクティブにします(以後、モデルに送信されます)。 |
| **Delete selected (n)** | 確認の後、チェックした項目を完全に削除します。 |
| **Copy selected (n)** | チェックした項目を、すべての人物から、別の人物に貼り付けるためにコピーします。 |
| **Paste (n)**(すべての人物のヘッダーにあります) | コピーした項目を、その人物に追加します。貼り付けた項目は、手で書かれたものとして扱われます(最初から持っていた項目は、初期状態のままです)。種類、ロック状態、古いかどうかは保持されます。その人物がすでに持っている項目(同じ種類とテキスト)はスキップされます。コピーした項目は、次にコピーするまで残ります。ウィンドウを閉じた後も残るので、複数の人物に貼り付けられます。 |

ボタンに表示される数字は、それぞれがチェックした項目のうち何件を変更するかを示します。変更後もチェックは残るので、撤回した項目をそのまま削除できます。

ウィンドウの上部にある**Export to JSON**は、本で追跡している人物(名前、別名、種類・状態・由来・ロックを含む項目、会った人々)を、ファイルとしてダウンロードします。処理の内容は含まれないので、どの本にも使えます。**Import from JSON**は、そのようなファイルを本に読み込み、追加のみを行います。本がすでに追跡している名前(名前または別名として)を持つ人物には、まだ持っていない別名、項目、会った人々が追加されます(同じ種類とテキストの項目はスキップされます)。それ以外の人物は、新しく追跡対象になります。他の人物がすでに持っている別名は、除外されます。取り込まれた項目は、この本の中に元となるパートがありません。そのため、再処理によって削除されることはありません。モデルが学習した項目は、手で書かれたものとして扱われます。古い項目は古いままです。取り込み後に表示されるメッセージには、追加または更新された人物の数と、追加された項目の数、または既に存在していた項目の数が表示されます。
<a id="what-goes-into-the-prompt"></a>

## プロンプトに入るもの

追跡対象のキャラクターのうち現在の場面に登場しているものごとに、プロンプトには次のようなブロックが追加されます。

```
What the characters of this scene know. A character acts only on the knowledge listed for it:

Fiora knows: Mara, a courier of the Guild of Lamps and the sister of her friend Nell; she owes the Guild of Lamps forty crowns.
Fiora does not know: that her father is alive, or that Thomas is her father.
Fiora has met: Mara.
Fiora is currently with: Mara, Thomas.
Fiora has never met or heard of anyone else in this story and knows nothing else of its secrets, plans or events.
```

送られるのは有効な項目だけです。最後の行（**closed world** 行）は、モデルがキャラクターに持たせるべきでない知識を与えてしまうのを防ぐためのものです。この行が扱うのは、物語によって語られること（人物、場所、秘密、計画、出来事）であり、その世界の人なら誰でも知っていること（キャラクターが自分の町を知っていることなど）ではありません。そのため、キャラクターは自分の町のことは知っています。この行は設定で無効にできます。追跡対象であっても現在の場面に登場していないキャラクターには、何も追加されません。「知らない」と書いた行すら追加されません。

<a id="who-is-present"></a>

### 現在の登場人物

ブロックは、パートの **Present Characters** フィールドから作られます。このフィールドは自由記述なので、次のように緩やかに読み取られます。

- 括弧で囲まれた文字は無視されます。`Tomáš (tired), Mizuki` は Tomáš and Mizuki として扱われます。
- 名前は **separators**（区切り文字。初期設定は `,` `;` 改行、`/`、`|`、`、` `，` `；`）で分割されます。
- ` - ` または `:` の後ろにあるものはメモとみなされ、捨てられます（`Mara - wounded`）。
- 大文字と小文字、アクセント記号、先頭の *the* は区別されません。
- 名前は **as a whole**（全体として）一致しなければなりません。*Mara's brother* は *Mara* とは一致しません。キャラクターを複数の書き方で記述する場合は、別名（aliases）を使ってください。一致し損ねた場合はブロック一つが抜けるだけで済みますが、誤って一致すると場面にいないキャラクターの記述が入ってしまう、という考え方です。

*Point of View* フィールドは単独では読み取られないため、視点人物も現在の登場人物に必ず書いてください。

<a id="processing"></a>

## 処理

プラグインは物語の流れに沿って動きます。**Processing**（処理）は、アクティブなブランチのパートを順番に、**start point**（開始点）から読み進め、**cursor**（カーソル、最後に読んだパート）を保持します。モデルを使わない場合は、誰が誰に会ったかを記録します。追跡対象のキャラクターは、現在の登場人物フィールドで一緒に書かれたすべての名前の人物に会ったものとみなされ、ブロックにはその一覧が記載されます。モデルを使う場合は、キャラクターが **learned**（知ったこと）も見つけます（[キャラクターが知ったことの読み取り](#reading-what-the-characters-learn) を参照）。

![処理パネル](../../images/plugin-knowledgetracker-processing.png)

タブ上部のパネルには、現在の進行状況が表示されます。新しいパートが確定すると（本に自動注釈と再草稿がある場合はそれらの後に）、パネルは自動的に再読み込みされます。ほかの方法でパートを追加、編集、削除した場合は、**Refresh** ボタン（歯車の横の矢印）を押して、物語を読み直してください。パネルには次の項目があります。

- **Process now**：まだ処理されていないパートを読み込みます。
- **Process next part**：まだ処理されていない最初のパートだけを、一度に一つずつ読み込みます（モデルを使う場合は、*Parts per run* の値にかかわらず、そのパートに対するリクエストが一回だけ送られます）。設定を試したり、一つのパートについてモデルが何を見つけるかを確認したりするときに使います。`parts` を 1 に設定した `knowledge-process` コマンドも同じ動作をします。
- **Start point**：処理を開始するパート（初期値は *Start of the book*）。それより前のパートは読み込まれることはありません。開始点を前に戻すと、新しい開始点からパートを読み直します。後ろに進めると、読み込み済みの結果はそのまま残ります。
- **Processed parts**：読み込まれた最新のパート。**処理された後にテキストが変更された**パート（編集または再草稿されたもの）には印が付きます。ただし、それによって自動的に再処理されることはありません。行のボタン **Reprocess from here** は、そのパートとそれ以降のパートから得られた内容を取り消し（手で書いた項目と取り消し記述は残ります）、もう一度読み込みます。

キャラクター一覧を下にスクロールすると、これらのボタンに加えて、**Process now**、**Process next part**、**Tidy knowledge** がタブ上部のバーにも表示されるので、上に戻らなくても処理を実行できます。

**Process new parts automatically** がオンのとき（初期状態ではオフ）、プラグインは次のことを自動的に行います。

- 生成が始まる前に、前回以降に書かれたパートが処理されるので、プロンプトは誰が誰に会ったかを把握できます。*Regenerate* や swipe で置き換えられようとしているパートには手を付けません。モデルを使う場合は、**Ask before applying** がオフのときに限りモデルで読み込みます（下記参照）。そうでなければ、誰が誰に会ったかだけを記録し、モデルが見つけた内容の確認はタブから開始します。生成の途中で確認を強制されることはないためです。
- パートが **再生成** され、新しいテキストが届くと、古いテキストから得た内容は取り消されます。
- swipe を行ったり別のブランチに切り替えたりすると、カーソルは両方のブランチが共有する最後のパートまで戻ります。
<a id="reading-what-the-characters-learn"></a>

## 登場人物が知ったことを読み取る

設定で **Read what the characters learn with the model** にチェックを入れます。そのうえで **Process now** を押すと、モデルに対して次のパートについて問い合わせます。対象は、登場している追跡キャラクターそれぞれが**何を知ったか**です。見たこと、聞いたこと、読んだこと、伝えられたことが含まれます。また、物語と矛盾する項目も示します(例: 出会った後なのに *has never met Thomas*)。リクエストには、パート(その視点と登場キャラクター)、追跡キャラクターが今知っていること、そして必要に応じてロアブックが含まれます。モデルには、その世界の人物なら当然知っていること(王が誰か)や、キャラクター自身から自然に導かれること(サキュバスは尻尾があることを知っている)は除外するよう指示され、確信のないことは報告しないよう求められています。どのパートにも登場しない追跡キャラクターについては、まったく尋ねられません。

1回の実行は、モデルへの1回のリクエストです。**Process now** の実行に3回を超えるリクエストが必要になる場合(未処理の長い区間、または **Parts per run** が小さく設定されている場合)は、まず何パート・何リクエストになるか、おおよそどれだけの文章がモデルを通るかを表示します。確認してから開始されます。各リクエストには指示文、ロアブック、キャラクターの知識も含まれるため、実際のコストは文章だけの量よりも高くなります。

**Ask before applying** がオフの場合、変更は直ちに適用され、それぞれがタブの Processing セクションにある **Applied automatically** のログに記録されます。どのパートから、誰が何を得たか、または何を失ったかが分かります。ログは編集できませんが、各行には **Revert** ボタンがあります。追加された項目は却下され(レビューで却下された場合と同様に *Old knowledge* に残ります)、撤回された項目は再び有効になります。あなたが後から手で編集、削除、撤回した項目の行は、そのまま残されます。ログには直近200件の変更が保持されます。

<a id="returning-to-an-earlier-point"></a>

### 以前の時点に戻る

知識を変更する実行の前には、トラッカーが**チェックポイント**を作成します。対象は、タブでのレビューの有無を問わない実行、新しいパートの自動読み取り、`knowledge-process` および `knowledge-tidy` コマンド、整理、モデルを使わない読み取りです。チェックポイントには、実行が開始された時点でのキャラクターの状態全体と、読み取りが進んでいた位置が保存されます(最初の実行前は *Start of the book*)。Processing パネルの **Checkpoints** には、新しい順に一覧が表示されます。各項目には、トラッカーが読み取った位置のパート、時刻、次に行われた実行の種類、追加・撤回された件数が示されます。現在のブランチ上にあるパートのチェックポイントだけが表示されます。

行の **Return to this point** を押すと、その実行とそれ以降のすべてが取り消されます。キャラクターとその知識、処理済みのパート、自動変更のログは、チェックポイント時点のものに戻ります。次の実行では、そのパートより後のパートを読み直します。取り消された実行のパートも含まれます。設定と開始位置は現在のままです。チェックポイント以降に学習したことはすべて取り消されるため、その後に手で行った変更も失われます。そのため、実行前に確認が求められます。トラッカーが持っていた状態は *before a return to a checkpoint* としてチェックポイントに保存されるので、後で戻ることもできます。実行や一連の実行が誤った結果になった場合や、本の古いバックアップを復元した後で、信頼できる時点からトラッカーに追いつかせたい場合に使ってください。

トラッカーは本ごとに直近20件のチェックポイントを保持します。これらは本の中ではなく、あなたのファイル(*Resources*、本ごとにまとめられています)に保存されるため、本のバックアップやコピーには含まれません。

**Ask before applying** がオフの場合、新しいパートは確定した時点で直ちに読み取られます。確定とは、生成が終わったとき、または本で自動注釈(と再下書き)か翻訳がオンになっている場合はそれが終わったときを指します。モデルはあなたが保持しているテキストを読み、あなたが読んでいる間に作業します。これは [what follows the part](../books/story-editor.md#what-follows-a-generated-part) の一つのステップです。次の生成時には知識が最新になっているため、待たされることはありません。中断された実行や閉じられたウィンドウなど、残っているものは、これまでどおり次の生成の前に読み取られます。

モデルが作業している間、小さな**進行パネル**がページの上に浮かびます。このパネルは**モーダルではありません**。ストーリーを読んだり編集したりし続けられ、タイトルをつかんで**ドラッグ**できます。閉じると非表示になりますが、作業は続きます(**Cancel** で停止できます)。

![The progress panel](../../images/plugin-knowledgetracker-progress.png)

モデルが回答している間、パネルには **What the model is writing** がリアルタイムで表示されます。最初に推論が、続いて回答が表示されるので、低速なモデルを長く待つ場合も空のバーだけが表示されることはありません。リクエストが終わると、同じテキストが **What the model thought** の下に残ります。実行のリクエストごとにブロックがあり、何と答えたかが示されます。モデルが何も提案せず、レビューが開かれない場合も同様です。その場合、タブには **Last run: what the model thought** というボタンが残るので、パネルを再び開いて、なぜ何も追加されなかったのかを確認できます。

モデルが回答すると、パネルはその旨を伝え、**Review changes** を表示します。同じボタンは、タブの処理パネルにもあります(*3 changes to review*)。**レビューは自動的には開きません。** レビューは、変更をキャラクターごとにまとめた表です。

![Reviewing the changes](../../images/plugin-knowledgetracker-review.png)

表の下にある **What the model thought**(最初は閉じています)には、モデルが回答する前に出した推論が入ります(モデルが送信する場合)。なぜその変更が提案されたのか、あるいは期待していた変更がないのはなぜかが示されるので、適用する前に判断できます。推論を行わないモデルでは、ここには何も表示されません。

| | |
|---|---|
| チェックボックス | 変更を適用するかどうか。最初はすべてチェックされています。各キャラクターには **Check all** / **Uncheck all** があります。 |
| **Retract** / **Add** | 撤回すると項目は古い状態になります(項目は保持されます。[the tab](#the-knowledge-tab) を参照してください)。追加は新しい項目で、*Knows* または *Does not know* です。追加の内容と種類は、適用前に**編集**できます。 |
| 引用 | 変更の根拠となるパートの語句と、それがどのパートにあるかです。そのパートに見つからない引用には印が付きます。モデルが作り上げた可能性があるため、受け入れる前に確認してください。 |

**Apply** は、チェックされた変更を適用して次へ進みます。**Cancel** は一連の処理全体を停止し、何も変更しません。その場合、次回も同じパートが再び提案されます。チェックを外した追加は、引用とともに**古い知識として保持**されます(あとで復元できます)。チェックを外した撤回は、項目をそのままにします。モデルが述べた内容のうち使えなかったもの(尋ねていないキャラクター、存在しない項目、引用のない変更、キャラクターがすでに知っていること)は、*Left out* の下に一覧表示されます。適用された変更にはそのパートの情報が紐づいているので、**Reprocess from here** で再び取り消せます。レビュー中にストーリーが変わった場合(別のブランチへの切り替え、パートの削除など)、変更は適用されず、もう一度処理し直す必要があります。

パートは **Parts per run**(既定では1)ごとの**実行**単位で読み取られます。モデルのコンテキストに収まらない場合は、収まる分だけに切り詰められます。一連の処理は、最後の確定パートまで実行を重ねながら続きます。確認を求める設定の一連の処理では、モデルが何も見つけなかった実行は、確認せずにスキップされます。**Ask before applying** がオフの場合、変更は直ちに適用され、パネルには実行ごとに1行のログが残ります。

!!!
このプロンプトは、いくつかのシーンを使って一つのモデルで試験したもので、広く検証されたわけではありません。キャラクターが知覚していないことを学んでしまうことは防ぎますが、提案された内容は確認してください。特に長いシーンに登場するキャラクターについては注意が必要です。リクエストは、下で選んだモデルに送信されます。そのサービスの通常の費用とプライバシーの扱いが適用されます。
!!!
<a id="tidying-the-knowledge"></a>

## 知識の整理

モデルは登場人物が知ったことを書き留めます。長い物語では、その一覧が増え、リクエストのたびにモデルへ送りたい量より多くの細かな事柄が含まれるようになります。**Tidy knowledge**（**Process now** の隣にあり、モデルの設定が必要です）は、モデルに対して、処理済みの直近のパートを文脈として参照しながら、キャラクターが知っていることを改めて読み直し、次の作業を行うよう求めます。

- **破棄**：残す価値のない項目を取り除きます。たとえば、些細な事柄、その場にいた全員が見ていた場面の詳細（物語自体に残っています）、後の出来事によって時代遅れになったこと、別の項目と同じ内容のことなどです。
- **統合**：同じことに関する複数の項目を、すべての事実を保ったまま一つにまとめます。

破棄または統合された項目は削除されるわけではなく、*Old knowledge* に移され、元に戻せます。変更は読み取りの場合と同じようにレビューされます（**Ask before applying** の設定により決まります）。または、ただちに適用されてログに記録され、**Revert** ボタンが付きます。

整理の対象になるのは、モデルが学習し、あなたが **lock** していない内容だけです。最初から入っている項目、あなたが手で追加または編集した項目、ロックされた項目、そして *Old knowledge* の項目は、決して変更されません（最初の二種類とロックされた項目は、ある項目が重複することになるかをモデルが判断できるように、モデルに示されます）。どのパートでも長く言及されていない秘密は、それだけで破棄する理由にはなりません。プロンプトにもその旨が書かれています。モデルが判断に迷う場合は、その項目を残します。モデルが学習した項目が **Tidy: from this many items**（8）未満のキャラクターは整理されません。**Tidy: parts of context**（10）は、整理のときに読む直近の処理済みパートの数です。

**Tidy automatically**（設定項目で、初期値はオフ）は、変更を確認なしで適用する実行（**Ask before applying** がオフの場合。新しいパートの自動読み取りも含みます）の終わりに、整理を自動で実行します。実行は、前回の整理以降にモデルが読んだパートが **Tidy after this many parts**（10）に達したときに行われます。整理で行われた変更は適用され、**Revert** ボタン付きでログに記録されます。実行のログにもその旨が示されます。確認しながら行う実行では、整理が自動で始まることはありません。項目が少なすぎるキャラクターは、モデルに問い合わせずにスキップされます。

コマンドバーからも同じ操作ができます。`knowledge-tidy`（変更を一覧で見るには `ask true` を使います。開いているタブにはレビューのボタンが表示されます）、そして、キャラクターと項目の番号を指定する `lock-knowledge` / `unlock-knowledge` です。

<a id="settings"></a>

## 設定

*Track a character* の横にある歯車アイコンから開きます。

| 設定 | |
|---|---|
| **In prompt** | ブロックをすべての生成のプロンプトに挿入します。オンの間、ボタンは緑色になります。 |
| **Depth** | ブロックを入れる位置です。プロンプトの末尾からメッセージ数で数えます。`0` はターンの指示の後、`1` はその直前です。システムプロンプトより前に入ることはありません。 |
| **Role** | ブロックを *System*、*Assistant*、*User* のどのメッセージとして送るかを決めます。 |
| **Say that nothing else is known** | 「ほかに知られていることはない」という閉じた世界の一文です。 |
| **Give what the characters know to the annotation** | 初期値はオンです。オンのとき、[AIで注釈](#annotating-with-what-the-characters-know)は、パートの開始時点で追跡中のキャラクターが知っていたことを受け取ります。 |
| **Process new parts automatically** | [処理](#processing)を参照してください。 |
| **Read what the characters learn with the model** | 処理の際、追跡中の各キャラクターが学んだことをモデルに尋ね、その結果を提案します。オフ（初期値）の場合、処理では誰が誰に会ったかを記録するだけで、コストはかかりません。 |
| **Ask before applying** | 初期値はオンです。オンの場合、すべての提案はレビューのために表示されます。オフの場合、提案はただちに適用され、ログに記録されます。 |
| **Let the model read earlier parts** | 新しいパートを読む間、モデルは項目が学ばれたパート（項目には「パート12で学んだ」と書かれています）を読むことができます。読んだ内容が、それを確認するか、繰り返すか、矛盾するかを確かめるためです。たとえば、伝聞だったことを自分の目で確かめられるようになった場合などです。1回のリクエストでの読み取りは、パートごとに最大5回までです。長いパートの本文は、コンテキストに収まる長さに切り詰められます。レビューでは、モデルが読んだパートが表示されます。読み取りのたびにモデルとのやり取りが一回増えるため、初期値はオフです。関数を呼び出せないモデルは、これまでどおりリクエストを読みます。 |
| **Parts per run** | 1回のリクエストで読むパートの数です。多いほどコストは下がりますが、回答は長くなり、レビューは難しくなります。 |
| **Tidy automatically**、**Tidy after this many parts** | 変更を確認なしで適用する実行の終わりに、整理を自動で実行します。実行は、この数（10）のパートごとに行われます。初期値はオフです。 |
| **Tidy: parts of context** | 整理で読む、直近の処理済みパートの数です（10）。 |
| **Tidy: from this many items** | モデルが学習し、かつロックされていない項目がこの数（8）より少ないキャラクターは、整理されません。 |
| **Lorebook for the model** | *Entries the parts activate*（初期値。パートについて生成で使われるはずのエントリ）、*The whole lorebook*（すべてのエントリ。コンテキストに収まらない場合は、有効化されたエントリだけを送り、その旨を注記します）、または *No lorebook* です。 |
| **Model / Protocol for the extraction** | 空の場合は、その本のモデルを使います。この処理にはより安価なモデルで十分です。また、プロンプトキャッシュを一つだけ持つサーバーでは、別のモデルを指定すると、キャッシュが置き換えられるのを防げます。 |
| **Separators of this book** | 「現在の登場人物」欄を名前に分ける区切りです。1行に1名になるように分けます（改行は `\n` です）。`and` のような単語は空白で分けられるので、*Jack and Jill* は、あなたが追加するまで一つの名前のままです。 |
| **My separators (all books)** | すべての本で共通する区切りです。その本の区切りが優先されます。どちらもない場合は、組み込みの区切りを使います。 |

**Use these settings for new books**（モデルの設定の下にあります）は、この本の設定を保存します。保存されるのは、モデルによる読み取りの設定、モデルとプロトコルを含む内容です。Knowledge Tracker をまだ使ったことがない場合、新しい本はこの設定から始まり、最初の実行から使いたいモデルで読み取りを行います。本の区切りは、その本に残ります。**Forget the settings for new books** を押すと、組み込みの設定に戻ります。すでに tracker を使っている本は、それぞれの設定を保ちます。

## プロンプト

読み取りのシステムメッセージ（**Knowledge extraction prompt**）と、整理のシステムメッセージ（**Knowledge tidy prompt**）は、[継承される設定](../books/prompts.md#inherited-settings)です。本は自分の設定を使います。自分の設定がなければ、上にある最も近いフォルダーで設定されたものを使います。それもなければ、あなたの全体設定を使い、それもなければ、実際のモデルで検証された組み込みの文面を使います。

これらは、本の *Prompts* タブの *Extension Settings* の下、フォルダーのダイアログ、または *Settings → Extension Settings → Knowledge Tracker* で、すべての本に対して設定できます（空の場合は、組み込みの文面が灰色で表示されます）。プラグインは JSON の回答形式を使って結果を読み取るため、組み込みの文面の回答形式は維持してください。モデルが以前のパートを読んでよい場合、`read_part` への指示はプラグインが追加します。そのため、あなたのプロンプトにその指示を書く必要はありません。
<a id="annotating-with-what-the-characters-know"></a>

## 登場人物が知っていることによる章の注釈

上のブロックは、モデルが執筆中に登場人物を全知にしてしまうのを防ぎます。同じ記録は、それでも入り込んでしまった誤りを見つける助けにもなります。モデルが[章に注釈を付ける](../books/annotations.md#letting-a-model-annotate)（**Annotate with AI**、章の範囲の指定、自動注釈、`/generate-annotation`）と、トラッカーはその章の開始時点で追跡対象の登場人物が知っていたことをモデルに伝えます。エディタは、知りえないことを言ったり、考えたり、行ったりする登場人物にフラグを立てます。例：*フィオラはトマスを名前で呼ぶが、記録では彼女は彼と会ったことがない。* 注記には、その根拠となる事実が示されます。

- **事実は章の時点のものであり、本の末尾のものではない。** 登場人物が後の章で知ったことは、まだ知られていない扱いになります。後の章で取り消される項目は、その時点ではまだ真でした。章自体がもたらすもの（判明したこと、出会った人物、その章で真でなくなること）は別にまとめて示されるため、章の前半が後半と照らし合わせられることはありません。
- **対象の登場人物。** 追跡対象のうち、章の *Present Characters* にいる人物、章の視点人物、または章の本文で名前が挙がっている人物です（単語単位で、大文字と小文字は問わず、別名も含みます）。
- **どの時点でも事実ではない項目は除外されます。** 手動で取り消した項目、整理パスで削除された項目、レビューで却下した項目がこれに当たります。
- **記録されていることだけ。** 記録にないことは事実ではないとモデルに伝えられるため、トラッカーがまったく聞いていないことについて登場人物にフラグが立つことはありません。*Say that nothing else is known* を有効にすると、登場人物が会った相手の欄に「(nobody else)」も追加されます。
- 手前の章がトラッカーに読み込まれていなかった場合、事実はそのことを示します。その章で登場人物が知ったことは欠けているため、先に **Process now** を実行すると、より良いレビューになります。
- 事実はアノテーションのリクエストのトークンを消費し、追跡対象の登場人物がいる章に対してのみ使われます。**Give what the characters know to the annotation** をオフにすると、この機能を無効にできます。

<a id="the-block-as-a-macro"></a>

## ブロックをマクロとして使う

自動挿入の代わりに（またはそれと並べて）、[{%{`{{command::knowledge-tracker-block::<characters>}}`}%} マクロ](../templates/macros.md#commands)でブロックを自分で配置することもできます。引数は場面の登場人物のリストなので、テンプレートは章のフィールドを渡せます：

```
{%{{{command::knowledge-tracker-block::{{presentCharacters}}}}}%}
```

マクロは **In prompt** がオンかどうかに関係なくブロックを出力するため、マクロを使うときはそれをオフにしてください。さもないと、モデルが同じものを二度受け取ります。深さとロールはマクロには適用されません（ブロックは、それを含むメッセージの一部になります）。リストされた登場人物のうち追跡対象が一人もいない場合は、何も出力されません。コマンドマクロの回答は、新しい章が続く元の章とともに保存されるため、同じ章からの二度目の生成は、その間に行った変更を見ません。再生成とスワイプでは改めて問い合わせられます。

## コマンド

[コマンドライン](../commands/index.md)とエージェント向けの一覧です。

| コマンド | |
|---|---|
| `knowledge-status` | 設定と処理の進行状況。 |
| `list-tracked-characters`, `add-tracked-character`, `update-tracked-character`, `delete-tracked-character` | 追跡対象の登場人物。名前、別名、または番号で指定します。 |

| `knowledge-reprocess` | 章（そのハンドルまたは位置）から再処理します。先に確認を求めます。モデルがオンのときは状態を戻すだけで、`knowledge-process` は章を読み直します。 |
| `knowledge-set-start` | 開始点を設定します。章を指定しない場合は、本の冒頭になります。 |
| `knowledge-tracker-block` | マクロ用に、ブロックをテキストとして出力します。 |

コマンドラインは引数をスペースで分割します。登場人物のリストは引用符で囲んでください（`/knowledge-tracker-block "Fiora, Mara"`）。

## 保存

すべては本とともに（その属性として）保存されるため、[本のバックアップ](../books/backups.md)やコピーにも含まれます。[チェックポイント](#returning-to-an-earlier-point)は含まれません。これは本に関連付けられた、ユーザーのファイルです。
