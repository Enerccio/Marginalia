# 管理书籍
<a id="the-book-list"></a>

## 书籍列表

**书籍**标签页列出你的书籍。其他用户的书籍不会显示。列表一次只显示一个[文件夹](folders.md)，当前文件夹中的文件夹显示在其书籍上方；在顶层且尚未创建任何文件夹时，列表就是你的全部书籍。

![书籍标签页](../../images/books.png)

| 列 | |
|---|---|
| **名称** | 书籍的名称。 |
| **标签** | 书籍的标签。 |
| **创建时间** | 书籍的创建时间。 |
| **最后修改** | 书籍最后一次被修改的时间。 |

列表按*最后修改*排序，最新的在前。点击列标题可按该列排序；若同时对多列排序，则列表会依次按所有这些列排序。

列标题下方的一行用于筛选列表：

- **名称**：名称*以*该文本开头的书籍。使用 `*` 作为通配符：`*dragon` 会找到名称中任何位置含有“dragon”的所有书籍。
- **标签**：拥有*全部*所选标签的书籍。

筛选行末尾的刷新按钮会重新加载列表。

每一行都有按钮：星形按钮将书籍设为[收藏](folders.md#favorites)，铅笔按钮打开书籍，**移动到文件夹**将其放入某个[文件夹](folders.md)，复制按钮创建一份副本，垃圾桶按钮删除书籍。标题栏中有**新建文件夹**、**管理**菜单（包括**整理**——用于[移动和复制](folders.md#organise)书籍和文件夹的窗口、**为书籍添加标签**、**统计**，以及**批量修改**子菜单），还有**导入**，用于从你已有的文件创建新书籍（参见[导入书籍](#importing-a-book)）。

<a id="a-book-is-open-in-one-window"></a>

### 一本书只能在一个窗口中打开

同一本书一次只能在一个窗口中打开，即使跨浏览器标签页、其他浏览器或你的手机也是如此。当你打开一本已在别处打开的书籍时，Marginalia 会告诉你它从何时起就已被打开，并询问**在此打开**：书籍随即在此处打开，其在另一处的窗口会关闭，并说明原因（如果另一处正在生成某个部分，询问中会注明，点击**在此打开**会停止该生成；已经写好的内容会保留）。点击**取消**则保持原位不变。当你登录后 Marginalia 打开你上次打开的书籍时，它不会从其他窗口抢走该书：它会保持关闭状态，并告诉你书籍在哪里。已关闭的标签页或已断开的设备中的窗口不会占用该书：**在此打开**会立即生效。

<a id="advanced-search"></a>

### 高级搜索

**搜索**（位于标题栏中，紧邻**管理**；在手机上则是标题栏中的放大镜）会打开一个窗口，用于按比筛选行更多的条件查找书籍。填写你想检查的内容，其余留空，然后按**搜索**（或在文本框中按 Enter）：

| 字段 | 查找…… |
| ----- | -------------- |
| **名称** | 名称包含该文本的书籍（`*` 为通配符）。 |
| **包含的标签** | 拥有这些标签的书籍：*所有标签*或*任一标签*，可在字段旁边选择。 |
| **排除的标签** | 不拥有这些标签的书籍：选择*任一标签*时，拥有其中至少一个标签的书籍会被排除；选择*所有标签*时，只排除拥有全部这些标签的书籍。 |
| **创建时间 从 / 到**，**修改时间 从 / 到** | 在该时间范围内创建或最后修改的书籍；*到*日期当天也包含在内。 |
| **部分数量 从 / 到** | 在其所有分支中拥有这么多部分的书籍（回收站中的部分不计算在内）。 |
| **文本** | 包含一个同时含有该文本所有词语的部分的书籍。词语、`"短语"`和 `*` 的用法与[故事搜索](story-editor.md#searching-the-story)中相同。 |
| **包含版本** | 默认关闭：只搜索部分的当前文本；开启后，若书籍某部分的早期版本含有这些词语，该书籍也会被找到，参见[版本历史](version-history.md#searching-the-old-text)。 |
| **搜索所有分支** | 默认关闭：只在书籍所处的分支中搜索文本（即你打开书籍时所看到的故事）；开启后，则在所有分支的部分中搜索。 |

书籍必须通过你所填写的每一项检查。找到的书籍会列在下方，附带其标签，并按最后修改时间从新到旧排列；点击列标题可对其排序。文件夹按钮会打开书籍（在搜索结果上方的窗口中打开，因此关闭书籍后会回到结果列表）。**清空**会清除所有字段。

![书籍的高级搜索](../../images/book-search-advanced.png)

<a id="cloning-a-book"></a>

### 克隆书籍

克隆按钮会询问新书籍的**名称**（默认为原书名称加上 *(Copy)*），并提供默认勾选的复选框**仅当前分支**。新书籍是一本独立的书，它会获得：

![克隆书籍](../../images/book-clone.png)

- 原书的设置（描述、语言、提示词、视角、时态、风格、备份设置）、扩展在书中保存的数据，以及标签；
- 相同的**模型**、**协议**和**世界书**。世界书是*链接*而非复制：对它的修改会同时体现在两本书中；
- 故事及其自己的部分副本、摘要和图片。勾选**仅当前分支**时，只复制从开头到结尾、位于[当前分支](branches-and-story-tree.md)上的部分；不勾选则复制所有分支。

克隆书籍会开始一份属于它自己的[版本历史](version-history.md#backups-copies-and-the-trash)（每个部分一个版本）；原书的历史不会被复制。

即使原书已发布，克隆书也不会发布。原书不会被改动。克隆书会被放入与原书相同的[文件夹](folders.md)中。

<a id="tagging-many-books-at-once"></a>

### 批量为多本书添加标签

**为书籍添加标签**（标题栏**管理**菜单中）会打开一个窗口，可以在多本书上添加或移除某个标签，无需逐一打开。选择**标签**（或输入新标签后按 Enter），列表会显示每本书及其标签；已带有所选标签的书籍排在前面，并以高亮显示该标签。每一行都有一个**+**按钮，用于为该书添加标签，以及一个**-**按钮，用于将其移除。若要对多本书进行同样操作，请勾选它们的复选框（标题栏中的复选框可全选），然后使用底部的**为已勾选的书籍添加标签**或**从已勾选的书籍中移除标签**。智能体正在处理的书籍会显示为灰色：它已被锁定，在运行暂停或停止之前无法勾选或修改。同一窗口也可用于为[世界书及其条目](../lorebooks/lorebooks.md#tagging-many-at-once)添加标签。

![为书籍添加标签](../../images/multi-tag-books.png)

<a id="changing-the-model-and-protocol-of-many-books"></a>

### 批量修改多本书的模型和协议

**管理**菜单中的**批量修改**子菜单包含**批量修改模型/协议**项。它会打开一个窗口，无需逐一打开，即可为多本书设置一个**模型**和/或一个**协议**。留空某个框（它显示为*不替换*），则书籍的该部分保持不变：只选择模型即可更改模型并保留协议。表格按名称列出当前[文件夹](folders.md)中的书籍，并显示它们目前拥有的模型和协议；**包含子文件夹**会加入其下的书籍。在**名称**下方的筛选框中输入文字可缩小列表范围，勾选要修改的书籍（标题栏中的复选框会勾选所有显示的书籍），然后按**替换并退出**。被筛选隐藏的书籍会被取消勾选，因此只有你看到的内容会被修改。智能体正在处理的书籍会显示为灰色：它已被锁定，在运行暂停或停止之前无法勾选或修改。

![批量修改多本书的模型和协议](../../images/mass-change-model-protocol.png)

同一菜单中的**批量修改语言**项对书籍的**语言**以相同方式工作：选择语言，筛选并勾选书籍，然后按**替换并退出**。表格显示每本书目前的语言，以及它从所在文件夹继承的语言（参见[语言](folders.md#language)）。

![批量修改多本书的语言](../../images/mass-change-language.png)

<a id="renaming-many-books"></a>

### 批量重命名多本书

**批量重命名**项可一次性重命名已勾选的书籍。请选择方式：

| 方式 | 作用 |
|---|---|
| **添加前缀** | 将**要添加的文本**放在名称前面。 |
| **添加后缀** | 将**要添加的文本**放在名称后面。 |
| **查找和替换** | 将名称中每一处**查找**的内容替换为**替换为**的内容（留空则删除）。文本按原样处理，而非作为模式；**区分大小写**默认关闭。 |
| **为书籍编号** | 为书籍编号：**名称模式**即新名称，其中 `{name}` 代表当前名称，`{n}` 代表编号，例如 `{name} {n}`、`{n}. {name}` 或 `Chapter {n}`。第一本勾选的书获得**起始值**，此后每本依次增加**步长**，**位数**用零补足编号（如 `007`）。 |

![为所有文件夹中的书籍编号](../../images/mass-rename.png)

**新名称**一列会在你输入时显示每本已勾选的书籍将获得的名称，因此请在按**重命名**之前仔细核对。编号按列表顺序（按名称）对已勾选的书籍依次计算。新名称开头和结尾的空格会被去除。当文本缺失、模式中没有 `{n}`、没有任何名称会改变，或某个名称最终会变为空时，不会进行任何重命名，窗口也会保持打开。筛选、**包含子文件夹**以及锁定的书籍在此与其他批量修改中的表现一致。

**为书籍添加标签**和**为文件夹添加标签**项则以相同方式作用于当前文件夹中的书籍或文件夹。
<a id="creating-a-book"></a>

## 创建书籍

1. 点击 **Add Book**。
2. 输入名称并确认。

新书会放入列表所示的[文件夹](folders.md)中，导入的书籍也是如此。新书会立即打开。如果你已在 *Settings* 标签页中设置了 **Default Model** 和 **Default Protocol**（见[账户与设置](../account.md)），新书会使用它们；否则请在生成之前，在 *About* 标签页中选择它们。

<a id="importing-a-book"></a>

### 导入书籍

书籍列表标题栏中的 **Import**（手机上为文件按钮）会打开一个窗口，可以用来创建新书的所有来源都在这里。
选择 **Source**；名称下方的文本、可接受的文件和选项都随之变化：

| 来源 | 上传 | 选项 |
|---|---|---|
| **Import from archive** | 一个 `.zip`，内含若干 `.md` 文件，每个文件对应一个部分，见[导入到书籍中](story-editor.md#importing-into-the-book) | 无 |
| **Import from SillyTavern** | 一个或多个 `.jsonl` 聊天记录，见[下文](#importing-from-sillytavern) | 合并用户与助手消息 |
| **Import from LM Studio** | 一个或多个对话，见[下文](#importing-from-lm-studio) | 合并用户与助手消息 |
| **Import from a document** | 一个单独文件中的成稿（Word、LibreOffice、RTF、Markdown、纯文本、EPUB），见[下文](#importing-a-finished-manuscript) | 每部分字数，章节的标题级别 |
| **Import from an Obsidian vault** | 知识库的 `.zip`，见[下文](#from-an-obsidian-vault-or-a-scrivener-project) | 同上 |
| **Import from a Scrivener project** | `.scriv` 项目的 `.zip`，见[下文](#from-an-obsidian-vault-or-a-scrivener-project) | 同上 |

上传文件，为书籍命名（名称会根据文件、文档标题或聊天中的角色自动填入；若留空，书籍将命名为 *New book*），然后点击 **Import**。进度窗口中的 **Stop** 会显示正在保存的各个部分；停止后，已保存的内容会保留。来源无法读取的文件会被拒绝并给出警告，其他上传的文件不受影响。

在书籍的设置菜单（⚙）中打开的同一窗口，可以把各部分添加到该书的指定位置，见[导入到书籍中](story-editor.md#importing-into-the-book)。

![导入窗口中的来源](../../images/import-source.png)

![将文本文件的 zip 压缩包导入为新书](../../images/archive-upload.png)

<a id="importing-a-finished-manuscript"></a>

### 导入成稿

如果已经有现成的草稿，请选择 **Import from a document** 并上传文件：可以是 `.docx`（Word）、`.odt`（LibreOffice、OpenOffice）、`.rtf`（富文本，来自写字板、TextEdit 及其他程序）、`.md`（单个 Markdown 文件）、`.txt`（纯文本）或 `.epub`（电子书）。文本会成为新书的各个部分，且全部标记为由你所写（导入不计入[统计](statistics.md)中的写作字数，部分的历史记录中会显示 *Import from a document*）。

- **章节。** 使用 *Heading* 样式的段落（Markdown 文件中的 `#` 标题）会开始一个章节，每个章节都以其标题开头（部分的第一个标题即为其章节标题，与[导出](export.md)时一致）。**Chapters start at heading level** 用于指定哪些标题会开始章节：即你所选的级别及其以上的标题（起初会选择文档中最浅的标题级别）；更深层的标题保留在正文中，作为较小的标题。没有标题的文档是一个章节。文档的 *Title* 不会作为正文导入，而是用来命名书籍（在 Markdown 文件中，即文件顶部页眉中的 `title:`，或位于 `##` 章节之前的单个 `#` 标题）。纯文本文件没有标题，因此单独成行的 `Chapter 12`、`Part IV: The Return`、`Book two` 或 `Prologue`（还有 `Epilogue`、`Interlude`、`Preface`、`Foreword`、`Afterword`）会开始一个章节；此时无需选择标题级别。
- **每部分字数。** 文本会在段落之间切分成约此字数的部分（初始为 1000），并在最接近该数字的段落分界处切开。一个部分绝不会同时包含一个章节的结尾和下一章节的开头；章节也不会被无故切开：若章节末尾剩下的内容少于该数字的一半，则保留在前一个部分中，因此长度不超过该数字一点五倍的章节会成为一个部分。超过该数字的段落不会被切开。
- 名称下方的一行文字会显示此次导入将生成多少章节、字数和部分；更改选项时它会随之变化。
- **纯文本文件的段落。** 空行分隔段落，段落内的行会被连接起来（按列宽折行的文本会变成一个段落）；没有空行的文件则每行为一个段落。Markdown 文件按原样保留，并在空行、标题和代码块处切分；使用 Windows-1252 而非 UTF-8 编码的文本也能读取。
- **格式。** 斜体和粗体会被保留（以 Markdown 的 `*italic*`、`**bold**` 形式）；其余格式（字体、字号、对齐方式）、图片、页眉和页脚、脚注、批注以及修订模式中删除的文字都不会被导入。表格会逐个单元格读取。

![导入 Word 文档，切分为约 500 字一部分](../../images/document-import.png)

旧版 `.doc` 文件需要先另存为 `.docx`、`.odt` 或 `.rtf`。

**EPUB** 会按阅读顺序逐页读取。页面的标题（`h1` 至 `h6`）即为章节；如果某页没有标题，但电子书的目录中为其命名，则该名称会作为其标题。封面、目录、脚注和注音文字的注释会被省略，电子书的书名用来命名书籍。受 DRM 保护的书籍无法读取。

<a id="from-an-obsidian-vault-or-a-scrivener-project"></a>

#### 来自 Obsidian 知识库或 Scrivener 项目

两者都是文件夹，因此请先将文件夹压缩（在 Mac 上，在访达中选择**压缩**；Scrivener 的 `.scriv` 同样是文件夹），然后上传 `.zip`。选项与文档相同。

- **Obsidian 知识库。** 每个笔记（`.md`）都是一个章节，以笔记名（或其页眉中的 `title:`）命名，并按路径顺序排列，其中的数字按数值比较（`Chapter 2` 排在 `Chapter 10` 之前）。文件夹是其下笔记的上一级部分，笔记内的标题低于该笔记自身的层级。链接 `[[Note|text]]` 会变为其文字；嵌入（前面带 `!` 的 `[[file]]`）、注释 `%%...%%`、块 ID 以及提示框的标记都会被删除；高亮 `==text==` 视为普通文本。隐藏文件夹（`.obsidian`、`.trash`）、附件和没有正文的笔记会被跳过。如果知识库中包含不属于故事的笔记，请在压缩前将其删除。
- **Scrivener 项目。** 导入的是稿件（binder 中的 *Draft* 文件夹，适用于 Scrivener 2 和 3），而不是研究资料、废纸篓或未设为 *included in compile* 的文档。文件夹，或下面还有文档的文档，会成为标题（其在 binder 中的深度即为其级别，其标题即为正文）；文件夹中只包含文档的，这些文档即为场景，依次排列，场景之间以场景分隔符隔开（不使用场景标题）。直接位于稿件中或位于仅包含其他文件夹的文件夹中的文档，会成为带有其标题的章节。项目名称用来命名书籍。

无论来源如何，导入完成后（即使你中途停止）新书都会被打开，并且[**Import finished**](story-editor.md#after-an-import)窗口会提供为各部分撰写摘要、以及让代理生成设定笔记的选项。

<a id="importing-from-sillytavern"></a>

### 从 SillyTavern 导入

若要继续你在 [SillyTavern](https://github.com/SillyTavern/SillyTavern) 中进行的角色扮演或故事，请使用 **Import → Import from SillyTavern**。在 SillyTavern 中导出聊天记录（*Manage chat files*，或从 `data/<user>/chats/<character>/` 中取出 `.jsonl` 文件），然后：

1. 上传**一个或多个** `.jsonl` 聊天记录。不是 SillyTavern 聊天记录的文件会被拒绝，其他文件不受影响。
2. 为书籍命名（名称会根据第一个聊天记录中的角色自动填入）。
3. 如果希望每一轮对话成为一个部分，请勾选 **Merge user and assistant messages into one part**：用户的消息（连续的多条消息以空行连接）会成为该部分的*指令*，其后的回答则成为其正文。若不勾选，每条消息都会成为独立的部分，其文本即为该部分的正文，因此书籍的阅读方式与聊天时相同。
4. 点击 **Import**。进度窗口中的 **Stop** 会显示正在保存的各个部分；停止后，已保存的内容会保留。

![导入 SillyTavern 聊天记录](../../images/sillytavern-import.png)

SillyTavern 在创建*分支*或*检查点*时会复制聊天记录，因此同一故事的多个聊天记录共享相同的开头。一并上传它们，Marginalia 会找出共同的消息并只保存一次：这些聊天记录会成为同一棵树的分支，你可以在[树状视图](story-editor.md)中浏览。消息的*滑动*（备选回答）会成为同级部分，书籍会在最后写入的聊天记录（按其最后一条消息的日期）的末尾打开。开头不相同的聊天记录会成为各自独立的首个部分。隐藏（系统）消息会被跳过，内容为空的滑动也会被跳过。回答的推理过程和模型名称会随部分一起保留。

<a id="importing-from-lm-studio"></a>

### 从 LM Studio 导入

若要继续你在 [LM Studio](https://lmstudio.ai) 中进行的对话，请使用 **Import → Import from LM Studio**。LM Studio 将每个对话保存在你主目录下 `.lmstudio/conversations` 文件夹中的文件 `<number>.conversation.json` 里（Windows 上为 `%USERPROFILE%\.lmstudio\conversations`）。其操作方式与[从 SillyTavern 导入](#importing-from-sillytavern)相同：

1. 上传**一个或多个**对话。不是 LM Studio 对话的文件会被拒绝，其他文件不受影响。
2. 为书籍命名（名称会填入对话的名称；若对话没有名称，则使用文件名）。
3. 若要每一轮对话成为一个部分（你的消息即为该部分的*指令*），请勾选 **Merge user and assistant messages into one part**；否则不勾选，使每条消息各自成为一个部分。
4. 点击 **Import**。

![已上传一个对话的 LM Studio 导入窗口](../../images/lmstudio-import.png)

LM Studio 保留的消息版本（你重新生成的回答、你编辑过的文本）会成为同级部分，而书籍会在显示的那个版本上打开；开头相同的对话会合并为同一棵树。推理模型的思考过程会作为该部分的推理内容保留，并附带模型名称。对话的系统提示、工具调用和附件不会被导入。

若要从备份文件开始一本书，请使用 *Settings* 标签页中的 **Import Backup as New Book**，见[书籍备份](backups.md#importing-a-backup-as-a-new-book)。

<a id="deleting-a-book"></a>

## 删除书籍

点击书籍列表中的垃圾桶按钮并确认。该书籍会从您的列表中消失。

如果书籍上有正在进行的操作，则不会被删除：例如正在生成的部分、摘要批处理、翻译、重写或批注窗口，或在另一窗口中打开的该书籍。此时 Marginalia 会说明阻碍删除的原因（*This is in use: ...*）；请等待其完成或将其停止，然后再次删除。若另一窗口或某个运行任务正在处理该书籍，则将[备份](backups.md)恢复到该书籍中时同样如此。

已删除的书籍不会立即从数据库中移除。在管理员使用 [清理](../administration/cleanup.md) 功能将其及所有部分彻底删除之前，您都可以从 [回收站](../trash.md) 选项卡中恢复该书籍。在此之前，数据仍保存在 [数据库备份](../administration/database-backups.md) 中。书籍自身的[备份](backups.md)是文件，会保留在原处。
