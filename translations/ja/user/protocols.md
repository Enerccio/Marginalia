# プロトコル

プロトコルとは、生成設定のまとまりのことです。サンプリングパラメータ（温度、Top P、ペナルティ）と、必要に応じて独自のコンテキスト上限と返信上限を含みます。[推論プロバイダー](inference-providers.md)が *どの* モデルに書かせるかを決め、プロトコルは *どのように* 書かせるかを決めます。

プロトコルはプロバイダーとは別になっているため、慎重なものや創造的なものなど複数のプロトコルを用意しておき、接続設定に触れることなく本ごとに切り替えられます。プロバイダーと同様に、プロトコルはご自身のアカウントに属します。[共有](#sharing-a-protocol)すると、他のユーザーがそのコピーをインポートできます。

![プロトコルのタブ](../images/protocols-list.png)

<a id="creating-a-protocol"></a>

## プロトコルの作成

**プロトコル**タブを開き、**プロトコルを追加**をクリックします。既存のプロトコルの編集は鉛筆ボタン、削除はごみ箱ボタンで行います。複製ボタン（2枚の紙のアイコン）を押すと、すべての設定を含むプロトコルのコピーを作成できます。名前は確認画面で決められ、元の名前に *(Copy)* が付きます。うまく機能している設定を失わずに、別のサンプリング設定を試すときに便利です。

**他のユーザーからインポート**（一覧の上）では、他のユーザーが[共有](#sharing-a-protocol)しているプロトコルを表示し、そのコピーをインポートできます。

![プロトコルのダイアログ](../images/protocol-dialog.png)

| フィールド | |
|---|---|
| **名前** | プロトコルの名前です。例：`Creative` や `Long context`。 |
| **種類** | リクエストの形式です。現在は **チャット補完** のみです。 |
| **最大コンテキストトークン数** | 任意です。このプロトコルを使う本のプロンプトと応答を合わせたトークン数の上限です。空欄の場合、プロバイダーの**最大コンテキストサイズ**が使われます。 |
| **最大返信トークン数** | 任意です。応答の最大長です。空欄の場合、プロバイダーの**最大応答トークン数**が使われます。 |
| **温度** | 文章のランダム性です。低い値（`0.7` 前後）は焦点が絞られて予測しやすく、高い値（`1.0` 以上）は変化に富み、意外性が増します。 |
| **Top P** | 核サンプリングです。モデルは、確率の合計がこの値（`0`〜`1`）に達するまでの、最も確率の高い単語の中からのみ選びます。`0.9`〜`0.95` が一般的な選択です。 |
| **頻度ペナルティ** | 既に出現した回数が多い単語を罰し、繰り返しを減らします。通常は `0`〜`1` です。 |
| **存在ペナルティ** | 既に一度でも出現した単語を罰し、モデルを新しい話題へ向かわせます。通常は `0`〜`1` です。 |
| **他のユーザーと共有** | チェックすると、他のユーザーがこのプロトコルを閲覧し、コピーをインポートできます。詳しくは[後述](#sharing-a-protocol)を参照してください。新規プロトコルではオフになっています。 |

各サンプリングパラメータには **Enable** チェックボックスがあります。有効になっていないパラメータは Marginalia によって設定されず、モデル独自の既定値が使われます。変更したいものだけを有効にしてください。

<a id="sharing-a-protocol"></a>

## プロトコルの共有

プロトコルのダイアログで **他のユーザーと共有** をチェックすると、このインストレーションの他のすべてのユーザーが、**プロトコルを追加**の隣にある **他のユーザーからインポート** で、そのプロトコルを名前と作成者（フルネーム。未設定の場合はログイン名）付きで見られるようになります。相手は行を開いて設定を確認し、**インポート** をクリックできます。すると同じ設定と名前を持つ、自分のプロトコルが作成されます。共有は閲覧のみです。他の人があなたのプロトコルを変更、削除、使用することはできず、コピーは非公開で、あなたのものとはつながっていません。その後どちらかが変更しても、もう一方には反映されません。チェックを外すと、そのプロトコルは相手の一覧から消えます。ただし、既に作成されたコピーは相手のものとして残ります。

<a id="limits"></a>

## 上限

[推論プロバイダー](inference-providers.md#general-settings)の上限は常に適用されます。プロトコルはそれぞれの上限を下げることはできますが、プロバイダーの値を上回ることはできません。

| | プロトコルの値を設定 | プロトコルの値が空欄 |
|---|---|---|
| コンテキスト | **最大コンテキストトークン数**。ただしプロバイダーの**最大コンテキストサイズ**の方が小さい場合はそちら | プロバイダーの**最大コンテキストサイズ** |
| 応答 | **最大返信トークン数**。ただしプロバイダーの**最大応答トークン数**の方が小さい場合はそちら | プロバイダーの**最大応答トークン数** |

最大コンテキストトークン数を 128 000 に設定したプロトコルを、32 000 のプロバイダーで使うと、32 000 が適用されます。プロバイダーが、そのサービス（またはそれを共有している管理者）の許容範囲を決めているためです。

Marginalia は応答のための領域を確保し、残りのコンテキストをプロンプトで埋めます。プロンプトには、テンプレート、ロアブックの項目、要約、そして収まる範囲の物語が含まれます。コンテキストが 32 000 トークンで応答が最大 2 000 トークンの場合、プロンプトには 30 000 トークンが割り当てられます。応答の上限は API にも送信されます（`max_completion_tokens`）。

モデルが許容する範囲より短いプロンプトに抑えたいときにプロトコルの上限を使ってください。たとえば、大きなコンテキストを持つクラウドモデルで長い本のコストと速度を改善したり、特定の本で応答を短くしたりする場合です。プロトコルの上限は、このプロトコルを使う本の[要約](books/summaries.md)にも使われます。

必要がなければ両方とも空欄のままにしてください。その場合はプロバイダーの値が適用され、本のプロバイダーを変更すると、その上限も一緒に移ります。

<a id="using-a-protocol-in-a-book"></a>

## 本でプロトコルを使う

各本のプロトコルは、その **概要** タブの **プロトコル** フィールドで設定します。すべての新しい本でプロトコルを使うには、**設定** タブで既定のプロトコルとして選択します。プロトコルがない本では生成できず、*本にプロトコルが設定されていません。* と表示されます。

<a id="suggested-settings"></a>

## 推奨設定

モデルに合わせて調整するための出発点です。

| 用途 | 温度 | Top P | 頻度ペナルティ | 存在ペナルティ |
|---|---|---|---|---|
| バランスの取れた文章 | `0.8` | `0.95` | オフ | オフ |
| 創造的で変化に富む | `1.0` | `0.95` | `0.3` | `0.3` |
| 一貫性があり指示に沿う | `0.6` | `0.9` | オフ | オフ |

推論モデルはサンプリングパラメータを無視したり、拒否したりすることがよくあります。その場合は無効のままにしてください。
