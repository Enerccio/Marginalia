# 资源文件

[资源](../resources.md)的文件（用户附加到故事片段上的图片、上传的文件）存放在每个用户的数据文件夹中，即 `data/<login>/images` 和 `data/<login>/resources`。删除资源或替换其内容时，只会修改数据库：文件仍保留在磁盘上，[清理](cleanup.md)及其他任何操作都不会将其删除。**Resource Files** 会找出不再被任何内容使用的文件，允许你下载它们，并将其从磁盘上删除以释放空间。

<a id="cleaning-up-the-files"></a>

## 清理文件

1. 打开管理页面的 **Resource Files** 标签页，点击 **Scan files**。进度条会显示正在读取的文件夹。此步骤不会更改任何内容。
2. 表格列出**没有任何资源指向**的文件，包括路径（`<user folder>/images/<file>`）、大小以及最后修改日期。所有文件默认勾选。取消勾选你想保留的文件；**Select all** 和 **Select none** 会全选或全不选，表头第一列中的箭头也有同样的作用。表格上方的一行文字会显示未使用的文件数量、总大小以及已勾选的数量。
3. 可选地，点击 **Download as ZIP**，将已勾选的文件打包成一个压缩包下载（压缩包内的条目以其路径命名）；也可以点击某一行中的箭头，只下载单个文件。删除前，请务必保留这份备份。
4. **Delete selected** 会在你确认后，将已勾选的文件从磁盘上删除。**Close** 会清空表格，但不删除任何文件。

![扫描后的 Resource Files 标签页](../../images/admin-resource-files.png)

!!!warning
已删除的文件无法恢复。如有疑虑，请先将其下载为 ZIP 压缩包。
!!!

<a id="what-counts-as-used"></a>

## 什么算作"在用"

只要**任何用户的任何资源**指向某个文件，该文件就算在用，即使该资源已被删除也是如此：位于[回收站](../trash.md)中的资源可以被恢复，其图片必须能够重新正常显示。因此，已删除资源的文件只有在[清理](cleanup.md)将这些资源从数据库中移除之后才会列出；被替换内容的旧文件（旧文件会保留在磁盘上）以及失败上传遗留的文件也是如此。

文件通过名称（一个随机标识符）进行比对，比对范围包括所有用户的文件夹，也包括已删除用户的 `<login>-deleted` 文件夹：这些文件仍视为*在用*，直到清理操作彻底删除该用户及其资源为止。

只读取数据文件夹中各文件夹下的 `images` 和 `resources` 文件夹，其他内容不会被读取或改动（例如数据库备份、智能体工作区等）。

在扫描之后上传的文件不会被删除：**Delete selected** 会重新读取数据库，并保留那一刻仍被资源指向的文件（提示信息会说明保留了多少个文件）。

扫描会读取整个数据文件夹，文件较多时可能需要一些时间；进度条上的 **Stop** 可以取消扫描。
