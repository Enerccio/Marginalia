# ストーリーエディター

本の **ストーリー** タブは、執筆を行う場所です。[アクティブなブランチ](branches-and-story-tree.md)のパートを、先頭から末尾まで表示します。

![ストーリーエディター](../../images/hero-story-editor.png)

このページではデスクトップでの画面構成を説明します。スマートフォンでは、ストーリーは1列で表示され、アウトラインはドロワーに収められます。詳しくは [スマートフォンでの Marginalia の使い方](../phone.md#the-story) を参照してください。

| 領域 | |
|---|---|
| **アウトライン**（左） | パートごとに1つの項目を表示します。`#1`、`#2`...のように、パートのデータベースIDを添えます。項目をクリックすると、そのパートまでスクロールします（まだ読み込まれていない場合は、その前のパートが先に読み込まれます）。ヘッダーには、ブランチのパート数が表示されます。[要約](summaries.md)があるパートは、項目の後ろに小さな文書アイコンが付きます。[Chapter Marker](../extensions/chapter-marker.md) 拡張機能を使うと、ここに章のタイトルが表示されます。 |
| **ロアブック**（左、アウトラインの隣） | 本のロアを確認できる領域です。検索ボックスがあり、エントリーのテキストをすばやく編集できます。詳しくは [ロアブックタブ](#the-lorebook-tab) を参照してください。 |
| **注釈**（左、アウトラインの隣） | 本全体を対象に、ストーリーの一節への[メモ](annotations.md)を表示します。 |
| **プランナー**（左、アウトラインの隣） | これから書く予定のシーンを、手作業で追加していく一覧です。詳しくは [プランナータブ](#the-planner-tab) を参照してください。 |
| **ストーリー**（中央） | 各パートの本文を表示します。右側にはメニュー（☰）とメタデータがあり、その下に下部バーがあります。 |
| **下部バー** | 左側に **要約** ボタン（リストアイコン）と設定メニュー（⚙）、中央にコマンドライン、右側に **+** ボタンがあります。 |

これは新しい本の画面です。これらはすべて、好みに合わせて並べ替えられるタブです。ストーリーもタブの一つです。詳しくは [タブの配置](#arranging-the-tabs) を参照してください。サイドバーとストーリーの境界線はドラッグで動かせます。Marginalia は位置を覚えており（本と一緒に保存されます）、本を開き直すとその位置に戻ります。

ストーリーは、常に末尾、つまり最新のパートから開きます。長い本は一度にすべて描画されるわけではありません。最後のパートだけが読み込まれ、スクロールアップすると、読んでいる位置を動かさずに、それより前のパートが上に追加されていきます。反対側の端にあるパートは再び外されるため、[アカウント](../account.md)の **ストーリーで一度に読み込むパート数** の設定で指定した数を超えて読み込まれることはありません（空欄の場合は、すべて読み込まれます）。パートが届くより速くスクロールすると、端に *Loading earlier parts*（または *later parts*）という表示が出て、まだ続きがあることを知らせます。アウトラインでパートをクリックするか、検索でパートを見つけると、その周辺のパートが読み込まれます。新しいパートを始めると、ストーリーの末尾に戻ります。

<a id="searching-the-story"></a>

### ストーリーの検索

アウトラインの上に、**今いるブランチ**のテキストを検索する欄があります（ストーリーツリーの検索は、すべてのブランチを対象にします）。長い本は一度にすべて読み込まれないため、ブラウザーの検索（Ctrl+F）では読み込まれていないパートのテキストは見つかりません。この検索では見つけられます。

- 探したい語句を入力します。入力を止めると検索が始まります。複数の語は、すべて同じパートに含まれている必要があります。語句は二重引用符で囲み（`"old key"`）、`*` は任意の文字列を表します（`light*house`）。大文字と小文字は区別されません。
- 語が現れるすべての箇所が一致となり、ブランチ全体を通して番号が振られます。欄の下には *Match 3 of 27, in part #5* と、どこまで進んだかを示すバーが表示されます。ストーリーは一致箇所までスクロールし、必要であれば、その周辺のパートを読み込みます。
- **上** と **下** のボタンで、前後の一致箇所に移動します（最後の一致の後は最初に戻ります）。欄の中で **Enter** を押すと下ボタンと同じ動作になり、**Shift+Enter** は上ボタンと同じ動作になります。
- 読み込まれているパート内のすべての一致が本文中で強調表示され、現在いる一致はより濃い色で表示されます。欄を空にすると、強調表示は消えます。

スマートフォンでは、検索はアウトラインのドロワーにあります。一致が表示されるとドロワーは閉じるので、次の一致を探すにはもう一度開いてください。

<a id="the-lorebook-tab"></a>

### ロアブックタブ

サイドバーの **ロアブック** タブには、ストーリーから離れずに本のロアブックの内容が表示されます。エントリーの内容を確認したり、その中の語を直したりするために、タブを切り替える必要はありません。このタブは、*ストーリー* タブに戻るたびに読み直されるので、本の *ロアブック* タブで行った変更はすぐに反映されます。

- 上部の **検索ボックス** には、名前・内容・メモ・フィルターのいずれかにその語を含むエントリーだけが表示されます（大文字と小文字は区別されません）。
- エントリーの **ペン** アイコンを押すと、名前、使用するかどうか、フィルターと検索方法、内容、メモを編集する小さなウィンドウが開きます。**保存** で書き込まれます（タグ、順序、有効化の設定は、本の *ロアブック* タブで変更します）。エージェントがロアブックを操作している間は、何も変更できません。
- **拡大ボタン**（⤢）を押すと、[全画面のロアブックエディター](../lorebooks/lorebooks.md#editing-in-full-screen)が開きます（デスクトップのみ）。ロアブックの検索ボックスの隣にあるものはそのロアブック全体を、エントリーの拡大ボタンはそのエントリーを、サブロアブック（*サブロアブックを含める* を有効にしている場合）の拡大ボタンはそのサブロアブックを開きます。エディターを閉じると、このタブは読み直されます。

- エントリーはそれぞれ、名前とペンを持つ1行として表示されます。矢印を押すと、**内容**（Markdown として整形して表示されます）と、そのエントリーを有効にする **テキスト**（*フィルターテキスト／パターン*。正規表現の場合は注記が付きます）が表示されます。
- **サブロアブックを含める** を有効にすると、ロアブックと、そのすべてのサブロアブック（どれだけ深くても）が、それぞれ独立した行として表示され、その下にエントリーが並びます。ロアブックの矢印を押すと、そのエントリーを隠せます。この設定が無効の場合は、本のロアブックのエントリーだけが表示されます。
- 無効になっているエントリーやロアブック（ストーリーでは使われないもの）は、薄く表示されます。
- ロアブックがない本では、その代わりに注記が表示されます。

![2つのエントリーを開いたロアブックタブ](../../images/story-lorebook-tab.png)

エディターの他のタブと同じく、このタブも独立したパネルとして切り離せます。詳しくは以下を参照してください。
<a id="the-planner-tab"></a>

### プランナータブ

**プランナー**タブは、ストーリーを進めたいシーンを、望む順番に並べたリストです。各シーンは、それを書くターンの詳細です。リスト用の**タイトル**、**シーンの設定**、**視点キャラクター**、**登場キャラクター**、**指示**の4つの項目を持ち、これは新しいターンのフォームと同じ4項目です。

![4つのシーンがあり、最初のシーンが書き終わったプランナータブ](../../images/planner-tab.png)

- **シーンを追加**を押すと、新しいシーンのフォームが開きます。シーンはリストの末尾に追加されます。ペンのアイコンでシーンを編集し、矢印で上下に移動し、ゴミ箱のアイコンで削除します。
- シーンの行にある**+**は、そのシーンのすぐ下、つまりそのシーンと次のシーンの間に**新しいシーンを挿入**します。
- シーンの統合ボタンは、そのシーンを**次のシーンと統合**します。両方の詳細がすでに結合された状態でフォームが開きます（2つのタイトル、シーンの設定と指示が上下に並んだもの、両方の登場キャラクター、そして最初のシーンの視点キャラクター。2つ目のシーンに別の視点キャラクターがいる場合は、フォームにその旨が表示されます）。合わない部分を変更して**統合**（または <kbd>Ctrl/Cmd+Enter</kbd>）を押すと、2つのシーンは1つになり、最初のシーンの位置に置かれます。両方のシーンが書き終わっている場合にのみ実行されます。
- **ブランチから取り込む**は、本が今いるブランチの各部分（最初の部分から最新の部分まで）のうち、ターンの詳細があるものごとにシーンを追加します。シーンの設定、視点キャラクター、登場キャラクター、指示が取り込まれ、指示の最初の行がタイトルになります。ターンの詳細がない部分は除外され、取り込まれたシーンは既存のシーンの後ろに、未完了の状態で並びます。すでに書いた物語を書き直す計画を立てるときに使います。取り込み、関連するターンを統合し、足りないものを挿入してから、新しいブランチ上、または本のコピー上でシーンを書いてください。
- シーンの前にあるチェックボックスは、そのシーンが**完了**（書き終わり）であることを示します。タイトルに取り消し線が入り、シーンが薄く表示されます。これは自動では確認されないので、シーンを書き終えたらチェックを入れてください。リストの上の行には、完了したシーンの数が表示されます。
- **シーンをクリック**すると、そのシーンの詳細が**新しいターンのフォーム**に入ります（フォームが開き、シーンの設定、視点、登場キャラクター、指示が入ります。以前そこにあった内容は置き換えられます）。内容に満足したら**生成**を押します。スマートフォンでは、先にドロワーが閉じます。

シーンは本と一緒に保存されるので、バックアップやコピーにも含まれます。モデルもシーンを追加できます。Arc Outline拡張機能の[プロット・ウィザード](../extensions/arc-outline.md#developing-the-plot-in-a-conversation)や[エージェント](../agents.md)は、[コマンド](../commands/index.md#the-planner)を使ってプランナーを読み取り、変更できます。モデルが追加したものは、すぐにリストに表示されます。

![新しいシーンのフォーム](../../images/planner-scene-dialog.png)

![シーンをクリックすると、その詳細が新しいターンのフォームに入る](../../images/planner-new-turn.png)

エディターのほかのタブと同じく、後述のように独立したパネルとしてドラッグして切り出せます。

<a id="arranging-the-tabs"></a>

### タブの配置

エディターはタブの集まりです。**ストーリー**本体（パートと、その下のバー）、**アウトライン**、**ロアブック**、そして[拡張機能](../extensions/index.md)が追加するタブ（キャラクター、アーク、サイドクエリーなど）があります。タブはヘッダーをドラッグして並べ替えられます（デスクトップのみ。スマートフォンでは1列のままで、アウトラインはドロワーに入ります）。新しい本では、アウトラインとロアブックが左側のパネルに、ストーリーが右側に独自の列として配置されます。ストーリーは自由に置けます。たとえば中央に置き、片側にアウトライン、もう片側にロアを置くことも、アウトラインの上に置くこともできます。

- 列内のパネルの上、間、下に現れる破線の帯のいずれかにドロップすると、そのタブはその列の中で独立したパネルに**切り離され**ます。列のパネルは互いに積み重ねられます。
- 左、右、または列と列の間にある縦長の帯のいずれかにドロップすると、**横に切り離され**ます。タブは他の列の隣に、独自の列を持ちます。エディターを広げて、列を増やす余地を作ってください。

パネルと列は仕切りで区切られています。仕切りをドラッグして、各パネルに必要な広さを与えてください。サイズは配置とともに保存されます。

![キャラクターが独立した列にあり、その下にサイドクエリーがあるサイドバー](../../images/story-editor-tabs.png)

- 別のパネルのタブヘッダーまたは本体にドロップすると、そのパネルに**結合**されます（タブの上にドロップするとそのタブの前に、本体にドロップすると最後に入ります）。最後のタブを失ったパネルは消え、パネルのない列も消えます。

配置とサイズは本と一緒に保存されるので、次に本を開いたときも、どのブラウザでも同じ状態になります。各パネルが表示しているタブも、作業環境の他の部分と一緒に覚えられます。読み込まれていない拡張機能のタブは、その拡張機能が戻ってくるまで場所を保持します。

ストーリーは常にどこかに表示されています。そのタブは閉じることができず、同じパネルに他のタブがあるタブは、別のタブが選択されている間は隠れます。パートを表示する操作は、ストーリーのタブを呼び戻します。アウトラインの項目をクリック、検索の結果を選択、[ストーリーツリー](branches-and-story-tree.md)でブランチを選ぶ、生成を開始する、などの操作は、まず**ストーリー**タブを選択します。生成が（通常は数秒かけて）プロンプトを準備している間、ほかのタブは無効になります。モデルが書き始めると再び使えるようになります。[後述](#while-a-part-is-generated)を参照してください。

<a id="minimizing-tabs"></a>

### タブの最小化

ストーリー以外の各タブには、名前の横に小さな**⌄**（シェブロン）ボタンがあります。これを押すとタブが**最小化**されます。タブはパネルから離れ（すべてのタブが最小化されたパネルは、当面消えます）、そのタブの丸いアイコンが、エディターの端のバーに表示されます。アイコンは、絵の描かれた色付きの円です（アウトラインはリスト、ロアブックは本、注釈は吹き出し、サイドクエリーは虫眼鏡など。絵のない拡張機能のタブには、1〜2文字の文字が付きます）。アイコンにカーソルを合わせると、どのタブかがわかります。何も閉じられず、タブは表示していた内容を保持します。アイコンをクリックすると、タブは元のパネルの、元のタブ順の位置に戻り、表示されます。

バーは、いずれかのタブが最小化されている間は表示されたままです。バーの上部にあるボタン（回る矢印）を押すと、バーはエディターの次の辺へ、時計回りに移動します（左、上、右、下の順）。ストーリーは最小化できないので、画面には常に何かが表示されています。

![エディターの端にある、最小化されたタブのバー](../../images/story-minimized-tabs.png)

アイコンは、変更するまではタブ名のアルファベット順に並びます。アイコンを別のアイコンにドラッグすると、その位置に入れ替わります。どのタブが最小化されているか、バーの位置、アイコンの順番は、配置やサイズとともに本に保存されます。

<a id="the-default-arrangement"></a>

### 既定の配置

新しい本は標準の配置で開きます（左側にアウトライン、ロアブック、注釈、右側にストーリー）。自分の配置を標準にするには、パネル、サイズ、最小化したタブ、バーの位置などを好みに合わせて設定し、ストーリーの設定メニュー（⚙）から**このレイアウトを既定として保存**を選んでください。独自の配置を持たない本（まだ並べ替えていない本）は、次に開くときにその配置で開きます。独自の配置を持つ本は、その配置を保ちます。既定の配置はユーザー設定に保存されます。

既定の配置に戻すには、ストーリーの設定メニュー（⚙）から**既定のレイアウトに戻す**を選び、確認してください。これは保存した配置か、何も保存していない場合は標準の配置です。戻るのはタブの位置だけです（サイズと最小化の状態は忘れられます）。本文、各パネルが表示するタブ、拡張機能のタブは残り、後者は最初のパネルに置かれます。
<a id="writing-the-next-part"></a>

## 次のパートを書く

1. 右下の **+** をクリックします。*新しいターンの指示* パネルが開きます。
2. 各項目を入力します。すべて任意ですが、モデルには何らかの指示があったほうがよいでしょう:

   | 項目 | |
   |---|---|
   | **Scene Setting** | パートの場所と時間。例: *The lighthouse, a stormy night in late autumn*。 |
   | **POV Character** | パートを誰の視点で書くか。 |
   | **Present Characters** | 場面にいる人物と、その状態。 |
   | **Instructions** | このパートで何が起こるべきか。 |

   *Scene Setting*、*POV Character*、*Present Characters* は直前のパートから入力されているので、違う部分だけ変更してください。*Instructions* は毎回空の状態で始まります。
3. **Generate** をクリックします。

![新しいターンの指示パネル](../../images/new-turn-instructions.png)

新しいパートが末尾に現れ、モデルが書くにつれて埋まっていきます。[推論モデル](../inference-providers.md#reasoning-models)の場合は、
推論の内容が先に **View Reasoning** の下に表示されます。

パートの生成中は、**+** ボタンが赤い **Stop** ボタンに変わります。停止すると、それまでに書かれたテキストがそのパートとして残ります。

<a id="while-a-part-is-generated"></a>

### パートの生成中

最初の数秒間、プロンプトが本の内容から組み立てられている間は、本のウィンドウ全体が待機します。モデルが書き始めると、保持されるのは新しいパートとそれより前のパートだけになります:

- **新しいパート** は完成するまで操作できません: 編集もメニューも使えません。
- **それより前のパート** はそのままの位置に残ります: 編集、注釈付け、下書きのやり直しはできますが、削除、結合、分岐はできません。また、物語は今のブランチにとどまります(スワイプや、ブランチの切り替えはできません)。前のパートやロアへの変更は、書かれているパートには反映されません。そのプロンプトはすでに組み立てられているためです。変更は後に続く部分に対して効力を持ちます。
- **それ以外はすべて自由に使えます**: ロア、本の設定とプロンプト、左バーのタブ(サイドクエリ、アークの概要、メモなど)、コマンドバー。生成がモデルの接続を一つしか使っていない場合、モデルへのリクエストは空きの接続ができるまで待ちます。
- **待機対象**: 2つ目のターン、検索と置換、本へのインポート、一括削除。ツリーとバックアップのタブも待機します。

ウィンドウでグレーアウトされている操作は、コマンド、エージェント、拡張機能から要求された場合も拒否されます。その場合、Marginalia は何が妨げになっているかを示します(*This is in use: …*)。

**本から離れると生成は停止します。** 終了ボタンは確認を求めます。*Yes* は **Stop** と同じで、届いたテキストは残ります。ブラウザのタブを閉じても同じ結果になります。パートの生成中にタブを閉じたり再読み込みしたりすると、ブラウザが確認を求めます。ネットワークが一時的に切れたり、ノートパソコンを一分ほど閉じたりした場合は、離れたことにはなりません。ページは戻り、その間に届いたものを表示します。

モデルがエラーを返した場合(サーバーに接続できない、APIキーが誤っている、コンテキストが長すぎる、など)、そのエラーが表示されます。テキストがまだ届いていなければ、物語は元の状態に戻ります。新しいパートやスワイプは削除され、再生成されたパートには以前のテキストが戻ります。エラーより前に届いていたテキストは、**Stop** の場合と同様に残ります。問題を解決してから、もう一度生成してください。

各項目がプロンプトにどう組み込まれるかは、本の [User Prompt](prompts.md#user-prompt) で設定します。既定のユーザープロンプトでは、モデルは各項目を *Current Location & Time*、*Point of View Character*、*Characters Currently Present / State*、*Plot Specifications for the Next Part* として受け取ります。

!!!
テキストは Markdown で書かれています。`*italics*`、`**bold**`、`# Heading` などは書式付きで表示されます。`#` 見出しを含むパートは、[Chapter Marker](../extensions/chapter-marker.md) 拡張機能における章になります。
!!!

<a id="drafting-the-instructions"></a>

### 指示の下書き

次に何が起こるべきか分からない場合は、パネルの *Instructions* 欄の下にある **Draft Instructions** を使うと、モデルがあなたの代わりに指示を書いてくれます。あなたが書くのと同じような形式です。ウィンドウが開き、次の内容が表示されます:

| | |
|---|---|
| **Guidance** | そのパートが何についてのものかを示します。大まかな構想、方向性(例: 「彼女は手紙のことで彼を問い詰める」)、あるいは何もなし、でも構いません。何もなければ、モデルは物語が導く方向に続けます。最初は *Instructions* にすでに入力した内容が入ります。 |
| **Plan of the Story** | 何らかの計画がある場合のみ表示されます。[Arc Outline](../extensions/arc-outline.md#drafting-the-instructions-for-the-current-chapter) が現在の章のデータとともに計画を提供します。読み取り専用で、モデルはそれに従います。 |

**Draft Instructions** を押すとモデルが動き出し、回答が **Drafted Instructions** に流れ込みます。次に進む前に、その内容を変更したり、空にしたりできます。**Draft Again** でもう一度試せますし、**Stop** を押すと届いた分は残ります。**Use as Instructions** をクリックするまでは何も変わりません。クリックすると、そのテキストがパネルの *Instructions* を置き換え(他の項目には触れません)、パネルは再び開いて **Generate** の準備ができた状態になります。

モデルが受け取るのは、これまでの物語(古い部分は生成時と同じく[要約](summaries.md)として)、パネルに入っている場面設定、視点人物、登場人物、直前のパートのロア、あなたが最後に書いた指示(書き方の例として)、ガイダンス、そして計画です。新しいターンで発動するはずのロアブックのエントリは見えません。リクエストは [impersonate プロンプト](prompts.md#impersonate-prompt) で行われます。使われるモデルは本に設定されたもので、下書きにも、他のリクエストと同様にトークンが消費されます。

![次のターンの指示を下書きしているところ](../../images/impersonate-dialog.png)

同じ機能はコマンド [`/impersonate`](../commands/index.md) でも使え、こちらは文章を返します。[エージェント](../agents.md)はこの機能を使いません。エージェントは独自の指示で物語を書きます。

## パートのメニュー

すべてのパートには、右上隅にメニュー（☰）があります。**編集**、**変更を破棄**、**再生成**、**スワイプ**、**書き直し**、**履歴**、**画像** はメニュー直下にあり、**削除** が最後の項目です。残りは四つのサブメニューにまとめられています。**注釈**（*パートに注釈を付ける*、*AI で注釈を付ける*）、**要約**（*要約を生成* / *要約を表示*、*要約を削除*）、**確認**（*プロンプトを表示*、*プロンプトを比較*、*トークン使用量*、*ロアの使用状況*）、**分岐と統合**（*ストーリーを分岐*、*前のパートに統合*）です。そのパートに該当する項目がないサブメニューは表示されません。Reviewer を使うと、*要約* の後に **確認** サブメニューが追加されます。各項目は次のとおりです。

| 項目 | |
|---|---|
| **編集** | 本文を編集可能なフィールドに切り替えます。**保存**（同じメニュー項目）で保存します。生成を開始する、またはタブを離れると、編集中の内容も保存されます。 |
| **変更を破棄** | 本文を編集中のときだけ表示されます。保存せずに編集フィールドを閉じ、パートは最後に保存されたテキストのままになります。本文を変更していた場合は、先に確認が表示されます。 |
| **再生成** | 最後のパートを書き直し、本文を置き換えます。最後のパートでのみ使えます。 |
| **スワイプ** | 最後のパートの別バージョンを書き、古いバージョンは別の分岐として残します。最後のパートでのみ使えます。[分岐とストーリーツリー](branches-and-story-tree.md#trying-another-version-of-the-last-part) を参照してください。 |
| **書き直し** | 任意のパートについて、あなたの指示に基づいてモデルにこのパートを書き直させます。[下記](#redrafting-a-part) を参照してください。本文を編集中は使えません。 |
| **履歴 (n)** | パートの[テキストのバージョン](version-history.md)を、バージョン数とともに表示します。比較する、以前の版に戻す、版に名前を付ける、といった操作ができます。本文を編集中は使えません。 |
| **パートに注釈を付ける** | パート全体についての[メモ](annotations.md#making-an-annotation)を作成します。特定の単語に注釈を付けるには、その単語を選択して右クリックし、**選択範囲に注釈を付ける** を選びます。 |
| **AI で注釈を付ける** | モデルに[パートを確認](annotations.md#letting-a-model-annotate)させ、メモを提案させます。本文を編集中は使えません。複数のパートにまとめて行うには、設定メニュー（⚙）の **AI でパートの範囲に注釈を付ける** を使います。新しいパートすべてに自動で行うには **自動注釈** を使います（[注釈](annotations.md#annotating-every-new-part-automatically) を参照）。 |
| **ストーリーを分岐** | このパートから新しい分岐を始めます。[分岐とストーリーツリー](branches-and-story-tree.md#branching-from-an-earlier-part) を参照してください。 |
| **前のパートに統合** | このパートの本文を、その前のパートに追加します。[下記](#merging-a-part-into-the-previous-one) を参照してください。最初のパートでは使えません。 |
| **プロンプトを表示** | このパートのために、モデルへ実際に送られたプロンプトを表示します。 |
| **トークン使用量** | このパートで、モデルのコンテキストがどのように使われたかを表示します。プロンプトの各セクション（モデルへの指示、ロア、要約、これまでの物語、あなたの指示、応答のために確保された領域）の円グラフと、モデルに送られた各メッセージのサイズが示されます。物語の一部が収まらなかった場合は、除外されたパートの数も表示されます。この情報が記録される前に書かれたパートには、グラフはありません。 |
| **ロアの使用状況** | このパートのプロンプトに入った[ロアブック](../lorebooks/index.md)の項目を、それぞれのトークン数と、その項目を見つけた要因（プロンプト本体、またはロアブックがより深く走査した際の別の項目の内容）とともに一覧表示します。手入力されたパート、この情報が記録される前に書かれたパート、またはロアブックのない本のために書かれたパートでは、記録がないと表示されます。本全体の情報は、設定メニュー（⚙）の **ロアの使用状況** を使います。[下記](#which-lore-entries-were-used) を参照してください。 |
| **画像** | パートに画像を添付します。[画像](#images) を参照してください。 |
| **要約を生成** / **要約を表示** | このパートまでの物語を要約するか、既存の要約を表示します。[要約](summaries.md) を参照してください。 |
| **要約を削除** | このパートの要約を削除します。[メタ要約](summaries.md#meta-summaries) の場合は、解除するか完全に削除するかを尋ねられます。 |

## 本文の編集

生成されたテキストは、あなたが自由に変更できます。パートのメニューで **編集** を選び、テキストを変更してから **保存** を選びます。編集されたパートは、編集後の内容のままモデルに送られます。

[要約](summaries.md) が対象とするパートを編集すると、その要約は古くなります。Marginalia は次の生成時にそれを検知し、要約を破棄します。予期せぬ事態を避けるため、**保存** の際に新しいテキストを先に確認します。要約が古くなる場合は、その件数を示すウィンドウが開き、**編集に戻る**（何も保存されず、エディタは入力したテキストのまま開いたままになります）、**そのまま保存**（要約は古くなります）、**保存して要約を再検証**（テキストを保存し、要約は有効なまま残ります。誤字の修正など、要約の内容を変えない変更に使います）のいずれかを選べます。この確認は **保存**（メニュー、ショートカット、エディタのボタン）に対して行われます。エディタを開いたまま生成を開始するなどの自動保存では、確認は表示されません。

## キーボードショートカット

コンピューターでは（[スマートフォン向けの表示](../phone.md) にはショートカットはありません）、執筆の流れをキーボードで操作できます。

| キー | |
|---|---|
| `+` | カーソルが *指示* にある状態で、*新しいターンの指示* パネルを開きます。 |
| `Ctrl+Enter` | 開いているパネルから生成します。`Esc` でパネルを閉じ、キーボードの操作はストーリーに戻ります。 |
| `Ctrl+.` | 実行中の生成を停止します。 |
| `s` / `r` | 最後のパートに対して **スワイプ** / **再生成** を行います。 |
| `e` | 画面上で最も目立つパートのエディタを開きます（該当するものがなければ最後のパート）。 |
| `Ctrl+S` | 編集中のパートを保存します（カーソルがその本文内にあるときも同様）。 |
| `/` | コマンドバーにカーソルを移動します（先にストーリータブが表示されます）。 |
| `Ctrl+Shift+F` | *アウトライン* タブを開き、分岐内の検索欄にカーソルを移動します（`Enter` / `Shift+Enter` で次 / 前の一致へ移動します）。 |
| `Ctrl+Shift+H` | 本の *検索と置換* ウィンドウを開きます。 |
| `a` | **選択範囲に注釈を付ける**: パート内で選択したテキストについてメモを作成します。 |
| `Alt+PageDown` / `Alt+PageUp` | 次 / 前のタブを表示します。すべてのシートのタブを、レイアウトの順に巡回し、最後の次は最初に戻ります。 |

`Ctrl`、`Alt`、`Meta` を伴わないキー（`+`、`s`、`r`、`e`、`a`、`/` など）は、テキスト入力欄にフォーカスがないときだけ働くため、入力の邪魔になることはありません。ショートカットは開いている本のストーリータブで働き、別のウィンドウが前面に開いているときは働きません。ボタンはツールチップにキーを表示し、最後のパートのメニューは *編集*、*再生成*、*スワイプ* の後にキーを表示します。Mac では、`Ctrl` と書かれたキーの代わりに `Cmd` が使えます（その `Cmd` キーを別の操作に割り当てている場合を除きます）。すべてのキーは [設定 → キーボードショートカット](../account.md#keyboard-shortcuts) で変更できます。
<a id="deleting-a-part"></a>

## パーツを削除する

**削除**を押すと、そのパーツが物語から取り除かれます。後に続いていたパーツは残り、その直前のパーツから続きます。そのため、物語の途中のパーツを削除すると、単にそれが取り除かれるだけです。最後のパーツを削除すると、その直前のパーツが分岐の新しい末尾になります。

<a id="deleting-many-parts-at-once"></a>

### 複数のパーツをまとめて削除する

設定メニュー（⚙）には**一括削除**があります。これをオンにすると、各パーツの左側にチェックボックスが表示され、物語の下にバーが現れます。バーには選択中のパーツの数と**削除**ボタンが表示されます。削除したいパーツにチェックを入れてください（チェックはスクロール中も保持されます。物語はパーツを一部ずつ読み込みます）。チェックボックスを**Shift + クリック**すると、そのチェックボックスと前にクリックしたパーツとの間にあるすべてのパーツにチェックを入れる（またはチェックを外す）ことができます。チェックされたパーツは赤く色づきます。その後**削除**を押すと、確認のあと、中止できない進行バーの表示とともに、パーツが一つずつ削除されます。削除の扱いは単一のパーツの場合と同じです。削除されたパーツの後に続いていたパーツは、その直前のパーツから続きます。削除されたパーツはごみ箱に入ります。その後、物語が再表示され、一括削除はオフになります。バー上の**キャンセル**を押すか、もう一度**一括削除**を選ぶと、何も削除せずにオフになります。生成を開始した場合も、一括削除はオフになります。ウィンドウ表示や翻訳の対象になっているチェック済みのパーツは物語に残され、Marginalia はその理由を表示します。

![一部のパーツにチェックを入れた状態の一括削除](../../images/story-mass-delete.png)
<a id="redrafting-a-part"></a>

## 部分の書き直し

**Regenerate**（再生成）と **Swipe**（スワイプ）は最後の部分にのみ作用し、ゼロから書き直します。**Redraft**（書き直し）は任意の部分に作用し、物語の途中にある古い部分でも使えます。また、依頼していない箇所は残します。部分のメニューから **Redraft** を選びます:

1. **Instructions for the redraft**（書き直しの指示）に、変更したい点を書きます。例として、*二人の間の会話を増やす*、*戦闘を長くする*、*地図の説明を削除する*、*結末はそのままにする* などがあります。指示が空の場合は、同じ出来事のまま部分を書き直します。
2. 部分を **Shorter**（短く）または **Longer**（長く）したい場合は **Length**（長さ）を選びます（既定値は **Same length**（同じ長さ））。その要求を伝える一文が、あなたの指示の後に追加されます（[Redraft Shorter Prompt and Redraft Longer Prompt](prompts.md#redraft-shorter-and-longer) を参照）。**Redraft** を選びます。テキストは **Redrafted text**（書き直した文章）に順次表示されます。途中で止めるには **Stop**（停止）を選びます。別の指示で試したい場合は、必要に応じて指示を変えてから **Redraft again**（もう一度書き直す）を選びます。**Differences**（差分）では、部分との変更点を単語単位で確認できます。部分に未解決の [注釈](annotations.md) がある場合は、**Deal with the open annotations of the part**（その部分の未解決の注釈を処理する）（初期状態でチェック済み）をオンにすると、それらも モデルに渡されます。**Apply**（適用）を選ぶと、それらの注釈は解決済みとしてマークされます。
3. 書き直した文章は編集可能なフィールドです（右下のアイコンで全文が収まるまで広げられます）。**Differences** は、あなたの編集に合わせて更新されます。**Apply** を選ぶと、部分のテキストが書き直した文章に置き換わります。**Close**（閉じる）を選ぶと、書き直した文章は破棄されます。**Apply** を選ぶまで、本の内容は一切変わりません。

![書き直しウィンドウ: 指示、新しいテキスト、差分](../../images/redraft-dialog.png)

モデルには [書き直しプロンプト](prompts.md#redraft-prompt) が渡されます。その内容は、部分の本文、あなたの指示、その部分より前の物語（有効な [要約](summaries.md) がある古い部分は要約として、それ以外は本文として渡されます。全体が収まらない場合は、新しい部分から優先されます）、部分より後の物語（余地の四分の一まで収まる範囲）、そしてその部分に対して現在適用されるロア（ロアブックから、部分のターンに合わせて再計算されます。そのため、項目を編集すると書き直しに反映されます。ロアブックが無い本では、部分の執筆時に使われたロアを使います）、本の視点・時制・文体、さらにその部分が生成されたターンの場面設定、視点人物、登場人物、指示です。部分より後の物語も渡されるのは、新しい本文が後続の部分へうまくつながるようにするためです。後続の部分が前提としている出来事は、残しておくべきです。

部分の位置、要約、画像、生成方法はそのまま保たれます。テキスト、その単語やトークンは置き換えられ、その部分は編集済みとして扱われます。書き直しの適用は、エディタでの **Save**（保存）と同じく編集にあたります。そのため、古いテキストを説明している [要約](summaries.md) は古くなり、Marginaliaはその数を表示します。部分自体の要約もその一つです。

要約が部分の内容を説明している場合（部分自体に要約がある、またはブランチの新しい部分が部分を説明している場合）、ウィンドウには **Revalidate the summaries this redraft makes outdated**（この書き直しで古くなる要約を再検証する）というチェックボックスが表示されます。初期状態ではオフです。書き直しで言葉遣いは変わったものの、起きることは変わっていない場合は、このチェックをオンにします。そうすると **Apply** の時点で要約のハッシュが再計算され、要約は有効なままになります。出来事が変わった場合はオフのままにし、要約を作り直してください。

このウィンドウは物語の操作を妨げません。詳しくは [書き直し・注釈ウィンドウと並行して作業する](#working-beside-the-redraft-and-annotation-windows) を参照してください。

<a id="working-beside-the-redraft-and-annotation-windows"></a>

### 書き直し・注釈ウィンドウと並行して作業する

コンピュータでは、**Redraft** と **Annotate with AI**（AI で注釈を付ける）のウィンドウは物語の右側に表示され、物語を使い続けられます。モデルが書いている間も、物語を読んだり、スクロールしたり、編集したりできます。ウィンドウを動かすには、タイトルをドラッグします。サイズを変えるには、端をドラッグします。タイトルの矢印（⌄）を押すと、ウィンドウはページ左下の [実行中の処理パネル](#the-panel-of-the-runs) に折りたたまれます。モデルは処理を続けます。**Open**（開く）を選ぶか、項目をクリックすると、ウィンドウが戻ります。**Stop** を選ぶとモデルが停止します（処理が終わった後は、**Close** でウィンドウを閉じられます）。スマートフォンでは、ウィンドウは引き続き物語の上に重なって表示されますが、同じように折りたためます。

![モデルが書いている間、物語の横に表示された書き直しウィンドウと、左下のパネルにある処理](../../images/redraft-beside-story.png)

**Close と Stop は別の操作です。** ウィンドウ内の **Stop** はモデルを停止し、ウィンドウには届いた内容が残ります。モデルが作業中に **Close** を選んでも、モデルは止まりません。ウィンドウはパネルに折りたたまれ、モデルはキューの中で処理を続けます。再度ウィンドウを開くと、その回答が表示されています。モデルが完了したウィンドウは **Close** で閉じられます。パネルで **Close** を選んでも同じです。閉じると、その処理は消えます。本や ブラウザのタブを閉じると、折りたたまれたウィンドウも停止します。同じことは、モデルの応答を待つ他のウィンドウにも当てはまります。具体的には、**要約**（および *Create summaries*（要約を作成）、*Rewrite all summaries*（すべての要約を書き直す））、[Reviewer](../extensions/reviewer.md)、本の説明文、ロアとアウトラインの生成機能、画像と漫画の生成機能、そして Beta Readers のペルソナライターです。オーディオブックの *Studio* と *Convert* のウィンドウも、ページを妨げません。これらを閉じても、変換が止まることはありません。

部分に対してウィンドウが開いている（または折りたたまれている）間は、その部分の メニュー の横に、何を行っているかが表示されます（*Redrafting · The book*）。また、その部分では **Regenerate**、**Swipe**、**Redraft**、**Annotate with AI**、**Merge into previous**（前の部分に統合）、**Delete**（削除）が無効になります。これにより、ウィンドウが部分を失うことはありません。部分の編集は引き続き可能です。本を閉じると、その本のウィンドウも閉じられ、モデルも停止します。[翻訳機能](../extensions/real-language-translator.md) が部分を処理している場合も、同じように *Translating the speech of the part...* と表示されます。同じ部分を二つの翻訳機能が同時に扱うことはありません。二つ目の翻訳機能は、その部分が使用中であることを伝えます。

- 書き直しを部分全体に **Apply** するとき、ウィンドウを開いた後に部分が変更されていた（その間に編集された）場合、Marginaliaは先に確認を求めます。**Differences** は、現在の部分と書き直しを比較し、適用すると何が置き換わるかを示します。その後、**Apply anyway**（それでも適用）または **Cancel**（キャンセル）を選びます。[自動で適用される](annotations.md#annotating-every-new-part-automatically) 書き直しは、部分が変更されていた場合には確認なしでは適用されません。その場合、ウィンドウはあなたの操作を待ちます。
- **Apply** で書き直しを適用する前、または注釈を追加する前に部分が削除されていた場合、ウィンドウはその旨を伝え、何も書き込まず、閉じます。

<a id="the-panel-of-the-runs"></a>

### 実行中の処理パネル

モデルを使って本に対して今動いている処理は、すべてのページの左下に一覧表示されます。対象は、生成、書き直し、注釈、[Real Language](../extensions/real-language-translator.md) または [Conlang](../extensions/conlang-translator.md) の翻訳機能による翻訳、要約の書き直し、Knowledge Tracker による物語の読み取り、[オーディオブック](../extensions/audiobook.md) の変換、そしてコマンドバーの時間のかかるコマンド（*Draft instructions*（指示の下書き）、要約など。そのウィンドウは横に表示され、他と同じく折りたためます）です。モデルの回答を待っているウィンドウも、モデルが回答している間は一覧に入ります。具体的には、**Impersonate**、ヘルプアシスタント、クイック翻訳、Conlang デザイナー、Side Query のチャット、Beta Readers、プロットウィザードです。このパネルには、**開いているすべてのページ**（別のタブやスマートフォンを含む）からの処理が表示されます。このページで始めたものだけではありません。何も動いていなければ、何も表示されません。

![パネルを開いた状態: 書き直しがパネルに折りたたまれ、モデルの文章の末尾、Open、Stop が表示されている](../../images/runs-panel.png)

- **Closed**（完了）の状態では、小さなバーで表示されます。最初の処理、残りの件数（*Translating the speech of the part... · 2 more*）、そしてモデルが動いている間は動くバーが表示されます。クリックすると一覧が開きます。ウィンドウを折りたたむと、自動的に開きます。
- **Open** の状態では、各処理が何をしているか、どの本か、どれくらい時間がかかっているか、何を待っているか、そしてモデルが書いている文章の末尾を表示します。
  - *Waiting for the model: 2 requests before this one*（モデルの待機中: この前に 2 件のリクエスト）は、モデルが他のリクエストで忙しいときに表示されます（[推論プロバイダー](../inference-providers.md) の *Connections*（接続数）を参照）。
  - *The model is thinking...*（モデルが考えています...）または *The model is writing...*（モデルが書いています...）は、モデルの思考または回答の末尾とともに、その下に表示されます。
  - *Waits for you*（あなたを待っています）は、その処理があなたの判断を待っているときに表示されます（適用する書き直し、確認が必要な Knowledge Tracker の提案、生成前の Prompt Inspector の質問、プロットウィザードのコマンドの許可など）。
- **Stop** は、処理がどこで始まったかに関係なく、その処理を停止します。**Open**、または項目のクリックは、折りたたまれたウィンドウを再表示します（開いたページでのみ有効）。または、処理そのものを表示します。処理があなたを待っている場合は **Review**（確認）になります。Knowledge Tracker の処理を開くと、そのページで本が開き（ほかに開いている本がない場合に限ります。そうでなければ、先にその本を閉じるよう求められます）、Knowledge のタブに切り替わり、確認画面が表示されます。**Close** は、ウィンドウを完全に閉じます（そのモデルも停止します）。
- コンピュータでは、パネルを左側のつまみ（左側の ⋮）でドラッグして動かせます。その位置は、このブラウザに保存されます。ページの下半分では、開くと上方向に広がり、角も同様です。パネルは常にページ内に収まります。パネルが [ヘルプアシスタント](../administration/help-assistant.md) の丸いボタンの位置と重なる場合（本の上では、両方とも左下の角にあります）、ボタンは横に移動し、場所が空くと元に戻ります。

ページを閉じた後に終わった処理が、開いている別のページを持つあなたの場合、その [通知](../account.md#notifications) が送られます（要約の書き直しのように、通知を持つ処理の場合に限ります）。

<a id="redrafting-only-a-passage"></a>

### 一部の文章だけを書き直す

部分の一部の文だけを書き直し、残りはそのままにしたい場合は、部分の本文でその文を選択し、**右クリック**します（スマートフォンでは長押しします）。メニューに **Redraft selection**（選択範囲を書き直す）があります。（この操作には部分の ☰ メニューは使えません。一部のブラウザでは、メニューを開くと選択が失われることがあります。）ウィンドウは上記と同じように動作しますが、二つの違いがあります。**Selected text**（選択したテキスト）が表示されること、そして書き直しは選択範囲を置き換える文章だけであることです。モデルには、選択範囲をマークした部分全体と、その周囲の物語やロアが渡されるため、新しい文章は前後の文とつながります。**Differences** は、選択範囲と書き直した文章を比較します。**Apply** を選ぶと、書き直した文章が選択範囲の位置に入り、選択範囲の端の空白や改行を含め、残りの部分はそのまま保たれます。[注釈](annotations.md) が未解決の場合、チェックボックスには、その本文が選択範囲と重なっている注釈だけが表示されます。選択した後に部分が（別のウィンドウで）変更されていた場合、**Apply** は実行されず、もう一度選択し直す必要があります。部分をエディタで編集している間は、エディタの選択が使われ、その編集は先に保存されます。

<a id="what-follows-a-generated-part"></a>

### 生成された部分の後に続く処理

あなたが（ページやコマンドバーから）生成した部分が完成すると、本はその部分に対して自動的に次の処理を、この順番で行うことがあります。

1. **Annotate**（注釈）: [自動注釈](annotations.md#annotating-every-new-part-automatically) がその部分を確認します。
2. **Redraft**（書き直し）: 注釈の指摘に対応するため、その部分を書き直します。
3. **Translate**（翻訳）: [Real language](../extensions/real-language-translator.md) と [Conlang](../extensions/conlang-translator.md) の翻訳機能が、その部分の発話を翻訳します。
4. **Knowledge**（知識）: [Knowledge Tracker](../extensions/knowledge-tracker.md) がその部分を読み取ります。
5. **Audio**（音声）: [オーディオブック](../extensions/audiobook.md) がその部分を音声にします。

本で有効にされた手順だけが実行されます。これらはサーバー上で動くため、ページを閉じても続きます。また、[実行中の処理パネル](#the-panel-of-the-runs) では一つの項目にまとめられます: *After part 14: Annotate ✓ · Redraft … · Translate*（部分 14 の後: 注釈 ✓ · 書き直し … · 翻訳）。モデルの文章と **Stop** は一つだけです。テキストを変更する手順が先に実行されるため、トラッカーとオーディオは最終的なテキストを受け取ります。あなたの判断を待つ手順（注釈や書き直しの選択）は、そのウィンドウを開き、項目には別のページで開くための **Review** が表示されます。

- **Stop** を選ぶか、あなたを待っているウィンドウを閉じるか、手順が失敗すると、そこで処理が終わります。それまでに行われた作業は残り、残りは実行されません。何が残っているかはメッセージで示され、手動で行う必要があります（各手順には部分に対する独自の操作があります）。
- **書き直し** が実行中の間は、次の部分を生成できません（どの処理によるかが表示されます）。他の手順が実行中であれば、生成できます。
- テキストが最終版になるまで、部分を削除することはできません。部分をもう一度生成すると、それ以前の版に続いていた処理は終了します。
- [エージェント](../agents.md) はこれらの手順を自分のコマンドで実行します。エージェントが生成した部分の後には、何も続きません。
<a id="merging-a-part-into-the-previous-one"></a>

## パートを前のパートに統合する

モデルが文の途中で止まった場合（応答の上限や接続の切断など）、同じ文章の続きを確実に書かせることはできません。代わりに次のパートを書き（*前のパートが止まった箇所から続けて*）、2つを**前のパートに統合**で結合します。統合は2つ目のパートのメニューから行います。確認画面が開きます。

- **テキストのつなぎ方**: 空行、改行、スペース、または何もなし。前のテキストの末尾から初期値が選ばれます。文末で終わっている場合は段落、途中で切れている場合はスペースになります。
- 両方のターンの**シーン設定**、**POV キャラクター**、**登場キャラクター**、**指示**。編集可能な欄にまとめられます。2つのターンの冒頭で共通する部分は一度だけ残ります。たとえば「決闘を書く。短くすること」と「決闘を書く。雨を加える」からは、最初の行に「決闘を書く。」、次の行に「短くすること」「雨を加える」がそれぞれ入ります。
- **データ**: 2つのパートが保持している値を一つずつ示します（たとえば物語の[変数](../templates/macros.md)や拡張機能のデータ）。各値が同じか、異なるか、どちらか一方のパートにだけあるかを表示します。統合されたパートは、別の選択をしない限り、**後のパート**（物語が今いる位置）の値を保持します。前のパートの値を選ぶか、値を省くこともできます。同じ値は、求めない限り隠されます。

![前のパートに統合する前の確認画面](../../images/part-merge-dialog.png)

前のパートはその位置、要約、生成方法（プロンプト、モデル、時刻）を保持します。結合されたテキスト、結合された推論、画像を受け取り、語数とトークン数は再計算されます。統合された側のパートは削除され（[ごみ箱](../trash.md)に入ります）、その後に続いていたものは前のパートから続きます。2つのパートにまたがる要約は、編集後と同様に古いものになります。統合されたパートの[履歴](version-history.md#backups-copies-and-the-trash)は削除され、残されたパートは結合テキストを**統合済み**のバージョンとして持ちます。パートが本の最初のパートである場合、または前のパートに他の続き（パートのスワイプ）がある場合は、統合できません。その場合は先に削除するか、分岐にしてください。

<a id="images"></a>

## 画像

パートには画像を付けられます。地図、キャラクターの肖像、挿絵などです。パートのメニューから**画像**を選ぶと、そのパートの画像の一覧が開きます。

![パートの画像ダイアログ](../../images/images-dialog.png)

- **画像を追加**（または、その上にファイルをドロップ）で、PNG、JPEG、GIF、WebP の画像を最大 10 MB までアップロードできます。WebP の画像は、Word や PDF ファイルには WebP を含められないため、アップロード時に PNG に変換されます。
- **キャプション**は画像の下に表示されます。空欄でもかまいません。
- **パート内の位置**は 3x3 のグリッドです。列はテキストの側（左、中央、右）、行はテキストの中での位置を表します。上はテキストの前、中段はテキストの中ほど、下はテキストの後です。マスをクリックして選びます。
- **テキストを画像の周りに回り込ませる**を使うと、画像の上下ではなく、テキストを画像の周囲に回り込ませられます。左または右に置いた場合、テキストは画像の横に流れます。中央の列では、画像の両側にテキストが流れます。その行にあるテキストのブロックのうち数個（約 400 文字、少なくとも 2 ブロック）が 2 段組になり、最初の部分が画像の左、残りが右に入ります。テキストは左の段を下に読み、続きを右の段で読むことになります。同じ位置にある 2 枚の画像は、段の間で上下に並びます。テキストに 2 段組にする余地がない場合（段落が 1 つだけの場合や、ブロックが上の帯ですでに使われている場合）、画像は中央揃えの独立したブロックになります。
- **幅**は、テキストの幅に対する画像の幅の割合です。**自動**では画像のサイズを保ちます（テキストより広くはなりません。両側にテキストがある画像は 30 % になります）。テキストが横に流れる画像は最大 60 %、両側にテキストがある画像は最大 40 % で、テキストに一定の余白が残ります。高さは画像の縦横比に従います。
- ごみ箱ボタンで、画像をパートから削除します。

![画像の位置: 中央に置き、テキストが周囲に回り込んでいる様子](../../images/images-position.png)

**ビューアでのプレビュー**（ダイアログのボタン。パートに画像がある場合は、パートのメニューにも同じ項目があります）は、本の文字スタイルを使って、パートを[ビューア](publishing.md)と同じように表示します。画像は指定した位置に置かれ、広い画面と狭い（スマートフォンの）画面を切り替えるスイッチがあります。プレビューは、エディタの現在のテキストをそのまま使います。保存されているかどうかは問いません。

![プレビュー: 2 段組のテキストの間に画像がある様子](../../images/images-preview.png)

ストーリーエディタ自体は位置を使いません。パートのテキストの下に、一覧として画像を表示します。位置は、ビューアと[エクスポート](export.md#images)で使われます。

画像をテキストのどこに置くかは、画像に保存された番号によって決まるのではありません。テキストはブロック（段落、リスト、引用、コードブロック）の間で区切られ、ブロックが途中で切られることはありません。そのため、テキストを編集しても画像は正しい場所に残ります。中央とは、テキストの中央に最も近いブロックの間の場所です。テキストが下端で回り込む画像は、最後のブロックの前に置かれるため、少なくともそのブロックが画像の横に来ます。同じ位置にある画像は一覧の順序を保ちます。同じ位置にあり、テキストを回り込ませない画像同士は、収まるならば横に並びます。PDF と Word は、幅を持つ画像についてこれを行います。

画像は**テキストの一部ではありません**。モデルは画像を見ることがなく、プロンプトにも含まれず、トークンとして数えられず、[要約](summaries.md)も変わりません。また、Markdown でもありません。テキストに書かれた `![](...)` のリンクはパートの画像にはなりません。代わりに**画像**を使ってください。

知っておくと便利なこと:

- **再生成**は、生成に失敗した場合でもパートの画像を保持します。**スワイプ**は新しいパートを（古いものの隣に新しいバージョンとして）書き、画像のない状態で始まります。**ストーリーを分岐**は、画像を新しいパートにコピーします。
- 画像はあなたのアカウントに属します。公開された本では、読者も[ビューア](publishing.md)で画像を見られます。ただし、本の*概要*タブで**読者に画像を表示**のチェックを外した場合は除きます。
- [バックアップ](backups.md)は、パートがどの画像を持っていたかは覚えていますが、画像ファイル自体は含みません。別のアカウントや別のインストール環境にバックアップを復元すると、画像のないパートになります。
- パートから画像を削除しても、パートから外れるだけです。ファイルは残り、[リソース](../resources.md)に一覧されたままです。そこでダウンロード、差し替え、削除ができます。リソースで削除すると、その画像を使っているすべてのパートから取り除かれます。ファイル自体はデータフォルダに残ります。

## 要約

下部バーの**要約**ボタン（設定メニュー ⚙ の左）を押すと、分岐の要約の一覧が開きます。ここで要約の編集、削除、メタ要約へのマージができます。ボタンのツールチップには、使用中の要約がプロンプトで何トークンを占めているかが表示されます。詳しくは[要約](summaries.md#the-summaries-overview)を参照してください。

<a id="how-much-of-the-context-the-story-takes"></a>

## 物語がコンテキストに占める量

設定メニュー（⚙）には**ブランチのトークン**があります。何かを生成する前に、有効な分岐の物語がプロンプトのどれだけを占めるかを表示します。**要約なし**（すべてのパート）と**要約あり**（要約と、最新のパートより後のパート）の2つのバーと、パートごとのトークン数と、**プロンプトの予算**（本のモデルのコンテキストから応答に残す分を引いたもの）に対する割合の表です。物語をまだ表している要約だけが数えられます。内容が合わなくなった要約は名前が示され、パートが生成されるときに除外されます。ロアブック、システムテンプレート、そのターンの指示も、同じ予算の一部を占めます。コンテキストサイズのあるモデルがない場合、表には割合が表示されません。

## ロアの使用状況

設定メニュー（⚙、**分析**）の **ロアの使用状況** では、本のロアブックのどの項目が生成で使われ、どれが一度も使われなかったかを確認できます。
推測ではなく実際の使用状況に基づいて、ロアブックを整理できます。各生成は、プロンプトに入った項目（とそのトークン数）を記録しており、ウィンドウはそれをパート全体で集計します。

- **パート** で集計対象を選びます。**アクティブなブランチ** なら現在のブランチのみ、**すべてのブランチ** なら本のすべてのブランチとすべてのスワイプが対象です。
- **開始パート** と **終了パート** で範囲を絞ります。番号はアウトラインに表示されるものと同じで、ブランチの最初のパートは 1 です。すべてのブランチの場合、番号はツリー内での深さを表します。範囲を指定しない場合は空欄のままにします。
- **表示** では、集計したパートのうち、**未使用**、**時々使用**、**常に使用** のいずれかの項目を残すことができます。

![ロアの使用状況ウィンドウ](../../images/lore-usage.png)

表には、本のロアブックのすべての項目が1行ずつ、使用回数の多い順に並びます。各行には、所属するロアブック、「未使用」「時々使用」「常に使用」のいずれかの区分、使用されたパート数（記録のあるパートのうち、割合付き）、全パートでの合計トークン数と使用1回あたりのトークン数、そして初めて使われたパートと最後に使われたパートが表示されます。見出しをクリックすると並べ替えられます。以前は使用されていたものの、現在は本のロアブックにない項目（削除された、移動された、ロアブックがオフになった、または本のものではなくなった）は、*現在ロアブックにありません* と表示されたままリストに残ります。削除された項目には名前がありません。

記録のあるパートだけが集計されます。手入力したパート、Marginalia がこの記録を保存するようになる前に書かれたパート、ロアブックがない本で書かれたパートには記録がないため、集計対象になりません。ウィンドウには、その数も表示されます。*常に使用* の項目は常時発動の項目である可能性があります。*未使用* の項目は、削除するか、より適切なフィルターに置き換える候補です。項目がなぜ今発動しないのかは、ロアブックエディターの [**発動をプレビュー**](../lorebooks/entries.md#preview-activation) で確認できます。

## テキストのスタイル

下部バーの設定メニュー（⚙）には **外観 → テキストのスタイルを変更** があり、スタイルごとに1項目ずつ、名前順で並んでいます。
スタイルの作り方は [スタイルガイド](styling-guide.md) を参照してください。
スタイルは、パートのテキストの見た目（フォント、サイズ、色、配置、見出しなど）を決めます。アプリケーションには、変更できない2つのスタイルが用意されています。**通常**（アプリケーションの見た目）と **本**（本のような読みやすいスタイルで、[ビューアー](publishing.md) が使うもの）です。独自のスタイルは [設定 → スタイル](../account.md#styles) で作成できます。

- 最初の項目 **既定（...）** は、あなたの *既定のスタイル*（*設定 → スタイル* で選んだもの。選んでいない場合は通常）に従います。新しい本には独自のスタイルがなく、この項目が表示されます。
- 別の項目を選ぶと、そのスタイルが **本の中に** 保存されます。そのため、既定の設定よりも優先されますが、適用されるのはその本だけです。チェックが付いた項目が、現在その本に設定されているスタイルです。**既定** を選ぶと、この設定を取り消せます。
- 削除したスタイルは、それを使っていた本では既定のスタイルに戻ります。

![外観、テキストのスタイルを変更：選択できるスタイル](../../images/story-style-menu.png)

**本** スタイルでは、段落は両端揃えになり、長い単語は自動的にハイフネーションされます。このとき使われるのは、本の **言語**（[情報タブ](managing-books.md#the-about-tab) で設定）の辞書です。ハイフネーションはブラウザが行います。一部の珍しい言語では辞書がないため、テキストはハイフネーションされません。

古い *テキストのスタイルを変更* のスイッチをオンにしていた本は、別の項目を選ぶまで引き続き本スタイルで表示されます。

<a id="highlighting-generated-text"></a>

## 生成されたテキストのハイライト

設定メニュー（⚙）には、チェックのオン・オフを切り替えられる **生成されたテキストをハイライト** もあります。オンにすると、すべてのパートでモデルが書いた語句がハイライトされるので、あなたが追加したり書き直したりした部分が目立ちます。Marginalia は [パートのバージョン](version-history.md) をたどって文章を追跡します。各バージョンは直前のバージョンの上に重ねて比較され、両者に共通する語句は、それを書いた人の扱いのままになります。そのため、生成されたテキストに入力した一文は、モデルが残りの部分を何度書き直しても、あなたの文のままです。一度も編集していないパートは全体がハイライトされ、自分で書いたパートにはハイライトがありません。エージェントが書いた部分はモデルの文章として扱われます。このスイッチは保存されず、ページを開き直すとオフに戻ります。

[履歴がオフになっている](version-history.md) パートには追跡すべきバージョンがないため、最初にモデルが生成した文章と比較されます。ハイライトは [スマートフォン](../phone.md) でも使えます。

同じ集計から割合も求められます。本の **情報** タブには、**ブランチの執筆の内訳** と **計算** ボタンがあり、アクティブなブランチの単語のうち、あなたが書いた割合とモデルが生成した割合を表示します。また、[エクスポート](export.md) では、その内訳をファイルの末尾に記載できます。

![生成されたテキストのハイライトと設定メニュー](../../images/highlight-generated.png)

## コマンド

ストーリーの下にあるメニューの横には **コマンドライン** があります。`/` を入力するとコマンドが表示されるので、1つ選んで **Enter** キー（または再生ボタン）を押すと実行されます。コマンドの結果は、入力行の上に表示される小さなウィンドウに出ます。引数の書き方、ヘルプの内容、時間のかかるコマンドを止める方法については [コマンド](../commands/index.md) を参照してください。コマンドラインは、現時点ではデスクトップレイアウトのストーリータブにのみあります。
<a id="search-and-replace"></a>

## 検索と置換

設定メニュー（⚙）には、**本の履歴を消去**と**履歴のごみ箱を空にする**もあります。詳しくは[バージョン履歴](version-history.md#deleting-versions)を参照してください。

設定メニュー（⚙）には**検索と置換**もあります。これは、ストーリー全体の単語、名前、または語句を一度に変更するものです。ウィンドウには**検索する文字列**と**置換後の文字列**の入力欄があり、次のオプションがあります。

![設定メニューの検索と置換](../../images/story-settings-menu.png)

![検索文字列を入力した検索と置換ウィンドウ](../../images/search-replace-dialog.png)

| オプション | 既定値 | 意味 |
|---|---|---|
| **正規表現で検索** | オフ | 検索文字列は[正規表現](../regular-expressions.md)として扱われ、置換にはそのグループ（`$1`）を使えます。オフの場合、入力したとおりの文字列で検索します。 |
| **大文字と小文字を区別** | オン | 入力したとおりの大文字・小文字の文字列だけが見つかります（*John* は *john* を見つけません）。オフの場合、大文字・小文字は区別されません。**正規表現で検索**がオンの間は固定されます。 |
| **要約を検索** | オン | [要約](summaries.md)も検索され、変更の対象になります。 |
| **すべてのブランチを検索** | オフ | すべての[ブランチ](branches-and-story-tree.md)を検索します。オフの場合は、現在アクティブなブランチだけを検索します。 |
| **すべての要約を再検証** | オン | 置換後、本のすべての[要約](summaries.md)が再び有効になります。下記を参照してください。 |

正規表現を使う場合、大文字・小文字は常に入力どおりに扱われます。無視したい場合は `(?i)` で始めてください。**検索**ボタンを押します（入力欄の右側にあり、スマートフォンでは入力欄の下にあります）。進行状況バーで進み具合が分かり、その横の**停止**で中断できます。検索しても何も変更されません。

表には、一致する箇所のあるすべてのパートとすべての要約が、種類とIDとともに並びます。行を開くと、その中の一致箇所を見られます。一致箇所の前後の文章が、現在の状態と置換後の状態の両方で表示されます。長すぎて表示できない一致箇所や置換文字列は、*[検索文字列]* や *[置換文字列]* と書かれます。

![検索の一致箇所。最初のパートを開いた状態](../../images/search-replace-found.png)

**検索する文字列**または**置換後の文字列**の入力欄で **Enter** を押すと、**検索**を押したときと同じ動作になります。

検索が終わると、入力欄とオプションはロックされ、**置換**ボタンが有効になります。**再検索**を押すと、見つかった結果は忘れられ、ウィンドウのロックが解除されるので、検索を変更できます。**置換**を押すとストーリーが変更されます。置換が終わるまでウィンドウは完全に固定され（**停止**も効きません）、終わると再び空になります。置換されたパートは、自分で編集したときと同じく編集済みとしてマークされます。

[要約](summaries.md#when-summaries-become-outdated)が説明している本文を置換すると、その要約は古くなります。**すべての要約を再検証**がオンの場合、Marginalia は本のすべての要約の確認値を計算し直します（置換で触れなかったものや、以前から古くなっていたものも含め、すべてのブランチの要約が対象です）。そのため、置換後はすべての要約が有効になります。また、古くなった要約も、本文を確かめることなく有効になります。要約の内容がまだ正しいと分かっている場合にだけ使ってください。

このオプションがオフの場合、検索の対象になった要約だけが最新の状態にされます。対象外の要約（検索しないブランチの要約で、アクティブなブランチと前のパートを共有するもの、または要約を検索しない場合のすべての要約）は古くなります。そのような要約がある場合、Marginalia は件数を知らせ、続行するかどうかを尋ねます。以前から古くなっていた要約は、そのまま古い状態が続きます。

![要約が古くなることへの警告](../../images/search-replace-warning.png)

[スマートフォンのレイアウト](../phone.md)では、同じウィンドウの入力欄とボタンが上から下に並びます。表は種類とIDを示す1列だけになり、その下に一致箇所と置換後の文字列が表示されます。

[要約の一覧](summaries.md#search-and-replace-in-the-summaries)には、要約だけを対象とした同じウィンドウがあります。

同じ検索と置換は[コマンドライン](../commands/index.md#commands-that-come-with-marginalia)から `/search-replace-parts` で実行できます。この場合、置換の前に確認が入ります。

<a id="importing-into-the-book"></a>

## 本へのインポート

設定メニュー（⚙）の**インポートとエクスポート**の下に**インポート**があります。これは、ファイルから新しい本を作る本タブのウィンドウ（[本の管理](managing-books.md#creating-a-book)を参照）と同じものですが、今いる本に対して使われ、パートはストーリーに**追加されます**。**ソース**は、`.md` ファイルのzipアーカイブ、ドキュメント（Word、LibreOffice、RTF、Markdown、プレーンテキスト、EPUB）、Obsidian ボールトのzip、Scrivener プロジェクトのzipのいずれかです。それぞれ、本タブと同じテキストと同じオプション（パートあたりの語数と章の見出しレベル）があり、インポートで何が作られるかが1行で示されます。SillyTavern と LM Studio のチャットは提供されていません。これらはブランチの木構造であり、ストーリーの途中に置く場所がないためです。

**パートを置く場所**では、パートの配置場所を指定します。

- **ストーリーの最後**：アクティブなブランチの最後のパートの後（空の本の場合は最初のパート）。
- **パートの前**または**パートの後**：一覧からパートを選びます（番号はアクティブなブランチ上の位置で、本文の先頭も示されます）。パートは二つのパートの間に入ります。その場所の後に続いていたものすべて（そのすべてのブランチを含む）は新しいパートの後ろに続き、既存のパートは変更も作り直しもされません。ストーリーの終わりは元の位置のままです（ストーリーはその分だけ長くなります）。その場所を対象にしている要約は、新しいパートを含まない内容を説明しているため古くなります。[要約](summaries.md)のウィンドウに表示されるので、そこで作り直してください。

![本のインポートウィンドウ](../images/book-import-into.png)

アーカイブ内のパートは、ファイル名の順に並びます。ファイル名中の数字は数値として比べられるため（`2.md` は `10.md` より前になります）、フォルダの中にあるものも同様です。フォルダ、隠しファイル（`.name`）、`__MACOSX` フォルダ、`.md` 以外のファイルは読み飛ばされます。ファイルの内容はそのままパートのテキストになり、モデルに送られることも変更されることもありません。すべてのパートは、あなたが書いたものとして扱われます。

インポートの間は、取り込んだパートの数を示す進行状況バーが表示されます。**停止**を押すと、保存中のパートの後で終わります。すでに追加されたパートはストーリーに残り（インポートは取り消されません）、取り込まれた件数がメッセージで示されます。

<a id="after-an-import"></a>

### インポート後

パートが本に入ると、**インポート完了**ウィンドウが表示され、長い物語を書きやすくするための二つの操作を提案します（新しい本としてインポートされた場合は、その本が先に開かれ、ウィンドウが前面に出ます）。どちらも設定メニュー（⚙、**分析**）にもあるので、後から、または繰り返し実行できます。

- **要約を作成...**：インポートした内容の要約を書きます。[要約の作成](summaries.md#create-summaries)を参照してください。最初に実行してください。エージェントが作業中は本がロックされます。
- **エージェントで設定メモを作る...**：ストーリーを読み、登場人物、場所、物、用語を見つけて、本のロアブックの項目として書き出す[エージェント](../agents.md)を起動します。[設定メモ](../agents.md#lore-notes-of-an-imported-book)を参照してください。

**今はしない**はウィンドウを閉じ、どちらも行いません。

![インポート後のウィンドウ](../../images/import-finished.png)

同じインポートをロアブックに対して行う方法は、[インポートとエクスポート](../lorebooks/import-export.md#importing-an-archive-of-text-files)に説明があります。

## ストーリーのエクスポート

<a id="what-the-model-gets"></a>

## モデルに送られるもの

新しいパートごとに、Marginalia は次を送信します。

1. システムメッセージとしての**マスターテンプレート**。役割、[ロアブック](../lorebooks/index.md)の項目、視点、時制、文体、[要約](summaries.md)を含みます。[推論プロバイダー](../inference-providers.md#general-settings)のジェイルブレイク用プロンプトが有効な場合は、その先頭に置かれます。
2. アクティブなブランチの前のパートを、モデル自身の以前の応答として送ります。[コンテキスト上限](../protocols.md#limits)に収まる分だけ、新しいものから順に入ります。収まらない古いパートは除外されます（[要約](summaries.md)がカバーしている場合を除く）。
3. 新しいパートへの指示を含む**ユーザープロンプト**。

どのパートでも**プロンプトを表示**を押すと、実際に送信された内容が正確に表示されます。テンプレートについては[本のプロンプト](prompts.md)を参照してください。
