# GPU

グラフィックカードは、多くの場合、一度に一つのモデルしか保持できません。言語モデル、画像モデル、音声モデルのいずれかです。Admin ページの **GPUs** タブでは、同じカード上のモデルとサーバーが順番にカードを使えるようにできます。これにより、言語モデルがカードを占有している間に画像や音声書籍が始まってしまうことを防ぎ、必要になったときに言語モデルが戻ってくるようになります。

管理者が一度だけ設定します。その後、各ユーザーが自分の AI やバックエンドのロックを選びます。

<a id="what-it-is-made-of"></a>

## 構成要素

| | |
|---|---|
| **GPU** | 一枚のカード（または一度に一つのモデルしか保持できない任意のマシン）。その名前と、**Also used outside Marginalia**（[下記](#a-gpu-that-others-use-too)を参照）。 |
| **GPU lock** | GPU を使う一つの方法：その上に何が読み込まれているか。例えば同じ GPU 上の *Language model*、*ComfyUI*、*Speech* など。ロックは順序付きの二つのステップリストを持ちます。**acquire steps** はロックを確保するために読み込みます（コンテナを起動する、モデルを読み込む、先に外す必要のあるものを解放する）。**release steps** はロックを解放して、カードから外します（コンテナを停止する、モデルをアンロードする）。三つ目のリスト **steps before every job** は、GPU がそのロックを保持しているかどうかに関わらず、そのロックの各ジョブの前に実行されます（保持していない場合は acquire steps の前）。毎回確認しておくべきこと用です。他のものがカードを使った可能性があるためです。**Jobs at once** は、そのロックのジョブが同時に何件実行されるかを制限します（一度に一枚だけ生成する画像サーバーなら 1、制限なしなら 0）。 |
| **GPU step** | 一つの HTTP リクエスト：アドレス、メソッド、ヘッダー（`Name: value`、一行に一つ、暗号化して保存されるので bearer キーを書くこともできます）、ボディ、タイムアウト（空欄の場合は 60 秒）、そして応答後の待機時間。ステップは複数のロックから使えます。例えば、画像ロックと音声ロックの両方が最初に実行する *unload the language model* ステップ一つ。**Test** を押すと、すぐにリクエストを送信します。 |

![ロックのウィンドウ](../../images/gpu-lock-dialog.png)

ロックは次の場所で選択します：

- 言語モデルの場合は、[AI の設定](../inference-providers.md)（一般設定の **GPU lock**）；
- [Image Generator](../extensions/image-generator.md#one-gpu-for-the-model-and-the-images) のバックエンド；
- [Audiobook](../extensions/audiobook-server.md#one-gpu-for-the-model-and-the-speech) のバックエンド。

**GPU lock** の欄は、少なくとも一つロックが存在するときにのみ表示されます。

<a id="variables-in-the-steps"></a>

## ステップ内の変数

ステップには、そのジョブが何のためのものかを指定できます。こうすると、一つのステップで複数のモデルに対応でき、別のモデルを試すたびにロックを編集する必要がなくなります。アドレス、ヘッダー、ボディで使えます：

| 変数 | 値 |
|---|---|
| `{{model}}` | ジョブが使用するモデル：AI のモデル ID（AI 設定にあるとおり、例えば LiteLLM 経由の `openai/big-32b`）、音声書籍バックエンドのモデル（`higgs-audio-v3`、`chatterbox-turbo`）、音声認識または画像バックエンドのモデル。モデルを使わないジョブ（クリップのクリーンアップなど）では空。 |
| `{{lock}}` | ロックの名前 |
| `{{text_model}}` | テキスト生成ジョブのみ：そのAIのモデル ID（`{{model}}` と同じ）。音声・画像ジョブでは空。 |
| `{{last_text_model}}` | すべてのジョブ：そのジョブの開始時点で記憶されている、このロック上での直近のテキスト生成のモデル（テキストジョブは自分自身の値を見る）。最初のテキスト生成より前、および Marginalia の再起動後は空。 |

フィルターは値を変換します：`{{model | strip:openai/}}` は値が接頭辞で始まる場合にそれを取り除き（LiteLLM のルート名のように、その背後のサーバーが知らない名前）、`{{model | last}}` は最後の `/` の後ろにある部分を残し、`{{model | json}}` は JSON 文字列用にエスケープし、`{{model | url}}` はアドレス用にエンコードします。複数をつなげて使うこともできます（`{{model | last | json}}`）。acquire steps と steps before every job にはそのジョブの値が渡されます。release steps には、読み込まれているロックの直近のジョブの値が渡されます（アンロードされるモデル）。**Test** は、変数を空にした状態でステップを実行します。

<a id="how-the-turns-work"></a>

## 順番の仕組み

- モデルへのすべてのリクエスト、すべての画像、そして音声書籍のすべてのバッチやサンプルは、そのAIまたはバックエンドのロックを**その処理の長さの間**取得します。
- GPU がすでにそのロックで読み込まれている場合、ジョブはすぐに開始され、ロックの **steps before every job** を除いて、どのステップも実行されません。
- 別のロックで読み込まれている場合、ジョブは、そのロックのジョブがすべて終わるまで待ちます。次に、そのロックの **release steps** が（一つが失敗しても）すべて実行され、続いて steps before every job と新しいロックの **acquire steps** が（順番に。最初の失敗で中断され、ジョブはそのステップのメッセージとともに失敗します）実行されます。
- release step が失敗した場合、新しいロックはまったく読み込まれません（カードがまだ満杯の可能性があるため）。ジョブはエラーで失敗し、GPU は以前のロックのまま残ります。別のロックの次のジョブが、再びそれを解放しようとします。
- ジョブの後も GPU は**そのロックで読み込まれたまま**です。タイマーでアンロードされることはありません。開いたまま、折りたたまれた、または閉じられた画像ウィンドウは GPU を保持しません。画像モデルは、言語モデル（または別のロック）がカードを必要とするまで読み込まれたままです。
- ジョブは到着順に待ちます。あるジョブが別のロックを待ち始めると、読み込まれているロックの新しいジョブはそのジョブの後ろで待ちます。そのため、忙しい言語モデルが画像を永遠に待たせ続けることはありません。
- ロックがない AI やバックエンド、または削除されたロックを持つものは、何も待ちません。

GPU が何を保持しているかは、アプリケーションが動作している間だけ分かります。再起動後は、何も読み込まれていないものとして扱われ、最初のジョブは acquire steps のみを実行します。

<a id="a-gpu-that-others-use-too"></a>

## 他でも使われる GPU

ロックが順序付けるのは Marginalia のジョブだけです。Marginalia がカードの保持内容として把握しているのは、自身のジョブからの情報だけです。Marginalia の再起動後、または別のプログラム、スクリプト、人がカードにモデルを読み込んだ場合（言語モデルを起こすルーターへのリクエスト、ComfyUI 自身のページでキューに入れられたワークフローなど）、Marginalia が読み込まれていると考えている内容は誤っており、満杯のカードでジョブが開始されることがあります。

- GPU に設定された **Also used outside Marginalia** は、Marginalia が自身の把握内容を信用しないようにします。この場合、**acquire steps は GPU がロックを切り替えるときだけでなく、すべてのジョブの前に実行されます**（release steps は切り替え時にのみ実行されます）。その場合、各ロックの acquire steps は自分で場所を空けなければなりません（他のモデルをアンロードする、他のサーバーを停止する）。また、繰り返し実行しても安全でなければなりません。すでに動いているサーバーの起動、読み込まれていないモデルのアンロード、停止済みコンテナの停止は、いずれも成功を返す必要があります。そうしないと、すべてのジョブが失敗します。この場合、すべてのジョブでこれらのリクエストの分の負荷がかかります。
- **Steps before every job** は、他のロックには触れず、一つのロックに対して同じことを行います。毎回確認すべきステップ（他のプログラムのモデルをアンロードする、サーバーが応答することを確認する）だけがすべてのジョブの前に実行され、残りは切り替え時のみ実行されます。
- これに適した安全な場所は、すべてのユーザーが通る GPU マシンそのものです。例えば、*start ComfyUI* が先に言語モデルをアンロードするプロキシや、言語モデルを読み込む前に ComfyUI を停止するルーターのフック。そうすれば、どのプログラムが要求しても、誰もカードを二重に埋めることはできません。

<a id="the-tab"></a>

## タブ

タブには GPU の一覧が、それぞれ現在読み込まれているロック（まだ何も実行されていない、またはアンロードされた場合は *Unknown*）と、その上で実行中・待機中のジョブ数とともに表示されます。続いてロックとステップが、それぞれ追加、編集、削除のボタン付きで並びます。**Refresh** は GPU が保持している内容を再度読み込みます。

![GPU、ロック、ステップを含む GPUs タブ](../../images/admin-gpus.png)

**Unload now** は GPU を手動で解放します。例えば、Marginalia の外でカードを使いたいときなどに使います。実行中のジョブを待ち、読み込まれているロックの release steps を実行して、GPU を unknown の状態にします（ステップが失敗した場合も同様です。メッセージにどのステップかが示されます）。次のジョブは、そのロックを再び読み込みます。

GPU を削除すると、そのロックも削除されます。ステップを削除すると、それを実行していたロックから取り除かれます。削除されたロックを指定していた AI やバックエンドは、ロックなしで実行されます。
<a id="an-example-one-card-several-models"></a>

## 例：1枚のカードで複数のモデルを使う

LiteLLM の後ろに `llama-server` を置き、コンテナを起動・停止する [`tools/gpu-control`](../extensions/audiobook-server.md#what-answers-those-addresses) 形式のプロキシを使う場合：

| 手順 | リクエスト |
|---|---|
| Unload the language model | ヘッダー `X-Llama-Unload: all` を付けて `POST http://litellm:4000/v1/chat/completions` を送る（[別のモデルのために GPU を空ける](../prompt-cache.md#freeing-the-gpu-for-another-model)を参照） |
| Start ComfyUI / Stop ComfyUI | `POST http://litellm:4000/gpu/comfy/start` / `.../stop` |

Marginalia だけがこのカードを使う場合、各ロックは自分の分だけを解放し、それ以上は解放しません。

| ロック | 取得時の手順 | 解放時の手順 | 同時ジョブ数 |
|---|---|---|---|
| Language model | （なし：ルーターが次のリクエストでモデルを読み込む） | Unload the language model | 1 |
| ComfyUI images | Start ComfyUI | Stop ComfyUI | 1 |
| ComfyUI speech | Start ComfyUI | Stop ComfyUI | 1 |
| ComfyUI speech recognition | Start ComfyUI | Stop ComfyUI | 1 |
| Clip cleanup | Start ComfyUI | Stop ComfyUI | 1 |

チャットの後に音声のバッチを実行すると、*Unload the language model*（言語モデルの解放）と *Start ComfyUI* が走ります。次のチャットメッセージは、まず *Stop ComfyUI* を実行します。ComfyUI のロックを分けているのは意図的です。あるロックから別のロックに移るときに ComfyUI が停止・起動され、それによってアンロード後もモデルが保持するメモリが解放されます（fp32 の Higgs はサーバーのメモリを約 16 GB 保持します）。そのため、画像モデル、Higgs、認識モデル、クリーンアップモデルが同時に載ることはありません。

**Also used outside Marginalia** を設定した場合は、代わりに各取得が自分で空きを作る必要があります。*Language model* は *Stop ComfyUI* を実行して取得し、ComfyUI の各ロックは *Unload the language model, Start ComfyUI* を実行して取得します。

別のプログラムが、独自のモデル（例えば音声モデルの隣にある小さなモデル）を持つ**同じ `llama-server` ルーター**を使う場合、*Unload the language model* はそのモデルも取り除いてしまいます。また、そのプログラム自身のアンロードは Marginalia のモデルを取り除いてしまいます。`tools/gpu-control` には、指定したモデル**以外**のルーター上のすべてのモデルをアンロードする呼び出しがあります。ボディ `{"keep": ["{{model | strip:openai/}}"]}` を持つステップ `POST http://litellm:4000/gpu/llama/unload` です（詳細は README のパススルーを参照）。これを *Language model* の**すべてのジョブの前のステップ**にしてください。そのロック上の各 AI は、どのモデルを残すかを選んで、自分のモデルを保持します。もう一方のプログラムも、各ジョブの前に自分のモデルに対して同じことを行います。残すモデルだけが読み込まれている場合、この呼び出しは何もせずすぐに応答するので、どちらのプログラムも相手を意識する必要はありません。

1つのロックで言語モデルと音声モデルの両方を担当する場合（両者はカード上で並行して動作します）、そのステップの `{{model}}` は音声ジョブの間は音声モデルになります。これはどのルーターのモデルにも一致しないため、各応答の直後に言語モデルがアンロードされてしまいます。代わりに `{{last_text_model}}` を、`{"keep": ["{{last_text_model | strip:openai/}}"]}` として使ってください。ロックのすべてのジョブは、ジョブの種類を問わず、直前のテキスト生成で使われたモデルを保持します。最初のテキスト生成の前には何も保持されず、最初のテキスト生成でそのモデルが読み込まれます。

ComfyUI の場合も同じ種類のステップは `POST http://litellm:4000/gpu/comfy/ensure` です。ComfyUI が応答していれば何もせず、停止していればコンテナを起動します。稼働しているのに ComfyUI が応答しない場合（内部でクラッシュした、またはハングした）は再起動し、準備ができるまで待ちます。ComfyUI のロックのすべてのジョブの前のステップとして実行すると、誰が停止させたかに関係なく、ComfyUI が稼働している状態になります。

言語モデルの AI は *Language model* を、画像バックエンドは *ComfyUI images* を、音声バックエンドは *ComfyUI speech* を選びます。Audiobook の [音声認識](../extensions/audiobook.md#speech-recognition) と [クリップのクリーンアップ](../extensions/audiobook.md#cleanup-of-clips) も、それぞれ独自のロックを使います。
