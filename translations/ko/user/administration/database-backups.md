# 데이터베이스 백업

데이터베이스 백업은 Marginalia 데이터베이스 전체의 완전한 복사본입니다. 모든 사용자와 그들의 모든 책, 로어북, 설정 및 확장 데이터가 포함됩니다. 실수나 장애로부터 설치를 보호하고, 다른 컴퓨터로 옮기는 데 사용합니다. 책 한 권만 백업하려면 사용자는 [책 백업](../books/backups.md)을 이용하면 됩니다.

![데이터베이스 백업 탭](../../images/admin-database-backups.png)

<a id="creating-a-backup"></a>

## 백업 만들기

**데이터베이스 백업** 탭에서 **백업 생성**을 클릭합니다. 복사본은 Marginalia가 실행 중일 때 만들어지며, 사람들이 글을 쓰는 중에도 일관성이 유지됩니다. 백업은 **이름**, **생성됨** 날짜, **유형**(*수동* 또는 *예약*), **크기**와 함께 목록에 나타납니다. 도구 모음에는 데이터베이스의 현재 크기가 표시됩니다.

각 백업에는 다음이 있습니다:

| 버튼 | |
|---|---|
| **다운로드** | 백업 파일(`.sqlite`)을 다운로드합니다. 서버 외부에 사본을 보관하세요. |
| **재시작 시 복원** | 백업을 복원합니다. [아래](#restoring)를 참고하세요. |
| 휴지통 | 백업을 삭제합니다. |

**백업 업로드**는 백업 파일(`.sqlite` 또는 `.db`)을 목록에 추가합니다. 예를 들어 다른 설치 환경에서 다운로드한 파일을 추가할 수 있습니다. 파일은 먼저 검사되며, SQLite 데이터베이스가 아니거나, 손상되었거나, Marginalia 데이터베이스가 아니거나(다른 애플리케이션의 데이터베이스), 실행 중인 버전보다 새로운 Marginalia 버전에서 만들어진 경우에는 *데이터베이스를 복원할 수 없습니다: ...*라는 메시지와 함께 거부되며 그 이유가 표시됩니다.

!!!warning 백업에는 비밀 정보가 포함됩니다
데이터베이스 백업에는 모든 사용자의 비밀번호 해시와 API 키를 포함한 모든 것이 들어 있습니다. API 키는 [데이터 폴더](index.md#the-data-folder)에 있는 `secret.key` 파일로 암호화되어 있으며, 이 파일은 백업에 포함되지 않습니다. 하지만 백업과 `secret.key`를 모두 가진 사람은 API 키를 읽을 수 있습니다. 다운로드한 백업은 서버 자체와 같은 수준으로 안전하게 보관하세요.
!!!

파일은 [데이터 폴더](index.md#the-data-folder)의 `db-backups` 폴더에 저장됩니다. Marginalia가 스스로 만든 사본인 `pre-restore-...`(a [복원](#restoring) 전에 만들어짐)과 `pre-migration-...`([업그레이드](#copy-before-an-upgrade) 전에 만들어짐)도 목록에 *수동*으로 표시되며, 따라서 예약 백업의 순환 삭제 대상이 되지 않습니다. 책 백업과 확장 프로그램 JAR 파일은 별도의 파일이며 데이터베이스 백업에 포함되지 않습니다.

**업로드된 파일([파트 그림](../books/story-editor.md#images))도 데이터베이스 백업에 포함되지 않습니다.** 데이터베이스는 이 파일들을 [리소스](../resources.md) 탭의 항목으로만 알고 있으며, 파일 자체는 데이터 폴더의 `data/<login>/images` 폴더에 있습니다. 이는 문제가 없습니다. 복원 후에도 항목은 백업 시점의 것이며, 그 항목이 사용하는 그림 파일도 폴더에 그대로 남아 있습니다. 백업 이후에 추가된 그림의 파일은 참조하는 항목이 없는 상태로 남아 디스크 공간을 차지합니다. 그림을 안전하게 보관하려면 자신의 백업에 데이터 폴더 전체를 포함하거나, [책 백업](../books/backups.md#pictures-in-a-backup)에 그림을 함께 묶으세요.

**다른 설치 환경**에서 백업을 복원할 때는 (Marginalia를 중지한 상태에서) 원래 설치 환경의 `secret.key`도 함께 복사하세요. 그렇지 않으면 저장된 API 키를 복호화할 수 없어서 모든 사용자가 다시 입력해야 합니다.

<a id="scheduled-backups"></a>

## 예약 백업

**예약 백업** 섹션은 백업을 자동으로 만듭니다:

| 필드 | |
|---|---|
| **백업 자동 생성** | 예약 백업을 켭니다. |
| **일정 (cron)** | 백업을 만들 시점입니다. [아래](#schedule-syntax)를 참고하세요. 다음 세 번의 실행 시각이 필드 아래에 표시됩니다. |
| **예약 백업 보관 수** | 보관할 예약 백업의 개수이며, 이보다 오래된 백업은 삭제됩니다. `0`이면 모두 보관합니다. 수동 백업과 업로드한 백업은 절대 삭제되지 않습니다. |

**일정 저장**을 클릭하여 적용합니다. 상태 줄에는 마지막 예약 백업이 만들어진 시각과 다음 백업이 예정된 시각이 표시됩니다.

예약된 시각에 Marginalia가 실행 중이 아니었다면(글을 쓸 때만 실행되는 데스크톱 앱에서 흔한 경우), 다음 시작 후 약 30초 뒤에 놓친 백업을 만듭니다.

<a id="schedule-syntax"></a>

### 일정 문법

일정은 다섯 개의 필드로 이루어진 cron 표현식입니다: `분 시 일 월 요일`

| 표현식 | 실행 시점 |
|---|---|
| `0 3 * * *` | 매일 3:00 |
| `0 */6 * * *` | 6시간마다 |
| `30 2 * * 1` | 매주 월요일 2:30 (요일: `0` 또는 `7`은 일요일, `1`은 월요일...) |
| `0 12 1 * *` | 매월 1일 정오 |
| `@daily`, `@weekly`, `@monthly` | 자정에 하루 한 번 / 일주일에 한 번 / 한 달에 한 번 (`@hourly`, `@yearly`도 사용 가능) |

시각은 서버의 시간대를 기준으로 합니다(Docker에서는 `TZ` 환경 변수로 설정합니다).

!!!
예약 백업을 끄려면 *백업 자동 생성*의 체크를 해제하고 *일정 저장*을 클릭합니다. 표현식은 그대로 유지되므로 나중에 다시 백업을 켤 수 있습니다. 표현식은 여전히 검사되며, 잘못된 표현식은 절대 저장되지 않습니다. 다만 백업이 꺼져 있는 동안에는 필드가 비어 있을 수도 있습니다.
!!!

<a id="restoring"></a>

## 복원

Marginalia가 데이터베이스를 사용하는 동안에는 데이터베이스를 교체할 수 없으므로, 복원은 **다음 시작** 때 이루어집니다:

1. 백업 옆의 **재시작 시 복원**을 클릭하고 확인합니다.
   탭에 *데이터베이스 복원이 예약되었습니다. 적용하려면 애플리케이션을 재시작하세요.*가 표시됩니다. **복원 취소**를 누르면 이를 되돌릴 수 있습니다.
2. Marginalia를 재시작합니다. [데스크톱 앱](../getting-started/desktop-app.md)을 종료한 뒤 다시 실행하거나, [서버](../getting-started/docker-server.md)에서 `docker compose restart`를 실행합니다.

시작할 때 현재 데이터베이스는 `db-backups/pre-restore-<time>-marginalia.sqlite`로 옮겨집니다. 이 파일은 목록에 나타나므로, 이 파일을 복원하여 복원 작업을 되돌릴 수 있습니다. 그 자리에 백업이 들어갑니다. 이전 Marginalia 버전에서 만들어진 백업은 자동으로 업그레이드됩니다.

백업은 교체되기 전에 다시 검사됩니다(*백업 업로드*와 같은 검사이며, *재시작 시 복원*도 이 검사에 실패한 백업은 거부합니다). 검사에 실패하거나 업그레이드가 실패하면 Marginalia는 현재 데이터베이스를 그대로 유지(또는 원래대로 되돌림)하고 정상적으로 시작합니다. 거부된 파일은 `db-backups/rejected-restore-<time>-marginalia.sqlite`로 옮겨지며, 로그에 그 이유가 기록됩니다.

백업 이후의 모든 것은 사라집니다. 그 이후에 만든 책, 파트, 설정이 모두 해당됩니다. 로그인한 사용자는 계정이 바뀌었다면 다시 로그인해야 합니다.

<a id="copy-before-an-upgrade"></a>

## 업그레이드 전 복사본

Marginalia의 새 버전이 기존 데이터베이스의 구조를 변경하려고 할 때, 먼저 `db-backups/pre-migration-<time>-V<version>-marginalia.sqlite`로 복사본을 저장합니다. 여기서 버전은 데이터베이스가 있던 버전입니다. 이 복사본은 백업 목록에 포함되므로, 예전 버전의 Marginalia를 설치한 뒤 그 복사본을 [복원](#restoring)하면 업그레이드를 되돌릴 수 있습니다. 최근 세 개의 복사본이 보관됩니다. 새 설치에는 복사할 것이 없으며, 복사본을 만들 수 없는 경우(예: 디스크가 가득 찬 경우)에는 로그에 그 사실이 기록되고 업그레이드는 계속 진행됩니다.

중간에 실패한 마이그레이션은 스스로 롤백되며 Marginalia는 시작되지 않습니다. 이 복사본은 업그레이드가 완료되었지만 원하지 않는 변화가 생긴 경우를 위한 것입니다.

<a id="moving-to-another-computer"></a>

## 다른 컴퓨터로 옮기기

1. 백업을 만들고 **다운로드**합니다.
2. 새 컴퓨터에 Marginalia를 설치하고, 처음 시작할 때 임시 관리자를 만듭니다.
3. **백업 업로드**, **재시작 시 복원**을 누르고 재시작합니다.
4. 백업에 있던 계정으로 로그인합니다.

이전 [데이터 폴더](index.md#the-data-folder)의 `data` 폴더(책 백업과 파트 그림)와 `extensions` 폴더도 복사합니다. 또는 Marginalia를 중지한 뒤 `.marginalia` 폴더 전체를 복사해도 됩니다.
