# 이미지 생성기

이야기의 한 부분에 맞는 그림을 만듭니다. 모델이 그 부분을 읽고 이미지 프롬프트를 쓰면, 사용자가 프롬프트를 고칩니다. 그다음 이미지 백엔드가 그림을 그리고, 사용자가 마음에 들 때까지 다시 그리기를 반복한 뒤 수락합니다. 수락한 그림은 해당 부분의 이미지가 되며, 부분 메뉴의 *이미지*로 직접 추가한 그림과 같게 취급됩니다(이야기에 표시되고 내보내기에도 포함됩니다).

이 확장 기능은 직접 그림을 만들지 않습니다. **ComfyUI** 서버나 **OpenAI images API**를 지원하는 서버와 통신합니다(stable-diffusion.cpp, LiteLLM 및 여러 호스팅 서비스도 이 API를 사용합니다).

<a id="adding-a-backend"></a>

## 백엔드 추가하기

*설정 → 확장 기능 설정 → 이미지 생성기 설정*에 백엔드 목록이 있습니다. (+)를 눌러 하나를 추가하고 항목을 채운 뒤 *설정* 페이지를 저장하세요.

| 설정 | 기능 |
|---|---|
| 이름, 유형 | 창에 표시되는 이름입니다. **ComfyUI** 또는 **OpenAI images API** 중 하나입니다. |
| 주소 | 서버의 기본 주소입니다. 예를 들어 ComfyUI라면 `http://localhost:8188`입니다. |
| API 키 | 베어러 토큰으로 전송됩니다. 암호화되어 저장되며 다시 표시되지 않습니다. 새 키를 입력해 바꾸거나 **Remove the key**를 누르세요. |
| 모델 | OpenAI images API 전용입니다. 요청의 `model` 값입니다. |
| 워크플로 | ComfyUI 전용입니다. ComfyUI에서 **Save (API Format)**로 저장한 워크플로입니다. 값이 들어갈 자리에 `{{prompt}}`, `{{negative}}`, `{{seed}}`, `{{width}}`, `{{height}}`를 적으세요. |
| 서버가 이 컴퓨터에 있거나 내 네트워크에 있음 | 로컬 네트워크 주소를 허용합니다. 클라우드의 서버라면 끄세요. 그래야 외부에서 사용자 컴퓨터를 호출하도록 만들 수 없습니다. |
| 너비, 높이, 네거티브 프롬프트 | 창을 열 때 처음 쓰이는 값입니다(해당 창에서 이미지 하나에 대해 바꿀 수 있습니다). |
| 제한 시간 | 이미지 한 장을 기다리는 최대 시간입니다. |
| 유휴 시 해제 | [GPU 하나 사용하기](#one-gpu-for-the-model-and-the-images)를 참고하세요. |

![설정의 백엔드](../../images/plugin-imagegenerator-settings.png)

**Test connection**으로 주소와 키를 확인할 수 있습니다.

패널에는 모든 프롬프트 앞에 붙는 **문체**(예: *수채화, 부드러운 빛*처럼 책의 분위기)와 **프롬프트 작성자를 위한 지시문**도 있습니다. 후자는 모델이 부분을 읽고 프롬프트를 쓸 때 참고하는 글입니다. 비워 두거나 그대로 두면 기본 지시문을 사용합니다.

<a id="making-an-image"></a>

## 이미지 만들기

![부분 메뉴의 이미지 생성](../../images/plugin-imagegenerator-menu.png)

1. 부분의 메뉴에서 **Generate image**를 선택합니다. 창의 모델(기본값은 책의 모델이며, 마지막으로 고른 선택이 기억됩니다)이 그 부분의 프롬프트를 쓰기 시작합니다. **Abort**로 멈추거나, 프롬프트를 고치거나, **Write the prompt with the model**을 눌러 다시 쓰게 할 수 있습니다. 다시 쓰기 전에 다음 항목을 채울 수 있습니다.
   - **Send lorebook entries** - 책의 로어북(및 하위 로어북)의 항목이 생성할 때와 같이 모델에 전달됩니다. 그래서 모델은 등장인물과 장소의 모습을 알 수 있습니다. 항목은 필터의 단어가 부분에서 발견될 때 전달됩니다. 필터 대상은 항목의 본문, 지시문, 장면 설정, 시점, 등장인물, 또는 *세부 사항*입니다. 항상 켜져 있는 항목도 함께 전달됩니다. 모델의 컨텍스트에 들어갈 만큼만 전달되며, 빠진 항목의 수는 알림으로 표시됩니다. 이 선택은 기억됩니다.
   - **Details** - 그림에 무엇이 보여야 하는지, 어떤 모습이어야 하는지 적습니다(*밤, 그녀의 얼굴 클로즈업, 빨간 드레스*처럼). 프롬프트 작성자가 이를 따릅니다. 이 내용은 이 창에서만 사용됩니다.
2. 백엔드를 고르고 **Generate**를 누릅니다. *크기와 네거티브 프롬프트* 아래에서 이 창에 대해 크기와 네거티브 프롬프트를 바꿀 수 있습니다.
3. 이미지가 나타납니다. **Reroll**은 새 시드로 다른 이미지를 만듭니다. **Discard**는 이미지를 버립니다. **Accept**는 이미지를 부분에 추가하고 창을 닫습니다. **Abort**는 만들고 있는 이미지를 멈춥니다(ComfyUI에는 작업을 중단하라는 신호가 갑니다).

![모델이 쓴 프롬프트가 있는 창](../../images/plugin-imagegenerator-prompt.png)

![이미지와 Accept, Discard, Reroll 버튼](../../images/plugin-imagegenerator.png)

<a id="one-gpu-for-the-model-and-the-images"></a>

## 모델과 이미지를 위한 GPU 하나

GPU가 작으면 언어 모델과 이미지 모델을 동시에 올릴 수 없습니다. 확장 기능은 메모리를 관리하지 않습니다. 대신 각 백엔드에 두 개의 요청 목록을 설정할 수 있습니다.

- **첫 이미지 전** - 창이 그 백엔드를 처음 쓰기 시작할 때 한 번 실행됩니다. 예를 들어 언어 모델을 내리고 이미지 모델을 올리도록 프록시에 보내는 요청이 여기에 해당합니다.
- **마지막 이미지 후** - 수락, 버리기, 창 닫기를 할 때 실행되거나, 마지막 이미지 이후 **유휴 시 해제**에 설정한 초가 지났을 때 실행됩니다. 그래서 잊어버린 창이 GPU를 계속 점유하지 않습니다(0이면 이 기능을 끕니다). ComfyUI라면 `POST <주소>/free`에 본문 `{"unload_models": true, "free_memory": true}`를 보내면 됩니다. 프록시라면 언어 모델을 다시 올리는 요청을 보내면 됩니다.

LiteLLM 뒤에서 라우터 모드로 실행 중인 `llama-server`라면, *전* 요청으로 프록시를 거쳐 언어 모델을 내릴 수 있습니다. 자세한 내용은 [다른 모델을 위해 GPU 비우기](../prompt-cache.md#freeing-the-gpu-for-another-model)를 참고하세요.

두 시점 모두 **요청 목록**을 받으며, 목록의 요청은 순서대로 하나씩 실행됩니다(**Add a request**로 요청을 추가하고, 휴지통 아이콘으로 제거합니다). 모델을 바꿀 때는 보통 여러 요청이 필요합니다. 예를 들어 언어 모델을 내리고, 이미지 서버를 시작하고, 이미지 작업이 끝나면 서버를 중지합니다. 각 요청에는 주소, 메서드(기본값 `POST`), 헤더(`이름: 값`, 한 줄에 하나), 본문, **제한 시간**(비우면 60초, 최대 600초이며, 큰 모델을 올리는 서버라면 더 길게 설정하세요), 그리고 **이후 대기**(응답 후 멈출 초, 승인 응답을 보냈지만 아직 바쁜 서버를 위한 설정)가 있습니다. 헤더는 API 키와 같이 암호화되어 저장됩니다(요청에 `Authorization: Bearer ...`가 자주 들어가기 때문입니다). 리롤하는 동안 백엔드는 계속 점유된 상태이므로, 모델을 바꾸는 비용은 첫 이미지에서만 듭니다. 모델 앞단의 프록시가 모델 이름으로 교체를 처리한다면 두 목록 모두 비워 두세요.

*전* 목록의 요청이 실패하면 나머지 요청은 실행되지 않고 이미지 작업도 멈춥니다(메시지에 어느 요청이 실패했는지 *Request 2 of 3: ...* 형식으로 나옵니다). 이렇게 해서 아직 가득 찬 GPU에 무언가 올라가는 일을 막습니다. *후* 목록은 요청 하나가 실패하더라도 **끝까지** 실행됩니다(모든 서버를 멈춰야 하기 때문입니다). 첫 실패는 경고로 표시됩니다. 이전 버전에서 단일 요청으로 저장된 백엔드는 목록의 첫 번째 요청으로 표시됩니다.

**한 GPU를 여럿이 쓰는 경우.** 같은 서버 주소(`http://host:port`)를 가진 백엔드를 쓰는 모든 사용자는 하나의 관문을 통과합니다. *전* 요청은 처음 시작된 창을 위해 한 번 실행되고, *후* 요청은 마지막 창이 끝날 때 실행됩니다. 그래서 한 창을 닫아도 다른 사람의 이미지 아래에서 모델이 내려가지 않으며, 이미지는 한 번에 하나씩 만들어집니다(두 번째 창은 차례를 기다립니다). 요청은 가장 먼저 시작하고 가장 나중에 끝낸 사용자의 요청입니다.

백엔드는 자신이 실행되는 GPU의 이름을 지정할 수도 있습니다(**GPU (이름)**). 같은 GPU 이름을 지정한 백엔드들은 주소가 달라도 서로를 기다립니다. [오디오북](audiobook.md) 백엔드도 여기에 포함됩니다(한 카드에 음성 서버와 이미지 서버를 함께 두는 경우). 다른 모델이 필요한 사용자는 나머지 사용자가 끝날 때까지 기다린 뒤에 자신의 요청을 실행합니다. 다른 사람의 로딩 작업에 끼어들지 않습니다. 비워 두면 같은 주소로 가는 요청끼리만 서로 기다립니다.

<a id="what-is-not-done"></a>

## 하지 않는 것

- 백엔드는 책마다가 아니라 사용자마다 설정합니다.
