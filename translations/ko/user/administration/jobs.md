# 작업

외부 AI에 Marginalia가 요청하는 모든 것은 *작업*입니다. 생성, 요약, 주석, 에이전트 실행, 장을 오디오로 변환하는 일, 이미지가 모두 여기에 해당합니다. 각 작업은 실행된 사용자, 시작 및 종료 시각, 종료 방식과 함께 기록되며, 모델이나 음성 또는 이미지 백엔드에 보낸 *호출*도 각각 고유한 시작 및 종료 시각과 함께 기록됩니다. 관리자 페이지의 **작업** 탭에서 이 기록을 볼 수 있고, `/jobs` 페이지에서는 지금 실행 중인 작업을 볼 수 있습니다.

저장되는 것은 메타데이터뿐입니다. 누가, 언제, 얼마나 걸렸는지, 어떤 AI나 서버를 사용했는지(AI의 이름, 또는 음성이나 이미지 서버의 호스트. 주소 경로나 쿼리는 저장하지 않습니다), 모델, 종료 방식, 실패했을 때의 짧은 오류 메시지가 기록됩니다. **프롬프트, 답변, 본문 텍스트는 어떤 것도 저장되지 않습니다.**

<a id="what-is-one-job"></a>

## 작업의 단위

- 여러 요청으로 묶이지 않는 **단독 요청**(생성, 주석, 다시 쓰기, 대행 입력, 한 부분의 요약, 도움말 도우미에 대한 질문, 부분 번역이나 설정 항목 번역 같은 플러그인 요청)은 호출이 하나뿐인 독립 작업입니다. 종류는 작업의 성격에 따라 `generation`, `annotate`, `summary` 등으로 표시됩니다.
- **요약 다시 쓰기**는 작업 하나(`summary`)이며, 작성된 요약마다 호출이 하나씩 생깁니다.
- **에이전트 실행의 작업 세션**은 작업 하나(`agent`)이며, 에이전트의 라운드마다 호출이 하나씩 생깁니다. 일시 정지되었다가 재개된 실행은 세션마다 작업이 따로 생기고, 하위 에이전트의 요청은 각각 독립된 작업이 됩니다.
- **오디오 변환**은 부분 묶음마다 작업 하나(`audiobook`)가 생기며, 라벨링 모델에 대한 요청과 읽어 준 각 조각이 호출로 기록됩니다.
- **이미지 생성기**로 만든 이미지는 이미지 호출 하나를 가진 독립 작업(`image-generator`)입니다.

<a id="what-runs-now-jobs"></a>

## 지금 실행 중인 작업: `/jobs`

![생성이 진행 중인 /jobs 페이지](../../images/jobs-live.png)

Marginalia 주소에 `/jobs`를 붙여 여세요(예: `http://localhost:8080/jobs`. 탭의 **실시간 보기 열기** 링크로도 열 수 있습니다). 다른 페이지와 마찬가지로 로그인이 필요하며, 관리자가 아닌 사용자에게는 아무것도 보이지 않습니다. 목록은 2초마다 새로 고쳐지며, 실행 중인 각 작업에 대해 사용자, 종류, 실행 시간, 완료된 호출 수, 지금 진행 중인 호출(AI나 서버, 그리고 호출이 기다린 시간)을 보여 줍니다. 서버가 바빠 보일 때 빠르게 확인하는 화면입니다. 하나의 모델을 기다리는 호출이 길게 늘어서 있다면, 모든 것이 느린 이유가 바로 거기에 있습니다.

작업 목록 아래의 **책에서의 실행**에는 지금 책에서 작업 중인 것들이 나열되며, 그 작업이 진행되는 동안 책의 일부가 삭제되거나 바뀌지 않도록 막아 줍니다(같은 내용을 각 사용자에게 자기 책에 대해 보여 주는 [실행 패널](../books/story-editor.md#the-panel-of-the-runs)도 참고하세요). 목록에는 사용자, 책, 실행 내용, 현재 상태(패널에 나오는 *모델을 기다리는 중*, *모델이 생각하거나 쓰는 중...*, *작업 중*, *사용자를 기다리는 중*, 그리고 생성의 경우 해당 부분을 쓰는 동안의 *INFERENCE* 같은 단계), 시작 시각, 붙잡고 있는 객체 수(책, 부분)가 표시됩니다. 열린 책의 창도 하나의 실행으로 취급됩니다(열린 책 창에는 이 단계 표시가 나오지 않습니다). **중지**는 해당 사용자가 직접 멈추는 것과 같은 방식으로 실행을 멈춥니다. **끝내기**는 확인 질문 후 실행을 중지하지 않고 끝내며, 실행이 붙잡고 있던 것은 즉시 풀립니다. 이것은 절대 끝나지 않는 실행, 즉 작업이 멈춰 재시작할 때까지 책을 붙잡고 있는 경우에만 사용하세요. 이런 작업은 깨어나면 여전히 쓰기를 할 수도 있습니다.

<a id="the-log-the-jobs-tab"></a>

## 기록: 작업 탭

![관리자 페이지의 작업 탭](../../images/admin-jobs.png)

| | |
|---|---|
| **사용자, 종류, 상태** | 필터입니다. *종류*는 작업의 성격을 뜻합니다(`generation`, `summary`, `annotate`, `agent`, `audiobook`, `image-generator` 등). 작업을 이름 붙이지 않은 코드가 보낸 요청은 `untagged`로 표시됩니다. |
| **경과 일수 기준 (일)** | 지정한 일수 이상 전에 시작된 작업만 보입니다. |
| **새로 고침** | 기록을 다시 읽어 옵니다. |
| **이 작업 삭제** | 필터에 보이는 작업과 그 호출을 영구히 삭제합니다. 삭제 전에 개수를 알려 주는 확인 질문이 나옵니다. 필터를 설정하지 않으면 전체 기록이 삭제됩니다. |
| **실시간 보기 열기** | 새 탭에서 `/jobs`를 엽니다. |

행을 클릭하면 작업의 호출을 볼 수 있습니다. 호출의 유형(언어 모델, 오디오, 이미지), AI나 서버, 모델, 시작, 종료, 소요 시간, 상태, 실패한 호출의 오류가 표시됩니다. 실패로 표시된 작업은 실패한 호출이 있었거나, 실행한 코드가 그 작업을 실패로 끝낸 것입니다. 취소된 호출은 사용자가 중지한 호출이거나, 작업이 끝났을 때 아직 실행 중이던 호출입니다.

![오디오 변환의 호출들](../../images/admin-jobs-calls.png)

실패한 작업은 어떤 호출이 왜 실패했는지 보여 줍니다.

![음성 호출의 오류로 실패한 변환](../../images/admin-jobs-failed.png)

**기록은 저절로 삭제되지 않습니다.** 요청이 들어올 때마다 기록이 쌓이므로, 가끔 정리하세요. *경과 일수 기준 (일)*을 설정하고(예: 30), 목록을 확인한 뒤 삭제하면 됩니다. [정리](cleanup.md) 기능을 쓰면 사용자를 삭제할 때 그 사용자의 작업도 함께 지워집니다.

![30일이 지난 작업과, 삭제 전에 나오는 확인 질문](../../images/admin-jobs-old.png)

![작업을 삭제하기 전의 확인 질문](../../images/admin-jobs-delete.png)

작업은 끝날 때 기록에 쓰입니다. 아직 실행 중인 작업은 `/jobs`에만 있습니다. 애플리케이션이 멈추면, 실행 중이던 작업은 끝나지 않은 상태이므로 사라집니다. 누군가 끝내지 않았고 30분 동안 호출을 하지 않은 작업은 완료된 것으로 처리됩니다.
