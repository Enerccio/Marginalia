# 故事编辑器

书籍的 **Story** 标签页是你写作的地方。它显示[活动分支](branches-and-story-tree.md)中从开头到结尾的各个部分。

![故事编辑器](../../images/hero-story-editor.png)

本页介绍桌面端布局。在手机上，故事以单栏显示，大纲放在抽屉中，参见[在手机上使用 Marginalia](../phone.md#the-story)。

| 区域 | |
|---|---|
| **Outline**（左侧） | 每个部分对应一个条目，依次为 `#1`、`#2`……并显示该部分的数据库 ID。点击条目可滚动到对应部分（如果该部分尚未加载，会先加载它之前的部分）。标题栏显示该分支共有多少个部分。带有[摘要](summaries.md)的部分，其条目后面会有一个小文档图标。[Chapter Marker](../extensions/chapter-marker.md) 扩展会在这里显示章节标题。 |
| **Lorebook**（左侧，位于 Outline 旁边） | 查看本书的设定，带有搜索框，并可快速编辑条目的文本，参见[Lorebook 标签页](#the-lorebook-tab)。 |
| **Annotations**（左侧，位于 Outline 旁边） | 针对整本书的故事段落[批注](annotations.md)。 |
| **Planner**（左侧，位于 Outline 旁边） | 你计划写的场景，是一个手动填写的列表，参见[Planner 标签页](#the-planner-tab)。 |
| **Story**（中间） | 每个部分的正文，右侧有其菜单（☰）和元数据，下方是底部栏。 |
| **底部栏** | 左侧是 **Summaries** 按钮（列表图标）和设置菜单（⚙），中间是命令行，右侧是 **+** 按钮。 |

这是新书的默认样式。所有这些都是可以自由排列的标签页，故事区也不例外，参见[排列标签页](#arranging-the-tabs)。侧边栏与故事区之间的分隔条可以拖动，Marginalia 会记住你放置它的位置（随书籍一起保存），并在你再次打开该书时恢复。

故事总是在底部打开，显示最新的部分。长篇书籍不会一次全部绘制：只加载最后几个部分，你向上滚动时，较早的部分会添加到上方，而你正在阅读的内容不会移动。另一端的部分会被再次卸载，因此加载的部分数量不会超过你[账户](../account.md)中**故事中一次加载的部分数**设置的值（留空则全部加载）。如果你滚动的速度快于部分加载的速度，边缘处会出现*Loading earlier parts*（或 *later parts*）提示，表示还有更多内容。点击大纲中的部分，或通过搜索找到某个部分，会加载它周围的各个部分；开始写新的部分则会带你回到故事末尾。

<a id="searching-the-story"></a>

### 搜索故事

大纲上方有一个搜索框，用于搜索**你当前所在分支**的文本（故事树的搜索会搜索所有分支）。由于长篇书籍不会一次全部加载，浏览器的搜索（Ctrl+F）无法找到尚未加载的部分中的文字，而这个搜索可以。

- 输入要查找的内容，停止输入后搜索开始。多个词必须都出现在同一个部分中；短语请用双引号括起来（`"old key"`），`*` 代表任意字符（`light*house`）。搜索不区分大小写。
- 每一处出现的位置都是一个匹配项，它们在整个分支中统一编号。搜索框下方会显示 *Match 3 of 27, in part #5* 以及表示进度的条。故事会滚动到匹配项位置，如果该部分尚未加载，还会加载它周围的部分。
- **up** 和 **down** 按钮分别跳转到上一个和下一个匹配项（到达最后一个后会回到第一个）。在搜索框中按 **Enter** 与 down 按钮作用相同，按 **Shift+Enter** 与 up 按钮作用相同。
- 已加载部分中的所有匹配项都会在正文中高亮显示，你当前所在的匹配项颜色更深。清空搜索框即可取消高亮。

在手机上，搜索位于大纲抽屉中；当抽屉显示出匹配结果时会自动关闭，如需查看下一个结果，请再次打开它。

<a id="the-lorebook-tab"></a>

### Lorebook 标签页

侧边栏的 **Lorebook** 标签页无需离开故事即可显示本书 lorebook 中的设定，因此你不必切换标签页就能查看某个条目的内容，或修正其中的字词。每次你回到 *Story* 标签页时，它都会重新读取数据，因此你在本书的 *Lorebook* 标签页中所做的更改会立即显示。

- 顶部的**搜索框**只显示名称、内容、备注或过滤器中包含该文本的条目（不区分大小写）。
- 条目旁边的**笔形图标**会打开一个小窗口，其中包含名称、是否启用、过滤器及其匹配方式、内容和备注；点击 **Save** 保存这些修改（标签、顺序和激活设置需在本书的 *Lorebook* 标签页中修改）。当有代理正在处理 lorebook 时，无法进行任何修改。
- **展开按钮**（⤢）会打开[全屏 lorebook 编辑器](../lorebooks/lorebooks.md#editing-in-full-screen)（仅限桌面端）：点击 lorebook 旁边搜索框的按钮会打开整个 lorebook，点击某个条目上的按钮会打开该条目，点击子 lorebook（需勾选 *Include sub lorebooks*）上的按钮会打开该子 lorebook。关闭编辑器后，该标签页会重新加载。

- 每个条目都是一行，显示其名称和笔形图标；点击箭头可展开，查看其**内容**（以 Markdown 渲染）以及**激活它的文本**（即 *Filtering Text/Pattern*，若为正则表达式则会附带说明）。
- **Include sub lorebooks** 会将 lorebook 及其每个子 lorebook（以及更深层级的子 lorebook）分别列为独立的行，各自的条目位于其下方；点击 lorebook 的箭头可隐藏其条目。未勾选时，只列出本书 lorebook 的条目。
- 已关闭（即不用于故事）的条目和 lorebook 会以淡色显示。
- 没有 lorebook 的书籍会显示一条提示说明。

![展开了两个条目的 Lorebook 标签页](../../images/story-lorebook-tab.png)

与编辑器的其他标签页一样，它也可以拖出到独立的面板中，参见下文。
<a id="the-planner-tab"></a>

### 计划面板

**计划**标签页是一份场景清单，按你希望故事经过的顺序排列。每个场景都是一个会写出该场景的回合的详细信息：列表中显示的**标题**、**场景设定**、**视角人物**、**在场人物**和**指令**，与新回合表单中的四个字段相同。

![包含四个场景的计划标签页，第一个场景已写好](../../images/planner-tab.png)

- **添加场景**会打开一个新场景的表单；新场景加在列表末尾。笔形图标用于编辑场景，箭头用于上移或下移，垃圾桶用于删除。
- 每个场景所在行中的 **+** 会在该场景下方**插入一个新场景**，位于该场景与下一个场景之间。
- 场景的合并按钮会**将其与下一个场景合并**：会打开一个表单，里面已经填好两个场景合并后的详细信息（两个标题、场景设定和指令上下排列、两者的在场人物，以及第一个场景的视角人物；如果第二个场景的视角人物不同，表单会注明）。修改不合适的内容后按下**合并**（或 <kbd>Ctrl/Cmd+Enter</kbd>）：两个场景变成一个，位置在第一个场景处。只有两个场景都已写好时，合并才会完成。
- **从分支导入**会为书所在分支的每一个有回合详细信息的部分（从第一部分到最新的一部分）添加一个场景，包括该部分的场景设定、视角人物、在场人物和指令，并以指令的第一行作为标题。没有回合详细信息的部分会被省略，新场景排在你已有场景的后面，且均未标记为完成。如果你要重写一个已经写好的故事，可以用它来做规划：先导入，再合并属于一起的回合，补上缺少的部分，然后在新分支上或书的副本中写这些场景。
- 场景前面的方框表示它已**完成**（已写好）：标题会加删除线，场景变暗。系统不会替你检查，写完场景后请自行勾选。列表上方的一行会统计已完成的数量。
- **点击某个场景**会把它的详细信息填入**新回合表单**（表单会打开，其中包含该场景的场景设定、视角、在场人物和指令，原有内容会被替换）。当你对内容满意后，按下**生成**。在手机上，抽屉会先关闭。
- 场景会随书一起保存，因此也会包含在书的备份和副本中。模型也可以添加场景：扩展 Arc Outline 的[情节向导](../extensions/arc-outline.md#developing-the-plot-in-a-conversation)以及[智能体](../agents.md)可以通过[命令](../commands/index.md#the-planner)读取和修改计划面板；列表会立即显示它们新增的内容。

![新场景的表单](../../images/planner-scene-dialog.png)

![点击场景后，新回合表单会填入其详细信息](../../images/planner-new-turn.png)

与编辑器的每个标签页一样，计划标签页可以被拖出，成为独立的面板，见下文。

<a id="arranging-the-tabs"></a>

### 排列标签页

编辑器由一组标签页组成：**故事**本身（各部分以及其下方的底栏）、**大纲**、**设定集**，以及[扩展](../extensions/index.md)添加的标签页（角色、弧线、侧边查询等）。拖动标签页的标题栏即可重新排列（仅限桌面端；手机端保持单列，大纲位于抽屉中）。新书默认在左侧面板中放置大纲和设定集，故事位于右侧独立的一列中。你可以把故事放在任何位置，例如放在中间，大纲在一侧，设定在另一侧，或放在大纲上方：

- 将标签页拖到某一列中面板上方、之间或下方出现的虚线条上，即可将其**分离**为该列中的独立面板；同一列中的面板会上下堆叠。
- 将标签页拖到编辑器左侧、右侧或列与列之间出现的高条上，即可将其**分离到侧边**：它会成为一个独立的列，位于其他列旁边。拖动分隔线可以加宽编辑器，以便容纳更多列。

面板和列之间由分隔条隔开：拖动它们，可以为每个面板分配所需的空间。这些尺寸会随排列一起保存。

![侧边栏中，角色位于独立的一列，侧边查询位于其下方](../../images/story-editor-tabs.png)

- 将标签页拖到另一个面板的标签栏或内容区上，即可**合并**到该面板中（拖到某个标签上，会放在该标签之前；拖到内容区，则放在最后）。失去最后一个标签页的面板会消失，没有面板的列也会一并消失。

排列和尺寸会随书一起保存，因此下次打开时以及在任何浏览器中都保持一致；每个面板显示的标签页也会与工作区的其他设置一起记住。未加载的扩展所对应的标签页会保留其位置，待扩展重新加载后恢复。

故事始终占有一个位置：它的标签页无法关闭；如果某个标签页与其他标签页共处一个面板，那么在选中另一个标签页时，它会被隐藏。任何显示某个部分的操作都会让故事标签页重新出现：点击大纲中的条目、搜索结果，在[故事树](branches-and-story-tree.md)中选择分支，以及开始生成，都会先选中**故事**标签页。生成准备提示词时（通常需要几秒钟），其他标签页会被禁用；模型开始写作后，它们便可再次使用，见[下文](#while-a-part-is-generated)。

<a id="minimizing-tabs"></a>

### 最小化标签页

除故事以外，每个标签页名称旁边都有一个小的 **⌄**（下箭头）按钮。它会**最小化**该标签页：标签页离开其面板（所有标签页都被最小化的面板会暂时消失），同时在编辑器边缘的一个栏中会出现它的圆形图标，即一个带图案的彩色圆圈（大纲为列表，设定集为书本，批注为对话气泡，侧边查询为放大镜，依此类推；没有图案的扩展标签页会显示一两个字母）。将鼠标悬停在图标上即可看到它是哪个标签页。没有任何东西被关闭，标签页保留其显示的内容。点击图标，标签页会回到面板中原先在各标签页之间的位置，并被显示出来。

只要有标签页处于最小化状态，该栏就会存在。栏顶部的按钮（环形箭头）会将栏按顺时针方向移到编辑器的下一侧：左、上、右、下。故事本身无法最小化，因此屏幕上始终有内容。

![编辑器边缘栏中的最小化标签页](../../images/story-minimized-tabs.png)

在你更改之前，图标按标签页名称的字母顺序排列：将一个图标拖到另一个图标上，它就会占据那个图标的位置。哪些标签页被最小化、栏位于哪一侧，以及图标的顺序，都会与排列和尺寸一起随书保存。

<a id="the-default-arrangement"></a>

### 默认排列

新书会以标准排列打开（大纲、设定集和批注位于左侧，故事位于右侧）。若要将你自己的排列设为标准，请先按喜好设置标签页（面板、尺寸、最小化的标签页、栏的所在一侧），然后在故事的设置菜单（⚙）中选择**将当前布局保存为默认布局**。此后，每本没有自有排列的书（即你未重新排列过的书）都会以该默认布局打开；已经排列过的书则保留其自身排列。默认布局保存在你的用户设置中。

若要恢复默认排列，请在故事的设置菜单（⚙）中选择**恢复默认布局**并确认。恢复的是你保存的那个布局；如果你从未保存过，则恢复标准布局。此操作只会把标签页移回原位（并清除尺寸以及最小化的记录）：你的文本、每个面板显示的标签页以及扩展的标签页都会保留，后者会放在第一个面板中。
<a id="writing-the-next-part"></a>

## 编写下一部分

1. 点击右下角的 **+**。*新回合指令*面板随即打开。
2. 填写各个字段。所有字段都是可选的，但模型至少需要一些指引：

   | 字段 | |
   |---|---|
   | **场景设定** | 这一部分发生的地点和时间，例如 *海边的灯塔，深秋的暴风雨夜晚*。 |
   | **视角人物** | 这一部分以谁的视角写成。 |
   | **在场人物** | 谁在场景中，以及他们的状态。 |
   | **指令** | 这一部分应当发生什么。 |

   *场景设定*、*视角人物*和*在场人物*会从上一部分带入，因此你只需修改不同的内容。*指令*每次都从空白开始。
3. 点击 **生成**。

![新回合指令面板](../../images/new-turn-instructions.png)

新的部分会出现在末尾，并随着模型的写作逐步填充。对于[推理模型](../inference-providers.md#reasoning-models)，推理过程会先出现在 **查看推理** 下。

在生成某一部分的过程中，右下角的 **+** 按钮会变成红色的 **停止** 按钮。点击停止会保留到目前为止已写出的文本，作为该部分的内容。

<a id="while-a-part-is-generated"></a>

### 生成某一部分时

在最初几秒，提示词正根据书籍内容组装，整个书籍窗口会处于等待状态。模型开始写作后，只有新部分及其之前的部分会被锁定：

- **新部分**在完成之前不能被修改：不能编辑，也不能打开其菜单。
- **之前的部分**保持原位：你可以编辑、批注和重写它们，但不能删除、合并或分支，故事也会停留在当前分支上（不能滑动切换，也不能切换分支）。对更早部分或设定的修改不会影响正在写作的部分：它的提示词已经组装完成。这些修改只会作用于之后的内容。
- **其他一切都可以自由操作**：设定、书籍的设置和提示词、左侧栏的各个标签页（侧边查询、弧线大纲、笔记……）、命令栏。如果生成占用了模型的唯一连接，对模型的其他请求会等待一个空闲连接。
- **等待中**的操作：第二个回合、搜索替换、导入到书籍中，以及大规模删除。树形和备份标签页也会等待。

窗口中被置灰的操作，当命令、代理或扩展请求它们时同样会被拒绝，Marginalia 会说明是什么在阻挡（*正在使用：……*）。

**离开书籍会停止生成。** 退出按钮会先询问；选择*是*等同于 **停止**：已到达的内容会被保留。关闭浏览器标签页也会如此，而在生成某一部分时关闭或刷新标签页，浏览器会先询问。网络短暂中断，或者笔记本合上一分钟，都不算离开：页面恢复后会显示期间已到达的内容。

当模型返回错误（服务器无法连接、API 密钥错误、上下文过长……）时，会显示该错误。如果尚未收到任何文本，故事会保持原样：新部分或滑动版本会被移除，重新生成的部分会恢复其之前的文本。错误发生前已到达的文本会被保留，与 **停止** 的情况相同。解决问题后再重新生成即可。

这些字段如何进入提示词，由书籍的[用户提示词](prompts.md#user-prompt)决定。使用默认用户提示词时，模型会收到它们作为*当前地点与时间*、*视角人物*、*当前在场人物及状态*和*下一部分的情节要求*。

!!!
文本以 Markdown 编写：`*italics*`、`**bold**`、`# Heading` 等会以格式化方式显示。带有 `#` 标题的部分会被[章节标记](../extensions/chapter-marker.md)扩展识别为一章。
!!!

<a id="drafting-the-instructions"></a>

### 起草指令

不知道接下来该写什么？面板中 *指令* 字段下方的 **起草指令** 可以让模型代你写出指令，就像你自己会写的那样。点击后会打开一个窗口，其中包含：

| | |
|---|---|
| **指导** | 这一部分应当围绕什么：一个粗略的想法、一个方向（"她就那封信质问他"），或者什么都不填，模型会顺着故事自然发展。它的初始内容是你已经在*指令*中输入的文字。 |
| **故事计划** | 仅当有来源提供时才显示。[弧线大纲](../extensions/arc-outline.md#drafting-the-instructions-for-the-current-chapter)会提供，内容来自当前章节的数据。只读；模型会遵循它。 |

**起草指令** 会启动模型，并将回答逐字流式输出到 **已起草的指令** 中。你可以在继续之前修改或清空它；**再起草一次** 会再尝试一次，**停止** 则保留已到达的内容。在你点击 **用作指令** 之前，什么都不会改变：该文本随后会替换面板中的*指令*（其他字段保持不变），面板会重新打开，准备好点击 **生成**。

模型会获得：至今为止的故事（较早的内容以[摘要](summaries.md)形式提供，与生成时相同）、面板中的场景设定、视角人物和在场人物、上一部分的设定、你最近的指令（作为你写作方式的示例）、你的指导和计划。它看不到新回合会激活的词条。请求使用的是[模仿提示词](prompts.md#impersonate-prompt)。模型就是书籍所用的那一个；起草与任何请求一样消耗令牌。

![起草下一回合的指令](../../images/impersonate-dialog.png)

命令 [`/impersonate`](../commands/index.md) 与此相同，它会返回文本。[代理](../agents.md)不会获得这一功能，它们会用自己的指令来写故事。

每个部分的右上角都有一个菜单（☰）。**编辑**、**放弃更改**、**重新生成**、**滑动**、**重写**、**历史（n）**和**插图**位于菜单本身中，**删除**是其最后一项，其余内容位于四个子菜单中：**批注**（*为部分添加批注*、*用 AI 批注*）、**摘要**（*生成摘要* / *查看摘要*、*删除摘要*）、**检查**（*显示提示词*、*比较提示词*、*令牌用量*、*设定集用量*）以及**分支与合并**（*创建故事分支*、*合并到上一部分*）。如果某个子菜单中对该部分没有任何内容，则不会显示。审阅器会在*摘要*之后添加其**审阅**子菜单。各项如下：

<a id="editing-the-text"></a>

## 编辑文本

生成的文本由你自行修改。在部分菜单中选择**编辑**，修改文本，然后选择**保存**。编辑过的部分会按你修改后的样子发送给模型。

如果编辑的部分被某个[摘要](summaries.md)覆盖，该摘要就会过时；Marginalia 会在下一次生成时注意到这一点并丢弃该摘要。为避免这种情况出乎意料地发生，**保存**会先检查新文本：如果会使摘要过时，会弹出一个窗口说明有多少个摘要，并提供**返回编辑**（不保存任何内容，编辑器保持打开，保留你的文本）、**仍然保存**（摘要将变为过时）和**保存并重新验证摘要**（文本已保存，摘要保持有效，适用于不改变其内容含义的修改，例如错别字）。该检查针对**保存**（菜单、快捷键和编辑器按钮）；自动保存（例如编辑器打开时开始生成）则不会询问。

| 按键 | |
|---|---|
| `+` | 打开*新回合指示*面板，光标位于*指示*中。 |
| `Ctrl+Enter` | 从已打开的面板开始生成。`Esc` 关闭该面板；键盘回到故事中。 |

| `/` | 将光标放入命令栏（先显示故事标签页）。 |
| `Ctrl+Shift+F` | 打开*大纲*标签页，并将光标放入分支的搜索框（`Enter` / `Shift+Enter` 跳到下一个 / 上一个匹配项）。 |

<a id="deleting-a-part"></a>

## 删除段落

**删除**会从故事中移除该段落。其后的段落会保留，并接续在它前面的段落之后，因此删除故事中间的段落只是把它拿掉。删除最后一个段落后，它前面的段落就成为该分支的新结尾。

<a id="deleting-many-parts-at-once"></a>

### 一次删除多个段落

设置菜单（⚙）中有**批量删除**。开启后，每个段落左侧会出现一个复选框，故事下方会出现一个工具栏，显示已勾选段落的数量以及一个**删除**按钮。勾选你想删除的段落（滚动时勾选状态会保留，故事只加载一部分段落）；在某个复选框上按住 **Shift + 点击**，会勾选（或取消勾选）它与你上一次点击的段落之间的所有段落；被勾选的段落会显示为红色。然后按下**删除**：确认后，段落会在一个无法中止的进度条后被逐个删除。删除方式与删除单个段落相同：被删段落之后的段落接续在其前一段落之后，被删段落则进入回收站。之后故事会重新显示，批量删除模式随即关闭。在工具栏中点击**取消**，或再次选择**批量删除**，都会在不删除任何内容的情况下关闭该模式。开始生成也会关闭该模式。若某个被勾选的段落正被上下文窗口或翻译功能处理，它会保留在故事中，Marginalia 会说明原因。

![批量删除，部分段落已勾选](../../images/story-mass-delete.png)
<a id="redrafting-a-part"></a>

## 重绘某一部分

**Regenerate**（重新生成）和 **Swipe**（换一版）只针对最后一部分，并从头重写。**Redraft**（重绘）可以作用于任何部分，包括故事中间的旧部分，并保留你没有要求修改的内容。在该部分的菜单中选择 **Redraft**：

1. 在 **Instructions for the redraft**（重绘说明）中写下需要修改的内容，例如：*在两人之间增加更多对话*、*让打斗更长*、*删去对地图的解释*、*保持结尾不变*。说明留空则按相同的事件重新写这一部分。
2. 如果该部分应当变得 **Shorter**（更短）或 **Longer**（更长），在 **Length**（长度）中选择（默认为 **Same length**，即同样长度）。系统会在你的说明之后追加一句相应的要求（参见 [Redraft Shorter Prompt and Redraft Longer Prompt](prompts.md#redraft-shorter-and-longer)）。选择 **Redraft**。文本会流式输出到 **Redrafted text**（重绘文本）中；**Stop**（停止）可提前结束。选择 **Redraft again**（再次重绘）可以再试一次，也可以换用其他说明。**Differences**（差异）会逐词显示与原部分相比的变化。如果该部分有未处理的[批注](annotations.md)，则会出现 **Deal with the open annotations of the part**（处理该部分未处理的批注）（默认勾选），它同样会把这些批注交给模型；**Apply**（应用）会将其标记为已解决。
3. 重绘后的文本是一个仍可编辑的文本框（其角落的图标可使其展开以容纳全部文本），**Differences** 会跟随你的编辑而更新。**Apply** 用它替换该部分的文本；**Close**（关闭）则放弃它。在点击 **Apply** 之前，书中的任何内容都不会改变。

![重绘窗口：说明、新文本和差异](../../images/redraft-dialog.png)

模型会收到[重绘提示词](prompts.md#redraft-prompt)，其中包括：该部分本身、你的说明、该部分之前的故事（较早的内容以[摘要](summaries.md)形式呈现，前提是摘要有效；其余为原文，且当内容放不下时，优先保留最新的部分）、该部分之后尽可能多的故事（最多占可用空间的四分之一）、各本设定集在该部分当前所处位置给出的设定（会为该部分的轮次重新计算，因此对设定条目的编辑会体现在重绘结果中；只有当书中没有设定集时，才使用该部分生成时所用的设定）、全书的视角、时态和文风，以及该部分所来自的那一轮的场景设定、视角人物、在场角色和指令。之所以提供该部分之后的故事，是为了让新文本仍能顺利衔接其后的内容：后续部分所依赖的事件应当保留。

该部分保留其位置、摘要、插图以及生成方式；文本、词语和标记会被替换，该部分也会被计为已编辑。应用重绘与编辑器中的 **Save** 一样，属于编辑操作，因此描述旧文本的[摘要](summaries.md)会过时，Marginalia 会告诉你有多少条。该部分自身的摘要也包括在内。

当某条摘要描述了该部分（该部分自己有摘要，或该分支中有更新的部分有摘要）时，窗口中会出现复选框 **Revalidate the summaries this redraft makes outdated**（重新验证因本次重绘而过时的摘要），初始为未勾选。如果摘要内容仍然正确（重绘只改变了措辞，而没有改变发生的事情），请勾选它：此时 **Apply** 会重新计算它们的哈希值，摘要便保持有效。如果事件发生了变化，则不要勾选，并重新生成这些摘要。

该窗口不会阻塞故事，参见[与重绘窗口并行工作](#working-beside-the-redraft-and-annotation-windows)。

<a id="working-beside-the-redraft-and-annotation-windows"></a>

### 与重绘和批注窗口并行工作

在电脑上，**Redraft** 和 **Annotate with AI**（用 AI 批注）窗口位于故事的右侧，使你在模型写作时仍能使用故事：你可以阅读、滚动和编辑故事。拖动窗口的标题可以移动它，拖动其边缘可以调整大小。标题中的箭头（⌄）会将窗口折叠进页面左下角的[运行面板](#the-panel-of-the-runs)：模型继续工作；点击 **Open**（打开）或该条目可以把窗口重新显示出来；**Stop** 则停止模型（模型完成后，**Close** 可关闭窗口）。在手机上，窗口仍会覆盖故事，但同样可以以相同方式折叠。

![模型写作时位于故事旁边的重绘窗口，以及左下角面板中的运行项](../../images/redraft-beside-story.png)

**Close 和 Stop 是两回事。** 窗口自身的 **Stop** 会停止模型，窗口则保留已经收到的内容。模型工作时点击 **Close** 并不会停止它：窗口会折叠进面板，模型继续处理其队列；再次打开窗口时，其回答就在里面。关闭模型已完成的窗口，或在面板中点击 **Close**，窗口便会消失；关闭书籍或浏览器标签页时，被折叠的窗口也会随之停止。等待模型的其他窗口同样如此：**摘要**（以及 *Create summaries*、*Rewrite all summaries*）、[审阅者](../extensions/reviewer.md)、书籍简介、设定和大纲生成器、图像和漫画生成器，以及 Beta Readers 的人物设定写作者。有声书的 *Studio* 和 *Convert* 窗口也不会阻塞页面；关闭它们从来不会停止转换。

当某部分上打开（或折叠）了窗口时，该部分的菜单旁会显示它正在做什么（*Redrafting · The book*），并且该部分的 **Regenerate**、**Swipe**、**Redraft**、**Annotate with AI**、**Merge into previous**（并入上一部分）和 **Delete** 均会被禁用，以确保窗口不会丢失其部分。编辑该部分仍然可以进行。关闭书籍会关闭其窗口并停止其模型。[翻译者](../extensions/real-language-translator.md)正在处理的部分会以同样方式显示 *Translating the speech of the part...*（正在翻译该部分的台词……）；两个翻译者不会同时处理同一部分，第二个翻译者会提示该部分正在使用中。

- 当你对整个部分点击 **Apply** 应用重绘，而该部分在打开窗口之后又被修改过（你在此期间进行了编辑）时，Marginalia 会先询问：**Differences** 随后会比较该部分的当前版本与重绘版本，让你看到应用后将被替换的内容；然后选择 **Apply anyway**（仍然应用）或 **Cancel**（取消）。[自动应用](annotations.md#annotating-every-new-part-automatically)的重绘在该部分被修改过时不会自动执行：窗口会等待你的决定。
- 如果在你点击 **Apply** 应用重绘或添加批注之前，该部分已被删除，窗口会告知你这一点，不写入任何内容，并自行关闭。

<a id="the-panel-of-the-runs"></a>

### 运行面板

所有当前正在用模型处理你的书籍的任务，都会列在每个页面左下角：生成、重绘或批注；由 [Real Language](../extensions/real-language-translator.md) 或 [Conlang](../extensions/conlang-translator.md) 翻译器完成的翻译；摘要的重写；Knowledge Tracker 对故事的阅读；[有声书](../extensions/audiobook.md)的转换；以及命令栏中耗时较长的命令（*Draft instructions*、摘要……：其窗口位于一侧，并像其他窗口一样折叠）。在模型回答期间，你正在等待回答的窗口也会列出：**Impersonate**、帮助助手、快速翻译、Conlang 设计器、Side Query 的聊天、Beta Readers 或情节向导。它会列出你**所有已打开页面**中的运行（例如另一个标签页或手机上的），而不仅是在本页面上启动的运行。没有运行时，则不显示。

![运行面板已展开：重绘已折叠进其中，并显示模型文本的末尾、Open 和 Stop](../../images/runs-panel.png)

- **收起**时，它是一个小条：显示第一个运行、还有多少个运行（*Translating the speech of the part... · 2 more*），并在模型工作时显示一个移动的进度条。点击它可以打开列表；当你把窗口折叠进面板时，它会自动打开。
- **展开**后，每个运行会显示它在做什么、属于哪本书、运行了多久、在等待什么，以及模型所写内容的末尾部分：
  - *Waiting for the model: 2 requests before this one*（等待模型：此前还有 2 个请求）：模型忙于其他请求时出现（参见 [Inference providers](../inference-providers.md) 中的 *Connections*）；
  - *The model is thinking...*（模型正在思考……）或 *The model is writing...*（模型正在写作……），下方显示其思考或回答的末尾；
  - *Waits for you*（等待你）：运行在等待你的决定时出现（要应用的重绘、要审阅的 Knowledge Tracker 提议、生成前 Prompt Inspector 的询问，或情节向导需要你允许的命令）。
- **Stop** 会停止该运行，无论它是在哪里启动的。点击 **Open** 或该条目，会重新显示已折叠的窗口（仅限于打开它的页面），或显示运行本身；当运行在等待你时，则显示 **Review**（审阅）。Knowledge Tracker 的运行会在本页面打开其书籍（若本页面没有打开其他书籍；否则会要求你先关闭那本书），切换到 Knowledge 标签页并显示审阅内容。**Close** 会永久关闭窗口（并停止其模型）。
- 在电脑上，你可以拖动面板左侧的把手（⋮）来移动它；它会保持你在此浏览器中放置的位置。在页面下半部分，展开时它会向上增长，就像在其角落里一样，并且始终保持在页面范围内。当它位于[帮助助手](../administration/help-assistant.md)圆形按钮所在的位置时（在书籍页面上，二者都位于左下角），该按钮会让开，待位置空出后再回来。

当你启动的运行在其页面关闭后结束时，你打开的另一个页面会发送其[通知](../account.md#notifications)（对于有通知的运行，例如摘要的重写）。

<a id="redrafting-only-a-passage"></a>

### 只重绘一段文字

若要重写几句话而保留该部分的其余内容，请在该部分的文本中选中它们，然后**右键单击**（在手机上为长按）：菜单中有 **Redraft selection**（重绘所选内容）。（该部分的菜单 ☰ 不适用于此，在某些浏览器中打开它可能会丢失选区。）该窗口的工作方式与上面相同，但有两点不同：它会显示 **Selected text**（所选文本），而重绘的内容仅是用于替换它的文本。模型会收到整个部分（其中所选内容已被标记）以及周围的故事和设定，因此新段落能与其前后的句子衔接。**Differences** 会比较所选内容与重绘后的文本；**Apply** 会把重绘文本放到所选内容的位置，并保留该部分的其余内容，包括所选内容两端的空格或换行。若存在未处理的[批注](annotations.md)，复选框只提供那些段落与所选内容有重叠的批注。如果在你选中文本之后（在另一个窗口中）该部分被修改过，**Apply** 会拒绝执行，你需要重新选择。在该部分正在编辑时，使用编辑器中的选区，并且会先保存编辑内容。

<a id="what-follows-a-generated-part"></a>

### 生成部分之后会发生什么

当你生成的某个部分（从页面或命令栏生成）完成后，书籍可能会自动对它进行更多处理，顺序如下：

1. **Annotate**（批注）：[自动批注](annotations.md#annotating-every-new-part-automatically)审阅该部分。
2. **Redraft**（重绘）：为回应批注而重新写该部分。
3. **Translate**（翻译）：[Real language](../extensions/real-language-translator.md) 和 [Conlang](../extensions/conlang-translator.md) 翻译器翻译其中的台词。
4. **Knowledge**（知识）：[Knowledge Tracker](../extensions/knowledge-tracker.md) 阅读该部分。
5. **Audio**（音频）：[有声书](../extensions/audiobook.md)将其转为音频。

只有书籍中已开启的步骤才会运行。这些步骤在服务器上运行，因此页面可以关闭；它们在[运行面板](#the-panel-of-the-runs)中合并为一个条目：*After part 14: Annotate ✓ · Redraft … · Translate*，显示模型的文本，并附带一个 **Stop**。会改变文本的步骤优先，以便跟踪器和音频获得最终文本。等待你的步骤（批注或要选择的重绘）会打开其窗口，该条目则有 **Review** 以便在另一个页面中打开它。

- **Stop**、关闭等待你的窗口，或某步骤失败，都会在该处结束整个流程：已完成的内容保留，其余步骤不再运行，并有一条消息说明还剩下什么需要手动完成（每个步骤在该部分上都有自己的操作）。
- **重绘**运行期间，下一个部分无法生成（会告诉你是哪一个运行造成的）；其他步骤运行期间则可以生成。
- 在其文本定稿之前，该部分无法被删除；重新生成该部分会结束其早先版本之后的流程。
- [智能体](../agents.md)通过它自己的命令完成这些步骤：智能体生成的部分之后不会有任何后续步骤。
<a id="merging-a-part-into-the-previous-one"></a>

## 合并到前一部分

模型在句子中间停止（达到回复长度上限，或连接中断）时，无法可靠地让它"继续"同一段文本。此时应改为写下一部分（*从上一部分停止的地方继续*），然后在第二部分的菜单中选择**合并到前一部分**，将两者连接起来。随即会打开一个审阅窗口：

- **连接文本的方式**：空行、换行、空格或不加任何内容。默认值取决于前一段文本的结尾：如果它以句子结束，则默认为段落；如果它被截断，则默认为空格。
- 两个轮次的**场景设定**、**视角人物**、**在场人物**和**指令**，合并在可编辑的字段中。两个轮次开头相同的内容只保留一次（"写决斗。保持简短"和"写决斗。加上雨"会得到第一行"写决斗。保持简短"，下一行为"加上雨"）。
- **数据**：两个部分各自保存的内容，逐项列出，并标明该值相同、不同，还是只存在于其中一个部分。除非你为某项选择前一部分的值或将其舍去，否则合并后的部分保留**较晚部分**的值（因为它代表故事现在的状态）。例如故事的[变量](../templates/macros.md)以及扩展的数据。相同的值默认隐藏，除非你主动要求显示。

![将一个部分合并到前一部分之前的审阅窗口](../../images/part-merge-dialog.png)

前一部分保留其位置、摘要以及生成方式（提示词、模型、时间）；它会获得连接后的文本、连接后的推理过程和图片，其字数和词元数会被重新统计。被合并的部分会被删除（它进入[回收站](../trash.md)），其后的内容则接在前一部分之后继续。覆盖这两个部分的摘要会过时，与编辑后的情况相同。被合并部分的[历史记录](version-history.md#backups-copies-and-the-trash)会被移除，保留下来的部分会以连接后的文本作为一个**合并**版本。如果某部分是书的第一部分，或者它之前的部分还有其他续写（部分的备选版本），则无法合并。此时请先删除这些续写，或将其变为分支。

<a id="images"></a>

## 图片

一个部分可以附带图片，例如地图、人物肖像或插图。在部分菜单中选择**图片**，即可打开该部分的图片列表。

![某部分的图片对话框](../../images/images-dialog.png)

- **添加图片**（或将文件拖放到其上）可上传 PNG、JPEG、GIF 或 WebP 格式的图片，大小不超过 10 MB。WebP 图片在上传时会被转换为 PNG，因为 Word 和 PDF 文件无法包含 WebP。
- **说明文字**显示在图片下方，可以留空。
- **在部分中的位置**是一个 3×3 的网格。列表示文本的一侧（左、中、右），行表示在文本中的位置：顶部位于文本之前，中部位于文本中间，底部位于文本之后。点击方格即可选择。
- **文字环绕图片**让文本环绕图片排列，而不是位于图片上方和下方。位于左侧或右侧时，文本与图片并排。位于中间一列时，文本位于图片两侧：该行处的若干文本块（约 400 个字符，至少两个块）会分成两栏，第一部分在图片左侧，其余部分在右侧，因此文本先从左栏向下读，再继续到右栏。同一位置的两张图片会在两栏之间上下排列。当文本没有足够空间分成两栏时（只有一个段落，或文本块已被上方的横带占用），图片会作为独立的块居中显示。
- **宽度**是图片宽度占文本宽度的百分比。**自动**会保持图片的原始尺寸（但不会超过文本宽度；两侧都有文本的图片为 30%）。文字环绕的图片最多为 60%，两侧都有文本的图片最多为 40%，以便文本留出一定空间。高度按图片的比例自动调整。
- 垃圾桶按钮会将图片从该部分中移除。

![图片的位置：位于中间，文字环绕图片排列](../../images/images-position.png)

**像阅读器中那样预览**（对话框中的按钮，部分菜单中在部分有图片时也有相同的选项）会按照[阅读器](publishing.md)的显示方式展示该部分，并使用本书的文字样式：图片位于你设定的位置，还可以切换宽屏或窄屏（手机）视图。预览使用编辑器中当前的文本，无论是否已保存。

![预览：文本分为两栏，图片位于两栏之间](../../images/images-preview.png)

故事编辑器本身不使用位置设置：它会将图片以列表形式显示在该部分文本的下方。位置设置由阅读器和[导出](export.md#images)使用。

图片放在文本的哪个位置，并不取决于与其一同保存的数字：文本会在各个块之间切分（段落、列表、引文和代码块永远不会被切断），因此编辑文本时图片仍会留在正确的位置。中间位置是距离文本中部最近的块与块之间的位置；如果图片设为文字在其底部环绕，则会放在最后一个块之前，以确保该块至少与图片并排。同一位置的图片按列表中的顺序排列；位于同一位置且彼此相邻（且不让文本环绕）的图片，在空间允许时会并排排列。PDF 和 Word 对于设定了宽度的图片会这样处理。

图片**不属于文本的一部分**。模型看不到图片，图片不会出现在提示词中，不计入词元，也不会改变[摘要](summaries.md)。它们也不是 Markdown：文本中写入的 `![](...)` 链接不是该部分的图片，请改用**图片**功能。

需要了解的几点：

- **重新生成**会保留该部分的图片，即使生成失败也是如此。**备选版本**会生成一个新的部分（与旧版本并列），新部分不带图片。**创建分支**会将图片复制到新部分。
- 图片属于你的账户。在[阅读器](publishing.md)中，已发布书籍的读者也能看到这些图片，除非你在书籍的*关于*标签页中取消勾选**向读者显示图片**。
- [备份](backups.md)会记录部分拥有哪些图片，但不包含图片文件。将备份恢复到另一个账户或另一个安装实例后，各部分将不再带有图片。
- 从部分中移除图片只是将其从该部分撤下。文件本身保留，并仍列在[资源](../resources.md)中，你可以在那里下载、替换或删除它。在资源中删除文件会将其从所有使用它的部分中移除。文件本身仍保存在数据文件夹中。

<a id="summaries"></a>

## 摘要

底栏中的**摘要**按钮（位于设置菜单 ⚙ 的左侧）会打开当前分支摘要的总览，在这里可以编辑、删除摘要，或将其合并为元摘要。按钮的提示会显示当前使用中的摘要在提示词中占用的词元数。参见[摘要](summaries.md#the-summaries-overview)。

<a id="how-much-of-the-context-the-story-takes"></a>

## 故事占用了多少上下文

设置菜单（⚙）中有**分支词元**。在生成任何内容之前，它会显示当前分支的故事在提示词中所占的比例：一个条形图显示**不含摘要**（所有部分）的故事，另一个显示**含摘要**（摘要以及最新部分之后的部分）的故事，还有一个表格列出各部分、词元数，以及占**提示词预算**（书籍所用模型的上下文减去回复所需空间）的比例。只有仍然准确描述故事的摘要才计入；已不再匹配的摘要会被列出名称，并在生成部分时被舍弃。设定、系统模板和本轮指令同样占用该预算。如果没有带上下文大小的模型，表格中将不显示比例。

<a id="which-lore-entries-were-used"></a>

## 查看哪些世界书条目被使用过

设置菜单（⚙）中的 **Analysis**（分析）里的 **Lore Usage**（世界书使用情况）会显示生成内容使用了本书世界书中的哪些条目，哪些条目从未被使用，
这样你就可以根据实际使用情况来精简世界书，而不必凭感觉猜测。每次生成都会记录其提示词中包含了哪些条目（以及每个条目占用的 token 数），
该窗口会把这些记录汇总到各个部分上：

- **Parts**（部分）用于选择统计范围：**Active branch**（当前分支），或 **All branches**（所有分支），即本书的每个分支和每个备选版本。
- **From part**（起始部分）和 **To part**（结束部分）用于限定范围，编号与大纲中一致（分支的第一个部分为 1；在所有分支中，编号表示该部分在树中的深度）。留空则表示从头到尾。
- **Show**（显示）用于筛选出在统计部分中 **Never used**（从未使用）、**Sometimes used**（有时使用）或 **Always used**（总是使用）的条目。

![Lore Usage 窗口](../../images/lore-usage.png)

表格中每一行对应本书世界书中的一个条目，按使用次数从多到少排列，包含以下信息：所属世界书；该条目是从未、有时还是总是被使用；
在多少个部分中被使用（仅计算有记录的部分，并给出百分比）；它在所有这些部分中消耗的 token 总数及每次使用的平均 token 数；以及它首次和最后一次被使用的部分。
点击表头可以排序。如果某个条目之前被使用过，但现在已不在本书的世界书中（已删除、已移动，或其所属世界书已关闭或不再属于本书），它会保留在列表中并标注为 *not in the lorebook now*（当前不在世界书中）；已删除的条目则没有名称。

只有有记录的部分才会被统计：手动输入的部分、在 Marginalia 开始保存此记录之前写的部分，或在本书还没有世界书时写的部分都没有记录，窗口中会注明这些部分的数量。
*Always used*（总是使用）的条目可能是常驻条目；*Never used*（从未使用）的条目则可以考虑删除，或改用更好的触发条件。要查看某个条目为何现在没有触发，可以在世界书编辑器中使用 [**Preview activation**（预览激活）](../lorebooks/entries.md#preview-activation)。

<a id="text-styles"></a>

## 文本样式

底部栏中的设置菜单（⚙）里有 **Appearance**（外观）→ **Change Styles For Text**（更改文本样式），这是一个菜单，每种样式占一项，按名称排序。
如何创建样式，请参阅 [样式指南](styling-guide.md)。
样式决定部分文本的外观：字体、字号、颜色、对齐方式、标题等。应用自带两种不可更改的样式：**Normal**（应用本身的外观）和 **Book**（类似书籍的阅读样式，即 [查看器](publishing.md) 使用的样式）。你也可以在 [Settings → Styles](../account.md#styles) 中创建自己的样式。
- 第一项 **Default (...)**（默认）跟随你的*默认样式*（即在 *Settings → Styles* 中标记的样式；如果你没有选择，则为 Normal）。新建的书没有自己的样式，会显示默认样式。
- 选择其他项会将该样式**保存在本书中**，使其只针对本书覆盖默认样式；被勾选的项即为本书当前使用的样式。选择 **Default** 可撤销此选择。
- 删除某个样式后，使用该样式的书会回退到你的默认样式。

![Appearance，Change Styles For Text：可供选择的样式](../../images/story-style-menu.png)

在 **Book** 样式中，段落两端对齐，过长的单词会自动断字，所用词典取决于本书的 **Language**（语言，在 [About 标签页](managing-books.md#the-about-tab) 中设置）。断字由浏览器完成；
对于少数冷门语言，浏览器没有对应词典，文本便不会断字。

之前打开了旧版 *Change Styles For Text* 开关的书，在你选择其他项之前，仍会显示 Book 样式。

<a id="highlighting-generated-text"></a>

## 高亮生成的文本

设置菜单（⚙）中还有一个可勾选的 **Highlight Generated Text**（高亮生成的文本）。开启后，每个部分中由模型写的词语都会被高亮显示，
这样你添加或改写的内容就会一目了然。Marginalia 会沿着[部分的版本](version-history.md)追踪文本：每个版本都会叠加在前一个版本之上，两者共有的词语仍归原作者所有，
因此你在生成文本中写下的句子，无论模型之后改写了多少次其余部分，仍然属于你。你从未编辑过的部分会整体高亮；你自己写的部分则不会有任何高亮。
代理（agent）写的内容也计为模型所写。该开关不会被保存：重新打开页面时它会恢复为关闭状态。

[历史记录被关闭](version-history.md)的部分没有可供追踪的版本，因此它会与模型最初生成的文本进行比较。该高亮功能在[手机](../phone.md)上同样可用。

同一套统计也可以得出比例：本书的 **Info** 标签页中有 **Authorship of the branch**（分支的作者归属）及 **Calculate**（计算）按钮，它会显示当前分支中由你写的词语占多少百分比、由模型生成的词语占多少百分比，
并且[导出功能](export.md)可以在文件末尾附上这一统计说明。

![高亮的生成文本与设置菜单](../../images/highlight-generated.png)

## 命令

故事下方的菜单旁边有一个**命令行**：输入 `/` 可查看所有命令，选择一个后按 **Enter**（或点击播放按钮）即可运行。命令的返回结果会显示在命令行上方的一个小窗口中。
有关如何编写参数、帮助信息的内容，以及如何中止耗时较长的命令，请参阅 [命令](../commands/index.md)。目前命令行仅在桌面布局的故事标签页中可用。
<a id="search-and-replace"></a>

## 搜索与替换

设置菜单（⚙）还有 **Clear history of the book** 和 **Empty trash of the history**，见 [版本历史](version-history.md#deleting-versions)。

设置菜单（⚙）还有 **Search and replace**，可一次性替换整个故事中的某个词、名字或短语。该窗口有 **Search for** 和 **Replace with** 两个字段，以及以下选项：

![设置菜单中的 Search and replace](../../images/story-settings-menu.png)

![输入了搜索内容的 Search and replace 窗口](../../images/search-replace-dialog.png)

| 选项 | 默认值 | 含义 |
|---|---|---|
| **Search by regex** | 关 | 搜索文本是一个[正则表达式](../regular-expressions.md)，替换文本可以使用其分组（`$1`）。否则按输入的原样搜索文本。 |
| **Case sensitive** | 开 | 只有大小写完全一致的文本才会被找到（*John* 找不到 *john*）。关：不区分大小写。使用 **Search by regex** 时此项锁定。 |
| **Search in summaries** | 开 | [摘要](summaries.md)也会被搜索和修改。 |
| **Search in all branches** | 关 | 搜索所有[分支](branches-and-story-tree.md)，否则只搜索当前分支。 |
| **Revalidate all summaries** | 开 | 替换之后，本书的每个[摘要](summaries.md)都会重新变为有效，见下文。 |

使用正则表达式时，大小写始终按输入的原样处理；如需忽略大小写，请在开头加上 `(?i)`。点击 **Search**（位于字段右侧的按钮；在手机上位于字段下方）开始搜索。进度条显示进度，其旁边的 **Stop** 可中断搜索。搜索不会更改任何内容。

表格列出了所有包含匹配项的故事部分和摘要，并显示其类型和 id。打开某一行可查看其中的匹配内容：匹配处前后的文本，既显示当前内容，也显示替换后的内容。过长而无法完整显示的匹配或替换文本，会以 *[searched text]* 或 *[replace text]* 的形式显示。

![搜索结果，已打开第一个部分](../../images/search-replace-found.png)

在 **Search for** 或 **Replace with** 字段中按 **Enter**，效果与点击 **Search** 相同。

搜索完成后，字段和选项被锁定，**Replace** 按钮变为可用。**Search again** 会清除搜索结果并解锁窗口，以便你修改搜索内容。点击 **Replace** 会真正修改故事：在替换完成之前，整个窗口处于冻结状态（即使是 **Stop** 也无法使用），完成后窗口会再次清空。被替换的部分会被标记为已编辑，就像你亲手修改过一样。

如果替换的是某个[摘要](summaries.md#when-summaries-become-outdated)所描述的文本，该摘要就会过时。开启 **Revalidate all summaries** 后，Marginalia 会为本书的每个摘要（包括所有分支的摘要，无论替换是否涉及它们，也包括之前已经过时的摘要）重新计算校验值，因此替换之后它们都将是有效的。这也会使过时的摘要在不检查其文本的情况下重新变为有效，因此仅当你确定摘要的内容仍然正确时才使用此选项。

关闭该选项时，只有搜索范围所覆盖的摘要会被更新。搜索范围之外的摘要（未被搜索的分支的摘要，这些分支与当前分支共享更早的部分；或者当摘要未被搜索时的全部摘要）会变为过时。如果存在此类摘要，Marginalia 会告诉你数量，并询问是否继续。之前已经过时的摘要仍保持过时状态。

![关于将变为过时的摘要的警告](../../images/search-replace-warning.png)

在[手机布局](../phone.md)中，同一窗口的字段和按钮上下排列，表格只有一列，显示类型和 id，其下方是匹配内容和替换内容。

[摘要概览](summaries.md#search-and-replace-in-the-summaries)中有一个仅针对摘要的同款窗口。

同样的搜索与替换也可以通过[命令行](../commands/index.md#commands-that-come-with-marginalia)运行，使用 `/search-replace-parts`；它在替换前会先询问。

<a id="importing-into-the-book"></a>

## 导入到书中

设置菜单（⚙）在 **Import & export** 下有 **Import**。它是书籍标签页中的窗口，用于从文件新建一本书（见[管理书籍](managing-books.md#creating-a-book)），而这里的导入则是针对你当前所在的书：各部分会被**添加到故事中**，而不是新建一本书。**Source** 可以是 `.md` 文件的 zip 压缩包、文档（Word、LibreOffice、RTF、Markdown、纯文本、EPUB）、Obsidian 库的 zip 包或 Scrivener 项目的 zip 包；每种来源都提供与那里相同的文本和选项（每部分的字数以及章节的标题级别），并有一行说明导入将产生什么。SillyTavern 和 LM Studio 的聊天记录不在此列：它们是分支树，不适合插入故事中间。

**Put the parts** 用于指定这些部分放置的位置：

- **At the end of the story**：放在当前分支最后一部分之后（对于空书，则作为第一部分）。
- **Before a part** 或 **After a part**：从列表中选择一个部分（编号为当前分支中的位置，附带文本开头）。新部分会被插入到两个部分之间：位于该位置之后的所有内容，包括其所有分支，都会排在新部分之后，且任何部分都不会被修改或重新生成。故事的结尾位置保持不变（故事因此变长了相应的部分数）。覆盖该位置的[摘要](summaries.md)会变为过时，因为它们描述的是没有新部分的故事。摘要窗口会显示这些摘要，并可重新生成。

![书籍的导入窗口](../images/book-import-into.png)

压缩包中的各部分按文件名排序，文件名中的数字按数值比较（`2.md` 排在 `10.md` 之前），包括压缩包内文件夹中的文件。文件夹、隐藏文件（`.name`）、`__MACOSX` 文件夹以及非 `.md` 的文件都会被跳过。文件内容即为该部分的原文，不会发送给模型，也不会被修改；所有部分都视为由你亲自撰写。

导入时会显示进度条和已完成的部分数。**Stop** 会在当前正在保存的部分完成后结束导入：已经添加的部分会保留在故事中（导入不会被撤销），并会显示一条消息，说明已导入的数量。

<a id="after-an-import"></a>

### 导入之后

部分内容导入到书中后，会弹出 **Import finished** 窗口，提供两项有助于撰写长篇故事的功能（刚作为新书导入的书会先被打开，该窗口位于其前面）。这两项功能也位于设置菜单中（⚙，**Analysis**），因此可以稍后或再次执行：

- **Create summaries...** 为导入的内容生成摘要，见[创建摘要](summaries.md#create-summaries)。请先执行此项：智能体在工作时会锁定该书。
- **Take lore notes with an agent...** 启动一个[智能体](../agents.md)，它会阅读故事，并将找到的人物、地点、物品和术语写成本书设定集中的条目，见[设定笔记](../agents.md#lore-notes-of-an-imported-book)。

**Not now** 关闭窗口，两项都不执行。

![导入后的窗口](../../images/import-finished.png)

将相同内容导入设定集的方法见[导入与导出](../lorebooks/import-export.md#importing-an-archive-of-text-files)。

<a id="what-the-model-gets"></a>

## 模型收到的内容

每生成一个新部分，Marginalia 会发送以下内容：

1. **主模板**作为系统消息：角色、[设定集](../lorebooks/index.md)条目、叙述视角、时态、风格和[摘要](summaries.md)。若已启用[推理提供方](../inference-providers.md#general-settings)的越狱提示词，则它排在最前。
2. 当前分支中之前的各部分，作为模型自己先前的回答发送——尽可能多地放入[上下文限制](../protocols.md#limits)之内，最新的优先。放不下的较早部分会被省略（除非某个[摘要](summaries.md)覆盖了它们）。
3. **用户提示词**，包含生成新部分的指令。

在任意部分上点击 *Show Prompt* 可查看实际发送的全部内容。模板说明见[书籍提示词](prompts.md)。
