# 권한

권한은 모든 사람에게 허용되지 않은 일을 한 사용자에게 할 수 있게 해 줍니다. 관리자는 권한을 사용자에게 한 명씩 부여합니다. 권한이 없는 사용자도 Marginalia의 나머지 기능은 평소처럼 모두 쓸 수 있습니다(책 쓰기, 로어북 만들기, 관리자가 [공유한](../inference-providers.md#shared-providers) 모델 사용하기).

| 권한 | 허용하는 것 | 설정 |
|---|---|---|
| **Create own models** | [추론 제공자](../inference-providers.md)를 추가하는 기능입니다. 이 권한이 없으면 사용자는 관리자가 공유한 제공자만 쓸 수 있습니다. 이미 가지고 있는 제공자는 계속 동작하며 여전히 편집할 수 있습니다. | |
| **Help assistant** | 매뉴얼을 바탕으로 답하는 채팅인 [도움말 어시스턴트](help-assistant.md)에 질문하는 기능입니다. | **Apply limits**와 **Allow navigating the interface**. [권한의 설정](#settings-of-a-permission)을 참고하십시오. |
| **Agents** | (실험적 기능, [에이전트](../agents.md) 참고) [Agents](../agents.md) 탭에서 에이전트를 만들고, 복제하고, 책에서 실행하는 기능입니다. | **Most agents**, **Concurrent runs**, **Requests to the model at once**, **Token budget of a run**과 사본 및 파일 할당량. [권한의 설정](#settings-of-a-permission)을 참고하십시오. |
| **Version history** | 사용자 책의 기록이 보관하는 [파트별 버전](../books/version-history.md#how-many-versions-are-kept)의 최대 개수입니다. 모든 사용자는 50개로 설정되어 있습니다(이 행이 없는 사용자도 마찬가지입니다). 권한이 부여되지 않으면 해당 사용자는 기록을 갖지 않습니다. | **Versions kept per part**. 폴더, 책, 사용자가 넘을 수 없는 상한입니다. 여기서 빈 숫자는 제한 없음을 뜻합니다. 새로 추가한 권한은 50에서 시작합니다. |
| **API access** | [HTTP API](../account.md#api-keys)의 키입니다. 사용자를 대신해 그 사용자의 책에서 작업하는 프로그램에 쓰입니다. 권한을 회수하면 사용자의 키도 중단됩니다. 관리자는 권한이 필요 없으며, 업데이트나 확장 기능에 키의 접근을 허용할 수 있는 것은 관리자뿐입니다. | |
| **Notifications** | 에이전트가 사용자의 도움이 필요한데 열려 있는 화면이 없을 때 서버가 보내는 [URL로의 메시지](../agents.md#when-you-are-not-there)입니다. 서버는 사용자가 입력한 주소를 호출하므로 독립된 권한입니다. 이 권한이 없으면 해당 입력란이 사용자의 설정에 나타나지 않으며 아무것도 전송되지 않습니다. | **Allow addresses on this machine and in private networks**. [권한의 설정](#settings-of-a-permission)을 참고하십시오. |

관리자는 항상 모든 권한을 가지므로 권한이 필요 없고, 따라서 줄 것도 없습니다(관리자의 버튼과 섹션은 권한에 따라 달라지지 않습니다). 새 사용자에게는 권한이 없습니다. [사용자를 추가한](users.md#adding-a-user) 직후 필요한 권한을 부여하십시오.

<a id="giving-and-taking-permissions"></a>

## 권한 부여와 회수

**Admin → Users**의 사용자 행에 있는 열쇠 버튼을 누르면 해당 사용자의 권한이 열립니다:

![사용자의 권한](../../images/permissions-dialog.png)

이 창은 사용자가 가진 권한의 표이며 열은 세 개입니다:

| 열 | |
|---|---|
| **Name** | 권한입니다. 설정이 있는 권한은 이름 앞에 화살표가 있습니다. [권한의 설정](#settings-of-a-permission)을 참고하십시오. |
| **Granted** | 권한이 작동하는지 여부입니다. 부여되지 않은 권한은 권한이 없는 것과 같지만, 설정은 그대로 보관되므로 잠시 끄고 다시 켤 수 있습니다. |
| 휴지통 버튼 | 권한(및 그 설정)을 영구히 삭제합니다. |

권한을 주려면 표 위의 **Add permission**을 누른 다음, 사용자가 가지고 있지 않은 권한 중 하나를 고르십시오. 그 권한은 부여된 상태로 표에 추가됩니다. **Save**를 누르기 전까지는 아무것도 저장되지 않습니다:

![추가할 권한 고르기](../../images/permissions-add.png)

- 저장할 것이 없는 동안 **Save**는 비활성화되어 있습니다.
- **Exit**은 창을 닫습니다. 저장하지 않은 변경 사항이 있으면 먼저 묻기 때문에, 변경 사항이 실수로 버려지는 일은 없습니다.
- 삭제한 권한은 저장할 때까지 표에 남아 있으며, 저장하면 영구히 삭제됩니다. 그 전에 되돌리려면 저장하지 않고 **Exit**으로 창을 닫으십시오.

저장한 뒤, 해당 사용자가 로그인해 있으면 그 사용자의 페이지가 새로 고쳐져서, 권한에 따라 달라지는 버튼과 섹션이 즉시 나타나거나 사라집니다. 본인의 페이지는 본인의 권한을 바꾸더라도 새로 고쳐지지 않습니다.

<a id="settings-of-a-permission"></a>

## 권한의 설정

일부 권한에는 전체 설치가 아니라 사용자별로 속하는 설정이 있습니다. 이런 권한의 행은 화살표로 시작합니다. 화살표를 누르면 설정이 펼쳐지고(창이 열릴 때는 접혀 있으며, 방금 추가한 권한은 펼쳐져 있습니다), 다시 누르면 접힙니다. 접기는 긴 목록을 짧게 보이게 할 뿐이며, 아무것도 바꾸지 않고 저장하지 않은 변경으로도 계산되지 않습니다.

![도움말 어시스턴트 권한의 설정](../../images/permissions-settings.png)

**Help assistant**, **Agents**, **Notifications**에 설정이 있습니다. 도움말 어시스턴트의 설정은 다음과 같습니다:

| 설정 | |
|---|---|
| **Apply limits** | 공유 모델의 경우, 사용자의 질문이 다른 요청과 마찬가지로 한도와 사용량에 포함되는지 여부입니다. [누가 비용을 내는가](help-assistant.md#who-pays)를 참고하십시오. 기본값은 꺼짐입니다. |
| **Allow navigating the interface** | 사용자가 길 안내를 요청하면 어시스턴트가 섹션을 열고, 탭을 선택하고, 무언가를 추가하는 대화상자를 열 수 있게 합니다. [길 안내하기](help-assistant.md#showing-the-way)를 참고하십시오. 기본값은 꺼짐입니다. |

에이전트의 설정입니다. 빈 칸은 기본값을 뜻합니다:

| 설정 | |
|---|---|
| **Most agents** | 사용자가 가질 수 있는 에이전트의 수이며, 에이전트의 복제본도 포함됩니다. 빈 칸이면 5입니다. 0이면 사용자는 기존 에이전트를 보관하고 실행할 수는 있지만, 새로 만들거나 복제할 수는 없습니다. 삭제된 에이전트는 자리를 비워 줍니다. |
| **Concurrent runs** | 사용자의 실행 중 동시에 작업할 수 있는 실행의 수입니다. 빈 칸이면 1입니다. |
| **Requests to the model at once (per run)** | 한 번의 실행에서 에이전트와 그 [하위 에이전트](../agents.md#sub-agents)를 합쳐 동시에 모델에 보내 둘 수 있는 요청의 수입니다. 빈 칸이면 1입니다. 이때 하위 에이전트가 모델에 요청하는 동안 에이전트는 기다리고, 반대의 경우도 마찬가지입니다. 더 큰 값을 주면 하위 에이전트가 에이전트와 병렬로 작업할 수 있습니다(에이전트의 모델에도 자체 [요청 상한](../inference-providers.md#general-settings)이 있을 수 있으며, 이것도 함께 적용됩니다). |
| **Token budget of a run** | 사용자의 한 번의 실행이 쓸 수 있는 토큰(보낸 것과 생성된 것)의 최대치입니다. 빈 칸이나 0이면 제한이 없습니다. |
| **Working copies** | 사용자의 실행들이 동시에 보관하는 책의 작업 사본 수입니다. 끝나지 않은 실행은 일시 정지된 것도 포함해 사본을 계속 보관하며, 끝나거나 중지되거나 삭제되면 사본을 돌려줍니다. 빈 칸이나 0이면 에이전트 수 외에는 제한이 없습니다. |
| **Largest file (KB)** | 사용자의 에이전트가 작업 공간에 쓸 수 있는 가장 큰 파일의 크기입니다. 빈 칸이면 1024(1 MB)입니다. |
| **Workspace size (MB)** | 사용자의 에이전트 한 개의 작업 공간에 있는 모든 파일이 차지할 수 있는 총 용량입니다. 빈 칸이면 20입니다. |
| **Files in a workspace** | 사용자의 에이전트 한 개의 작업 공간이 담을 수 있는 파일의 수입니다(폴더는 세지 않습니다). 빈 칸이면 500입니다. |
| **Checkpoints of a run (MB)** | 한 번의 실행의 모든 [체크포인트](../agents.md#checkpoints)(작업 사본과 그 작업 공간의 복원 지점)가 차지할 수 있는 총 용량입니다. 이 중 일부는 자동 체크포인트를 위해 남겨 둡니다. 빈 칸이면 100입니다. |

![에이전트 권한의 설정](../../images/permissions-settings-agents.png)

알림의 설정입니다:

| 설정 | |
|---|---|
| **Allow addresses on this machine and in private networks** | 하위 권한입니다. 체크 상자는 **Notifications**가 부여된 동안에만 선택할 수 있습니다(그렇지 않으면 회색으로 비활성화되며, 권한을 회수하면 선택이 해제됩니다). 이 설정이 없으면 인터넷의 주소만 호출됩니다. 다음 주소는 호출되지 않습니다: `localhost`, 사설 네트워크(`10.x.x.x`, `172.16-31.x.x`, `192.168.x.x`), 링크 로컬 또는 공유 주소(`169.254.x.x`, 클라우드 호스트가 메타데이터 서비스를 두는 `100.64-127.x.x`), IPv6의 고유 로컬 주소. ntfy나 Gotify가 같은 컴퓨터 또는 관리자의 네트워크에서 실행되는 사용자에게는 이 설정을 체크하십시오. 기본값은 꺼짐입니다. 이름은 해석된 주소로 검사하므로, 사설 주소를 가리키는 이름은 거부되며, 찾을 수 없는 이름도 거부됩니다. |

관리자는 권한도 하위 권한도 필요 없습니다. 관리자는 메시지를 받으며 로컬 주소를 사용할 수 있습니다. 완전히 신뢰하지 않는 사람들과 공유하는 서버에서는 하위 권한을 끄십시오. 그렇지 않으면 서버가 사용자가 입력한 어떤 주소로든, 관리자의 네트워크 안에서도 요청을 보내게 됩니다.

<a id="when-permissions-were-introduced"></a>

## 권한이 도입된 시점

권한이 생기기 전에는 **Users can create their own models**와 도움말 어시스턴트의 **Enabled** 스위치(**Apply limits** 및 **Allow navigating the interface**와 함께)가 전체 설치의 설정이었습니다. Marginalia는 업데이트될 때 이들을 권한으로 옮겼습니다. 당시 존재하던 모든 사용자는 모두가 모델을 만들 수 있었다면(기본값이었습니다) **Create own models**를, 어시스턴트가 켜져 있었다면 같은 두 설정을 가진 **Help assistant**를 받았습니다. 관리자가 바꾸기 전까지 이들에게는 아무것도 달라지지 않으며, 이후에 추가하는 사용자는 권한 없이 시작합니다.
